# v08 连续主体的工程复用说明

这份说明记录《一杯咖啡的远行》v08 使用的窄实现方式，供下一部作品按需要借用。它不是通用时间轴或动画平台。正式保存、冷开、离线导出与艺术验收的结论，应以本作品最终 `VERIFICATION.md` 及对应产物为准。

## 一份阅读状态，一条导航

保留一个 Flow 导航实例，由既有 sticky 与 `teacherController.read()/subscribe()` 提供真实阅读状态。导航 Source 通过 `layout.reportSize()` 报告实际高度，避免默认占位造成空白；本作品导航为48px。标题和导航按原 Flow 顺序组织，不加第二套导航或独立滚动控制器。

最新作品层导航事件 `coffee.v08.navigation` 携带 `{chapter:"02"…"07"}`，Runtime 把目标章映射到对应入场路线，并设置临时 `arrivalOverride`。命中该路线时跳过移动主体、恢复驻留显影，避免局部程序只剩标注、主体却停在侧边。覆盖在该路线被识别后、遇到另一条有效路线时释放；进入无移动路线的驻留区不会靠计时器清除它。`chapter:"01"` 或没有对应路线的值会清除覆盖。

这是用户导航意图的临时标记，不是第二份阅读位置。实际位置仍由同一阅读状态和最新几何决定，不使用延迟同步。其他导航入口若希望采用同样的到达策略，也需发出同一事件；不能假定刷新、历史恢复或外部定位天然会触发它。

## 原生照片只报告自己的几何

原生照片保留原实例 ID、素材归属和编辑身份。在现有照片父组内，以同一 grid 区域叠放透明 Source 几何探针，使探针尺寸跟随照片布局，不增加额外流程高度或第二个导航包裹组。

探针只读取自身 Source 的局部投影与 teacher viewport，向共享状态报告归一化的 `x/y/w/h`。Runtime 使用同一视口尺寸还原像素位置。无需查询跨源父 DOM，也不记录整页固定 scroll 坐标。布局变化后的几何重新报告，使局部程序从初始占位长到实际高度时，后续目标仍然有效。

## 局部程序用薄适配接管

U03、U05、U06 继续由实例的 `data.html` 承载文档和资源绑定，保留各自成熟交互机制，通过正式 Source 的 `document:'web'` 薄适配连接连续主体。适配只负责两件事：

- 把局部程序自身 DOM 中当前可见主体的 rect、材料和必要状态报告给共享状态；U06 另报液体出口。
- 接收共享 handoff 事件，只改变主体图层显影，不隐藏按钮、滑块、标签或整个交互容器。

局部内容继续通过现有 height report/layout 合同参与 Flow。`scope.events` 用于共享事件，`scope.state` 用于最新几何与状态；适配把作品事件转发为局部 `coffee:handoff`，既有交互逻辑仍由原程序管理。

U06 切到稀释或萃取完成后，以当前 `mode==='dilute'` 或 `material==='coffee-liquid'` 结束 `roast-filter` 入场路线。这样，锚点从粉层转到液体导致的布局变化不会再次召回熟豆；液体离开本章的 `liquid-cup` 路线仍可运行。这是局部程序当前状态的约束，不新增完成锁或第二份实验状态。

## 显影权要有来有回

原生主体通过 `scope.target({kind:'instance',instanceId})` 的 motion 接口取得一份受控 opacity lease。写入串行化，反向阅读可重复0→1→0；退出时先恢复 opacity=1，再释放 lease。局部交接采用相应的整体 opacity，控制范围止于主体图层。

移动素材未完成解码或像素读取时，不取得显影权。reduced-motion 与非交互状态保留场景驻留主体，停止跨页移动。位置、材料和目标配准完成后才做短互补显影；隐藏只承担交接，不承担叙事。

## 同款材料先配准，再处理遮挡

用与原生/局部图位相同的原图或其提取层。先确定 object-fit、图像内可见 bbox、观察方向和实际 DOM rect，再计算移动主体的中心与宽高；不能用整个透明画布的尺寸代替身体尺寸。

本作品的实例包括：原生果实1254²图像中的身体裁切；U03 alpha>8 的材料 bounds；U05原三张1254²照片的边界暗背景去除与原三层滑块混色。U05 先在原图坐标内合成，再施加整体显影，保留任意滑块位置的材质身份。

进入摄影果堆或麻袋时，使用明确的原图归一化落点，并用同一照片、同一 object-fit 映射恢复前景遮挡。摄影杯入口中心为 `max(手机126/桌面132, 照片底边+提取杯身高度/2+36)`，因此从真实照片底边之后的留白进入，后续仍按实时目标完成配准。

手机一般材料轨道的中段中心在 `W−10`，身体宽度收至不超过14px；初始离位和末段入位逐步恢复实际目标尺寸。fruit-sorting 手机分支先在原果实行内横移并缩小，再沿窄边运行，最后20%进入果堆。液体另用 `W−20` 的细小液滴轨道；杯入口也有独立路径，因此“14px窄边”不是所有路线全程的统一限制。这些参数属于本作品的审图结果，下一部作品应重新按版式确定。

## 保留的最小公共接口

| 接口 | 用途 |
| --- | --- |
| `teacherController.read/subscribe` | 唯一阅读状态与投影更新 |
| `layout.read/subscribe/reportSize` | Source实际尺寸、Flow高度与布局变化 |
| `scope.state.get/set/subscribe` | 当前槽位几何、材料和局部状态 |
| `scope.events.emit/subscribe` | `coffee.v08.handoff` 与 `coffee.v08.navigation` |
| `scope.target(...).motion` | 原生主体的有限显影租约 |
| `scope.cleanup` | 取消订阅、恢复显影和释放资源 |
| `document:'web'` | 在保留原文档和脚本的前提下挂接薄适配 |
