## 结论与边界

本轮仅审查本地 `updated.html`，并同步 r240 已采用的图注：**“滤杯与杯分开展示，便于观察滴落。”** 页面初始图注与 `WATER_STUDY.text.caption` 已同时更新；构建脚本也同步，避免重新生成时丢失。没有修改互动机制。

原 13 个核心函数仍与基线一致。播放、暂停、稀释、重置、声音、原生键盘操作及 reduced-motion 的代码路径均保留。

**主线实际验收结果：18 项通过，2 项属于已确认的继承性刷新边界。** 两项是萃取阶段和稀释状态在页面 reload 后恢复；正式 opaque sandbox 不提供可用的 `sessionStorage`，r218 基线同样如此，所以不能声称刷新恢复通过，也不将其描述为 v08 新回退。

**同一阅读会话内的章节往返保持已经在 r246、1440px 与 390px 实测通过。** 这是活跃实例的内存状态保持，与整页刷新和独立进程冷开不同。本文只继承主线报告的实际结果，不把源码路径存在当作刷新恢复的证据。

### 三个容易误写的行为口径

- **暂停后再次点击是“重新播放”**，会从起点开始，按钮也写“再看水经过一次”。现有程序没有断点续播承诺。
- **重置只重置稀释加水量**，即 `add(0)`；没有把整个页面、音效开关和萃取阶段都重置。
- **当前正式交付只能确认阅读过程中保留 `mode / added / progress`。** 源码虽然尝试 `sessionStorage`，但正式 opaque sandbox 中不可用，因此页面刷新不保留这些运行态。此边界在 r218 已存在。音效默认关闭、不存储；GLX 保存或独立进程冷开也没有因此获得运行态恢复承诺。

## 科学图注与示意点

数值模型准确表达本实验设定：已滤净饮品 200g、固定咖啡来源溶解物 3g，加水后质量分数为 `100 × 3 / (200 + added)`。程序没有尝试从萃取动画预测真实萃取速度、得率或风味。

72 个光点只用于呈现“同样多的示意标记分布在更多液体里”，不是可见粉渣、分子照片、分子数或实测浓度采样。画面真实感提高后，这一误读风险仍存在；现有紧邻图注已明确“不是可见的真实咖啡颗粒”，足以支持当前概念实验。若实际手机审片中这句被遮挡或过小，应修可读性，毋须改实验机制。

液位是与质量对应的概念体积表达，没有真实刻度；色深和速度也已标为示意，不能用于识别咖啡的实际浓度或风味。新增“分开展示”说明解释滤杯与玻璃杯的空隙，避免把分解视图误读为真实器具悬空。


## 慢滚进入后切换稀释：独立只读发现

核对本地 `runtime/journey-runtime.js` 与本程序后，确认存在仍可绘制 `roast-filter` 的路径：慢滚不会设置只由导航事件触发的 `arrivalOverride`；进入稀释或萃取完成时，本程序默认锚点从 `coffee-grounds` 改为 `coffee-liquid`，全局 Runtime 仍无条件将该锚点当作熟豆的目标。目标下移后，几何进度可能重新落入有效行程区间，导致杯上方出现整颗豆或碎豆。

给主线的最小修正建议是在路线选择与导航覆盖处理之后、素材就绪检查之前加入当前场景约束：

```js
if (r?.type === 'roast-filter' &&
    (s.u06?.mode === 'dilute' || s.u06?.material === 'coffee-liquid')) {
  r = null;
}
```

本次未修改 Runtime、GLX 或互动代码。主线应确认 slot 桥传递了 `mode/material`；本程序已返回这两个字段，当前 Runtime 的 `pixelRect` 会保留它们。无需新增导航状态、完成锁或实验重置。

修后只需复核具体剩余风险：不点击导航，慢滚从 U05 进入 U06，在原本会显示熟豆的位置切到稀释；改变加水量并小范围正反滚动，确认不重新出现豆子。另在萃取自然完成后检查一次同类反弹。直接导航结果仍复用既有有效证据。
