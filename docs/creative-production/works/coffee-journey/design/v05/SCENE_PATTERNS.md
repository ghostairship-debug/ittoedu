# 五种可迁移的场景组织方式

这些是从实际作品提炼的决策与输入约束，不是“一键生成精品”的通用模板。工程事实见 native/REPORT.md；只有固定溶质稀释做过跨主题、同引擎验证。

## 1. 人物主图＋环境副图＋独立正文

**任务：** 解释人的动作、材料与环境的关系。U02 让分选动作成为主图，环境图片只补充发生条件。

**输入：** 一张动作清楚、主体留有空间的人物照片；一张环境照片；主标题不超过约两行；短导语；独立正文与每张照片的来源。

**组合：** 主图占最大面积；副图保持较小；标题和导语形成另一个视觉重心；长段正文回到 Flow 阅读流。固定构图采用原生 group，组内文字与图片分别持有身份。不能把整张排版截成图片。

**改写时先动什么：** 先裁切人物和动作，再调文字宽度；换图后检查手、工具和材料是否还在画面内。文字变长时，不缩小所有字号来勉强维持原构图。

**不应机械复用：** 咖啡分选图的竖长比例、人物朝向、红色果实和肯尼亚图注。人物面向另一侧时，应改变图文相对位置。

## 2. 同一时点的多状态观察

**任务：** 看清不同工艺选择留下的差异。U03 的共同基准是“开始干燥时”。

**输入：** 状态 ID、名称、主图、说明、结构图、状态属性和步骤。主图应使用接近的观察距离；结构图承担照片不能证明的关系。

**状态：** 选中路线、详情开关、比较开关。进入比较不改选中路线；返回后恢复；详情与比较不能同时争夺主要画面。

**输出：** 主对象、文案和组织说明同步更新。验收一个关键路径：选择第二/第三状态 → 打开详情 → 比较 → 返回，仍保留所选路线。

**当前边界：** content.json 有内容结构，但三个路线、四层组织与部分 DOM 仍依赖咖啡。它是可学习的成熟案例，跨主题仍需适当改写渲染，不是任意对象比较组件。

## 3. 配准关键帧的连续演变

**任务：** 让观众通过一个连续参数观察外观变化。U05 使用生豆、转黄、熟豆三张同尺度图。

**输入：** 三个关键帧、对应文案、相同朝向和尺度、一个 0–100 观察参数。先做配准，稳定沟槽、主体中心、大小和阴影，再谈动画。

**机制：** 每一段保留一张不透明底图，另一张逐渐覆盖；不要将两张图同时降到半透明。播放、拖动、预设共同写入一个参数；用户拖动即停止播放。局部放大不改变观察参数，Escape 能退出放大。

**真实意义与边界：** 参数是艺术观察进度，不是真实温度、时间或工艺质量。不同材料数量、拓扑与形状变化不能简单换三张图后承诺无缝变形。适合锈蚀、表面处理等视觉解释时，仍需重新检查帧间关系。

## 4. 改变一个量，观察不变量

**任务：** 让画面、公式和文字共同解释一个明确关系。U06 的稀释分支已经移开咖啡粉，杯中溶解物质量固定。

**输入：** 初始总质量、固定溶质质量、最大加水量、说明与图形语义。只在初始已溶解、后续液体不含该溶质且忽略损失、反应和沉淀等条件下直接复用。

**输出：** 总质量、质量分数、液面、点分布与说明由同一状态得到；示意点总数保持。三个预设是 0、最大量的一半（四舍五入）、最大量，标签由作者同步改写。

**实际验证：** 糖水副本以 30 克糖、300 克初始糖水、0/150/300 克清水得到 10.00/6.67/5.00%。water.js 字节完全相同；仅改配置。见 REUSE_GUIDE.md 的契约与证据。

**不能套用：** 糖正在溶解、温度控制溶解度、发生沉淀、真正萃取动力学。这些问题改变了模型，应另行构造机制。

## 5. 原生叙述包围局部程序

**任务：** 保留图文修改能力，同时让一个复杂互动作为完整场景运行。

**输入：** 原生前导标题/正文、一个只负责局部状态的程序、原生后续解释。Flow 持有章节顺序；程序不接管整篇导航或其他章节。

**程序边界：** 控件、受控画面和实时说明必须共用状态，因此可以保留为一个局部程序。静态章节叙述、外部照片与图注不必进入同一个程序。

**保存分工：** GLX 保存配置、源码、布局与资源；播放进度、临时选择属于阅读会话。会话存储不可用时仍可操作，不承诺重新打开仍处于同一播放位置。

**实际装配经验：** 在本轮果铃构建中，Flow 的自然高度程序导出为约 150px iframe。通过为三个局部场景明确 viewport CSS 与画幅，正式导出恢复完整高度。此处理只用于局部程序；不得据此把整篇文章固定成一个 viewport。详见 native/ASSEMBLY_GUIDE.md。

## 从作品抽象时的退出条件

能够写清输入、输出、边界，并在另一个主题中实际替换内容后仍成立，才考虑成为可直接复用机制。只在本故事中好看的细节保留为案例。素材、场景组织、程序机制与创作判断可以分别复用，不必强行统一成一种组件。
