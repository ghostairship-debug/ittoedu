# 从内容到可修改作品：给后续 AI 的创作指导

本指南来自《一杯咖啡的远行》v0.5 的实际制作。阅读它的目的，是学会做判断、做修改、验证表达；不是把下一件作品换一个标题后套进咖啡页面。当前正式工程版本和未收口项以 `README.md`、`../../handoff/NEXT_PASS.md`、`DELIVERY_MANIFEST.json` 为准，旧装配报告不作为当前状态。

## 1. 先找观众需要看见的关系

不要先罗列要用的组件。把内容写成一个能被观察的问题，再选择形式。

| 内容中的关系 | 本作采用的形式 | 判断依据 |
|---|---|---|
| 一件熟悉的东西，背后有陌生的来路 | U01 杯子静物＋果实对照 | 先建立日常经验，再改变观看距离；开篇无需复杂操作 |
| 人的劳动与材料之间的关系 | U02 人物摄影为主、环境小图为辅 | 人的姿势和手边的果实就是信息；无需用图标代替照片 |
| 同一个时点，不同选择留下不同组织 | U03 状态切换、局部图解、并排比较 | 固定比较时点比增加一条时间轴更有解释力 |
| 安静但不可缺少的工序 | U04 两张尺度不同的照片＋节制文字 | 降低操作强度，给后面的显著变化留出空间 |
| 连续观察中的外观变化 | U05 一粒豆、三个配准关键帧、一个连续参数 | 同一个物件的位置稳定，观众才容易把差别读成变化 |
| 哪些量变化、哪些量不变 | U06 过程示意＋固定溶质的加水实验 | 图像、数字和说明由同一个状态计算，避免彼此矛盾 |
| 经验如何回到个人 | U07 同一只杯子＋三个感受提示 | 用重复建立回环，把判断还给读者，不做知识点清单 |

选定形式后，要能说出它帮助读者多看见了什么。若一个动画只让标题飞入，而不能解释顺序、注意力或变化，就先删除它。

## 2. 先确立图文关系，再做装饰

为每个场景指定一个主观察对象。U02 是分选台上的人；U03 是一颗果实；U05 是豆的表面；U06 是杯中物质的关系。标题、说明和控制围绕这个对象安排，不让每一个元素都争当主角。

摄影、静物、图解承担不同任务。摄影保留具体地点、人与环境的复杂性；生成静物帮助保持观察尺度和构图；原创图解只解释照片无法可靠显示的组织关系。不要把生成图当作真实同一批材料的记录，也不要让一张“像剖面”的生成图片承担精确结构证明。

本作的色彩顺序是纸色与照片、浅色标本、纸色交接、深色烘焙、浅绿色水、纸色杯子。深色只在材料变化最强的章节集中使用。所有章节采用同样的卡片、同样的按钮数量、同样的三栏布局，会抹平内容差异。

## 3. 素材策略要服务于观察

1. 先搜索能表达具体动作和环境的真实照片，并保留作者、原始页面和许可。不同来源不必伪装成一次跟拍。
2. 找不到合适的物件视角时，再生成少量明确用途的静物。提示词写清主体位置、视角、光线、背景、留白和不应出现的物件。
3. 对连续变化的素材，优先保持主体尺度、沟槽位置、朝向与阴影关系。配准比新增更多中间帧更重要。
4. 对精确关系用程序或矢量图，不用生成图片猜测数据、数量和结构。
5. 素材达到参考水准后，把时间转到正式装配、修改能力与复用验证。本轮只新增一张杯子图，开篇和结尾共同使用。

素材表应解释用途、来源、许可或生成方式、裁切及局限。一个散落着几十张候选图片的文件夹，不等于可供后续 AI 理解的素材资产。

## 4. 原生对象和局部程序的边界

普通标题、正文、图片、图注，应尽量保留原生身份。本作全文由一个 Flow 组织；七处固定构图采用 Flow 中的有界原生 `group`，组内文字和图片仍分别可编辑，它们不是额外的 Slide 页面。复杂状态、Canvas、连续素材融合和局部音效，分别保留在 U03、U05、U06 三个局部程序中。

不要把整篇 HTML 插进一个大 Web 对象后宣称“已原生装配”。也不要把需要共享状态的按钮、物件和说明拆成彼此不知道对方状态的程序。一个局部程序的边界，应覆盖它必须共同更新的最小完整场景。

本作三段程序各有清楚的输入：处理方法、视觉进度、加水质量。它们周围的叙述不需要进入程序。正式工程的实际对象身份由果铃产生，后续修改必须读取当前投影路径，不能沿用旧序号猜测目标。

## 5. 让一个状态同时驱动画面和解释

U03 的核心状态是 `selectedMethod`，比较是另外一个阅读模式。进入比较不改掉已经选中的路线，返回时恢复它。组织详情和比较画面要有清楚的显示规则，避免两个不同观察尺度混在一起。

U05 的参数是 0–100 的视觉观察进度，不是温度、时间或品质分数。前半段以生豆为不透明底帧，转黄帧逐渐覆盖；后半段以转黄帧为底，熟豆帧逐渐覆盖。把两张图同时降到半透明，会让背景漏进来，形成无意义的暗闪。

U06 的加水实验采用明确设定：移开粉渣后，200 克饮品含 3 克咖啡来源溶解物。加水量为 `a` 时，总质量是 `200+a`，质量分数是 `3/(200+a)×100%`。液面、点的分布、总质量和百分比来自同一组状态；点的总数保持。萃取过程只作关系示意，不根据动画速度虚构真实萃取动力学。

有声音时，要说明它承担的作用。本作的轻水声由读者主动开启，在播放或加水时提供动作反馈；不作为背景音乐，也不承担理解内容的唯一渠道。

## 6. 修改已生成作品的方法

先定位问题所在层级。错字改原生文字数据；图片替换走媒体目标；一段程序的文案或参数改该实例当前暴露的内容、依赖或源码；整篇节奏有问题，才调整章节顺序与尺度。不要为一个错字重导整篇作品。

修改之前记录目标身份、当前内容及相邻章节。修改之后检查目标、邻居和框架，验证 Undo/Redo，再保存和重新打开。工作目录中的 `content.js` 改了，并不表示已保存 GLX 内的对应资源自动改变；正式工程要通过当前工程路径再次提交。

早期 Flow 试运行中的局部程序热更新曾触发 DOM 挂载错误，后续宿主软件批次已针对共同挂载链完成修复。当前续改仍应以真实事务 ACK、目标身份、邻居、Undo/Redo、保存冷开和正式离线结果为依据；具体仍未验证的编辑条件如实记录，不因旧失败而重新改造宿主软件。

## 7. 从初稿到参考水准的三轮观察

**表达轮：** 不看检查数字，先完整阅读。主对象是否明确？每一段是否有必要？是否有机械重复？开篇是否建立兴趣，结尾是否改变观众对开篇物件的理解？

**操作轮：** 用真实点击、键盘和滚动操作。比较返回是否保留选择？控制是否靠近它影响的图像？离开后动画是否停止？手机上能否在合理位置发现开始操作？

**工程与迁移轮：** 修改原生标题、正文、图片和局部配置；检查邻居、历史、保存与冷开。把一个机制换到另一个主题实际运行，明确哪些代码没动、哪些配置变了、哪些语义仍硬编码。

本轮艺术复审只要求两处有价值的修改：消除锚点双重顶部补偿，让章节定位更干净；把手机端 U06 的开始操作提前。达到参考水准后，不继续为微小摄影风格差异反复生成素材。

## 8. 两个可引用的创作配方

### 配方 A：同一时点的材料比较

适用：处理路线、修复方案、材料结构或工艺选择。先写出“比较发生在什么时点”，为各路线准备同尺度主图与独立结构图。选择状态、详情状态和比较状态分开管理；说明随选中状态更新；返回比较前的路线。验收重点是差异是否可见、比较基准是否一致、返回是否丢失选择。

U03 是这个配方的正面案例，但其三条路线、四层组织名称与咖啡文字仍有故事依赖。跨主题使用时需要改配置结构和部分渲染，不能宣称是任意材料的现成组件。

### 配方 B：改变一个量，观察不变量

适用：稀释、配比和质量守恒的入门解释。先把假设写在画面内，只开放一个有解释价值的控制。每次输入后，用同一个公式计算全部输出，再更新图像。保留有代表性的预设，提供重置、减少动态和离开暂停。

本轮把 U06 复用成“300 克糖水含 30 克糖”，最大加水量改为 300 克，关闭咖啡萃取分支，替换文案和无障碍描述。引擎字节完全相同；实际得到 10.00%、6.67%、5.00%。因此可直接复用的是“固定溶质质量的稀释观察”，不是通用萃取模拟器。

## 9. 需要主动避免的低质量模式

| 低质量表现 | 更有效的修正 |
|---|---|
| 每章一个图标、三张卡片、一个口号 | 依据人的动作、材料尺度和内容关系重新分配版面 |
| 控制很多，但只改变装饰颜色 | 留下能改变解释结果的输入，并同步图像和文字 |
| 数字非常精确，模型假设不明 | 明示设定；无法支持的部分改成定性示意 |
| 声音和自动动画持续播放 | 主动开启、局部出现、离开暂停，静态仍能理解 |
| 浏览器漂亮，工程只剩一个 Web 对象 | 重新划分原生叙述与局部程序，实际修改验证 |
| 把每个特效都打包成“通用组件” | 先做跨主题小实验，再确定机制的输入、边界和必要抽象 |
| 用通过了多少测试代替艺术判断 | 把事实检查与观看判断分别记录，直接修改最影响表达的问题 |
