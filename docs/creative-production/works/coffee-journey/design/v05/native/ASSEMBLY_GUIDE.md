# 果铃 GLX 混合作品｜当前装配与继续修改

**适用版本**：Project 11，revision 179 的 [正式咖啡工程](coffee-journey-v05.glx)。以 [NEXT_PASS](../../../handoff/NEXT_PASS.md) 和 [manifest](../DELIVERY_MANIFEST.json) 为当前版本证据。先复制新命名副本，避免覆盖已经通过验收的 r179。

## 结构与职责

- 1 个 Flow 将 U01—U07 组织成连续阅读；
- 7 个有界原生 group 保留必要的跨栏构图；
- 62 个原生文字实例、8 个原生标题块、8 张原生图片、7 个背景形状均可按真实目标修改；
- U03 / U05 / U06 是三个局部 HTML 程序，控制、实时图像与同步说明共同处在各自局部状态范围；
- 正文、图注、段落、通用导航不由局部程序接管，也没有把全文封成一个大 Web。

## 怎样修改

1. 从当前 GLX 的 `project.list` / `project.read` 取得真实工程目标、Source 路径与 revision。旧阶段脚本中的编号和 SOURCE_MAP 不能继续当依据。
2. 修改字句使用原生文字/正文目标；换图使用媒体目标；调整布局使用对象/组属性或正式事务，保留现有人工排版。
3. 修改局部行为：取得当前 U03/U05/U06 对应的 `*.content.html` 或 Source 依赖，明确本次只改该局部程序；如需改配置，连同文案、预设与图示是否一致一起检验。
4. 修改独立参考目录的 HTML/CSS/JS 不等于正式 GLX 自动更新，必须经过已接入的正式写入链。
5. 每轮只核对相关目标、相邻对象、Undo/Redo、保存后新进程冷开和离线导出；有有效证据则复用。

## 画幅与移动阅读

Flow 内容可以自然重排；有界原生编组或程序保留作者画幅时，内部元素可能随可用尺寸缩放。当前整篇手机缩小和 DOM 热挂载 bug 已修复，不能重新把过时诊断当成现状。U03/U06 小屏图内文字是**作品视觉改善目标**。若背景 Runtime 在后续加入，应明确它是全局层还是 Flow 纸面层，避免被固定构图遮挡、拦截输入或重设局部程序状态。
