# 复用成果与实际迁移

## 分级：什么可以拿走，什么需要重新判断

| 成果 | 本轮定位 | 使用边界 |
|---|---|---|
| `water.js`＋`water.css`＋HTML 壳 | 已实际复用的局部机制 | 固定溶质质量、增加清水、克为单位、示意杯形；不求解真实流体或萃取动力学 |
| `water.config.js` | 可替换参数和文案 | 初始质量、溶质质量、最大加水量、点数、模式、标题、说明、无障碍描述与部分配色 |
| U03 状态观察、局部结构、并排返回 | 需要配置抽象后复用的机制 | `content.json` 已组织内容，但三条路线与四层组织的渲染仍有咖啡依赖 |
| U05 连续关键帧覆盖 | 可学习和改写的机制 | 三个对齐关键帧、两段覆盖；不同素材数和形状需要重新处理，不是任意图片的无缝变形器 |
| 摄影跨栏、环境副图、静物大留白 | 创作案例和组合方式 | 主次关系可迁移；图片裁切、比例和文字长度须按新内容重做 |
| Flow 原生阅读＋有边界的自由布局＋局部程序 | 正式工程组织案例 | 当前协议路径必须从工程重新读取，不把本作对象 ID 当作模板常量 |
| 杯子、咖啡果与烘焙图片 | 故事素材 | 可以作为咖啡示例，不应机械搬到其他材料主题 |

## 已实际完成的迁移：糖水稀释

入口：`reuse/sugar-water/index.html`。这是独立副本，可以直接打开，不依赖咖啡文章。

只替换 `water.config.js`：初始溶液由 200 克改为 300 克，溶质由 3 克改为 30 克，最大加水由 100 克改为 300 克；关闭咖啡萃取分支，替换标题、说明、颜色和 Canvas 的无障碍描述。HTML 壳、绘制、公式、滑块、预设、声音入口与生命周期处理保持相同。

| 加入清水 | 溶液总质量 | 糖的质量 | 实际显示 |
|---:|---:|---:|---:|
| 0 克 | 300 克 | 30 克 | 10.00% |
| 150 克 | 450 克 | 30 克 | 6.67% |
| 300 克 | 600 克 | 30 克 | 5.00% |

实际通过浏览器按钮操作检查了上述三个状态；72 个示意点的总数保持，糖的质量读数保持 30 克。程序文件与咖啡版本字节相同，SHA-256 为：

`4467596e69e323bec095bb5706fa3dae4132ba7f1a04140e297f6a224a7c03e6`

证据：[独立浏览器迁移事实](evidence/sugar-water-browser-facts.json) 中的 `checks.reuse`、[糖水预览](evidence/sugar-water-preview.jpg)。这些事实仅证明本次配置迁移的独立 HTML 路径可用；尚未覆盖另一主题的正式 GLX 装配／保存／导出，更不证明适用于任意化学体系。

## 配置契约

| 字段 | 意义与约束 |
|---|---|
| `id` | 当前活动的状态命名空间。不同主题必须使用不同值 |
| `baseMass` | 初始溶液质量，必须大于 0，包含溶质质量 |
| `soluteMass` | 固定溶质质量，0 到 `baseMass` 之间 |
| `maxAdded`、`defaultAdded` | 清水输入范围与起点；不表示从已存在的杯中实际抽水 |
| `particleCount` | 示意点总数，不对应真实分子数 |
| `initialMode`、`extraction.enabled` | 是否显示本作的咖啡过程分支；一般稀释题应关闭萃取分支 |
| `text` | 页面标题、Canvas 描述、数值标签、实验设定、三个预设和结论文案 |
| `palette` | 画面主体配色。部分界面线条仍沿用本作浅绿设计，不是完整主题系统 |
| `extraction.steps` | 咖啡关系示意的阶段说明；不是可直接用于其他工艺的动力学模型 |

参数变化后，必须同步检查 `text.assumption` 的设定数字和三个 `text.presets` 标签：这些作者文案不会从数值参数自动生成。预设实际输入为 0、四舍五入后的最大加水量一半、最大加水量；滑块步长为 1 克。以 `reuse/sugar-water/water.config.js` 为完整配置起点，逐项改写并做语义核对。Canvas 配色沿用六位十六进制颜色格式。

直接复用的前提是：初始溶质已溶解，后续只增加不含该溶质的液体，并可忽略反应、蒸发、沉淀和损失。“盐水加纯水”可沿此判断；“糖在水中逐渐溶解”需要另外描述溶解过程，不能仅换标题套用。

输出采用同一状态：`total = baseMass + added`；`fraction = soluteMass / total × 100%`。根节点还暴露 `data-added`、`data-total`、`data-solute`、`data-concentration`、`data-particles` 与播放状态，便于有针对性地验证图文一致性。

## 资源和嵌入边界

U06 不依赖外部网络、照片或第三方库。HTML 引用同目录的 `common.css`、`water.css`、`water.config.js` 和 `water.js`。外层文章根据来源窗口匹配 `coffee:height` 消息，调整局部 iframe 高度；在果铃内，正式程序的容器尺寸与资源闭包由工程持有。

局部程序只拥有自己的材料状态，不控制全文导航。文章导航负责章节定位。U03 的 `coffee:reveal` 只请求外层把当前活动起点带回视野，不越权改其他章节。

## 状态、离开与保存

U06 用当前主题命名空间保存会话内的模式、加水量和观察阶段；存储不可用时仍能正常运行。离屏或页面隐藏时暂停，返回时对齐画面与数值。减少动态模式逐段阅读萃取说明，加水直接显示静态结果。声音必须主动开启。

这类会话阅读状态不等于 GLX 的永久作者状态。GLX 保存的是配置、程序、布局与资源。重新发布、换浏览器、清理会话或以新的程序实例打开时，不能承诺继续上次的临时播放进度。作者希望改变默认状态，应改配置并正式提交、保存。

## 为什么没有继续包装成组件库

本轮证明了稀释机制可通过配置复用，因此保留小而明确的源文件组合。U03 和 U05 仍有材料、状态数量和构图依赖，先记录方法与边界。没有把三个特效统一成一个巨大的“全能场景组件”，也没有以复制目录代替实际迁移验证。

后续可再选一个不同的稀释主题检验质量范围、文本长度和数值精度。只有反复出现的稳定输入与输出才值得进一步抽象。
