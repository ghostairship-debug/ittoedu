## 2. 总体视觉方向：一条主体叙事线，几种合理的表现方式

### 2.1 艺术原则（据此取舍）

1. **同一时间、同一语义位置只能有一件主体。**Runtime 承担跨阅读场景的连续视觉身份；摄影中的果实/豆堆、U03/U05/U06 局部程序都可以接管主体的可见表现。退出的是上一投影载体，**主体应融入新场景或被下一程序承接，不无故消失**。这是一条叙事所有权链，不要求每刻是同一张贴图，也不宣称不同地区的纪录摄影拍到同一批咖啡。
2. **主体移动有目的地。**必须有可读文字、物件插槽、被强调的问题或局部实验作为终点；没有目的的转场允许删除/缩短。摄影场景与纪实人物不为匹配 Runtime 被强行重绘。
3. **照片保留真实空间，程序只负责必要变化。**柔光、桌面纹理、碟子、接触阴影、玻璃折射从高质量图片或分层素材获得；数学、液位、组织关系、对照和可交互对象交给可控程序与 DOM。
4. **滚动仍由宿主负责。**Runtime 消费 `reading` 与 `flowMotion`，不再开一个 `window.scrollY`、`IntersectionObserver` 决策导航位置或设 1350ms 独立相位钟。可以有作为纯函数的“艺术姿态插值”，没有第二个滚动控制器。
5. **屏幕是长篇阅读，不是七张动效幻灯片。**有强交互（U03/U05/U06）时由局部程序接管；U02/U04 以**入景—摄影内驻留**代替漂浮，不牺牲人物摄影。保留书页留白和自由阅读；无需让独立 Sprite 每秒都占据视口，但不能把照片内的主体当成“已经消失”。

### 2.2 四种实现路径的真实取舍

| 路径 | 视觉上限 | 前提/代价 | 结论 |
|---|---|---|---|
| A. 原 Global Underlay + 正文透明开口 | 可在纸面留白或已透明的照片区域露出唯一物件；纯背景连续最简单。 | Underlay 位于原生照片**下方**，不可能直接盖过完整的不透明杯子；对象离开洞口会被图片遮住。需要分层空景、动态开口或其他投影表面，且手机遮挡要实测。 | 作为**无交叠、留白段的廉价实现**；不把“挖透明洞”当成 U01 全程万能答案。 |
| B. 单一 Runtime 逻辑 + Flow 视觉插槽/只读几何 | 能把物件精确放入 U01 摄影位、U01 果实位和跨章留白；布局变化可跟随。 | 当前接口没有通用“原生元素视口矩形批量读取”合同；若由作品自行量固定视口像素仍会回到 v07 问题。前景投影还要确定层级、clip 和互动事件穿透。 | **主方案的空间组织方式**，按 §2.3 阶段性探路，必要时最小补接口。 |
| C. Runtime 与原生照片/局部程序在指定插槽视觉交接 | 最能保留开篇摄影、U05 现成关键帧、U06 科学操作；避免任意复杂变形。 | 交接处需要同构图/姿态/尺度/遮罩，且确保交接瞬间只有一份主体可见。若不同嵌入程序拿不到相同宿主状态，不能伪称完全同步。 | **主方案的显影方式**；不必追求同一个 Canvas 绘制全篇所有物件。 |
| D. 全靠 Flow/Spatial/局部程序拼出各自独立动画 | 单个插槽容易做得极美。 | 多个局部程序独立响应滚动易出现时钟、状态分叉；极容易把全篇包成几个不可编辑大 Web。 | 只在 U03/U05/U06 原本就耦合的局部程序内部采用；不把它用作全篇导演。 |

### 2.3 最优主方案：**“视觉插槽 + 单一演员状态 + 受控交接”**

- **作者侧插槽清单**是作品的布景数据：`slotId / nativeInstanceId / subjectRole / enter / exit / layer / safeMask / desktop-mobile composition`。直接引用已存在的 U01 摄影组、果实组、U03 科学程序、U05 局部程序和 U07 摄影组；必要的过渡留白用有意义的原生组。它只声明“在哪里展示”，不保存滚动位置、导航状态或像素级动画曲线。
- **唯一动作事实**来自同一宿主 `teacherController` 的实际阅读/导航运动；由 `background-runtime.js` 的纯姿态映射决定 `subject / phase / pose / opacity / layerIntent`。一旦跳章、回退、手机重排，目标插槽矩形必须重新解析，旧画面只用于自然打断的视觉过渡；资源和对象身份保持。
- **一个演员，多种驻留载体**：留白段由现有 Global Underlay 负责；U01 由分层摄影杯暂时接管；U02 的果堆、U04 的袋口/豆堆由纪实照片中**明确可辨的现有物件**接管；U03/U05/U06 由局部程序中的实体接管；U07 由初始同款摄影杯接管。入景时可短暂由前景对象与照片目标受控交叉显影，但绝无两个持续并行、不同步的独立物件。独立 Runtime 主体隐藏时，目标照片或程序必须能说明“主体现在在哪儿”。
- **分层优先级**：正式导航 / 可交互控件与文字最高；科学标注及可触达按钮高于装饰；前景演员只在已声明的视觉安全区域可见；摄影前景遮挡/边界随后；Underlay 纸色和非主体纹理最低。原则是**文字和实验不用躲演员**。
- **渐进交接而非强制 morph**：图像与程序都能在本章节内用相同光照/轮廓做 200–400ms 视觉意义上的位置/遮罩渐变，但时长不能成为独立的导航时钟；其进度取自宿主导航位置或同一实际插槽跨越距离。没有足够中间画面时直接以留白/遮挡/焦点移动交接，比两个不匹配物件硬融更自然。
- **独立背景纸色**可以继续由现有 Underlay 绘制并跟随 `paperBands`；主体投影是否同一 Canvas/同一平面是作品级合成选择，不能以“Canvas 个数=主体个数”误判。无论实现如何，**主视觉语义和相位只有一个 owner**。

**必须在下一轮先做的原型选择试验**：U01 先验证“可显示的真实插槽 + 分层杯子”是否在现有 Flow/Overlay/局部 Source 机制中成立，不预先宣布不用软件改造；若前景投影必须靠读取宿主未开放的 DOM 或用两份独立滚动时钟维系，就暂停这一实现，申请 §8 的最小公共只读接口，或者选择保守的照片交接备选。**高质量与长期可维护性都优先于强行实现看似连贯的全程 morph。**

## 3. U01：从“照片 + 装饰杯”改为“摄影里的唯一一杯”

### 3.1 最终画面提案（1440 桌面）

**开场静帧仍基本像现在那张优秀的原始摄影**：左边衬线大标题和引言，右边浅石纹桌面、上午的斜光、陶杯、杯碟、深浅接触影。图片可以和 v05 一样保持近似 1.35 倍文字栏比例。不要重做一张风格相近但光照/杯型不同的 AI 场景来替代旧图。唯一改变：右侧杯身现在是唯一可动画主角；画面右下不再出现小 Runtime 杯。

**摄影级分层的推荐制作规格：**

1. `plate`：以旧照片 `v05/assets/cup.webp`（正式 U01 图像实例 `0f19f30b-5bed-4933-af07-311081583f85`）为视觉基线，制作**没有杯身的桌面空景**；杯碟可以留在桌上作为固定场景道具，也可单独拆前层以形成遮挡。杯子离开后，桌面与碟子仍自然受光。删除原杯身时，必须同时重建被杯身遮住的碟面/接触阴影，不是抠出杯子留白洞。
2. `subject-cup`：从**同一张原图**取得杯身、把手、杯口、咖啡液面及必要的微弱反光；与旧图严密像素配准，向 v07 Runtime 素材 `assets/runtime/cup.webp` 统一杯形/视角，**以旧原图视觉作为新的杯身份标准**，不要继续画出当前那只没有碟子的另一款杯。
3. `front occlusion / contact shadow`：按需拆前景碟沿、投影、杯底接触暗部；杯未动时阴影与杯体完全闭合；杯上移时接触影相应缩浅，静止碟子和实物环境仍不变，避免“平面贴图悬浮”。静态桌面投影不应跟着飞走，只有杯身接触投影发生变化。
4. `lighting match`：重用原片光向（左上暖日光）、曝光和接触面颜色；物件缩放/移动时允许遮罩、轻微视角调整与环境反射，严禁在画面下滑时突然换成暗边硬阴影、冷色无影棚对象。
5. `material bridge`：当杯子离开原摄影位置、进入页内留白后，才逐步与 v07 原有红果 `cherry.webp` 融合；中间帧先是杯的体积与深色液面收束，再引入红色表皮/轮廓。**杯子本身**变，不是杯子旁再长一颗果实。果实到达 U01 下半 `把时间往前推一点` 的图位时完成身份交替。

**制作取舍重点**：开篇摄影主体的质量优先于使用 v07 现成 `cup.webp` 的便利。若原图杯子/把手遮挡无法无痕抠取，应保留原整幅照片作为开场固定画面，等主体在可用留白处进入下一段时**一次受控交接**；但不得在开场同屏叠第二个杯子。禁止为了“全程动画”把已优质的开场摄影换成明显劣质的生成式杯。

### 3.2 U01 内容内的五个可确定帧

以下是**艺术关键帧，不是强制逐帧时间轴**。插槽中心均随真实 Flow 可视矩形计算，下面百分比仅用于构图审查，不能写死为滚动阈值。桌面实际锚点首选现有原生 group/image，不把坐标复制为独立导航数据。

| 帧 | Flow 触发区域/现有身份 | 主视觉与层级 | 文字及交接原则 |
|---|---|---|---|

### 3.3 真实锚点如何写入作品而非猜滚动百分比

- 定义 U01 作者插槽，例如 `heroCupSlot` = 图片 `0f19f30b-5bed-4933-af07-311081583f85` 内杯位的相对矩形；`originCherrySlot` = 图 `942e61c7-e691-4fac-b4c0-a09dd872b314` 可视区。杯位相对坐标参考正式 1440 封面可进一步标定，**不是本轮凭截图指定永久绝对数**。
- 下一轮在 1440/390 两种 Flow 排版测出这两处图片的**真实可视 rect** 和其版面内的主体占位比例；对有 `object-fit/object-position` 的原生图片，必须同时转换从原图坐标到裁切后视口坐标。图片标题/图注增长、字体变化、变宽时自动重新取 rect。
- 姿态不是“scrollTop 超过 600px 杯飞到某点”，而是 `pose = interpolate(SlotA,SlotB, visibility/reading-position)`。滚动相位唯一来自宿主；视口位置来自宿主的实际布局事实或已证明可靠的局部布局能力，且标明作者用途。正常滚动的形变切分可借插槽间真实距离；点击跳转的显示插值取 `flowMotion`，两者只影响同一个 `visual`，不并行更新。
- 维护成本约束：同一 Slot 描述能换图片、换 Flow 宽度、改字后仍“绑到对象”。为每个设备写 `READING_KNOTS` 一套常数只能作为低保真回退。背景 `READING_KNOTS` 和 `READING_HEIGHTS` 的现状见 `background-stages.js`；移动后纸色断点也要依**内容边界**重新校准，防止 U05/06 出现不正确底色。
- 摄影在前/后景的插槽必须说明 `occlusion`：桌面空景是静态视觉层，Actor 的前景或受控开口是可变视觉层，最上为必要的前景碟沿/反光；禁止一张完整不透明图片挡住 Actor 然后通过调增 Runtime `opacity` 企图“使其出现”。

### 3.4 移动端 U01 另行排版，不照搬桌面飞行轨道

390px 的正式截图开篇已是“标题→整幅杯子摄影”的合理节奏，屏宽不足以容纳长期漂浮的右侧视觉轨道。继续保持**标题先读、环境照片再出现**。主体只在照片自身内部短暂活动，离开照片后可通过留白区的小尺度物件接到后面的“果实”插槽；过渡后不沿正文右缘粘着一截半杯或半豆。小于约 360px 视口时，更倾向两幅清楚的定格和短暂交接，而非捏小主体与标注字体。手机原生正文、链接、引用、章节导航点击热区不被动效覆盖。

### 3.5 U01 样板质量的淘汰门

在展开其余六章之前必须用真实 GLX 预览确认：

- A 静帧肉眼上与原图一样可信：把手边界、杯口椭圆、阴影和桌面材质无明显拼接；**0 个重复杯子**；不因 Runtime 变清晰度/色温而破相。
- A→B→C→D 慢滚/快速滚/反向滚三种方式至少有 5 个取样点，没有突然变出第二颗完整果实、主体跳 100px 级位移、影子留一块脏污或遮挡大段文字；点击 U02 后无需看完整变形也能落在正确页面。
- 手机正文在 B/C 过程不因为留给 Actor 的强制空白而出现过长断层；减少动态下照片与果实图位都是完整可解释的静物。
- **若摄影拆分无法达到原图质量**，立即回退到“原照片静止 + 在页内留白处一次可控影像交接”，不为动画覆盖劣质修图。这是主方案内许可的务实备选，不需要新平台机制。

## 4. 导航：恢复 v05 的“先刊头，后吸顶”，但沿用 v07 唯一导航状态

### 4.1 目标行为和现状核对

原始 `../v05/index.html` 明确排列为：

```text
<body scroll owner>
  <header class="mast"> 作品名 / A JOURNEY THROUGH MATTER / Chapter 01—07 </header>
  <nav class="nav" style="position:sticky;top:0"> 七章 / 进度 </nav>
  <main> U01 ... U07 </main>
</body>
```

原 `article.css` 设桌面 `.mast{height:84px}`，手机约 64px；`.nav{position:sticky;top:0}`。**v07 正式 GLX 里“全篇·刊头”依然是 Flow 的第一个原生组**，但正式截图第一像素已是导航；导航组件挂 `global.overlay` 且 `viewportPinned:true`，来源 `coffee-navigation.js` 的内部 `nav` 反而是 `position:relative`。当前固定是宿主全局平面造成的，无需重写按钮逻辑或引用 v05 的 `window.addEventListener('scroll')`。

目标是：打开 U01 顶部先看见原生刊头、**下面紧接完整宽度导航**，再进入英雄图文；往下滚 mast 随正文上移，导航接触 Flow 内容视口顶部后仅这一条吸顶；向上滚能够自然露出 mast。桌面/手机导航条**背景色和底线贯穿整个内容视口宽**，中间的章名可以限制在合适的阅读宽度，不能因为 `.inside` 居中而让整条背景右侧缺一截。标题是 mast 而非导航的固定副标题；U01 正文大标题仍在第一章内。

### 4.2 推荐最简实现及条件

1. **保留同一 `coffee-navigation.js` Source / chapter IDs / 组件数据**（七个目标在现有导航实例 `931b8fb6-7308-4876-8e5b-c3cfb5d95d3f` 中已齐）。第一选择是把此导航的**实际根节点**放到 Flow 同一滚动拥有者里，与现有 `全篇·刊头`、U01、其余章节为同级，不是新增第二个长期显示的导航。
2. 真正 sticky 应作用在**Flow 可滚动容器内的适当根包裹元素**，满足它所在的 sticky containing block 覆盖后续整篇内容。**把 `position:sticky` 写在一个仅 48px 高、或祖先被 `overflow:hidden` 截断的嵌入局部网页内，通常不会吸住整篇**。下一轮先读实际渲染 DOM、定位滚动祖先、验证此条件；不能因 v05 普通网页可用，就假定 GLX 的 Source/web 节点同样可用。
3. 保留原来的按钮 `port.execute({type:'scene.go',sceneId:locationId,targetInstanceId})`、`port.read().reading.progress/activeInstanceId`、点击可用状态、键盘焦点与 U05 深色导航。宿主 `src/shared/flowReading.ts` 当前已有基于**实时目标 rect** 的导航插值、布局变动重测、输入中断与 reduced-motion 处理；导航 Source **不再另外调用 `scrollTo` 或第二个定时器**。
4. **精确落点只有一份顶部补偿**：目标章节的实际 `scroll-margin-top`（或由宿主按导航高度统一折算）应包括吸顶高度 + 一点内容呼吸距离；不要同时在滚动父层再叠 `scroll-padding-top`。导航高度随字号、折行、390px 行高变化时取实际值并更新同一定位机制。未吸顶前点击章节，目标落下时导航已吸顶，须按**落点时的 sticky 几何**计算，不能固定猜测 scroll 结束延迟。
5. `nav` 根背景/边框及 progress 的坐标用实际 **Flow 内容视口宽度**；`.inside` 仍可限制到 1280/1440 的最大阅读宽，并用手机 7 等宽/可读分布（必要时水平滚动且标明当前章节）防溢出。不能对导航之外的正文突然增加第二套“安全区”；宽度属于整块画布/真实 Flow 视口。

**原生身份取舍**：最优是保留原来的导航实例 + 定义并改定位方式；如果宿主不支持把已在 Global Overlay 的实例原样移入 Flow，允许经正式作者事务对同一 Source 定义重新投影，但必须报告“保留/替换了什么 ID”，不偷换成“183 个实例全部未变”。mast 三个原生文本与七章章节标题必须保留独立可编辑；不能把整篇和刊头合并成一个 HTML。

### 4.3 若当前宿主无法做 Flow sticky

- 首选**软件线最小能力**是让 Flow 中一个原生根组/组件以其**现有阅读滚动容器**为 sticky owner，支持 `top:0` 和自然正常流占位，发布与编辑使用同一语义。不能只在导出端临时 hack 一条固定导航。
- 如果改宿主 sticky 属于高成本且导航外层已能按真实位置信息定位，可退而用**仍然只有一份**现有 Overlay 导航：其位移/透明度从同一 Flow 刊头尾缘的只读 viewport rect 派生；碰到顶端后固定，反向回来解除。这要求几何事实的稳定暴露而非独立滚动监控。此方案对视觉正确性可接受，但维护难度高于纯 sticky；不应成为默认架构。
- 不采用：固定 Overlay + 复制另一份 Flow nav + 视觉交叉淡入；`setTimeout(...,1350)` 对齐滚动；复制 v05 `article.js` 再监听 `scrollY`；为了导航在所有组件外创建新“safe area”框架。

### 4.4 导航验收门

初始帧 mast 可见，导航确实在它下面；滚到 mast 尾缘时无跳动地吸顶，反向回到 mast 时自然解除；内容视口边到边无右侧白/黑窄边。U01/U03/U05/U07 点击落点在真实可读标题/章节开头，不露上一章残字、不遮挡本章首行；不连续点击、不跳闪。操作系统减少动态开启时零强制平滑。人工滚动打断任何正在运行的跳转后，当前高亮/进度统一。浏览器 back/forward 或作品既有历史行为应**逐项验证现有支持边界**，不因导航迁移无意丢失，也不擅加一套 HTML `history.pushState`；当前导航 Source 不包含 URL 历史实现，不能把“保存阅读进度”误称为“浏览器历史原本已完整支持”。

## 5. 七章持续主体与六段交接：依据 Owner 新方向收敛的实施建议（2026-10-23）

### 5.0 优先级与“持续存在”的操作定义

**新 P0：全篇尽量始终能追踪同一个叙事主体。**它可以以独立 Runtime 物件存在，也可以**进入既有摄影的物件/果堆/麻袋，成为场景内的实体**，或交由 U03/U05/U06 的局部程序承载。进入后，照片或程序中的那个对象就是主体的驻留形态，不能把 Runtime 画面隐藏后便不再考虑它的去向。

- **独立显形**：在页间留白、分层摄影或需要强调运动的时刻，Runtime 绘制单体并按原生视觉插槽行进。
- **入景驻留**：主体朝摄影中的某个**明确目标**移动，在袋口、豆堆、果堆或真实遮挡边缘完成缩放/遮罩/焦点交接；进入后由照片中可辨识的物体承载它，在该照片停留的阅读区间持续可见。照片滚走后可以通过下一幅视觉焦点延续。**不是贴一个看起来悬浮在照片上方的小豆子**。
- **局部接管**：主体进入 U03/U05/U06 已有局部程序的可观察对象后，Runtime 主体停止单独绘制，由局部程序可见地承载；离开时按实际内容演示状态或有明确语义的代表状态交接。
- **允许暂时不在视口中，但不允许无解释地断开叙事身份**。长文阅读时照片可随正常 Flow 滚出，正文仍可通过下一视觉插槽接上；不要求给每一段文字附加永久浮动角标，也不要求读者一秒不见物件就违约。
- **连续优先级**：明确入画目标与身份承接 > 摄影/材质可信度 > 与滚动一致的位置连续 > 精致的遮挡和景深 > 必要的材质变化；复杂物理 morph 排在最后。任何技术炫技如果破坏真实照片或科学含义就删减。
- **摄影真实性边界**：U02 与 U04 的纪实照片来自不同地点和拍摄者，“单体进入照片”是**编辑式视觉隐喻**。可以让动画物件与已拍到的咖啡果/豆在遮挡区自然合并，但不得对外声称它本来就在该批真实照片中，不能抹去人物动作或出处。进入果堆时优先采用已存在的可辨识果实作为**接替显示者**，而非永久篡改照片增加虚构物体。

## 6. U03 科学编辑重设计：由“近似三张图 + 大量矩阵”改成“看一眼就能分辨的组织标本”

### 6.1 科学基准必须固定到同一时点、同一个可比较的种子尺度

**唯一比较时点：开始进入干燥环节时的代表性材料。**

| 材料 | 必须画出的实体 | 不应错误画出的东西 | 显性图示差异 |
|---|---|---|---|
| **日晒 / Natural** | 完整咖啡果：鲜红外果皮、较厚果肉及黏液、内侧羊皮层、两颗种子；保留整体果皮体积。可局部“开窗”显示内部组织。 | 不要画成被剥成两颗裸露绿色生豆；也别把“日晒”误说成只能太阳暴晒。 | 主体外形最大：**红色封闭果实，局部剖面见层**。 |
| **水洗 / Washed** | 外果皮/大部分果肉和黏液已去除；**仍有淡米白、纤维/纸质的羊皮层**包裹的双籽轮廓，近表面不显黏液膜。 | 不要等同已经去壳的平滑绿色生豆；不能画成与蜜处理完全同样黄褐湿润表面。 | 同尺度下是**清爽的米白/浅茶色纸质表面、较干净、能看到羊皮层纹理**。 |
| **蜜处理 / Honey** | 外果皮/大部分果肉已去除；羊皮层仍在，**外表有可见连续或斑块状的琥珀/金色半透明黏液、局部粘连与高光**，保留多少可变化。 | 不要出现红色完整果皮或直接往咖啡中加蜂蜜；不要把黄色深浅当成严格工艺量纲。 | **同一羊皮层基底上有明显一层粘稠透明膜**，从普通缩图就可辨。 |

**关键纠正：**“日晒/水洗/蜜处理”并排展示的对象最外形状可以不同——日晒包含整个果实因而天然更大；统一比较的应是**内侧两颗种子的尺度、视角、光源与核心结构的相对位置**，而非把整颗果实强制缩成与水洗两粒羊皮豆一样大。一般处理法存在操作变型；图像不能把代表性示意夸称工艺标定或含水量实验。

### 6.2 推荐主体构图：“同视角大标本 + 单侧切窗 + 直接层标”

**桌面比较视图**仍三栏，但改为 **“实体表面可直接区分 + 近同尺度的组织剖面插窗”**。

- 三个画幅使用同一注册画布/相机视角，光线从左上，浅米色底，不画七彩科学卡通球。主材质占主要面积；小右下角各嵌一个一致视角的**半剖切窗**，红色果实（果皮/果肉/黏液/羊皮/双种子）、水洗（外壳虚位+羊皮）、蜜处理（外壳虚位+可见黏液+羊皮），断面轴线一致。
- 切窗不得反客为主或遮盖材料差异：**在关闭所有标题、表格和注释的情况下，三件物体本身已经显著不同**。切窗负责“为什么不同”，主体材料负责“眼睛看到什么”。
- 标注用真实**中文 DOM 文字**（桌面建议 `外果皮 / 果肉`、`黏液层`、`羊皮层`、`种子`），引线 SVG 只负责锚点、连线、与切窗区域匹配。避免文字在生成图像内部烧录以免乱码和不可编辑。画面至多同时显 2–3 个主要引线，详情展开完整 4 层，颜色与下方矩阵四个 swatch 精确同义。
- **“已去除的层”用带标签的淡虚廓**，并在图例写出“虚线：原位置，当前不存在”；虚线不能像仍有一层灰色果皮，也不要用虚线把水洗、蜜处理勾出同样大圆外轮廓而掩盖实体差异。
- 放大详情：左为占较大面积的物体与圈出的“显微式**示意**放大窗”（不是实际显微照片），右边完整层列表、步骤说明与一句工艺边界。若局部几何未准确对应，宁愿单独绘制一个抽象层结构窗，也不把生成模型的幻觉纹理画出毫米精度。
- 物体本身的**写实材质**采用真实拍摄参考 + 一致性的生成/重绘；植物组织的名称、包覆和去留由程序/矢量确定。把素材切窗标为“结构示意，厚度不代表实际测量”。

**具体改动点：**`programs/u03/build_u03.py` 中的 `annotations(mode,prefix)` 目前只有 `path/circle`，绝无可见 `text`；`diagram()` 把 `*-section.webp` 与标注 SVG 叠加；`.compare .material-leaders{display:none}` 又隐藏了比较页引线。下一轮应新建可控的 `label/leader anchors` 数据，CSS 与 DOM 显示标签，不在固定 SVG 上补几行小字了事；更换 3 张主剖面后从该脚本统一生成 `u03.html/u03.css/u03.js/content.json` 和 SVG，再使用正式作者事务提交至 r215 的 U03 目标实例。**本轮绝不运行脚本**，以免覆盖现有源包。

## 7. U06 科学实验的摄影级表达：精确数值不让位于材质

### 7.1 现状与不可更动的行为合同

正式对象 `8f45751d-9cc3-49dd-ba88-c645759f022c` 是本来就成立的局部实验。v06 原始检索实现 `../v06/programs/u06/water.js` 有独立 `W=660,H=610` Canvas：`glassPath()/glassHandle()/funnel()/draw()` 画容器、漏斗、水、液面、玻璃边线、光晕及标记；`readout()/step()/switchMode()/add()` 持有实际状态与显示。材料只在画布里是插画风，科学关系无需翻案。

- 模式一 **萃取示意**：看水接触咖啡粉、部分可溶物进入水、粉渣由过滤留下；这不是可精确求解萃取率/风味的专业模型。
- 模式二 **加水稀释**：从已移走粉渣、初始 200g 的滤净饮品出发，咖啡来源溶解物质量固定 3g；加清水 `a ∈ [0,100]g`，总质量 `200+a`，质量分数 `100×3/(200+a)%`。例如 `a=0→1.50%`；`a=100→1.00%`，总质量 300g，而溶解物仍为 3g。原动画中的颗粒是**符号化物质标记，绝不是可见真实咖啡分子**；其数量或画面密度不应被解释为实测颗粒数。
- 保留 `data-*` 绑定、滚动高度报告 `coffee:height`、切模式、滑块/预设/重置、键盘语义、WebAudio 在用户触发后播放、水流反馈、`sessionStorage` 状态与 reduced-motion/可见性管理。执行时如发现 r215 的 U06 内嵌源码与 v06 文件有差异，以**正式工程当前代码**为准，先做函数职责对照再改渲染器。

### 7.2 两个真正可执行的材质方案

| 方向 | 画面与实现 | 优点 | 主要风险 | 裁决 |
|---|---|---|---|---|
| **A. 摄影级分层容器 + 程序液位/标记（推荐）** | 制作透明玻璃/瓷杯的背层、前沿厚度、把手/反射、底部投影和一张独立液面高光素材；液体体积仍由 `draw()` 或 CSS/SVG mask 在杯腔形状内随质量变化，前层折射/反光覆盖其上；漏斗为独立纹理层，水流与代表性标记程序画。 | 材质质量上限高；液面与质量仍由程序精确对应；角色清晰（资产给真实，程序给逻辑）；适合作为可迁移的实验组件参考。 | 透明玻璃边、杯腔液体裁切和不同液位的高光容易不协调；导出须完整打包分层资源。 | **主方案**，先以空杯/满杯/半杯静帧证实再投入全动画。 |
| **B. 现有 Canvas 全程序写实升级** | 用渐变折射、边缘双高光、内外壁光、微透视、投影和精细水面 shader-like 绘制重新修饰 `glassPath/funnel`；状态逻辑不改。 | 低新素材成本、纯代码响应尺寸、导出闭包简单。 | 扁平形制由 Path 主导，继续增加 Path 很容易成为“画得更复杂的插画”，无法自然匹配 U01/U05 的物件质量。 | **低成本备选/原型对照**；只有 A 的分层遮罩导出与材质动态明显失败时采用。 |

### 7.3 推荐视觉分镜（开放式编辑图，不必延续圆角卡片）

**整体编排**：U06 继续浅绿色纸面，左侧一套**带真实玻璃厚度的玻璃杯/滤杯观察舞台**，右侧大面积留白展示当前数值、解释与操作；细直线与字体延续整篇编辑式写作。去掉厚重、无内容收益的圆角“实验卡片”边框，保留少量轻纸色衬托保证文字和透明玻璃可辨。

1. **“从粉体到液体”阶段**：上方摄影级滤杯/滤纸与真实研磨粉纹理，下方透明玻璃接液杯（注意粉/水接触区域分开）；细水流有受控轨迹，水流经粉体后形成较浅的咖啡液。程序只绘制水流/滴落/物质标记，三阶段脚注准确描述；颗粒可用稀疏概念标记配合**“示意”**提示，不伪装真实颗粒悬浮照片。
2. **“水再多一点”阶段**：滤器视觉退出/折叠到旁注，只留下已经滤净的杯子（杯中没有可见粉渣）。液体初始显示既定高度，加入 50g/100g 后**液面连续上升**、液色适度变淡；同一 3g 视觉标记总数保持不变，其在更大液体范围分散，而不是点击加水时凭空生成更多“溶质”。必要时以透明稀疏点、图例注明“示意分布”，不依赖肉眼去数点。
3. **分层材质**：`glass-back` 为透明轻灰折射和被液体遮挡的背壁；`fluid-fill` 用杯腔多边形/遮罩夹裁，`fluid-surface` 为随液位移动的椭圆液面与接触边缘；`glass-front` 叠厚玻璃反光、前壁纹理、杯把和杯口线；`contact-shadow` 与桌面接触不随水位飞走，底部折射可随深度轻变。避免完全黑的、不透明的“杯中咖啡圆盘”。
4. **数值**：保留醒目的 `1.50%→1.00%` 动态主读数；辅助 `原饮品 200g / 加水 a g / 总质量 200+a g / 咖啡来源溶解物 3g（不变）`，同页公式一次解释，后续重复强调 **3g 固定**即可。大数、线框/等距图中的标签不随玻璃折射而失去对比。
5. **互动**：模式标题与“看水经过一次/再看一次”置于舞台上方或紧邻下方，滑块/加 50g/加 100g/重置与数值相邻；不能把按钮藏到长图滚到底部。用户加水时只运动液位、密度/色彩和水流（若开启音效），**不触发全局 Runtime 的第二套液体变化**。

### 7.4 素材和渲染边界

- 下一轮生产同视角、透明通道一致的 `u06-glass-back`、`u06-glass-front`、`u06-glass-rim`、`u06-glass-shadow`、`u06-filter-paper`、`u06-coffee-grounds` 等素材；若是 WebP 分层，单一拼版主视觉保持 RGBA 原始文件便于后修。玻璃轮廓先在当前 660×610 坐标系内登记罩形，输出资源可 2× 分辨率，再以程序适配设备 DPR。具体资源命名可在实施时定，但需集中登记到正式源包资源与 GLX 资源闭包。

### 8.2 依赖 Codex 当前导航/视口线，但本轮不介入

- **视口真实右边界**：编辑/试运行/离线的整个 Flow 背景、正文内容视口和导航条是否同宽，右侧是否仍有莫名保留边、全局 Overlay 是否相对错误的父画布定位。这属于**软件坐标/渲染所有权**；不要在 v08 创作里用 `margin-right:-22px`、`width:calc(100% + Npx)` 或旧安全区等“艺术补偿”掩盖确定性宿主 bug。
- **导航精确目标**：`flowReading.targetTop()` 当前直接按目标实际 rect、scale、`scrollMarginTop` 计算，并能在动画中随 Layout 重测；要检验 Codex 修复后“最终停在标题可见位置”确实成立。若此问题仍存在，归导航宿主线；本方案只决定 sticky nav 应补偿多高，不能修软件时序。
- **Global Overlay/Underlay 实际可见面**：目前不同 plane 的对齐、z-order、canvas DPR 与根视口定位需在下一轮只读实测一次。工程可运行不保证所有画布处于同一空间坐标。若 Codex 正在改变这些值，原型应使用修复后的公共接口，不因本设计抢修软件源码。
- **重要并行原则**：U01 素材拆分、U03 概念图设计、U06 材质草图都可以与 Codex 软件修复并行准备；只有需要真实 viewport 绑定的 **Flow 插槽 / sticky / 导航最终验收**依赖公共接口稳定。无需等“软件所有其他可能问题都审查完”才创作。

### 8.3 目前尚**不能**当成已存在的接口

**缺口候选 A（优先，复用性最高）：以已有原生实例 ID 获取 Flow 实时可视几何的只读快照。** 当前 `teacherController.ts` 的 `reading.progress` 只给归一化阅读值，`flowMotion.scrollTop` 只在某次导航运动对象中体现；没有公开的“给定图片/原生组 ID，返回当前可视 rect”的稳定通用方法。U01 真实物件插槽若必须对齐原生图片，需要以下**最小充分事实**之一（示例签名是方案，不是已经实现的 API）：

```ts
// 可并入现有 TeacherControllerPort 或现有 Flow 对应的只读观测服务；命名待软件线决策
readFlowPlacement(targetIds: string[]): {
  viewport: { left: number; top: number; right: number; bottom: number };
  scrollTop: number;                 // 同一 Flow owner 的真实坐标，不另建 scroll state
  targets: Record<string, {
    rect: { left: number; top: number; width: number; height: number };
    visible: boolean;
  }>;
} | undefined;
```

要求：仅返回**允许被当前内容实例引用的**标准 Flow 实例布局；与既有 `reading` 的滚动/ResizeObserver 观测节拍一致，布局变化/图片解码后刷新；矩形是**当前播放视口 CSS 像素坐标系**，而不是作者设计画布帧；不向局部内容开放读取任意宿主 DOM/密钥；对需要的少数 ID 批量读，不能为全篇 183 个实例每帧做查询。**只有实测无法从现有作者可用的 Flow 插槽 Source 定位得到相同精度时才申请**，不因为“新 API 看起来通用”就开发。

**缺口候选 B（更窄，条件型）：Flow 原生根级 sticky 元素支持。** 若导航 Source 放进真实 Flow 流内后，因宿主中间 `overflow/transform/containing block` 导致不能覆盖整篇 sticky，最低要求是“一个现有 Flow 根直接子元素可按同一滚动 owner `position:sticky;top:0`，占正常流空间并在编辑/试运行/离线一致”。先尝试改作品装配和组位置；不需要普适动画时间轴、通用 overlay 布局 DSL 或第三套 Nav 服务。

**不构成立项理由**：全球同步复杂转场动画编辑器、逐元素拖拽曲线、多份 page state、对 U06 水声的全局 Timeline、读取所有 HTML DOM 的插件、Flow paper 二次背景层、全局万能 safe-area、每章单独滚动监听、通用科学粒子 3D 引擎。这些都超出作品质量瓶颈。

### 8.4 A/B 两个接口不通过时的安全备选

- **U01**：不开可移动前景演员，首屏继续使用原摄影单一杯、下半改为 Runtime/原生果实的一次可控交接；局部展示区由原生 Flow 自身排版。可以降低一点“杯子一路飞过文章”的动感，但不能牺牲画面可信度或制造双杯。
- **导航**：只保留一个现有 Overlay Nav；如果可用公共几何事实来自现有接口，就让 Nav 位移绑定原生 mast 的几何阈值（不新建滚动状态），达到相同视觉；否则在明确说明无法恢复自然 sticky 的前提下把接口缺口提交软件线，**不伪装本任务艺术已验收**。
- 所有退化应明确记录最终用户能观察到的**具体差别**，不能用“兼容性方案”隐瞒未完成的体验目标。

- 三个视觉状态作为**审片帧**：`extract-before-water`、`extract-active`、`dilute-0g/50g/100g`，各有一张桌面与一张手机布局对照。所谓“真实”主要体现在玻璃厚度、明暗反射、液体边界和接触投影；过度写实导致液位看不清时降低色彩复杂度，保证科学解释优先。
- 延续原脚本 WebAudio 无素材购买需求；如果未来换入真实水声，须另查权利/体积/静音和操作手势约束，本批**不把换声音列为先决条件**。

### 9.4 明确不重做的素材

- U02 分选、咖啡园和手中打开果实的纪实摄影，以及 U04 袋中生豆、搬运人物的真实照片；附原作者/时间/许可，勿“统一风格”重生成一遍。
- U05 已验证的生豆/转黄/熟豆三关键帧与局部程序控制；与全局材质对齐只允许必要的配准/遮挡，**不能破坏 U05 用户可拖进度**。
- 七章主文案、章节顺序、图注/来源、题意、手动操作、U07 感受提问；没有具体问题证据的地方不重新设计。
- v07 现成过渡的算法与母图：`assets/source/*.png` 作为回退与切分参考保留，`assets/runtime/*.webp` 可部分继续使用；无须“一次性重生所有形态”。
- 不采购专业 3D 模型/特效插件，不生成通用背景墙，不另起全篇巨大 HTML 模板。

### 9.5 素材目录和文件身份原则（实施时）

设计源文件可继续放于 `design/v07/` 关联源目录，并由实施者按版本组织新的 v08 创作支线或资产目录；**不能覆盖 v07 正式母图/GLX**。采用“透明母图 → 注册参数/遮罩 → 面向运行时的压缩素材 → 正式组件资源引用 → GLX 保存 → 离线闭包”单向映射，所有中间帧、提示词、衍生来源及许可在下一轮的素材台账更新。正式编辑提交只能用果铃规范作者事务；只把 `u03.js` 或 `water.js` 写进仓库不会自动改变已有 r215 GLX。高质量图片不能压缩到失去杯口釉质和黏液半透明细节；反过来大图也不能引起手机明显加载卡顿。

## 11. 可审片、可测量、可否决的 v08 验收定义

### 11.1 P0 艺术指标

1. **主体持续可追踪且唯一**：U01 独一杯/果；U02 红果进入分选照片果堆并在那里驻留；U03 由选中标本接管；U04 生豆进入袋口/豆堆并在那里驻留；U05/U06 由局部程序接管；U07 返回原摄影杯。1440/390 的真实滚动连帧应能指出每次谁在承载主体，不能只有先退场、过很久再凭空出现；任何时刻也不得出现两个竞争的同类主体。
2. **U01 高质量**：与 v05 原摄影 A/B 对照，看不出低级抠图/换光源/把手错配；摄影杯—果实位关系一眼明白，且不是“播放一次宣传片”才能看懂。不会仅仅为了变形丢掉正文阅读性。
3. **滚动锚点**：慢速自由滚、滚轮快速跳过、导航连续点击、向上反向滚时，Actor 的起点/终点都落在**真实原生图位**。空间轨迹不遮挡任何正文、交互、图注；中途停止后没有对象自己继续追逐旧滚动进度。
4. **手机主动构图**：390px 和窄于 360px 视图重点看标题完整、杯子完整、果实完整和长文不被右侧浮物压住；不要求手机与桌面走同一条曲线。操作减少动态后不出现空白断帧。
5. **导航阅读回归**：初始 mast 在导航上；mast 正常滚出；Nav 到顶自然吸顶；反向恢复；横条铺满正确内容视口；点击各章精确到位、进度和高亮同步。不以肉眼可见跳闪、固定延迟或第二导航换取效果。

### 11.2 P1 科学图与实验指标

1. **U03 去掉标签盲辨**：三材料主体在普通尺寸下即可对应日晒完整果皮、水洗可见羊皮但无明显黏液、蜜处理羊皮外有明显黏液。三者同视角、内双籽同尺度。图解有实在的“果皮/果肉、黏液、羊皮、种子”中文标注和准确引线；去除组织的虚廓有解释；在手机不需要先读矩阵才能理解物体。
2. **U03 状态不回退**：切三路线、展开详情、打开比较、返回（含恢复此前详情）、键盘方向键/Home/End、实时高度、焦点保持均与 v07 合同一致。
3. **U06 玻璃真实且读数明确**：玻璃前后层、反光、底影、液面、稀释色彩协调，科学液位可读；`baseMass=200g,soluteMass=3g` 的正式原模型保持，`a=0/50/100g` 分别显示约 `1.50/1.20/1.00%`，总质量 `200/250/300g` 且溶质 `3g` 恒定（显示按原精度格式）。抽象溶解物标记不可被读为真实颗粒计数。
4. **U06 行为不回退**：萃取步骤、进入稀释、滑动/预设/重置、声音开关（触发后生效）、状态恢复、可用键盘/触屏与减少动态、离开/返回视口的动画生命期稳定。

### 11.3 技术保真与抽样矩阵（用现有证据复用，重改处必新验）

- **正式作品优先**：只看 `art-studies-offline.html` 的演员中间帧**不构成**成功；必须看正式 GLX 的 Flow、试运行与真实离线 HTML。为 U01 输出**单独连续慢滚审片**，附 A/B/C/D/E 定位与可读文本。
- **桌面 1440px**：七章正文关键截图；六段过渡各 0/25/50/75/100 的真实导航中间帧，记录对象位置与可见性而不只看形态 `phase`。文字长段停留时取至少一帧验证不被遮。
- **手机 390px**：七章顶/中代表帧，U01 标题→摄影→下半果实 5 帧、U03 全比较与详情、U05 滑块 3 帧、U06 加水 0/50/100g；六段只复验**已改变且风险最高**的中间帧，勿机械重复无变化证据。
- **边界条件**：宽度 320px、390px、768px、1440px 至少对改动目标做代表性检查；相同内容下改变窗口宽度、字体回流、图片尺寸就位后原生锚点应自动重配；书签/导航返回、连续快速 U01↔U07，轮滚手动中断、`prefers-reduced-motion`、无网离线、首次加载字体/图片顺序分别挑危险路径检查。
- **一致性检查**：明确比较编辑/试运行/离线；正式工程保存、退出进程后冷开；原生 mast/大标题/图片图注及 U03/U05/U06 各自程序仍是可选、可修改的独立对象；素材打包没有外链断裂，媒体署名没有丢失。GLX 保存 revision 按真实事务自然增加，不假装仍是 r215。
- **主观签收标准**：艺术复审须真实查看摄影边缘、材质分层、物件自然落位及文字节奏；**U02 果堆、U04 袋口必须各有一次可辨的入景—驻留—接出/转焦点**，不能用直接淡出替代；如 U01 混合素材的拼接质量明显不如 v05 原片，即使动画程序全通过也判“未达参考水准”，退回 S1 的保守摄影方案。最终 Owner 的艺术判断高于开发者自评的 accepted。

### 11.4 哪些情况属于“可以停，不再打磨”

- U01 开篇/果实交接读者看得懂、没有明显穿帮，导航已经恢复，U03 一眼分清三路线，U06 实验既写实又可计算，U05/纪录摄影没有受到负面干扰，正式 GLX 与离线功能一致。
- 其余没有妨碍阅读的轻微色差、复杂形变中个别看不出的中间帧、不直接涉及作品的通用编辑器边缘 bug，**不继续扩张为新一轮全面软件审查**。
- “参考价值”指下一作品可以学到“原生文字/照片 + 唯一演员 + 受控视觉插槽 + 科学局部程序 + 精确数值”的生产方法，而非本篇开发出新引擎或追求每一件物件都能永久 morph。

## 12. 下一轮的实际交付清单与本轮结论

下一轮正式实施时，交付者应一并给出：

1. **v08 正式 GLX**（保留 v07/r215 原件）及可离线阅读的完整正式 HTML，而不是仅独立动画样片。
2. U01 摄影分层的原片 A/B 和 A/B/C/D/E 实际滚动帧；展示 U01 唯一杯、U01 唯一果、U07 同款杯；明确归档套用的原创/历史资产来源。

**最终决策（Owner 2026-10-23 补充收敛）**：采用 **“持续主体 + 入景驻留 + 局部接管”**。照片中的果实/豆堆/袋口是有意义的**驻留位置**，而非 Runtime 退出后留下的一幅不相关摄影；独立演员只在留白与转场时出现，避免悬浮重复。六段以明确到达和可追踪身份为主，物理 morph 非必须。U01/导航仍是首个 P0 样板，另需在 U02 果堆、U04 袋装豆堆各打通一次真实入景原型，才能声称本机制可复用；U03/U06 按 §6/7 改视觉，U05 保留交互。优先作品级的原生插槽、遮挡和视觉匹配，不建通用时间轴；无法稳定锚定原生物件时，仅提出 §8 所述最小只读布局和 sticky 能力。
