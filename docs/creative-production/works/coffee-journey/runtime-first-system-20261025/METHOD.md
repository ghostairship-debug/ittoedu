# Runtime-first 创作方法与职责

## 1. 选择依据

Runtime-first适用于多个视觉对象共享连续时间、材质、镜头或阅读阶段，拆成许多独立节点后同步成本明显增加的作品。咖啡的杯、果实、种子、豆、粉与液体有共同视觉生命周期，集中进同一Scene Runtime能用同一phase直接计算当前画面，反向和跨章不依赖历史到达顺序。

它不适合成为所有作品的唯一方式。静态图文优先原生内容；离散状态展示可用原生状态；真实空间关系可用Spatial；互动游戏可自行拥有模拟循环。既有局部程序已运行可靠时，不为统一名义强行改写。持续动画并不自动改善叙事。

## 2. 四类成果

| 类别 | 软件或作者职责 | 本轮证据与边界 |
|---|---|---|
| 软件能力 | Flow阅读事实、同批测量、runtime作用域/暂态motion、资源闭包、组件插入/身份与声明引用重绑、唯一事务、撤销、保存、冷开、正式导出、隔离观察 | 咖啡保存/编辑证明与MCP真实回执；不新建平行保存/文件/组件库 |
| 可执行资产 | 已有连续变量配方、新连续阶段背景、可嵌入事件绘制/关键点采样模块 | ASSET_INDEX列实际包、输入与依赖；尚未验证的抽象不冒充可用组件 |
| 创作方法 | 主次关系、阅读节奏、主体连续、色彩归属、响应式构图、互动位置、艺术取舍 | 这些由模型判断；可以作为参考，不能固化为七章模板 |
| 具体素材 | 摄影、生成图、材质、纹理、关键帧、音视频 | 咖啡14项素材与七章分镜标reference；授权与生成属性沿原台账，不默认泛化为公共素材 |

## 3. 原生与Runtime边界

原生负责需要人工独立编辑的正文、阅读顺序、章节锚点和正式对象。Runtime负责确实共享动态时序和合成关系的主体、材质及必要标注；局部实验负责输入与解释性计算，通过少量语义状态与全局场景协作。导航程序调用宿主正式导航，不自行维护另一份滚动owner。

咖啡最终保留47个原生文字、7个章节锚点和3份源码定义/owner；总实例76。v07历史记录为183实例，当前减少不等于质量下降，也不是受控的速度实验。原生可编辑性通过UI改字、Undo/Redo、验证副本保存和冷开实际证明，源码/参数保存在GLX。暂态呈现不写持久正文或工程History。

避免两个相反错误：把全部作品变成单一不可独立编辑的Web盒子；或把每个粒子/材质拆成需要模型维护身份、布局与同步的原生对象。边界由人预期的修改方式和对象耦合决定。

## 4. 连续叙事的实现与艺术判断

### 进度与主体

只读取一份当前阅读事实。需要按章校准时，使用scope.measure把所有章节与终点放在同一几何采样中，映射为阶段值；布局变化后重新校准，连续滚动时不要每帧追逐布局。绘制函数从当前phase和实验状态直接求当前画面，任意跳转、反向或导航中断都能接续。

主体交接需要看得懂的变化依据：同一注册点、尺度、运动方向、质地或语义承接至少有一项保持。转场中的位移、遮罩、材质混合是手段；不能用变化数量替代故事。章节长度、过渡带和主体节奏由正文及观察任务决定。不要为了每章看起来统一而强制同构。

### 色彩

先确定大背景所有者，再调整配色。咖啡的失败直接来自正文区域不透明背景与全局Scene同时切换；最终以唯一Scene背景、透明正文组、同phase文字显隐解决。U04到U05通过暖砂/褐/深炭，U05到U06通过深炭/绿/淡绿衔接，保持章节区别。

通用规则是统一归属与同步；不是所有作品都用渐变或同色系。文字遮罩、透明合成和进入退出均须与主体一起看。大面积渐变不能修复被另一层遮住的背景。新组件采用验证再次复现白色页面遮住global underlay，证明装配前提需要写清；并不需要增加一个背景API。

### 响应式

用每种主体的清晰配置管理宽度、位置、视觉占比、文字避让和过渡状态。1440桌面可左右分工，390移动端可上下分工或在文字退场后让主体居中。相同场景不要求所有主体同尺寸：杯、豆、烘焙器、萃取器具的形状与解释任务不同。

咖啡此次提高手机正文/导语字号，并修复开篇注释与杯、烘焙标签与底部说明碰撞。参数应集中；在关键画面和实际滑动中判断裁切与密度，不只看静态hero。避免把所有层都加遮罩来换取局部可读性。

## 5. 生命周期与性能

单一渲染调度器合并阅读、状态和布局事件。没有事件时不循环；确实在播放的实验才拥有活动RAF。隐藏层不做无效变换，未变化值不重复写样式。布局测量和像素处理应避免放入高频绘制循环，资源解码结果复用。

原生文字的暂态motion使用持久任务与事件写入，不每帧创建任务；退出作用域取消，恢复作者样式。suspend可能只是暂时离屏，不能无条件恢复所有文字造成闪现；退出运行与作者视图隔离要以宿主真实生命周期验用。咖啡前后作者DOM均opacity1、r264不变脏。

实验离屏/后台/suspend停止，重新进入读取当前状态。普通scope.state适合运行会话内语义数据；要跨工程托管重绑时使用已声明stateBindings。局部控件单独销毁、全局仍存活的active残留是当前咖啡条件性边界，通用化时必须明确，不因正常离章通过而宣称所有销毁路径通过。

性能数字辅助诊断。咖啡实测空闲1秒新增绘制0；rAF含离屏节流与重复时间戳，不能作为FPS成绩。截图/连续帧/录屏、操作响应、页面异常与真实读者感受共同决定是否通过。长时内存、实体手机与热降频未认证，应如实保留范围。

## 6. 最小实际装配流程

1. 明确内容目标、关键观察与互动后果，决定哪些内容共用Runtime。已有成熟策划直接承接。
2. 读ASSET_INDEX短索引或asset.search，选择少数相关资产。已有清楚目标不通读工程。读取契约及必要源码；不合适则拒绝。
3. 新建正式GLX，使用已存在空白页或按内容新增Flow/Slide/Spatial。project.list返回路径，listChildren返回页面句柄；不要猜ID或把文档句柄用于要求页面的配方。
4. 普通正文/布局可批量表达成HTML/CSS或对象草稿，由project.apply正式测量装配成独立内容；耦合程序限定在局部。软件管理身份、资源与引用闭包。
5. 模型提供视觉、计算、文案和素材选择，软件负责确定性装配。源码用from读取相对依赖；多项已有路径用operations一次事务。主Agent只写其独占工程，独立媒体/研究才并行。
6. 实际观察代表性关键画面并操作核心实验。发现问题局部修正；本任务明确要求七章/双宽/冷开/离线，因此补足这些范围，不能以默认首版省略。
7. file.save确认savedRevision=currentRevision且dirty=false；document.export确认官方离线产物。独立进程打开及file://运行分别检验GLX与导出消费者。

现场发现：旧connect-mcp.ts样例的project.save在当前MCP未注册；实际正式保存工具是file.save。记录此说明漂移，未修改并行Codex的软件范围。

## 7. 两条路线与真实成本

参考增强路线先用短索引、成熟组件和自动装配，省去重复身份/依赖/滑杆工作。高自由度路线从艺术方向和内容结构开始，可完全自行编写Runtime；仍可复用生命周期与资源服务。两者可组合，既有组件的默认蓝色卡片不是新作的默认艺术风格。

可稳定复用的是输入契约、资源闭包、事务保存、状态同步和事件调度；不应标准化的是章节数、隐喻、主视觉、色彩、互动数量、素材风格与每章构图。多Agent仅在任务可独立产出且合并成本低时并行。本轮原生子Agent的DevSpace读取长时无返回，改为Root取证、子Agent纯文本独审，避免声称不存在的并行收益。

Luna和主Agent采用同一冻结任务、软件构建及资产版本。各阶段计入墙钟，工具内部执行时间与墙钟分别报告；不把素材或重试移出计时。首次正式保存不自动等于首个可用版本。十分钟未完成继续完成，不减目标；原始产物与外部修订分开。单主题对照只说明本次条件，不能证明普遍速度/质量。

## 8. 反馈与晋升

每次真实采用记录资产、修改、失败、耗时、质量与编辑性影响、正式交付状态及证据。reference可读不等于component；candidate有契约不等于usable；经过正式保存/发现/插入/修改才usable；在不同主题或结构中证明价值后再限定范围recommended。没有独立复用价值的复杂咖啡分镜继续作为参考，不强行组件化。
