**唯一当前作者基线**：[r179 GLX](../design/v05/native/coffee-journey-v05.glx)，Project 11，SHA-256 `e3303319b283afe4284628adb07a06e00251435569cd37268ad9171426e5ab90`；现行交接 [NEXT_PASS](NEXT_PASS.md)。正式独立离线文件位于 `../design/v05/native/coffee-journey-v05-offline.html`，作为现有可回退基线。新创作一律从 r179 的**新命名副本**开始，正式作者状态只保存在 GLX，独立 `index.html` 是视觉设计参照，不能作为整体回灌来源。

## 1. 目标与停止线

目标增加一个目前作品尚不具备、可供未来 AI 参考的创作范式：**跨章节持续身份的可执行视觉物件**。阅读从杯子回溯果实，再经不同加工、烘焙和萃取回到同一杯咖啡；物件随着章节进入、返回或跳跃，在屏幕不同安全位置流畅迁移并切换形态；静态阅读时保持克制。

必须证明的能力：
1. **跨章节连续性**：一份 Runtime 实例、一个有效观看事实来源，不在七章重新创建同一对象或复制七套导航状态。
2. **多形态表达**：图像关键帧／遮罩／粒子／位移按需要组合，支持方向反转和快速目标更新；不是每一段统一叠一层淡入淡出。
3. **前景独立**：背景不拦截点击、滚动、选择，不吞并原生标题／图文及 U03/U05/U06 局部程序；可保存、冷开、断网导出。
4. **可迁移参考**：留下阶段映射、时间线与轨迹配置、资源闭包、修改路径和反例，而非咖啡特供的一整页 Web。

**不纳入本轮**：重写 Flow/TeacherController/组件平台、第二套导航状态、跨章节后台全屏实时双页面、真实流体模拟、3D 引擎、复杂人工关键帧编辑器、持续高频装饰粒子、重新生成全部摄影、学科事实细节及摄影一致性校对。背景效果若损害现有内容阅读，应弱化或放弃相应段落，不因“必须一直可见”硬盖前景。

## 3. 方案设计

### 3.1 单一视觉 owner，不制造第二个阅读状态

**确定采用一份 Global Underlay 的作品级 Source Runtime**。这份 Runtime 同时绘制全篇基础底色、咖啡物件、变形和位置，不再将各章节大面积不透明背景作为独立绘制 owner。前景 Surface、原生对象和三个局部程序全部在 Underlay 之上，背景无需跳到 Overlay 抢占视觉层级。全篇背景的正常可见性取决于清理其上方不透明纸面/章节/iframe 背景；优先修正作品声明，不能仅因默认白纸盖住而否定 Underlay 方案。

**背景统一的具体改动边界（只在后续作品副本实现）：**

1. **项目与 Flow 纸张**：取消当前顶层及容器自己铺设的大面积不透明背景，在作者数据中显式声明透明。当前 `resolveComponentBackground()` 在缺省背景时会回退 `#ffffff`，`resolveFlowPaperBackground()` 在未声明项目背景时又可能回退 `paperBackgroundColor`；因此**仅删背景图层不能透出 Underlay**。候选是明确设置项目背景 `transparent`，并清除覆盖它的 Surface own paint/color 与纸张残余背景，而不是把全平台默认白纸改成透明。
2. **原生背景形状**：逐项识别当前 7 个“背景形状”中哪些只是全幅底色，适合移除或设透明；真正承担边框、局部强调、图形视觉关系的对象仍属于正常前景，不因名称为“背景”一并删除。操作走正式事务/Undo，保组结构及内容身份。
3. **局部程序**：U03 `labs.css` 的浅色 `body.lab-page`，U05 的深色 `body.roast-page`，U06 `water.css` 的 `.water-page` 都有独立不透明底色。正式 GLX 内嵌版本也需检查同类 CSS；改为可透出的绘制方式，局部对比线、图片遮罩和内容控制仍可保留。必要时测试 iframe/Source 宿主本身是否透明，不能只观察外层 DOM。
4. **编辑与交付一致性**：检查正式试运行、编辑器和编译单 HTML 的前景透明语义；现有 Flow 编辑器 CSS 仍含 `.component-flow-paper { background:white }`，如果作者画布显示与交付不同，只对作者明确请求透明背景的情况做窄范围接线，不全局移除默认纸张。
5. **浅深场景交界**：U05 原先是深底浅字，U04/U06 是浅底深字；连续 Flow 滚动可能让两个章节同时出现在视口。由全局背景阶段色/渐变控制主要氛围，实测过渡时两边的关键文字对比度。必要时只保留很小的局部半透明文字衬底或调整文字颜色，**不恢复每章独立的大面积不透明背景**。

**验收顺序**：先只做透明化让静态全局底色在 U01/U04/U05/U06 露出来，证明无漏白和媒体黑框；再加一颗示意物件和三个锚点动画，最后才接入全篇资源。这样能区分“背景看不见”与“动画状态不正确”，避免一起排障。

Runtime 不主动决定章节。每次 mount 首先 `read()` 得到状态，再订阅当前 Flow 的阅读变化；将 `reading.activeInstanceId` 映射到当前七章的正式锚点，`reading.progress` 仅作为全篇进度与边界兜底。**章内连续 scrub 非第一版必要条件**；切章节或进入阈值时按当前视觉状态平滑迁移即可满足本作主目标。锚点从当前 GLX/导航目录读取，映射以作者配置定义；不猜旧 r73 ID，不解析沙箱外宿主 DOM，也不新增平行存储。若嵌套标题会成为 activeInstanceId，先归属到其上级章节再计算，绝不把章节总数简单等同 7 个顶层 heading。

初始化与冷开：订阅不保证回放，先读取当前状态直接绘制静态帧，之后才消费变化；当前进度是阅读会话，不写入 GLX 作者数据。Source 仅负责 `visual = f(chapter, optionalInput, viewport, preferences)` 与插值，形态参数和资产是可修改的工程配置。独立 `scene.go` 不应作为 Flow 滚动入口。

### 3.2 七章视觉叙事时间线

| 章节/时段 | 主形态 | 位置与动态 | 是否与局部程序联动 |
| --- | --- | --- | --- |
| U01 | 首先是咖啡杯；进入“回溯”后切换为红色果实 | 开场避免覆盖大杯照片；从杯的旁侧收缩/淡化后以果实建立共同物件身份 | 无 |
| U02 | 红色果实 | 沿作品留白移动，在人物和照片旁低权重静止 | 无 |
| U03 | 果实→包覆组织减少→种子 | 用分层剥离/遮罩和短位移暗示状态，不默认选定“日晒/水洗/蜜处理”中的唯一支线 | 不耦合 U03 选择；仅展示共同前进关系 |
| U04 | 生豆 | 最安静的锚点，基本静止，必要时缩小/淡化 | 无 |
| U05 | 生豆→转黄→深烘 | 复用 `green/gold/roast.webp`，同尺度过渡；移动至暗场安全位置，避免和主豆争夺注意 | 若能以现有授权状态桥真实复用 U05 的 slider，才做 0–100 同步；否则只保持章节级阶段/弱化以免双时间轴矛盾 |
| U06 | 熟豆→研磨颗粒→溶液视觉 | 采用聚散、轻粒子、遮罩/融解；要表达跨材料形态的变化，不强行对咖啡液做几何 morph | U06 稀释与萃取模型仍由 U06 程序自行持有 |
| U07 | 回到开篇陶杯 | 过渡后收束到安静静态，形成环形叙事 | 无 |

**状态画面少、身份持续**。不必每章一直悬浮一颗巨大豆子；静止阅读中可缩成角落的标本小图，U04 极弱化，U05/U06 主互动时适当隐退。作品中的照片和原生文字始终是阅读主角。

### 3.3 素材和视觉风格

先复用 `design/v05/assets/natural.webp`、`green.webp`、`gold.webp`、`roast.webp`、`cup.webp`，需要时从已有素材制作小尺寸透明精灵/遮罩；U06 粒子可程序绘制。只在实际过渡不能满足审美时补充一份咖啡粉或可溶颗粒素材。不批量生成新摄影、不引入外链图片、避免整图矩形浅色背景贴到暗场产生边框。

**层级与背景**：仅 Global Underlay 负责铺底色、章节气氛和持续动效；上层对象保持内容身份。物件可以出现在部分文字或图形后方，允许少量视觉重叠，但关键文字/按钮对比度与指向性必须清楚；`pointer-events:none`。静态阅读时弱化、切换时短暂强调，390px 使用独立的安全位置配置。不要为每章再造一块全幅背景。正式图片仍独立为 GLX 资源；未来替换阶段资源、颜色和锚点不必重建正文。

### 3.4 时间线与响应

- 首次打开：直接显示当前章节的静态阶段，不把全篇从头播一遍。
- 顺序滚动：章节确认变化后开始当前→目标的短缓动，画面与文字位置独立，不触发导航。
- 点击目录/跨多章跳转：**从当前视觉帧直接平滑重定向至最终目标**，不慢速逐章播放所有中间形态。
- 快速连续跳章：取消旧补间并继承已绘制的位置/透明度/形态去新目标；不积攒队列、不重新挂载组件。
- 反向滚动：可逆回到上个阶段，接受叙事上的“时间回溯”，不假装液体真实逆向物理转化。
- 静止：达到目标后停止 rAF（DOM 动画可由 WAAPI 管理）；页面隐藏/组件 suspend 停止；resume 按当前阅读事实恢复，dispose 释放订阅、定时/动画与资源。
- `prefers-reduced-motion`：省略空间长路径与粒子，直接交叉切换当前阶段或静态显示，信息不丢失。
- 视口宽度变换：配置按规范化比例给位置，落到当前 CSS 像素后适配；不以桌面固定 1440 画幅整体同比压小手机对象及标签。

## 4. 分阶段执行与明确决策门（须在 Codex 软件修复交付后）

### Gate 0：取最新软件与正式作品基线（只读）
- 读取 Codex 本轮任务真实完成状态、直接相关源码、其测试与未完成边界。已验证而未受影响的能力不重跑全仓。
- 以当前 r179 另存新的实验 GLX；旧冻结原件/哈希、13 张作品预览、现有三程序事实作为回退参考。
- **禁止**把后台规划直接写进正在被 Codex 修改的软件范围，也不开始通用 API 改造。

### Gate 1：三锚点最小 PoC（决定此方向是否可用）
- 在隔离 GLX 副本插入**一个** Source Runtime，先只做 U02 红果、U05 焙豆、U07 杯子，使用占位或已有图片+短缓动。
- 核心探针：Source `read/subscribe` 是否在**鼠标滚动、目录跳转、回退**得到稳定 `reading.activeInstanceId/progress`；运行实例是否持续不重挂；在**一个真正透明的 Flow 前景**之下，Global Underlay 能否贯穿所有章节呈现、尺寸/坐标正确、交互不被拦截。PoC 不再比较 Overlay 路线。
- 只做一条真实 `GLX -> Preview/Player -> 保存 -> 新进程冷开 -> 正式离线单 HTML`，复核三个锚点、快速跳转、反向与空闲停止。
- **过门**：三个锚点可读且转场完整、对前景零干扰、正式离线运行；底层无新增重复导航状态。
- **失败分流**：若 Source 无法收到 Flow 阅读位置，精确报告断在导航观察/Source 桥哪一条，交由软件唯一 owner 作窄修；若 Underlay 被遮蔽，逐层核查作者工程背景、Flow paper fallback、原生背景形状和局部 iframe 背景，优先清除无意义的不透明绘制。只有明确证明宿主无法表达所需透明语义时，交原背景/Surface owner 做最小接线；不通过改成 Overlay 或复制滚动引擎回避根因。

### Gate 2：制作完整七章连续物件
- 用一份阶段/锚点配置扩为七章，同时配置统一背景的底色、材质和氛围变化；优先完成 U01 逆向开篇、U03 分层剥离、U06 粒子过渡、U07 回环；复用 U05 配准帧。重点复核 U04（浅）→U05（深）→U06（浅）的连续滚动交界，确保同屏跨章节时两边文字不因背景切换失去对比度。
- 单独验证用户在 U03 切处理路线后背景不与当前路线矛盾。
- U05 输入共享作为**加分能力**而非强制前置；若无直接正式绑定，暂以章节状态/降低透明度处理，不修改通用 Source Host 为了读取 iframe slider。
- 代表性 1440/390 截图、正常滚动/导航跳转/连续跳跃、静止 CPU/rAF 和减少动态；优先视觉质量而非强求新特效数量。

### Gate 3：两处原定重点视觉精修（背景机制通过后）
- **U06**：动态图解的杯、液面、滤杯、粒子、状态强调与小屏标注；让关系一眼可读，保原质量守恒计算/按钮/声音/减少动态。具体见 [质量审查](../../../../../output/coffee-closeout-review-20261022/CLOSEOUT_EVALUATION.md)。
- **U03**：SVG 保留层的高对比视觉、并排模式直接显示各路线结构差异、390px 图例可读；保三路线状态、详情、比较、返回。
- **U05**：保已成熟的 25/50/75 三关键帧，审查与背景的视觉主次；不重新海选关键帧。
- 不触动 U01/U02/U04/U07 已成熟的普通图文内容，除非新背景遮挡迫使局部迁移位置。

### Gate 4：参考复用与最终收口
- 在独立非咖啡主题小工程复用一份“持续章节物件”配置/Source，验证阶段与锚点能够替换且不依赖咖啡硬编码；无需再创作完整第二件精品。
- 将 U06 固定溶质机制换成糖水/盐水，在**正式 GLX** 中装配、改参、Undo/Redo、保存冷开、离线导出，完成现有独立 HTML 复用证据缺口。
- 按场景粒度更新 [REFERENCE_CASES](../design/v05/REFERENCE_CASES.md)：新增“跨章节持续物件”时注明实际兼容载体、最低输入、算法和可替换素材、绑定/解绑、成功证据与局限；不全量加载每件作品、也不把概念图写成已验证资产。
- 冻结新的当前 GLX 副本，基于该副本正式导出 HTML；更新唯一 [NEXT_PASS](NEXT_PASS.md)、manifest、7 章代表性桌面/手机截图。归档原 r179 为已验收基础，不覆盖或删除历史失败。

## 5. 最终验收（按对使用效果的影响排列）

| 验收维度 | 必须看到的结果 |
| --- | --- |
| 连续性/状态 | 单一背景实例；滚动、目录导航、反向、快速跳章最终落到当前章；没有旧补间追上新的目标；静止时不持续动画 |
| 视觉质量 | 物件形态清楚且可辨；一个全局 Underlay 在各章有正确底色与阶段视觉；透明前景不盖死物件，U04/U05/U06 交界保关键字对比度；允许少量底层视觉重叠但不影响阅读与操作 |
