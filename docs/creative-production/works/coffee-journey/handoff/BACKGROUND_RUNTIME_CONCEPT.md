# 跨章节咖啡物件 Runtime｜创作候选与最小验证方案

状态：**2026-10-22 早期讨论稿（现以 [背景 Runtime 与创作收口正式方案](COFFEE_RUNTIME_AND_CLOSEOUT_PLAN_20261022.md) 为执行依据），未实施、未验收、不得收录为已验证参考案例。** 当前正式作品仍为 r179。创作目标是增加一种与 U03/U05/U06 互补的高价值范式：**贯穿全篇、随阅读位置与少量明确参数变化的持续视觉叙事对象**。

## 为什么值得做

咖啡作品已经覆盖图文混排、状态比较、局部关键帧、数值驱动示意，但还没有展示**跨章节同一视觉对象的持续身份与转场**。这类机制可迁移到“种子的旅程”“人体器官变化”“机器装配”“城市演变”等作品。比简单增加粒子、流光背景更有参考意义。静止时克制、章节变化时运动，避免对阅读产生持续干扰。

## 叙事状态设计

| 段落 | 视觉状态与作用 | 建议表现 |
| --- | --- | --- |
| U01 | 先见一杯现成咖啡，再向前追溯果实 | 杯子作为回环起点，转入果实时采用叙事回溯/淡化，不声称真实液体能逆变成果实 |
| U02 | 红色果实 | 小幅位移至人物摄影留白；不遮挡人物与标题 |
| U03 | 果实／去除外层后的种子 | 用剥离、交叉溶解或图形过渡表现共同变化；三路线为可替代路径，背景不要无依据选择唯一路线 |
| U04 | 生豆，进入安静交接 | 定位静止、显著降低视觉权重，不额外持续摆动 |
| U05 | 生豆→转黄→深烘 | 复用现有三张已配准关键帧，必要时订阅当前 U05 的有效参数，避免创建一份独立竞态进度 |
| U06 | 烘焙豆→研磨/溶质粒子→饮品 | 形态变化跨物理类别，用遮罩/粒子聚散/溶解切换，不使用失真的连续轮廓 morph |
| U07 | 回到第一章的杯子 | 再现同一杯子，动画收束为静态，让全篇形成回环 |

不强迫咖啡果、豆子、液体、杯子全部使用同一张图片形变。**连续身份是叙事逻辑，视觉过渡可组合关键帧、透明度、遮罩、运动和粒子。**

## 建议的技术所有权

- **单个作品级 Source Runtime** 负责长期物件绘制、视觉插值和定位（候选：Global underlay 的一个资产实例），不在七章各复制一份本体，也不持有章节导航的独立真相。
- Flow 导航/滚动 owner 提供必要的 `chapterId` / `chapterProgress` / 如需 `roastProgress` 的权威观看信号；Runtime **订阅**并将信号投影为画面。实际是否已经有安全的章节/滚动状态出口需从当前源码及 GLX 小样验证，不可跨沙箱任意读取宿主 DOM。
- 默认在章节**跳转或有效滚动区段变化时运动**，静止后停止 rAF；快速跳章取消上一段补间并按当前目的地收敛，后退时可逆。不强制所有内容与页面一起移动。
- 重点约束为可读性、层级、输入透明：`pointer-events:none`，桌面/移动端使用不同位置、大小和显隐；避免与白底原生 group、深色 U05 层或独立局部 iframe 产生遮挡。必要时下沉、降低对比或隐藏。
- `prefers-reduced-motion` 采用直接跳到当前物件状态、保留静态含义的方式。切后台和卸载必须停止 rAF，回到前台从权威状态恢复。
- 复用资产只记录阶段、外观资源、轨迹控制点、触发和遮挡规则；具体咖啡素材与阶段名称应是作者配置。不要为首个样例新建通用背景编排平台。

## 现有能力与未验证边界

已确认存在两类执行型背景库：`guoling.work.background.ambient` / `guoling.work.background.scene`，正式 Source 包含 Canvas、`scope.state.get/subscribe`、`suspend/resume/dispose` 和清理。2026-10-20 A07 在 Published sandbox 与 compiled HTML 验证过背景响应、生命周期、保存与冷开；组件库插入有 global underlay 及 Flow underlay 规划。

尚**未**在当前七章同一 Flow 里证明：
1. global underlay Runtime 的真实 z-order 是否始终可见且位于照片/原生层合适位置；
2. Flow 导航、章节锚点或滚动进度能否通过软件现有安全 API 向该实例发布事件；
3. 在单连续 Flow 的局部程序与 iframe 间穿越时是否真正是一份长期绘制状态；
4. 快速跨章节、移动版、保存冷开及正式离线导出的整体行为；
5. `background.paint` 是静态 CSS 背景，不等同于以上可执行 Source Runtime，不可混用验收结论。

## 推荐实施/停止线

**PoC 0：** 在 r179 的新测试副本（不动原件）插入一个全局 Source 物件，先验证 U02 果实 ↔ U05 烘焙豆 ↔ U07 杯子的三个锚点。真实跳章/滚动后看移动路径、层级、生命周期，执行保存/新 profile 冷开/离线浏览器验证。先不要实现 U01–U07 全参数、多章同步。

**PoC 1：** 成功后扩成七章配置表；与 U05 局部进度做一次明确且可取消的绑定。美术在关键变化时亮相，U02/U04 安静时弱化甚至不显示。

**收口与验收：** 桌面/390px、正向/后退/快速跳章、当前输入不被挡、低运动模式、离屏和恢复、只有一套活动绘制与状态订阅、GLX 修改→Undo/Redo→保存冷开→离线导出；任何明显干扰文本或造成底层软件重构的效果先降级，优先完成 U06 和 U03 的既定局部收口。

完成实际跨主题/跨作品复用前，只称“跨章节连续叙事物件的验证案例”，不夸大为通用背景动画引擎。
