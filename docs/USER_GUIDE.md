# 用户指南

本指南适用于 **互动课件编辑器（Windows x64）**，当前工程格式为 Course Project V9（`schemaVersion: 9`）。详细合同见 [docs/contracts/](contracts/)。产品由 **ittoedu** 开发，英文名为 **ittoedu Courseware Editor**。Course Project V9 JSON 是工程的业务真相；当前原生 2D 画布使用 Phaser，DOM/Canvas/WebGL 由运行时或组件按需增强。编辑器是 AI-native 课件的轻量编辑与交付容器：手动模式解决文字、素材、布局、稳定状态、常用映射和事件驱动的入场/退场编排；简单点击/切场/播媒体用原生节点与声明式交互；稍复杂的局部互动用组件（可复用或为本课新建）；整页动画、特效与连续机制用场景/世界运行时。包版本号已是 `1.0.0`，V9 Schema 已软冻结；未获教师验收前不宣称 Editor 1.0 已发布。

文档同步基线：**2026-08-28**。1.7.0 原型位于归档标签 `internal-prototype-1.7.0`；当前主干的生产路径只接受 Course Project V9、Published Course V2、Runtime API 2/3 与 Component API 4。当前版只使用 `%APPDATA%\ittoedu-courseware-editor`，不会读取或迁移旧品牌目录。自动化通过不代表教师 `accepted`。其他规范和证据入口见 [文档导航](README.md)。

## 1. 启动编辑器

源码检出的标准启动方式是根目录双击入口；开发验证可另行构建 Portable/目录版，但这些本地制品不随源码分发：

1. 在 Windows 10/11 x64 安装 Node.js LTS；
2. 拉取或解压完整源码目录；
3. 双击根目录 `启动课件编辑器.cmd`。

入口会先把仓库 `.agents/skills/` 中的两个权威课件 Skill 幂等同步到当前用户的 `%USERPROFILE%\.agents\skills`，首次缺少依赖时再自动执行 `npm ci`，随后构建 Player、Renderer、Electron 并直接打开应用。之后每次双击都会同步 Skill 并按当前源码重新构建，不会调用 `electron-builder`，也不会生成 `release/`、Portable EXE 或安装程序。需要在终端启动时可使用 `npm start`，它同样会自动执行 Skill 安装；也可只运行 `npm run install:courseware-skills`。

Skill 安装器只管理 `orchestrate-courseware` 与 `build-courseware-project`。目标内容未变化时不会重复复制；只有仍与安装记录树签名匹配的副本才会自动更新。用户改过的已管理 Skill 会保留并显示人工处理提示，编辑器仍可继续启动。未纳入管理记录的同名当前 Skill 会用仓库副本覆盖。旧 `build-project-v8-courseware` 与 `build-project-v7-courseware` 只在既往由本项目管理且字节仍与安装记录或已知官方版一致时安全退役；修改过或未管理的旧 Builder 副本会保留。安装过程不会删除或修改 `%USERPROFILE%\.codex\skills` 中的历史副本。Codex 未立即显示新版本时应重启 Codex。它们属于外部 AI 创作工作流，不代表 Editor 1.x 内置了 AI 生成功能。

仓库中历史 1.6.0 便携版/目录版记录不包含当前 Course Project V9 能力，不应作为当前版本启动入口或分发物。

根目录入口直接运行项目锁定的 Electron，不提供商业代码签名。请只从可信仓库获取源码，并保留 `package-lock.json`；不要关闭系统安全功能。

源码版编辑器需要本机 Node.js/npm；首次依赖安装需要访问 npm registry。编辑器完成构建后、预览及导出的离线课件不依赖浏览器扩展或本地服务器。

## 2. 认识界面

主窗口分为六个区域：

1. 顶部工具栏：两种模式都保留新建、打开、保存、撤销、重做、模式切换、“整课预览”和统一“导出”；简洁模式把最近工程、另存为和工程检查收进“更多”，专业模式直接显示这些入口。组件导入只位于右侧“组件”页，不在顶栏提供重复入口。
2. 左侧场景列表：顶部固定“全局层”，其下可查看缩略图，选择、新建、复制、重命名、删除和排序场景。
3. 中央工作区：始终显示同一个 1280 × 720 画布，可在“编辑状态”和“当前位置试运行”之间切换；画面不会换到另一块预览区。Slide 的两种状态在同一 Renderer 文档中使用同一套 Published V2 Slide 宿主；Flow / Spatial 保持各自的专用作者面。编辑状态可选择、框选、移动、缩放和旋转原生节点。无限画布在编辑态即可平移/缩放会话镜头（写入 home 或镜头画面才持久化）；当前位置试运行与整课预览里仍可自由逛世界，同时可用镜头画面、路径和下一步巡游。拖画布不只限于空白：只要该处没有被组件、运行时、视频控件或教师控制器占用，就可以拖拽平移、滚轮缩放，且只改会话、不写回工程。
4. 右侧面板：
   - “元素”是原生元素添加与媒体管理入口，不再保留重复的“素材”一级 Tab；“常用”提供文字、公式、图片、视频、声音和全部图形快捷入口，“媒体”可批量导入、管理和复用图片、视频与声音，专业模式再显示“控制与全局”；
   - “组件”只在专业模式显示：提供“打开内置组件库”“导入外部组件”和合并管理能力后的“工程组件”列表；
   - “图层”用于查看叠放顺序、重命名、显示/隐藏、锁定、复制、删除和排序节点；
   - “属性”用于编辑场景、单个节点或多选节点；简洁模式提供常用图文设置和“出现动画”，专业模式追加精确参数、播放初始状态、点击交互与运行时设置；
   - “互动与动画”只在专业模式显示：普通场景编辑 `scene.interactions`，全局层编辑课程级 `globalInteractions`，用于进入事件、音视频生命周期、组件/运行时事件和其他非点击规则；
   - “开发”只在专业模式显示：打开加宽的单任务工作台，在“运行时 / 对象 JSON / 规则 JSON / 组件代码”之间切换，受控修改工程内容。
5. 画布下方状态条：切换当前场景的基础、初始、反馈、完成等命名状态，并设置运行初始状态和场景缩略图状态。
6. 底部状态栏：显示处理状态、当前场景、节点数、选中项和工程是否已命名。

窗口标题中课件名称后的 `*` 表示有未保存修改。

### 2.1 简洁模式与专业模式

两种模式使用同一份 Course Project V9，只改变工作入口和信息密度。切换模式不产生工程历史、不删除高级规则或运行时，也不会改变预览和导出结果；本机会记住上次使用的模式。

- 简洁模式右侧只有“元素 / 图层 / 属性”，适合添加图文素材、画布排版、常用属性、文字编辑和单元素出现动画；
- 专业模式右侧为“元素 / 图层 / 属性 / 互动与动画 / 开发”，继续开放组件包、完整规则、运行时、对象结构、精确参数和高级声音能力；

### 2.2 项目字体与色板 Token

在专业模式进入“全局层”，清空节点选择后，“属性”会显示“字体与色板 Token”。字体条目保存稳定 ID、显示名称和 CSS `fontFamily`，颜色条目保存稳定 ID、显示名称和颜色值；同类 ID 必须唯一，并以小写字母开头。添加、修改和删除均进入撤销/重做历史。

这些 Token 是供人类和 AI 对齐用词的最小机器可读词汇，不是主题引擎：它们不保存叙述性的美术方向，不会自动绑定节点，也不会在修改后批量替换已有文字、填充或边框。需要改变实际画面时，仍须选择对应节点修改属性并检查各个状态。
- 简洁模式遇到已有专业规则、运行时或组件时只收起高级编辑入口，内容仍按原工程运行。需要调整时切换专业模式。

## 3. 新建、打开、最近工程和保存

### 3.1 新建

单击“新建”或按 `Ctrl+N`。默认工程包含一个名为“场景 1”的白色 16:9 场景，并在全局层放置一个可编辑的画布内教师控制器。控制器跨场景持续存在，默认包含一个点击后展开全部场景的“场景目录”按钮。

如果当前工程有未保存修改，新建或打开其他工程前会确认是否放弃；如需保留请先取消并保存。直接关闭编辑器时会明确提供“保存 / 不保存 / 取消”：选择“保存”会等待当前工程保存成功后关闭；选择“不保存”会清理恢复副本并关闭；选择“取消”继续编辑。

### 3.2 打开工程

1. 单击“打开”或按 `Ctrl+O`。
2. 选择一个 `.h5lesson` 文件。
3. 编辑器校验文件签名、工程版本、数据和包内路径后载入工程。

当前工程 Schema 为 Course Project V9。旧 Project V1–V8 不再由主程序载入、导入或逐级迁移；编辑器会在解析前显示“旧工程格式不受支持”，且不会产生可继续保存的半加载工程。V9 工程包含三类 surface、统一图层、场景状态、语义公式、最小字体/色板 `designTokens`、图片作者安全区、声明式交互、可顺序/并行的动作步骤、元素入场/退场、声音库、视频节点、结构化教师控制器、`playback.presenter` 合同、自由运行时和组件。启用 `playback.presenter` 后，PageUp/PageDown 与已录入的附加按键可按“相邻场景导航”或“只触发作者规则”策略执行；后一策略没有匹配的 `presenter.command` 时不会自动翻页。左/右方向键仍由独立的键盘导航开关控制。输入框、文本编辑、滑块、显式键盘捕获区和模态层保留键盘所有权；首尾边界、长按与硬件抖动有明确反馈或去重。需要恢复更旧工程时，请使用归档标签 `internal-prototype-1.7.0` 对应的旧编辑器或后续独立离线转换工具，并保留原始文件。

如果提示工程损坏或格式版本不支持，请使用兼容版本的编辑器打开，或从备份恢复。不要手工修改工程压缩包中的文件。

### 3.3 最近工程

专业模式顶部“最近工程”和简洁模式“更多”中的“最近工程”都列出最近打开或保存的最多 12 个 `.h5lesson` 文件。单击条目即可打开；文件被移动或删除后，失效条目会在刷新列表时清理。

最近工程只记录本机文件路径，不会上传工程内容。

### 3.4 保存与另存为

- 单击“保存”或按 `Ctrl+S`：新工程会打开保存对话框；已有路径的工程写回当前文件。
- 在专业模式单击顶部“另存为”，或在简洁模式打开“更多”后单击“另存为”；也可按 `Ctrl+Shift+S`。工程会保存到新的 `.h5lesson` 文件，后续“保存”写入新文件。
- 保存成功且保存期间没有发生新修改时，窗口标题中的 `*` 消失；若压缩或写盘期间继续编辑，已写入的是启动保存时的快照，新修改仍保留且 `*` 不会错误消失。

工程文件包含课件数据、素材、自由运行时和工程组件。移动到另一台电脑时，只需复制 `.h5lesson` 文件。运行时和组件都属于可执行代码，只打开可信来源工程。

当前自动化已验证：把唯一外部组件源删除后，移动的 `.h5lesson` 仍可重开、修改、重存并从归档恢复组件；移动后的离线便携单 HTML 与完整网页包也可通过 `file://` 离线运行。在线轻量单 HTML 会保留声明的远程依赖，不属于这项离线便携证明。该结果来自同一 Windows 主机的隔离目录（2026-08-13 验证，记录存于 Git 历史），只证明自包含与路径独立，不等于已经在另一台干净电脑上完成人工验收。

### 3.5 自动恢复

发生未保存修改并停止操作约 1.8 秒后，编辑器会异步压缩并在本机应用数据目录写入恢复副本。恢复管线同一时间只运行一份；新修订会取消过期压缩、合并等待中的更新并跳过重复修订，避免连续编辑时并发写盘。正常保存、新建或打开其他工程后，对应恢复副本会被清理。

如果程序异常结束且恢复副本仍在，下次启动会显示恢复提示：

- “恢复课件”：载入副本并将其标为未保存工程；请立即使用“保存”或“另存为”。
- “丢弃副本”：删除该本地恢复数据。

自动恢复不是版本历史或正式备份，也不会自动覆盖原 `.h5lesson`。重要课件仍应定期手动保存并保留外部备份。

## 4. 管理场景

- 选择：单击场景卡片。
- 新建：单击“新建场景”。
- 复制：单击场景卡片右侧的复制按钮；副本插在原场景之后。
- 重命名：双击场景名称，或在未选择节点时使用“属性”面板。
- 背景色：清空节点选择后，在“属性”面板设置场景背景色。
- 排序：拖动场景卡片左侧的把手。
- 删除：单击删除按钮并在确认提示中继续；删除场景可以撤销。

工程至少保留一个场景。建议单个工程控制在 200 个场景以内，防御性硬上限为 1000 个场景。超过建议值仍可编辑，但几小时的大课更适合按章节拆成多个工程。预览与导出按场景列表从上到下播放或生成页面。

### 4.1 管理同一场景的状态

每个场景有一个“基础场景”和至少一个命名状态。基础保存规范元素；命名状态只保存与基础不同的字段，所以基础修改会自动传播给没有单独覆盖该字段的状态。

- 单击“基础场景”：编辑所有状态继承的基础值；
- 单击命名状态：画布立即显示该状态，后续位置、尺寸、显隐、文字、样式、组件参数和背景修改只进入当前状态；
- “新状态”：创建一个继承基础的空状态；“复制”：复制当前状态的全部覆盖；
- 双击状态卡或使用“改名”修改名称；
- “设为初始”：决定进入场景时 Player 首先显示哪个状态；
- “设为缩略图”：决定左侧场景卡片显示哪个状态；
- “清除覆盖”：使当前状态重新完全继承基础；
- 在状态中删除元素只会让它在当前状态隐藏；切回基础删除才会从场景和全部状态中移除；
- 在状态中新建元素只在该状态显示，但仍拥有普通图层、选择框和属性编辑能力。

单个场景最多保存 100 个命名状态。状态卡上的“初始”和“缩略图”徽标是两个独立角色：前者决定进入场景时的画面，后者只决定左侧场景卡的代表画面。

场景缩略图不会执行 JavaScript 运行时，也不执行入场/退场或应用 `playbackInitialVisibility`；它按作者稳定可见性显示节点，并合成已启用的 `scene.runtime.staticFallback` 和 `globalRuntime.staticFallback`。顺序为：背景 → 全局 underlay 元素 → 全局运行时 underlay → 场景运行时 underlay → 场景节点 → 场景运行时 overlay → 全局 overlay 元素 → 全局运行时 overlay。`runtime-layer` 透明叠加；`full-scene` 会在自身层级清除下方合成后铺满画布。未登记静态后备的已启用运行时会显示“运行时”提示角标。

右侧属性面板顶部会标明“基础场景”或当前状态名称。状态中尚未修改的元素显示为继承基础；一旦修改会形成覆盖，可用“恢复基础值”清除该元素在当前状态的全部覆盖。

### 4.2 编辑状态与当前位置试运行

- 两种状态使用同一块 1280 × 720 舞台。切换只改变输入与运行权限，不改变画布坐标；
- Slide“编辑状态”直接挂载同文档 Published V2 authoring 宿主，并在上方叠加透明 Phaser 原生交互层。该透明层只负责选择、框选、移动、缩放和旋转，不重复绘制第二套视觉；Flow / Spatial 的编辑状态继续使用专用作者面；
- authoring 模式只显示当前 Slide 的稳定合成画面，并冻结学生点击/拖拽、宿主与教师控制器动作、声明式互动、音视频、导航、演示者输入、呈现推进及 `courseState` 写入。它通过带 session/revision 的版本化 direct ready/patch/ACK/error/target 协议更新画面与 Runtime/Component 编辑目标，也不允许扩展直接改写 Store；
- “当前位置试运行”与“整课预览”使用 CoursePlayer + Published V2 playback，从当前页或课程起始页真实运行。Published 会话会按声明初始化 `courseState` 默认值；`node.click` Interaction 可按存在性或类型化比较读取它，并用“设置课程状态”同步写入，与已支持 Runtime/Component carrier 和导航守卫共享同一份 Store。顶层 `block` 守卫只检查跨 location 的 go/next/previous；replay 不离开当前 location 且不经守卫，restart 明确绕过守卫、回到课程起点并把 `courseState` 重置为声明默认值；
- 当前 Runtime playback 范围为 Slide scene-local 与 session-global API 2 DOM/Phaser/hybrid、Slide scene-local API 3 DOM 与 Flow surface-local API 3 DOM；全局 API 2 在一个会话内保持唯一实例并随 Slide/Flow/Spatial 导航迁移。Slide scene-local API 2/3 的 `presentation` 已接线；API 2 `nodes`、Slide scene 以外的 `presentation` 和动态 Runtime 导航守卫仍未覆盖；
- Component API 4 已证明的互动 playback 是 Slide scene/surface、Flow block/surface 和 Spatial world/surface 的本地 DOM carrier，以及 Slide scene Phaser carrier；这些本地 carrier 接通共享课程状态和宿主动作。manifest 的 `supportedScopes` 只有 `scene` / `global`，`surface` 是 carrier 不是 manifest scope。global Component 当前只证明可见挂载，不承诺 `global` scope 上下文、跨 location 单实例或内部状态保留；hybrid 也不宣称完整 parity；
- 编辑状态中的场景/状态选择始终由编辑器决定，authoring 宿主不会反向导航或覆盖选择。只有试运行中的场景和命名状态变化会同步高亮左侧场景与下方状态卡；
- 顶部“整课预览”全屏打开同一块 1280 × 720（16:9 等比适配）舞台。编辑、当前位置试运行与整课预览共用这份逻辑画布；预览不再使用更矮的对话框改变缩放。

## 5. 添加元素与复用素材

“元素”面板顶部可搜索元素、图形或素材。简洁模式提供“常用 / 媒体”两个分类：“常用”包含文本、公式、图片、视频、声音和全部图形快捷入口；“媒体”提供图片、声音、视频的批量导入以及工程素材管理和复用；专业模式再增加“控制与全局”。组件位于独立“组件”页，不再与原生元素混排。文字、公式、图片、视频和基础图形支持两种添加方式；声音通过“常用”或“媒体”导入：

- 单击条目：添加到画布默认位置。
- 将条目拖入画布：添加到松开鼠标的位置。

新增对象会保持选中，但侧栏仍停留在当前“元素”或“组件”入口，方便连续插入；连续使用默认位置会自动轻微错开。只有主动单击画布对象或图层项时才切换到“属性”。从图片或视频快捷入口一次选择多个文件时，最多 12 个有效项目会以确定性、不重叠布局加入当前画布并保持多选；更多项目或当前层容量不足时只加入媒体库。直接从“媒体”页导入始终只入库，不自动创建节点。图片、声音、视频均按内容哈希复用已有字节，批次中的跳过和失败项目会在结果中说明；一次批量提交可用一次 Undo 撤销。

单项图片、视频、声音导入和图片替换也使用完整素材事务：节点/声音引用、素材元数据和实际文件字节会一起撤销、重做。复用原来已经存在的素材时，Undo 只移除本次新增引用，不会误删旧素材；替换图片后 Undo 会恢复旧元数据与旧字节。

建议每个场景控制在 250 个节点以内，防御性硬上限为 1000 个节点。超过建议值时状态栏会提示使用网页包；一次性复杂视觉可由场景运行时承载，高复用能力可组合为职责清晰的互动组件，不要在单场景无节制堆叠节点，也不要为一次性效果强行组件化。

### 5.1 简洁模式的出现动画

简洁模式下，选中场景元素后直接在“属性”→“出现动画”选择：

- 效果：无、淡入、滑入或缩放；
- 滑入方向：从左、右、上或下；
- 速度：快速、标准或舒缓；
- 延迟：不延迟、0.3 秒、0.6 秒或 1 秒。

选择效果后，编辑器会在一次可撤销操作中同时创建当前场景/状态的 `node.activated → node.enter` 规则，并把该元素的 `playbackInitialVisibility` 设置为 `hidden`；选择“无”会成对移除这条简洁规则和对应初始隐藏。编辑画布仍保持元素可见，预览、撤销和重做都不需要再手工协调两处设置。若元素已有可能重叠的专业入场规则，简洁模式不会覆盖，而是提示切换到专业模式。

### 5.2 专业模式的事件动画与规则

专业模式在“属性”→“通用”开放“互动播放初始状态”：

- “遵循作者可见性”（`inherit`）：Player 初始按节点或当前命名状态的 `visible` 显示；
- “初始隐藏，等待入场”（`hidden`）：只在互动 Player 中先隐藏，等待规则执行 `node.enter`。

“互动与动画”把每条完整规则按“当 / 如果 / 就”组织，并提供自然语言摘要、搜索/筛选、常用模板和可读动作顺序。需要超出简洁出现动画的编排时：

1. 选择业务触发点，例如按钮点击、进入场景/状态、组件或运行时事件、音视频事件、节点激活，或指定动画步骤完成；
2. 添加“元素入场”（`node.enter`）或“元素退场”（`node.exit`），选择目标节点、立即/淡化/滑动/缩放、滑动方向、时长与缓动；
3. 为每个动作步骤设置局部延迟，并选择“上一组完成后”（`after-previous`）或“与上一步同时”（`with-previous`）；连续的 `with-previous` 形成一个并行组；
4. 需要跨规则接力时，再以该步骤稳定 ID 选择“动画完成”（`animation.completed`）触发器。

入场会先建立 Player 瞬态可见性；退场会立即禁用该元素输入，完成后瞬态隐藏。它们都不会改写节点 `visible`、不切换 `scene.presentation`、不把动画进度存入工程。同一规则尚未完成就再次触发时，旧运行会取消并从动作规范起点重播；不同规则争用同一节点时，新动画从当前帧接管。被取消的动画不发 `animation.completed`。编辑画布、场景缩略图、PDF/PPTX 和其他静态捕获不应用 `playbackInitialVisibility`，始终按作者稳定可见性展示，以便选择和修改。

同一条规则在上一次尚未完成时再次触发，Player 会取消旧运行并从新触发点重启，避免同一规则的延迟和动画无限叠加。

本编排能力不是通用关键帧或路径时间轴。连续路径、物理、粒子或算法动画继续由组件或自由运行时完成。

### 5.3 专业模式的课程状态与导航守卫

“互动与动画”中的“专业：课程状态与导航守卫”是整课级作者入口，在 Slide、Flow 与 Spatial 工程中都可使用：

1. 在“课程状态声明”新增布尔、数字、文字或空值状态，并设置整课启动默认值；
2. 修改状态键时，编辑器会同步导航守卫、场景/全局 Interaction 的课程状态条件与写值动作；被任一处引用的状态不能直接删除。修改类型前也必须先清理不兼容的比较条件或写值动作；
3. 在“导航守卫”选择所有来源或指定来源位置、一个或多个目标位置、`all` / `any` 匹配方式，以及“存在/不存在”或按类型比较的条件；
4. 填写导航被阻止时的教师可读提示，再保存守卫。

每次保存都是一条可撤销操作，并在进入 Store 前解析完整 Course Project V9；陈旧修订、重复 ID、失效位置/状态引用、非法比较、错类型写值和空条件都不会静默写入。两个 Interaction 编辑区都可添加“课程状态存在/比较”条件和类型化“设置课程状态”动作；不同条件按“并且”判断，写值动作同步且不是终止动作。Published playback 会把同一份状态共享给 Interaction、当前受支持的 Runtime/Component carrier 与导航守卫。顶层 `block` 守卫只在 go/next/previous 实际跨 location 时执行；replay 不执行守卫，restart 绕过守卫并把课程状态重置为声明默认值。

## 6. 文本与富文本

### 6.1 编辑文字

1. 在“元素”中添加“文本”。
2. 单击文字选择整个文本节点。
3. 双击文字进入就地编辑；也可在“属性”中单击“编辑局部文字格式”。进入时文字默认全选，可重新拖选需要设置样式的片段。
4. 输入完成后按 `Ctrl+Enter` 提交，按 `Escape` 取消，或单击编辑区外提交。

中文输入法候选阶段不会被误判为提交。

### 6.2 局部富文本

就地编辑上方的浮动工具栏可对当前文字选区设置：

- 加粗、斜体、下划线、删除线；
- 黄色高亮、取消局部高亮；
- 局部文字颜色；
- 添加或取消所选字符的着重号；
- 清除所选内容的局部格式，使其重新继承整段样式。

局部样式会跟随文字一起保存、预览和导出。在“属性”面板直接改写整段“文字内容”时，编辑器会按未改变的前后文字重新映射原有局部样式；被删除文字对应的样式会随之删除。

### 6.3 整体文字样式

选择单个文本节点后，可在“属性”面板设置：

- 字体、字号、文字颜色、加粗、斜体、下划线、删除线、整段高亮和整段着重号；字体列表同时显示中文名称、实际 CSS 字体名和当前设备的“可用/未安装”状态，输入中文名或 CSS 名均可过滤，也可按 Enter 使用自定义字体或回退字体串；
- 行距、字距、内边距；
- 水平左/中/右对齐及垂直顶/中/底对齐；
- 横排、列从右向左的竖排，或列从左向右的竖排；工程分别保存为 `horizontal`、`vertical-rl`、`vertical-lr`；
- 文本框背景色、背景透明度和圆角；
- “自动尺寸”“固定尺寸并裁切”“自动缩小字体”三种溢出策略。自动尺寸在横排时自动增高并允许调宽，在竖排时保持可调高度并自动增宽，因此竖排文本框可以直接输入高度或拖动画布上下边缘纵向拉长。

着重号按字符保存和绘制：横排显示在字下方，竖排无论列从哪侧开始都显示在字右侧；空白字符不显示圆点。编辑器会为着重号预留行间或列间空间。局部着重号可以覆盖整段设置，也可以在整段已开启时只取消所选字符；这些差异会随撤销、保存和重新打开保留。

单 HTML、网页包和 PPTX 都不会自动嵌入用户自行填写的系统字体文件。跨电脑分发时，优先使用目标电脑常见字体，并在最终目标设备上检查换行和字形；PDF 会固定当前电脑上的渲染结果。PPTX 中未使用可见着重号的普通横排和右起竖排文字仍可编辑，因此缺少字体时可能发生替换和重新换行；包含可见着重号的文本节点会按稳定画面转为图片。PowerPoint 的原生东亚竖排不支持列从左向右，为避免静默颠倒列顺序，左起竖排也会在 PPTX 中转为图片。

所有名称为“透明度”的编辑器控件都使用同一含义：`0%` 表示完全不透明，`100%` 表示完全透明。工程内部仍保存不透明度数值，现有工程的数值无需转换。

### 6.4 语义公式

从“元素”→“常用”单击“公式”，或把公式卡片拖到画布，可添加一等 `FormulaNode`。新公式会保持选中，但不会打断连续插入并强制跳转属性。双击画布公式可直接打开公式编辑层；主动单击公式或图层后，也可在属性栏使用同一编辑器。

普通作者不再编辑 JSON AST。可直接输入 `x^2`、`x_i`或 `a/b`；`a/b` 会生成可编辑的竖式分数，而不是用斜杠文字冒充。结构模板覆盖分式、平方根、n 次根、上标、下标、上下标及圆/方/大括号，并提供常用运算符和希腊字母。模板中的 `□` 是未填槽位，按 Tab 跳到下一个；所有槽位补全前不能提交。

输入时实时预览专业排版。按 Enter 或单击“应用公式”才会以一次可撤销事务写入工程；按 Escape、单击“取消修改”或关闭画布编辑层会放弃未提交内容。未知命令、缺失括号、超出工程限制或未填槽位都会显示错误，不会污染当前工程。

无障碍描述默认从公式结构自动生成，并在公式提交时同步更新。作者也可改为自定义读法；此后修改公式不会覆盖自定义内容，界面会要求复核，也可随时恢复自动描述。Formula ID 和递归 AST 仍是工程、AI 定位和导出的唯一事实；原始 AST 只在专业“开发”面板的选中对象诊断/受控 JSON 入口中出现。当前线性输入是与七类公式 AST 对齐的受限子集，不代表支持任意 LaTeX、矩阵或多行方程。

编辑画布、整课预览、场景缩略图、单 HTML、网页包和 PDF 共用同一个公式渲染模块，排版规则一致；Slide 编辑画布与 playback 宿主位于同一 Renderer 文档，并使用同一组内置 font-face。公式按内置 `STIX Two Math` 显示，不再回退到系统数学字体（Windows 上曾表现为 Cambria Math）。公式结构、样式和无障碍文本可进入场景状态覆盖，并随撤销、重做、保存和重新打开保持。若“工程检查”提示公式内容超出节点边界，应增大公式框或减小字号后再导出。

PPTX 会把每个公式导出为独立透明图片，同时在对象元数据中保留 Formula ID 和无障碍文本。公式对象可以整体移动、缩放、复制或删除，但不能在 PowerPoint 中继续编辑分子、分母、根式、上下标或 AST；需要改公式时应回到 `.h5lesson`。

## 7. 图片与媒体

### 7.1 导入和替换

1. 单击“图片”或把“图片”拖入画布。
2. 从系统对话框选择一张或多张 PNG、JPEG、WebP、GIF 或 SVG。
3. 如需更换素材，选中图片后在“属性”中单击“替换图片”。
4. 已导入图片会同时出现在“元素”→“媒体”→“图片素材”；需要再次使用时单击“添加到画布”，会创建引用同一工程素材的独立可编辑图片元素，无需重复导入文件。

在媒体库删除素材前，编辑器会检查整份工程，而不只检查当前画布。基础/命名状态背景、命名状态节点覆盖、全局层、声音目录、场景/全局 Runtime 的素材绑定与静态后备，以及组件公开图片属性、嵌套 Props 和状态覆盖都属于引用。存在直接引用或由源码/自由文本保守识别出的可能引用时，删除会被阻止并指出场景、状态、节点、组件或 Runtime 上下文；组件包上下文缺失时也不会因此放行可能的引用。只有未引用素材可以删除，且该删除可完整 Undo/Redo，恢复或再次移除元数据和原字节。

图片扩展名必须与实际内容一致，单张图片不得超过 100 MB。读取失败时，可先使用图片软件重新导出后再试。

### 7.2 显示方式

- “适应（完整显示）”：完整显示图片，节点框内可能留空。
- “填充（允许裁剪）”：铺满节点框，超出部分被裁剪；用“填充焦点 X/Y”决定保留区域。
- “拉伸”：图片直接匹配节点框，可能改变原始比例。

“左/右/上/下裁剪”会从源图片对应边缘真正移除内容，四项都为 0 时显示完整源图，可随时用“重置裁剪”恢复。适应模式还可调整图片在框内的位置；拉伸模式不显示无效的焦点控件。

还可设置保持宽高比、水平/垂直翻转、圆角，以及矩形边缘或椭圆/径向羽化。关闭“保持宽高比”后可自由改变宽高；开启后角点和四条边的缩放手柄都会保持比例。

“图片安全区”用于标记裁剪后必须保留的主体、文字或关键物体。每个安全区具有稳定 ID、名称和相对图片节点的左/上/宽/高百分比；区域必须完整位于节点内。选中图片时，编辑画布会显示安全区覆盖层，添加、改名、调整和删除都支持撤销/重做并随工程保存。安全区只帮助作者检查，不会限制裁剪、自动移动焦点，也不会出现在 Player、缩略图、HTML、PDF 或 PPTX 中；导出预检只会提醒人工确认主体是否仍完整。

### 7.3 声音库与声音映射

在“元素”→“常用”中选择“声音”，或在“媒体”中单击“导入声音”，可一次选择多个 MP3、OGG、WAV 或 M4A。每个声音库条目都有稳定 `soundId`；导入后到“媒体”中试听、重命名和删除，切换专业模式后还可设置：

- 声道：背景音乐、旁白、音效或界面提示音；视频音量由独立的 `video` 声道统一管理；
- 默认音量和是否循环；
- 播放生命周期：声明式动作可指定随当前场景结束，或在课程范围持续；
- 已在交互规则中引用的声音不能直接删除，应先删除或改写对应映射。

专业模式下，“元素”→“媒体”中的“全局声音设置”可修改成品默认静音、主音量、背景音乐/旁白/音效/界面提示音/视频五个声道音量，以及旁白压低背景音乐的开关和目标音量；这些修改支持撤销和重做。Player 会按工程设置应用 ducking 淡变；浏览器阻止自动播放时，背景音乐和旁白会等待首次用户手势重试，短促音效不会无限排队。交互规则通过 `soundId` 或声道执行播放、暂停、继续、停止和切换静音，并可为播放/继续设置淡入、为暂停/停止设置淡出，不依赖素材文件名或物理路径。

### 7.4 视频素材与 VideoNode

在“元素”→“常用”中选择“视频”可一次选择多个 MP4 与 WebM 并批量放到画布；在“媒体”中单击“导入视频”则只批量入库。素材条目显示文件名、时长、文件大小和尺寸；每次单击“添加到画布”都会创建引用同一素材的独立 `VideoNode`，之后可像其他节点一样选择、删除、拖拽、缩放、旋转、排序和按场景状态覆盖。

视频属性包括适应/填充/拉伸、自动播放、循环、静音、音量、播放速度、开始/结束时间、封面图片或视频帧、表面点击切换播放以及简易画布控制。播放器会把视频音量纳入全局静音和 `video` 声道；还可设置视频开始时对背景音乐不处理、临时压低、临时暂停或永久停止，暂停/结束/销毁视频时会恢复临时处理，永久停止不会恢复。视频开始、暂停、结束及播放到指定秒数也可作为声明式交互触发器。编辑状态只显示封面或指定视频帧，不自动播放；真实播放请在“当前位置试运行”或“整课预览”中验收。

视频表面点击保留给视频本身的播放控制，因此视频节点不再提供“连接到状态”快捷按钮。需要根据视频推进状态或场景时，切换专业模式，在“互动与动画”使用视频开始、暂停、结束或到达时间点；需要显式由教师点击跳转时，在视频上方放置独立按钮或透明图形热点。现有工程中的视频 `node.click` 规则不会被删除，但只有同时关闭“点击切换播放”和原生 controls 后才能接收表面点击。启用内置点击/controls 与既有点击规则冲突时，编辑器会显示诊断；循环视频配置 `video.ended` 规则时也会提示结束事件通常不可达。

## 8. 图形库

Editor 1.0.0 内置以下图形：

- 基本：矩形、圆角矩形、圆/椭圆、三角形、菱形。
- 线条与箭头：直线、折线箭头、左/右/上/下箭头、双向箭头。
- 括号与着重：左/右/上/下大括号、横向/纵向大括号对、左/右方括号、着重圆点、着重三角。

选中图形后，可更换图形类型并设置填充色、填充透明度、边框/线条颜色、透明度和宽度，以及实线、虚线或点线。透明度同样是 `0%` 完全不透明、`100%` 完全透明。矩形支持圆角；直线与折线箭头还可分别设置起点和终点箭头，箭头样式包括三角、尖角、圆点和菱形。

## 9. 互动组件

互动组件属于专业能力。切换到专业模式并打开右侧“组件”页后，可以选择两条加入工程的路径：

1. “打开内置组件库”：在全尺寸库中按通用/学科、学段和用途筛选，可多选或全选当前结果；单击“加入工程”只嵌入精确组件包，不自动在画布堆叠实例。
2. “导入外部组件”：一次选择多个 `.h5component`；选择完成后逐包校验 API、身份、ZIP 哈希和内容哈希，有效包在同一批事务中直接加入工程，不再弹出确认或成功摘要。成功结果写入状态栏，跳过或失败项用可关闭错误提示说明；会覆盖既有代码的更新/替换仍要求显式审阅。
3. 加入后统一出现在“工程组件”。单击卡片或预设即可插入当前作用域，也可把卡片拖到画布指定位置。新实例保持选中但不会强制跳离“组件”页。

内置库的“通用组件”固定优先，其他学科只在 catalog 实际含有相应元数据时动态出现。搜索名称、用途或标签不会改写工程；同一包在分类和版本结果中会按 package ID 去重。与当前发行版审核摘要一致只证明 catalog 的发行身份与完整性，不产生更高的运行权限；外部导入只是另一种分发方式，已审核包与目录包使用相同执行语义。新外部包直接校验并加入，不再逐包弹窗；会覆盖已用代码的更新、替换及同 ID/版本哈希异常继续接受显式门禁。已经嵌入工程的精确组件可反复实例化，不再读取目录或重复提醒。

编辑模式始终可以把 V4 组件作为整体选择、移动、缩放和旋转。组件可显式公开文字、长文本、数字、开关、颜色、选项和工程图片，提供页面、变体和预设，并自动把 `props.content` 中所有文字显示在“属性”面板；manifest 必须用 `supportedScopes` 声明 `scene` / `global` 作用域，并声明 DOM、Phaser 或 hybrid 渲染能力。Slide/Flow/Spatial 中的 `surface` 是实例所在的宿主 carrier，不是 manifest 的第三种 scope。当前四个内置实验组件还将所有可编辑稳定可见文字登记为画布目标。Component API 1–3 旧包会被明确拒绝。

Slide 组件由同一 Renderer 文档中的 Published V2 authoring 宿主直接显示，Flow / Spatial 继续由各自的专用作者面显示。左侧场景缩略图优先绘制组件包 `manifest.thumbnail` 指定的图片；组件未提供缩略图或图片解码失败时，编辑器会绘制带组件名称的边框后备框，因此组件不会再从缩略图中无声消失。编辑状态冻结组件互动，只保留稳定视觉与显式编辑目标；真实互动仍需在“当前位置试运行”或“整课预览”验收。

V4 预设会显示在对应“工程组件”卡片下，可点击或拖入画布。组件内部按钮、拖拽、动画和场景跳转只在预览、单 HTML 与网页包的受支持 carrier 中运行。本地 DOM carrier 与 Slide scene Phaser carrier 可以控制指定场景跳转、上一页、下一页、重播本页和重开课件；global Component 不能用可见挂载推导这些完整会话语义。

### 9.1 组件画布文字编辑

组件作者可以显式开放稳定文字区域。编辑状态下双击已登记区域，会在该区域上显示轻量输入框，直接修改组件实例 Props；单行文字按 Enter 提交，多行文字按 `Ctrl+Enter` 提交，按 `Esc` 取消。修改支持撤销/重做，处于命名状态时写入当前状态覆盖。试运行、整课预览和成品播放器不会出现编辑命中区。

宿主不会猜测组件画面中的文字。DOM 组件只有带 `data-courseware-edit-key="content.title"` 的元素可命中；Phaser/hybrid 组件只有通过可选、仅编辑态的 `ctx.editor.registerTextRegion({ key, getBounds })` 登记的区域可命中。Component API 4 上下文只可能在 Published V2 authoring 模式中看到这一可选字段，组件必须判空；当前位置试运行、整课预览、普通 preview、capture 和成品 Player 均不提供 `ctx.editor`。`key` 还必须对应 manifest 已公开的 `text` / `textarea` 字段或有效 `props.content` 字符串。

未登记区域仍把组件作为整体选择，并可在“属性”中修改公开文字，不会报错或改变播放行为。协议细节见 [组件开发指南](COMPONENT_AUTHORING.md)。

### 9.2 工程组件管理与故障隔离

“工程组件”就是组件包的唯一使用和管理入口，不再另设“组件包管理”列表。卡片始终显示名称、版本、来源和场景/全局实例数；打开 `⋯` 菜单可执行：

- “查看详情”：查看稳定包 ID、精确版本、来源、渲染方式、可用作用域、SHA-256、许可证和发布阻断；
- “更新组件”：只在 catalog 出现更高语义版本时显式执行，不会静默替换；读取时重新复验哈希；
- “替换组件包”：只接受同 ID 的新包，并校验它仍支持所有现有实例所在的场景/全局作用域；成功后全部实例同步，任一校验或导入步骤失败时保留原包和原实例；
- “定位使用位置”：跳到该包的一个场景或全局实例；
- “从工程移除”：只有场景和全局实例数都为 0 时可用；仍被引用时按钮禁用并显示使用数量。

同一 ID/版本对应不同哈希时会阻断，维护者必须提升版本号。组件含可执行浏览器代码；哈希一致只证明字节未改变，不证明代码安全。单个组件创建、属性/尺寸/显隐/暂停更新、捕获准备或销毁失败由宿主隔离并记录诊断，不应让整页其余内容停止工作。遇到问题可在“工程检查”定位包引用，并导出诊断报告交给组件作者。

当前外部目录包含朗读标注、拼音标注、文字视觉容器和图片装饰容器，第一方稳定 ID 均使用 `com.ittoedu.*`；第三方组件不得冒用该命名空间。文字容器在同一属性中切换透明玻璃、磨砂玻璃、便利贴、撕纸和文件夹；图片容器切换笔刷和贴纸。原七个视觉 ID、包和来源不明位图已删除，不提供迁移。四包全部为 `experimental`；隐藏 E2E 已完成当前组件矩阵，catalog 因而移除 `current-v8-full-matrix-unverified`，但许可未知和维护人未指派仍是真实发布阻断。

### 9.3 统一全局层

单击场景列表顶部“全局层”即可进入类似 PPT 母版的统一编辑层。这里可以直接添加文字、图片、视频、基础图形、画布内教师控制器，以及 manifest 明确支持 `global` 的 V4 组件；通用标题、Logo、页眉页脚、导航和装饰无需复制到每个场景，也无需包装成组件。

全局层中的每个元素都可编辑位置、尺寸、旋转、叠放顺序、`underlay/overlay` 和场景可见范围：

- `all`：所有场景可见；
- `include`：只在指定稳定场景 ID 中可见；
- `exclude`：除指定场景外可见。

V4 DOM/hybrid 组件有一个明确例外：它的 DOM 部分位于固定组件 DOM 平面，整体在 Phaser Canvas 上方，因此不能靠选择 `underlay` 压到原生 Canvas 节点背后；`underlay/overlay` 仍控制它的 Phaser 代理/Phaser 部分。确需 Canvas 后景的组件应使用 Phaser 渲染，或由运行时 DOM underlay 承载后景。

全局原生元素和教师控制器具有跨场景会话语义，隐藏时会关闭显示和输入。global Component 虽可在对应页面可见挂载，当前没有对等的全局单实例会话所有者；不得依赖 `ctx.scope === 'global'`、普通翻页/replay 后保留内部状态，或只有 restart 才重建的生命周期。

### 9.4 场景与全局运行时文字

Course Project V9 工程可由外部 Builder、生成脚本或专业模式“开发”面板写入运行时。API 2 canvas Runtime 严格声明 `dom`、`phaser` 或 `hybrid`；API 3 surface Runtime 使用 DOM，旧 API 1 会得到“不受支持”诊断。属性栏会显示运行时登记的全部 `content.values` 文案并保存到工程与 Published payload；Published V2 当前在试运行、整课预览、离线/在线单 HTML 与网页包中执行 Slide scene-local 与 session-global API 2 DOM/Phaser/hybrid、Slide scene-local API 3 DOM 与 Flow surface-local API 3 DOM。全局 API 2 在单个会话中只创建一次并随 Slide/Flow/Spatial 当前页迁移；Flow/Spatial scene-local API 2、global API 3 与其它 shared carrier 仍按 fallback/占位处理。已支持 carrier 的 Runtime host actions 接入同一 Published 导航/重播/重开会话；Slide scene-local API 2/3 `presentation` 已接线，API 2 `nodes`、Slide scene 以外的 `presentation` 与动态 Runtime 导航守卫仍是 partial context。修改 `renderMode` 不会自动转换 DOM/Phaser 实现。

场景或全局运行时如果显式启用 Runtime Authoring V1，还可把文字或图片区域开放到对应画布作用域：文字目标必须对应 `content.values` 中已有的键，图片目标必须对应 `assets` 中已有的绑定。编辑状态下双击目标即可原位修改文字或选择替换图片；`ctx.authoring` 不提供原始 Store，修改由宿主转成 canonical command/history。`scene.runtime` 的内容由当前场景的基础及全部命名状态共享，`globalRuntime` 的内容由整课共享，均不会生成某个状态专属覆盖。

没有声明 authoring 版本或目标的 API 2 运行时仍由 Published 宿主显示其稳定视觉，不会变成空框，也不会自动扫描像素推断可编辑内容；其文字、素材绑定和源码继续从“属性”或专业“开发”面板修改。Runtime Authoring V1 是 API 2 上独立、可选的编辑扩展。

题目、答错、答对、完成等稳定画面应使用场景状态和可编辑元素；场景运行时负责判定、事件、过渡和瞬态效果，并切换这些状态。跨场景一次性规则可以由全局运行时实现，不必包装成组件。不得把整页稳定 UI 只放进自由运行时；人工可见文字仍必须登记并可编辑。

地球、太阳系、立体几何等真 3D 可以由具体运行时或 V4 组件携带 Three.js 实现，不要求编辑器核心内置 Three.js。程序化的一次性 3D 可直接使用运行时；带模型、较大或可复用的 3D 默认把离线 GLB 放进 V4 组件包。当前“媒体”管理还没有独立“模型”类型，不能把 GLB 当图片导入；没有 3D 的课件不会承担该能力。教师仍通过运行时 `content.values` 或组件 `props.content`/公开参数修改允许编辑的内容。

组件包含经过审核的可信 JavaScript；外部导入只是分发方式，不代表低权限或不可信。Slide authoring 与 playback 位于同一 Renderer 文档，但 authoring 的宿主动作和课程状态写入仍被主动冻结；同文档不等于取得任意 Store、文件或桌面能力。课程确需本地、父页面或桌面能力时，应通过明确宿主合同接入，并为不具备该能力的网页导出提供清楚的降级。不要导入未经审核、来源不明的组件。

组件包不得超过 50 MB，根目录必须包含 `manifest.json` 和 manifest 指定的普通 JavaScript 入口。制作组件请参阅 [组件开发指南](COMPONENT_AUTHORING.md)。

### 9.5 专业“开发”面板

“开发”是专业模式中的受控工程工作台，不是编辑器自身源码入口。进入后右侧栏会加宽，顶部以“运行时 / 对象 JSON / 规则 JSON / 组件代码”显示各任务的当前状态；一次只打开一类内容，避免多个代码框纵向堆叠。代码区使用较大的等宽字号并关闭自动折行。当前提供：

- 当前场景或全局运行时源码：没有运行时时可创建最小 Runtime API 2 模板；应用前检查源码体积、禁止的模块语法、JavaScript 语法和运行时文档结构；
- 所选对象 JSON：允许修改通过 Project Schema 校验的字段，但对象 ID 和类型不可更改；
- 当前规则 JSON：继续使用标准 `trigger / conditions / actions` 结构，规则 ID 不可更改；
- 所选组件的 manifest/runtime：导入的第三方组件默认只读；只有在场景“基础”或全局层单击“创建可编辑副本”，编辑器才会生成带明确来源标记的新包 ID/版本、保留原包，并把当前实例切换到工程内副本。命名状态只能覆盖组件 Props，不能替换组件包，需先返回“基础”。副本通过包路径、入口、缩略图、素材、运行时 API、注册身份和现有实例作用域校验后，才允许修改 manifest/runtime。

应用成功的运行时、对象、规则和可编辑组件修改都会进入工程撤销历史。“开发”面板在编辑/校验源码时不会执行它；Slide 的稳定作者视觉与实际试运行都由同文档 Published V2 宿主按各自模式执行，Flow / Spatial 则保留专用作者面。面板本身不提供文件系统浏览、Shell、依赖安装或编辑器源码修改；课程扩展需要宿主能力时，应走明确宿主合同，而不是把开发面板改成通用 IDE。组件/运行时源码也不承诺保密：工程作者态本来就包含这些代码，互动成品中的执行逻辑可被有技术能力的人恢复和分析。

第三方组件的“只读”只防止在当前工程中直接覆盖原包，不阻止查看或复制已经交付给用户的代码，也不替代组件许可证。创建可编辑副本前应确认授权允许修改和二次分发。

### 9.6 声明式交互规则与教师控制器

专业模式把声明式交互按来源与作用域分为两个编辑区，而不是把关系写死在运行时代码里：

- 普通场景中的规则保存在 `scene.interactions`；进入“全局层”后，点击规则和非点击规则改为保存在课程级 `globalInteractions`，不会复制到每个场景；
- 选中普通节点或全局元素时，“属性”面板显示“交互”，只编辑该元素的单击规则，并可用“连接到状态”快速建立映射；全局规则还可选择“生效场景”，底层以 `scene.in` 条件保存。视频节点不提供该快捷入口，因为其表面点击默认属于播放控制；
- 右侧“互动与动画”不依赖清空节点选择，只编辑非点击规则，可新增进入场景、进入命名状态、节点激活（`node.activated`）、动画完成（`animation.completed`）、声音结束、视频生命周期/时间点、组件事件和运行时事件触发；全局规则也可按场景限制。运行时事件必须明确选择“当前场景运行时”或“全局运行时”；
- 两个编辑区共用同一套场景/呈现/课程状态条件、动作步骤时序和动作编辑器。课程状态条件可检查声明键存在性或按声明类型比较，动作可同步设置声明键；同一条 `node.click` 规则不会在“互动与动画”中重复出现。面板以“当 / 如果 / 就”解释机制，并提供自然语言摘要、搜索与筛选、常用模板和顺序/同时动作标记。

常用配置流程是：

1. 选择触发器，例如某节点点击、进入场景/命名状态、节点激活、指定动画步骤完成、组件事件、带场景/全局来源的运行时事件、声音结束或视频事件；
2. 按需添加“当前场景属于……”（`scene.in`，主要用于全局规则）、“当前呈现状态属于……”（`presentation.in`），以及“课程状态存在/比较”条件；同一条件内多个 ID 按“或者”，不同条件按“并且”判断；
3. 添加动作步骤：元素入场/退场、切换命名状态、设置课程状态、跳转场景、上一页/下一页/重播/重开，以及声音或视频控制。课程状态写值必须匹配声明类型；每一步都有稳定 ID、局部延迟和 `after-previous` / `with-previous` 启动方式；
4. 连续 `with-previous` 步骤并行启动；下一个 `after-previous` 等待整个并行组完成。只有正常完成的入场/退场才发出可供其他规则使用的 `animation.completed`；
5. 把场景导航、重播或重开放在最后一个独立动作组。选择“跳转场景”时可配置高级 `scene.go.targetStateId`，留空则进入目标初始状态；
6. 需要复用或调整规则优先级时，使用规则卡片的“复制 / 上移 / 下移”。复制会生成新的规则与动作 ID，排序只在同类规则中进行，两者都进入撤销历史。

最常见的状态关系不需要写运行时：同场景可直接配置“点击按钮节点 → 切换到某状态”，跨场景可配置“点击按钮节点 → 跳转场景并进入指定状态”。目标状态会在目标节点、组件和运行时创建前一次性物化，不会先显示初始状态再跳变；目标状态失效时安全回退到目标场景初始状态。复杂判定、拖拽轨迹、程序动画和大量动态数据仍由场景运行时或组件处理，优先发出语义化 `runtime.event` / `component.event`，再由专业模式“互动与动画”映射到稳定状态、声音、视频或导航结果。

直接重复一个或多个节点时，编辑器会为每个副本各复制一次对应的单击规则，并把触发节点改为新 ID；非点击规则不会随节点重复。复制完成后仍应在“当前位置试运行”检查目标场景/目标状态、声音和视频引用是否符合教学意图。

新工程默认的教师控制器是 `globalLayer` 中的 `TeacherControllerNode`。它本身属于画布内容，位置、尺寸、标题、进度、配色、透明度和圆角均可编辑；成品不会额外出现第二套导航栏。

控制器可配置 1–12 个按钮。默认“场景目录”动作为 `scene.open-picker`：点击后展开所有场景，高亮当前场景，选择任一项后跳转并进入该场景的初始状态；目录不提供状态选择。展开、滚动、焦点与当前项高亮只是 Player 临时 UI，点击外部、Esc、选择场景、折叠控制器、发生导航或销毁时关闭，不写入工程、命名状态或 `courseState`。

上一场景、下一场景、重播当前场景、重新开始课程、切换静音和切换全屏仍是标准动作。只在业务明确要求某个固定目标按钮时，才使用高级 `scene.go`，并可选配置 `targetStateId`；它不是默认场景目录的实现方式。

开启“允许折叠”后，控制器出现“收/展”按钮；“打开课件时默认折叠”决定首次创建时的状态。运行中手动折叠或展开不会改写工程，但同一全局控制器实例在普通跨场景切换和“重播当前场景”时保留当前折叠状态；“重新开始课程”会重建全局作用域并恢复工程配置的默认状态。编辑画布可临时点击“收/展”预览，临时状态同样不写入工程。

互动 Player 中，展开面板和收起胶囊的整个可见表面都可发起拖动，不需要寻找专用把手。按下后在鼠标 6 px、触控 10 px 的视觉位移阈值内释放，仍按原目标执行按钮或收/展；超过阈值后本次手势只移动控制器，不再触发按钮，也不会把操作传给底层课件。拖动距离会换算到 1280×720 逻辑坐标，旋转后的可见边界仍受画布约束，靠近边缘时可贴边停放。

聚焦控制器后可用 Alt+方向键每次移动 8 个逻辑像素，Alt+Shift+方向键每次细调 1 个像素；按钮仍用 Enter/Space 激活，位置变化通过无障碍提示报告。授课拖动只记录为当前 Player 会话的 `dx/dy` 偏移，不写回 Project：切换场景和重播本页会保持，重新开始课程、刷新或重新打开成品后恢复作者位置。PDF/PPTX 即使显式保留控制器，也使用作者稳定位置而不是授课临时位置。

## 10. 选择、移动、缩放和旋转

### 10.1 单选和多选

- 单击节点：只选择该节点。
- `Ctrl` / `Shift` + 单击：在当前选择中添加或移除节点。
- 在画布空白处拖动：框选与选框相交的可见节点。
- `Ctrl` / `Shift` + 框选：把框选结果加入当前选择。
- `Ctrl+A`：选择当前场景全部节点。
- 单击空白处或按 `Escape`：清除选择。

在“图层”面板中也可使用 `Ctrl` / `Shift` + 单击进行多选。

### 10.2 变换

- 拖动节点：移动单个节点；拖动多选中的任意未锁定节点可整体移动所选未锁定节点。
- 拖动八个控制点：缩放；多选时按整个选择框比例调整各节点的位置和尺寸。
- 拖动选择框上方的圆形手柄：旋转；多选时围绕选择中心旋转。
- 缩放时按住 `Shift`：保持当前宽高比。开启“保持宽高比”的图片会在全部缩放手柄上自动保持比例。
- 旋转时按住 `Shift`：以 15° 为步长吸附。

拖动时会吸附画布边缘、中心和其他节点的边缘/中心，并显示参考线。按住 `Alt` 可临时关闭移动吸附。节点至少保留一部分在画布内，最小尺寸也会受到限制。

“属性”面板可输入精确的 X、Y、宽、高、旋转角度和透明度；透明度 `0%` 表示完全不透明，`100%` 表示完全透明。方向键每次微移 1 像素，`Shift` + 方向键每次微移 10 像素。

### 10.3 画布视图缩放与平移

编辑状态右上角提供缩小、当前比例、放大和“适合窗口/复位”控件。缩放范围为 50%–200%，步进 5%；也可按住 `Ctrl`（兼容 `Command`）滚动鼠标滚轮。按住空格再用鼠标左键拖动，或直接按住鼠标中键拖动，可以平移画布视图；这只改变观察位置，不会修改节点坐标。单击“适合窗口”会把缩放与平移复位到 100% 和画布中心。

缩放和平移只在“编辑状态”生效。“当前位置试运行”在同一工作区恢复完整 Player 输入与默认视图，避免把编辑视图状态误当成课件内容。

### 10.4 对齐、分布和批量操作

选择至少两个未锁定节点后，“属性”面板提供左对齐、水平居中、右对齐、顶对齐、垂直居中和底对齐。选择至少三个未锁定节点后，还可执行水平等距或垂直等距分布。

锁定节点仍可被选中，但不会参与移动、缩放、旋转、微移、对齐或分布。多选属性还支持全部显示、全部隐藏、全部锁定、全部解锁、复制所选和删除所选。

## 11. 图层管理

“图层”面板显示当前编辑作用域的一层节点列表；普通场景显示场景节点，全局层显示全局文字、公式、图片、视频、图形、教师控制器和组件。Editor 1.0.0 不支持分组或嵌套。列表最上方就是该作用域画面最上层。

每个图层可执行：

- 单击选择，`Ctrl` / `Shift` + 单击多选；
- 双击名称重命名；
- 显示或隐藏；
- 锁定或解锁；
- 复制或删除；
- 拖动左侧把手改变前后层级。

隐藏图层不会出现在预览和导出中。锁定只保护编辑操作，不影响预览和导出显示。

运行时/组件内部的 DOM 与 Phaser 对象不等于这里的普通节点图层。Player 使用固定的粗粒度平面：运行时 DOM underlay → Phaser Canvas → V4 组件 DOM → 运行时 DOM overlay；不同渲染器之间不能按每个对象任意穿插。DOM/hybrid 组件整体跟随组件框，但其 DOM 部分位于 Canvas 上方。需要精确交错的定制内容应由作者在同一渲染器中完成，或拆成明确的前景/后景。编辑器不会把 DOM、Phaser 或 Three.js 内容自动互转。

## 12. 复制、撤销和重做

- `Ctrl+C`：把所选节点复制到编辑器内部剪贴板。
- `Ctrl+V`：粘贴并轻微偏移副本。
- `Ctrl+D`：直接重复所选节点。
- `Delete` / `Backspace`：删除所选节点；文字就地编辑时只删除文字。
- `Ctrl+Z`：撤销。
- `Ctrl+Y` 或 `Ctrl+Shift+Z`：重做。

历史记录最多保留 50 步。新操作会清除已经撤销的后续分支；打开其他工程或新建工程时会清空历史。复制/粘贴使用编辑器内部剪贴板，不会读写 Windows 系统剪贴板中的其他内容。

## 13. 整课预览

单击顶部“整课预览”后，编辑器使用与单 HTML、网页包相同的 Player Runtime，在全屏 16:9 覆盖层中从第一场景的初始状态打开当前课件。舞台始终是 1280 × 720 逻辑画布并等比落入窗口；它用于验收完整课程路径。若只想从正在编辑的场景/状态就地验证，请使用中央“当前位置试运行”。

- 画布内教师控制器的默认“场景目录”展开全部场景，选择后只进入目标初始状态；固定场景/状态跳转是高级按钮动作。普通翻页与场景重播保留折叠状态，课程重开恢复默认折叠状态。
- 开启键盘导航时，左/右方向键仍可切换上一/下一场景。
- 在属性栏启用“翻页笔 PageUp/PageDown”后，无修饰键的 PageDown/PageUp 分别代表前进/后退；还可检测并登记精确的附加按键与修饰键组合。选择“相邻场景导航”时直接翻页并在首尾边界提示；选择“只触发作者规则”时只分发对应的 `presenter.command`，没有匹配规则就提示且不自动翻页。输入框、就地文字编辑、选择框、滑块、组件显式键盘捕获区和打开的模态层不会被翻页笔抢键；长按与短时间硬件抖动不会重复触发。
- 调整窗口大小：课件保持 16:9 等比适配。
- 当前已接线的声明式交互、视频和受支持组件 carrier 会按工程配置响应点击、音视频事件、状态切换、拖拽或其他交互；能力索引列为未覆盖的 trigger、condition、action 或 carrier 不会因打开整课预览自动取得 parity。
- 元素入场/退场在对应规则触发器发生后执行；顺序、并行、延迟和完成事件均按工程步骤语义运行。复杂运行时/组件动画按各自逻辑运行。

“重播本页”只重建当前场景的原生节点、本地场景组件和场景运行时；课程进度状态、全局原生元素、教师控制器和 session-global API 2 Runtime 保留。global Component 当前不承诺单实例或 replay 后内部状态保留。“重开课程”会明确绕过守卫，把课程状态重置为 V9 声明的默认值，重建受支持的全局/场景作用域并回到第一 location。两者语义不同。

关闭整课预览覆盖层不会修改工程。当前 Published V2 数据直接在主 renderer 内存中挂载并随覆盖层释放，不会把课件写成临时 HTML 文件；工程素材必须已有保存字节，编辑状态与当前位置/整课预览统一把这些字节内联为 data URL，不会因为元数据存在 `remote.url` 就改走网络，远程-only 素材仍会被当前 producer 拒绝。显式 `network.connectOrigins` 等实际连接需求会在预览期间取得精确 origin lease，关闭预览、切换工程或跨文档导航即撤销；未声明 origin 仍被拒绝，CORS/TLS 不会被绕过，远程脚本不开放。异常缺失活动 Course Project V9 时会明确报告整课预览不可用，不生成 V8 课件或打开独立窗口。

## 14. 导出单 HTML、网页包、PPTX 和 PDF

单击顶部“导出”后选择格式。四种格式的关键区别：

导出前建议先运行“工程检查”：专业模式可直接单击顶部入口，简洁模式从“更多”打开。当前面板直接读取 Course Project V9 的 locations、surfaces、统一图层、交互、组件、运行时和素材事实，不再以 V8 投影充当当前工程诊断；诊断项使用稳定 V9 target，可定位时跳到对应 location、surface、scene、flow block 或 layer item，无法可靠定位时保留明确路径而不伪造跳转。Runtime/Component 源码网络行为、真实像素和部分富排版仍需另行检查，因此“0 个问题”不能视为整课语义完整。未引用素材以 `asset-unused` 信息项列出；检查本身不会修改工程。面板上方还提供两个只读审阅摘要：

- “信息释放”按每个场景/状态的现有可见性与声明式交互，列出初始可见、分步显示和没有可达揭示路径的隐藏节点。运行时、媒体、组件和翻页笔事件只按“可能发生”处理，因此它不是一次真实授课模拟；
- “视觉密度”按可见对象数、文字字符数、累计包围盒面积和显著重叠对数生成 0–100 启发式分数及低/中/高分档。它不理解教学重点、留白意图或视觉质量，不会单独阻断导出。

当真正选择单 HTML、网页包、PDF 或 PPTX 时，编辑器还会生成该格式当前已接线的“导出预检”。报告分为“错误 / 警告 / 说明”：已检出的确定性错误必须返回编辑并修复；只有警告和说明时，可阅读静态化差异及启发式风险后确认继续。在线轻量单 HTML 会列出实际引用的远程素材；不能形成精确 HTTPS origin 的地址会阻断，但预检不会探测远端是否可达或是否允许 CORS。V9 Runtime/Component 源码的实际网络使用与工程声明一致性以及部分富排版检查当前仍未完整接入，报告存在不等于覆盖完整，这是长期边界而非临时状态；离线便携单 HTML/网页包应在真实浏览器中确认没有意外外联，在线轻量单 HTML 应核对预期远程请求、可达性和 CORS。未引用素材只产生一条数量/字节聚合说明；这不表示 `.h5lesson` 会自动裁剪素材。可定位项目会跳到对应场景、状态或节点；“保存报告”会另存包含报告版本、工程/目标格式、生成时间、稳定诊断 code、问题定位字段和汇总的 JSON，便于复现同一次导出决定。

“导出诊断报告”与上述两种检查用途不同：它导出主进程、编辑器、预览和组件的本地异常日志及版本/平台信息，不包含课件素材内容，适合在崩溃、预览或组件异常时交给开发者排查。它不是课件内容清单，也不会自动修复问题。

开发者或 AI 也可在仓库终端执行 `npm run --silent validate:project -- <file.h5lesson>`。stdout 只输出稳定 JSON，包含 Schema issues 路径、当前已接线的结构性工程健康结果和默认离线便携单 HTML、网页包、PDF、PPTX 四份预检；当前 CLI 不执行在线轻量模式的 remote URL/CSP 检查。退出码 0 表示这些已接线检查没有 error，不表示完整 V9 语义或实际网络使用与工程声明一致已经证明。退出码 1 表示工程可读但已检出 error，2 表示参数、文件、归档或 Schema 无法校验。命令不会启动窗口、执行真实导出或改写文件；Node 近似布局和 Headless 绿色都必须由真实 Player、导出画面及外部请求检查补足。

### 14.1 导出单 HTML

1. 单击顶部“导出”，选择“离线便携单 HTML”或“在线轻量单 HTML”。
2. 阅读导出预检；在线轻量模式会列出实际远程素材，非精确 HTTPS 地址会阻断。
3. 选择文件名和保存位置。
4. 在系统浏览器中双击 `.html`，逐页检查布局和组件交互；在线轻量模式还要检查远程请求、CORS 和断网结果。

离线便携模式不需要同目录资源、服务器或网络，移动课件时只需复制这一个文件；全部发布素材使用 Data URL，CSP 不开放远程 origin。在线轻量模式仍是一个文件，但会保留实际引用且声明了 `remote.url` 的工程素材 HTTPS 地址，并把工程 `network.connectOrigins` 写入精确 CSP；未声明远程地址的工程素材与全部组件素材继续内联，远程脚本不开放。两种构建都要求每个被引用的工程素材具有已保存字节；只有 `remote.url` 而无工程字节的 remote-only 素材会被 producer 拒绝。在线轻量不探测远端可达性或绕过 CORS，也不能保存长期 API Key。两种单 HTML 都使用 PublishedLesson V1，不包含可直接导入的 Course Project V9、历史记录、编辑器字段、组件 manifest 或独立原始 `runtime.js`；互动执行代码仍会以可恢复的编码形式随成品交付，因此不能把它视为加密或 DRM。

预计文件超过 50 MB 时，编辑器会显示体积、解释启动和内存风险，并推荐改用网页包；可以在未超过 256 MB 时选择继续。超过 256 MB 后必须改用网页包。没有 `remote.url` 的视频在两种单 HTML 中都会转成 Base64；已声明且实际引用的视频只有在线轻量模式会保留远程 URL。体积与离线可用性需要按最终模式分别验收。

### 14.2 导出网页包

1. 单击顶部“导出”→“网页包”。
2. 保存 `.zip` 文件并完整解压。
3. 打开解压目录根部的 `index.html` 检查翻页和互动。

网页包把播放器、唯一的 `course-data.js` 发布数据、图片、声音、视频和组件运行素材分开存放，避免把全部 Base64 内容塞进一个 HTML。它不包含 `project.json`、组件 `manifest.json`、独立组件 `runtime.js` 或源码映射。复制或上传时必须保留整个目录结构，不能只复制 `index.html`。它支持直接通过 `file://` 离线打开；正式部署时建议把整个目录放到静态 Web 服务器。技术细节见 [PublishedLesson V1 发布格式](PUBLISHED_LESSON_V1.md)。

### 14.3 导出 PDF

1. 单击顶部“导出”→“PDF”。
2. 等待全部场景渲染。
3. 选择保存位置并打开 `.pdf` 检查。

纯 Slide PDF 按课程 location 顺序逐页建立独立、惰性的 Published 捕获 generation，页面包含 scene/surface layer 以及纯 Slide global layer，并按固定 DOM underlay、Phaser Canvas、组件 DOM/WebGL 和 DOM overlay 合成。运行时/组件会执行捕获准备、等待已登记的有限加载任务，并在继续等待后续实例前立即冻结各自 Canvas/WebGL 最终帧；任一资源或页面捕获失败都会记录具体原因并使导出明确失败，不返回透明空图冒充成功，也不改用旧静态页面后备。Mixed PDF 不启动 Slide 动态实例，而是把 Slide 写成静态 HTML composition，Flow 使用语义打印计划，Spatial 按镜头输出 SVG；纯 Flow/Spatial 也不执行动态 Runtime/Component。声明式交互、声音和元素入场/退场不会保留；`playbackInitialVisibility: 'hidden'` 不应用，节点按作者稳定可见性处理。视频保持封面或首帧，不会播放。画布内教师控制器默认不进入静态导出，只有节点明确启用静态导出时才进入纯 Slide 捕获。

当前静态导出捕获的是作者/组件通过 `capture.waitUntil()` 与 `prepareCapture()` 准备好的一个确定帧，不会自动抽取动画全过程。动态过程多帧捕获仍是研究项；在时间点、帧数、输出形式和真实课例需求得到验证前，编辑器不会另加第二套捕获时间线。

### 14.4 导出 PPTX

1. 单击顶部“导出”→“PowerPoint（PPTX）”。
2. 等待全部场景对象生成。
3. 选择保存位置并用 PowerPoint 或兼容软件检查。

PPTX 使用 16:9 宽屏版式，每个场景一张幻灯片，并按编辑器中的前后层级逐个生成对象：

- 未使用可见着重号且不属于左起竖排的文字导出为 PowerPoint 原生文本框，可直接改字并调整常用文字样式；包含可见着重号或使用左起竖排的文本节点导出为独立透明图片，可整体移动、缩放和删除，但不能在 PowerPoint 中逐字编辑；
- 公式由共享渲染器生成独立透明图片，Formula ID 与无障碍文本写入对象元数据；可整体调整，但不能在 PowerPoint 中编辑公式结构；工程检查会明确列出该静态化差异和可能的公式裁切；
- 基础图形优先导出为 PowerPoint 原生形状，可调整填充、线条、大小和旋转；
- 图片导出为独立图片对象，裁剪、圆角、翻转和羽化效果会合成进该图片；
- 视频导出为带文件名的静态视频封面/占位，不保留播放、声音和时间事件；
- 画布内教师控制器默认省略；显式启用 `includeInStaticExports` 时只保留静态外观，按钮不工作；
- Slide 互动组件按实例创建独立 Published generation 并导出为透明静态图片，可移动、删除、复制和重新排版，但不保留点击、拖拽、动画等行为；Slide scene/surface DOM 与 Slide scene-scope Phaser 使用真实实例捕获，单个实例失败后只对该实例使用作者静态后备或诊断占位，已经成功的快照继续保留；
- 当前场景可见的全局原生文字、图片和图形继续按独立对象导出；其中着重号文字和左起竖排文字遵循上述图片保真规则。纯 Slide 的 global Component 只在静态导出语义下捕获当页可见外观，不证明 playback 的 global scope/session lifetime；
- Slide scene API 2 canvas Runtime 与 API 3 DOM Runtime 会优先由隐藏 Published host 捕获单项透明快照；失败按 Runtime 条目记录，只回退该项，不清空其他成功快照。捕获失败或未产生有效图片时使用工程登记的静态后备；实际快照和后备都不可用时显示可选择占位并报告。纯 Slide 才纳入 global API 2 动态层，Mixed Slide 不重复合成 global；Slide surface Runtime 不执行真实捕获，Spatial Runtime/Component 只使用静态后备或 SVG 占位，Flow 不执行动态实例也不映射 PPTX；
- 隐藏节点不导出，场景背景写入幻灯片背景，不会额外生成一张覆盖全页的静态截图。

PPTX 的定位是提取素材和继续排版，而不是高保真静态归档。实时 Player 的运行时 underlay、Phaser Canvas、组件 DOM/WebGL、运行时 overlay 使用固定平面；导入 PPTX 后这些视觉会变成独立图片并按对象顺序放置，因此混合渲染器的固定平面关系不保证逐像素复现。需要完全固定画面时请导出 PDF；需要保留互动时请导出单 HTML 或网页包。

### 14.5 导出检查建议

- 小中型互动交付可选单 HTML；含大视频、大量声音或其他资源密集内容时优先网页包；打印或固定版式选择 PDF；在 PowerPoint 中继续编辑时选择 PPTX。
- 纯 Slide PDF 固定真实 Published 页面，页面资源失败会明确失败而不改用静态页；Mixed/Flow/Spatial PDF 使用各自静态表达。PPTX 中普通原生节点可继续编辑，公式、着重号文字、左起竖排文字和互动组件只保留静态快照；只有上述受支持的 Slide Runtime/Component 条目优先真实捕获，失败时按单项回退到 `staticFallback` 或可见占位。
- 大量高分辨率图片和视频会增加导出时间、文件体积和内存占用。含大视频时直接优先网页包；单 HTML 出现体积警告时改用网页包，其他导出失败时再压缩素材或删除未使用素材。

## 16. 安全与本地数据边界

- 编辑器 Renderer 没有不受限的 Node.js、文件系统或 Shell 入口；桌面操作通过 Preload 暴露的冻结 API，并继续校验 IPC 参数、路径和文件类型。可信扩展若与该宿主同上下文，可以使用宿主明确提供的能力；这不是外部导入造成的安全缺口。
- 编辑器主框架禁止任意外部导航和新窗口；远程媒体/API 只按工程声明与宿主策略开放，下载和设备能力只在出现真实 consumer 后逐项接入。
- Slide authoring / playback 使用主 Renderer 文档中的 Published V2 宿主。authoring 状态主动冻结互动、媒体、宿主动作、导航与课程状态写入，并用带 session/revision 的版本化 direct patch/ACK/error/target 协议隔离陈旧更新；这是一条作者职责边界，不把可信 Runtime/Component 重新定义为不可信代码。Flow / Spatial 专用作者面与镜头语义保持不变。
- `.h5lesson`、最近工程列表和自动恢复副本保存在本机；单 HTML、网页包、PDF、PPTX 仅写入用户在系统对话框中选择的位置。
- 离线便携单 HTML 不开放外部 origin；网页包只允许包内资源及部署后的同源连接，不开放外部 origin；在线轻量单 HTML 只放行远程素材的精确 HTTPS origin 与工程声明的 `https`/`wss` `connectOrigins`，远程脚本仍禁止。三者中的可信运行时和组件代码都可控制课件页面自身。
- `.h5lesson` 的自由运行时和 `.h5component` 都是可执行代码，不等同于普通图片素材；本产品只接收已经审核的 Runtime/Component，格式校验本身不替代该审核。

## 17. 常见错误处理

| 提示或现象 | 建议 |
| --- | --- |
| 工程文件损坏 | 重新复制原文件，或从备份/自动恢复副本恢复；不要修改压缩包内容 |
| 工程格式版本不支持 | 使用创建该工程的兼容编辑器版本，或升级当前编辑器 |
| 最近工程无法打开 | 文件可能已移动；使用“打开”重新选择新位置 |
| 自动恢复失败 | 立即手动另存工程，检查磁盘空间和用户目录写权限 |
| 图片类型不支持 | 转为 PNG、JPEG、WebP、GIF 或 SVG |
| 图片读取失败 | 重新导出图片，确认扩展名与内容一致且文件未被占用 |
| 声音或视频无法导入/播放 | 转为标准 MP3/OGG/WAV/M4A 或 MP4/WebM，确认浏览器可解码且文件未损坏 |
| 视频在单 HTML 中启动缓慢 | 改用网页包；大视频不建议以内联 Base64 单文件交付 |
| 组件缺少 manifest/runtime | 联系组件作者重新打包 |
| 组件 manifest 校验失败 | 按组件开发指南修正字段、版本和文件路径 |
| 组件包无法删除 | 在“组件”→“工程组件”卡片查看场景/全局实例数并定位、删除全部实例；被引用的包会被安全阻止删除 |
| 组件替换失败 | 必须选择同 ID 且覆盖现有实例作用域的新包；失败不会改写当前工程 |
| 组件运行异常 | 打开“工程检查”，导出诊断报告后交给组件作者；故障实例会被隔离，其他内容应继续运行 |
| 导出被阻断 | 打开“工程检查”，逐项定位并修复“错误”；提醒和建议不阻断 |
| 保存或导出失败 | 检查权限、文件占用和磁盘空间，改存其他目录 |
| 单 HTML 文件过大 | 按提示改用网页包；若继续单 HTML，请在目标电脑实测启动速度和内存占用 |
| 网页包打开空白 | 确认已经完整解压，且 `index.html`、`course-data.js`、`player/`、`assets/` 等目录结构未被破坏 |
| PDF/PPTX 导出慢或失败 | 压缩高分辨率图片、减少场景/素材后重试 |
| 双击入口未打开编辑器 | 确认已安装 Node.js LTS；保留完整源码目录和 `package-lock.json`，查看启动窗口中的构建错误后重试 |

应用会把主进程、编辑器、预览和组件的异常写入轮转的本地诊断日志；界面提示会给出中文原因和处理建议。可从“工程检查”导出文本诊断报告。单个组件异常不会使其他场景停止工作。

## 18. Editor 1.0.0 收敛边界

Editor 1.0.0 不提供通用关键帧/路径时间轴、节点连线式状态机、内置题库/成绩系统、多人协作、云存储、模板市场、组件热重载、移动端编辑、任意网页导入、DOM/Phaser/Three 自动代码转换或视频文件导出。当前一等公式覆盖行、标记、运算符、分数、根式、上下标和围栏，并提供受限线性输入、结构模板和实时预览；尚不支持任意 LaTeX、矩阵、向量、分段函数、多行对齐、空间光标或虚拟数学键盘。编辑器提供事件驱动的元素入场/退场、顺序/并行步骤、表单式场景/全局交互、声音库和可编辑视频节点；可信运行时和组件负责复杂连续动画与业务互动，Three.js 如需使用只随具体内容打包。

Blueprint、AI 局部 patch 和其他编辑器内 AI 接入统一延后到 2.0 以后。1.x 的 Slide 统一画布只提供版本化、可校验的 direct authoring patch / ACK / error / target 与显式目标边界，不会调用模型、自动理解画面或替用户修改工程。Unified Authoring Blueprint 仍是未评审的研究提案（2026-08-13，存于 Git 历史），不是当前产品能力；AI 可在编辑器外通过当前 Skill 和可复现脚本生成完整 `.h5lesson`。

编辑器外部 AI 路径以两个仓库 Skill 为机器执行真相：`orchestrate-courseware` 先写出并确认中等详细的 `01-teaching-plan.md`，再写带表面、布局和逐步操作的 `02-presentation-script.md`；确认后 `build-courseware-project` 盘点资产、选择 Native / Runtime / Component，使用仓库真实 TypeScript API 增量构建或局部修补 Course Project V9，并做保存重开、Player 与导出验证。教师工作流不使用 Hash、审批状态机或 Evidence 清单。自动管线最多标记 `engineering candidate`，不能自行授予 `art candidate` 或 `accepted`。

PDF 和 PPTX 都不保留场景导航、声明式交互、声音、视频播放、自由运行时和组件行为；单 HTML 与网页包当前保留原生交互、媒体、Slide scene/surface、Flow block/surface 和 Spatial world/surface 的本地 DOM Component、Slide scene Phaser Component，以及 Slide scene-local 与 session-global API 2 DOM/Phaser/hybrid、Slide scene-local API 3 DOM 和 Flow surface-local API 3 DOM Runtime 的真实播放。global Component 只证明可见挂载，不具有已证明的 global scope/session lifetime。Published 会话会初始化已声明的 `courseState` 默认值；`node.click` Interaction 可读取并同步设置它，受支持 Runtime/Component carrier 与导航守卫使用同一份 Store。守卫只检查跨 location 的 go/next/previous，replay 不检查，restart 绕过守卫并重置状态默认值。Slide scene Runtime API 2/3 的 `presentation` 已接线；API 2 `nodes`、Slide scene 以外的 `presentation`、动态 Runtime 守卫、Flow/Spatial scene-local API 2、global API 3、未覆盖 shared carrier、Component hybrid、声明式 Runtime/Component 事件触发或 Flow/Spatial 动态静态捕获仍未实现 parity。统一全局层可直接编辑母版式原生元素、教师控制器和全局 API 2 Runtime；稳定画面应主动创作为场景状态，任意运行时代码不会被反向拆成可视化节点。

开发者可使用 [五路径渲染宿主基准](../examples/render-host-benchmark/README.md)核对原生节点、Runtime API 2 Phaser、Runtime API 2 DOM + Three.js，以及 Component API 4 的 DOM 表格与 Phaser 仪表。自动化压力段执行 25 轮，合计 100 次定制场景切换和 25 次末页重播，并检查挂载点、Canvas/WebGL、活动 RAF、控制台异常和外部请求。

自动化验证以当前 `npm run typecheck`、`npm test` 与隐藏 Electron E2E 的实际结果为准（E2E 使用 `COURSEWARE_E2E_BACKGROUND=1`，窗口不显示、不进入任务栏且不抢焦点）。历史 W1/W3 基线数字（2026-08-13）与验证记录已随文档整合移除，存于 Git 历史。当前结果上限为 `engineering candidate`：真实课例的人工验收、另一台干净 Windows 的首次启动冒烟尚未完成，不能宣称 `accepted` 或发布就绪。
