## 2 建议的分流目标

分流对象是正式组件实现及其有效状态版本，以及该组件中真正耦合的程序范围；不是整课，也不是每个 DOM 节点或每个事件。作者不填写新 carrier 标记、能力编号或注册表，也不默认按可抽取模板创作或限制 API5 能力。以下是软件的出口判断范围，不是创作规范。

容易理解的判断顺序是：

1. 已有直接实现或能保真投影的静态内容，沿现有直接出口。
2. 有程序时，检查程序及依赖是否只使用组件局部环境和现有转换器已承接的能力；覆盖完整才抽取。API5、引擎名称、有无脚本、代码长短都不单独决定出口。
3. 需要完整浏览文档，或实际环境／动态依赖无法确定，就保原生 iframe。每个真正独立或耦合的程序文档用一个必要载体；软件不再给它套 transport iframe。已有嵌入文档只有确认独立时才去掉外层包装，不能强拆 parent/top 或布局耦合。

| 内容与程序 | 建议出口 | 资格依据与典型操作 |
| --- | --- | --- |
| 普通文字、公式、专业正文、静态 HTML/CSS/SVG | 可保真的局部投影同文档 | 沿现有专业／静态投影。完整 html/body 外壳本身不是需要 iframe 的理由；但真正依赖独立文档兼容模式、文档视口／排版语义的静态全文可 native，不能反过来“无脚本一律 direct”。 |
| 软件已有直接实现的专业组件与默认实现 | 同文档共享实现 | 定义和依赖准备一次，实例只持数据、状态与独立 Scope。软件固定来源由既有预置 owner 确定，不能凭作者填的 key／名称或“像预置”授信；当前可编辑 Source 预置的身份接线仍有差额。有源码定制时重新判断实际程序，不重写保存工程或取消源码编辑能力。 |
| 普通局部 Web 互动 | 同文档，作为本次必须恢复的能力 | 局部 DOM/SVG 查询和修改、onclick/监听、样式和类切换、输入反馈、局部计数、函数计时器及简单 Canvas 动画，均属于候选目标；引用、事件和任务生命周期能由现有转换与 Scope 承接才 direct。不是见到这些关键词就自动通过。 |
| 局部 API5 Source | 同文档，作为本次必须恢复的能力 | 初批取固定骨架／文本、root 局部查询与修改、instance 数据、scope.state/events/cleanup、resources 与确定纯计算；已有其他正式端口按实际消费者承接。模块依赖闭合，函数体及依赖都需纳入判断，不能只看导出了 mount。来源未知的动态 HTML／事件代码、未知 receiver 或完整 Document 依赖先 native。 |
| 静态外壳中的 iframe/object/embed | 确认嵌入内容独立后，外壳直接输出，保嵌入载体自身 | 外层没有脚本不能证明独立：复用已有子文档／Scope／资源引用事实，确认子文档不依赖该外层的 parent/top/frameElement、base／URL 或布局语义才不加软件外层 iframe。具体耦合或内容／环境未知时保整个耦合范围 native；不为此建通用子文档分析或探活矩阵。 |
| 完整网页程序、文档导航／解析器行为、无法确定环境依赖的库 | 原生 iframe | 需要真实文档、原脚本装载／源序、浏览器全局或动态未知程序等能力时，保原件和依赖。当前已验的外来 Phaser/Pixi/Three 网页继续使用此路；不按引擎名字永久拒绝 direct。 |

Canvas、SVG、WebGL 或代码长度本身不决定出口。一个只在自己的 canvas/root 上绘制、生命周期已由软件承接的局部程序可以 direct；一个很短但依赖真实 Document、动态源码或不可确定环境的程序也可以 native。对第三方引擎不借本任务制作一套新引擎适配平台。

## 3 分流怎样落在现有编译边界

建议在 `compileCoursePlayback` 所使用的原编译服务中形成一次出口决定及具体理由，两个正式导出入口消费同一个结果。`nativeProgram.ts` 的“有 script 即 native”规则被实际可转换范围判断替换，不再另建一份与转换器脱节的黑名单。

直接输出资格须满足三个属性：

1. 标记、样式与 ID/label/ARIA/URL 引用能由现有局部投影保留；程序作用于自己的 root 与已开放端口，不借抽取获得宿主权限。
2. 入口及其闭合依赖的实际环境引用、调用方式均落在现有可转换合同内。复用词法作用域与现有转换结果，区分局部变量和真实环境引用；普通可追踪别名随同处理。反射／动态环境访问或不透明依赖无法确定时，选择 native，不再迭代实现完整 Window/Document。
3. 程序的事件、计时、动画及资源租约能由现有 Scope/实现 dispose 承接。闭包和模块初始化不因多实例、同页重入或顺序调整被重放；正式 state 与局部内存继续保持原有区别。

“没有诊断”不是资格。当前编译器还保有 `blocking:false` 的局部诊断，部分拒绝发生在调用时；不能据此把暂未触发的 unsupported 分支签为 direct。需要在同一转换遍历中明确“该转换范围已覆盖／这里需要原生文档”，仅携带派生出口与具体原因，不增加作者 Schema、注册库或新的运行验证平台。

判定只分析／准备，不执行作者程序。准备阶段确认不能保真时直接选择 native；已经运行后出现异常，只报告当前失败，不自动在 iframe 重跑。语法错误、缺少真正源文件或后台服务也不能靠 iframe 修好，应保原件与明确诊断，而不是整课拒绝或静态截图。

Source direct 接回已有 `sourceFactories`／局部环境和原 World/Host/Scope；Web direct 接回已有 classic/module/handler consumer。Source 与 Web 共用分流属性及原依赖 owner，不能分别维护两套环境规则。无 root 的行为组件同样按实际 API/环境判断，不能仅因没有 DOM root 就全部 native。

Source 第一个自动抽取资格范围保持窄而明确：固定 HTML 骨架的动态文本／数据与可确定属性可以分析，未知模板若可能产出 script/on* 不冒称局部安全；初批不要求恢复 Source 的任意 free document/window、ownerDocument 逃逸、Worker 或动态执行。这只限定转换器能证明覆盖的范围，作者仍可使用完整运行能力；输入超出该范围使用原生载体，不拒绝作品、不增模型标记，也不据此创建全语言数据流分析平台。

本目标针对正式 HTML/ZIP 的发布编译。编辑工作台保可编辑源码、现有沙箱和权限环境；不为减少导出 iframe 将外来代码直接放进有登录／文件能力的 Renderer。预览若消费编译制品就复用同一决定，其他作者消费者保既有行为并做受影响检查。

## 4 性能与生命周期目标

iframe 每个都拥有完整文档环境，会增加内存和计算开销；Shadow DOM 提供 DOM/CSS 边界，但不会创建一个独立 JavaScript 全局，也不能代替实际权限与生命周期合同。[MDN iframe](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe#usage_notes)、[MDN Shadow DOM](https://developer.mozilla.org/en-US/docs/Web/API/Web_components/Using_shadow_DOM)。

因此性能目标是普通局部互动不为每个实例起 iframe；复杂原生程序只保其必要文档。最方便的状态保留方式是“首次需要才加载，暂时离屏保留原实例并局部暂停，返回继续原实例”，不先销毁再尝试冻结。iframe 销毁后，其 JavaScript 堆、Canvas/WebGL 状态等不能由 DOM 截图或一般 JSON 自动恢复。

宿主应区分实例仍属于作品、所在场景是否活动、当前是否可见。暂时离屏／离开场景时保稳定 key、同一个已连接的 DOM、原 src 和 Scope，避免重复 mount 或移动活 iframe 祖先导致重载；复用已修的 World 投影保护。通过现有事件桥通知可控程序暂停引擎循环、动画和应暂停的媒体，回来继续。需要持续的音频／全局行为按原语义处理；休眠场景不继续发起当前场景动作。无需新增全局暂停系统或任意 JavaScript 堆快照。

当前实现仍在播放时释放离开所属场景的 Source/Web 实例；API5 MountedComponent 只有 update/updatePlacement/dispose，没有通用暂停或恢复接口。World 的 `__runtime.visibility` 目前也没有实例可见状态载荷。这项建议仍需在现有 World/Scope 事件桥接入实际场景／可见事实，并由可控程序承接局部暂停，不能把现有代码写成已自动冻结。

CSS 隐藏 iframe 不会自动把子文档置为隐藏状态；浏览器后台节流也不是宿主可以保证的单 iframe 硬冻结。[MDN Page Visibility](https://developer.mozilla.org/en-US/docs/Web/API/Page_Visibility_API)。完全不协作的黑盒可以保留原实例以避免重置，但内存仍占用，后台工作也可能继续；不能同时承诺完整内部状态、释放内存和硬暂停。

只对明确提供足够恢复 state 的程序考虑闲置释放，返回按其恢复合同重建；没有恢复能力的不作无提示超时淘汰。删除、显式复位／重建或关闭作品才结束对应生命周期。若要求黑盒一直保到关闭，应接受已访问实例累积的内存成本，不宣称此方案零开销，也不以固定 iframe 数量上限静默丢状态。

同文档实现及依赖沿现有编译／缓存尽可能共享，实例数据与 Scope 保独立。原生 iframe 可以复用同一份物化资源 URL／下载缓存，但不同 realm 的库执行和堆不自动共享；不能把 ZIP 压缩、文件变小或资源缓存命中当作 CPU／内存无损证明。禁止为共享库强行把无关实例合进一个全局文档，造成 ID、状态和退出时机串扰。

共享的是编译代码与确定可共享的专业实现，不擅自共享原来每个程序文档独立的可变模块变量、namespace 或初始化状态。局部 Web/Source factory 保原程序范围内的一次初始化和各实例间隔离；只有原合同已明确共享的业务状态才沿原 owner 共享。最低验收的两个互动实例必须同时有各自计数／状态，以发现同文档后错误串用 module cache 的问题。

## 5 SearXNG 当前接线与服务落点

当前 [searchSettings.ts](../../src/shared/workbench/searchSettings.ts) 默认 auto + Exa + 空 searxngURL；[SearchRouter.ts](../../src/main/workbench/network/SearchRouter.ts) 自动模式使用当前可用 OpenAI 路线，再按已有规则转当前选择的独立服务。[SearxngSearchProvider.ts](../../src/main/workbench/network/SearxngSearchProvider.ts) 已使用实例 URL 请求 `/search?q=…&format=json&pageno=…`，解析真实结果、部分引擎失败和后续页；[现有设置 UI](../../src/renderer/workbench/SearchSettingsSection.tsx) 已能填写本机／局域网／公网 HTTP(S) 地址。无需另写搜索 SDK 或把它伪装成模型。

SearXNG 是搜索聚合服务软件，需要一个实际运行的实例；使用无 Key 的引擎不需要模型 API Key。Docker 是服务端部署选项，官方也支持直接安装，并非普通用户或服务端必须使用 Docker。JSON 必须在服务端启用；官方明确说明未启用会返回 403，很多公共实例关闭 JSON。[官方直接安装](https://docs.searxng.org/admin/installation-searxng.html)、[官方容器安装](https://docs.searxng.org/admin/installation-docker.html)、[官方 Search API](https://docs.searxng.org/dev/search_api.html)。

| 落点 | 适用与成本 | 建议 |
| --- | --- | --- |
| 已有本机／局域网实例 | 填地址、启用 JSON、检查上游可用；不新购服务 | 有需要时用于可选接线验收，不是普通用户搜索的必需步骤。实际有没有可用实例仍按环境检查记录，不从源码默认值推断真实 profile。 |
| 本机容器新实例 | 需要可工作的容器运行环境与出网；运行在本机 | 已有环境时是验证 SearXNG 的直接路线；本方案不安装或启动服务，不把它变成果铃普遍启动依赖。 |
| 果铃共享托管实例 | 普通用户无需自己部署，服务方承担机器、流量和维护；上游仍有限流等约束 | 如要把 SearXNG 做成普通用户默认可用能力，需要 Owner 确定已有／新增服务落点与运行责任；开源软件不能代替这一选择。当前不默认新购服务器。 |
| 第三方公共实例 | 可免费试用，但 JSON 开放性、限流和持续可用性由运营方决定 | 可作用户显式选择和实网测试候选；不把随便一个公网地址写死为稳定产品默认，不做自动巡检／服务池轮询。 |

推荐当前保留“已有 OAuth／免 Key Exa 开箱可用，SearXNG 可选配置”的路由，不把本机 SearXNG 部署放到普通用户搜索的关键路径。SearXNG 技术上可以让客户端免配置：产品方预先提供一个启用 JSON 的可用服务即可，用户不必装 Docker、部署服务器或填写模型 Key。但当前产品默认实例 URL 为空，没有已验收的默认服务，因此目前这条 SearXNG 路线尚不能作为普通用户免配置交付；不是 SearXNG 本身做不到。

本机只读检查已发现 Docker CLI 和登记的 WSL2 `docker-desktop`；Podman 命令未发现。Docker daemon 是否可用、真实 profile 是否已有实例、容器及上游网络是否可达仍未知；没有启动服务、扫描凭据或发出搜索请求。具备 CLI 不等于可工作的容器服务，不能据此写“已配置”。

OpenAI OAuth 与 API Key 在 [supportsOpenAISearch](../../src/shared/workbench/searchSettings.ts) 是两条分别受支持的现有连接。当前 OAuth 使用者不需要 API Key；API 路线未实网不是 OAuth 的配置缺口。本包不创建 API 账号、不采购、不切换模型或新增收费回退。

实例接入建议沿原设置与 Main 网络服务：使用独立配置目录保存服务配置，启用 JSON、设置实际可出网的无 Key 引擎，再填写果铃实例地址。SearXNG 容器出网与果铃 Main 出网不是同一环境；若有代理需求，在服务自己的官方 outgoing 配置中处理，不能假设桌面代理已自动传给容器。

本机实施时建议用官方 Compose 单实例、绑定本机地址，并在持久化 `settings.yml` 设置 `search.formats: [html, json]`；填入果铃的地址示例为 `http://127.0.0.1:8080/`，实际端口由实例配置决定。保留无 Key 可用引擎，按真实结果处理不响应上游，不以引擎全集或自动实例轮换增加复杂度。实例配置与缓存独立保存，不进入用户工程或 HTML/ZIP。[官方 search 配置](https://docs.searxng.org/admin/settings/settings_search.html)、[官方 outgoing 配置](https://docs.searxng.org/admin/settings/settings_outgoing.html)。

发布行为用一份混合工程即可：静态正文、两个有重复内部 ID/CSS 的普通局部互动、一个局部 API5 Source、一个现有原生框架代表和既有导航。正常点击、输入、计数／动画、状态切换；保存／新 Host 冷开；标准 HTML 与 ZIP 断网使用；离屏／离页后返回保同一实例及应保的局部状态，可控循环停止再继续，复位真正清理；检查互不串扰、不重复注册。冷开按正式持久化语义，不冒称恢复关闭前任意程序内存。已验的三个框架原生能力按相关变化复用，不机械重跑所有语言／框架／Surface 组合。

性能用同一普通互动占主要数量的作品，对比当前粗分流与候选细分流：内容、布局、程序、浏览器和操作序列一致，记录活 iframe 数、进入／回访／普通响应耗时及有明显阻塞时的定向 profile。成本变化必须超过自然波动；重复采样只为处理波动，不能因低影响边缘变体不断扩矩阵。只减少 iframe 数不能单独签性能通过；也不要求所有设备统一毫秒阈值。实际性能数字须实施后测量，本研究不预填节省比例。

SearXNG 最低验收是一条果铃实际搜索与当前正式来源打开入口（设置测试／Timeline 的来源链接及其 IPC/Main consumer），加设置保存冷读和当前另一种主模型下复用同一独立服务的路由事实；不要求为了打开来源额外运行另一条工具调用链。错误／分页／部分失败已有受控证据按相关变化复用。服务不能出网、被上游限制或 JSON 未开要准确报告，不能把 HTTP200、空结果、适配测试或别的后端成功当作实网通过。不为本包重新请求收费 OAuth/API 搜索。

SearXNG 条件估时：已有可用实例约20—45分钟接入及聚焦验收；已有 Docker daemon 正常且镜像／上游网络可达，本机起实例约45—90分钟。这是实施估计，不是当前实测或截止承诺；遇 daemon／网络阻断应报告具体条件。共享托管在服务落点明确前不估交付日期。分流的正向资格尚无当前实现，本研究不给缺依据的总工时保证；实施首个普通互动与 Source 资格后才可据实际差额更新工时。

## 7 建议与待确认选择

分流目标已经由用户明确：应完成上述局部程序直接输出与复杂程序原生承载。本研究新增的建议是用同一编译转换范围产生资格和理由，不新增作者标记或另一套平台；不是批准后的实现，也不承诺任意程序必能抽取。

最新用户约束已经纳入：不默认限制创作以便抽取，由软件决定出口；优先用原实例保活和局部暂停保持离屏状态。细分流与此生命周期建议尚未实施，保活也仍有内存及黑盒后台工作成本。

普通用户免配置搜索优先沿已有 OAuth／免 Key Exa，SearXNG 保可选。只有希望默认也使用 SearXNG 时，才需要明确共享服务的运行位置和责任；本机部署不是必需步骤，不凭本文作采购／部署授权。OpenAI API Key 不属于当前 OAuth 使用前置。
