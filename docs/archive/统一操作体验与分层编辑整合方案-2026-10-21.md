## 1. 结论、目标与本轮边界

**建议保留现有统一组件树、ProseMirror、Runtime 作者桥和 DocumentSession，将“命中谁、选中谁、谁接收输入、谁显示操作、命令作用于哪里”收敛到现有编辑器的同一个交互 owner。** 不再让表面、builtin 名称、DOM 包装或是否处于 Runtime 内部决定一套独立操作规则。

需要统一的是用户操作语义和当前目标，不是把所有内容转换成同一种节点，也不是把所有编辑器塞进一个 contenteditable。外层整体和内部对象必须同时可达；跨层切换后，画面、工具条、右侧属性、图层、键盘和 AI 选区必须指向同一个明确目标。

目前多数正式数据、写回、保存和历史机制已经存在。真正缺口是不同交互入口没有完整消费同一个精确目标，而且可编辑能力、几何目标、输入焦点和编辑位置混在一起。仅统一工具条皮肤、扩充双击类型白名单或继续增加表面专用处理，不能消除根因。

本轮交付只有本方案：代码只读探索、产品分析、官方资料联网核实。未修改产品代码、工程、Skill、任务板或发行物，未运行产品测试、构建、付费模型、commit、push 或发行。已有咖啡创作任务和其他 dirty 成果不属于本轮写域。

## 2. 产品根因：结构统一没有形成操作统一

用户真正面对的是四类意图：选中眼前内容、修改内容、操作包含它的整体、试用作品。用户不应通过试错识别 guoling.text、document-block、author spot、Flow block 或 iframe。

当前有六个互相交叉的边界：

1. 自由画布主要依赖有 frame 的几何对象，Flow 依赖文档选区和原子 NodeView。
2. 普通 group 有子对象，但未进入现有“容器编辑位置”路径；真实 Slide/Flow/Spatial container 又通过另一工作区进入。
3. Runtime 已提供精确内部作者地址，但很多 UI 消费者只拿到 owning instanceId。
4. 文本编辑本体部分共用 ProseMirror，外壳却分别决定双击、光标、IME、blur、Esc、提交和工具条。
5. 属性、图层、右键、快捷键、AI 高亮和结果定位没有完整共享目标精度。
6. 草稿、焦点、临时选区、冻结 AI 目标和工程作者身份性质不同，现有接线有时用相同实例 ID 代替这些区别。

因此，统一必须从“操作地址和输入所有权”开始，同时覆盖外部消费者。只在某一编辑器里补功能，会继续产生新的体验分支。

## 4. 建议的统一产品规则

### 4.1 用户可理解的三层目标

- **整体**：章节、图文组合、组件、容器等有实际内容意义的范围，可调整整体布局、背景、位置和尺寸。
- **对象或字段**：图片、标题、段落、图表标题、按钮文案等眼前的可操作内容。
- **内容范围**：文字光标/选字、表格单元格范围、公式等专业选择。

这只是交互层级，不新建工程作者树。普通 HTML 包装 div、布局辅助节点和 Runtime 技术边界不自动成为用户必须逐层穿过的层级。对象、作者字段和文档范围可能不是同一种可删除结构，界面必须基于其实际能力显示命令。

### 4.2 默认操作建议

| 意图 | 统一规则 | 必要细化 |
| --- | --- | --- |
| 预知点中谁 | Hover 显示轻边界及语义名称，点击结果与提示一致 | 使用实际前景绘制命中；不能越过真实遮挡或点击透明空壳误选下层 |
| 修改普通文字 | 点击按位置放置光标；拖动选字；双击保留正常选词/短语行为 | 原生正文、独立文字和可定位 Runtime 文字使用共同规则；plain 字段不伪装富文本 |
| 操作图片/形状等 | 单击选眼前实际对象，显示同一套对象反馈 | 不再要求图片独有 Alt 深选；已选子对象下次手势保持稳定 |
| 操作整体 | 点边框、名称标签、父级路径，或层级菜单明确选整体 | 从内容直接选择任一有意义祖先，不以连续双击次数表达深度 |
| 移动/缩放 | 对象边框/把手开始；文字内部拖动留给选字 | 自由布局写 frame，流式布局调整顺序/宽度/布局约束；没有能力时不显示假手柄 |
| 进入专注编辑 | 共同的“编辑内部/返回上层”动作，保持目标定位 | 真 container 复用专业工作区；普通日常改字换图不以逐层切工作区为前置 |
| 右键/属性/AI | 与当前点选或右键新命中的精确目标一致 | 不能标签是内字段，执行却作用于整个实例 |
| 多选 | 建议对象态统一 Shift+点击增减选择，框选当前编辑范围；Alt 深选仅作辅助 | 正在文字输入时 Shift+点击仍服从文字范围选择；父子同时出现时保留祖先排重，跨载体不成立的命令禁用并说明 |
| 空白操作 | 不同布局保留有价值导航差异，并给一致工具提示 | Spatial 空白平移、Slide 框选不强行等同；空间/中键平移和框选工具应可发现 |

内容优先针对“最小有意义且可可靠写回的目标”，不是最深 DOM 节点优先。重叠图层仍按绘制/可见性判定，并提供当前位置层级列表；锁定对象可被检查，但修改能力受锁定约束，不绕过锁定编辑子项。

### 4.3 目标反馈和操作栏

1. 同一时刻只有一个活动交互目标或一个明确的多选集合。主目标实线、必要父级弱边界；文字光标与包含它的对象范围是同一层级状态，不是竞争的两个选区。
2. 层级路径显示“作品 › 生长章节 › 图文组合 › 照片”等有意义名称。现有容器编辑 path 不被覆盖；对象祖先列表由正式归属派生。
3. 一个当前目标只显示一套上下文快捷操作。固定应用导航可以保留，固定格式区与浮动快捷条共用命令定义和当前格式状态，不各自维护一份选择。
4. 局部文字接管后，父组快捷条、外层 PM 上下文操作/段落 handle 和其他对象操作退出激活状态；仅隐藏视觉不足以满足此规则。
5. 字体、字号、加粗、颜色等高频控件保持位置和语义；rich/plain/cell/formula 的专业差异按能力显示，不能仅因位于 Runtime 而切成另一套外观。
6. 没有可写目标的可见内容不显示假的编辑光标。整体、参数或源码入口要明确可达；无支持原因不能变成静默双击无效。

### 4.4 焦点、键盘、提交和撤销

| 状态 | 输入/命令归属 | 离开与历史规则 |
| --- | --- | --- |
| 普通文字/正文 | 当前文字适配器接收光标、选字、Enter、输入法和文字剪贴板 | 有效输入沿同一 Session 提交；Esc 离开文字层级，已确认输入不整段丢弃；Undo 撤回输入 |
| 表格 cell | 同一 rich-text 命令；表格适配器接收 Tab/Enter 导航 | 保留稳定 cell ID、合并区和公式语义；光标键不被全局层级导航抢走 |
| 对象/内部字段 | 对象或字段能力决定复制、删除、重复、变换 | 不支持独立删除/复制的作者字段不得静默升级到 owning instance；可显式选父级 |
| 公式/参数临时表单 | 表单自身定义确认/取消 | 与普通正文离开不同，但差异来自明确表单状态，不能来自 Surface/builtin 名称 |
| 源码编辑 | 现有源码编辑器接收自己的文本输入与未应用草稿动作 | 不强行用普通正文覆盖代码编辑；正式采用仍走 Session |
| IME composition | 当前输入控件优先 | 不用 Esc/Enter 切父级、删除对象或重建编辑器；等待现有 compositionend/ACK 保稿机制 |
| 工具条/弹出控件 | 保留当前内容选区，工具操作仍作用于它 | 点击工具条不触发错误 blur 提交/切目标；键盘可进入工具条并返回原选区 |
| 编辑/试运行 | 编辑接管选择与修改，运行交给作品交互 | 复用现有 edit/run；不为每类嵌套另设局部运行模式，也不全局暂停所有程序 |

窗口快捷键、菜单、右键和快捷条最终调用同一语义命令。Ctrl/Meta+A 在文字态选择文字，在对象态选择当前编辑范围对象；同一焦点下与菜单“全选”一致。Esc 的上下层次为关闭临时菜单 → 退出当前普通文字编辑 → 当前对象 → 父级/范围；明确取消表单和输入法优先处理。

普通文字输入使用同一历史分组定义：连续输入段、格式操作、一次拖拽、一次换图分别形成可理解的 Undo 单元。复用已有 historyGroup 及其输入边界策略，不按表面重新建栈，不把 800ms 当前实现细节当产品限额。专业草稿若继续以最后一次整段提交，就无法达到与正文一致的输入撤销；应把其有效输入 operation 边界送入现有正式提交链。

## 5. 最合适的技术路线

### 5.1 路线比较

| 路线 | 判断 | 原因 |
| --- | --- | --- |
| 保留现有 PM/组件树/Runtime bridge，收敛交互 owner 与适配器 | **推荐** | 直接处理当前目标精度、输入和命令分裂；复用已有专业编辑、写回和保存 |
| 全量更换为 Tiptap/Lexical/tldraw/GrapesJS 统一编辑器 | 不推荐作为本次路线 | 未找到当前问题必须换库的证据；换库不解决 iframe、作者地址和层级，还要重做正文/表格/公式/导出 |
| 只把各处快捷条改成同一皮肤 | 不充分 | 选区、focus、命令作用域仍并行，错目标与双击无入口仍存在 |
| 给所有 Runtime/HTML 拆原生子节点 | 不采用 | 会改变源码/布局/程序语义；任意 Canvas 和隔离 frame 也无法通用反解 |
| 一个跨所有表面和 iframe 的 contenteditable/PM | 不成立 | Selection 属于 Document；iframe 独立文档，统一体验必须在应用层协调 [W4] |
| 所有内层操作都先强制“深入编辑” | 不推荐默认 | 延续层级阻碍；专注编辑应是辅助，普通改字/换图需要直接可达 |

本地依赖已核：React 19.2.7，prosemirror-view 1.42.3、state 1.4.4、model 1.25.11；package.json 未直接声明 prosemirror-history，当前 SharedDocumentEditor 明确不安装第二正式历史。外部官网滚动版本不等于本地版本；本方案不要求升级依赖。

### 5.2 现有 owner 上的职责收敛

建议在现有 Bridge/kernel 编辑状态中收敛当前交互，而不是在其旁边建立新 selection store 或通用编辑平台：

~~~mermaid
flowchart TD
  A["Surface / PM / Runtime / 图层入口"] -->|"候选、精确作者地址、视图几何"| B["现有编辑器交互 owner"]
  B --> C["同一选中反馈、层级、快捷条、属性、键盘"]
  B --> D["workbenchSelection：AI 捕获与结果定位投影"]
  B --> E["专业编辑 / authorSpotEdits / 布局命令"]
  E --> F["现有 kernel / Bridge / DocumentSession"]
  F --> G["canonical 内容、History、恢复、保存"]
~~~

专业编辑器仍可有自己的 EditorView 和局部浏览器 Selection；它们不各自决定谁是应用的活动目标。每文档/编辑视图保留自己的恢复位置，当前可见编辑范围统一决定谁接管输入。AI 已发送的冻结目标/pin 和人工当前目标用途不同，不能因“统一”将二者合成可变引用。

当前对象 IDs、Flow selection、selectedSpotKey、editingTextNodeId 等外部可见含义应逐步变成共同状态的派生投影；同一候选迁移时停止旧分支写入，不维持长期双写。旧控件可以暂读派生 IDs，但不能继续独立决定目标。

### 5.3 目标的最小必要信息

以下是职责草图，不是新持久格式、不是新的执行授权类型：

~~~typescript
type InteractionSelection = {
  documentId: string
  epoch: string
  context: {
    rootInstanceId: string
    containerId: string | null
    plane: 'local' | 'underlay' | 'overlay'
    stateId?: string | null
  }
  targets: ExistingAuthorAddress[]
  inputOwner: 'none' | 'document' | 'field' | 'cells' | 'formula' | 'source'
  phase: 'selected' | 'editing' | 'gesturing' | 'handoff'
}
~~~

- ExistingAuthorAddress 复用现有 instance、DocumentSelection、ComponentAuthorField/dataPath/sourceRegion 等可写语义；不是要求把执行权限/grant 类型直接当 UI 状态。
- 位置、hover、bounds、光标 bookmark、mountGeneration 是当前视图数据，不能持久化为第二套作者身份或坐标。
- 对象层级从 owningContainer/childIds 派生；字段以 owning instance 加稳定 slot/authorKey 等地址派生。author spot 本身不是包含任意 DOM 祖先的对象树。
- capabilities 从现有专业 adapter/作者绑定派生，包括编辑、格式、替换图、几何、排序、可独立复制/删除等；不建设新的全局注册/审批平台。
- local state 身份必须同时携带 container，不能把两个容器中的同名状态混为一个目标；共享实现的修改不因点选普通实例而被隐式扩大。
- 普通当前编辑目标的初始值/版本，在本次成功 ACK 后按已接受 operation 推进，不能每次盲目重抓最新版本覆盖外部冲突；冻结 AI 任务的目标和授权不随之改写。

## 6. 命中、层级、拖缩和范围

### 6.1 命中与几何解耦

自由 frame、Flow DOM/PM、Spatial 视口和 Runtime realm 各自提供已有真实目标/几何。共同规则负责选择目标，不把 freeSurfaceTargets 扩成包办所有载体的第二场景树。

必要调整：

1. free targets 继续服务几何变换；无 frame 不能成为“无法选取”的理由，也不能为自然正文强行补 frame。
2. Flow NodeView、InstanceView 与宿主 pointer 只上报候选或接管结果，不能各自把同一点击最终写成不同 selection。
3. 统一普通点击、已选对象再次按下、右键和 hover 的目标深度；Alt 深选可保留为辅助，不是图片可编辑的隐藏前提。
4. Runtime 统一询问 requestComponentAuthorHit，并保留 painted 前景结果；不能用宿主矩形命中越过真实遮挡。
5. Spatial 保留 world/HUD、相机及 semantic zoom 过滤；全局编辑范围、祖先 hidden/locked 和 active state 沿现有规则判定。
6. 父子多选保留 selectedFreeTargets/courseObjectEdits 的排重，整体与后代不能一次变换两遍；不合法跨 owner 排序不静默重归属。

Hover 等高频观察复用现有 spot 订阅、局部几何和 realm hit，不在每次 pointermove 读取完整工程/HTML 或重建 Runtime。异步命中结果只更新其所属文档、当前指针意图和有效 mount；不能让旧 hover 响应覆盖新的点击目标。点击与实际手势继续沿同一个 resolver 确认作者地址，不以测量缓存另造可写身份。

### 6.2 层级与专注编辑

现有 editingContainerId/path 是“现在打开哪个专业工作区”，不是“当前选中对象的所有祖先”。应保留前者，从同一正式树派生后者，并供画布路径、图层和“选父级/子级/同级”命令共用。

透明布局 group 内的普通对象应直接可达；真 container 保留专业工作区与进入/返回。若内部操作需要切入专用工作区，同一次明确操作应携带目标到正确位置，恢复该对象/光标，不变成“先进入后重新找”。对复杂容器可保留原位查看和专注编辑，但不复制工程或绕过 container 状态/作用域。

文档内部树应作为“内容层级”显示，不能误成每段可自由 z-order 的图层。纯包装节点可折叠，用户创建并命名的有效组合不能因过滤而失去整体入口。

### 6.3 拖动和缩放

- 自由对象继续使用现有 frame/矩阵/吸附与专业 resizeMode；文字框扩宽不自动缩放字号。
- Flow 正文/流式组拖动优先表达顺序、宽度和容器布局参数；图片裁切、整体缩放和改列宽是不同命令，不能互相替代。
- Runtime 内部有 geometry author 地址的对象复用现有 CSS/source/records 手势写回；没有 geometry 能力时可以选中、改字/换图，但不显示可拖缩承诺。
- 选中框是派生几何，不能把测量像素写回成另一套持久布局。

## 7. 文字与 Flow 文档投影的整合路径

### 7.1 合并宿主外壳，不重造文字引擎

将 FlowProfessionalDraftEditor 与 useSlideNativeTextEditor 重复的焦点、初始 caret、portal、blur、IME、Esc/完成、工具条挂载、ACK 后切换等职责收敛到一个共同专业编辑宿主。Text/Formula/SharedDocumentEditor 本体继续复用。

需要覆盖的内容适配：

| 内容 | 复用/补齐方式 |
| --- | --- |
| 普通 rich 文字 | TextComponentEditor/SharedDocumentEditor；保留 inlines、links、math、rangeIds |
| document-block | 为 content/title/body/citation/list item/code 等现有 slot 提供可定位专业编辑；嵌套标题不再仅运行态绘制 |
| Runtime rich dataPath | 使用同一文档字段适配，而非按 owning builtin 猜编辑器或转纯文本 |
| Runtime plain string | 可以保真正 plain 输入内核，但共同外壳、光标定位、工具条和生命周期；不再进入即全选整个字段 |
| 表格 rich cell | 复用 stable cell 地址、rich inlines、合并区和专业导航；保留原 cell-text 的格式保护 |
| 图表标题/标签 | 接共同字段目标和输入；不把修改一个标题升级为重做整张图 |
| 公式/代码 | 继续专业语义；公式表单与普通文字状态明确，源码用既有代码编辑器 |

Caret 必须由点击位置或现有可用 bookmark 映射进入，原字符/公式边界无法精确定位时应给稳定、可解释的位置，不能默认全选再误覆盖整段。格式能力读取实际字段及 source authoring 支持，不虚构 rich capabilities。

### 7.2 连续正文与独立构图对象不能混为一谈

同一操作体验不意味着所有文字都属于同一段连续文档。应维持：

- 连续叙述由文档 owner 管理 Enter、跨段选区和顺序；不因外层视觉布局而无意拆成无法连续编辑的岛。
- 独立文字框、图注、界面标签仍可拥有独立语义，但日常点击、光标、工具条与退出体验一致。
- 程序内部字段仍由其作者源/records 管理，不通过 DOM 抓取重建一份正文。

不能从“没有 frame”或某个 CSS 类名就自动判断所有旧 group 内文字都该变成一篇正文；先保留现有作者语义与身份。新内容装配由软件保持正确正文/布局投影，不要求模型写额外类型登记。

### 7.3 同 DOM 连续文档优先 contentDOM；先验证具体组布局

PM NodeView 有 contentDOM 时由 PM 管理其可编辑后代，没有时内部需要自管 [W1]。因此，对确属同一文档的 section/阅读布局，优先让 PM 可遍历其专业子内容，不长期以原子对象包住普通正文。

当前 group 子树由 React/World 挂载，不能直接加 contentDOM 后继续让两个 owner 操作同一 DOM。若需要编辑专用布局组投影，必须满足：

1. 它只是从正式 group/childIds 派生的编辑投影，工程仍保存同一实例树和现有组件。
2. 对纳入 contentDOM 的可编辑后代，PM 独占其可编辑 DOM；World/React 不再并行重排这些后代。原子媒体/程序保持明确 NodeView owner。
3. flowDocumentBlock/flowDocumentEdits 的身份、父子往返、保留未选后代以及 .body.md/.body.html 的读写映射一起核对，不能只改画面。
4. 不将任意自由构图、旋转组或程序强行纳入一条阅读选区，不改变原布局或 silently staticize。

**T1 局部验证**：用当前咖啡的一个无 frame Flex/Grid 图文组，验证段落/标题/图片真实编辑、IME、顺序/身份往返和现有布局保持。只有这项真实 DOM owner 属性需要验证，不跑整篇创作。如果单一 contentDOM 会破坏该组合的独立语义，则保留局部 EditorView，经共同宿主整合，明确其为独立内容区域；普通连续正文目标仍需由正确文档投影满足，不能以“技术不可行”为由重新拆碎正文。

### 7.4 输入提交与目标切换

普通有效文字 operation 应复用现有 ACK/拒绝和 historyGroup 机制，避免“正文按段撤销、局部整场编辑一次撤销”。切换流程统一为：在初次指针动作中捕获原编辑目标及用户指向的新候选作者地址/局部 caret 意图 → 结束/等待合法输入 → 提交并等待现有 ACK → 验证并重新定位同一候选地址 → 一次选择/进入编辑。

- 保留已有 Slide/Spatial“提交后接续同一次点击”的用户结果，但不能原样推广其按坐标再命中的实现。Flow 提交后自然高度或布局改变时，初始屏幕坐标可能已指向其他内容；必须继续定位原意图对象。无法取得可靠地址时明确保留原选择/提示重选，不能暗中改投新的命中对象。
- 只保留一次待续接的明确选择意图，不构造任意事件重放队列；不重放 Runtime 未知业务点击。
- IME、格式弹出框、失效目标、拒绝提交和外部改动沿现有保稿机制处理，不能吞稿或静默改父级。
- 选区变动本身不进入内容 History；切入父级也不修改作品入口/归属。

## 8. Runtime、HTML 和隔离文档的整合边界

### 8.1 已有链路必须复用

[authoringDom](../../src/components/web/authoringDom.ts) 自动发现真实 text node/img；[ownedDocumentAuthoring](../../src/components/web/ownedDocumentAuthoring.ts) 与 [nestedAuthoringDom](../../src/components/web/nestedAuthoringDom.ts) 处理嵌套文档；[SandboxComponentRuntime](../../src/player/components/runtime/SandboxComponentRuntime.ts) 汇报 authorKey/binding/几何并提供 realm 命中；[componentAuthorEdits](../../src/core/components/authoring/componentAuthorEdits.ts) 和 [authoringRecords](../../src/components/web/authoringRecords.ts) 编译正式变更。

当前自动观察不涵盖任意 Canvas/WebGL 像素、伪元素、CSS background、表单值或不能唯一定位的程序生成内容。Canvas 可编辑目标依赖实际 authoring.register 及现有键对应；author spot 只支持目前 text/image 等语义，不是完整 DOM 对象树。

### 8.2 必须补齐的消费者

- Slide 的 resolveSpotAt、Flow 的 beginRegisteredSpot、Spatial 和 Program root 接同一命中/激活结果，保留 mountGeneration、authorKey/scope、真实 painted 信息。
- Flow 增加内部图片选中/替换、格式和上下文路由，Spatial/Program 补齐通用作者字段入口。
- 初始点击位置、局部选区、字体样式和格式能力经已有桥/适配传给共同编辑宿主；跨 frame rect 逐层映射，不能当作外层 client rect。
- 高亮/属性/AI/剪贴板使用精确 ComponentAuthorField；live spot.id 失效不能作为作者身份继续写入。
- 原生布局子对象与 Runtime 字段采用相同用户反馈，但保持各自正式写回地址。

### 8.3 受管 realm 内必须同步区分编辑与运行

iframe 内部事件不会进入外层 React 的 capture。当前 Sandbox 的 capture 主要发送 interaction.clicked/authoring.double-click；World 的 playing/activity 约束宿主动作，不等价于阻止原生链接跳转、表单默认操作和作者 JS 点击处理。若只补 hover/caret 元数据，内容优先单击仍可能一边进入编辑、一边运行作品。

因此要沿现有 edit/run 和受管文档初始化桥，把输入归属送入受管 realm；利用 [authoredDocumentBootstrap](../../src/components/web/authoredDocumentBootstrap.ts) 已有“作者脚本之前”的同步初始化位置，在支持的文档中先裁决编辑手势：编辑态阻止本次手势进入作者点击处理/浏览器默认操作，只发送精确选择或 caret 意图；运行态释放给作品。指针序列、焦点与键盘按同一输入 owner 配套，不能只阻止末尾 click 而遗漏 pointerdown/mousedown 已产生的业务行为。

接管只针对作品的编辑手势；已经激活的专业输入、工具条和输入法操作必须交还其输入 owner，不能再被统一拦截器吞掉。此机制仅在作者环境接入，Published/离线播放保持运行语义，不携带会阻止用户正常交互的编辑遮罩。

这不是新增运行模式或全局暂停：timer/动画继续沿既有生命周期，也不把被拦截的作者业务点击在提交后重放。未受管跨源 frame、未能在作者脚本前安装接管的内容、主动绕过约定的作者监听，不能承诺其内部已获得相同点选编辑；保留整体/源码等实际入口。T2 必须包含“点击受管程序中的按钮文案/链接进入编辑且不执行，切到运行后同一控件正常执行”的对照。

### 8.4 必须保留的边界

W3C Selection API 明确不同 Document 不共享 Selection [W4]。统一体验不承诺拖一条浏览器文本选区横跨普通正文、iframe 和 Canvas。对象级组合操作可以统一；不成立的跨文档文字选区应有明确边界和光标行为。

跨 frame 通信继续复用现有 source/origin/作用域校验，不以统一交互为由移除 sandbox、注入 Node 或扩大宿主权限 [W7][W8]。唯一绑定/旧值校验防止真实错写，必须保留；局部解析或能力不足只诊断相关部分，不拒绝整份可用内容。

源码修改可能重载程序，保留现有提示及生命周期；本次不建设任意程序运行状态恢复系统。页面文字列表保留辅助/批量用途，但按原文字符串 page-copy 的页面级替换，不能充当眼前单对象编辑的精确替身。

### 11.2 必须覆盖的连续作业

3. **精确命令范围**：对象、文本范围、内部作者字段分别使用复制/剪切/删除/重复；不支持者明确反馈，禁止默默扩大到owner。测试同组件字段A→B菜单与属性更新。

5. **Runtime代表边界**：文字与图片各一个，有真实前景遮挡/嵌套缩放的代表反例；受管按钮/链接编辑不执行、运行正常；未知Canvas只呈现实际注册能力，纯程序根和Spatial接线到达共同入口。
6. **外部消费者**：图层定位内部图片、属性操作、AI精确高亮及“选中结果”；CtrlA与菜单全选在文字/对象/全局范围同焦点一致。
7. **保存与输出**：编辑未blur时普通保存 → 新进程/新profile重开 → 同对象继续编辑；涉及作者值的变更用公共HTML导出代表回放。纯chrome不要求重验所有Office/视频/发行。
8. **可信失败**：仅对被修改的生命周期增加一次延迟ACK或拒绝/外部冲突保稿；ACK期间Flow重排/目标位移后仍定位初次点击的同一对象；目标卸载后不改投父级或旧坐标下的新对象。没有相关变化不重跑旧全部异常矩阵。

验收结果分开记录：聚焦代码/类型、真实UI、保存冷开、Published/导出、Owner产品接受。一个层级的成功不能代替另一个。当前发现主要是核心操作与一致性问题；未现场观察的错删推断不能升级成已证实数据损坏。
