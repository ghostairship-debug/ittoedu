## 1. 决定记录

目标是让人和 AI 都能完成“找到能力—在正确位置添加—继续修改—保存和交付”，保留现有表达能力与人机接力。软件继续承担身份、归属、默认值、资源、事务和保存；模型负责内容、布局分组与交互意图。

| 决定 | 本方案采用的边界 |
|---|---|
| 正式底座 | 保留 Project 11／Published 4／Component API 5、实例树、DocumentSession、PM 与专业算法。`childIds/rootIds/global` 持有内容归属，`container` 持有独立容器配置；表面与编辑 DOM 是投影。 |
| Flow 内容模型 | 一个活动 Flow 使用现有 PM 根；章节、列与卡片是同一正文范围内的组织。确需独立文档、视口或坐标语义时才使用子容器；局部程序可作为原子对象。 |
| 编辑能力 | 本组是否进入阅读布局只看组自身；每个子节点决定自身编辑能力。加入程序不改变邻近文字的编辑路径。 |
| 布局表达 | 原生阅读组复用无 frame 的 group 与 `style.display=grid/flex`，自由区域保现有几何。子节点按实际放置与有效布局语义处理：普通文字带 frame 仍可自然排版，frame 的存在本身不决定原子边界。模式切换复用现有字段，并处理子项坐标、尺寸和归属；图表保设计画幅。 |
| 发现与动作 | 基础元素、专业对象、可调程序、模板与功能共用发现事实；保留工具栏、正文菜单、面板等就近入口。新建、模板、复制、预设与应用功能有明确动作含义。 |
| 人机共同操作 | 复用现有正文回写、专业工厂、库插入与应用 planner。UI 捕获选择，AI 引用已观察目标；共同领域准备 edits，沿原 DocumentSession 提交。 |
| 内容输入 | 连续正文、常规 grid/flex 和专业数据沿可靠映射落为可编辑结构；耦合程序保局部实现，外来复杂 HTML 保源与真实编辑边界。CSS、真实媒体、动效和源码表达继续可用。 |
| 实施方式 | 先做窄切片，再以完整任务合并验收；保存、重开、History 和播放随受影响切片闭合。发现与 AI 使用属于本轮目标，不强绑在第一个提交单元。 |

普通修改作用于当前实例；修改共享定义、批量更新或保存为可复用条目是明确动作。普通分栏不产生子工程或独立 History。方案继续使用现有字段与 owner，实际用例证明缺失作者语义时，再定位必要的最小变化及其直接消费者。

以下为本次实施验收定义，实际完成情况见RESULT。切片按实际改变的属性选择最低成本有效检查，复用未受影响证据。

### 4.1 长文中加入图表并继续输入（S2＋S3＋S4）

空白 Flow 写字 → 段中打开添加并按用途找到图表 → 插入、定位 → 保前后文和格式 → 改图表数据 → 后文继续输入 → AI 以相同语义插入／局改。

正文菜单与实际已有 ElementsTab 等入口使用相同默认和专业编辑能力，先改另一图表不污染新建值；一次 Undo 撤回完整插入，保存重开后可继续编辑。当前 Slide 工具栏没有图表按钮；本场景不以新增该按钮为隐含要求。

### 4.2 双列图文加入程序（S1＋S5）

选择内容 → 按明确规则分配双列 → 调比例 → 加入局部互动 → 两列文字继续直接输入 → 段落跨列拖动。

程序只占自身原子边界，图表保设计画幅；列内适配、逻辑阅读／复制顺序和程序运行保持。验证相关边界键、范围删除、撤销、保存冷开与实际 Player。

### 4.3 人添加代码实现的可调组件（S4＋P4）

按用途找到可调组件 → 插入即可运行 → 改标题、图片和速度等实际开放参数 → 按需展开源码。普通修改保当前实例范围；仅源码可改的部分明确显示边界。

### 4.4 AI 批量创建、人调整、AI 局改（P3）

AI 一次准备标题、双列图文、图表与局部互动 → 现有服务提交 → 人换图并调列宽 → AI 只改所选段落及图表数据。

保人工换图、列宽、邻文、对象身份、源码与资源；观察与修改针对实际范围，软件完成身份和必要装配。接口直调不替代真实模型采用。

### 4.5 独立区域简改、深编与返回（P4）

Flow 中加入 Slide／Spatial 区域 → 父级改外框和开放字段 → 进入对应工作台 → 返回父阅读位置。保持同一实例、工程与 History，entry 不变；普通分栏继续留在正文。

### 4.6 保存、播放、浮层与实际交付

同一短样本包含正文、专业对象、双列、局部程序、必要嵌套区域和一件浮层；可选咖啡作品副本中的相关片段作为压力样本，不重做整篇。按各片变化检查保存、独立重开、实际 Player／HTML 与受影响静态输出。

| 放置／输出 | 必须保留的语义 |
|---|---|
| 随文及局部自由区域 | 外框参与阅读顺序；自由区域内部保局部坐标。 |
| 固定纸面／段落锚定／固定视口浮层 | 复用 flowPlacement 与 paragraphAnchor，绘制平面和阅读顺序分开；全局内容保作品作用范围。 |
| 正文与浮层转换 | 保同一实例，显式转换固化当时显示位置，转回正文有明确落点；滚动和重排只派生显示。 |
| 锚点删除 | 当前 V10 清引用并保存储 frame，不保证删除前视觉位置；显式解除可固化当前显示框，界面支持定位和撤销。 |
| Player／HTML | 保实际阅读布局与程序运行；编辑截图不替代播放证据。 |
| PDF／Word 等静态格式 | PDF 检查实际排版；Word 优先专业文字、表格、图表可编辑语义，复杂布局／程序按现有适配说明差异。Markdown 表达边界不得覆盖未选内容。 |

### 4.7 效率与证据范围

人端记录按用途发现、从添加到可编辑的实际路径、结果定位及返工。AI 记录说明输入量、工具往返、回执量、首个可用提交、修复轮数和总时长；软件记录受影响的准备、提交与输入／渲染成本。比较始终保同等内容、必要媒体／互动、局部可编辑性和交付结果。

复用 [ExecutionRunRecord](../../src/shared/workbench/execution.ts) 的 `requests[].usage`、`payload.serializedBytes` 与工具执行记录。serializedBytes 是整个供应商序列化请求，工具记录数是执行次数，两者均不能单独充当披露工具字节数或数量。实际披露量要按真实 profile、授权与已加载工具族，从请求中分离统计；默认 general 约 70–75KB 仅为旧估算，未实测。

[当前状态](../development-plan/CURRENT_STATUS.md) 中 YOU&ME 27 分钟记录仅作宏观历史参照；材料与准备条件不同，不作本轮量化前后基线。P3 使用同模型、同提示、同素材与相近环境的短任务对照；无可比条件时报告本次数据，不推导倍数提速。少量样本先定位主要成本，有含混或具体退化再扩大；单次通过不签稳定成功率。

源码事实、聚焦自动检查、真实 GUI、保存冷开、模型采用、实际输出和 Owner 接受分别记录。每片的功能准备与接线证据只证明对应属性。
