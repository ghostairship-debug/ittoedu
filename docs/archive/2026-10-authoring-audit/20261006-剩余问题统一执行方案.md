## 2 方案选择与止步边界

| 路线 | 决定 | 原因 |
|---|---|---|

## 3 R1 默认 Web targets 减量

### 结果和单一 owner

让无作者执行面的默认 Web 收到目标身份和现有动作所需信息，避免整课作者 values 的生成、序列化和跨 realm 克隆。ComponentPlatformRuntime 仍是唯一 target snapshot owner；DocumentSession/History 不变。Editor、Published、观察使用同一规则。

内部仅两个 profile：full 与 references。沿现 TargetSnapshot 形状保留 reference、instanceId 和实际必要 metadata；references 不产生 value。无需 Project/Published Schema 新字段、作者登记或 AI 标签。

### profile 选择

- effective implementation 是共享或私有 Source：full，保同步三类 target.read 与跨未访页读取。
- builtin html-program：full。普通 HTML 脚本没有正式 window.scope 导出，但脚本与桥同一 realm；不能仅凭默认 adapter 没调用 target 就减少所有可执行 HTML 的现有载荷。
- 仅 effective builtin guoling.web 且最终投影后的作者载体没有执行面：references。
- script、on*、javascript URL、modules/moduleGraph、iframe/object/embed、template/foreignObject 或未知结构：full。复用现 parser 做语法事实判断，不分析 JS 是否“看起来用不到目标”。这只是选择优化路径，内容仍照常导入和运行，不是拒绝门。

只看 definitionId、旧导入来源或“没有 moduleGraph”都不够。判别取当前 effective implementation 与本次 projected payload。

### 精确修改点

| 文件/函数 | 修改 |
|---|---|
| src/components/web/moduleGraph.ts 的共享纯载体 helper | 复用现 HTML parser，输出执行面/未知结构事实；不给编辑器、Player 各复制一套判断 |
| src/player/components/ComponentPlatformRuntime.ts：targetSnapshots | references 直接从正式引用构造，不调用 target.read、不先构造 full 再删 value；full 保现语义 |
| src/renderer/components/SandboxComponentImplementation.ts：SnapshotPorts、mount/update | 统一传 profile。每次 mount/update 重判；同一 realm 只允许 references→full，先接收完整 targets 再执行内容 update。已 full 的 realm 不降级，正常退休后新 realm 可重新选择 |
| src/renderer/components/CourseV10RuntimeView.tsx：两 resolver | 接 profile 到唯一 runtime owner；Source 显式 full，其他专业 DOM/Canvas 路径不改 |
| src/player/componentPlatform/publishedPlayer.ts：两 resolver | 同形接线，独立输出和捕获不另复制规则 |

当前 Host 已把 html/modules/moduleGraph 纳入 generation signature；仍须保上述单调升级与消息顺序，不把换代细节当作 update 正确性的唯一前提。内部临时 profile 不持久化，不新建 dispose 平台。

state/theme/resource/teacher 继续原独立通知，frame-only 继续 placement；不新增向全部 realm 广播 full targets 的事件。资源映射复制暂不扩修，原样本asset为0。

**第一包不以缓存为前置。** references 必须直接跳过作者 values 的克隆；full 仍沿现实现。若实际证明父端 repeated full 构造还显著，才在同一 world 内 lazy memo 一份纯派生 DTO；失效依据精确 project/preview 身份及实际依赖，不能只用 revision，也不能跨 world 建缓存或改变 Source 最新已观察快照语义。

### 最低验收

1. 一个 profile/投影 case：静态 Web 的 mount 和 update 都无整课 value；执行面/未知/HTMLProgram/shared/private Source 皆 full。references→full 顺序和同 realm 不降级有针对性断言。
2. 复用已通过的 form/CSS carrier，确认揭示/复位和局部编辑继续成立；复用一个现 Source 跨页 carrier，确认同步读取未访实例、surface、project及父动作不降级。旧未改原子行为不重跑。
3. 与现 probe 相同原rev32/pg4，只做一次公开观察对照：targets UTF-8体量、full values构造次数、软件wallMs、应用private峰及正常释放；输入、代码cut、当前系统commit条件分别记录。不人为耗满内存、不设固定降幅门、不把逻辑字节等同heap。

成功标准是明显重复载荷已去除、实际所需行为保留、同样本未出现新增失败；报告实际改善。若载荷降了但资源仍高，按剩余具体 owner 再判断下一步，不把首包扩成全 runtime 重构。

现产品默认端口为 45123；本次 profile 配置为 45888。CLI 必须输出实际 endpoint，客户端不能硬编码样本端口。

实施边界：

10. headless 不弹工作台模态确认。授权 workspace 内复用现权限；必须另行交互授权的操作明确返回原因，不能自动放权。隐藏 worker 关闭不触发 window-all-closed 停驻留服务。
