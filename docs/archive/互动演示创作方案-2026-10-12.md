## 1 已收敛的创作目标

果铃用于创作可持续编辑的互动演示与内容体验。教育群体是首发对象，课件是当前测试场景，不能把所有创作任务都导向教学 PPT。可以从 H5、网页、互动叙事、信息探索和局部游戏的角度设计体验，再选择适合的正式载体；这些设计视角不意味着把整件作品做成一个不可分的网页程序。

| 已收敛方向 | 对作品和实施的约束 |
| --- | --- |
| 从内容主线与核心体验出发 | 先明确观众要看见什么、理解什么、做什么、得到什么反馈，再组织页面、场景与路径；不先确定一套静态幻灯片再补按钮 |
| 两种推进模式 | 自动推进完成约定目标；逐步确认在足以改变后续工作的关键产物节点询问继续或修改。模式不改变权限和费用边界 |
| 先做可操作的关键场景 | 关键体验在扩展全作之前落实到正式工程，包含必要的视觉、互动、反馈和导航；不能只交标题、正文和互动占位 |
| 充分但分层的能力说明 | 创作前知道可实现的表达方式，具体工具参数、Runtime API 和源码按需加载；不以几句分类标签代替能力理解 |
| 保留多种表达载体 | 场景状态、Runtime、Spatial 各有适用性，不因 Runtime 能模拟其他能力就删除其他载体，也不要求每件作品使用全部能力 |
| 一切皆组件的复用方向 | 高频互动核心逻辑、背景、动效和行为均可组件化复用；组件不等同于固定视觉模板或一定有独立矩形外框 |
| 背景和节点共同参与视觉设计 | 按内容选择全局背景图／背景 Runtime，可与内容联动并按页排除；专业节点也可按需深改，保留正式内容与人工编辑语义 |
| 软件承担机械执行和准确反馈 | 身份、批量装配、资源、事务、History、保存由软件处理；进度、终止、部分完成和真正交付分开说明，导出携带实际内容与依赖 |

用户已明确：尚未选择时以选项卡选择自动／逐步推进，之后记住；首批采用少量高频、可深改机制及背景；实施尽可能一次完成，未完成项必须告知。第 2、6、11—12 节据此落实，不再重复列为待用户决定。

## 2 推进方式与职责

### 2.1 自动推进与逐步确认

- **首次选择与记忆**：尚无已选模式且用户本次未直接说明推进方式时，使用现有提问卡提供“自动推进”“逐步推进”及独立文字输入；选择后作为当前会话事实记住，续作沿用。用户已经明确“直接做完”或“逐步确认”时直接采用，不再重复问默认模式；后续可改。
- **自动推进**：策划、关键场景和整体进度照常产出并展示，但不因此结束任务或默认等待。继续完成当前约定目标，缺少不可替代输入、真实无法继续、超出现有授权或用户要求停下时，才按事实提问或报告。
- **逐步确认**：在方向、关键体验原型等有实际选择价值的节点，先展示可审阅成果，再通过现有提问卡询问继续或修改。不按页、工具调用或固定阶段数量增加确认。
- 用户只要求策划、原型或局部修改时，该范围就是目标；自动模式不把它扩成完整作品。用户后续明确改变推进要求时采用最新指令，界面选择与续作上下文应同步。
- 提问卡固定提供独立“其他想法”输入；点击选项只提交选项，提交文字只提交文字，不要求先勾选“其他”，不把文字与某个确认选项强行合并。详见软件方案第 9、18 节。
- 阶段说明是进度，等待回答是等待，模型本轮结束不是用户目标完成。自动续作及终止判断沿软件方案第 16 节处理，不新增教学阶段状态机、每次收尾必调的审查模型或无限重试。

当前产品缺少明确的两种模式入口；本节是目标行为，不是对当前 UI 的描述。实施后由宿主沿已有提交、运行、调整与续作链传递模式，Skill 消费该事实，不另存一套模式状态。

接线由软件方案第 18 节统一规定：会话持久化偏好、运行初始副本和有序调整分开表达；首次模式卡复用 ask_user 的窄用途标识，用户实际回答由宿主写回。自然语言已明确模式时直接同步，不再弹卡；不能改写原始冻结输入或让 Skill 维护第二份偏好。触发和写回属于已定交互的实现细化，不再作为 Owner 二选一。

### 2.2 人、模型与软件各自负责什么

模型负责内容判断、体验路径、构图、视觉、交互反馈，以及确需编写的局部程序逻辑。软件提供已有的编辑、导航、状态、镜头、运行、资源和持久化能力，承担机械装配与正式提交；不能把“软件实现”解释为所有自然语言创意均可自动变成现成效果。

人和 AI 修改同一份当前内容、参数和源码。续作先取得相关范围的当前事实，保留人工布局和代码修改；不要求人工操作与 AI 代码能力完全对称，也不新增全局运行态恢复系统。

## 3 拟采用的创作流程

### 3.1 明确内容主线和核心体验

读取用户材料、已有策划及实际作品，提炼本次目标、受众、使用场景、必须准确的内容和交付要求。先看软件提供的表达能力概览，再决定体验：哪些信息适合直接呈现，哪些需要比较、探索、操作、推演、选择或反馈。短编辑不进入整套创作流程。

策划同时考虑内容、主要画面、互动、导航和素材。使用场景／内容单元组织主线，不把逐页讲稿作为所有任务的起点。教育任务按需使用教学质量方法；其他演示不强套知识点、教师、学生或测评词汇。

建议新作品将策划保存为 `<作品名>/01-创作策划.md`，作为本方案拟同步的命名调整；已有 `01-教学策划.md` 或用户指定文件继续沿用，不为改名迁移或重写。策划记录目标、主线、关键体验、视觉方向、载体选择及理由、必要导航和交付范围，不增加逐对象登记表、必填模板或另一份流程台账。

### 3.2 设计并实现可操作的关键场景

选最能检验内容表达或互动机制的片段，直接在正式工程内实现。观众应能看见主要材料，完成关键动作，得到有意义的反馈，并知道如何进入、继续或返回。需要运动表达、场景变化或背景联动时，原型就应包含足以判断效果的部分，不全部推迟到最后润色。

“先关键场景”是减少方向性返工的创作方法，不是新的强制准入门。用户目标本来是静态演示或机制已清楚时，使用相称的关键片段即可；不为每个作品强加游戏或试验阶段，也不要求每个片段都先获得单独审批。

尽早选择一条真实可走的导航路径。面向触摸、自助探索或剧情选择的作品，应有适合受众的可见入口与反馈；教师演示可采用合适的正式键盘推进。不是所有作品都要导航栏、目录或完整教师台，但主路径不能只存在于作者脑中，不能把用户不知道如何继续留到交付时。

### 3.3 扩展整体结构与内容

关键方向成立后扩展其余内容。已确定且相互独立的页面描述由软件批量创建、返回全部正式目标，已确定的素材也可批量准备和装配。为建立原型而先创建必要空页或一次创建已明确页面，不与本流程冲突；需要取消的是“必须先把整作铺成静态页，互动留到后期”的默认顺序。

内容按实际可编辑粒度进入工程：专业正文、文字、表格、图表、图片、图示、组合对象和局部程序按需要组合；真正耦合的实验、模拟或游戏可保留共同源码。不为了拆分而拆散程序内部控件，也不以整页 HTML 包住本来需要分别编辑的全部内容。

页数、场景数和素材量服从内容。场景状态可以承载同场景线性推进、分支或选择跳转；Runtime 维护程序内部过程；Spatial 用于真实空间关系与镜头探索。需要扩充或调整既定结构时修改当前工程，不维护外部整课 HTML 再反复重导。

### 3.4 精修实际结果

持续对照策划承诺补齐核心内容，局部调整图示、图片、版式、反馈与动效。选择、拖拽或按钮只有产生与目标有关的行为和反馈，才算实现相应体验；工具成功、脚本运行或界面能点击，不能代替内容质量。

背景、专业节点、行为和局部源码均可按需精修，但不要求所有对象定制源码。素材按任务选择用户资料、真实来源、图库、生图／参考图编辑、原生或代码表达；不设全局来源排名、强制搜索次数，也不把粗糙手绘图形作为通用图片替代。生成图不能冒充真实证据，核心内容不能以占位宣告完成。

### 3.5 检查与交付

优先检查关键片段的实际呈现、主要动作、必要分支及导航衔接，修正观察到的问题。独立 HTML 预览通过不能代签正式嵌入后的尺寸、输入、反馈和导航；不默认逐页截图精修或机械运行全矩阵。

交付说明已完成内容、当前工程、实际来源和明确缺口。用户要求保存或文件交付时取得真实保存回执，并对相关持久化风险做必要重开检查；要求导出时检查真实导出消费者。未完成核心目标时继续工作或明确报告阻断，不以阶段产物和一次模型 `stop` 代替完成。有效证据未受相关变化影响时复用。

## 4 状态、Runtime 与空间的选择

| 载体 | 适合承担的内容 | 需要避免的误用 |
| --- | --- | --- |
| 场景状态 | 同一场景中作者明确设计的线性推进、分支、选择跳转及可返回的阶段；状态中可以包含动画、视频和 Runtime | 不把每个连续数值、拖动位置、随机组合都枚举成正式状态；不把用途收窄为讲解步骤 |
| 局部 Runtime | 实验、游戏、模拟、复杂动效、连续过程和程序内部变量；内部也可以有必要的多视图 | 不因其表达力强就把所有可编辑文本、表格和场景组织塞入一个巨型程序 |
| Spatial | 地图、空间关系、尺度探索、镜头路径、多个独立节点共同构成的可编辑空间 | 不因 Slide 的背景程序能画地图就默认替代；也不为无空间语义的内容强制使用 |
| Slide／Flow | 独立场景、定幅演示与连续阅读，允许和其他载体混用 | 不把 Slide 的存在当成必须采用 PPT 叙事和统一卡片版式的理由 |

同一场景状态不是独立页面。当前状态定义主要保存对象、顺序与背景的覆盖，切换时解析当前状态，不为每个状态同时创建一套完整页面 DOM。更多状态会增加数据，但不能仅凭状态数量断言显著性能退化。

性能仍取决于状态关联的实际对象、资源和运行程序。当前隐藏对象不能一概视为已停止运行；大量状态专属的大图、视频或程序仍可能增加开销。上述结论来自当前结构定位，不是任意规模下的性能实测。保持这些载体，不增加数量限额，也不为假设性性能问题先建新的调度平台。

## 5 视觉、背景与节点深改

### 5.1 背景也是组件，可以装饰也可以联动

背景按内容判断采用颜色、图片、图形或 Runtime。全局底层背景图／背景 Runtime 是优先评估的视觉方向之一，不是强制模板；可预制少量高质量基础背景，再依作品主题精修。

背景位于内容底层，前景节点继续独立编辑、选择和操作。装饰性背景不抢占前景输入；需要联动时复用当前正式事件、共享状态或组件参数响应内容变化，例如随场景阶段、选择结果或进度改变光线、纹理、空间或运动。不要要求背景直接扫描和控制整页私有 DOM。

全局背景可配置应用范围，排除不适合的页面；这些页面可以有自己的背景。只修改选定作用范围，不通过复制一批全屏矩形假装全局背景，也不改动无关页面的人工设计。全局层、排除范围和基础 Runtime 能力已有基础；新增预置资源及具体联动体验仍需实现和实际呈现验证。

### 5.2 高频互动与动效按组件复用

复用的是核心行为和可编辑配置，例如选中状态、正确性判断、拖拽目标与反馈、排序、匹配、揭示、进度和必要重置；视觉、文案、布局和反馈方式可按作品调整。选择和拖拽不应都变成同一张题卡。用户已接受少量高频预置，首批实施范围见第 6 节；这是待落实范围，不能提前当成已交付目录。

背景、动画和行为都属于可封装代码能力，可由可视组件、无独立画面的行为组件或两者组合承担。沿当前组件、数据、参数、事件与运行机制实现，不为了统一称呼再建第二种组件平台，不强迫每种效果占用独立可见框。

### 5.3 原生／专业节点允许深度设计

文字、表格、图形、图表及其他专业节点不应因使用内置实现就停留在默认外观。按目标选择样式、主题、状态、动效、行为或源码调整，不规定每次都从第一档依次升级。已有实现能表达时复用，确需不同表现时允许实例级或共享实现深改，并明确实际影响范围。

深改继续保留正式数据、人工属性面板和保存消费关系；不能把文字、表格数据硬编码到视图后声称原编辑能力仍有效。源码可改不等于任意改法都自动与专业数据兼容。图标是表达需要，不在当前目录中虚构一个专用 `icon` 内置类型；按实际图形、SVG、图片或局部程序能力承载。

## 6 组件复用与交付体积

组件库提供可复用实现与内容，完整条目可以完整插入，可拆分条目应支持明确选择对象／子树并带上所需依赖。单程序内部多页若需要部分采用，按可编辑配置或模块结构处理；不能仅按一次预览中未访问就裁剪分支或任意 JavaScript。

资源范围修复沿提炼、插入、编译、发布的实际依赖链完成，详见软件方案第 19 节。明确未引用的素材不进入 HTML／ZIP；后续状态、隐藏分支、全局背景、主题／字体、音视频和动态资源名称所需内容必须保留。资源未出现在显式绑定表中不自动等于无用，原工程也不因导出裁剪而删除数据。

用户已同意首批采用少量高频、可深改机制。按以下范围复用已有实现或补齐缺口，不重新开发已经具备的能力，也不把每一行都强制做成新的独立组件类型：

| 首批范围 | 可复用行为与可修改部分 |
| --- | --- |
| 选择与反馈 | 单选／多选、选中状态、内容相关反馈及必要重置；可改文案、数据、视觉和布局 |
| 揭示与分步呈现 | 点击／操作后显示内容、切换阶段或展开说明；复用现有状态与事件，允许图文和局部程序参与 |

## 11 后续实施与验证边界

后续统一实施时，先按软件方案处理真实阻断和失实状态，再同步当前已可用能力的创作方法与分发说明。内部按依赖分步骤，整体尽可能一次完成两份方案的约定范围，不预先缩成首批交付。可独立成立的修复不等待整个预置库齐备；涉及待实现接口的 Skill 段落与软件同批更新，不出现文案先宣称可用、产品后补的空档。确有未完成项时逐项写明内容、原因、影响和继续所需条件，不能静默取消、从清单删除或以阶段完成代替总目标完成。

验证按要证明的属性选择：

- **文案与接线**：检查旧冲突已在实际消费的相关说明中消除；用当前运行的 `skills.read` 及请求上下文确认送达。只读源文件或构建成功不足以证明模型收到新规则。
- **软件缺陷**：复用软件方案各节的最低有效检查，不因本方案落稿重跑已有有效证据，不机械跑全部模型、页面或导出矩阵。
- **创作方法效果**：在有授权的短真实创作中，观察模型是否先形成有意义的可操作关键片段，并落实真实导航、视觉与反馈。优先复用现有材料和工程证据，不为展示流程重复生成整套长作品。载体由内容选择，不要求一次作品覆盖状态、Spatial、全部背景和全部互动。
- **编辑与交付**：对实际改变的持久化／源码／资源路径检查人工修改保留、相关保存重开与交付结果。专业节点深改时，对本次实际改动的一个代表节点通过原属性面板修改一项正式数据，确认新画面响应，并结合相关保存重开复核；不只检查标识和元数据仍存在，也不要求 Owner 亲手操作或所有专业节点重跑矩阵。新增预置组件检查该组件的核心动作及实际表现，不把每个组件都接到同一庞大验收工程。

上述检查用于发现新方法是否被采用、真实能力是否能完成目标；一次样例通过不是“所有作品都优秀”或“达到完美”的证明。费用、账号和模型沿已有明确授权，不能为追求效果默默升级模型或增加付费路径。

## 附录 A 表达能力概览草稿

以下是面向模型的文案素材，拟由软件按当前工具、权限和配置筛选后提供。它不替代实际目录；文中能力只有在本轮确实可用时才应展示，规划中的新组件、批量入口和搜索后端不得提前出现为可用项。

**内容与空间。** 你正在创作可持续编辑的互动演示，可以按内容选择定幅场景、连续阅读或可探索空间，并在同一作品中混用。先考虑观众需要看见、理解和操作什么，再决定如何组织；不必先做一套幻灯片。文字、专业正文、公式、表格、图表、图形、图片、音视频和组合对象可以分别编辑。地图、空间关系或尺度变化适合使用真实空间与镜头；长文适合连续阅读；独立场景可用定幅页面。软件维护正式对象和资源身份，不需要你自行编页号、对象 ID 或引用登记表。

**同场景变化与程序过程。** 同一场景可以保存多个作者设计的呈现状态，用于线性推进、剧情分支、选择跳转和返回；状态可以改变内容、外观、位置、可见性、背景与顺序，并包含动态组件。它们不等于另外复制一批独立页面。连续拖动、数值模拟、随机过程和组合繁多的游戏变量更适合由局部程序管理。按内容选用即可，不必为了展示能力给每个片段配置状态，也不必因会写代码就把整个作品放进一个程序。

**互动与反馈。** 可以使用当前可用的输入、选择、揭示、弹出内容、交互规则、事件和状态来响应操作；也可以通过局部程序实现更复杂的模拟或游戏。先定义操作改变什么、结果如何显现、用户如何理解，再选择实现。需要多次使用的机制可复用组件及其参数，并按主题调整外观、布局和反馈。库中没有的机制不要假装存在；取得实际接口或当前源码后再实现，软件负责正式接入。

**导航与运动。** 作品可以有页内推进、页面切换、指定状态跳转、空间镜头及必要返回。观众应知道怎样开始和继续；教师演示可采用明确可用的键盘操作，自助或触摸体验则按需要提供可见入口。正式导航目标、顺序和播放控制由宿主维护。动画可以帮助观众看清变化、关注关系或进入情境，既可用于内容对象，也可放在局部程序；按表达需要使用，不要求所有画面都运动或每种效果都有人工时间轴。

**图层与视觉。** 内容可处于页面或全局层。全局底层可以承载背景图片、图形或 Runtime，并选择适用页面；例外页面可以排除并使用自己的背景。背景可只装饰，也可通过正式事件或共享状态随内容变化，前景节点保持独立编辑和操作。专业节点可以调整样式、参数、状态、行为和必要源码以形成作品自己的视觉；深改仍应读取和保留正式数据，避免让人工文字、表格或其他属性修改失效。

**素材与当前事实。** 用户资料、当前作品、图库、网页来源、生图与参考图编辑是否可用，以本轮配置为准。真实材料用于支持真实事实；生成内容适合表达设计意图，不能冒充原始证据。选择最适合内容的来源，不必为遵守固定顺序重复搜索。软件承担资源摄取和保存；遇到缺资源或外部服务失败，应按实际回执说明，只处理受影响范围。

**共编与交付。** 从正式工程的当前内容继续创作，局部修改保留范围外内容、人工布局和源码调整。源文、对象、页面和模块的具体操作通过当前工具按需取得，不先阅读整套 API。新导入的局部程序在授权目标内接入，之后以工程内当前源码为准。检查正式嵌入后的画面、主要操作和实际采用的导航；提交、保存、重开和导出是不同结果，依据当前回执准确说明。阶段产物用于展示进度，是否等待和如何继续由用户目标与本次推进方式决定。
