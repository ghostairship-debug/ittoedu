| “高级编辑恢复稿已保留”阻断 | 未接入编辑入口或同位置多版本的 pending 被 `prepare()` 统一算作不就绪，再由 Store 扩散。 | 将“原稿需要保留”与“当前文档不能继续”混为一个条件。 |
| 基础表面容器进入组件库 | 内部定义过滤误用源码构建清单；宿主实现的基础容器不在清单里。空白工程即可得到“幻灯片容器”卡片。 | 容器化后，库展示消费者仍沿用旧事实来源。 |
| 底栏删除含义不清 | 整页删除已有右键命令；显眼垃圾桶来自状态条，只删除状态。 | 整页和局部状态的层级没有在可见操作中说明。母版禁删本身正确。 |
| 大 HTML 正式提交／保存仍重 | 输入逐键为局部草稿，成功预览通常局部 patch；正式作者记录重装、整包命令复制及最终保存仍有大 source 成本。历史同样本保存8.697→7.130秒，非本次原件新测量。 | 资源与未变正文复用已有改善，但正式准备仍有整包处理；这是条件性性能成本，不能替代上述正确性根因。见 B14。 |

大、小 HTML 均含 iframe：小文件为无 sandbox 的同源 srcdoc；大文件为旧 compiled Player 动态创建的 `allow-scripts` 沙箱。核心区别是直接 DOM 读取与消息桥，不是“有无 iframe”。大文件的资源和正式提交成本需单独判断，不能用体积解释字体、虚线与命中错误。

指定 GLX 的 V10→11 读入转换保留了原 HTML、实例和资源，本轮未发现迁移主动锁定它。真正根页面删除在临时副本新增第二页后成功，不能继续声称“第一页在领域层固定禁删”。Owner 已澄清真实诉求是删除入口可发现性与范围表达。

## 3. HTML 编辑交互方案

### 3.1 推荐：恢复“编辑／完成编辑”

- 查看态按作品正常呈现和交互，提供“编辑”。
- 进入编辑态后显示可编辑范围；当前编辑与可移动／缩放能力的提示按真实能力出现。
- 提供“完成编辑”，结束当前输入并返回查看态；文件保存仍归既有保存入口，不把模式切换变成额外磁盘保存。
- 可安全应用的输入沿现 owner 提交；确实冲突的输入保留并说明该处未应用，不把模式切换失败变成永久占住整个编辑器。
- “移动”使用清楚的拖拽手柄和就近说明，避开正文与输入选区；不再用悬在文字上方的按钮遮挡编辑。
- 同源 DOM 与沙箱消息桥消费同一份样式、几何和编辑能力事实，保留程序、资源和 sandbox 边界。

备选是采用与编辑器一致的模式栏。Owner 已接受这一方向；若后续选择它，需先展示完整按钮含义与状态变化，复用现有行为，不自行新增未定义的第三动作。本文默认推荐前一种恢复方案。

### 3.2 技术收口位置

修现有 `htmlFrameAuthoring` 的样式、caret／anchor／focus／word 报告与 confirmed 提示；让现有 frame 映射同时服务字形、选区、rect 和 geometry，并正确计入 iframe 边框／padding，避免重复缩放。保留原始 Text 值，消费其 computed white-space；不靠折叠原文或按包围盒猜字号修正。修共享 DOM 发现／命中的真实可见性语义，包含 html/body 视口 overflow 传播和 absolute／fixed 的实际 containing block；不能只硬编码放过 body。

沿原 `HtmlTextDrafts`、预览控制器和正式 Source writer 处理输入。不要为同源、opaque 和 GLX 各造一套裁剪、样式或恢复规则；复用 owned 路径已经具有的输入意图与二维矩阵能力，收回重复的近似映射。

逐键输入目前只是局部草稿，预览成功后通常也是局部 patch；不能按“每键保存 25MB”开展优化。正式提交仍存在外包级记录重装与命令复制。正确性恢复后，只有实际测量仍命中这些成本时，才沿已有 source splice、记录区与资源分析复用收窄准备；不先建设新 Worker／缓存平台。

## 4. 编辑阻断的产品原则

### 4.1 三种处理，不把异常一律变成全局错误

| 情况 | 用户应看到什么 | 可限制的范围 |
|---|---|---|
| 软件可确定处理：自身提交已成功、无关版本变化、预览正常重挂载等 | 自动完成；无需用户排除技术状态，也不反复弹报错。 | 不限制正常编辑。 |
| 原稿已保留、局部资源／运行诊断、非当前字段未完成 | 在对应位置给简短状态，按需查看／复制原稿；避免红色全局 toast。 | 不限制其他内容；不能因此把文档永久标成不可编辑。 |
| 当前动作确实无法正确完成，且不能安全自动处理 | 说明哪一次修改／保存没有完成、输入保留在哪里、可采取的动作。 | 仅保护该次写入及确有依赖的操作；其余可用能力继续开放。 |

保存失败、磁盘真实冲突等必须如实告知，但不应锁住画布。保存当前已应用内容与保留未应用稿需要清楚区分：存在未应用输入时不能显示“全部修改已保存”。这不是忽略错误或伪造成功。

保留唯一 writer、最终 CAS、真实未知提交查证和未保全输入保护。对于 unknown，先查既有回执，不能盲目重放；对于已明确拒绝／未提交的输入，沿原 owner 保留或释放该项，不能遗留一个无人能处理的全局队列错误。

### 4.2 已定位的主链与处理范围（诊断基线）

本表保留开始／继续输入、提交、换对象／页面／文档、保存／关闭及HTML模式的诊断断点和原拟处理边界；各项现状逐一见RESULT的A01–A20覆盖表。主链核查不等于静态排除了所有运行时异常。

| 链路 | 当前事实／定位 | 计划处理及保留边界 |
|---|---|---|
| A01 旧高级恢复稿 | `courseDraftLifecycle.prepare` 将未接续／多备选 pending 统一变成 issue，`editorStore.flushDrafts` 抛出。 | 将保留原稿与活动提交分开；旧稿继续进入现有恢复持久化，并提供可查看内容。不能仅删提示而保留 blocked，也不能清空原稿。 |
| A02 文字恢复误冲突 | `slideAuthoringSlice.restore` 整 data 比较，未识别草稿已应用；颜色等无关变化也触发。 | 用现字段 planner 判断实际依赖，识别已应用；将合法文字意图准备到当前对象，保留新颜色及人工修改。真正同字段冲突才保留待选版本。 |
| A03 持续 blocked 与无退出 | blocked 稿占用活动编辑槽；继续输入不解锁，普通 Esc／失焦仍尝试 commit。 | 真实冲突稿退出活动占用，原稿仍可查看／接续；当前输入应有明确完成、保留后退出的路径。不能靠反复按 Esc 才恢复整个工程。 |
| A04 保存与旧稿清理 | 保存返回未等后台空恢复稿 ACK；正常完整关闭另有 prepare 屏障。 | 复用现输入写队列闭合保存与稿状态，不使已应用旧稿在清理窗口后再次变成活动冲突；不得阻塞于无关旧稿。 |
| A05 未挂载属性恢复稿 | `PropertyControls` 为未挂载恢复属性注册 `flush:()=>false`；同文档 flush 因而失败。`beginSlideSpotEdit` 开始另一文字前也调用该 flush。 | 未挂载旧稿保留待接续，不充当当前输入未完成；只处理当前动作实际依赖的活动属性。真实数值／同字段冲突仍拒那次属性写入。 |
| A06 Source／JSON 缓存草稿 | 两类 provider 的 prepare 遍历同文档脏稿并尝试应用；旧基线、未完路径或语法问题可传播到文档准备。 | 保存／导航不强迫应用所有历史缓存草稿。可安全接续的活动输入按现语义处理；不可应用部分保留，影响限定在原入口，不让未确认程序因导航自动被强行写入。 |
| A07 正式队列拒绝／unknown | Bridge 对已有 projection.error 拒后续提案；已有按 operationId 查证和 retry/cancel 端口。 | 复用已有查证、确认未提交／拒绝和释放路径，检查所有实际输入 consumer 是否接上。不得 blanket 清 error、跨项删队列或重放 unknown。断开的是该文档写入时，本地输入仍须保留，其他文档正常。 |
| A08 Flow 草稿／输入法 | Flow 提交失败保留源码和诊断；SharedDocumentEditor／Flow drain 按任意诊断拒绝；文档保存准备还会按 Flow 草稿存在与否拒绝。当前 Flow 草稿主要按文档持有。 | 正常输入生命周期错误优先修根因；活动 IME 不强制提交。有效正文继续可编辑，问题段保源；待保留历史稿不等于当前活动 composition。保稿后允许换 surface 时，必须同步收敛草稿作用域及清除规则，不能让新页提交顺带删掉旧页原稿。 |
| A09 HTML 完成编辑 | `finishInline` 失败后 `setEditing(false)`不退出；局部字段失败扩大为模式不能结束。 | 已应用则直接完成；未应用则保留该处草稿并明确结果，允许安全退出输入。保持作者输入隔离，不能因忽略模式 ACK 让业务点击误运行。 |
| A10 HTML Source 真冲突 | `HtmlTextDrafts.prepare` 无法映射任一稿即 not ready，上层统一显示“正文输入尚未确认”，保存／保留后关闭路径受限。 | 保留逐稿具体原因与内容。允许保存当前正式内容时必须明确还有未应用稿；关闭前先确认该稿已可靠保全，不能丢稿放行。 |
| A11 HTML 结构／样式编辑 | 任何 retained draft 都作为 pendingDraft，禁用整套结构／样式写入。 | 先应用可合并草稿；真实来源冲突只限制有冲突的结构写入，避免历史保留稿永久封锁整套能力。 |
| A12 HTML ready／模式等待 | 等 ready／ACK 时禁模式按钮及 iframe 输入；失败退出与恢复需完整闭合。 | 修桥初始化根因；成功严格按 ACK 交接，真实失败结束等待并可重试／进入源码。不能把“未就绪”无限期留下。 |

### 4.3 提示必须能让用户继续

推荐表达示例，最终用语随已批准方案细化：

- 已保留旧稿：“有一份上次未应用的修改，当前内容可继续编辑。”提供“查看原稿”。
- 单处写入冲突：“这段文字同时有其他修改，本次输入已保留。”提供比较／重选位置／保留后退出。
- 属性值不完整：在该字段附近指出具体值问题，原值继续有效，其他对象可编辑。
- 保存真实失败：“文件尚未保存：目标位置无法写入。”提供重试／另存；画布输入继续保留。
- 某程序不可运行：在该程序附近诊断，正文和其他程序继续使用。

没有具体失败动作、目标和恢复出口的“请修正后继续”不能作为完成状态。同一原因不因每次点击反复弹同一红框；诊断留现有日志，界面只显示当前确有用的信息。不以“零错误日志”作为可编辑性验收。

## 6. 减少同类问题反复发生的工作方式

### 6.1 一项变更只维护一组可核对事实

沿既有方案／结果文件记录以下四部分即可，不建设新的治理平台：

1. **设计决定**：旧操作、新操作、用户看见的差异、Owner 已明确的取舍。存在新的体验变化，实施前展示这一具体变化再讨论；不把纯内部实现细化重复送审。
2. **问题对照**：真实作品／入口／载体、用户操作、当前错误、应有结果、必须保留的人工内容与操作。不能只写“大 HTML 不好编辑”。
3. **影响与证据**：唯一 owner、直接 producer／consumer、改变的路由或共享语义、仍有效与需补充的证据。一个问题收回共同根因，退出对应重复规则，避免入口各补一份。
4. **最终结果**：最终组合版本通过了哪些具体操作、有哪些未验证属性与真实失败。不用“全绿／已独审”替代产品行为，不把局部成功写成全产品无阻断。

### 6.2 实施前先判断行为是否改变

- 改共享函数时列直接消费者；名字或源码文件未变，不代表它仍经相同路由。
- 改发现、命中、布局资格、source 报告时，核实际文字会否从 DOM 改走消息桥／PM／专业编辑器。
- 收回共同语义：可见性、文字样式事实、草稿状态、事务归属各有明确 owner；适配器传递事实，不能悄悄降低能力。
- 新增检查先问它保护哪一个真实失败；无依据的门改为诊断或移除。防已知错写、数据损坏和未知副作用重放的必要边界继续保留。

### 6.3 旧证据按实际属性复用

| 情况 | 处理 |
|---|---|
| 旧属性已证明，但本次改变了依赖路由／语义 | 补验该属性。例如新祖先裁剪影响旧 GLX 发现和命中，原可编辑性证据需回原入口核对。 |
| 旧证据从未证明当前属性 | 不外推。例如 textarea 改字保存不证明 opaque 原位字体、虚线和真实鼠标命中。 |
| 相关实现、依赖与关键环境未变 | 继续复用，不因为换 reviewer、上下文压缩或无关文案修改重跑。 |

用户已报告的具体作品回退，应回原入口确认；迭代使用保留同一失败语义的小反例，最终组合版回该作品做一次最短相关链。连接、故障时序、纯planner等问题从保持相同语义的最低成本反例开始，不以实机原作品复现作为普遍前置门。不要每个小改动重开25MB文件，也不强制所有内容×所有表面全矩阵；相关实现未变的有效证据继续复用。

### 6.4 最小验收同时覆盖修复与保留行为

每项至少回答：原操作是否经过真实目标入口？结果是否正确？本次依赖变化可能破坏的相邻能力是否仍成立？需持久化的修改能否沿正式事务保存并独立重开？

避免假通过：

- 有按钮／一个 marker 不证明能真实鼠标命中，也不证明其他已确认字段有提示。
- 数据字号没变不证明原位输入字形、基线和选区一致；视觉属性看真实呈现。
- 程序状态由测试代码预置，只能证明状态保留，不能据此签真实鼠标互动。
- 修改夹具／断言必须说明原条件为何不合法，保留原失败；不能删除正在保护的行为以换取通过。
- 重要职责变化沿现协议做独立 review；先核真实 consumer 和失败出口，不按文件数量、测试数量或 Hash 证明正确。

这套方式降低重复回退，不能承诺以后没有缺陷。验收投入只跟当前真实影响扩大，不为假设风险另造全仓门禁。

### 6.5 本次为什么反复出现，以及如何让方案直接约束修复

1. **修的是共享函数，验的却是某一条旧入口。** 消除幽灵框的祖先裁剪改变了旧 GLX 的真实命中；同源小 HTML 的成功也没有经过 opaque 桥。后续先列该共享事实的直接消费者，选实际不同的分支反例，回原作品确认；不靠文件“没被本次改动”判断体验不会受影响。
2. **保护落在某个动作上，没有覆盖同一语义的其他动作。** 分栏只拦删除键，粘贴／剪切／Enter仍走默认跨载体替换；公开正文 rewrite 缺少明确删除范围的意图。后续以范围修改和关系意图作为修复边界，不继续按按键或入口各造局部规则。
3. **局部输入事实丢失后，被迫用过宽条件做决定。** failure压成字符串后无法区分拒绝、unknown或断连；保留稿压成Boolean后会锁其他文档。应保留现有typed outcome、operationId和目标归属，沿原owner解决，不以隐藏toast、清全局error或放弃所有稿来换“可编辑”。
4. **只检查进入和正常成功，没有闭合失败、改绑与清理。** 暂时补读失败没有重连出口，属性控件关闭A后改绑B却失去登记，组件提交失败先丢审阅上下文。验收应对这次改变的生命周期补一个真实反例；不是每项都增加庞大故障矩阵。
5. **优化所依据的等价关系不成立。** 同revision不等于resources未变；普通组content不等于包含全部后代的图面；capture像素大小不等于原阅读尺寸。优化前明确所复用的事实，针对实际不同而被误判相同的输入验证，不用普遍Hash／全量克隆替代正确语义。
6. **用户可见设计和内部等价修复没有区分。** HTML模式改名／换操作本是产品决定，却被技术实施直接带入。此后连贯体验变化先展示并讨论；已批准体验下的内部修复继续自主推进，不为每个代码细节增加审批。

每个修复在本文件对应条目回填“共同根因、已覆盖的兄弟入口、仍保留的正确边界、最终证据”即可。原测试若只证明按钮或某一个动作，就补缺失属性；已有效的保存／冷开／运行证据继续按依赖复用。不需要新平台、另建总任务系统或无差别全仓重跑。

## 11. 架构修改计划与本批实施（Owner后续授权）

### 11.1 选择与不采用的替代办法

最合适的边界是修正现有领域owner及直接消费者，保留正式实例树、单个连续正文编辑器、DocumentSession writer／History和既有文件服务。不重写编辑器，不建立第二套恢复系统或统一万能错误平台。源码定位已足以启动；实施中用反例证伪选择，发现错误则在对应领域修正，不用历史报告压过实际结果。

| 共同领域 | 选定修改 | 为什么不采用局部替代 |
|---|---|---|
| 正式操作／连接 | Projection与Bridge保留明确outcome／operationId；瞬时读取由连接owner恢复；已确定未写入的操作闭合现resolver，unknown只查原操作。资源更新按实际model/update事实接纳，History区分no-op回执和改变内容的历史边界。 | 只隐藏toast、清整份error、盲重放或关闭全部CAS会保留根因或造成错写；每个控件各造重连/队列也会分叉。 |
| 输入与恢复 | 原Lifecycle／draft registry区分活动输入与已保全原稿；目标按document／epoch／surface／state归属。冲突稿保留但释放无关编辑占用；字段接续按原基线／当前值／草稿意图判断。mounted控件登记跟随真实binding，保留稿不会被另一目标提交清掉。 | 不以“存在任意旧稿”作全局门，也不靠清空旧稿放行。保留同一writer，草稿不变成第二正式工程。 |
