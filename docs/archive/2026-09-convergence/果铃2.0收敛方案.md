## 1. 已确定的产品决定

1. 当前没有用户，大规模重构正当其时；旧路线、既有 Store 与执行器不构成限制，不以范围过宽缩减完整目标。
2. 通用 AI 内容工作台，教育是首发场景；教学方法作为可选技能，不写死在产品外壳。一级对象只有空间、文件、会话。
3. 文件与会话正交；h5lesson 是可关闭文件，Flow、Slides、Spatial 是其内部表面。Markdown 默认正文，源文是另一视图。
4. **果铃自建统一完整执行器**，覆盖产品内直接编辑、内容/素材生成、多步骤任务、受控代码构建与导入。可复用成熟 SDK/Agent 核心，不要求从零复制通用编码产品。
5. **API 接入为主。** 用户可配置 DeepSeek、MiniMax 或其他供应商及多模态模型进行低成本生产；通过 API 提供的 Token Plan/其他允许套餐是正式使用场景。
6. **OAuth 是用户可选连接，GPT OAuth 首轮上线。** 开发使用 Owner 当前账号通过正式登录流程接入，前期图片生成使用该连接；独立图片 API 供应商与账号待定。其他供应商按实际支持接入；API 文本/编辑主链不强制用户拥有 GPT 订阅或启用 OAuth，需要生图时须有已验证的图像连接。
7. 对话/规划、视觉理解、图片生成/编辑可以分别选择连接。开发质量基准与用户模型选择分开；低成本 API 生产必须真实验收。
8. 外部 AI/CLI 通过一套 MCP 使用果铃能力，作为开放协作与兜底入口。取消三家 CLI 深度嵌入作为必做项，保留实际内容能力。

## 2. 交互与信息架构

默认左资源、中内容、右 AI：左侧资源管理器在上、会话列表在下，默认常驻，用户可主动隐藏；中间文档标签、简洁工具栏与主要画布/正文；右侧 AI 助手和输入区常驻。沿用左上角工作空间新建/切换入口，不增加同义项目层级。面板真正收展与记忆尺寸，不通过高频收展才能管理多文件。知识库、模板、工具管理和任务详情按需进入，不全部占据一级导航。

资源区使用“资源管理器”名称；文件管理以右键、拖拽、快捷键等 Windows 常见习惯为主，顶部保留少量高频入口。会话可新建、搜索、重命名、删除，与文件保持正交。

课件内容区底部固定横向场景/页面导航，每个场景卡片下方直接放自己的小状态按钮，当前场景和状态分别突出。场景多时横向滚动，控制底栏高度以保留大画布；场景树原有层级与 Flow/Spatial/Mix 的定位能力必须保全，非 Slides 页面不伪造呈现状态。导航属于当前文档，不与工作空间文件树混排。

工作台可插入文字、图片、视频、音频，支持资源管理器媒体拖入；选中后用快捷工具条和按需属性浮层完成常用手动编辑。保留既有快捷工具条内直接输入、提交的元素级 AI 修改，不强制跳转右侧助手。两处 AI 入口共用执行、目标、权限和文档变更；各 Surface 保留自身模型，Flow 正文不强行变成自由画布元素。

专业编辑器主体布局保留，只将原有常驻右侧工具面板改为 WPS 式侧边按钮按需展开，AI 也放在按钮组；资源/会话默认收起，如保留入口则浮出。两种模式编辑同一文档并共享 History、资源与保存。独立窗口/标签分离待定，不作为本轮前置。具体布局与待验证场景见[交互细则](../../../GPTpro方案/guoling_2_0_execution_plan/mid_term/WORKBENCH_EDITOR_LAYOUT.md)。

发送前展示文件、页面、对象或正文范围。显式局部修改限制范围；普通聊天的选区/图片是上下文，不增加应用自己的自然语言意图分类器。运行时按实际权限使用能力，不追随焦点偷换目标。

普通编辑默认原位变化、完成自动提交、一次撤销；用户要求先审阅时改变同一 EditSession 的接受策略。长任务、页数或复杂度不能自动变成候选交付。

同一任务可交替直接编辑与构建工具，不要求用户预选 live/build；不因调用构建而自动切换模型或计费来源。超出已有授权时再处理具体权限。

## 3. 文档内核与工具边界

```text
API / Token Plan / 可选 OAuth → 果铃统一执行器 ─┐
人工编辑 ─────────────────────────────────────┼─ 统一 Tool Gateway
外部 AI / CLI → 果铃 MCP 桥 ──────────────────┘       ├─ 文档工具 → DocumentSession → 视图 / History / 保存 / 恢复
                                                     ├─ 文件 / 构建 / 媒体服务 → 各自操作或 job 回执
                                                     └─ 后续可选薄 runner → 外部 Agent → 同一 MCP
```

- 主进程文档服务持有 DocumentRegistry 和每文档独立 DocumentSession；纯 TypeScript 内核不依赖 Electron。每份文档一个正式 writer、操作序列和 History。
- renderer 中的 ProseMirror、画布与 Store 是视图、缓存或未 ACK 编辑投影；人工输入可即时显示，AI 读取前须完成已发出的人工修改。
- documentId/revision/epoch 是文档身份；路径是可变 binding；当前页、选区和缩放属于 ViewState。会话或模型连接不能替代文档身份。
- Markdown 以保真源文/资源引用为正式内容，h5lesson 沿用受支持 V9 与资源侧车，各有 Driver，不统一成万能 JSON。
- ToolCatalog 导出人工操作、函数工具与 MCP schema；内部调用不必绕 MCP。宿主注入身份、基准、权限、operationId 和历史分组，模型只拿短句柄与内容。
- MCP bridge 接同一 Gateway 和能力服务；文档操作只连接同一文档服务，多客户端不能启动各自可写内核。人工、内置 AI、外部 MCP 的同类操作共用权限、领域规则和回执。
- 领域 planner 按纯度迁到 core，DOM、Phaser、播放器测量保留窄视图端口。复用能力，不保留另一套正式 Store/History。

DocumentSession 只承担正式文档内容的权威与历史，不充当所有任务的容器。任务可以引用零份或多份文档；新文件、数据处理与作业使用各自的资源引用及授权，不能为适配文档工具伪造当前文档。模型循环不依赖具体格式或“元素”结构；各能力自行定义操作、提交与验证语义。图中后续分支表示扩展位置，不表示本次新增交付项。

## 4. 正文流、直接编辑与构建

### 正文草稿和正式提交

正文使用 `edit.begin → edit.delta/snapshot → edit.complete/abort`。每文档一个活动正文生成组；重叠区域受控，其他区域人工输入继续并可靠映射。完成后一次事务/一次撤销，人工操作穿插时按正式操作序列处理。

Provider 原始工具参数分片先进入执行器解析缓冲。调用、目标与授权固定后，可以增量解码指定 content 字符串，再发类型化文本事件投影草稿；无需完整 JSON 到齐或额外模型轮才显示已确认文字。**不完整参数不能执行正式操作。** 字段重复、转义截断、缺片、目标变化或异常结束须撤回或明确失败，不猜补。完整参数与最终文本通过校验后才提交。

明确目标绑定的独立文本流同样可用，但不得截取普通聊天/思考冒充正文。外部 MCP 仅完整调用时按操作级更新，不假称逐 token 生成。

生成中只保存已提交 revision；取消当前未完成草稿，保留此前正式操作。停止屏障、幂等、恢复和一次撤销由任务/文档内核保证；不能把本地取消等同供应商已退款或请求未收费。

### 受控构建和导入

统一执行器在独立 scratch 编码、调用受控构建、读取错误修复、隔离预览，再经正式入口导入。live/build 是工具权限与交付方式的区别，不是两套循环。

源工程和正式文件不向构建子进程开放旁路写入，scratch 允许必要操作；进程、文件、网络、凭据与资源限制须实际实现，不能只设置 cwd 或写提示词。编译通过不等于交互正确，真实宿主检查与资源闭包保留。

只删除普通编辑的 candidate/replacement 必经链。构建、导入、Runtime/Component 继续保留 staging、检查与 canonical commit。跨文档分别提交、如实显示部分完成，不假称全工作区原子事务。

## 5. 执行器、模型连接与计费

| 层 | 职责 |
|---|---|
| ExecutionEngine | 任务循环、工具往返、上下文、取消/恢复、预算与状态 |
| ModelProvider / 媒体 Provider | 一次请求、真实流、协议与用量、图片生成/编辑 |
| Connection | 供应商、endpoint、凭据引用、认证方式、账户与能力 |
| Billing | 按量、Token Plan/其他订阅、预付或未知；独立于认证 |
| Tool Gateway | 目标、权限、幂等、领域操作与真实回执 |

API Key 不等于按量付费，OAuth 不等于通用订阅额度。套餐的模型目录、额度窗口、并发和适用范围按实际路由处理；未知余额显示未知，不把 token 估算当成套餐实际扣费。

完整执行器须负责上下文预算/压缩、工具参数与结果、错误分类、有限重试、操作查询、任务恢复和成本记录；不能用“加一个 SDK”低估这些责任。供应商的原生续接/签名等必需字段由 Provider 保留，不一律压缩成最低公共消息格式。

运行事实、操作/job 状态和成果引用独立于可压缩的模型上下文；模型结束、进程退出、成果提交与验证通过分别记录。任务按其实际目标、必要子任务和验证证据结算，不把缺失或未知结果标为成功。此处细化既有 S05/S07/S13 语义，不增加固定审查轮或新验收门。

图片理解、生成和编辑分别发现与验收。低成本文本搭配独立多模态模型是正式组合；模型能力不支持时显示缺口或使用用户预先配置的角色连接。不后台更换供应商、模型、档位或费用来源；用户已允许的回退须记录，范围外再询问。

高能力 GPT 可建立开发质量上限对照，但产品不绑定 GPT；低成本 API/可用套餐需有真实生产证据。SDK 选择、内部测试模型与用户默认设置分离。本轮不建设平台充值、销售套餐或托管计费服务。

开发主路由是 TeamoRouter 的 DeepSeek（provider `teamorouter`，`https://api.teamorouter.com/v1`），第二路由为 DeepSeek 官方 API。开发测试运行时读取 `TEAMOROUTER_API_KEY` / `DEEPSEEK_API_KEY`，产品运行时凭据进入自己的安全存储。模型与能力在探针时按实时目录和实际调用钉定；Owner 提供的路由说明中 `deepseek-flash` 指 V4.1、`deepseek-v4-flash` 指 V4，不得混写，dsh 配置清单不是供应商目录权威。

首轮提供 GPT OAuth，Owner 已选择当前账号并授权正式登录及前期 OAuth 生图验证。独立图片 API 待定，不是 B05 的账号前置；B05 前必须验证所选 OAuth 图像连接与所需能力，不能把登录成功当作生图/编辑成功。该开发连接选择不强制所有用户启用 OAuth，不改变 API 主使用方式。

OAuth 是可选使用能力，GPT 及其他拟支持连接上线前分别验证。OpenClaw 文档记录了 ChatGPT/Codex OAuth 生图/编辑路径，但图像型号可用范围与 API 不完全相同，部分路由可能选择原生 Codex runtime。资料可作技术参考，不能代替果铃实际 endpoint、模型、执行者和计费证据；API 主链独立成立。

## 6. 外部 MCP 与兜底

外部 Codex、Claude、OpenCode 和其他客户端使用同一果铃 MCP Server。只维护注册、配置位置、传输/认证兼容；不深度适配原生聊天、思考、模型目录与会话生命周期。

本地使用经验证的 stdio bridge 或 loopback Streamable HTTP，连接绑定授权；HTTP 具备身份/来源校验与短期令牌。预览页面无桥和凭据。远程客户端无法访问本机时明确不支持，不默认建设公网隧道。

交接包含用户要求、目标、已提交事实、剩余工作、必要附件与重新观察入口。交接前停止并结算旧 run，外部取得新授权后推进。MCP 不负责果铃自动启动、接管或停止外部 CLI 的整个 Agent；无缝自动换执行器不是 2.0 承诺。2026-09-24 Owner 决定：中途交接不作为 2.0 验收，原 S12-T04 与 REL-T12 删除；外部直接读写同一文档仍按 S12 验收。

果铃只展示实际 MCP 调用和结果，不伪造外部完整聊天、思考、费用或逐字流。撤权后拒绝晚到写入，但不能保证外部模型/独立 shell 停止。MCP 不是外部进程沙箱；磁盘旁路修改由 FileService 处理重载/保存冲突，不能冒充宿主提交。

后续允许果铃通过薄 runner 主动启动外部 Agent，承担有限启动、事件、取消和结果收集；它是可选外部作业能力，不是 ModelProvider 或另一套文档业务内核。交接会结算旧 run，委派则由父任务等待并接收子任务结果，两者不能混用。具体授权收拢、进程状态和成果核验见 [L03](../../../GPTpro方案/guoling_2_0_execution_plan/long_term/L03.md)。本次只明确方向，runner 未排期，不加入当前 S12 或 2.0 发布前置。

## 7A. 2026-09-25：2.0 追加创作能力收口

当前 Codex 既有验收先完成剩余项目并形成稳定 baseline；不在最后三项验收过程中插入 Runtime/HTML/Flow 内核改动。原有通过证据保持有效，不因追加需求回退为未完成。该 baseline 已于 2026-09-25 以 `25b12b4b` 提交；尚余的 REL-T11 按 §7B 挪到 M18 之后。

baseline 之后，2.0 继续完成五项必做能力：M15 Runtime/Component 轻编辑与自动图文发现；M16 Flow 混合画布与页面 Runtime；M17 HTML 高保真机械导入；M19 Slide 有限画布尺寸参数化；M18 后置 Representation Planning 与创作链收口。完成这些新增验收后才形成新的 G-2.0。2026-09-25 讨论后另增 M20、M21，并与上述五项整合重排，见 §7B。

Runtime 编辑只做文字、图片和少量已有参数。用户可以在试运行推进到某一动态状态后返回当前状态编辑；宿主自动发现 DOM 与 Phaser 常见图文（Phaser 只做 Text 与静态 Image），Three 不做适配。AI 不再承担任何登记（含文案表与编辑目标注册）；Scene Runtime 与 Component 复用轻编辑基础。不得扩成任意 DOM/CSS/JS/Three 深编辑器。

HTML 首版默认整体 Runtime 高保真导入，程序机械完成资源抽取、引用重写、包装和正式导入，不调用 LLM 重新实现。Native 拆分后置为有明确编辑收益时的优化；听力案例作为首个真实保真基准，但不建立像素评分服务或固定多 Agent 审核。

Flow 保留 Markdown/SharedDocumentEditor 连续正文，同时把 Native 文字、图片、形状与组件作为自由图层（默认随段落，可选固定纸面）；浮动能力沿用组件机制，不另建浮动 Runtime。正文新增文字继续用段落/标题命令；产品与 AI 的“插入文字”改为插入“文本框”（Native Text）。Flow 页面 Runtime 作为正文中的整块区域，可承载长 HTML 并随内容高度延展，不重构成 Slide 子类。

Slide 定义收敛为有限二维自由画布，1280×720 仍是兼容默认而非唯一尺寸；Flow 负责连续流式空间，Spatial 负责无限二维世界与镜头。三种 Surface 主要区分空间组织方式，而不是把 Runtime/Native/Component 能力人为分成三个等级。

## 11. 被取代的讨论结论

- 自建只负责直接编辑、CLI 长期专管构建 → 自建循环默认覆盖产品任务；后续可通过薄 runner 委派有限外部任务，不恢复 CLI 各自拥有业务逻辑的长期分工。
- GPT/OAuth 作为主入口 → API/Token Plan 为主，OAuth 可选。
- 低成本模型只作备选 → 低成本生产为正式验收场景。
- 三家 CLI 深度适配必须保全 → 一套 MCP 与薄配置兼容，保全实际内容能力。
- 工具分片直接执行，或必须另开模型轮才显示 → 增量解码受控投影，完整校验后提交。
- 最小纵切等于缩减范围 → 小范围早期验证贯穿完整目标实施。
