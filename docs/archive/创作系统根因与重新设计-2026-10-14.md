# 创作系统根因与重新设计

> 历史依据：2026-10-17从根目录迁入；原日期、阶段状态和未完边界保留。当前执行与剩余见[当前状态](../development-plan/CURRENT_STATUS.md)，本文件不自动恢复旧任务或旧授权。


当前结论：创作系统未达到可持续编辑、具有设计质量且效率合理的目标。验证作品只是暴露问题的样本，停止修订作品和重复付费试作。本轮先完成根因诊断与整体设计，不把方法文案、运行成功或局部软件修复说成系统改善。

## 1. 失败发生在同一条生产链

当前主要流程是“提纲→页面骨架→HTML/程序→逐工具装配→检查能否运行”。模型被迫兼任设计者、软件实现阅读者、装配操作员和验收员。可用的组件/API 很多，但最容易生成、装配和检查的是文字面板与控件，最终形成全幅网页和一个计算器。视觉、领域表现、自然推进和普通编辑被留到末尾；长时间操作没有换来相应质量。

这不是再加一句“互动丰富些”能解决的问题。既有方案已经要求关键体验、运动、状态与空间表达；真实创作仍没有落实。我的执行也偏离了目标：把改好这份课件当成产品修复，且验收只查点击、计算、保存、冷开和导出，遗漏普通用户改字及作品表达质量。本轮指令还把图片限制为一张，直接缩窄了美术路线，不能再把资产少全部归因模型。

导出HTML的具体浪费在生产消费者中仍存在：`compiledPlayer`将`world.themeCss()`（含整套内嵌字体）与组件CSS拼接，`createCompiledContentEnvironment`先对输入CSS做`:root`替换，再遍历全部style，把刚加入的同一段再次扫描。原文件有101条font-face、6,121,891字符字体CSS。冷开profile中该环境创建含子调用约292ms，GC约419ms；首次翻页出现约722ms microtask，翻页段另观察到GC约358ms（可能嵌套，不相加）。这是应先修的真实重复工作与分配压力，不足以声称全部冷开耗时已归因。Navigation的responseEnd约2886ms，占load时间约73%，可能包括文件供给与解析回压，尚未细分为磁盘、浏览器等待或诊断开销；不把这段洗成字体CPU耗时。正常首屏图像解码约28ms，当前证据不支持先压缩美术表现或改成全iframe。具体采样与限制见[原HTML性能记录](../../output/authoring-redesign-20261014/current-performance/REPORT.md)。

## 3. 新的生成单位：一个可感知、可操作、可修改的体验片段

先确定观众面对的材料、怎样介入、真实关系怎样改变、变化如何被看见，以及为什么自然继续。艺术方向、资产、运动和内容规则在这时共同决定，不能在文字页面完成后才补“美化”和按钮。静态阅读、图表和线性展示仍可采用，具体媒介服从内容，不强制所有作品游戏化。

例如结构拆解的重点是部件、装配关系、尺度与运动；观众操作部件，看见结构关系变化，再自然进入下一层观察。动作与反馈共同解释内容。多一个拆解按钮并不自动产生这种体验，更不意味着目前已有祈年殿模型及拆件资产。

推进可以来自操作材料、观察焦点移动、过程到达某状态、展开局部或进入新空间；软件仍沿现有状态、镜头和导航 owner 执行。目录、按钮和教师控制台按需使用，不以统一底栏代替作品自身的衔接。

视觉先确定主体与环境、构图、视角、材质、光线、文字角色，再准备资产。图片可以承担背景环境、主体、器物、纹理和过程材料；可复用资产与代码绘图、动画共同组成画面。既不限定一张封面，也不以图片数量当质量指标。动作应展示因果、结构或时间，不只是卡片淡入和数值条平滑。

## 4. 内容可编辑与复杂表现同时成立

Source 是统一组件的代码实现方式，不是组件之外的新对象。Git `21f28fd0`（2026-10-06 V10工程候选）中的 `ComponentImplementation` 已同时包含 builtin/source；二者共享 ComponentInstance、data/frame/resources 和正式事务。现合同还明确自定义源码保留专业作者身份。问题在消费者按实现类别限定编辑入口，没有贯彻统一组件已有的编辑能力；不能把这个缺陷解释为 Source 合理脱离抽象。

默认目标是标题、正文、标签、说明和可替换素材有正常编辑入口；复杂程序可以保持同一 Runtime，而不牺牲这些内容的可修改性。现有专业正文、DOM AuthorSpot、data/source 绑定和 canonical 写回应继续作为基础。静态内容可可靠抽取时由软件处理；不能抽取的程序也不因此失去它本来能够提供的内部编辑点。

本轮具体失效不是“全页程序无法编辑”，而是实现类型变化后编辑能力丢接：builtin 有自动文字热点，自定义 Source 没有自动启用；页面文字快捷入口又把它排除。此前推动通过私有 Source 接状态/导航时，漏验普通编辑保全。修复应让支持的 DOM 内容共享既有观察与写回能力，Source 显式注册也继续有效，且避免重复目标。仍为 builtin 的总结页和原 rev9 不能仅凭这条 Source 根因宣称同样已定位；其实际文字入口另用一次聚焦 GUI 检查确认。

纯 Canvas/WebGL 里没有可选文字 DOM 时，需要让运行画面中的作者文字关联实际内容数据或现有 authoring 注册。计算结果应改参数/规则，作者标签应能改文案，二者不能混成覆盖显示值。第三方不可定位的黑盒要如实说明边界；本系统生成的普通文字不能用这一例外免责。具体修复以本轮实际消费者诊断为准，不建设任意程序逆向编辑器，也不强制逐词拆成独立组件。

修改要进入同一工程、可撤销，保存重开及运行/导出消费当前值。不能只在临时 DOM 改出一个效果，不能维护源码正文与属性正文两份真相。更不能把“对象数变多”当编辑体验通过。

进一步消费者研究发现两个必须保留的范围差别。第一，Published direct Source没有挂文字记录回放，native Source现回放还以data.html存在为条件；必须把作者侧与实际运行出口一起接通。第二，现记录写入`instance.data.authoringRecords`，适用于这些Web派生Source，却不能直接推广到任意Source：业务data允许数组、primitive或strict专业对象，软件不能偷偷加字段。通用覆盖记录的归属应在统一组件的作者数据层解决，建议复用现AuthorRecord语义由组件层持有，与组件业务data分离；正式字段及已有记录保全需在实际实现中同步Schema/保存/消费者，不据此新建Source编辑平台或静默迁移用户文件。已有dataPath/sourceRegion精确写回继续优先使用，不把派生计算值改字当改算法。细节见[编辑链实施边界](../../output/authoring-redesign-20261014/editability-design.md)。

独审补充：若正式作者记录移出业务data，组件复制、库摄取及资源重映射也必须沿各现owner搬运同一记录，避免保存/播放器接通而复用组件时丢失人工修改。此项是既有核心操作的消费者保全，不引入新平台或全量矩阵。

## 5. 软件与模型重新分工，减少生成的串行成本

生成耗时近似由各轮串行模型等待之和，加上必要工具执行和外部资产等待组成。把每个可由程序确定的装配步骤都交给长上下文中的 max 再判断，会不断支付推理和传输成本；上下文越累越大，后续修改还要重新理解大量无关实现。缓存或更强模型不能消除这些往返本身。

| 模型负责 | 软件负责 |
| --- | --- |
| 领域内容与规则、艺术方向、动作与后果、表现代码及真正有选择的修订 | 目标与身份、当前作者源/数据及必要依赖、资源接入、批量装配、事务、History、保存、编译和客观回执 |
| 决定哪里共享、哪里需要局部定制 | 复用默认实现；只给作者增量及实际需要的源码，不把成熟运行闭包默认暴露为可编辑入口 |
| 看关键画面与核心动作后判断表达是否成立 | 返回受影响范围与必要观察事实；已经证明且没有变化的行为无需模型反复检查 |

源码层首先区分作者源与运行制品：`generate-component-builtin-sources → builtinSources → projectFiles projection → sourceAuthoringEdits` 是已证修改边界。不能只截短85万字让模型失去可用源码，也不能把全部依赖复制到每个实例。需在现默认实现/编译 owner 上提供短而完整的作者入口和明确依赖，使局部HTML或程序能接现数据、资源、状态、运动、导航与编辑绑定；入口形态由必要消费者确定，不另建 DSL、执行平台或第二 writer。短入口是默认工作材料的改善，必须保留按需读取完整作者源、API5自由程序与复杂native承载、专业数据和现编辑绑定，不能缩成有限hooks或固定模板。

现有批量工具真正用于相互独立的内容和装配；依赖当前观测的修改才顺序执行。资产准备可与不依赖它的业务代码并行，正式写入仍由唯一事务 owner 收敛。模型不维护内部编号，不逐页面读取同一实现，不为已知事实重复截图。长任务工作上下文只保当前相关素材与必要协议链，原始记录保留；不盲删 native reasoning/tool 链，不先做缓存平台或增加摘要模型调用。

进一步核实：现`batch`只覆盖canonical普通编辑，`project.apply`属于另一条Gateway文件入口，除批量加页外每次只接受一个路径。但真实修订q10已在同一次模型回复发出多次写入，说明单路径工具并不强制“一次模型请求只能改一处”。因此不把扩大批量接口列为首要修复，更不能据此解释全部串行耗时；优先利用现同轮多调用和软件源/依赖准备。只有具体业务要求同组修改必须一次提交，而现canonical准备确实不足时，才补那条共同事务，不预建通用批次引擎。相互依赖或同目标冲突仍按真实依赖处理，不为省回合并发重放未知写入。

短作者入口的具体比较见[源码职责方案](../../output/authoring-redesign-20261014/source-boundary-design.md)：首批优先短作者模块+软件闭合一次共享Source依赖，保完整默认实现，复用现moduleBindings；多文件原实现作者包留给实际深改需求，不先展开全库。当前resolver并不支持直接import builtin，依赖准备必须实接；现workspace的COW也不等于共享依赖自动局部分叉，这两处明确为实施缺口。

max 也不应成为机械步骤的默认解决办法。这次极小 course.logic 请求在失败及重试上合计约5分钟，是继续量化推理配置适用范围的证据，不是现在静默换模型或保证降强度不损质量的依据。

## 6. 按用户结果实施，不再继续修这份作品

1. **先恢复普通文字编辑与短作者入口。** 查清当前生成物断点，接通现 authoring/writeback；修复打包依赖冒作作者源的问题。这同时影响用户能否修改以及模型改一个功能的成本。保复杂表现、共享默认实现和唯一工程。
2. **让新的创作单位进入实际流程。** 方法、能力发现、少量有表达力的示例与工具入口同批调整：从希望表达的现象抵达实际最短用法；第一段正式体验就落实主要视觉材料、关键动作、运动与后果，再扩展。自动模式无需增加确认阶段，阶段产物也不变成另一份作品。
3. **修原HTML已测到的重复字体与样式工作。** 同一document的字体由其共同owner安装一次，direct组件只接必要主题规则和自身样式，不反复携带/转换字体base64；隔离native文档仍由自己的document持有字体。消除局部样式二次扫描，保CSS选择器及字体实际呈现。改后只复测原路径冷开与这次首次翻页，查长任务和必要画面；余量再按新证据决定是否追查。此前隔离GLX副本准备不作为这个问题的证据，旧有效修复保留，不销毁离屏状态。
4. **修复后再做一次有信息增益的真实创作。** 以不同于当前面板的关键表现检验系统，不能由Root代写作品。实际检查普通改字/换素材、关键动作的可见后果、融入内容的推进和主要画面；必要保存冷开与正式出口复用已有链补受影响属性。记录首个可用体验时间、总模型请求/等待/读取量和打开时间，不凭‘completed’或单样本宣称质量稳定。

不重建组件平台、通用游戏引擎或动画编辑器，不强迫预设模板，不增加固定审批、限额或全矩阵。本轮方案完成不等于上述开发完成；文字编辑缺陷、短作者入口、实际生成质量/速度、当前打开卡顿仍须实现或验证。发行继续暂停，不提交、发布或部署。
