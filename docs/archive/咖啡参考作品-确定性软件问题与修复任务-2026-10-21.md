## 2. B01：Flow 热更新 / 重装配导致 DOM 祖先循环

### 2.1 已确认现象与影响

已挂载的 Flow 局部程序修改 `.content.html` 后，界面出现：

```text
Failed to execute 'append' on 'Element': The new child element contains the parent.
```

历史第一次记录为 revision 20，事务已提交，保存 recovery GLX 成功，dirty=false；重开可以恢复。另一次在将 group 从 Slide 移入 Flow 后出现同类异常。因此，**不能将其笼统描述成保存失败或数据丢失，也不能因为保存成功就签收持续编辑正常。**

直接证据：

- `docs/creative-production/works/coffee-journey/design/v05/native/incident-runtime-content-edit.json`
- `docs/creative-production/works/coffee-journey/design/v05/native/REPORT.md` 的“Flow 热编辑”段。
- `docs/creative-production/works/coffee-journey/design/v05/reviews/native-flow-groups.png`
- 可选副本素材：`native/coffee-u02-u05-v05-recovery.glx`、`native/coffee-journey-v05.glx`。

### 2.2 本次找到的具体链路

当前 `src/renderer/document/editorSession.ts`，`objectView` 约 453–511 行：

1. NodeView 创建外层 `dom` 和 `objectHost`，把 host 放入 dom。
2. 调用 `options.renderObject(block, objectHost)`。
3. `refresh` 继续复用同一个 objectHost，执行：

```ts
// 摘自当前生产代码；以执行时文件为准。
destroy?.();
objectHost.replaceChildren();
destroy = options.renderObject?.(block, objectHost);
```

当前 `src/renderer/ui/FlowWorkspace.tsx`，`renderObject` 约 670–714 行：

```ts
const shell = host.closest('[data-flow-block-id]') ?? host;
const stage = document.createElement('div');
shell.prepend(stage);
stage.append(host);
// ...
// 返回的清理函数包含 stage?.remove()
```

第一次挂载时，host 被移进 stage；清理时删除 stage，同时使 host 离开原 NodeView 外壳。refresh 再复用 host 时，`closest` 可能已找不到外壳，fallback 得到 `shell === host`。随后先把 stage 放入 host，再把 host 放入 stage，就形成祖先循环。

**证据强度：** 这条链已通过下面的局部反例验证，且对应当前生产代码。完整 UI 是否还存在其他触发分支，需要用真实 Flow 定向复现；不能把局部反例当成所有热编辑故障均已定因。

### 2.3 本次无文件写入的局部复现

在项目现有 Node/JSDOM 环境中运行以下等价 DOM 序列。未启动应用、未修改源文件或作品：

```js
const { JSDOM } = require('jsdom');
const d = new JSDOM('<!doctype html><body></body>').window.document;
const shell = d.createElement('figure');
shell.dataset.flowBlockId = 'example';
const host = d.createElement('div');
shell.append(host); d.body.append(shell);
function mount(h) {
  const s = h.closest('[data-flow-block-id]') || h;
  const stage = d.createElement('div');
  s.prepend(stage); stage.append(h);
  return () => stage.remove();
}
const destroy = mount(host);
// hostConnected=true, hasShell=true
destroy(); host.replaceChildren();
// hostConnected=false, hasShell=false
mount(host); // HierarchyRequestError
```

实际输出：

```json
{"phase":"first_mount","hostConnected":true,"hasShell":true}
{"phase":"after_cleanup_before_refresh","hostConnected":false,"hasShell":false}
{"phase":"refresh","name":"HierarchyRequestError","message":"The operation would yield an incorrect node tree."}
```

### 2.4 修复目标与边界

在现有 NodeView / Flow 渲染接缝上确立清晰所有权：NodeView 持有的可复用 shell/host，不应被下一次仍要复用它的销毁逻辑一并丢出父结构。选择保留稳定 host、在 host 内挂内部结构，或明确恢复挂载关系等正确方案；应根据现有 caption、选中、观察、运行时挂载约定决定，不指定机械替换某一行。

同时检查此链上已存在的 `queueMicrotask(root.unmount)`、`runtime.onElement(id, null)` 与重新挂载的先后关系：旧清理不得卸载/清空同 id 的新挂载。只有反例成立才修相应分支，不建设全局生命周期平台。

不接受的“修复”：try/catch 吞掉异常；遇错直接跳过 append 留下空对象；每次源码修改强制重启应用；关闭热修改；把原生 group 改成整页 Web；取消正式 Undo/Redo；以重新打开后的成功掩盖原会话失效。

## 3. B02：局部程序正式画幅塌缩为约 150px
