## 5. 轻量失败基线：两次运行与可靠比较

仅为开发诊断与本轮收口提供证据，不接入build、verify、pretest或CI，不变成每个工作包必跑的门，不建设失败管理平台。

### 5.1 工具与运行范围

- 一个 `scripts/test-failure-baseline.ts`，用tsx运行；两个npm入口 `test:baseline:record`、`test:baseline:check`。
- `--record <起点文件>` 运行并保存；`--check <起点文件> --output <终点文件>` 在同一次终点运行中比较并保存可复用结果。比较结果不得由后一次record覆盖。
- 范围与test:product一致，明确保留其两个现有排除项；排除项不计通过，不扩大exclude、skip或过滤。核对实际Vitest与生命周期，不复制一套以后漂移的产品范围规则。
- 使用Vitest JSON报告。首轮默认稳定低并发 `maxWorkers=3`，参数可调；失败按文件单独进程复跑一次。只有证据表明资源竞争时才进一步降并发，不循环重试到绿。
- 元信息只记HEAD、相关dirty事实、Node／Vitest版本、测试范围、并发、耗时、执行数量及报告是否完整；不加全仓Hash或环境指纹平台。
- 起点默认 `output/test-baseline/start-e77963756.json`；终点准备共享于 `docs/development-plan/test-baseline/known-failures.json`，在尚未获commit授权时只产生工作区文件。
- README给出用法、分类及文件统计（前20）、已知证据范围；分类是诊断标签，不决定是否修产品。

### 5.2 比较语义

| 情况 | 必须给出的结论 |
|---|---|
| 同一用例两次实际失败 | 本轮观察为稳定失败；不能由一次初跑失败直接认定 |
| 仅一次观察失败 | 本轮观察为偶发；首轮过、复跑同文件时失败也必须记录，不能忽略 |
| 原稳定失败现在明确通过，且本次其他观察未失败 | 才能记为已修复；现在仅偶发时记“转为偶发”，不报修好 |
| 原基线只有偶发，现在两次失败 | 新增稳定失败，不能因名字已在JSON中就放过 |
| 消失、改名、删除、skip、零匹配、未运行 | 不等于修复；找对应证据或记未决 |
| 整文件加载失败 | 单列文件级错误，关联该文件未执行的用例；不能将子用例没有结果当通过 |
| 旧文件错误现在展开为具体失败 | 先判定先前被遮蔽、无法归因，不能按名称集合直接宣布全部新增或旧错误已修 |
| 子进程崩溃、全局准备失败、JSON缺失或报告不完整 | 未完成验证，不能返回“没有新增失败” |
| 同文件同fullName重复 | 保留各记录，防止Map覆盖；无可靠对应关系时标明比较未决，不自动相减 |

用例键使用仓库相对路径及fullName，统一路径分隔；失败信息保留简短摘要，原始报告可回查。已有文件级失败可以作为已知失败记录；它遮蔽的子用例不能签通过。预先存在的条件skip按实际报告，不增加全仓“必须无skip”的新门。

退出码建议：0＝本次报告与比较足够、无新增稳定失败；1＝新增稳定失败；2＝运行／报告／比较证据不足。即使返回0，也只能声称本次比较的“无新增稳定失败”，不能声称全仓通过。影响结论的未决项必须显式保留，不能以exit 0吞掉。脚本不自动更新或批准失败基线。

起点和终点足以证明脚本的实际使用；不另建测试框架。与基线保护相关的异常／漏跑处理交集中独审核对，不把只看退出码当验收。

### 5.3 数量与新失败处理

- 不固定要求起点31条都红；31个已报告条目必须找到实际状态或缺失原因。其他新发现的失败也不能漏掉。
- 未解释的新失败先定位，不能写进known-failures洗绿。确认本轮造成的必须处理；确认与本轮无关则保留证据和归因，不宣称本轮修复。
- 旧报告6个“全并发失败、单跑通过”文件不设永久白名单；每次按当前观察分类。
- 历史数百条红例只做归类和统计，不启动全仓清零。仅在失败阻止本轮必需行为验证时补最小必要处理。

## 6. 验证安排

最低成本且能证明目标的检查通过后停止；验证随真实变化扩展，不按文件数机械成矩阵。

| 属性 | 最小充分证据 |
|---|---|
| Flow试运行点击 | 当前真实Flow壳层的宿主DOM按钮及一个教师按钮，编辑／运行往返；不能只测一个脱离React捕获路径的函数 |
| 空程序根插入 | 正式Kernel／Bridge／Session插入、History、Undo／Redo，另有非容器／锁定拒绝零写入 |
| HTML名称及模式 | Pane真实入口／ACK；若IME或完成逻辑变动，补相应真实浏览器输入／结束检查 |
| 普通文档与Flow入口 | 实际渲染：无选区文档动作、普通文件选区格式、Flow输入光标与段落类型；检查恢复后的可见入口与目标范围 |
| 输入、IME、投影与保存 | 受影响的实际owner行为用例；涉及浏览器事件／焦点时用现有最小Chromium装配；涉及正式数据／保存链时用fixture或副本做相关Undo／保存／冷开 |
| 几何、组与浮层 | 仅当实际改动命中这些路径时，补选中／拖动／取消及准确目标；未变有效证据复用 |
| 类型与构建 | 产品组合候选完成后保留原三段typecheck；只按实际运行验证所需准备相关Player／Renderer／Electron产物，已准备且未变不重建 |
| 全量诊断 | 起点一次、终点一次；终点同次比较和落盘；中途只运行受影响检查 |

浏览器验证不限定为“只有输入类回归”，也不强制完整Electron、物理IME、所有作品和全出口矩阵。真实渲染、实际业务按钮、保存、模型fixture与Owner接受分别报告。
