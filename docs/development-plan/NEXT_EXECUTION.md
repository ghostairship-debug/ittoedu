更新：2026-10-27。**状态：开发前收口方案；本轮只整理指导体系，不执行产品源码开发。下一轮用户授权开工后，直接从下文“开始工作”进入。** 本文承接前三轮研究与近期审计，替代旧报告的排期/启动指令；长期治理遵循 [DEVELOPMENT](../../DEVELOPMENT.md)。

## 目标与产品边界

目标是在质量、表达自由和深度编辑成立的前提下，让内置 AI、外部主 Agent 经果铃 MCP 的首次合格创作及后续修改，速度不明显差于外部主 Agent 独立写 HTML；同时证明人工接力、局部返修与持续创作的实际收益。典型作品十分钟首次合格继续作为挑战目标，不能用首次预览、首存、首导或 run 结束替代。

深度编辑可由原生字段、Runtime 内部绑定、局部 Source、文件与正式事务共同实现。不追求全面原生化，不把整页/主要内容封进缺乏可操作编辑边界的大 Web 对象；也不要求把所有复杂程序拆成原生控件。表面形式、导航和交互服从作品需要，线性段落允许合适的下一步按钮。

保持现有产品定位、核心交互、默认行为与兼容范围。内部实现和可撤回实验自主进行；改变这些产品边界时，拿具体方案与用户确认，不能以实验或“技术重构”绕过。

### 工作包 2：完整成熟会话纵切；ACP保留独立订阅价值

**当前默认投入：用完整 Pi AgentSession 做一次真实领域纵切。** 原因是它有机会让模型历史、压缩、通用重试和循环由一个成熟会话拥有；前轮faux provider只证明生命周期，尚未证明真实任务收益。只嵌入agent-core却保留整套自研权威history/retry/loop，不算完成目标。

- 保留Gateway/DocumentHost、当前稿、对象作用域、Source/COW、正式事务/History、版本、保存与停止撤权；只将通用会话责任交给候选。UI记录是展示/领域证据，不再回写成第二套权威模型历史。用户输入的持久接受、steer/follow-up及已有子任务启动、取消、封存和续作继续接同一领域服务；逐项核真实支持，不假定Pi自动提供完整多Agent编排。
- 从现有Engine与DesktopService的边界接一个可撤回候选，先完成真实短改与单元Source深改，再用工作包3的作品副本检验跨对象、共享定义范围、中途人改、停止及进程恢复。恢复要核正式最终文档，不能只看原生session能加载。
- 退役责任包括实际移交的provider stream、通用循环、权威模型历史、压缩及支持的重试/会话生命周期；空回复、截断和不合作工具等旧分支按真实支持核验，不能从SDK名称推定覆盖。随对应消费者迁移退出旧机制，保持可回到原入口，不做双权威运行。
- 用同领域工具/目标/写权与尽可能相同的已授权模型配置比较；渠道不同就报告完整产品路线差异，不冒充纯内核实验。先各做代表性筛查，仅在波动会改变决定时少量交错复验，不机械重跑全部组合。
- 判断依据：数据/范围/保存/撤权成立；高频短改没有实质退步，复杂任务的合格总耗时、人工介入或消耗有实际改善；同时确实卸载维护责任。历史125%仅为诊断参考，单次8.504秒不作为稳定门槛，也不事后挑有利指标。
- 通过则在已授权且已验证范围逐步采用；不通过则停止这条接法、保留可用自研入口并写清局部原因。不能以“再测一种内核”不断延迟开发，也不能因一次配置错误否定整个成熟会话方向。

**ACP订阅支线同步保留。** 用户已明确认可“使用自己已有的模型订阅、减少手动MCP配置”的价值，无需重问这个方向。沿原生官方Agent登录、稳定公开接口与薄适配器接入，果铃注入领域工具；不取用/中转订阅token，也不把协议支持当成渠道授权。

已有Codex原生订阅、两次正式保存、跨进程resume与冷开证据可复用。接下来只补正确目录到实际模型、正确工具名恢复、目标上下文和必要权限事件的缺口。Claude/Antigravity等按该渠道当时官方方式、用户可用账号及授权核验；握手不等于创作成功，不为了供应商齐全做全矩阵。

ACP可以因订阅价值成为用户可选入口，是否新增选择UI、首次登录流程、默认接管或自动切换须提交具体产品方案确认。它不依赖Pi先赢，也不预设自研/Pi/ACP三套长期常驻；只有真实渠道或工作负载硬约束支持才保留多个执行器，每个会话仍只有一个权威历史。

**止损。** 需要shadow history、改写原生loop或大量专属prompt才能接通，就停止该接法；既有稳定入口继续服务当前任务。实现细节可自主决定，默认模型/路由/权限/用户操作发生变化时只暂停相关切换。官方CLI可以作为明确授权的被测产品通道，不得代替主Agent承担本轮开发和判断。

### 工作包 3：真实生产、主动并行和人工接力

**复用既有两题及其需求，先完整完成一题，再用第二题检验迁移。** 两题入口为 [市场题](../../output/audit-remediation-20261027/benchmark/brief-market.md) 与 [叙事题](../../output/audit-remediation-20261027/benchmark/brief-story.md)。已经读过/跑过的题标明复测；需要“未知修改”时另封存未泄漏的具体要求，不能把旧题改称盲测。

| 路线 | 执行和产物 |
|---|---|
| A | 主Agent直接通过真实果铃MCP创作与修改，正式GLX |
| B | 同主Agent独立写HTML，允许合理模块化与正常工具；不经果铃作者流程冒充外部基线 |
| C | 果铃内置AI按实际配置创作与修改，正式GLX；模型/推理档位/渠道如实记录 |

三条路线保持独立上下文与共同任务标准；不要让验证者代写正文、人工补完后报告自主成功。更强模型或用户介入可用于恢复，但必须与原失败分账。第三轮四格是预置Source下的局部生产证据，不替代A/B/C整作比较。

**共同旅程。** 从创作到首次合格，再做真实人工改文案/布局/数据、未提前泄漏的局部返修、必要Source交互改动、保存冷开与离线交付。跨对象/共享定义/停止恢复只取受本批变更影响的场景，同一对作品复用这些检查；未触及的有效证据不重跑。当前以桌面为主，移动、语音或图片只在题目要求时加入。

**主动并行。** 足够重且可独立修改的语义单元可主动委派，软件传同一份公共事实/来源、范围、产物角色并机械采用；公共定义、正式文档与集成保持单writer。计入父准备、子执行重叠、装配、返修及QA成本。短任务直接做，不固定开三位作者，不把“发生重叠”当净提速。

**Skill与参考库随真实任务改进。**

- 源Skill说明现有能力怎么用，工具名称/参数以实际catalog为准；读取Skill可能改变工具披露，不改变写入授权。设计理念、流程、素材和案例按需读取。主入口不累积复盘教训或复制长Schema，软件已经处理的机械职责不再教模型手工做。
- 现有新作入口已很短，`creative-reference/`已可按问题导航；复用它们，具体重复内容或误导例子命中后才修。保留现有Skill标识、安装路径和实际分发链，不把物理搬走references当作能力/创作分离已完成。
- 仓库参考目前并不自动随独立安装分发。今后需要独立MCP/服务器时，基于真实读取/资产需求外置；当前不新建RAG、全局Skill同步或资产平台。已退役的全局自动安装保持退役。
- 改动Skill维护源后沿现有 `generate:ai-capabilities` 同源同步并核实际消费者；未同步或未实测的候选如实标注，不能只凭文档声称模型已采用。当前dirty的三个references及生成包先保全核对，不能覆盖。
- 每次真实作品只沉淀能改变下次选择的局部方法/组件、适用条件和修改入口；写回既有反馈，不复制整作充模板库。允许合理拒用，不以模板数或统一风格作成果。

**验收口径。** 沿用 [既有冻结协议](../../output/audit-remediation-20261027/benchmark/protocol.md) 及同版brief、数据与素材：t0是收到完整任务和已可用素材并被要求开始；T1到首个真实内容、可操作的有效预览；T2到首份满足共同标准、已保存且离线可运行的正式交付。各路线先到同等人工修改状态，收到共同局改要求才起算T3，终点为修改合格、其他内容保留、正式文件与离线物均更新；规定人工编辑/Undo/Redo/保存冷开耗时单列，不混入T3。历史记录保留原口径，不回填改写。

发现、等待、装配、保存、导出及失败返工均在实际墙钟内；公共素材准备单列。候选事后被判合格才可用其实际提交时刻为终点；被拒后的等待与返修保留在最终合格墙钟中，独审处理时间另列。保留冷暖启动/环境、人工介入和可见usage；SDK耗时、并行时间并集和模型用量不能互相替代，计量不可见写unknown，不填0。

质量看内容完整/事实与推导、阅读与视觉、互动反馈、导航以及题目要求；编辑深度看真实选中、局部改、范围保全、Source可接手、History与保存。自动检查只负责确定性要求，不能用字数、节点数或同一评分替代语义/艺术判断。第一题通过后第二题检验方法迁移；若仍慢或难接手，优先减少强制结构和接口往返，而非增加原生比例或复杂提示词。

### 条件优化：按实际收益进入

| 触发证据 | 可以自主推进的内部优化 | 收口/撤回依据 |
|---|---|---|
| 重复schema、无意义发现/读回占主要回合 | 原有profile和tools.load短回执、稳定披露、独立读并发与真实错误恢复 | 实际模型收到完整可用能力，合格总耗时/消耗改善；不牺牲恢复或权限 |
| 图像/历史负载有明确瓶颈 | 保留原图与回读的模型副本、有限稳定投影；端点支持后才试缓存/传输参数 | 中文数字/单位仍能识别、误用不增加；不追缓存率，不永久保留全部旧图 |
| 采用/导出/首开计时指向样式字体或依赖 | 在现有owner中试新采用的样式来源精简、字体/运行时按需处理、总首开优化 | 保真、完整动态/离线和真实到可编辑时间改善；旧工程不自动迁移，无收益则撤回 |
| 错误owner、重复状态/依赖环或共享热点实际拖慢本批 | 借鉴清晰模块/contract边界，按真实消费者迁移与退役 | 受支持行为保留、依赖方向清楚、旧writer退出；不做全仓重构前置 |

已知UI缺陷与恢复已确认交互可在对应包内修；新交互/默认布局不能以优化之名直接改。缓存键、WebSocket、全追加历史、统一文字余量、双视图与固定并发数均不是先验必做项。
