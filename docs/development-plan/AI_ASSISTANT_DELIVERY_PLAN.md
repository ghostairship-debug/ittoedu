## 3. 正式依赖与执行顺序

[manifest](roadmap/manifest.json)只列开始该节点开发必须满足的硬前置；独立规格中的真实集成条件与Acceptance仍须全部满足，才能声明节点完成。接口已定时可先实现独立叶子；未接上真实consumer不能冒称整节点通过。最终汇合节点显式等待各条必选线，不因放开开发并行减少S3/S4、PPTX或三CLI验收。

1. **089及090–094**：先关闭首批四项反例。090稳定公共任务/原生授权端口及现有聊天壳最小回答；三adapter按专属文件推进，公共Harness、配置和IPC由唯一Owner集成。
2. **095与096可并行**：095实现真实结构/草稿/画面/运行观察；096仅依赖090，先交付正式能力源的小卡片/查询与精简输入，不等待全部Surface观察。完整观察的请求接线在100/103汇合，不能用假观察验收。
3. **097→100→101/102及099**：100硬前置为090/095/097；任选一家已实际通过本次所需原生基础门的CLI完成真实反馈纵切，另外两家继续开发并在103全部汇合。101教师UI、099动态检查按各自稳定端口和非重叠写域推进；共同事务和宿主文件仍顺序集成。
4. **098/099/104→103→060**：图片、动态与Builder入口收敛；103集中补齐受影响的三CLI矩阵并复用有效证据。050/051/052/083/087及S3都保留，不在每个局部节点重跑全部。
5. **1.9**：040后先由唯一Owner稳定042身份、045材料和044阶段事件的必要窄接口，再并行做保存/身份叶子、材料解析/查询、041基础工作台。044实际自动/手动流程仍须等042/045；041的阶段卡与首成果接线等真实044产物后集成。043消费040/042/044/045的任务和材料事实，不再等待041整体UI完成。050显式汇合040–045，051 PPTX并列，060等两线。
6. **2.0**：000后设置、Skill、材料和无障碍随各界面/合同稳定推进。020仍消费实际设置、021内置Skill、022材料；025做有限对照。030不以025整项完成作为开发前置，键盘/焦点/状态公告跟随UI实现，最终帮助与支持结论待025后收口。040仍显式等待020/021/022/025/030，041 PPTX并列，050签署后060发布。

路线Write locks是本节点可能触及的写域，任务卡只申明当前批次实际需要的锁。不同节点不能同时占用同一锁；若粗锁涵盖不同叶子文件，由唯一协调Owner在同一协调任务下持锁，向隔离工作区委派精确非重叠叶子，再顺序集成，不能省略锁或用worktree绕过同文件冲突。共享文件不分给两个writer，叶子结果只证明该子范围。

共享真实窗口、输出目录和同一工程提交保持串行；独立准备/读取可并行，但同一制品只构建一次。遇到新共享修改时先收回该叶子写入，由Owner接线或调整批次，不复制状态/接口绕行。只有跨执行者确需协调才维护现有任务卡，不新增调度引擎、锁平台或里程碑账本。历史1.2 frontier不是当前待办。

## 4. 原生能力与工程写入边界

完整定义见[共同实施合同](roadmap/1.8/IMPLEMENTATION_CONTRACT.md)和[架构合同](ARCHITECTURE_CONTRACT.md)第7节。默认观察范围、工程修改范围、原生CLI权限是三个维度。

当前代码中Codex固定只读/never、Claude工具白名单、OpenCode终端关闭和限定文件桥、共同cwd/环境与prompt限制均需在相应092–094及090/091/096修订。对等是保留原生有效授权及GUI回传，不是默默提权。默认小观察不妨碍CLI主动取得更多资料，用户已有Skills/工具连接不得被profile遮蔽。

应用不自建独立MCP服务/工具RPC平台，仍保留原生CLI已配置的连接。编辑器正式修改通过canonical命令与资源事务；candidate root闭合约束的是宿主摄取，不是整个CLI的工作目录/文件权限。原生文件或工具操作成功不能冒称画布/History已提交。Generated Component/Runtime宿主能力另按原合同，不能继承CLI所有权限。

所有scope、观察、候选、receipt、取消、首存和恢复由唯一Owner管理。自动/手动流程和simple/professional消费同一能力，UI不另存工程、任务或修改历史。

## 6. 高可靠性验收

### 6.1 准备与局部验证

结构/身份/原子性用解析和针对性测试，视觉看真实画面，互动看实际动作，持久化看受影响的撤销/保存重开/导出。按本次要证明的行为选择最少的充分证据；“1–3条命令”只是上限提示，不允许将全量测试藏进一条命令来满足数量。一个命令可以合并同批必要测试，已有有效证据无需为了凑命令再跑。

现有npm脚本会隐式准备：test与test:product重建Player；test:e2e还做全样例检查、课例/组件矩阵准备以及Renderer/Electron构建。局部节点使用直接的本地Vitest/Playwright入口，按下面规则单次准备所需制品；直接入口不等于允许使用缺失或过期制品。

| 本次验证 | 必要准备与选择 |
| --- | --- |
| 纯逻辑、Schema、本地repository | 已安装依赖即可直接运行明确的Vitest文件/命名用例；测试确实消费Player制品时才补Player构建 |
| Player行为或导出使用当前Player制品 | 相关源码/依赖变化或制品缺失时执行一次build:player，然后把同批目标测试合在一次Vitest调用 |
| Electron UI/运行宿主 | 按实际改动分别准备一次Renderer、Electron、Player及命名用例需要的fixture；只有某用例依赖其生成物才做对应课例/矩阵准备 |
| 真实CLI纵切 | 先确认目标用例确实需要原生调用；按指定adapter/行为显式选入，局部修改不默认调用另外两家或生成整课 |
| 版本集成/发布候选 | 保留既定verify与实际验收范围；同一候选只执行一次，不能先把verify内含的整套检查重复跑一轮；有新变化时只补受影响证据 |

局部命令采用npx --no-install vitest run和npx --no-install playwright test，指定实际文件及必要的命名过滤。综合stabilizationCoreUsability包含真实三CLI与整课/Component/Runtime生成，局部节点必须用精确grep；仅103、1.9/2.0汇合门可按其实际范围显式选完整矩阵。不得用通配匹配或pass-with-no-tests掩盖漏测；被exclude、skip或0匹配的目标没有获得证据。能力索引测试通过现有test:capabilities或直接Vitest选择，不能再交给明确排除它的test:product。

新增目标行为目前没有用例时，在实现同一改动中先添加命名用例，再更新选择表达式；旧用例只证明原保全范围。可用Playwright --list核对选择，不把列举当测试通过。所需制品来源/相关变更和检查结果记在现有交接证据，不新增hash/缓存台账；CLI/窗口/输出目录共享时顺序验证。

未变化的实现、依赖、fixture和关键环境证据持续有效。失败先定位到具体行为，仅复核受影响范围，不重试凑成功；只有失败指向更广范围或版本门要求才扩测。文档变化不触发产品全量测试。本轮优化不改变package.json生命周期或测试代码。

### 6.3 速度与质量

既有本地目标继续适用：上下文提示更新p95≤500ms，原生事件到UI p95≤300ms，以至少30个确定性本地事件测量。简单选区初始技术说明预算≤12KB，原图/材料/源码单列；预算不能删掉必要信息。

秒级Native、分钟级动态和标准整课≤30分钟是分阶段目标。020在开始前冻结标准课例规模、材料、模型/强度、初次/连续会话与完成口径；报告实际分阶段和总耗时、输入量、往返、返工、失败。少量真实模型运行报告原始时间与中位数，不伪装可靠p95。整课起点为原件上传完成且用户启动任务，材料解析与必要图像理解计入总耗时；不是等全部提取结束才开始计时。手动教师等待单列，首个画布产物时间不代表整课完成。

质量按材料准确、知识获得路径、教学推进、视觉可读与一致性、真实互动、可编辑/可重开/可运行/可导出检查；同一CLI与模型并不豁免质量比较。不能以跳过必要QA、更换模型却不披露、删除失败或静态截图替代互动来达标。未达目标先修直接瓶颈，涉及范围/预算取舍再由Owner决定。

### 6.4 内部闭环与外部对照

025保留真实CLI/对应插件的有效比较要求，用于证明原生能力与课件质量没有因GUI包装下降；未失效历史对照可复用，只补实际差异。外部基线不替代本产品的实际操作，也不进入教师日常任务流程。

2.0验收实际材料处理、设计、生成、修改、运行检查、修复和导出全部经软件完成。不得请外部AI先生成最终产物再导入冒充内置，不得要求另一外部Agent检查/修复才能完成。原生CLI自身网络/model服务仍可调用，不把“内部完成”错误解释为本地离线推理。

GUI不必逐项复制IDE的专有面板，但不能因此裁剪CLI原有工具/权限。没有真实可比证据时不宣称一比一功能或质量等同。
