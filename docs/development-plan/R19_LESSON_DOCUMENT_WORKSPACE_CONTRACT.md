# 1.9 课例、真实文档与共编执行合同

日期：2026-09-15。状态：**按 Owner 已确认体验与“持续推进至方案可执行”的授权收敛的实现基线；尚未实现。** Owner 同日明确本次没有兼容需求：不实现旧课例身份、旧会话或旧缓存的迁移。对应 [总实施方案](R19_SHARED_DOCUMENT_EDITOR_IMPLEMENTATION_PLAN.md)；正文表示见 [共用正文合同](R19_SHARED_DOCUMENT_CONTENT_CONTRACT.md)。本文规定应用文件与会话边界，不向 Course Project V9 增加工作空间、聊天或阶段字段。

## 1. 教师入口与导航

1. 首次进入显示“打开工作空间”“新建工作空间”和最近工作空间。工作空间是真实目录；打开目录不批量整理、搬动或索引全部材料，也不强制在其根目录写管理文件。
2. 进入后左上是目录资源管理器，按需展开；左下是当前工作空间的课例及其对话，中间对话，右侧材料、教学文档和课件标签。没有课例时中间提供“新建课例”“打开课例”；已有材料仍可浏览。
3. 新建课例先确定名称与存放位置。默认位置为工作空间当前选中目录，展示最终文件夹路径；同名不覆盖，给出可点击的新名称建议。创建真实课例目录及必要标识成功后进入主对话；取消或创建失败不出现虚假课例。
4. 打开课例选择真实目录。已有标识直接打开；普通目录按本次“作为课例打开”的动作建立最小标识，保留所有已有文件。课例下发现多个 `.h5lesson` 时列出供选用，不凭文件名猜当前工程。原有独立工程打开/人工编辑入口保留；接入文档创作时将所在或指定真实目录关联为课例。
5. 未生成课件时，右侧照常打开材料和教学文档；收到第一个实际可展示课件后打开其标签。空画布、日志和占位内容不计首成果。单击文件预览、明确打开后保留标签；有草稿的标签不得被预览替换。
6. 默认一条对话贯穿本课例；“新对话”只新建对话，不复制课例或工程。点击目录文件只是打开文件；发送给 AI 的文件/选区通过输入区引用明确可见，不因浏览自动扩大修改目标。
7. 原有 simple/professional 保留为工具披露方式，三栏关系相同；窄窗口允许折叠侧栏，材料/文档/课件入口始终可找。阶段状态由流程 Owner 提供，导航不另建阶段状态。

## 2. 目录和身份

推荐新课例默认结构如下；已有教师文件名与组织方式保持，课例标识只记录实际相对路径：

```text
课例名称/
  .courseware/lesson.json
  .courseware/authoring-state.json
  materials/                  # 整理正文、必要图示、出处索引
  assets/                     # 教学文档使用的本地附件
  teaching-brief.md            # 当前教学简报
  01-teaching-plan.md          # 实际产出后才创建
  presentation-brief.md        # 当前呈现简报
  02-presentation-script.md
  course.h5lesson             # 实际构建/保存后才出现
```

- `lesson.json` 是 strict、版本化的应用文件：`schemaVersion:1`、稳定 `lessonId`、`title`、文档角色到相对路径的映射、可选当前课件相对路径。它不保存正文、工程副本、聊天或 CLI 句柄。目录名称与显示名称修改保留身份。
- `authoring-state.json` 由阶段 Owner 写入当前流程、阶段、确认基准和下游待复核关系；不保存第二份教学文档。不存在时可由真实文件重建待确认状态，不能猜测教师已经确认。
- `lessonId + 规范化真实目录` 定位课例；对话记录在应用本地按课例与 `conversationId` 归属。工程编辑目标仍采用实际 projectId、路径、revision、sessionGeneration/epoch 与 canonical owner，不能用课例 ID 替代它。
- 创建课例即确定归属；尚无 `.h5lesson` 时可整理材料、编辑文档和对话，不制造空工程路径。第一次构建可以持有唯一未保存工程，预定保存位置在真实课例内。
- **首次工程保存**只完成工程文件绑定并失效旧编辑 epoch，重新观察后接续；课例、文档和原对话不重建。保存失败或取消保留当前稿与课例归属，迟到候选不能应用到新目标。
- **工程 Save As**仍产生新的工程 workspace identity，不复制原工程会话、候选、trace 或项目专属 CLI 恢复句柄。它不是复制课例：原课例文档保留，原工程对话作为原目标历史可查看；新目标重新读取当前文件开始对话，不把旧候选复用到新文件。保存到课例外部的文件作为独立工程目标，新对话显式绑定该目标；课例标识的当前相对路径不写入 `../` 或绝对路径，也不声称课例已复制。
- 移动同一课例保留 `lessonId`，停止/失效旧 epoch，按稳定 ID 重关联本版本对话、阶段记录与恢复稿到新目录，再重定位相对引用和工程/CLI 目标；这是当前课例移动，不是旧格式迁移。复制课例创建新 ID、新对话和待确认阶段，正文与附件可复制，执行记录不复制。外部复制造成两处相同 ID 且原目录仍存在时提示作为副本打开，不静默合并。
- 新记录直接使用本合同的课例/对话归属，不读取并迁移旧 `projectId + normalizedPath` 记录。遇到旧版本或损坏记录只报告该记录不可用，不静默套用新语义或清空其他记录；原生 CLI 能力与有效目标绑定仍由现有 adapter/工程 Owner 负责。

## 3. 文件编辑接入口与唯一正文

共用编辑核心只消费下列窄接口，具体 IPC 名称由对应 Owner 实现；不新增通用工具平台或模型循环。

| 接口 | 输入 / 输出与责任 |
|---|---|
| `openDocument` | 课例＋实际相对路径 → UTF-8 正文、磁盘版本、附件版本与诊断 |
| `saveDocument` | 文档引用＋预期磁盘版本＋当前正文＋附件变化＋操作 ID → `saved` 新版本 / `conflict` / `failed` |
| `watchDocument` | 通知外部变更或文件丢失；不得直接覆盖未保存稿 |
| `prepareAiEdit` | 先完成当前保存，冻结真实文件、目标范围、版本、任务 epoch；失败不发送旧稿冒充当前稿 |
| `applyAiEdit` | 基准版本＋明确修改 → 实际保存的全部/部分改动、冲突位置和改动记录 |
| `revertAiEdit` | 改动记录＋当前版本 → 已撤回和未撤回的具体部分 |
| `confirmStage` | 由流程 Owner 接收阶段、真实文档引用、已保存正文与附件版本；不由编辑器自行推进阶段 |

正式当前稿是课例中的 `.md` 文件；未保存稿、光标、撤销记录、AI 改动记录与冲突恢复物位于应用本地，不进入 `.h5lesson` 或导出物。文档自己的编辑历史不接管 Flow 工程历史。Flow 仍通过唯一工程命令/资源/History 提交。

版本必须能区分真实内容，不能只用文件名或 mtime。磁盘版本可由文件内容派生，用于并发写入比较；确认基准还包括正文引用的本地附件版本。版本值用于证明当前稿身份，不要求正常 Markdown 往返的字节完全一致。

## 4. 保存、关闭和外部修改

- 排版正文默认直接可编辑，按需切源文。两种视图只有一个当前稿；现有 Markdown 中不认识的扩展按保真片段保留，不通过忽略内容生成“成功”结果。
- 默认短暂空闲后自动保存，初始 debounce 为 800ms；Ctrl+S、发 AI、阶段确认和正常关闭前主动 flush。组合输入未完成时等待结束，不写半个汉字；触发保存时仍存在后续修改，状态继续显示未保存。
- 文件写入采用预期版本检查、同目录暂存与替换。新附件先准备并落到最终可引用位置，再替换 Markdown；失败保留恢复稿与原文件。跨多文件不能伪称一次文件系统原子替换：用文档操作记录区分准备、正文已落盘和结果已记录，崩溃后核对真实文件恢复，不重复改稿。未引用的新附件可后续清理，不提前删除旧引用资源。
- 文档源文允许保存未闭合数学或扩展，显示诊断。切到排版视图保留问题原文；需要解析该内容的生成或导出先定位问题，不能默默使用最后有效结果代替当前稿。
- 无本地修改时外部修改刷新；双方均改时对基准、本地稿、磁盘稿三方比较。可确定不重叠的内容自动合并并保存；重叠处保留双方并就地选择。文件外部删除时保留草稿，显示重新保存/另存入口。
- 保存失败时保留可恢复稿，关闭时明确“重试保存 / 保留恢复稿后关闭 / 返回编辑”；只有恢复稿实际落盘成功才可声称保留后关闭，恢复写入也失败时停留编辑或由教师明确丢弃。恢复稿按真实课例和文件定位，发现版本冲突先比较，不能直接覆盖磁盘。
- 删除聊天/缓存只清理应用所管记录，不能删除课例正文、附件或尚未保存的文档恢复稿；删除真实文件须走明确的文件操作。

## 5. AI 共编和阶段接续

1. AI 改稿前保存当前稿，记录基准、文件和范围。明确改稿请求默认直接应用无冲突部分并标出；范围外正文、样式、资源引用保持。
2. AI 运行期间教师改同一处时，以教师当前稿为准；保留 AI 建议供就地处理。已应用、部分应用、冲突或失败分别显示，不能把“生成了建议”说成已修改文件。
3. 一次 AI 修改形成一个改动组。记录实际写入的范围与前后内容；撤回通过范围映射及内容匹配形成新的修改，只逆转仍能可靠对应的 AI 内容。后续手改或外部重排导致无法可靠定位的部分标为“未撤回”；不整篇还原，不为此重排 Flow 的既有历史。
4. 文件改动标记保留到教师清除或下一次明确操作；历史记录可以查看来源。普通 Ctrl+Z 是编辑操作撤销，“撤回本次 AI 修改”是有边界的新操作，二者不混称。
5. 手动流程保持教学简报→策划→呈现简报→脚本的分别确认，四份真实 Markdown 都登记角色并使用同一文件版本确认接口。确认时重读已保存正文及本地附件；构建提交前再次校验实际引用的确认基准。内容变化使原确认失效，依赖该基准的在途阶段任务暂停或失效，旧稿候选零工程写入；下游已有成果保留并标为待复核，不自动重写或重建。自动流程不增加逐稿人工批准，但同样校验本次消费的文件版本，关键缺失/冲突时提问。文档 AI 非冲突合并仍按普通共编规则处理。
6. 压缩、重启、切 CLI 或继续中断任务时，重读实际文档、材料索引、有效确认与当前工程观察。旧 running 标为中断；原生恢复句柄仅经 adapter 核实后使用。不能把聊天摘要当当前稿，也不能重放旧候选。
7. 首次新课例默认提供手动引导，可切自动；自动必须有成功读取的材料。模式只是本轮推进方式，变更时保留当前文件和已提交成果，不把自动稿伪装成教师已确认稿。

## 6. 材料与课例独立性

材料入口包括选择工作空间已有文件和从其他位置添加；教师选定本次使用范围后，原始 PDF、DOCX、PPTX 分别真实读取。课例 `materials/` 保存必要正文、图示和出处索引，覆盖本次教学范围，不只保存摘要或指向共享原件的绝对路径。

出处记录原材料名称、页/幻灯片/段落定位、提取范围及必要识别说明；需要复核的原始片段或原件副本按实际必要性随课例保存。移动/删除共享原件后，已整理材料仍能供创作消费。仅定位、上传、列目录或建立索引不能标“已读取”。原始文件保留，不要求改写教师的大工作空间。

PDF、DOCX、PPTX 必须分别证明读取正文与必要图示、来源可追溯及真实创作消费；保留既有文本入口。PPTX 材料读取与可编辑 PPTX 工程导入是不同路径，彼此不能代替验收。
