# 1.9 目录会话、文件目标与真实文档共编合同

日期：2026-09-18。状态：**已确认的目标合同；批次 A 正在按本合同改运行代码（F01 归属／目标／保存）。Skill 未改。** 实施与差距统一见[完整实施方案](R19_FRONTEND_SPECIAL_IMPLEMENTATION_PLAN.md)。本文取代旧版强制课例身份、四阶段文件和固定布局要求；不改变 Course Project V9、Published V2、唯一工程事务及[统一正文合同](R19_SHARED_DOCUMENT_CONTENT_CONTRACT.md)。

## 1. 工作空间、项目与会话

- 工作空间是真实根目录；项目是其中可选的真实文件夹。选择已有文件夹或创建命名文件夹即可工作，不要求 Git、课例注册、lesson.json 或先建课件。不自动搬动已有文件或批量扫描整个目录。
- 对话归属是规范化的目录作用域（workspaceRoot，以及可选 projectPath）与 conversationId。工作空间会话的 cwd 是根目录，项目会话的 cwd 是项目目录；多个会话、多个可编辑文件可以共存。
- 路径比较、持久化、列表、读取、发送、补充输入、停止、恢复和删除使用同一归一化规则。Windows 大小写、分隔符、尾分隔符及实际路径关系由共享 Owner 处理；不得仅凭同名目录、前缀或客户端传来的 conversationId 跨作用域取记录。
- 查找指定会话需要验证记录真实归属，不能全局 listAll 命中 ID 即放行。当前根目录中的项目与根目录会话分组呈现；切换、重命名、归档、删除针对明确 ID，不能用“最近一条”代替指定会话。
- 打开文件只是改变内容页与自动焦点，不切换、复制或重建会话。没有 .h5lesson 时也能聊天、读取材料、编辑文档、恢复任务。
- 新项目只有一次名称/位置选择；取消或创建失败不产生假条目。同名不覆盖，提供明确的新名称。新会话只创建会话；删除会话不删除目录、文件或未保存恢复稿。
- 会话/任务/trace 存在应用本地；文件内容存在用户目录。应用记录不能成为第二份文件正文或工程。旧格式无迁移要求，损坏/未知记录逐条隔离，不能清空其他数据。

## 2. 文件上下文与发送目标

| 情形 | 默认行为 |
|---|---|
| 未打开可编辑文件 | 目录任务，可以使用当前目录内文件；不会凭空产生编辑工程 |
| 当前 .h5lesson，无选中对象 | 当前页为默认编辑范围 |
| 当前 .h5lesson，已有选中对象 | 自动变为当前选择；取消选择回到当前页 |
| 当前 Markdown | 当前文档；存在有效文字选区时可明确改选区，不套用“当前页” |
| Office 等外部宿主文件 | 可以作为引用材料；仅显示真实支持的查看/打开/编辑能力，不显示无效页/选区操作 |
| 当前消息明确指定对象/范围 | 优先于自动选择与当前页；浏览其他文件不改写此显式目标 |

输入框上方只有一个可点开的自动目标提示，如“电路.h5lesson · 第 3 页”或“电路.h5lesson · 2 个对象”。平时不要求先选文件再选范围；整文件、目录和其他目标放到展开入口。目标默认跟随活动内容页；点击输入框不得清掉画布选择。跨消息锁定如有需要置于低频菜单，必须持续可见且可解除，不能成为默认操作负担。

`@` 引用用于告知材料或路径，**不自动把引用文件设为编辑目标**；需要修改该文件时通过明确意图/目标动作呈现。发送前可见本次目标；发送时冻结目录作用域、conversationId、实际文件身份、范围、版本及任务 epoch。之后切标签、换页、选对象只影响下次消息。冻结信息不足、目标失效或有未解决保存冲突时定位问题，不默默改到另一文件。

权限产品目标是工作空间内完整工作权限、外部默认只读，需通过实际原生配置和授权接线及验证；不能仅靠标签、输入文件allow_once或自建OS沙箱宣称完成。目录/编辑焦点不裁剪原生工具能力，也不隐式新增未授权权限；原生无法表达的范围明确报告支持差异，不能显示已生效。

## 3. 工程身份、首次保存、另存与目录操作

- 工程修改目标独立于目录会话，绑定真实 projectId、工程路径/未保存身份、revision、sessionGeneration/epoch 与 canonical Owner。不能用会话 ID、目录或文件显示名称代替工程身份。
- 第一次生成可以持有一个真实未保存工程；首次保存只绑定工程文件并失效旧目标 epoch，重新观察后继续原目录会话。不重建会话；取消或保存失败保留当前工程、草稿及归属。
- Save As 建立新工程编辑身份，旧候选、执行句柄、工程专属 trace 和提交记录不复制到新目标。原目标历史仍可查。**目录会话可保持不变**，但其消息引用保留原文件身份；历史消息不是新文件的执行授权或提交历史。下一轮重新观察新目标，不复用旧 epoch/candidate。
- 保存到目录外不会隐式迁移会话 cwd、目录归属或扩大引用范围；新文件作为明确文件目标处理。如需到新目录工作，由用户显式切目录/创建会话。不得把外部绝对路径伪写为课例相对路径。
- 文件重命名/移动由文件 Owner 同步标签、引用、观察与恢复定位；在途任务必须验证原冻结目标，不能凭新名字套用。目录移动后先核实原目录与记录再显式重新关联；源仍存在时不得自动合并同名会话。
- 复制目录/文件只复制用户明确选择的内容，不复制会话/候选/原生执行句柄。文件复制或 Save As 的新身份需由正式 Owner 分配，不保留两个可写对象的同一执行身份。
- 本版本自身的重命名/移动连续性与损坏隔离仍须验证；“无旧格式兼容”不能作为删除真实文件、跳过首次保存或丢弃恢复稿的理由。

## 4. 文件端口、保存与恢复

端口名称是职责说明，复用现有实现后在相应节点确定 strict 类型，不新增一套工具平台。

| 端口 | 责任 |
|---|---|
| openDocument / watchDocument | 目录作用域＋真实文件定位，返回正文、磁盘版本、附件版本和诊断；通知外改/丢失，不直接覆盖草稿 |
| saveDocument | 引用＋预期版本＋当前正文/附件＋操作 ID，返回 saved / conflict / failed |
| prepareAiEdit | flush 当前稿，冻结文件/范围/版本/任务；失败不发送旧稿冒充当前稿 |
| applyAiEdit / revertAiEdit | 经过文件 Owner 应用或选择性撤回，返回真实范围、保存状态、冲突及记录 |
| reviewCurrentArtifact | 仅用于用户明确要求审阅的制品，记录真实已保存文件/附件版本；不默认生成四个阶段或确认状态 |

Markdown 是真实当前稿；本地恢复稿、光标、撤销与冲突状态由文档会话 Owner 持有。Flow 通过唯一工程命令/资源/History 提交，两者不嵌套历史。磁盘并发比较使用能识别真实内容的版本，不能只用文件名或 mtime；不要求无关 Markdown 格式化逐字节相同。

- 排版/源文共享一个当前稿；未知扩展保真，错误数学可保存并诊断，不能用最后有效渲染冒充当前正文。
- 默认短暂空闲自动保存，初始 debounce 800ms。Ctrl+S、发送依赖当前稿的 AI 请求、制品确认与正常关闭前 flush；IME composition 结束后保存，不写半个汉字。保存中又有修改继续显示未保存。
- 文件写入进行预期版本检查、同目录暂存和替换；附件先就绪再替换正文。多文件操作记录准备/正文已落盘/结果已记录，崩溃核对实际文件，不宣称跨文件原子替换、不重复改稿、不提前删旧资源。
- 外部改动无本地草稿时刷新；双方改动时比较基准/本地/磁盘，无冲突部分合并，重叠部分保留双方。外部删除保留草稿并提供重新保存/另存。
- 保存失败显示重试、保留恢复稿后关闭、返回编辑；恢复稿实际写入成功才能声称保留。恢复也失败时不得自动丢稿。恢复定位到实际目录/文件并先核对版本。
- “已应用、未保存、保存中、已保存、冲突、失败、待恢复”分别来自真实状态。隐藏内容区、换停靠方向或切换编辑器模式不改变文档/任务寿命；正常关闭的处理由统一 Owner 决定。

## 5. 共编、材料与按任务创作

1. AI 明确改稿请求默认应用无冲突部分并标记。运行期间用户修改同一处时保留当前稿及 AI 建议，不覆盖；范围外正文、样式与资源保持。
2. 一次 AI 修改形成一个实际改动组。撤回只逆转仍可可靠定位的 AI 改动，保留之后手改，分别显示已撤回/未撤回；不整篇还原。普通 Ctrl+Z 与“撤回本次 AI 修改”有不同语义。
3. 工程写入须经 canonical transaction 与真实 receipt；原生 CLI 外部写文件由文件冲突/重载 Owner 处理，不能伪称已通过工程事务或提供没有真实记录的撤销。
4. 材料可以已在目录里，也可通过路径、@、附件或粘贴提供。任务按需读取相关部分，记录实际来源、位置、版本与读取结果；附件/索引存在不等于 Agent 已消费。
5. PDF、DOCX、PPTX 各自保留正文、必要图示/结构和可追溯出处的原格式消费验收。需要独立交付的整理材料写成真实文件及资源，不依赖临时绝对路径或共享原件持续存在；不要求每个任务先创建材料目录或点击“采用”。
6. 默认以用户任务持续推进：理解目标、需要时补问、读取材料、必要策划、创作、检查和交付。可以按需生成计划/脚本，但没有固定四个 Markdown、强制导入/策划步骤或自动/手动四阶段切换。
7. 用户明确“先给我看计划/确认后再做”时才在真实当前制品处暂停。内容/附件变更使针对该稿的批准失效；依赖旧稿的任务必须重新观察或停止旧候选，不猜测批准已转移。一般任务不凭空引入确认门。
8. 保留教学知识获得路径、真实互动、三 Surface 与质量指导；消除强制流程不等于删掉教学质量。044/F07 实施必须同步运行 guard、提示词、托管 Skill 源/安装产物及实际 consumer；只改界面文案不算完成。本轮未修改这些运行制品。
