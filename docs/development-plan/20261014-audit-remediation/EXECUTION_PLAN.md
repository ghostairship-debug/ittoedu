## 各包通用执行规则

1. 读取包内直接 producer/consumer 与相关架构合同；复制将改文件当前原件，以已有 dirty tree 为基线。不能 reset/stash/clean，不能覆盖用户工程。
2. 从当前可信失败实施，按现 owner贯通必要消费者。若发现新消费者遗漏，补回该包，不另造平行实现。
3. 先做最低成本能证伪的检查；涉及真实入口、渲染、字体、运行输出才补对应浏览器/文件生命周期证明。已通过且未受变化影响的证据复用。
4. 正式 writer、资源归属、异步生命周期等重要结构变化由未参与实现者审实际候选；原具体方向独审可复用，候选新增差额仍核对。普通文案修正无需扩大评审。
5. 源 Skill/协议变化使用既有生成、安装流程同步，不手改生成副本。构建只准备受影响 consumer；不机械跑全矩阵。
6. 每包报告候选、实际执行、验证范围及剩余。工程候选不等于视觉质量、实机、Owner accepted或发行；未知费用和性能不能编成已测值。
