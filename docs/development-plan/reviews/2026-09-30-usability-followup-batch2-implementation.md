## 2. 目前已落地并验证的第二批能力

### 2.1 UF-03／UF-06：保存、导出与可靠发布

- 保存前确定的冲突／权限／空间拒绝，与进入发布后无法确认结果分开；不再仅凭“调用过保存函数”把全部异常变成 unknown。正式拒绝可由原操作查询，实际写入但外层 ACK 丢失可从持久证据查证，不重复覆盖。
- 新建导出和更新导出共用正确的写入阶段：同目录临时文件写完并刷盘，持久记录其文件身份与内容摘要，再发布。最终 ACK 丢失时查询必须同时匹配候选身份和摘要；其他进程放入内容相同的文件也不能冒充原操作成功。没有可靠身份时保留 unknown，不虚假结算。
- 导出写入前的 EEXIST、ENOSPC、EACCES 等有明确拒绝回执；进入发布后的真正不确定状态保留候选与查询路径。没有用通用错误文案、清空目标或无条件覆盖作为恢复方案。
- 同一任务显式续接，经宿主 task lineage、当前授权、文档与文件版本核对，可以更新该任务以前的导出；仅复用会话历史的独立任务不能取得覆盖权。
- 不支持硬链接的 Windows 发布经现有小型原生 helper 走同目录、不覆盖既有目标的移动；保留中断／重名保护。原 helper 在第二批早先已实现，本轮复用并验证。

入口：`delivery/DocumentDeliveryService.ts`、`DocumentDeliveryOperationStore.ts`、`workbenchDeliveryAdapters.ts`、`documentJournal.ts`、`publishNewFile.ts`。

### 2.2 UF-04：坏记录局部隔离与显式恢复

- 健康 run/submission 可以继续列举和使用，坏条目保留原件并单独报告，不再因一份坏历史阻止新会话。
- 未完成的文件移动只保留相关文档和路径。两端都找不到时不猜测位置，但恢复面板可“恢复为未命名稿”，保留同文档的正文、资源、Undo/Redo、正式操作回执与停止屏障，再由用户另存。旧路径和原文件不被擅自重建／改写。
- 显式另存或解除旧绑定之后，过时移动 intent 不重新绑定到旧位置；只保留仍归它处理的未决项。
- 连来源都无法解析的坏 intent，不允许据此证明危险写入安全；但健康已有文件可读取，新会话继续使用，诊断保留。对无法排除冲突的写入仍提供明确限制，而不是伪称全局恢复成功。
- 关闭保全不再等五分钟才让用户决定。等待三秒会主动提供“继续等待／返回编辑／仅保留已经确认的恢复稿后关闭”；三秒是显示选择的时机，不是取消任务的时间配额。继续等待仍使用原请求；用户返回后旧 ACK 和旧对话框结果不作用于新关闭尝试。
- 最后一个选项明确警告尚未同步的视图输入可能丢失。它不会删除已持久化恢复稿，不会把未确认输入说成已保全。确定保存失败也提供同一恢复出口。

入口：`DocumentFileCoordinator.ts`、`DocumentHostService.ts`、`WorkspaceRecoveryPanel.tsx`、`createWindow.ts`、`documentCloseCoordinator.ts`、相关 shared/preload。

### 2.3 UF-02：停止当前与暂停后续分开

- 保留“停止当前”的原本含义，同时提供“停止并暂停后续”；主助手与元素卡都使用既有提交队列，而不是删除后重建消息。
- 暂停状态先持久化，再停止当前任务；已排队消息不丢，新草稿不被覆盖，只有用户明确“继续排队任务”才恢复。外部接管造成的暂停原因不被用户普通暂停覆盖。
- 已验证当前请求停止后零新增启动，再次显式恢复只启动原排队项。与第一批的关闭／发送竞态、同 submissionId 查证和草稿保留共同工作。

### 2.4 UF-05：正常范围续接

- 源文范围和 Flow 段落范围依据正式操作 splice 与历史推进；同任务先前扩写、前面插入不相关人工文字、Save As 或合法路径变更，不再一律按旧范围拒绝。
- 重叠人工改写、删除或来源不明仍拒绝错误定位，不全文搜索另一处相同文字。恢复后仍验证原任务来源，未扩大为整文档写授权。
- CRLF/LF 处理限定在可以唯一匹配的换行映射，保留原文件换行形式，不把多处模糊文本当成可安全替换。

### 2.5 UF-07／UF-08：材料、排队与冷却

- 原件按来源目录进入任务，明确直接发送的图片仍带真实像素；旧 inline 图在消费后进入可回读工作集，不把上传大材料等同于每轮重复发送全部字节。
- PDF／Office 提取按页批次保留进度；界面显示已保留页数并能取消后续提取，再次提取可复用成功批次。既有100页和累计观察图额度修复保留。
- 动态准入并发不足进入公平等待，等待不占执行时限；停止会取消等待，已消费帧不再因累计数量／总量导致重建候选。
- 临时429冷却可在原任务等待，明确停止仍有效；余额不足与暂时限流分开，未知付费副作用不盲目自动重试。作用范围落到具体资源／目标，独立能力不被无关失败冻结。

### 2.6 UF-09：后台预览和恢复入口

- 活动标签状态传入预览 owner。隐藏页停止无关宿主刷新、测量，并暂停可管理的媒体与 CSS/WebAnimations；恢复后继续已有表单内容、页面局部变量与支持的动画。后台 Agent 不因切换标签被停止。
- 没有修改全局 setTimeout/RAF，也没有销毁隐藏 iframe 来假装无损暂停任意脚本。任意页面 JS 定时器仍是明示的生命周期边界。
- “重新加载预览”可以从丢失 frame 内容的状态重新加载正式源码，文档磁盘内容不变。按钮明确告知重新加载会重置页面运行状态；不把它说成无损保留任意互动进度。
- 第一批的混合 HTML 精确源码定位和横向弹层修复保留。

### 2.7 UF-10：PPT 损失、启动与窄窗

- PPT 新建在生成正式课件前显示实际源页、对象种类、未保留／简化原因；取消不生成课件、原 PPT 不变，用户确认后才创建。没有恢复外部转换器或自动静态后备平台。
- 日常源码启动按相关输入和已有构建复用，缺失或过期才重建。锁文件变化时提示 npm ci；安装完成自动识别并重建，不再要求手工删除启动索引。未安装或改动用户依赖来测试此分支。
- 首次／第二实例文件参数走同一待打开入口，字体等待不再把工作台外壳延迟到全部字体加载结束；正确字体度量的依赖继续保留。
- 最小窗口调整为640×480，配合既有自适应面板；本轮真实680×560窗口验证 HTML 保存按钮在屏内且实际命中。不是所有表面和缩放倍率的全矩阵验收。

### 2.8 UF-11：测量后做局部减负

run checkpoint 队列按 run 隔离；诊断计时改为追加记录，旧 v1 文件保持可读和不改写，2200条记录可查回，不再用2048条截掉后半程。仍保留正式文档和必要回执的持久化，不取消fsync来换“快”。

12 MiB纯合成fixture单次测量：克隆8.74ms、序列化10.04ms、解析5.10ms、保存含fsync67.97ms、冷读19.70ms、两份历史列举77.73ms；卡住一份run写入时，另一份小保存19.64ms完成且早于释放阻塞。事件循环最大延迟28.67ms。原始数值见 `local-history-measurement.json`。

这些数字不是课堂生成提速比例，也不证明所有历史开销已消失。全checkpoint与部分历史索引仍有完整对象处理；当前证据不支持为此新建数据库或立即大规模重构。

### 2.9 UF-14：受管会话用户接管

- 使用任务自己的可见受管浏览器，不读取个人浏览器资料。用户接管时，当前任务 Agent 暂停，其他任务不受影响；显示的就是原受管会话，不重建另一份登录状态。
- 接管期间已请求的动作等待，不持续报拒绝诱发模型重试。等待位于操作队列外，避免“恢复控制也在队列后面”的死锁；停止可取消等待。
- 返回任务后重新观察，旧写动作／旧观察不能执行；新的只读观察可继续。cookies保留在受管会话，不通过状态和日志返回模型。
- 本机真实Edge和受控HTTP页面验证了接管、等待、返回、旧批准失效、取消及清理。商业网站、跨来源SSO和真实账号不是本轮验证内容。
