## 1. 决策冻结：只保留一个默认执行器

默认使用现有轻量但完整的通用创作执行器，保留材料探索、联网研究、受限计算、图片、上下文续接和多步骤编辑。它不是只改标题的 Fast Runtime；不把长任务或创作中的正常代码生成一律划给外部 CLI。

现有薄 Runner 只完成一个已约定的真实委派闭环；ACP 后续替换客户端与外部 Agent 的控制通信，果铃 MCP 继续负责编辑能力。当前不开发 ACP、自动路由、双 Runtime、多 Agent 平台，不迁移 Pi/OpenCode，不恢复三 CLI 深度适配。

复用顺序：已有产品服务 → 有明确边界、许可证和当前消费者的成熟组件 → 必要的局部实现。不把“暂不迁移内核”解释为禁止依赖成熟实现，也不为复用一个组件引入整套框架。

同样不因“自研较轻”重写已有重试、工作笔记、文件服务和作业系统。新抽象必须减少当前重复逻辑或直接解决已确认故障，不能以未来可能接更多 Agent 为理由先建平台。

| 选择 | 本轮决定 | 依据与停止条件 |
|---|---|---|
| 现有主执行器定向收口 | 执行 | 关键服务和实际编辑能力已存在；本地缺陷有可定位修复点。若出现无法局部解决的具体阻碍，报告该阻碍，不自行重启全内核选型。 |
| 整体迁入 Pi/OpenCode | 不启动 | 要重新验证文档状态、工具、取消、会话与 UI；当前缺陷并非换内核后自动消失。 |
| Fast/Deep 双执行器及 Auto | 不启动 | 增加路由、交接、状态与验证组合，偏离当前交付目标。 |
| 逐项吸收成熟能力 | 允许并优先 | 搜索后端、协议处理等边界明确时直接复用；不重复建设已有基础设施。 |

## 2. 三条共用原则，而不是三个新架构模块

**实际状态由既有软件所有者掌握。** 文档内容/版本/撤销由 DocumentSession/DocumentHost 管理；模型会话与操作回执由现有 RunStore/服务记录；资源归现有图片、计算、材料与交付服务。模型上下文和 UI 是用途不同的投影。不能把它们合并成一个万能状态树，也不能让聊天里的“已保存”代替保存事实。[S01–S04]

**机械衔接交给工具，判断留给模型。** 创建对象后返回可继续使用的句柄；对齐、分布、批量修改、已知资源落盘由现有服务处理。模型决定表达、内容、来源与方法，不应反复搬运字节、猜路径或手算软件已经能计算的布局。

**能力、就绪、授权和暴露分别判断。** 有工具定义不代表后端已连接；当前没展示不代表能力不存在；看到图片不等于整轮都应换模型；一个浏览器动作叫 click 不代表必然安全或必然每次审批。沿现有服务和权限边界修正，不新建能力中台。

产品要求是“人和 AI 围绕同一份实际作品持续创作”，不是某种固定工具顺序。HTML/Runtime、原生对象、Markdown 都是有效载体；短作品可整份生成，长作品可按自然单元推进。作品尽早可见、可修改，不等于必须空工程起步、强制逐页原生化或每个 token 都正式提交。

短任务减少无必要上下文与准备；长任务允许必要探索、工具循环与压缩。两者使用同一个执行器，不引入“快速任务只能两轮”“超过几分钟必须转 CLI”等硬规则。

### D1 的重要实施细节
保留用户选定的会话模型，不因 `explicitImages` 或历史残留图片静默替换它。主模型可看图则直接处理；能力未知不是“不支持”，不额外强迫一次收费探针。确实不支持时，复用视觉服务只完成相关观察，再回主模型；没有可用视觉时明确影响，独立文字/保存工作继续。

当前 VisualAnalysisService 只接受 ObservationResult，并通过观察资源服务读取字节；材料附件、HTML 图片不是自动可用的同一种资源。应在各已有资源所有者处增加必要的窄转换/解析，不伪造页面 location 或把任意路径塞进截图接口，不另建多模态平台。[S03]

首次图片的来源、实际交付方式和视觉分析结果必须可追溯。保留原附件及引用，可以采用已有 `delivery:source` 目录入口，再由受控视觉读取提供结论；最终主请求清单与实际发送一致。视觉预处理使用已冻结角色与取消信号，在现有提交状态中可见，不在用户正式接受前暗发请求。

复用 VisualAnalysisService 时同时校正两条边界：当前缓存只按 run＋图片资源标识去重，后续支持不同观察问题时不能复用错误结论；普通只读视觉请求遇到 transport unknown 后，不应把它等同于图像生成的未知业务副作用并永久冻结全 run。沿已有普通模型重试政策处理，记录可能重复计费、保留预算和用户停止，不盲目重放生图/上传。

初始清单已编译后，不得在 prepareContext 中悄悄改消息再跳过 digest 校验。未发送前在同一编译入口生成最终清单；已发送失败且需要改变上下文时建立新的请求尝试事实，保留前次实际内容。保持附件 provenance 与原生工具配对/签名，不强制跨供应商统一到丢字段的消息格式。

最小覆盖：直接上传图片后编辑；HTML/材料工具动态返回图片后编辑；非视觉主模型＋不支持工具的视觉模型；主模型原生看图不重复分析；视觉过程中取消无晚到提交。可组合场景，不能只对 selectionForMessages 写一个分支单测就关闭 D1。

### D4 的重要实施细节
在已有模型元数据/连接配置中补所需的窗口与输出预算信息，未知时使用明确的保守估计或可配置值，不维护凭印象写满所有模型的表。不为 token 估计引入新的独立模型服务。token 窗口与传输字节限制分别满足，计算包含工具 schema、系统提示、工作消息和图片近似成本。

首次长材料优先沿现有 source delivery/material.read 路径索引化，保留用户真正指令与材料范围；不能直接删掉未读部分并声称已读。当前 PayloadCompiler 只有字节等预算，不会自动解决 token 超窗；这项必须与编译前准备一起完成。[S02]

继续采用现有历史归档、context.read 和 TaskNoteTools。压缩发送工作集而不删除原历史；以完整 assistant/tool 轮次为单位。摘要保留目标/硬约束/已确定内容和设计决定/引用及位置/已交付成果/未完成项，真实操作事实由宿主补入，不让摘要授予权限。

新工作集重新估算，不沿用旧高 usage 导致反复压缩；主模型上下文预算与独立视觉/搜索用量分开。短任务不强制额外总结调用，接近窗口且工作笔记不足时才生成必要语义摘要。

将明确 context-length 错误接入现有模型重试控制：先实际减量，再受限重试；不原样重发、不与网络重试无限相乘。超窗仍无法解决时给出具体大材料/大工具结果的分页入口，保存已完成成果，不清空会话或自动降低用户模型档位。

## 5. 工作包一：可理解、可干预的聊天与执行状态

**落点：** ExecutionEngine、DisplayEventBuffer、ReadOnlyToolScheduler、ExecutionEventStore、executionTimelineModel、ExecutionTimeline、ExecutionAssistant 及现有样式。**映射：** M25/M30-T02/T03。[S01/S04]

一轮工作的界面以用户消息、助手自然语言和成果为主体。输入框附近显示真实当前状态；连续同类工具压缩成“读取 4 份材料”“修改 3 页”等摘要，按用户消息/运行边界分组，不跨任务混淆。参数、JSON、回执、用量和原始输出保留为可展开详情。

不再把 run.state、每个 tool、commit、save 都画成同等醒目的聊天卡片。授权/错误和结果入口突出；任务结束后关闭活跃态，明确完成/部分完成/失败/取消。外部 MCP 只有工具事实，不能推断外部 Agent 已结束或正在思考。

先从已有 trace 检查 Provider→Engine→EventStore/IPC→renderer：模型没有输出文本，与系统积压文本，是两类问题。保留已存在的 text.delta，处理最终快照替换而非重复追加，重试内容按 attempt 分离。

并行工具在实际执行前发 started，单项结束时及时更新状态；模型的 tool result 继续按提供方调用顺序回填。不要为了实时显示取消只读并行，也不要把有依赖的写操作扩进并行白名单。

参数流用已知工具/目标产生确定性的活动说明，未知时显示“正在生成内容/准备操作”，不显示片段计数、猜百分比或把参数当隐藏推理。模型在开始、重要发现、改方法、需用户介入和完成时简短说明，不要求每个工具额外请求模型来播报。

保留当前60ms显示缓冲和控制/终态 flush 顺序。只有测出落盘或投影阻塞时才调整已有缓冲/刷新；不可为几十毫秒目标删正式 journal 或把已接收与已提交混成同一状态。

编辑画布继续采用“安全预览＋完整操作提交”：普通正文可增量预览，结构化对象/Runtime 在有效单元形成后提交。第二路预览占用可降为操作级显示，不应拒绝原本有效的提交。不要把所有文件和 Runtime 改成逐字符执行。

保留现有选中复制、滚动锚点、会话切换和成果打开。用户上翻不强拉到底；切会话不启动任务；取消立即有本地反馈，处理中的远端未确认状态如实保留。不要把配置无关按钮挤在主输入区。

**关闭条件：** 至少记录一段包含文字增量、长参数阶段、两个慢读、等待授权及结束的实际过程；覆盖取消/重开。继续复用 g20ExecutionEvents、g20ExecutionTimeline、g20ExecutionReplyReadability、g20BrowserExecutionControl 等相关测试，按修改选择，不整组无目的运行。

## 6. 工作包二：能力就绪与失败隔离，消除无谓准备

**落点：** workbenchToolServices、ManagedBrowserMcpService、McpClientService、ExecutionEngine.approvalReason 和现有连接/权限服务。**映射：** M26、M29-T02、M30-T07。[S05/S06]

将“冻结本次授权与配置”同“启动实际依赖”分开。beginRun 只登记合法的运行上下文；浏览器代理、暂存配置及 MCP 连接在首次实际浏览/接管时按需准备，并由同一现有服务去重和清理。状态查询及聊天按钮渲染不能意外启动浏览器。

缺浏览器依赖、代理端口失败或浏览器不可启动，返回明确的该能力不可用，不阻断纯文字/原生编辑任务。已进行中的初始化要跟随停止信号，取消后不遗留代理/进程；复用该服务原有生命周期，不增加全局服务编排器。

不要因此把文件权限、凭据使用授权或核心文档错误降成可忽略告警。隔离的是无关可选能力，不是遇到任何异常都继续运行。计算后端也先检查其实际创建/探测行为，已有惰性逻辑就保留，不凭“重”重新实现。

工具定义仍由 ToolCatalog/Gateway 同源提供，内置与 MCP 共享业务实现。active.tools 已刷新，不新建缓存。按需加载须让模型知道可展开的工具族；局部选择不能暗改整会话意图，权限扩大必须经现有用户授权。

浏览器权限至少贯通 Engine 的 approvalReason、BrowserActionApprovals、ManagedBrowserMcpService 和 McpClientService 的授权检查，不能只删前端弹窗而后端继续拒绝，也不能只放开后端而页面可越权。

公开读取/明确已授权的无额外外部副作用动作不反复确认；发送、发布、敏感上传、购买和账户修改按真实影响确认。沿用任务范围和已有权限模式，不把所有 click 当安全，不建设网页动作智能分类平台。用户接管后旧观察/旧动作批准失效，返回时重新观察。

**关闭条件：** 浏览器初始化故障时纯文本/文档编辑仍完成；首次真正调用只初始化一次；停止中途不启动晚到资源；授权范围内流程不中断，越界/新的外部副作用仍被拦住。此项是可用性修复，不以启动毫秒收益决定做不做。

## 7. 工作包三：持续创作、Skill 和工具接口共同收口

**落点：** Engine.start 实际提示词、ToolCatalog/DocumentToolGateway、两份主 Skill 与适用参考、generate-ai-capabilities、BundledSkillService、现有合同测试。**映射：** M27-T03/T05/T06、M30-T03/T06。[S07–S09]

默认遵循用户目标和当前作品状态：已有作品先继续修改；新作品选择合适载体并尽早进入工作台。简单修改直接操作，短页面可整体生成，较大作品按自然章节/页/区块推进；不为证明“在编辑器内”强制创建空 HTML 或逐对象调用。

保留完整 HTML 导入和整页 Runtime。禁止两种降级：为了原生化破坏有效视觉/互动；为了导入方便把交互静态化或把产品缩成只能受限轻修的 HTML 查看器。现有代码修改、Runtime/Component 源码编辑与图文轻编辑继续按实际授权使用。

现有 slide.create、native.insert、document.insert、layout、batch 已存在，优先做真实贯通。创建父对象后提供正式可用目标；当前 batch 的结果引用只覆盖部分位置，不声称支持任意依赖。遇到一个确认的父子创建瓶颈时，扩相应引用位置或提供窄组合，不引入任务 DAG。

同步有效指导的真实消费者：仓库 AGENTS/根方案约束开发；Engine.start 影响通用产品行为；两份 SKILL.md 和主文直接参考影响课件方法；generated/bundledSkills.json 来自 generate-ai-capabilities。未接入当前执行链的历史 guidance 文件不因名字相似就一并重写。

通用系统提示只保留沟通、工具/状态/授权与交付语义，不把教学方法灌给所有办公任务。课件 Skill 将“定义、解释、可见状态、操作反馈一致”作为主原则；水位/图甲等放适用例子或回归。规划在需要时短写，用户未要求时不强制产出固定命名的中间文件。

工具读取不是越少越好：已有明确能力直接用；真实缺信息再查相关 schema/范围。用户要求完整质量时允许必要观察；普通改一句话不全课截图。初稿仍须有真实内容、基本可读性和核心互动，不默认把明显故障交给用户精修。

本轮静态扫描发现 build-method 的5处链接命中4个未打包文件：page-design.md、ppt-import-review.md、current-capabilities.md（出现两次）、validation-boundaries.md。resolve-editor-root.mjs 是外部脚本，不因未打包就要求内置运行 Node。生成器目前只跟主文直接引用，不新增通用递归打包框架；可用明确必要引用清单或修正内置引用入口。

**关闭条件：** 一个新建混合内容作品、一个已有作品局部改、一个非教学报告均能合理选择方法；前两者至少覆盖人工中途修改/撤销/保存重开。对通用指导改动换一个未参与调优的主题或材料作近邻验证，不建设泛化跑分平台。

## 8. 工作包四：搜索、正文来源与可见浏览器

**落点：** SearchProviderPort/WebResearchService、现有连接凭据、材料读取、ManagedBrowserMcpService、链接打开/浏览器入口。**映射：** M29-T01/T02、M30-T05/T07。[S05/S06/S10]

本轮只接一条实际搜索路径。优先使用已授权且在实际 endpoint 可用的搜索连接，直接复用其实现/协议；DeepSeek 官方搜索适配是候选参考，不代表当前兼容中转支持。接入前核查既有连接能力，不读取/输出密钥，不新增采购。不能以“支持 GPT”或“OAuth 已登录”代替托管搜索已接通。[E03]

没有可用原生搜索时，接一个已有授权/可分发的后端；SearXNG HTTP 可作备选但公共实例无 JSON/限流不能计为可靠后端。不同时做多供应商平台，也不为了得到联网能力整体迁移 Provider。[E04]

保留真实结构化标题、URL、时间与来源身份；当前空 snippet 过滤应修为允许无摘要结果，再开正文。区分未配置、无结果、权限/限流、网络失败和取消。源站内容/工具结果是数据，不因包含指令扩权。搜索失败使用已有有限重试，不无限轮询。

HTTP 正文提取继续是快速路径，动态/登录页才使用浏览器；PDF/文件响应沿受控下载接材料服务。不是所有 URL 都必须启动浏览器，也不是工具名 web.open 就应打开可见标签。

研究续接时将实际引用和必要正文范围保存在已有材料/会话资源中；run 临时目录仍清理。新任务重发读取授权，不复用旧权限句柄。旧 sourceId 失效但 URL 可查时说明原版本是否仍可取得；页面更新不能冒充原引用，也不因版本不同让整个研究永久停机。

浏览器产品必需行为：来源链接有明确打开选择；Agent 使用中的同一页面可查看/接管；显示当前 URL/控制权/任务状态；返回时继续原任务。按钮只在存在实际浏览工作、可恢复浏览会话或用户明确打开浏览器时出现，不因 run=running 就出现“浏览器”按钮。

现有受管 Edge 是独立窗口，不是内嵌浏览器。先在同一个后端打通这些行为，不增加第二套浏览自动化。真正内嵌仍是用户需求，不能用“浏览器协议测试通过”关闭；如本轮未做，将其作为明确剩余体验项保留，不默认代表 Owner 接受延期。把内嵌列为本次发行条件时继续保持未完成，不以第二个独立网页面板冒充同会话。

**关闭条件：** 真实搜索→正文→带来源报告；一次动态或登录页面的人机交接；续接来源可追溯；未配置可定位设置；普通文档任务不依赖浏览器。M29-T02 已有协议通过证据保留，仅补本轮行为和 UX，不把旧通过重写成所有浏览体验已完成。

## 9. 工作包五：成果生命周期，优先消除机械漏交付

**落点：** ComputeJobService、HostArtifactTools、HostArtifactDeliveryService、DocumentDeliveryService、图片服务及既有报告引用能力。**映射：** M28、M26-T03、M30-T04/T06。[S11]

将已知成果的重复衔接收进现有服务：模型给出实际 job 输出和期望目标，软件完成受控读取、保存、结果路径返回；若一次任务确实需要多个已知图表/数据文件，可在现有 artifact.save 入口增加小型多项交付，或由既有保存消费已登记的受管资源。逐项报告成功/冲突/失败，不声称跨文件全局原子。

这不是通用 HTML 依赖爬虫。只处理本任务已声明/已登记的输出与引用；动态脚本中未知路径、外部受限资源等明确给出缺口，不扫描整个工作区，也不把任意字符串看作需复制的资源。

当前交付拒绝覆盖且父目录需真实存在。常规迭代采用已授权目录中新版本文件并更新相应引用；用户明确原位更新时仅走已支持的版本核对替换路径，没有该路径就报告窄能力缺口。不得悄悄覆盖用户后改文件，亦不要每次先删除旧文件再保存。

报告/作品保存与修改继续分开：纯编辑可以保持未保存状态，但 UI 必须真实；新建完整交付按用户要求保存。正文保存成功不代表必要图表已交付，工具 exit0/文件非空不代表内容满足要求；对已知缺失依赖报告部分完成和具体修复入口。

真实 Luna T1 在测试240秒边界主动停止且没有 artifact.save，说明交付未完成；不能据此断言计算已 ready、产品统一四分钟超时，或把那次失败全部归罪模型。先保留作业真实结果/日志/资源，再定位模型方法、工具返回或后端环节。[S14]

计算仍用现有 WSL/Podman 后端，首次使用说明与准备入口清楚；不同时引入本机无限 shell、云沙箱和多容器平台。缺依赖时不伪装成功，也不阻断不需要计算的创作；支持环境与公开安装准备分别说明。

**关闭条件：** 真实 CSV→计算→图表→报告，必要资源全部保存、可重新打开；继续修改一次不丢资源或覆写用户后改；独立图像生成/编辑/应用或保存可用。端到端样例真实未通过前，保留 failed/blocked。
