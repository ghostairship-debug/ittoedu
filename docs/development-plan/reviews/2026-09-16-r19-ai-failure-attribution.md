## 1. 20分钟为什么耗尽

预算是整个任务的绝对期限，包含准备、原生执行、排队输入、检查与提交，子回合不重新计时。当前界面已经显示剩余分钟；本次不是缺少倒计时。

第四次 DeepSeek 的公开事件如下（北京时间）：

| 边界 | 实际时间或耗时 |
|---|---|
| 首条任务提示 | 00:56:11.702 |
| 首次候选预检查通过 | 01:11:38.820；距提示15分27.118秒 |
| 中途补充排队 | 01:05:14.413 |
| 首回合最终输出 | 01:12:46.989 |
| 补充正式消费 | 01:12:47.033；排队7分32.620秒，剩余3分15.840秒 |
| 绝对期限耗尽 | 01:16:02.878；failed、0 committed |

首回合26次公开工具调用：读取16次、修改5次、自测准备/运行2次、候选准备/预检查3次。第二回合5次：读取3次、修改2次，未再次交付。工具次数不等于各阶段墙钟耗时，不能据此推算模型思考耗时。

初始请求同时要求两处跨表面导航、Spatial 默认布局、既有机制保全及实际检查，是复合修复。ROOT 又在运行中发现原验收错误地镜像生成代码，补充了教师稿已有的错误预测实验要求。Claude 在回合边界才消费该输入，剩余时间不足以完成后续重交。

有待处理输入时，现有宿主按合同暂不提交旧候选，并要求模型按更新后的目标重新交付；仅删除候选文件，当时草稿和源码仍可用。任务终态后暂存根已清理。这不是宿主误丢已提交成果，也不能将首轮 `prechecked` 称为本来一定会成功提交。

**判断：任务复合程度、首回合耗时、通道排队语义和ROOT验收安排共同导致失败。此单例不足以证明统一20分钟合理，也不足以决定应延长到多少分钟。** 不通过加大预算或不断重试掩盖问题。

证据：`output/r19-current-teacher-luna/20260915-current-unified/claude-deepseek-repair-2026-09-15T16-55-37-913Z/public-timing-tool-analysis.json`、`run-assessment.json`、`retention/bounded-review-summary.json`；预算合同见[实施合同](../roadmap/1.8/IMPLEMENTATION_CONTRACT.md)，实际消费见 `harness.ts` 的 `consume`。

## 2. 失败应分开归因

| 现象 | 归因与证据边界 | 产品处理方向 |
|---|---|---|
| 反馈暂存被提前清理、跨页提交后原目标观察失败 | 已复现的宿主生命周期问题，已修复并有直接回归及真实消费证据 | 保留对应窄回归；不靠重写课件掩盖 |
| 空组件被准入 | 产品检查不足；已有真实空白反例，空白拒绝及正常绘制分支已验证 | 保留绘制准入；不扩大为任意教学语义判断 |
| 长历史使聊天入口很慢 | 产品重复全量读取；同profile入口51.733秒降至13.365秒 | 定向读取修复已实机闭合 |
| 两轮prechecked后才拒绝静态错误 | 原始日志证实清单options格式与Native工具/Component目标错配均晚到宿主prepare才报错；deferred=[]不表示全部检查已完成 | 优先以免费反例确认能否将同源静态校验前移，减少新回合成本 |
| 学生按钮无法从Slide进入Flow、从Flow进入Spatial | 主要是模型错用API：把locationId传给仅接受Slide sceneId的goToScene；正式顺序推进能力已存在，实际按钮失败已观察 | 消歧能力卡和目标信息，不静默兼容错误标识，也不为该课写特殊跳转 |
| Spatial默认内容出画 | 宿主正确投影了保存的camera；生成结果未使默认镜头覆盖内容。AI原子工具只要求模型填写坐标，缺少直接复用的内容取景入口 | 将现有确定性取景计算接入正式创作能力，降低模型算坐标的负担 |
| 预测错误便禁止验证 | 主要是模型违反教师稿，且模型自测把同一错误逻辑判为通过。代码静态证据明确；此前完整实机错误分支因出画未执行 | 从教师稿独立确定正、反向验收场景，不能拿生成代码推导“正确答案”；归入实际生成质量问题 |
| 最后完整单测的14项超时/清理失败 | 原红轮保留；13项聚焦串行通过，Builder缓存清理复现后修复，最后1项复验通过 | 与模型生成错误分别报告，不称整个原测试轮全绿 |

## 3. 建议的产品改进

### 先纠正开发与验收方式

- 对每个失败先固定“输入—预期行为—实际结果—失败边界”，再选择产品修复、模型限制记录或有限对照；不把样例最终被反复修好当成改进证据。
- 1.9按新增工作台、身份、文件/材料消费、共编、Flow/Word等真实consumer验收。三CLI既有适用证据继续复用，不展开格式×流程×模型矩阵。
- 将当前大样例冻结为诊断证据，保留首次57.4分钟与全部返工。涉及完整整课教学质量和软件内独立QA的工作按[2.0生产闭环](../roadmap/2.0/r20-020-public-authoring.md)定位，不因样例失败无界扩充1.9任务。
- 以后复杂实验先固定全部验收要求，并按自洽结果分阶段提交。现有canonical事务、正式回执和新观察已支持分段，不新建任务平台。

### 导航与取景：减少可确定的模型计算和误选

优先于新增能力，先为上述两类静态错误建立免费的窄反例：manifest复用正式共享schema；目标类型检查只在冻结描述足够可靠时前移。当前live目标resolver属于Renderer Owner，不复制Store或resolver，不为了预检引入整套headless预演。能可靠前移的规则才进入实现；资源闭包、编译、动态行为和live身份仍由正式Owner裁决。

1. **导航消歧。** 在Component能力说明中明确：goToScene仅接受列出的Slide sceneId；Flow/Spatial locationId不可代入；整课相邻位置使用已有顺序推进能力。提供最小跨Surface示例。验证目标是说明与实际支持一致，不宣称一条提示能保证模型遵循。
2. **复用Spatial取景Owner。** 产品已存在 `spatialSessionCameraFittingWorldContent` / `fitSpatialSessionToWorldContent`，不是从零缺少取景算法。当前缺口是AI正式工具仍让模型自行提交数值。可复用该计算，明确内容范围、视口、padding及要更新的home/进入镜头，通过唯一候选事务持久化；不能只改变临时编辑镜头，也不在每次打开时自动改用户布局。先做确定性单例与保存重开/Player验证，再决定是否需要一次真实模型消费。

### 交互正确性与排队输入：明确能力边界

3. **独立行为验收。** 从当前教师稿提取少量真实可操作场景，例如“预测错误→实际验证→看到现象→重试且保留记录”。先使用现有输入与观察能力，不为电路课硬编码规则，不建立任意脚本或万能教学判定器；自动化软件内QA按2.0已有范围推进。静态准入通过仅说明相应工程属性通过。
4. **解释排队后果。** 现有剩余分钟/queued显示可补足：当前通道将在回合结束后处理补充，未提交结果需重新检查，仍使用同一任务剩余时间。无需新增倒计时平台。增加“下一任务处理”、延长预算或跨任务保留未提交源码会改变行为/留存边界，须单独决定，不能偷偷自动续费、延期或重放旧候选。

## 4. 当前停止边界

本轮分析期间不再启动模型修课件，不修改正式课件或手工重建已清理候选。已经验证的产品修复继续有效；尚未实现的建议仍标为建议。现有能力、模型遵循度、样例质量、版本engineering candidate和Owner accepted分别记录，不互相替代。
