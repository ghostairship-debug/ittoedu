## 修复边界

- Codex generation 使用 app-server `turn/start.outputSchema`。候选 envelope 从正式 Schema 派生，适配服务端实际支持的 JSON Schema 子集；step.input 仅在传输中编码为 JSON 字符串，到宿主恢复对象并经过原有 strict 校验。普通对话必须保留纯回复能力，不能被候选约束强制成修改。原生 CLI 的模型循环、认证和会话继续由 CLI 自己拥有。
- OpenCode 使用标准 ACP 文件写入与既有 session staging 通道。仅当前 session/request 的 `candidates/<requestId>/candidate.json` 可写，限制当前阶段、真实路径、大小和最多 8 次同文件写入；不开放任意文件、terminal、MCP 或 live project API。终态后摄取当前文件并清理，非法候选仍交由原 strict 校验与既有一次 repair；取消、迟到和失败不能提交工程。
- profile、请求提示与实际结果通道一致。`stateId: null` 等目标地址字段仍必须完整保留，不用宿主猜测补值或宽松解析掩盖模型错误。
