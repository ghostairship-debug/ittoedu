## 4. UF-01：修改归属与局部撤销

### 事实与入口

A01 已以原方法复现：AI 零写入，用户在任务期间改字，卡片仍显示 AI 修改并无冲突地撤回人工文字。当前做法比较请求开始与结束的全字段快照。

C01 本轮调用原 `revertElement` 方法确认：AI 改过的标题位置被人工重写后，正文另一处若恰好唯一包含 AI 改后文字，撤销会无冲突地修改正文那一处。`ExecutionDesktopService.ts:928–932` 在原位置不匹配时回退到 `uniqueIndex` 全文搜索；`:97–99` 只证明文字唯一，不能证明属于原操作。内存反例中“后来人工改成的新标题\n另一段保留的改后文字”被错误改成“后来人工改成的新标题\n另一段保留的原标题”，返回 applied。这是内容错误，不只是卡片展示不准确。

入口：`src/main/workbench/execution/ExecutionDesktopService.ts:832–948` 的 `recordElementBaseline/recordElementResult/revertElement`；`src/core/drivers/course/elementFields.ts:76–85`；Gateway 正式操作回执和 DocumentSession 历史。

### 最小有效修复

- 以本 submission/run **确实 applied 的 operationId 集合**关联正式历史，在提交点取得本操作的变更范围和前后值。只看 actor=agent 不够，两个 AI 任务也不能互相认领。
- 卡片只保存可派生的局部变更描述／正式操作引用，不为每个请求再持有一份全工程历史。AI 零写入时显示“本次没有应用修改”。
- 对文字范围，沿后续正式 splice 推进位置；对对象按稳定身份和实际修改字段推进。撤销前比较当前对应值，真正重叠修改才冲突；人工调位置不阻止撤销 AI 改字，也不能被一起撤回。
- 原范围被改写、删除或无法沿正式历史定位时，不得回退到全文唯一同文再替换。其他位置即使内容相同也不是原操作目标；仅对冲突范围提供明确处理入口，不强制撤销无关人工编辑。
- 同一卡片多次提交可按实际操作逆序组合成一次用户撤销；逆操作仍由 DocumentSession 一次正式事务提交，并可 redo。仅凭最终内容相等不能证明操作归属。
- 历史不足、目标删除、映射歧义时不猜测；保留其他可编辑功能，说明局部撤销的具体缺口并指向普通历史。Runtime／Component 目前不支持字段级卡片撤销的明示边界不冒充已补齐，也不借此把 Runtime 重写成 Native。

### 针对性验收

在现有元素卡／执行服务测试中覆盖三个参数组：①AI 零写入＋人工改字；②AI 改字＋人工移位／另一 AI 改其他字段；③人工在 AI 提交后改同一字段，并参数化原位置改写／删除、别处唯一同文。前两组不撤回人工内容，第三组明确冲突或不可定位，全文其他位置零修改。再用一条隔离界面链验证卡片 undo/redo 与普通历史顺序一致，无真实模型调用。

### 6.1 回执语义统一

| 真实结果 | 应有结算 |
|---|---|
| 新内容只进入恢复稿，目标文件仍旧 | 未完成交付，列出具体文件和未保存版本 |

- 沿现有 `continuedFrom`、提交身份和原操作回执，计算同一任务仍有效的未保存文件、未决副作用及必需交付缺口；新 run 的空 tools 不能清零这些事实。不复制历史工具列表伪装成本轮调用，不建第二套义务数据库。

### 针对性验收

- UI 的无变化状态可以禁用或幂等保存，但 Main 同样应正确处理重复调用，不能仅靠隐藏按钮修复。认证确实需要重接时给出原因和正式登录入口，不把普通元数据保存展示成隐式登出。

### 针对性验收

复用连接设置与 OAuth 本地确定性测试：①已登录→原样保存／仅改计费→新任务仍取得同一账号有效快照；②账号／endpoint／认证方式改变、撤权及迟到回调不能复活旧凭据；③面板保存后的登录状态、角色选择与可启动性一致。使用假凭据和本地测试服务，不读取真实账号、不为此发起真实登录或生图。

## 14C. UF-14：受管网页的用户登录入口

### 已确认缺口与未验证边界

G01 是能力入口缺口：`src/main/workbench/externalTools/ManagedBrowserMcpService.ts:93–101` 为任务创建新会话并固定 `--headless --isolated`，当前产品没有显示／接管该实际会话供用户登录的入口。系统浏览器已登录不等于此隔离会话已登录。此事实不等于所有网站或所有自动登录流程失败；本轮未测试具体商业站点。

当前 [L06](../../../GPTpro方案/guoling_2_0_execution_plan/long_term/L06.md) 已要求允许用户正常登录，并将 cookie 留在受管会话。本工作包落实既有范围，不新增统一账号平台，也不把网站登录混同于模型 OAuth。

### 补齐边界

- 先核实现有受管浏览器及 MCP 的可见会话／用户接管能力；通过现有 session owner 提供用户打开、正常登录、返回任务继续的入口。必须让用户操作任务实际使用的受管会话，不另开一个不共享会话的系统浏览器后宣称登录完成。
- 登录等待显示具体原因、继续／取消入口；等待期间不循环点击登录、不自动扩大授权、不换账号或替换会话。用户登录后的观察和工具调用继续使用原任务授权及真实页面状态。
- 凭据和 cookie 保留在受管会话，不读取其他浏览器凭据、不写入模型提示词／课件／导出、不绕过验证码。会话结束、取消、重启后的真实保留范围按当前 session owner 明示，不承诺跨任务永久登录。
- 若当前 carrier 不支持同会话接管，记录具体接口缺口并在该 owner 内补齐或替换窄适配；不得用一个永远无法完成的“请先登录”提示代替交付。该缺口不阻塞无登录网页和其他 UF。

### 针对性验收

使用本地受控登录 fixture：未登录任务→显示实际受管会话→由用户入口完成测试登录→回到原任务读取受保护测试页；核对会话一致、取消有效、cookie 未进入模型／制品。真实扫码／SSO 网站的登录可用性另列，缺少可用站点或用户登录条件时保留未验证，不能借本地 fixture 报全部网站通过；不新增采购或索要凭据。
