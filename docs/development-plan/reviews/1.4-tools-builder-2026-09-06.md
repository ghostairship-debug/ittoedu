# 1.4 工具与 Builder 集成复核

当前已完成实现、聚焦验证和桌面集成回归，形成 `v1.4.0-rc.1` 工程候选。S1 的 Owner 签署只覆盖 1.2–1.3，1.4–1.5 已于2026-09-06随 S2 获 Owner 整体签署，范围与已知限制见 [S2验收单](../acceptance/S2-tools-and-materials.md)。以下保留各轮工程验证的历史状态。

## 实际结果

- 正式 Facade 覆盖 Native / Flow 内容、页面 / 状态 / 互动、Spatial 镜头 / 路径 / 关系、课程导航 / 状态 / 守卫 / 播放 / 网络、背景、Recipe、媒体 / 字体、材料引用、Component 插入 / 包替换 / 属性和 Runtime 插入 / 源码 / 字段。update 保留完整 canonical target，create 使用独立 scope；一次调用只形成一个资源历史事务。
- 跨 Surface 导航规划属于 composition 用例层，Store 根只接窄端口。动态候选没有调用方可替换的宿主或成功标记；包替换检查真实引用及命名状态。故障、capture deadline 和迟到结果不写工程或 registry。
- 隐藏、停用和相机之外的实例在私有投影中验证，提交保持原布局 / 状态。Spatial Component 用实际 DOM 挂载和产品捕获屏障验证；其对外交付的相机页仍是静态。Spatial world Runtime 尚无正式动态宿主，动态插入明确拒绝。关闭既有故障 Runtime 可以直接执行和撤销，不要求故障代码重新运行。
- 工程字体合同经 Owner 单独批准。Published 资源闭包包含直接字体引用；停用 Runtime 的已序列化素材绑定和后备仍须携带，停用代码的非执行引用不强行进入发布资源。
- Builder 模块声明 `apiVersion = 2`，调用 `api.createCourseProject()`；产品管理 Chromium 工作会话，所有写入走同一工具，最终只接受已登记的 `finish()` 结果。V1 保持兼容并提示迁移，没有第二命令实现。
- 低信息固定课例使用两份确认后的 Markdown，经 14 个工具事务生成三 Surface、动态组件、Native 反馈、Flow 表格和 Spatial 路径 / 关系 / 相机；真实 CLI、archive 重开及离线 HTML 连续操作通过。该证据不声称执行过其他弱模型或得到 S2 教师签署。
