## A. 必验（3 步，约 3 分钟）

1. **普通中文输入**
   - 在聊天输入框用拼音打一段中文（含选字），如「平均分是分数的前提」。
   - 判据：候选框正常出现；选字后文本正确进入输入框；无丢字、无重复、无错位。
   - *为什么必验*：输入框是 React 受控组件（`value={instruction} onChange={setInstruction}`，`LessonConversationChat.tsx:195`、`CourseChatPanel.tsx:476`）。「受控输入框 + IME」是已知易错组合——组合期间把 value 写回 DOM 可能打断输入法。**这条读代码判断不了，只能真人打字。**
2. **组合中输入回车（关键）**
   - 打 `pingjunfen`（拼音尚未选字、候选框开着）时按 **Enter**。
   - 判据：Enter 交由系统输入法处理（会按输入法设置选字或提交当前拼音），**不得**触发「发送」或接受 `/`、`@` 菜单；输入框内容不得被提交为聊天消息。
   - *为什么必验*：**2026-09-19 的 P2-4 改动给 Enter 赋予了新语义**——`/` 或 `@` 候选菜单打开时，Enter 表示「接受当前候选项」（`ChatComposerMenus.tsx` 的 `handleKeyDown`）。代码里已加组合守卫（`event.nativeEvent.isComposing || event.keyCode === 229` 时不消费按键，单测 `chatComposerMenus.test.tsx` 覆盖），但**模拟事件不等于真输入法**，需真人确认。
   - 补充一次：先打 `/` 让命令菜单弹出，再用拼音打字并在候选框开着时按 Enter。判据：选字正常，**不得**选中任何菜单项。
3. **发送后清空**
   - 正常发送一条中文消息 → 判据：消息出现在记录中，输入框清空，无残留组合态。

## B. 已由代码排除（无需逐条执行；若 A 中偶遇异常仍请记录）

| 原步骤 | 判据 | 排除依据 |
|---|---|---|
| 3 组合中输入斜杠 | 打拼音时输入 `/` 不得弹命令菜单 | 命令触发条件已收紧为 `^\/([^\s/]*)$`（`ChatComposerMenus.tsx`）：要求**整串**以 `/` 开头且不含空格与第二个 `/`。先打拼音再打斜杠得到的 `zf/` 不匹配，不弹。单测 `chatComposerMenus.test.tsx`「keeps POSIX absolute paths out of the command menu」覆盖同一规则 |
| 4 组合中空格/数字选字 | 选字正确，不触发快捷键 | 菜单只消费 `ArrowUp`/`ArrowDown`/`Enter`/`Tab`/`Escape` 五个键，**空格与数字键不在其中**，不会被拦截；且组合期间五个键也一律不消费 |
| 5 @ 输入 | 全角＠或组合中的 @ 不得误弹菜单 | `@` 触发条件 `(?:^|\s)@([^\s]*)$` 要求 `@` 前是行首或空白：全角「＠」(U+FF20) 不匹配半角 `@`；拼音串后的 `zf@` 因 `@` 前是字母也不匹配。半角 `@` 在行首或空格后弹出引用菜单是设计行为 |
