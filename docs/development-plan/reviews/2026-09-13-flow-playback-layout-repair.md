# Flow 产品布局与播放视口修复记录

2026-09-13。状态：产品修复及聚焦验证完成，形成 engineering candidate。只修改产品和验证代码，没有修改旧课件。本记录不等于 Owner S3 或发布签署。

## 结果与原因

旧样本缺少 widthMode 时读取为 reading，是既有兼容行为；本轮保证新内容经正式创建入口使用 fluid，并使工具、观察和渲染消费一致。反复出现差异的原因是多个边界没有一起验证：正文与视口浮层的坐标含义、固定控制器 frame 与响应式 Flow 的关系、常驻边条占位，以及实际新内容经过生成与导出后的结果。

| 产品变更 | 保证的结果 |
|---|---|
| Native Flow 浮层增加 strict paperSpace 输入，使用既有 canonical patch | 正式 AI 工具可表达稿纸/视口定位；正文占位仍走 flow.content。非 Flow/教师控制器拒绝该参数，失败零提交 |
| snapshot 提供解析后的 layout，观察提供实际视口/正文尺寸 | 生成器能区分正文、稿纸和视口，不依赖截图猜坐标 |
| 同一 Flow 的目录锚点按 Surface 去重，并保留冻结活动锚点 | 新增小标题后的观察不会把同一讲义重复算作新页面；原授权拦截继续有效 |
| Flow 控制器底部居中，12 CSS px间距，窄窗重排按钮 | 作者 frame 的 x/y 不再直接指定 Flow 初始播放落点；作者尺寸上限/样式保留；自动纠偏不污染手动偏移 |
| PlaybackViewSession 逐轴派生浮动边条和安全区域 | 零范围隐藏并退出焦点/无障碍操作；无18 px常驻空槽；缩放不重排正文，原生滚动条与平移条命中带独立 |
| paper 浮层从整课 bounds 中排除 | 正文滚动不触发多余整课平移条和控制器漂移 |
| 共享 Flow 字体链与既有导出字体收集 Owner 接通 | 新 HTML 携带实际使用的 Noto Sans SC，避免依赖查看设备字体；已确认浏览器正文和组件实际使用内嵌字体 |
| 现有排序组件明确按钮文字颜色 | 编辑器全局按钮样式不会把组件按钮变成白底白字 |

无新工程 Schema 分支，无第二 Store/History，无观察状态写回工程；Slide/Spatial 的基础 fit 与控制器投影保留。
