# 教师控制台组件化与课件内深度定制方案

日期：2026-09-14。状态：组件化工程实现与聚焦验证已落地；真实 Luna 经反馈修复完成自动提交、保存重开及定制控件验证，教师美术验收未完成。详见 reviews/2026-09-14-teacher-controller-component.md；不改变版本验收状态。

## 1. 目标与已确认决定

将教师控制台改为内置提供、完整源码和素材随工程保存的组件。每份课件拥有自己的实现，AI 可修改布局、代码、图片、纹理、动画及操作组合，保存重开和导出后仍保留，不受编辑器默认组件升级覆盖。

定制范围包括去掉固定面板底板、透明或非矩形外观、分散的按钮区域，以及让按钮成为背景中的书签、卷轴、仪表或装饰物。它不是只开放颜色和圆角的皮肤系统。

宿主继续管理导航、播放与观察状态。组件负责界面呈现和输入；不复制导航序列、Store、History 或课程 Session，不创建教师控制台专用的第二套源码打包机制。

相关产品取舍：原生保留高频、直接、稳定的编辑能力；复杂视觉和局部交互优先使用组件，连续机制使用 Runtime。原生只按真实高频收益补强，不以穷举图形和效果参数为目标。本方案只实施教师控制台纵切，不顺带改写全部原生能力路线。

## 3. 最终结构

### 3.1 默认组件与工程副本

内置默认包采用现有 Component API 4 和组件资源体系。新工程通过正式工厂嵌入包、素材和一个全局控制台实例。Builder 与 UI 使用同一工厂。

工程保存完整包，不只保存外部目录地址或默认版本号。编辑器升级不自动覆盖工程源码；恢复默认也是可撤销的显式编辑。相同组件包被其他工程引用时，本工程修改不产生跨工程写入。

常用文案、颜色、素材选择和显示选项通过组件参数编辑；布局、结构和行为修改走源码编辑。不得以参数面板不足为由限制 AI 修改源码，也不得每次小修改都重生成整个包。

### 3.2 控制台身份

推荐在现有组件实例上增加窄的可选语义角色，用于声明教师控制台身份，不增加新的 Native discriminator，也不以包名、按钮标签或 DOM 特征识别角色。具体字段名在独立合同变更中固定。

角色只允许出现在全局 Overlay，并受唯一实例约束；它标识正式控制台能力，不是组件作者自报即可得到任意宿主权限。角色、组件包及其引用通过同一 canonical 事务提交。

新增字段属于 V9/Published V2 合同扩展：独立合同提交，双方 strict schema 同步；旧 V9 继续可读，旧 reader 遇到新增数据须明确失败，不得静默丢失角色。若现有字段足以无歧义承载，应优先复用，但必须在合同阶段给出解析与直接 consumer 证据，不能私藏在任意 props 中绕过身份合同。

### 3.3 宿主接口

沿用现有组件宿主接口方式增加可选、受生命周期约束的教师控制台端口，不开放 raw Store、任意宿主 DOM 或 Electron 接口。

| 能力 | 要求 |
|---|---|
| 当前场景、步骤、目录、边界与变化订阅 | 消费唯一导航 Owner；快照只读，销毁取消订阅 |
| 步骤、场景、精确跳转、重播、重启 | 复用正式动作；返回真实接受/拒绝及必要反馈 |
| 教师临时越过导航守卫 | 与普通课程推进明确区分，仅正式控制台端口保留现有教师权限 |
| 静音、全屏、目录选择 | 补齐现有控制台动作，状态变化可被组件观察 |
| 观察缩放、平移与恢复 | 消费既有 playback view Owner，不复制倍率、pan 或相机状态 |
| 折叠、运行时拖动、跨场景状态 | 延续宿主 Session 语义及独立定位，不写回作者工程 |

实现前核对现有所有控制台动作及自动注入控件，逐一映射到默认组件，禁止遗漏缩放、恢复等非持久按钮。普通组件现有 actions 语义不变，不因控制台需求让所有导航绕过守卫。

## 4. 深度定制与背景融合

### 4.1 素材与外观

组件可使用包内图片、纹理及正式工程素材引用。AI 替换素材与修改引用一起进入资源事务，维持素材闭包和离线可用性。背景底板可以完全透明；内部可以由多个独立区域构成，不要求绘制矩形面板。

按钮装饰、纹理与真实交互区域由独立控制台组件一起呈现，验证可点击反馈和文字可读性。视觉融合不要求把按钮烘焙进课件背景图，也不绑定背景坐标。动画使用组件生命周期及捕获机制；静态后备不是交互验收。

### 4.2 统一独立定位

无论采用独立工具条还是背景融合外观，控制台均保持独立的视口定位。课件缩放、平移、内容重定位、Flow 正文滚动及 Spatial 镜头移动，不改变控制台的位置和尺寸。背景融合只表示视觉风格与构图融合，不表示绑定背景的坐标或变换。

沿用控制台既有的独立定位和 Session 拖动语义；教师主动拖动可以改变位置，窗口 resize 或全屏切换按控制台自身响应式布局保持可达。这些变化不由课件内容的变换驱动。

不增加“浮动/画面融合”两套定位模式，不新增背景坐标绑定、世界投影或课件变换上下文。保持全局 Overlay 单份身份，透明底板和分散控件仍由这一独立组件实现，不复制到每个 Surface，也不开放全局与本地任意逐项混排。

### 4.3 跨场景配置与命中

保持一个全局组件身份，允许工程内 props/源码根据稳定场景或 Surface 身份选择外观和布局。删除、复制及重建场景时，相关引用需经过已有引用清理 Owner；失配回到默认布局，不产生隐形但仍可点击的热点。

透明区域不阻挡课件输入，只有真实控件接收指针。多个分散按钮必须支持键盘焦点、可理解标签及合理点击范围。全屏、窗口 resize、Flow 滚动和 Spatial 镜头移动之后，视觉区域与命中区域保持一致。

## 5. 故障恢复与生命周期

正常运行只有一个控制台界面。组件编译或准入失败不替换当前可用版本。按 Owner 2026-09-14 的明确决定，源码恢复只放在全局属性的“教师控制台 → 控制台维护”折叠区；恢复通过原有可撤销文档/资源事务执行。

试运行、Player 和离线 HTML 不注入恢复按钮、不提供隐式恢复快捷键、不临时替换为默认控制台。异常继续走组件诊断；需要维护时回到编辑器属性处理。视觉和交互检查应观察实际效果，不能按 DOM 中是否存在 button 猜测定制控制台有效性。

作者态不触发导航、播放或教师越过动作。跨场景切换及重新挂载必须保留规定的折叠等状态并清理旧事件；重启和重播分别沿用现有状态重置语义。组件不得修改宿主 Session 的内部存储。

## 6. AI 编辑闭环

观察结果应同时提供控制台角色、组件实例和包源码目标、当前素材、场景布局配置，以及相关宿主能力的正式说明。对“融入当前背景”任务提供背景素材与当前画面作为视觉参考，并明确控制台保持独立定位；不得只给颜色参数卡，也不要求背景变换信息。

工具路径复用 component.configure / component.package / 素材导入和既有 canonical transaction。布局、背景素材和控制台源码的联合修改必须以一个可回滚逻辑编辑提交；不允许先写正式背景、再等待可能失败的组件候选。

AI 修改后核对具体请求：只改颜色不能算“融入背景”完成；真实点击不能被源码存在或 screenshot 替代。提交后再区分静态呈现通过、动态通过及教师接受。失败或迟到候选零工程写入。

正式能力索引、编辑器入口及相关 Skill 随实现一起更新，允许对控制台源码深度编辑；继续保护其全局身份和唯一性。原先普通替换禁止绕过控制台身份的边界不能通过删除检查来解除，需提供正式角色迁移/更新命令。

## 7. 旧工程与导出

旧 Native 控制台保持可读及原功能可用。首次转换通过显式、可撤销的工程编辑完成，不在打开文件时静默迁移。映射标题、按钮 ID/动作/显隐、样式、位置、折叠、可见范围和静态导出选项；验证无法等价映射时保留旧控制台并说明具体项。

转换须在一次事务内嵌入组件包、替换原实例并修复引用，尽量保留稳定图层身份；同一工程不得同时激活旧 Native 与新组件控制台。Undo/Redo 同时恢复节点、源码与素材。

2026-09-15 Owner 更新：产品尚未生产，无旧工程兼容需要；删除旧 Native reader/renderer、discriminator、专用布局/编辑器和转换入口。默认工厂直接创建组件，属性管理统一消费组件参数。

Preview、Player、HTML/Web 读取工程保存的同一组件包和素材。静态导出遵守原 includeInStaticExports 选择，使用组件正式捕获机制；原 Flow 页脚特例要在 exporter 中按控制台角色承接，不因 carrier 改变丢失。必须分别验证不包含和包含控制台的静态结果，不把动态功能描述为静态格式能力。

## 8. 开发批次与停止条件

本方案不创建任务卡、不分配版本验收状态。实施启动时按最新源码和工作协议确定实际写域；批次是依赖顺序，不表示已开工。

| 批次 | 交付 | 直接验收与涉及边界 |
|---|---|---|
| A：合同与消费边界 | 固定组件角色、布局上下文、教师端口、旧数据兼容及 Published 投影；更新冲突合同 | strict 解析、旧 V9 可读、新数据旧 reader 明确失败；完整动作映射；不增加第二状态 Owner |
| B：默认组件纵切 | 默认包入工程、全局角色挂载、原生到组件显式转换、作者入口和恢复路径 | 一份旧工程转换后保存重开/撤销重做；普通导航与教师越过区别；默认控制台各动作真实运行 |
| C：视觉融合 | 素材、透明分散控件、独立定位与场景外观配置 | Slide/Flow/Spatial 各一代表夹具；课件缩放/平移/滚动/镜头变化时控制台位置尺寸不变且点击有效；resize 后可达；空白区域穿透；故障可恢复 |
| D：AI 与交付汇合 | AI 源码观察/修改、资源事务、Preview/HTML/静态导出及能力文档 | 真实 Luna 改纹理并重做布局、融合背景后保存重开；同一结果在实际导出中呈现及运行；教师视觉验收 |

目标源码域：shared contracts 与控制台一致性/引用；player 组件宿主、导航与观察适配；renderer 工厂、组件资源事务、属性/代码入口、Published/export；能力发现及目标测试。组合根只接线，不把新控制台业务塞进 Store 或 App。

本轮不预设新文件 API 的完整名称。A 批次必须形成可实现的窄合同并列清各 consumer 后再进入 B；复用既有控制台独立定位规则，不为视觉融合增加 Surface 背景投影机制。

## 9. 验收样例与证据口径

1. 默认等价：旧控制台转换后原按钮、位置和行为保留；两份工程修改互不影响。
2. 纹理定制：将普通面板改为带真实纸张/木纹素材的专属控制台；文件中有完整资源，离线重开仍显示。
3. 背景融合：去掉面板，以与背景协调的纹理和构图安排三个分散控件；分别触发下一步、目录和重播；课件缩放、平移或重定位后控制台位置尺寸不变、命中准确，其他背景区域可操作。
4. 场景适配：同一组件在不同场景采用不同外观；Flow 滚动与 Spatial 镜头移动不带动控制台；返回场景后外观及独立布局正确恢复。
5. 状态与恢复：折叠、切场、缩放及重播不重复创建控制器；故障、不可达和取消候选都有明确且可用的恢复结果。
6. 交付一致：当前试运行、整课播放、离线 HTML 使用保存的实现；适用静态导出的包含开关与后备画面正确。

按批次从最低成本的失败证据开始：合同用解析；事务用副本保存往返；视觉与点击用真实宿主；不以文件存在、hash、空候选或零匹配测试代替行为。有效结果仅在相关实现变化时补跑。

真实模型只使用已确认路由的 Luna；未确认路由或能力不足时先做无模型验证并说明缺口，不自行换模型。用户已授权 Luna 付费测试、自主重跑并默认 Fast，具体规则见 AGENTS.md。记录首次候选效果、修复续跑、速度、最终正确性，不能把工程通过称为教师接受。

## 10. 主要实施风险

- 用户可见：控制台错误继承课件变换导致位置或尺寸变化；透明整屏容器阻挡课件；转换丢失原动作；异常后无法恢复。优先用实际命中、迁移副本和故障验证解决。
- 兼容与持久化：组件角色及源码/素材未成对保存；静态导出遗漏原规则。必须由统一事务和匹配 producer/consumer 闭合。
- 开发维护：原生和组件各自维护一套导航、观察状态或默认按钮规则。宿主能力唯一，默认界面组件化，兼容路径仅承接旧数据。

实施事实：role 合同、内嵌默认包、原位可撤销转换、三 Surface 独立挂载、源码恢复、AI 工具发现与静态导出规则已实现。真实窗口验证包含缩放/平移、Flow 滚动、Spatial 镜头切换、源码属性刷新、离线 HTML、Flow 页脚图面。首次 Luna 超时后继续修复了文件候选转换不一致；后续普通速度任务完成自动提交，两次 Fast 反馈修复完成目录越界与纸纹问题。最终保存重开、实际按钮操作和独立定位验证通过，宿主恢复误报也已修复。首轮失败与后续修复分别记录，美术质量及教师接受仍独立。
