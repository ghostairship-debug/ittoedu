## 3. 修复循环中新发现并关闭的问题

### 3.1 属性输入没有完整等待正式 ACK

首次接通嵌套文字属性后，继续检查异步拒绝路径发现：上层回调没有完整返回格式命令 Promise，输入控件可能在正式写入未结束时认为操作完成。修复贯穿 `formatTextStyle`、`patchSelectedBlock`、字号／行距等回调，错误和 ACK 返回到原有草稿管理链。

这项修复保留用户尚未提交的 raw 输入，不使用重载文档或丢弃整个投影作为恢复手段。晚到的旧 ACK 不能把新输入标为已保存；切换对象、文字范围以及卸载重挂后，状态仍按原字段归属处理。[E01、E04]

### 3.2 已拒绝／结果未知的输入缺少精确恢复入口

继续探查发现，投影有意保留失败提案，但旧路径不能完成安全的显式重试和取消。仅在 UI 隐藏错误或立即回滚都会与正式 Session／History 冲突。

本次在 `DocumentProjection`、`CourseV10DocumentBridge` 和既有属性输入 registry 上接入临时运行期恢复能力，返回 `ready`／`applied`／`pending`。主要保证如下：

- 已确认拒绝，只释放该输入对应的精确提案；不影响别的字段或其他在途操作。
- 结果未知，先查原 operationId；未取得确定结果前不重放，不把已提交但 ACK 丢失误作新操作。
- 若原操作其实成功，只结算一次，不生成第二次写入或额外 History。
- 明确重试仍重新验证文档 epoch、目标、字段、范围和正式值；别的 pending／composition 不会被顺带恢复。
- 已在队列中但尚未发送的操作拥有自己的精确句柄；Bridge 在前序已知失败时阻止新操作进入“幽灵队列”。

控件中的 Enter、明确字体选择、失败后继续编辑并失焦或 Esc 才触发对应动作；自动 flush、重新连接和重挂不会自动重放。未知结果继续保留输入及错误。恢复能力只存在于运行期，不写入工程格式。[E01、E04]

### 3.3 真实 GUI：图层对象选择残留旧文字范围

生产界面复核时，从图层选中嵌套标题、修改字号，出现“文字范围已切换，请重新选择”，正式 revision 仍为 179。侧栏表现为整块属性，但旧 Flow 文字范围仍参与格式命令的防过期判断。这是实际产品失败，不是测试桩推测。

根因位于最终覆盖旧 surface 入口的 `crossSurfaceCommands.selectNode/selectNodes`。修复在显式对象选择时清除过期瞬态文字范围；真正的 PM 文字范围选择仍保留其作用域和过期保护。相同 GUI 流程随后通过，字号只改目标，撤销／重做、保存与新进程冷开全部一致。[E03、E05]

### 3.4 复核中同时纠正的测试与探针问题

为避免把测试故障包装成产品修复，本轮保留了原始失败记录并单独分类：

- 老 `f1FlowAuthoringAck` 测试使用已经失效的 course view／owner 桩，3 个用例在到达目标行为前失败。改用当前真实 `createV10StoreHost` 和 `ComponentNavigationOwner`，仅替换 DOM 渲染边界；保留 ACK 延迟、拒绝、正式写入与 History 验证，4 项通过。
- 新的旧范围测试首轮 fixture 缺少 `wideContentWidth`，不能算有效产品 red。产品 red 来自上述真实 GUI，修正 fixture 后 2 项通过。
- “旧 ACK 完成后又提交新 raw”用例原来误期待两条 Undo 记录。诊断证明两次 operationId 不同、正式 revision 增加 2、最终字号 42、没有错误；两次均使用既有 `flow-property-format` 分组，所以合并为一个 Undo 条目。最终测试要求两次正式操作、只有一个历史条目、一次 Undo 精确回原值、一次 Redo 精确回 42，并保留全部未保存 raw／ready 断言。没有为该例更改产品逻辑。
- 首次导出 UI 探针的“字号”选择器命中两个字段；修正为目标属性区域。离线手机探针曾因截图后的滚动位置让固定目录覆盖点击坐标，实际点到第七章；通过点击命中诊断修正滚动位置后，返回按钮正常。失败证据与后续验证均保留。

## 8. 大 HTML 性能：具体改善与保留成本

使用完全相同的 **25,709,739 字节**样本、同一套未失焦 Ctrl+S 脚本、隔离工作副本和全新 profile 做修前／修后对照。两次均完成输入仍聚焦时保存、正式 Undo／Redo，以及新进程冷开内容核验，无页面错误。[E09、E10]
