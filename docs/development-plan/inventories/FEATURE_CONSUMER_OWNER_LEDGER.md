## Evidence and counting rules

- Evidence uses an exact repository-relative path plus a top-level symbol, exported function, class, Store field/action, package script, or named test file.
- `existing/preserve` means the cited current path exists and must not be rebuilt by stabilization work. `partial` means an implemented path and a cited gap coexist. `legacy-consumer` means the cited current consumer still reads a Legacy carrier. `missing` means the cited current entry explicitly reports absence and the expected package scripts/paths do not exist.
- Runtime/preview/export and build/fixture/release are separate consumer categories. An empty category is not deletion proof; deletion evidence lives only in `legacy-consumers.json`.
- Reproduce symbol relations with `git grep -n -I -F -- '<symbol>' -- 'src/**' 'scripts/**' 'tests/**' 'examples/**'`.
- Starting Legacy record and consumer-relation counts are machine-readable and reproducible from `docs/development-plan/inventories/legacy-consumers.json`; this Markdown does not duplicate those counts.
