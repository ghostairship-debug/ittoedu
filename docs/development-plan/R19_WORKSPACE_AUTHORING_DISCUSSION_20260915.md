## 4. 大工作空间与课例文件夹

### 4.1 两层含义

**大工作空间**是教师打开的真实目录，承载自由组织的原始资料和多个课例。可以按学科、学年、单元组织，也可以保持教师既有的混杂结构。

**课例文件夹**是一次具体课例创作的归属，集中保存其整理后的材料、教学文档、课件及导出成果。课例可以包含多个课时；这不等于把整个大工作空间限定为一份课件。

下列目录用于说明关系，不是已经确定的强制命名或层级合同：

```text
我的备课资料/                        ← 大工作空间
├─ 教材与课程标准/
├─ 网上收集的资料/
├─ 备课随记.docx
└─ 八年级物理/
   ├─ 串并联电路/                    ← 独立课例
   │  ├─ 材料/
   │  │  ├─ 材料索引.md
   │  │  ├─ 教材内容.md
   │  │  ├─ 教案要求.md
   │  │  ├─ 例题与练习.md
   │  │  └─ 图示/
   │  ├─ 01-teaching-plan.md
   │  ├─ 02-presentation-script.md
   │  ├─ 串并联电路.h5lesson
   │  └─ 导出/
   └─ 浮力/                          ← 另一个独立课例
```

### 4.2 讨论形成的建议行为，细节待定

| 操作 | 当前建议 | 仍需细化 |
|---|---|---|
| 打开工作空间 | 选择真实目录，呈现原有文件和课例 | 如何识别既有课例、最近记录与多工作空间切换 |
| 新建课例 | **已确认：创建前确定名称和存放位置，填写或采用建议名后创建真实课例文件夹** | 默认位置、建议名来源、重名处理、已有目录的采用方式 |
| 打开课例 | 恢复该课例的会话、阶段和相关文档/课件 | 恢复页签、当前稿、未完成任务的具体交互 |
| 修改名称 | 明确区分显示名称和磁盘文件夹名称 | 是否联动改名及引用更新 |
| 移动课例 | 按同一课例迁移处理，重新关联路径与资料 | 同机移动、跨工作空间、外部手动移动如何识别 |
| 复制课例 | 形成独立课例，选定的文档和成果随之复制 | 是否复制阶段记录、确认状态，以及与课件另存为的区别 |
| 单独打开/另存 `.h5lesson` | 保留现有可编辑课件文件能力 | 与课例文件夹及配套教学文档如何关联 |

以上不等于改名、移动和复制的全部语义已批准。特别是“复制整个课例”“课件文件另存为”“移动同一课例”必须分别定义。

## 5. 课例材料：独立整理与实际读取

### 5.1 已确定的策略

共享目录只提供原始输入。课例实际使用的内容经过提取，在课例内部独立落盘，后续创作不依赖原始资料的原位置或持续不变。

材料可以来自工作空间中的已有文件，也可以由教师从外部加入。软件负责读取、提取和组织，不能要求教师先在外部把 PDF/DOCX/PPTX 转成文本。目录里存在文件或选择了附件，都不能直接视为成功读取。

Owner 指出，整理后的文字文档通常只有 KB 级，磁盘占用不是保留必要内容的主要顾虑。必要图示按实际教学用途保留，不把“小文档”误解为所有资料都必须纯文本化或压成很短的摘要。

### 5.2 当前建议的组织方式

- **Markdown 正文**：按章节保存本课需要的定义、讲解、例题、公式、表格与相关上下文，便于教师阅读和 AI 定位。
- **材料索引**：说明各文档包含什么、对应教学范围及出处；是否增加结构化索引文件待实现设计。
- **必要图示**：保留实际教材图、实验图、扫描页等，与正文建立明确关联。
- **出处与缺口**：记录来源文件、页码/章节、读取范围和材料版本；无法可靠识别的图文、公式必须显示缺口。
- **摘要与依据**：摘要帮助快速理解，详细原文片段与必要原图支持深入读取和核验，不能只剩 AI 改写后的概述。

整理结果也应能够在右侧查看、修正，并明确哪些内容被本课采用。初次提取、教师修订、AI 摘要与后续更新的关系尚需设计。

当前建议是：源文件后续变化不自动覆盖课例已采用材料；教师主动更新时重新整理并说明变化。更新后哪些策划/脚本需要重新核对，仍需具体交互设计。

### 5.3 本版材料验收继续保留

PDF、DOCX、PPTX 三类分别在软件中完成实际读取与创作消费。核对整体结构、本课所需正文、必要表格/公式/图示和来源。关键内容读取失败应明确说明，不能依靠虚构或未说明的推测绕过材料条件。

自动创作仍须有明确采用且成功读取的课程材料。工作空间中选入文件的路径，需要与现有上传/已读条件统一接线；不能机械要求教师重复导入同一材料，也不能把“目录可访问”当作“材料已读”。

## 6. 文档驱动与教师/AI 共编

### 6.1 持续保留完整教学文档

继续沿用现行核心文档：

- `01-teaching-plan.md`：完整教学策划。
- `02-presentation-script.md`：完整呈现脚本。

教学简报和呈现简报用于补全需求和形成阶段决策，完整策划与脚本支持教师详细审阅、AI 实际生成及结果核验。简报不能替代两份正文；聊天摘要不能成为唯一依据。

问答中形成的重要约束，也应进入对应文档或持久阶段记录。已有文件并不自动保证 AI 会使用它们，压缩上下文、恢复任务或切换 CLI 后需要明确重新读取当前文件。

### 6.2 软件内呈现与共编

文档生成后自动在右侧打开，显示的是课例文件夹中的真实文件。教师能够直接改全文，或选择具体段落交给 AI 共改；后续生成消费这份当前文档。

讨论中提出的必要行为包括：

1. 编辑可靠落盘，并显示保存状态。
2. AI 修改以当前版本为依据，保留教师最新手动修改。
3. 阶段确认绑定教师实际审阅的当前稿。
4. 已确认内容发生变化后，明确哪些后续阶段或课件部分受影响。
5. 生成后对照脚本与实际课件核验，记录缺项和偏差。

同日接续讨论已确认：**教师明确要求 AI 改稿后，默认直接更新文档，标出改动，并支持撤回**，不默认增加一次“采用修改”的确认；教学策划和呈现脚本的阶段确认仍保留。自动保存的触发、改动标记与对比的具体呈现、撤回与教师后续编辑的关系、共同编辑冲突、版本查看和确认失效的粒度尚未定稿。

### 6.3 自动/手动沿用既定方向

手动流程继续按以下顺序推进，每个阶段都在同一工作台内完成：

**教学简报确认 → 教学策划确认 → 呈现简报确认 → 呈现脚本确认 → 构建与检查。**

自动流程基于成功读取的材料，复用完整教学、呈现、构建和检查能力推进，在关键缺失或冲突时向教师提问；不强制每份文档逐一批准。默认采用哪种推进方式、模式选择的具体入口尚未决定。

普通局部改字、换图或改色继续走直接编辑，不重新经过整课策划流程。研发先贯通手动流程、再复用其能力实现自动流程，是此前提出的交付顺序建议，不代表已经启动这些任务。

## 7. CLI 接续与项目状态

已确认的目标是：不同 CLI 能在同一个课例中继续工作，材料与教学文档不会因为切换而丢失。

当前建议：进入课例后，以课例目录作为 CLI 当前工作目录；按任务需要仍可访问大工作空间内的共享材料。整理后的材料和生成文档写入本课例，CLI 原生工具与授权边界继续保留。

共同文件之外，还需要可持久恢复的任务目标、重要约束、当前阶段、确认版本、已完成结果与待办。索引帮助定位真实文档和工程事实，不复制另一份课件内容真相。

**文件持续存在与原生会话连续是两件事。** 新 CLI 重新读取课例资料接续，不承诺不同 CLI 原生对话或内部上下文天然互通。切换、恢复前后仍需处理未落盘编辑、当前任务及迟到结果。

可读阶段记录、应用私有会话、原生 CLI 历史、缓存和 trace 的具体存放位置与迁移范围尚未统一设计。不能据本文直接把所有内部记录写入教师目录或复制原生会话标识。

当前源码的 workspace 身份包含 `projectId + normalizedPath`。文件夹前置、课例迁移与稳定归属需要调整现有生命周期，不能仅改 CLI 工作目录即宣称完成。

## 8. 最新工作台布局：左侧上下整合

Owner 提出采用 VS Code 式布局，并与已有方案整合；随后确认继续沿此布局讨论。

| 左侧：同一侧栏上下分区 | 中间 | 右侧 |
|---|---|---|
| **上方资源管理器**：当前工作空间真实目录与文件 | 当前对话、选项问答、任务进度 | 当前教学文档、材料或课件的标签页；支持编辑与预览 |
| **下方项目及对话**：课例/项目与相关会话 | | |

资源管理器承担文件查找与打开；项目及对话承担创作任务的切换与续接。课例项与真实目录关联，不要求教师维护另一套独立的文件组织。

具体交互建议：

- 点击文件，在右侧打开，保留当前会话归属。
- 选择课例或其对话，中间切换相应会话，资源管理器定位该课例，同时保留访问大工作空间共享资料的能力。
- AI 生成策划、脚本后在右侧直接呈现；形成课件后，增加课件标签，在材料、策划、脚本和画布之间切换。
- 持续显示当前工作空间与当前课例；浏览另一个文件不自动重定向已发出的任务。
- 左侧上下分区可折叠、调整高度。具体默认比例、窄窗口行为及是否记忆布局尚未设计。

现有极简/专业模式方向继续保留：两者具备相同 AI 能力，专业模式保留完整手动能力。两种推进方式（自动/手动）与两种工具呈现方式（极简/专业）分别表达，不混成一组难以理解的模式。

## 9. 选项问答与减少教师输入

Owner 明确软件层需要能够弹出可点击按钮：大多数问题给出选项，最后保留自由填写。这里的核心是软件实际呈现可操作问答，不能只让 AI 在文字中列选项，再要求教师打字作答。

当前交互建议：

- 支持单选、多选和自由填写；多选问题应能勾选已有项并补充要求。
- 一轮只问少量高影响问题，材料已明确的内容先提取供确认。
- 区分材料事实、AI 建议和教师明确选择；默认选中不能冒充已经确认。
- 优先在当前对话中就近呈现问题卡，确需回答才能继续时再考虑阻断式弹窗。
- 回答进入对应文档或阶段记录，恢复后仍可取得。

问题卡/弹窗的具体样式、选项数量、默认值与批量确认交互尚未定稿。当前 `NativeAgentQuestion` 已有单选、多选和填写回答的渲染基础，不能据此认定跨 CLI 和各创作阶段均已完整接通。

同日接续讨论已确认：**同一条对话贯穿材料整理、教学策划、呈现脚本和课件修改，教师可按需另开对话**；不默认每到一个新阶段就自动拆出新对话。阶段以文档成果和进度提示表达的具体方式仍是交互建议。

## 14. Markdown 源文保真：产品细化建议与接续状态

**第14.1–14.6节记录当时的源文细化建议；当前正式执行表达已在第15节链接合同收敛，旧正文保留/双格式建议不再适用。** Word同期交付和1.9版本归属的Owner选择记录在第14.7–14.8节。源文仍须能理解、修改并保持当前新模型的正文、格式与对象。

### 14.1 按内容选择表达方式

| 内容 | 推荐的源文表达 | 排版界面行为 |
|---|---|---|
| 标题、段落、强调、列表、引用、简单表格 | 使用常见 Markdown 表达；源文保持便于教师和 AI 阅读 | 连续编辑正文，工具栏修改格式 |
| 行内与独立数学 | 采用明确的数学扩展规则，候选为 `$…$` 与 `$$…$$`；保留公式原始表达和必要说明 | 句内或独立排版，点击原位置修改，可辅助输入 |
| 颜色、字号、行距、着重号等既有格式 | 用有限、明确支持的样式扩展保留；由软件按可视操作生成，源文可查看修改 | 原有格式继续可用，正文默认显示实际效果 |
| 合并表格、可编辑图表、折叠章节等复杂内容 | 完整的扩展片段，可折叠显示；展开后能够读取并修改真实单元格、数据、配置和结构 | 使用对应表格、图表或章节工具编辑 |
| Flow 互动组件 | 扩展片段包含实例参数和明确的组件包、资源引用；代码与资源沿用正式工程保存归属 | 保留组件及参数编辑能力，文字在其前后连续编写 |
| 图片及图示 | 正文保留说明与关联，实际图片使用明确的资源引用；图注、尺寸和环绕等必要信息保留 | 显示图片与说明，支持对应图文操作 |

“可折叠”只是源文显示方式，不是把对象变成不可编辑占位符。展开图表片段应能看到数据和配置；展开组件片段应能看到实例参数及包引用。完整内容不能只剩一个依赖软件当前内存或临时缓存的 ID。

普通 Markdown 工具对扩展内容的解释能力与本软件不同。建议扩展片段具有可读名称和说明，便于外部查看和 AI 理解；完整可视编辑、普通工具阅读和课例整体搬迁分别验证，不承诺任意 Markdown 工具都能运行 Flow 互动。

### 14.2 一个当前稿，两种编辑视图

- 排版视图与源文视图编辑同一份当前内容；源文中的有效修改切回后真实生效。切换视图不另存一份需要长期同步的正文。
- Flow 源文是课件当前正文的编辑表达，正式保存仍进入课件工程；教学文档的正文保存为课例真实 `.md` 文件。共用编辑能力不改变两者各自的保存归属。
- 切换源文但未修改内容时，保留原有格式、图表数据、组件参数、资源关联和稳定身份；验证内容含义与行为，不要求机械的字节相同。
- AI 修改选中段落时保留范围外内容；参数、样式与公式修改采用和可视编辑相同的效果。源文模式不扩大已经发出的 AI 任务目标。
- 旧正文中的 `$`、反斜杠和代码示例保持原来的文字含义。新增数学语义与普通文字、代码区、转义字符的区别需要明确，不能靠全局字符串替换改变旧内容。

### 14.3 对象与资源随实际归属保存

- Flow 对象引用继续指向工程内实际资产与组件包，按既有工程闭包保存；不凭显示名称猜测资源，也不把暂存路径当作长期引用。
- 材料整理稿和教学文档的图示位于课例所属的真实目录，使用课例内可解析的相对路径；移动整个课例后仍能读取，不长期依赖共享原件、临时提取目录或原电脑的绝对路径。
- 在 Flow 与教学文档之间复制内容，需要同时处理所需资源到目标归属。单独复制 Markdown 而未携带附件时，显示具体缺失及补齐入口，不能把缺图当作完整复制。
- 移动对象保留身份；复制对象形成独立实例并处理必要内部身份；删除对象按原有规则处理受影响的导航与引用。删除一个图片引用不等于删除仍被其他内容使用的图片文件。

### 14.4 未完成或无法解释的源文

- 输入过程中允许保留未完成公式或扩展片段；就近显示具体问题，保留当前源文草稿和最后一次有效排版结果，并清楚区分二者。
- 修复前，不把残缺解析结果提交为 Flow 正式工程，不通过忽略字段、删掉对象或把对象替换成图片来完成切换。
- 未应用的源文草稿应能在切标签、关闭和重启后恢复；不能只在内存暂存。恢复信息的存放方式留待保存合同设计。
- 对真实 Markdown 文档，当前源文可以作为文件保存；未完成数学或扩展内容应明确提示其呈现状态。将该内容用于结构化课件生成时，仍须核对所需内容能被正确解释。文档源文保存与 Flow 结构化提交的条件分别定义。

### 14.5 建议验证的具体反例

1. 一段中文包含行内分式、普通美元符号、反斜杠和代码示例；切换源文后数学与字面文字含义均保持，未闭合公式不会吞掉后续正文。
2. 修改带颜色、字号、行距和着重号的段落；只改一个词后，其余格式和段落身份保持。
3. 在源文中修改合并表格的一个单元格、图表的一条数据或组件的一个参数；切回后结构保留、修改真实生效，原有导航仍正确。
4. 移动、复制和删除含图片/组件的内容，保存重开并移动整个课例后核对资源；缺失附件时有具体说明。
5. 教师在 AI 修改后继续手改，再撤回 AI 修改；保留范围与实际冲突需按后续共编规则核对，不能把简单的最近一次撤销等同于选择性撤回。
