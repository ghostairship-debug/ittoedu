## 主线与完成目标

统一的是果铃能力及其正式实现。人、内置 AI、外部 AI 消费同一业务 owner；AI 按任务读取当前内容、提出内容修订或调用必要动作，软件负责绑定、身份、布局、资源、应用、事务、撤回、保存和正式回执。能力覆盖文字、图片、表格、代码、专业组件及其属性修改、跨类型转换、新增和组合编辑。

“读内容、修内容、做动作”是协作分工，不要求实现三个巨型工具。复用现有 Gateway、DocumentHost、DocumentSession、执行器、内容请求与资源/文件服务，在实际 consumer 缺口上接线；不新建 Agent 平台、意图小模型、私有写作 DSL、通用规则引擎、第二份工程或纯包装 Facade。模型理解意图并产生适合任务的富文本、数据、HTML/SVG、源码或图像；不负责抄目标路径、生成身份、全量复制数据和填无意义参数。

首轮给紧凑语义内容与绑定，复杂任务按需展开；同任务读更多不扩大写权限。当前授权内核心能力默认可用，精确能力由宿主自动接入，不能因模型未先发现或加载工具/Skill 而拒绝支持的动作。Skill 提供场景方法，不作为能力授权或发现前置门。工具失败在原任务内恢复，保留正式回执；已提交动作不重放，真实未知副作用先查证，目标版本变了由软件重新读取。

## 已确定的产品约束

- 首发面向教师，保留成熟可见编辑器、专业算法与人工布局。普通局部修改默认生效、可撤回；保存应应用当前有效可见稿并落盘。未完成或无效输入保留，给具体修正入口，不悄悄丢稿或写0。
- 本机外部 MCP 配置默认持久，优先做到有本机执行能力的外部 Agent 按一句提示自行连接。软件打包并提供实际可用入口，不要求教师掌握仓库、Node、tsx、令牌与环境变量。持久配置不等于跨作品复用失效目标或重放动作。
- 网页结果范围不清时提出简短结果选项，同时推进已知已授权的低风险准备。已经明确授权的最终动作继续执行；不逐次点击、输入、上传重复确认。没有授权的发送或最终提交不擅自执行。
- 内置与外部的能力差距是接线/产品入口缺口，不建立两套能力体系。Office 复用现有原格式服务和外部编辑路径，不重写 Office；素材、文件、导出、历史、页面状态也归既有业务 owner。
- 不增加媒体供应商、收费路径、运行环境或管理员安装；不承诺大量视频/在线交互离线可用，也不绝对保证旧电脑兼容。复用既有授权与环境，缺配置如实记录，仅影响相关验收。
- Project V10、Published V3、Component API 5 是当前生产入口；不加旧工程兼容或转换器，保留原件。发行继续暂停。

## 先约束设计增量，避免修复再制造负担

这是开发判断规则，写在现有 Outcome、Acceptance 或交接说明中即可；不建检查平台、评分表、运行时门或逐包审批。

新增抽象、核验、预算、等待或用户步骤时，用几句说明：

1. 它处理哪个当前可复现错误、直接 consumer、现有合同偏差或已批准目标？
2. 它保护什么具体用户结果，失败怎样发生？已有哪个 owner 已保护同一属性？
3. 复用或局部修改为什么不足？调整正确 owner 是否能消除根因及重复状态？
4. 最便宜、能证伪成功的检查是什么，通过后在哪里停止？

没有当前依据，默认不加。必要且未覆盖的边界保留；重复的合并到单一 owner；格式偏好、静态猜测或仅防未来风险的门删除或改成诊断。局部修补若保留已证实根因、复制规则或双轨状态，应在正确边界调整，不以少文件为目标。

唯一正式 writer、最终 CAS、停止屏障、实际授权根/realpath、资源引用及真实未知副作用查证，因防止当前错写、损坏或重放而保留。不得借此扩成通用防御平台。能解析、承载、保存和使用的内容先进入作品；局部问题保原内容并诊断，不整份拒绝或静默静态化。Hash/字节比较仅用于确实要求的身份、完整性或确定性属性。

独立 reviewer 在相应重要选择或待合候选中检查这些判断；普通就绪叶子同时推进。此规则自身不能成为所有任务开工的前置门。

## 并发和唯一写入

在实际可用线程内尽量铺满依赖就绪且写域不重叠的工作；当前21线程只是本次可用资源快照，不写成派发事实。共享源文件、配置、构建产物和 fixture 同时只有一个 writer。一个 owner 的多个包是同一条接线队列，不能再派多个 Agent 同时改同文件。

WORK_PACKAGES 的共享表是可能触及的职责边界，不是一次抢下全部文件。任务卡使用现协议既有粗锁；粗锁覆盖数个独立叶时由父协调卡持锁并明确委派真实文件，不能为并发造“none”锁绕开。共享 hunk 提交给表中 owner；确需整文件移交，先暂停原 writer 再交接。

具体防冲突：

- I 写能力/正式文档/Session/公共合同与 Main 公共装配，G 写执行器/上下文/结果，H 写常驻 MCP/启动，U 写 App/Store/Bridge，X 写共同格式输出与人工导出消费者。
- A01 整体拥有项目文件 coordinator/Markdown/Flow 身份链；A02 整体拥有 HTML 应用与测量装配链，A03 资源叶交 A02 接线。不能拆同一个大文件同时写。
- S03 与 S04 分别拥有网页授权和浏览器服务；HTML 预览服务整文件归 S08，A03 资源接线交 S08。S05/S10 是 I 的接线需求，实体修复分别归 TE04、TE09/TE10，不再派重复实体 writer。
- T 独占对应测试全文，实施者不能改其断言；E 固定候选 cut 后机械运行，不修改正在测试的源/产物。昂贵构建单 writer、按相关变更准备一次；多个族复用，不让整个开发队列等待无关构建。

start_dependencies 是必要端口的最窄就绪条件，-min/-port 表示该接口已可消费，不表示整包已结束。integration_joins 仅表示最终汇合的验收归属；其双向关系不是开工依赖，也不能变成阶段墙。卡中记录已交付的具体函数/内容形态/consumer 即可，不新接口登记平台。

| 最窄就绪标签 | 实际可消费的内容，沿用现有类型/函数 |
|---|---|
| K01-min | 既有业务服务能由公共注册消费的最窄 hook；先接一个 consumer，其他逐项补 |

## 最小验证与完成定义

验证证明具体属性：解析/语义用最近层反例，保存/撤回/恢复用真实工程副本，视觉看实际呈现，互动做真实动作；模型可用性只用既有授权的代表性调用。T 保留原失败期望，E 记录真实匹配及原输出。零匹配、skip、mock、工具接受和派发状态都不是产品通过。

最低充分检查通过就停。仅相关实现/依赖/定义变化、新失败、新假设或真实汇合属性扩大；不因审查者更换、上下文压缩或阶段推进重跑。旧全仓红债单列，承担本包对应维护与新增红，不把全仓清零或全模型/全 CLI 矩阵变成每叶门。

交付覆盖全部 implement 项与已确认优化；每个 candidate_probe 有一次有效确认/反证/条件处置，成立的归实际包修复。环境/供应商条件只限制相关证明，不扩范围也不假通过。当前保护行为和反证项有明确保留/关闭结论，不重复开发。

结果记录具体 cut、变化、原失败为何解除、最低证据、独立审查、剩余条件与未测范围。源码候选、工程证明、真实视觉/互动与 Owner 接受分开。持续推进至本包目标与处置完成，不逐阶段重复询问是否继续；新产品取舍或未授权费用另报具体问题。最终按文档规范更新当前状态与结果入口，不发布安装包。
