## 2. 已确定的产品行为

### A. 预算与停滞分开

- 总预算是成本上限，不叫作死循环检测。保留默认 20 分钟，工程任务开始前显式选择 20 / 40 / 60 / 120 分钟，工程/课例任务的活动原生回合可主动延长 20 分钟，从任务开始计最多 120 分钟；不自动延长。检查/候选等待阶段不提供延期入口，课例讨论和文件任务发起时仍使用默认预算。
- 一个任务只有一份权威 deadline，准备、CLI、检查、提交和前端显示使用同一值。延长必须绑定当前 task / epoch / workspace，过期或终态输入不可复活任务。
- 区分近期原生活动、重复候选没有进展、整体预算耗尽。无输出不能单独证明死循环；已知工具执行或等待用户时不能误报为卡死。有效活动不能由轮询或重复心跳伪造。
- 已有重复候选和格式修复上限保留。期限/停止之后旧候选零提交；此前已提交内容保留，新任务从当前工程和原生会话继续，不建立跨任务自动重放或第二草稿库。

### B. 运行中补充与纠正

- Codex 使用已有原生 `turn/steer`。Claude / OpenCode 在核对本机协议后采用原生中断当前回合、在同会话续接最新输入；这是回合中断，不是用户的“停止任务”。
- 普通补充可选择下一回合处理；纠正方向立即引导。界面区分已接收、正在中断并续接、已送达及下一回合处理，不把排队称为已被模型执行。
- 宿主先持久化最新输入，再中断；收到旧回合结束后才启动新回合。旧候选不得抢先提交，当前暂存源码保留供续接使用。Stop、期限、身份切换和失败期间不得自动重启。
- 保留原生权限/工具/会话，不另建模型循环、通用 RPC 或任务平台。

### C. 减少可确定的模型失误成本

- 候选 helper 对可完整读取的 Component manifest 复用正式 schema；冻结目标种类可靠时提前拒绝 Native 工具处理 Component 目标。资源、live 身份、编译与动态行为仍归正式宿主检查。
- Component 能力说明明确 `goToScene` 的 Slide sceneId 范围；顺序跨 Slide / Flow / Spatial 使用已有 `nextScene`，模型本地无条件成功的 mock 不能证明真实导航。
- `spatial.structure` 增加内容取景操作，复用现有 Spatial Owner 的计算；单一候选事务更新目标 surface 的 home 和目标 location 对应镜头，不悄悄修改其他入口、不在打开时改布局。有效 world 内容不包括 global / viewport 控制器。

### D. 工作台界面与业务能力解耦

- 保持三层职责：Shared / Core 管正文与事务；本地服务和原生适配管理文件、CLI 与事件；前端管理布局、交互和人类可读状态。画布、选区、IME 等仍留在 Renderer。
- 本批以真实消费者为边界拆分工作台：View 只呈现，导航/文件会话/切换用例通过窄端口调用既有 Owner，桌面 API 在应用组合层注入。迁移旧 writer，不做 re-export 或第二 Store / History。
- 实机检查后调整入口层级、展开区域、路径展示及响应式布局。聊天输入和文件正文必须可达；材料、阶段、设置不能把主要内容挤出可用区域。窄窗使用清晰的面板切换，而非无限堆叠。
- 核对实际教师路径：选择工作空间 → 命名课例 → 查看材料 → 打开并编辑文档 → 切换聊天/课件 → 保存并重开；文件冲突、未保存稿、停止和课例切换继续受原 Owner 保护。

### 6.1 目标、归因与范围

教师提出任务后，Agent 根据当前对象、需求和真实能力直接选择参数/内容修改、现有接口组合或源码创作路径，避开已知必败分支，并交付可继续编辑、可保存重开、可运行及满足所需导出的结果。本批补齐[常规任务三层方案](AI_COMMON_TASK_EXECUTION_PLAN.md#31-任务入口的路径选择)的首次决策与换路规则，接续既有交互/组件任务族；不增加通用 Agent 平台或课例专用工具。

此前方案已有三层分工和文件入口不要求先失败的原则，但实施主要停留在能力推荐、候选拒绝和原生续接，尚无完整首次路由。把候选最终提交成功当作默认调试目标，会掩盖错误推荐、首次走错路和人工干预成本。本次应修正这条共同机制，不能仅关闭两个局部 P2、补一句“失败后换办法”就宣称完成；也不能把已有多轮修复成功改记为首次自然成功。

### 6.3 产品工作包与完成标准

#### R. 首次按真实能力选择路径

R 是本批 E/F/G 的共同实现前置，不增加路线节点、模型服务或独立 Agent。沿原生 CLI 的同一会话处理“理解目标 → 核对适用能力 → 选择路径 → 准备候选”，无需默认增加一次独立模型调用或教师审批。

| 执行路径 | 首次进入条件 | 例子与边界 |
|---|---|---|
| 参数、内容修改 | 已有对象的公开字段能够完整表达变化 | 改标题、颜色、尺寸、公式或组件公开参数；保留对象身份及未指定内容 |
| 现有接口与操作组合 | 单字段不足，但正式操作、已有组件及其组合能完成完整目标 | 图文插入、状态与显隐、导航、批量配置；产品生成工程引用及操作依赖 |
| 源码创作或修改 | 现有声明式内容和公开参数不能表达所需行为，当前正式 Component/Runtime 等载体能够承接 | 修改已有组件机制或实现新模拟；允许首次直接进入，不要求先失败，不默认重建整个对象或课件 |

- **语义与可用性各有归属。** 模型理解自然语言、目标、期望结果与保持条件，必要时拆成有依赖的操作；软件根据冻结工程事实、对象 carrier、Surface/owner/state、参数合同、接口及实际 Player/导出支持判断适用性。关键词只帮助发现，不据关键词或任务长短硬选路径，不把创新教学内容自动判为源码任务。
- **先判完整需求能否表达。** 支持判断区分可用、已知不支持和信息不足，并说明适用条件、排除原因、可行替代或需补读的信息。缺少能力卡不等于底层能力不存在，未知项先按需读取；只有原生工具/现有合同也无法消除的真实歧义或缺失条件才交给教师。不能用写入 Schema 合法替代可运行判断，也不承诺静态判断能预知所有视觉或执行结果。
- **同源事实用于首次输入。** 在现有 `generationCapabilities`、能力发现/query、profile 和本地 helper 中提供针对任务的适用入口与排除理由，复用正式工具条件、公开参数和 Published 支持判断。路由记录只保留目标/期望、选择路径及理由、相关能力版本/条件与需补信息，归既有任务/诊断 Owner；不写入 V9、不增加第二能力 registry、工程真相、模型循环或通用工具 RPC。新增传输字段须与实际 producer/consumer 同批定义，本文不预称其已存在。
- **推荐与执行一致。** 已确认不支持的具体分支在初始可用推荐、预检与真实执行使用同一判定；保留对限制的可读说明和其他正式工具发现能力。模型仍选择开放创作手段，不能绕过真实载体能力或把路由结果当作 OS 权限白名单。
- **执行路径与交付方式分开。** 快捷候选和完整 V9 文件均可首次选择；完整文件适合已有工程合同能表达而快捷字段不足的情况，不能使 Player 执行不支持的动作。素材搜索/生成本身不自动归为源码兜底。若使用完整文件仍无法表达所需行为，应选可承接的正式动态载体，或说明真实能力缺口。
- **按必要操作组合。** 同一任务可让标题走参数修改、教学机制走源码修改，复用既有步骤与前序结果引用，不新建动作语言。各候选继续经过唯一工程/资源/History 事务，路由本身不产生提交；不能为局部需求默认重写整个 V9 或用截图替代可编辑结果。
- **完成证据：** 免费检查证明公开参数、正式组合和需要源码的代表需求分别得到适用入口；已知不支持分支首次即被排除，未知项可补读后重新判定。真实模型是否自然选对路径须由 6.4 实测证明，规则测试或预填正确路径不能代替。

#### E. 常规交互组合与导航目标

- 先检查现有 `slide.interaction`、组件配置及前序结果引用能否完整表达已知需求。`slide.interaction` 仅接受 Slide scene owner；`course.navigation` 负责作者态课程位置的增删改排序，不能作为 Player 导航入口。能表达的沿原工具改进目标解析、组合输入和推荐；确有缺口时在已有任务族补一个由真实 consumer 约束的窄分支，不建立第二动作语言或新工程真相。
- 模型仍负责内容、视觉状态和触发条件；产品负责由这些明确配置生成一致引用、动作和显隐关系。状态变化必须能同时作用于相应图形/文字；“操作后显示解释”按明确配置执行，不由软件猜测教学意图。
- `step.next` 保持先走呈现步骤再进下一场景；`scene.next` 保持跳过剩余步骤到下一场景。精确目标使用已有正式位置能力；组件/Runtime `goToScene` 仍限 Slide，顺序跨 Surface 复用已有 `nextScene`。不承诺不存在的跨 Surface 公共方法，不绕过导航守卫。
- 保持当前 Published `presentation.set` 的支持条件：`currentSlide`、无 transition、独占最后执行组且动作收尾；global 规则须有 `scene.in`，不支持 `scene.enter` 触发。能力、健康检查与执行复用同一判断；不支持的组合在正式边界明确拒绝，不静默丢动作。
- 修正 review 的能力矛盾：当前不支持的 `presentation.enter` / `presentation.in` 不再作为 compose 可用分支对外推荐；将已知限制及经核实的替代路径提供给 R。若要开放这两种执行语义，必须由真实 Player consumer 和相关合同完成后再开放，不能只加 Schema。该修正不删除既有工程表示能力，也不以删除教师需求降低验收。
- 名称解析先按当前位置的 applicability 及正式状态/目标语义确定对象集合；另一位置专属的全局或 Surface 图层不参与当前页重名判断。当前真实歧义仍要求稳定 id 或补足目标信息；不能静默选中另一个对象。
- **完成证据：**一个含多呈现步骤的 fixture，真实点击分别证明步骤推进与跨 Surface 目的地；明确配置的两种图形状态与解释显隐同步；事务只改指定对象，受影响保存/重开及 Undo/Redo 保留。静态结构与实际呈现分别检查。

#### F. 正常交付与按失败原因恢复

- 在现有 helper/暂存/原生续接链上完善正常路径：正常调用完成预检与正式候选写入，结果直接给出当前请求对应的交付回执，减少模型重复组装路径和标记。现有去掉 `--check` 即可写候选的能力继续使用，不新建同功能 helper。
- 明确 `prechecked`、`ready-for-host` 与宿主 `committed` 三个事实；只预检不能声称修改已应用，也不能仅因自然语言宣称完成就提交。宿主成功仍须当前候选根内文件、身份/epoch 校验和唯一 canonical 事务。
- 对有证据可恢复的“只预检/缺候选/格式错误”，沿既有原生继续机制返回具体原因、预期产物和下一步；先核对当前机制，补缺口而不复制模型循环。在宿主任务进入终态前判断是否可有界续接，已终态任务不得复活。沿原任务预算与既有修复次数计数，保留已提交结果；不自动开新付费任务，不把运输/服务异常都归为模型错误。
- 续接必须有当前请求的正式宿主结果：现有 `continue()` 只接受匹配的 `committed` / `unchanged` / `rejected`。对确需候选却未交付的编辑结果，先记录带具体原因的正式 `rejected` 再续接；不能直接凭原生回合结束、自然语言或 `prechecked` 启动下一轮。合法讨论/无需修改、已明确受阻缺少条件、Stop 和到期分别沿现有结束语义，不强制追索候选。
- Stop、过期、身份失效之后零旧候选提交；不扫描候选根之外寻找工程文件，不自动摄取历史或未提交源码。反馈对教师保持可读，原始路径/协议细节进诊断日志。
- 当前有界拒绝续接只是安全网；新增原因驱动恢复接入 R 的适用性判断，由错误 producer 提供准确 code、目标/字段、条件和建议下一步，沿既有正式反馈回到同一模型。不得只解析中文报错或把所有 `tool-failed` 都建议重试/源码兜底。

| 失败原因 | 当前任务内处理 | 再尝试的必要变化 |
|---|---|---|
| 已知能力不支持 | 排除具体分支，选择经核实可行的替代；没有路径时说明能力缺口 | 能力版本或相关适用条件发生实质变化；改摘要、步骤 id 或反复重组同一无效动作不构成变化 |
| 参数/目标错误 | 指明字段及当前目标，保留可行路径修正 | 实际参数/目标修正；不自动新增、替换载体或重写整课 |
| 信息不足 | 读取缺失对象、接口/参数或必要材料，再作选择 | 得到新事实；同一读取无新信息不续圈 |
| 缺候选/交付格式错误 | 复用 F 已有具体交付反馈与格式修复上限 | 实际写入/修正当前候选，不把 prechecked 当交付 |
| 临时工具/运输/服务故障 | 按已确认原因有限恢复；不归为能力不支持 | 故障可恢复的证据，沿既有原生生命周期；不复活终态、不自动开新付费任务 |
| 结果语义/视觉错误 | 将受影响对象的真实结果与既定要求反馈，保留原失败 | 内容、机制或实现实质修正；结构通过和已提交不能结束验收 |

- 在原任务中保留失败分支、相关能力条件和尝试结果，复用已有进展/预算 Owner。对同一原因不变的无效分支不再自动安排等价续试；拒绝理由和可行替代应在下一次生成前明确。工程更新后按相关事实重判，不能把一次失败变成跨任务永久黑名单，也不因无关 revision 变化就允许原失败分支重试。已有格式/停滞/期限上限不提高。
- **完成证据：**同一能力错误即使改写摘要/步骤 id 也不会再次走入原无效分支；参数修正仍能留在可行路径成功，补读新信息和相关能力变化允许重判。预检/交付可区分、一次候选只提交一次、缺交付有界恢复及 Stop/期限/身份失效零旧提交继续保全。

#### G. 可操作的观察与验证反馈

- 已有缺口清单和冻结反例只是准备工作。补接 G1 应用内试跑/预览的 Player 诊断 → G2 当前任务观察/反馈的交互诊断摘要；G3 在既有受影响对象与回执事实中关联规则/动作，G4 为新制品提供可复用的真实点击及目的地检查。先复用 `coursePlayerTryRun.ts`、`authoringObservation`、`generationHostFeedback` 及真实 Player，不能仅再次盘点后把 G 记为完成。
- 复用当前工程观察、诊断、真实宿主和导出检查，把已明确的期望状态、显隐和目的地与实际结果对照，反馈到对应对象/动作；只在现有反馈确有缺口时补接线。
- 软件可判定的错误尽早反馈；视觉差异查看真实呈现，教学内容按已冻结要求检查。不把“编译成功/已提交/按钮存在”当作教学互动完成，也不为了本批建立通用语义评分器或自动教师评审系统。
- “原任务自动修复后成功”仅指模型利用已有正式反馈，在同一有界任务内续接、生成候选并获宿主 `committed` 后实际结果正确；不把文字自述计作修复。观察/Player 检查只形成反馈或失败证据，自身不能创建候选、提交工程或开启付费任务。
- **完成证据：**已知规则被跳过或导航未执行时，实际诊断可经产品反馈回到原任务并指向规则/对象；代表性按钮实际点击到达既定 state/location，并核对显隐结果。报告分别列出实际执行、失败、未执行、自动修复和人工干预；宿主修复证据与模型使用修复后能力的证据独立记录。不得要求所有 Native/参数修改附带新的通用检查 DSL，或把 G 扩成 2.0 通用教学评分系统。

### 6.4 验证顺序、预算与停止条件

1. **开测前先证明可行路径与反馈。** 当前暂停原计划三通道付费验证，直到 R 首次适用性判断、E 两项反例修复、F 按原因换路和 G 本任务所需反馈接线有直接免费证据。每叶子选 1–3 项命名检查，覆盖合法直达与可信失败模式；汇合只按相关变化准备一次必要构建。不得仅凭代码有分支、能力卡存在或旧 39+88 项通过开测。
2. **免费证据按属性选择。** R 检查参数/接口组合/源码路径的适用入口、已知不支持首次排除、信息不足补读；E 将 review 探针转为正式行为回归并保留已有点击导航证据；F 检查同原因不变不再重复、参数修正仍可成功及原生命周期边界；G 使用真实 Player/应用反馈 consumer 检查跳过诊断、点击显隐和实际目的地。免费测试可以固定语义输入证明程序判定，不能据此声称模型自然选路已通过；不为这些局部检查整文件触发真实 CLI 矩阵。
3. **冻结自然任务与计分规则后，三个通道各一项。** 继续使用 `output/r19-efg-coordination/bounded-goal/` 的相同有界教师要求、独立副本及 R1–R5 验收，不改写冻结输入来规避失败；运行前另记首次路径与干预计分字段。Codex / OpenCode 只用已确认实际路由的 Luna，支持则 Fast；Claude 只用已确认的 DeepSeek，沿现有授权自主执行必要验证，不另换模型。教师输入不提示内部工具/协议/交付步骤；脚手架只准备环境、操作与采证，不能指定正确路径、替模型写答案或中途补协议。三项只证明该目标的自然组合选路及交付，不能代表全部路由覆盖；源码直达等缺口先用免费反例，确需模型证据再限定一项有新信息增益的任务，不自动扩大矩阵。若发现跨通道共用产品缺陷，暂停所有依赖该缺陷路径的后续运行；通道独有失败不阻止其他独立任务。
4. **预算用于控费，任务复杂度先控范围。** 沿用 A 的预算与活动规则，不用固定总时长判断死循环；启动前依据现有产物和所需改动确定任务是否有界。若仍需多场景整课创作或额外资料研究，先重新限定诊断任务，不能用不合适的 20 分钟任务评价模型。记录有效输出、工具等待和无进展，不自动延期或用心跳延寿。
5. **诊断运行与验收运行分开。** 同一失败原因已确认，即停止该假设下的付费重复；新一轮开始前记录哪项相关实现/合同/夹具/配置变化或哪个可证伪新假设，使结果能改变下一步决定。换模型、提高预算、重复同样提示或追求绿灯不构成理由；纯 flaky 原样重试仍最多一次。确需人工注入提示、协议或修改内容的诊断运行可以用于定位，但保留原失败并记录干预，不计自然首次成功。任务内正常自动修复沿 F 的规则，不由 ROOT 反复另开任务追索通过。发现产品原因先修产品，发现评测矛盾先另存修订版并保留原记录，发现内容错误如实记错；不通过删要求、换容易样例或运行后改断言消除失败。
6. **首次路径、恢复、干预、结果与速度分别计量。** 至少记录首次选择的执行路径及交付方式、选择依据、首次候选是否完整正确、首个拒绝原因、同原因重复次数、改路发生在失败前还是后、原任务自动修复成功、人工干预后成功、未提交/部分正确/未执行、原生回合与正式提交数。同因重复包含本地 helper 与宿主拒绝，不能只统计宿主回合而隐藏模型在本地反复试错。首次选择正确不等于结果正确；多轮查阅本身不算失败，候选被拒或结果错误后修成不能计首次正确。提前直接源码创作成功属于源码路径；常规任务依赖手写整份工程的文件成功不补算前两层覆盖。保留原始输入、配置和正式回执，计时从用户请求到首次正确可用结果，包含失败、等待和修复；准备、模型/工具、宿主及总耗时分列，费用未知如实记录。小样本不推算总体成功率或 P95，不用最终全绿替代普通教师的自然完成证据。
7. **三项结果用于收敛产品缺口，不替代 050。** 对照[050 规格](roadmap/1.9/r19-050-internal-dogfood.md)的真实教师组合链，复用已通过的自动/手动、PDF/DOCX/PPTX、文档/Flow、重启/切 CLI 证据，仅补实际缺口。完整目标仍按真实成果验收，未通过/未执行继续保留；满足后才进入[060](roadmap/1.9/r19-060-release.md)所需候选收口，不自动 accepted、发布或转移失败到 2.0。

### 7.2 第一批：常规编辑从任务输入到交付结果

**完整结果：** 简单属性修改、多步跨页编辑、已有组件编辑三类链路贯通任务输入、能力发现、内容准备、候选交付、宿主反馈与最终结果。按实际修改选择保格式改文、多对象排版、组件公开参数或必要源码变体；简单小改继续守住短路径，复杂任务证明未指定内容保全。先交付受影响纵切，不把每个变体扩成新的完整模型矩阵。

1. **同源任务视图。** 从同一份冻结请求派生模型默认输入，提供用户目标、必要当前内容/导航事实、精确目标引用、相关可用操作及按需资源位置。组件复用 UI / Builder 的字段解析，给出当前有效值、正式字段键、用途、类型/约束、可调用入口及实例/共享影响；具名状态取该状态有效值，锁定或不支持说明原因。已注册的可见文字区域沿正式映射关联字段，不从任意 DOM 猜可写路径。布局任务按需提供同一 Owner/平面的有效几何、短内容、层级与必要邻近关系，跨页按精确目标补读；普通改字不默认附带整页对象。宿主完整请求继续供程序读取，重复推荐按操作只表达一份，目标关联用引用；不能把重复内容从初始提示搬到必读文件来宣称减少负担。选区仍是焦点，不是修改权限边界；来源版本和当前任务身份继续由现有 Owner 维护。
2. **完整而紧凑的操作说明。** 复用正式 Schema、适用条件和现有 query，按本次操作选择分支，保留字段类型、必填项、默认语义、约束、准确目标和一个有效例子；去除无关变体、重复描述与程序专用包装。字段视图准确区分现有值编辑与增删/重排能力；`content` 数组合并不能写成替换，缩短数组不宣称删除默认尾项。引用依赖必须闭合，不能截断必要 Schema 凑大小。组合任务能够一起获得所需操作，避免每发现一个底层依赖又查一张卡。说明是否足够调用由实际 consumer 证明，不设固定查询次数，也不为每个自然语言需求新增专用工具。
3. **一条正常候选准备路径。** helper 的默认生成路径已经执行静态检查，应收敛为“写创作输入 → 一次调用完成检查并生成候选 → 声明交付 → 宿主回执”。`--check` 仅用于确有需要的只检查场景，不成为正常任务固定前置。模型面对稳定的创作输入，版本包装、身份填充、对象/字符串转换及通道终结格式尽量由现有 helper / adapter 派生；输出提供本通道可直接使用的明确交付声明。小操作已有直接输出短路保留，不能为了统一而强迫它先写文件或多开回合。
4. **保持真实交付边界。** 静态预检不等于交付，候选文件就绪不等于正式提交。仍须当前原生成功终态及明确候选声明，不能扫描到文件就自动摄取，也不能把旧文件、迟到文件、普通答复或 Stop 后产物当成新候选。宿主仍核对当前身份、资源、期限与 canonical transaction，只有正式 committed / unchanged 能证明应用结果；已有提交的续轮不重复应用相对修改。
5. **让失败可直接处理。** 复用正式解析与错误来源，反馈具体步骤/字段、适用条件、实际值和必要补读位置；不在每次错误后重发整套协议。参数错误修字段，缺少事实补读，能力不支持改用真实可行路径，暂时故障沿既有恢复机制处理。无进展、预算耗尽、用户停止与真实版本冲突保持原有边界，不再追加一次模型失误对应的全局例外。
6. **同批退出旧负担。** 标题居中的字段与几何语义只放相关操作说明；控制台定制说明只随相关目标/能力提供；其他专项媒体/动态说明按任务需要加载。删除被正常入口替代的重复 v1/v2、字符串/对象、预检/交付说明。修正 `qa-repair` 的固定一次停点：每次候选等待宿主反馈后，可在原任务预算内继续修具体差距；保留真实停止，不强制按固定轮数完成。正常源码创作可阅读组件实现；普通工具调用应有足够公开说明，不增加“禁止读 helper 源码”的提示来制造通过。
7. **Native 多处改字保真。** 在共享文本映射与实际工具中保留未修改区间的 runs，统一同一基线下的多处替换、位置映射和插入样式继承。整段改写仍可使用，但不能继续把所有差异之间的内容当作一个替换区；重复文本或差异匹配有歧义时明确诊断或取得精确范围，不虚报无损。模型使用已捕获选区或可唯一定位的原文/上下文，不要求手算字符偏移。范围约束、原文基线、不重叠和 Unicode 边界由程序检查；保留当前 code point 坐标语义并避免拆断用户可见字符。显式指定的样式变化才覆盖相应样式。所有受影响 Native consumer 使用同一规则，不能靠固定拆成多轮修改掩盖共享函数缺陷；Flow 正文不回退旧 runs 分支。
8. **成组布局复用正式命令。** 将现有 Slide 对齐/分布的规划能力接入正式 AI 入口及候选私有事务。复用多选 Owner 对精确目标、旋转包围盒、锁定、状态和间距的处理；若当前规划与 live 提交耦合，在该 Owner 内分离可复用规划，候选准备不得调用 live 提交函数。保持一次原子文档/资源/History 事务，删除对应重复算法而非维护 UI / AI 两套布局。Flow 正文继续使用流式布局，其他 Surface 只按实际支持暴露。固定间距堆叠、成组归一等尚无正式语义的能力由真实任务驱动，不先建设通用布局求解器；已有文字测量可提供估算诊断，视觉正确仍由真实呈现证明。

**任务视图的同源约束。** 事实来自本次冻结请求及其绑定的正式定义/资源；实例有效值、状态覆盖和邻近关系允许由正式解析器派生，不要求视图是请求字段的字面子集。目标、状态、版本和派生来源须可追溯，投影过程中不混入新的 live 状态；信息不足时沿既有观察 Owner 取得一致的新观察，不拼接不同版本的事实。字段、约束和能力语义复用 UI / Builder / 正式执行 Owner，禁止手写第二字段表或用另一套算法重算规则。聚焦检查比较同一冻结输入下的字段、有效值、可写范围及锁定/不支持原因；关系输入与正式布局规划一致，不能仅凭视图文件存在或字符串相同证明同源。

### 7.3 第二批：四阶段文稿与构建输入、校验和修正

**完整结果：** 自动流程在材料与当前文件有效时，生成、校验并保存真实阶段文稿；可修复的候选格式问题回到原会话修正。手动流程仍分别确认当前教学简报、策划、呈现简报和脚本，不能用预授权替代看过当前稿后的确认。

1. **按阶段和环境组装输入。** 保留共同教学要求、材料出处、当前已确认稿和本阶段输出合同；从同源参考中取当前需要的内容。格式说明只提供正文写法与限制，不整篇注入校验文档标题/命令；教学方法和运行环境说明分别维护。软件内构建只取得当前窗口的 Builder V2 用法，外部构建保留外部启动方式；公共 Facade/工具语义继续同源，不能靠加载不适用步骤后再禁止执行维持差异。
2. **阶段候选校验前移。** 将 CLI 现有正文/数学/本地附件校验所用逻辑放在现有正式 Owner 可复用的边界，宿主在写正式阶段稿之前检查暂存候选；CLI 保留为同一检查的可选入口，不各写一套解析或资源规则。必须覆盖候选位于暂存目录、附件相对真实课例目录解析的差异。无效候选留暂存并给出行列/字段诊断，既有正式稿和已确认前阶段不被覆盖。
3. **先接反馈，再撤固定命令。** 当前阶段服务遇到失败主要标记 failed；正式文件保存与阶段可确认检查也不是同一个步骤。先把可修复候选错误接到原生同会话续接，保留本阶段、文件基线和已有材料，修正后重新校验；再删除每阶段必须手动运行 `npx ... validate-lesson-markdown` 的提示。不能只删 CLI 要求，留下错误没有早反馈或正式稿先被写坏的路径。

**完整结果：** 模型取得精确、可用于判断下一步的结果证据；确定性等待与重复检查减少，同时保留真实行为和用户目标核对。

**退出证据：** 已执行但未满足教师目标的例子不会被反馈成目标通过；未覆盖条件仍明确标记。纯换序、字段修改、对象增删和共享资源影响能分别准确表达，截断摘要不会承诺全部未改，模型收到的反馈与人类审阅一致。并行动作检查不再等待全部时长之和，执行未结束/取消/导航失效不能早报通过；实际状态和受影响 Player 行为保持正确。仅对已有证据确实可复用的内容减少重验，不把少做检查本身当成果。

### 7.6 验证、计量与停止条件

**正确性与首轮表现分开。** 首次候选正确、候选前本地修复、宿主反馈后自行修复、普通教师反馈后修复、人工技术介入和最终失败分别记录。原任务内自主修复可以证明该路径能够完成；人工补协议/改候选、换强模型及第三层兜底不能冒充前两层自主覆盖，也不能回写为首次正确。固定 60 项与前两层覆盖目标由[常规任务方案第 7 节](AI_COMMON_TASK_EXECUTION_PLAN.md#7-覆盖率准确性与速度的验收)维护；本轮三批只验证受影响纵切，不新建一份分母或重跑全部矩阵，不把历史首次正确率变成本轮持续追绿的阻断门。

**计量完整任务。** 复用现有发送边界、原生轨迹和 timing，必要时只补能影响判断的缺失标记。记录初始提示、独立输出 Schema、宿主其他技术字段；后续实际工具返回与可得原生用量另列，不能用磁盘文件大小或截断前 stdout 代替模型实际读取。时间从用户请求到首次正确且可用结果，包含失败、工具准备、读取、检查、反馈和修复；最终任务结束另记。跨普通教师反馈的修复保留同一原目标的累计机器时间及用户等待，不能只报第二个成功任务。未知的排队/网络/模型推理分项保持未知，字节数不折算为未经测量的 token 或延迟。

**采纳工具调用分桶，仅作观测。** 直接解析已有 native-record 的 `events`，不新增产品事件平台、分类模型或次数门。先按 `task.taskId` / 请求及任务起止界定完整任务，包含原生续轮；若文件混有多个任务，先用现有任务/原生记录关联，不能把整个会话都算到一项。按 `(adapter, sessionId, payload.id)` 配对 `tool-call` / `tool-result`，合并同一次调用的进度和终态；同一记录的多个保存副本去重。缺 id、缺终态、失败和取消分别保留，不补造成功；统计调用数时一次命令内多个子命令仍算一次。

简单属性修改仍用于检验没有增加必经 I/O；复杂文本、排版和组件任务用于检验保全与完整能力。两者目的不同，不用单纯改色成功替代复杂结果，也不为本次新增代表集分母。报告提到的动态观察帧等待仅是待测分项，不能据此宣称它是总耗时主因。

**保持真实自然任务条件。** 采用普通教师指令，不在验收运行注入操作名、内部协议或人工候选修正。真实模型按现行授权：Codex / OpenCode 用实际确认 Luna，默认使用通道支持的 Fast；Claude 用实际路由确认的 DeepSeek。传输差异先用协议证据验证，仅补受影响通道的必要真实任务；不自动展开任务 × 三 CLI × 格式矩阵。比较时固定任务、实际模型/强度/速度档、应用/CLI版本及冷启动/连续会话条件，无法对齐则分别报告，不宣称公平提速。

**停止而不追绿。** 目标行为及可信失败模式已有直接证据后结束该批检查。首轮失误如已能自行修正，且没有发现新的产品缺口，不追加通用提示、不重复同一课例追首次成功。必要观察与修复次数不是固定功能门，但消耗全部入账；诊断重复须有相关变化或可证伪新假设。性能差异不清楚时先定位具体阶段，只做能改变判断的补测；没有可支持的加速结论就写未证实，不持续跑到出现更好数字。

**三种完成证据同时交付。** 公开接口足以调用且错误可定位；用户结果及受影响保存/重开/行为正确；相关旧负担确实退出，读取/步骤/等待成本有前后事实。可以证明结构性成本减少而整体提速尚不确定，必须分别表述；单次更快不能外推总体成功率、P95 或固定提速比例。
