日期：2026-09-07。性质：官方资料研究、当前源码与既有真实使用证据评估；不是实施完成报告。

## 1. 结论与成功标准

Owner 明确要求：创作助手体验至少达到 VS Code 中 Codex / Claude Code 插件级别，只能更高不能更低，特别是 AI 必须实时理解课件现状。

当前不达标。问题涉及信息获取、执行环境、反馈通道、界面和验收，不能靠增加提示词、换模型、放宽候选校验或等待 1.9/2.0 自然解决。现有 CLI 和宿主事务仍可复用，但“单次文本快照 → 最终候选 → 人工应用”的产品闭环需要升级。已证实缺口见 [G01–G12 记录](reviews/1.8-ai-assistant-gap-register.md)。

本评估把“不低于”定义为：相同用户工作流具有至少同等的上下文可达性、行动能力、可控性和可审阅性；在课件领域增加结构、画面与运行状态的一致理解。模型每次输出质量不能由宿主保证，宿主必须保证不人为剥夺任务所需能力、不虚报成功、能验证结果和继续修正。未通过下文的实际基准之前，不宣布插件体验对齐。

当前 S3 是实质可用性阻断，不是仅等待教师签字。已有文字生成、label 修改及指定包源码修订证据继续有效，但不能替代自然语言、视觉任务和连续编辑验收。

## 4. “实时理解当前课件”的具体合同建议

这不是只给模型一张截图，也不是把整个工程持续重复发送。需要三种同源、带身份的观察：

1. **工程结构**：当前文档 revision、Surface/位置/步骤、选区、可见性/图层、文字和样式、素材引用、组件/Runtime 源码及共享影响。活动文字草稿也须可观察，并标明它尚未形成正式提交；不能只读上次保存文件。
2. **实际画面**：从真实作者/目标运行宿主获得页面截图及对象局部图，标注 viewport、缩放、裁剪、Surface、选区和 capture 时间；图片原始资产独立可读。画面与结构不一致时等待同一 revision 渲染就绪再发，不能混用旧截图和新对象。
3. **运行事实**：当前预览/试运行模式、步骤/镜头、实际挂载实例、公开状态、资源加载和运行错误；动画用带时间点的多帧与相应行为检查，单张静态图不能证明翻滚。

“实时”的建议验收口径：

- 选择、切页、编辑提交及运行状态改变后，本地上下文提示目标在 500ms 内更新；这是待测工程目标，不是当前成绩。
- 每次发送读取当前编辑器状态，不能要求先保存/重新上传；已存在的先保存才能建本地 workspace 的入口限制须评估未命名工程的临时身份与 Save As 迁移语义。
- 运行中的任务在下一次可接收输入的原生协议边界获得变化提示；重要目标变化立即使旧候选不可提交。无增量输入支持的 adapter 必须明确显示同步状态并提供取消/恢复到新快照，不能假装已实时获知；此退化只能用于过渡，不能通过最终“实时”验收。
- 切换选区不悄悄重定向正在执行的修改；区分“用户当前关注对象”和“本任务已经绑定的修改对象”。用户显式改目标时再更新任务范围。
- 截图延迟单独记录。截图就绪后才能声称已看见最新画面；动画无需把每帧发送给模型，但按需观察必须覆盖任务所需时间点。
- 人工改动导致旧候选过期后，自动说明冲突并基于新观察继续；不丢掉教师修改、不仅显示 stale 后让用户自行重新描述。
- 读取范围与写入范围分开。为理解所选对象可以读取关联资源，为替换可以建立必要新资产/新载体，但不能因此授权随意改整课。

UI 可显示“已同步：第2页 / 选中图片 / 当前画面”以及变化中状态；内部 revision/路径放诊断详情，不把协议术语塞进教师主流程。

## 5. 实现边界与需要修订的假设

保留：CLI 自己的模型循环与认证；Course Project V9、Published V2；正式命令、准入、资源闭包和唯一事务/历史；staging 结果摄取与失败零写。不要复制一套模型 runner，也不要开放 live Store 或直接改 .h5lesson。

改造方向：宿主持续发布带版本的只读观察制品，通过各 CLI 原生输入/文件能力提供信息；CLI 按需读取相关资源并输出候选，宿主校验和预览/应用后，将真实 receipt、画面和诊断回传给同一任务。每次观察仍是不可变快照，但任务不再只有最初一份快照。

这是一项正式的会话/生成合同演进，不能偷塞进任意 JSON：要定义观察身份与过期规则、任务与 CLI turn 的对应关系、讨论/计划/编辑意图、应用策略、提问/纠正、实际结果回传。当前 `expectedResult:auto|candidate` 和一次格式修复不能表达完整交互；格式修复预算与正常连续创作不是一回事。宿主只按明确状态和事件调度，不替模型做规划或另起模型调用。

| 路径 | 可复用部分 | 当前缺口/实施前需证明 |
| --- | --- | --- |
| Codex app-server | 原生会话、结构化输出 | 接模型目录、图片、公开摘要、steer/interrupt；候选之外的交互消息不被 schema 错误强制成结果。具体本机版本逐项能力探针 |
| Claude 原生程序化会话 | 当前 stream-json 输出与 resume | 目前 stdin 一次写完关闭；需验证所装版本双向输入、提问、图片、模式/模型控制，不能拿“能输出流”冒充双向能力；必要时升级原生集成方式，保持 CLI 自有认证和循环 |
| OpenCode ACP | 原生 session、配置返回、候选文件写入 | 从协商开启只读快照/能力文件和图片内容；接真实配置选项；确认纠正和运行反馈能力，缺项不静默降级 |
| 宿主观察 | publishedCapture、动态准入 capture、正式投影 | 现有 capture 并非完整作者画面/交互观察服务；需补全 Surface 与运行状态，复用真实 painter/host，避免另一套渲染器 |
| 素材与包编辑 | asset.media.import、native.authoring、component.package、runtime.source | 原图可读、候选资产可生成、选区创建依赖、替换语义和引用传播；真实图片改色不能等价成画一个色块遮住图片 |

图片分析与图片编辑必须分开：CLI 模型支持图像输入，并不保证能生成任意修图结果。确定性改色/裁切可使用正式图像处理能力；生成式局部编辑需要真实可用的图像工具/服务。当前尚未核实三 CLI 的这类工具可用性，须在 W05 先做能力验证。若使用新服务/依赖或开放暂存区执行能力，须明确合同与资源边界，不能承诺“换模型就自然具备”。图像结果仍通过正式资产事务进入工程。

对于 VS Code 可以执行脚本/测试的能力，本产品必须提供同等任务效果的受管验证与素材处理环境。不能继续把所有读取、运行手段关掉，再希望 Skills 弥补；也不能直接把任意 OS 权限交给生成组件。原生 CLI 暂存区执行与已准入 Runtime 的宿主权限是两条不同边界。

## 7. 产品验收：不用协议提示的真实任务

以下是必选入口提示；测试可以操作 UI 和读取结果，但不得把内部 tool 名、target、UUID、schema 或候选示例加进教师提示。每项记录 CLI/模型/强度、输入上下文、真实修改、可见结果、失败原因与耗时。Codex、Claude、OpenCode 各自验证，不能用一种成功代替另一种。

| 用例 | 教师原话/动作 | 必须观察到 |

代表性写入用例验证保存重开、Undo/Redo、Player和适用导出；图片/动画看实际画面，不只统计节点。已有未变化且直接对应属性的证据可复用。
