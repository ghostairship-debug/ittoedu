# 内容接入与联动创作修改方向

日期：2026-10-17。依据本轮 Owner 提供的 GPT Pro 评估、当前未提交工作树、前序职责调查，以及《校园雨水实验室》的冻结生成记录。

**建议主线：软件接走确定性的运行接线，让模型集中表达业务关系；同时用一件围绕同一对象或过程展开的作品，验证能力是否被实际采用。** 减少样板代码、改善表达、维持持续编辑是三个不同结果，需要分别举证。

Owner 随后已授权按本文先实施确定小修、Source 局部增强，再推进显式状态连接。这一批已完成并同步工具、方法和分发；[实施结果](../../output/content-behavior-20261017/REPORT.md)记录了正式事务、真实 Published 输入联动与 GLX 保存冷读。机制与示例页分离、代表性模型作者实跑、图表消费者及自主子 run/成果直接交接继续按后续范围处理；不把本批技术验用替签表达质量或提速。原作品未改，发行仍暂停。

## 3. 建议的修改顺序

以下按实际行为闭环组织，不按 Markdown 章节机械拆提交。小型独立适配不必等主线全部完成，但也不应以它们替代主线结果。

### 先修确定的契约失配和机械接缝

1. **简化准确的作者保证。** 修改 runtimeNote、直接方法示例和实际分发材料：状态/事件订阅无需重复登记 cleanup；首次 `get` 仍保留。普通 DOM、计时器、Observer 及外部资源仍需明确清理。`teacherController.subscribe` 两种宿主的清理保证目前不完全一致，先沿现有 Host/World 统一保证，再统一说明，不能直接删除所有退订要求。
2. **补短工具接线。** 已观察页面 path 与对象插入目标的适配、快捷 `insert.click` 复用现有 `scene.next/previous`、建页时可携首稿内容，分别沿 Gateway、点击规则和文件规划 owner 完成。新页回执已经有 `surfaceId`，不能再把“重新查目的页身份”设为固定步骤；不建设通用依赖 DAG 或新寻址登记表。
3. **专业表格接收内容。** 新表或明确替换范围接受行列内容，由现有表格 owner 生成/保留内部 ID。现有合并、富文本及局部改格不因此重建整表。图表已有语义 data 入口，继续复用。
4. **披露已有图片配置事实。** 将任务冻结时已知的生成/编辑角色状态和原因投影给模型。`image.status` 查询的是图片作业，不能当作配置查询；不增加收费探测或新的前置门。

这些项目主要减少确定性的簿记和往返，不能单独签收表达质量。

### 主线先做：已有内容的局部行为增强

**第一个可验用结果：** 对一个已经装配的内容主体，模型提交业务增强代码；软件沿现有 Source 准备路径组合基实现，使一个条件输入驱动另一处结果显示，作者无需重抄完整 API5 挂载壳。

实施边界：

- 复用 `prepareComponentAuthorSource`、现有 workspace/moduleBindings、Source 私有化及提交/保存路径；软件维护组合外壳，完整 API5 源码深改仍可用。
- 增强执行在现有基实现完成挂载之后；原 update/dispose、活动控制和作用域取消继续有效。增强自身创建的业务资源仍应有明确 disposer 或使用受管辅助方法。
- 可以提供小范围的受管监听、首次读取并订阅等便利方法；不反向解析任意 JavaScript 来猜业务行为，不要求所有内容改成一种固定函数模板或标记语言。
- 既有 HTML 能承载并运行的内容继续直接接入；仅在需要宿主端口时使用正式增强路径。不向所有普通或外来 HTML 脚本自动开放完整宿主上下文。
- 共享公式和共享状态访问可先放进现有普通 JavaScript 模块，软件保存实际依赖。公式复用不需要新建公式 DSL。

首步至少证明：原内容和人工 frame 保留；增强确实驱动结果；原实现更新仍工作；挂载作用域取消、销毁或 reset 后旧回调不再生效。普通暂停、离屏和跨页保留遵循既有生命周期与状态语义，不因此清空订阅或记录。到此先结束生命周期包装这一闭环，不等待全类型绑定系统。

### 随后做：显式连接和机制自由组合

**显式连接先从一条标量关系开始。** 连接必须说明当前状态来源、真实目标和变化后的表现，不另存一份运行数据。新建正式连接时，同一闭环内补齐其所支持的保存、改名、复制和消费者，不能先上线一份只在当前会话成立的关系再把已知成本后移。

需要特别保留的差别：

- `logic.courseState` 的当前声明是标量；`scope.state` 能存 JSON，包括雨水样例的记录数组。不能把全部业务 JSON 强塞进现有标量声明，也不能为此立即扩成通用状态图。
- 现有改名 planner 同步导航 guard 和互动规则（含命名展示态覆盖），没有覆盖所有消费者；例如该路径目前未同步 input 的 `stateKey`、`answer.stateKey`、`validityKey`。输入复制已有另一套托管键重绑。扩显式连接前，应补齐本次实际命中的直接消费者。
- Source 只有显式参加引用维护的连接才能由软件重绑。普通业务代码保持原样，不全仓扫描替换状态字符串。
- 复制时的继续共享与独立副本必须明确表达；软件不凭名字相似或位置相邻替作者决定。正式记录的具体载体及 API 名称由首个真实消费者约束，本文不预先冻结一套新绑定协议。
- 原生图表当前按作者 `instance.data` 绘制，没有简洁的 state→data 绑定入口。需要它时增加明确的运行投影适配，复用现有数据解释和绘制；不以正式 `data.set` 写回作者数据来模拟实时绑定。

**机制与示例页分开组合。** 沿现有组件包/容器插入 planner，将“准备可用机制”与“创建带标题的新页示例”拆开：

- 采用当前对象或区域时，不自动插页、生成标题或重排邻居；沿当前 frame、父子关系和事务装配。
- 逐步揭示复用现有互动规则；分类、匹配等复用现有组件包和局部 Source，不重复实现动作引擎。
- 保留完整配方作为可选示例；不把它变成所有题材的默认构图。
- 仅允许区域插入还不足以获得内部视觉自由。现有配方 runtime 带有自己的面板和控件样式，需要通过已有 data/Source 改写；不新增统一皮肤语言或为每种程序能力建设人工编辑器。

### 再完善委派成果交接

材料冻结读取、成果来源和单文件 `artifact.save` 已存在，不能再要求父模型复述产物字节。后续让父模型选定成果文件组和目标后，由现有成果 owner 沿依赖闭包直接应用；自主子 run、窄上下文和取消继续接现有执行机制。

任务目标、审阅和采纳判断保留在模型侧。先让一个任务少接线，再扩大并行；完整子 run 的上线与实际并行提速仍需各自证据。

## 4. 表达方向：用主体的变化承载解释

当前创作说明已经允许原场景推进、地图/混合导航、连续阅读和按实际结果承接，不需要再堆“禁止 PPT”“每页必须互动”等规则。

参照作品应体现：用户操作后，能看出改变了哪个对象或过程，结果怎样产生，解释为何成立。页面或阶段可以保留；主要信息关系应持续可辨。

雨水题材可沿用六个阶段，作为验用示例而非统一模板：

| 阶段 | 主体与操作 | 解释与证据 |
|---|---|---|
| 问题 | 同一座校园中呈现降雨与去向 | 问题靠近实际观察对象 |
| 关系 | 标出雨量、入渗、径流的对应部分 | 数量、单位和公式按理解需要出现 |
| 调整 | 在雨、铺装、土壤附近改变条件 | 场景表现、数值、说明消费同一计算结果 |
| 比较 | 对照两次明确记录的条件与结果 | 差异能追到实际变化的条件 |
| 改造 | 在同一校园尝试铺装/土壤方案 | 建议引用最近真实实验及同一公式重算 |
| 结论 | 回看用户实际尝试的方案 | 无记录时说明证据不足，不编造经历 |

表现只能表达给定简化模型能够推出的量，例如水量比例和去向；不能暗示算出了真实积水深度。机制、空间、叙事和阅读题材可以采用不同组织方式，不把以上六阶段推广成必经流程。

运行和编辑的粒度可以不同：一个连贯局部程序可以承担主体表现，标题、标签、图像和关键文字仍沿现有作者字段/编辑位置暴露；适合直接编辑的原生对象继续独立。不能以“拆成许多对象”替代实际可编辑，也不为每项代码能力另造可视编辑器。

## 5. 验用与停止条件

实现阶段从最低成本有效证据开始：

| 要证明的结果 | 最小有效证据 |
|---|---|
| 作者契约准确 | 核两个真实运行宿主的保证，检查源说明与实际分发消费者一致；不为说明小修重跑整课 |
| 软件接走固定包装 | 一个真实增强案例，核基实现挂载/update/dispose、首次显示、变化传播及作用域取消/销毁后的清理，保留普通暂停/跨页语义；必要结构迁移做一次独立 review |
| 新增正式连接正确 | 对所支持引用做一次针对性的改名或复制，再保存/重开，运行态不写作者工程 |
| 机制可以自由装配 | 当前对象/区域内可操作，人工 frame 与邻居保留；不以模板数量或新接口存在证明 |
| 模型采用且表达改善 | 在实现生效后做一轮代表性作者实跑，并在同工程做一次标题、标签、图片或局部布局修改，验证联动仍成立 |

真实作者重点记录三件事：

1. **生成负担：**模型仍写了哪些固定适配、发生哪些无新事实读取和修补；只统计确属机械的部分。
2. **表达关系：**一个重要条件改变后，主体表现、结果和后续解释是否清楚连动；不只看按钮能点或数值会变。
3. **持续编辑：**普通编辑和必要源码修改、保存/重开后，作者内容与运行关系是否保持正确。

一次新作者可证明该样本采用情况，不证明普遍质量或稳定提速。若要比较耗时，保留相同任务目标、已知配置和冻结输入，并披露随机模型及环境差异；不自动追加作者轮次、裸 HTML 对照、全矩阵或作品精修。

有效聚焦证据通过就停止对应检查。能力未变的旧证据继续有效；缺的是新接口的模型采用和作品质量时，不能靠增加源码测试代签。
