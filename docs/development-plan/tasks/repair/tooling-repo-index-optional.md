# tooling-repo-index-optional 将 repo-index 降为可选本地缓存

- Status / Owner: queued /
- Risk / Hotspot: S2 / generated-index
- Outcome / Why now: 基线 `442d4e1` 的 repo-index 有 9 个 tracked 生成文件（约 13.41 MiB、约 29,200 行），约 70 个提交触及该系统、56 个是生成刷新，近期样本约 21% diff 行来自索引；它没有产品运行时 consumer，`contexts/` 没有可审计的决策收益，而 golden/quality 主要自证自身。保留显式手动导航，移除 tracked cache 与默认维护门，直接降低已量化成本。
- Write scope / Baseline: baseline `442d4e1`；允许修改 `.gitignore`、`package.json`、`.github/workflows/check-contracts.yml`、`repo-index/README.md`、`docs/development-plan/inventories/FEATURE_CONSUMER_OWNER_LEDGER.md` 的 MOD-19 行；允许删除 `repo-index/generated/**`、`repo-index/golden-tasks/**`、`scripts/repo-index/evaluateGoldenTasks.ts`、`tests/unit/repoIndexGoldenTasks.test.ts`。仅当“缓存缺失时手动生成/查询”失败时，才可最小修改 `scripts/generate-repo-index.ts`、`scripts/query-repo-index.ts`、`scripts/repo-index/query.ts` 及其直接测试。必须保留 `repo:index`、`repo:context` 与 `repo-index/semantic/**`；禁止新增自动缓存、watcher、数据库、图/向量检索、替代 quality 框架，禁止修改产品源码、合同、能力索引或本总纲。
- Acceptance: `git ls-files repo-index/generated` 无输出且该目录被 ignore；package 默认脚本与 CI 不再调用 `repo:index:quality`、golden 或 freshness gate（`repo:index:check` 可作为显式工具开发命令保留，但不是阶段门）；golden 目录、评估脚本和唯一测试 consumer 已删除；在缓存缺失状态运行 `npm run repo:index` 后，`npm run repo:context -- --path src/renderer/store/editorStore.ts --size small` 返回可读上下文，生成缓存不出现在 `git status --short --untracked-files=all`；semantic 可选事实继续工作。
- Focused validation: ① `npx vitest run tests/unit/repoIndexGenerator.test.ts tests/unit/repoIndexQuery.test.ts tests/unit/repoIndexSemantic.test.ts tests/unit/repoIndexTypeScriptAdapter.test.ts`；② 从已删除的 `repo-index/generated` 状态执行一次 `npm run repo:index`；③ 执行一次 `npm run repo:context -- --path src/renderer/store/editorStore.ts --size small`，随后只人工查看 `git status --short --untracked-files=all` 是否隐藏缓存。不得运行已删除的 golden/quality、全量测试/E2E/verify。
- S2 safety / rollback: 删除前从基线 `442d4e1` 逐一核对静态脚本、package、CI 与文档 consumer，并先确认 `.github` 中唯一调用点确为本卡允许的 `.github/workflows/check-contracts.yml`；若发现其他 workflow/脚本 consumer，不扩大白名单，任务立即 blocked 并报告精确路径。只删除本卡点名路径，不删除 generator/query/semantic，不改 Git 历史。失败时从 `442d4e1` 恢复被删文件和调用点；任何新发现的产品或 fresh-checkout 必需 consumer 都使任务 blocked，并把精确 consumer 报给 Reviewer，而不是继续删除。
