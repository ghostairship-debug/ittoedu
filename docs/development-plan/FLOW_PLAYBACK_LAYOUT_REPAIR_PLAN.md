# Flow 新生成内容一致性与播放视口修复方案

2026-09-13，按 Owner 最新反馈修订。状态：产品修复完成，形成 engineering candidate。旧课件只是测试用例，本轮不修稿、不制作其修复副本；产品必须保证新生成内容在各入口具有一致的布局语义和正确结果。实施证据见第7节；Owner S3 和发布结论独立。

## 1. 要交付的结果

本轮只做产品层修复，交付三个方面的结果：

1. 通过正式创建/生成入口产生的新 Flow 内容，默认合理使用可用宽度；标题、正文、图片、组件及相关浮层按正式布局语义协同。编辑、试运行、整课预览和 HTML 不依赖生成后人工调整 widthMode、定位、frame 或空段落才能保持一致。
2. Flow 播放中的教师控制器随实际视口保持合理位置，在支持的窗口下全部动作可达；教师仍可拖动、折叠和展开。
3. 各方向的播放平移条只在存在实际可移动范围时出现，不需要时隐藏并释放常驻占位。Flow 正文自身的滚动按正文溢出独立处理。
4. 缩放、平移、边条显示变化和 resize 不重播、不丢答案/焦点/互动进度，不产生工程修改或 History。

“一致”指相同工程事实和布局规则：相同实际内容宽度下，排版与相对几何等价；不同宽度下允许正文自然重排，但定位原点、尺寸含义、叠放、内容完整性及交互不因入口改变。阅读模式的正常留白、短正文下方的自然空白，不再被一概判为渲染缺陷。

不把“所有入口共用一个渲染器”或“模型碰巧生成了一份合适课件”当作保证。生成工具的默认值/可表达能力、canonical 提交、布局 consumer 和实际验收必须闭合。

## 2. 实施前已核实的责任边界

| 现象 | 当前原因 | 本轮处理 |
|---|---|---|
| 旧课件正文仍很窄 | 缺 `widthMode` 时保留 `reading`，稿纸上限760 px，正文可用688 px | 不修该样本；验证新建/生成入口稳定使用正式 fluid 默认值，保留旧读取语义 |
| 正文与共享文字相对漂移 | 居中稿纸与视口绝对坐标混用 | 产品保证正式生成工具能正确表达正文/稿纸/视口定位，且各 consumer 一致处理；不靠事后改测试课件 |
| 控制器偏左、悬空 | 原 frame 为 x=190、y=638、900×64，只做越界纠偏 | 产品增加 Flow 播放视口适配规则 |
| 无移动范围仍显示边条 | 自绘平移条只设置 disabled/透明度，底部、右侧恒占18 px | 产品改为逐轴按需显示，取消常驻占位 |

调查中，同一实际应用窗口的试运行/整课预览 Flow 视口宽976/1556 px，正文宽均688 px；标题相对视口左位置144/434 px，横幅均40 px。预览根节点基础比例为1，容器铺满内容区。正文宽度没有扩大，不能归因于预览被额外缩小。

证据入口：[调查记录](../../output/playwright/flow-preview-diagnosis-20260912/REPORT.md)、[预览截图](../../output/playwright/flow-preview-diagnosis-20260912/preview.png)、[课件事实](../../output/playwright/flow-preview-diagnosis-20260912/fixture-facts.json)。这些是本机调查制品；当前 fixture 的部分 frame 与用户截图并不完全相同，不能称为用户原会话的逐像素复刻。旧样本用于说明失败机制和兼容回归，不再作为改稿对象。上述调查尚未证明所有新生成路径均有缺陷，实施时由正式创建/生成路径的反例决定具体修改点。

## 3. 三项修复

### A. 产品保证新生成内容的布局一致性

沿用 V9 已有的 `widthMode`、FlowBlock、paper/viewport 定位及现有布局 Owner，闭合“创建/生成 → canonical 工程 → 编辑 → Published → 试运行/预览/HTML”。不通过更新旧测试文件替代这条产品链路。

**A1. 创建默认值与正式生成工具对齐。**

- `src/renderer/course/flowDocumentModel.ts` 已有 `widthMode: 'fluid'`。检查人工新建、正式 AI 创建、Builder 等当前支持入口是否实际消费同一工厂/default，不让某条生成路径自行拼装缺省 reading 的新 Flow。已正确的路径只补必要验证，不重复实现默认值。
- 新建普通 Flow 默认 fluid；只有任务明确要求固定阅读宽度时才使用 reading。向已有 Flow 增补内容沿用该 Surface 的明确布局，不把增补操作变成隐式迁移。
- 默认值由产品命令落实，能力卡/生成上下文说明真实行为；不能只修改提示词并期待模型每次主动补字段。
- 明确的坐标空间应由正式工具表达并经过目标范围校验。当前 `nativeAuthoringTool.ts` 的新增模板和 `layerItemPropertiesInput.ts` 的属性分支没有 `paperSpace`，不能因为人工属性面板已有入口就认为 AI 能力已经对等。补齐必要的 Flow 定位参数及同一 canonical patch 路径，保持 strict、作用域和未指定字段保留语义；非 Flow 消费者不借此扩域。
- 工具和能力卡发生变化时，由正式生成器同步相关能力制品；不手改 generated JSON，也不另建 Flow 专用生成 writer。

**A2. 明确新生成内容的载体与定位关系。**

| 新内容的作用 | 产品支持的表达与处理 |
|---|---|
| 标题、正文、需要为后续内容占位的说明/横幅 | 使用 Flow 文档流中的正式 block，后续内容自然顺排；不得默认生成 viewport 绝对文字再让教师改稿 |
| 图片、表格、图表、局部互动 | 使用正式正文 block/carrier，宽度消费实际内容容器；保留各自高度、宽高比和互动协议 |
| 确需叠加在稿纸上的元素 | 明确 paper 定位，消费实际稿纸原点及正文 scroll；生成观察提供必要的纸张/内容宽度和现有几何 |
| 真正固定于视口的提示/共享内容 | 明确 viewport 定位，使用实际视口 CSS 尺度，保留其固定语义，不强制转换为 paper |
| 教师控制器 | 由宿主按 B 的视口规则投影，生成器不得用原1280×720绝对位置承担响应式适配 |

`paper` 本身不进入文档流、不自动让位，固定 frame 也不自动变成比例布局。依赖内容顺序、占位、响应式横向关系的常规内容要由现有语义 carrier 表达；必要叠加仍允许存在，不能泛化为禁止全部重叠。已声明的坐标空间、frame、宽度策略应忠实执行，不依据文案或元素 ID 猜定位并静默纠正。

**A3. 统一 producer/consumer，并以可执行约束保证。**

- 检查 Flow 编辑展示、生成观察、Published producer、FlowSurfaceHost、HTML 对 widthMode、正文 padding、paper origin、viewport、媒体/组件尺寸的使用。发现重复默认值、重复 fit 或坐标补偿时，在已有共享 Owner 收敛；相同布局输入只解析一次。
- 全局元素跨三表面复用，Flow 的定位表达和投影不能改变 Slide/Spatial 的内容、frame 或共享层顺序。Flow body 仍是语义正文，不把它改成通用 LayerItem。
- 生成观察给出当前 Surface 类型、实际布局宽度、宽度模式及相关坐标空间；生成工具可表达这些约束，提交时验证合法字段、目标和载体。布局相关诊断通过现有候选反馈/修复链返回，不创建第二套模型循环或通用布局平台。
- 几何测试验证确定性规则；真实宿主检查正文占位、必要内容裁切、paper/viewport 投影和跨入口结果。对模型错误的载体选择或需要修正的候选，保留原始失败及产品修复/续轮证据，不由开发者直接改输出文件后记为成功。
- 工程保存、重开、Undo/Redo、Published 和 HTML 均消费同一份最终生成结果；不生成一套编辑版和另一套播放版。

交付物是产品默认值/工具/布局链路的必要修复、针对性回归和通过正式入口生成的新样本及 HTML。无旧课件改稿、修复副本或测试用例美化任务。

### B. 教师控制器适配 Flow 播放视口

**本方案建议采用：Flow 播放控制器默认底部居中，保留教师本次播放中的手动拖动。** 这是本次提出的新产品行为，前两轮只确定了需要合理适配；不把“底部居中”描述为此前已经实施或已经明确批准的规则。

适用入口：当前位置试运行、整课预览、Player/HTML 的 Flow 场景；Flow 页面编辑展示及生成观察同步消费相同的默认投影规则，显示与命中使用同一几何，避免新内容在编辑时按一处避让、播放时控制器却换到另一处。全局层的原始 frame 编辑仍由原作者 Owner 持有，明确其尺寸/样式与 Flow 播放位置的区别，不静默写回投影坐标。Slide、Spatial 保持当前控制器投影规则。

默认投影规则：

- 以实际播放视口的安全区域计算位置，安全区域包含当前可见边条的命中区域；不再以1280×720的位置直接投影到任意 Flow 视口。
- 常规展开态水平居中，底部建议保留12 CSS px间距；控制器宽度以作者设置为上限，窄窗口按可用宽度重新排按钮，保持文字清晰，不把整条控制器作为位图或整组 transform 缩小。
- 折叠态按实际可见操作区域计算可达性；折叠/展开保留一致的恢复位置，展开后全部必要操作可用。已有 rotation/compact/按钮配置继续消费，投影与命中必须使用同一几何结果。
- 拖动保留于现有控制器运行会话，resize 后仅做必要纠偏。缩小后再放大不得积累误差，也不能把自动纠偏当成教师手动移动。
- 默认位置、手动偏移、最终投影纠偏分清职责；沿用 `TeacherControllerRuntimeSessionStore`，必要的“是否手动移动”信息也只存在该会话 Owner，不新增第二套位置 Store。
- 沿用已有生命周期：折叠状态按稳定 controller ID 共享，拖动偏移按 surface session 保存；场景/整课重置按原语义执行。观察缩放和恢复视图不冒充课程重置，不清空教师的拖动状态。
- 控制器不随正文滚动，不随整课观察 zoom/pan 缩放，不重挂实例。调整 frame DOM、按钮布局与命中时复用现有控制器实例。

用户可见影响要写清楚：Flow 中控制器的播放初始位置将按上述宿主规则确定，作者 frame 的 x/y 不再直接决定其播放初始落点。作者的按钮、样式和大小偏好继续保留。本轮不新增持久化“自动/绝对定位”切换；若必须保留每个课件的任意固定播放落点，则需要另行明确该产品选择及其 strict 合同，不能通过猜测旧 frame 自动分类。

### C. 滚动条和平移条按需出现

先区分两种行为：

| 控件 | 显示条件 | 修改的状态 |
|---|---|---|
| Flow 正文滚动条 | 正文在对应方向实际溢出正文视口 | 该正文容器的 scroll |
| 播放视图平移条 | 当前观察变换和有效内容边界产生非零可移动范围 | 现有 PlaybackViewSession.pan |

实现要求：

- 每个轴分别从同一 `playbackPanRange` 结果决定显示。不能只以 zoom 是否大于100%判断；100%下确有可达内容越界，也可能需要平移条。
- 零范围时隐藏整条轨道与滑块，同时退出 Tab 顺序和无障碍可操作树；只设 `aria-disabled` 或透明度不算完成。隐藏后不存在18 px永久空槽。
- 只需横向移动就只显示横条，只需纵向移动就只显示竖条；两个方向都需要时避免角落命中区重叠。
- resize、zoom、恢复视图、活动 Surface/内容边界变化都重新解析可移动范围。细小浮点误差使用统一、可说明的 CSS 像素容差处理；不把有意义的溢出阈值放大到不可达。
- 平移条变化不改变 Flow 正文基准排版宽度，不反向补字号、不新增 fit。避免“出现边条 → 正文变窄 → 重新排版 → 范围变化 → 边条反复出现/消失”。

**采用的几何路线：取消恒定 gutter，平移条改为按需显示的独立浮层。** 基础排版宽高来自实际宿主，边条显示与否不参与基础正文布局；不用通过让根容器每次增减18 px来释放空间。

- 必要时浮层显示在播放边缘。Flow 原生滚动条仍在自己的滚动容器内；同侧同时可见时，平移条放在相邻的独立命中带，不能遮住或劫持正文滚动条。
- 控制器及缩放面板按可见 chrome 的安全区域避让；在当前可支持视口下，边缘内容通过相应平移仍可完整查看。不能以隐藏正文滚动条或改写正文 scroll 来合并两种操作。
- 边条的显示、布局、安全区域由 PlaybackViewSession 持有同一份派生结果；Controller 读取这份结果，不能独立猜另一套18 px。
- 显示变化期间若当前边条正在拖动，按既有取消/释放 pointer capture 路径结束，不遗留透明遮罩或失效拖动状态。隐藏时如果焦点位于该条，将焦点退回播放视口，不重置课件交互焦点。

上述路线以“不常驻占位、不因观察缩放重排正文、两种滚动可分别操作”为共同约束。实施中的真实浏览器检查必须覆盖相邻命中带；仅单测 style/hidden 不足以关闭这一项。

## 5. 验收：新生成内容为主，旧样本只做兼容回归

### 5.1 样本和窗口

- **正式工具确定性新建样本**：从空工程经真实创建/authoring commands 构建普通 Flow 图文、正文互动、必要 paper 浮层和明确 viewport 提示；短/长正文以及显式 reading 是针对不同规则的变体。布局规则在生成前固定，不根据截图结果调 frame 或补空段落。
- **实际 AI 新生成样本**：经产品真实 AI 入口生成一份包含标题、解释正文、配图和一个已有局部互动的 Flow 内容，复用可用素材及组件，不引入无关付费生成。由其正式提交结果直接走编辑、试运行、整课预览、保存重开和 HTML；不得由开发者手动设置 widthMode/paperSpace 或改输出文件来取得通过。记录实际模型/配置和首轮/修复续轮结果，不用单个模型样本替代确定性约束测试。
- **旧原始样本**：仅保留必要的兼容读取和控件回归；不改内容，不制作修复版，不要求它已有的错误排版变漂亮。已有有效证据直接复用。

正式工具样本覆盖稳定产品规则，实际 AI 样本证明能力发现、调用和最终 consumer 真正接通。若生成结果失败，定位并修复对应产品默认值、工具表达、观察/反馈或 consumer，再通过正式路径复验；不将“以后让教师改课件”作为本轮出口。

以当前问题的约1574×983实际应用内容窗口，加1280×720作为基本代表；记录实际测量值和DPR，不按请求的窗口尺寸臆测。仅当这两种窗口不足以触发已知横向/纵向边界时，再补一个直接命中边界的尺寸。

每个尺寸都在**同一应用窗口保持尺寸不变**的条件下，通过真实按钮走“编辑 → 试运行 → 编辑 → 整课预览 → 返回”。导出 HTML 按同样的浏览器可用窗口检查独立播放；允许预览标题栏造成正常高度差异。

不得再次缩放应用窗口，让两个入口的内容区人为等宽后替代正常路径验收。等宽渲染检查如保留，只是辅助证据。

### 5.2 必须直接观察的结果

| 检查 | 通过标准 |
|---|---|
| 新建默认值 | 人工创建、AI/Builder 当前支持的创建路径消费同一正式默认值；普通新 Flow 显式 fluid，明确 reading 的例外按选择执行 |
| 生成工具与观察 | 生成器能读到布局上下文、经正式工具表达必要定位；已声明语义不在提交/发布时丢失，不用客户端私有补丁绕过 |

| 无需滚动 | 短正文且观察内容无溢出时，不显示任何多余滚动/平移条，不留下18 px空槽 |

| 单轴/双轴平移 | 根据真实可移动范围显示相应边条，可拖到两端；还原至无需移动时消失；100%下真实越界仍可到达 |
| 几何稳定 | 100%→200%→100%、resize、边条显隐无持续 ResizeObserver/布局振荡；仅观察缩放不改变正文基准宽度和换行 |
