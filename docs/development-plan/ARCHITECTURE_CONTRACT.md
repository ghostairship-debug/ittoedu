# 架构合同：当前必须保留的边界

开发治理以 [DEVELOPMENT](../../DEVELOPMENT.md) 为准。本页记录产品语义与工程边界，具体实现/验证程度见 [当前状态](CURRENT_STATUS.md) 和直接消费者。旧 V9/V10 命名不决定现行 wire，历史排期不自动生效。

<a id="component-platform-contract"></a>
## 1. 正式数据、保存与历史

- 当前作者工程为 Project 11，运行投影为 Published 4，组件接口为 API 5；定义见 [正式源合同](../../src/shared/contracts/component-platform/)。现行 Project 10 文件/恢复记录只在读取边界转换，保留原件，Session 与写出为 11；不得借精简扩大或取消兼容范围。
- DocumentSession 是正式作者数据与资源事务的唯一 writer。UI、内置 AI、MCP、Source/文件采用最终共用正式命令、版本检查和 History；GrapesJS/ProseMirror/DOM/截图/缓存是投影，不成为第二工程。
- 内容、作者字段、已采用源码、资源及必要依赖必须随工程保存/恢复/重开。合法未保存人工草稿进入当前读取、脏判定和保存准备；IME 或无效输入不能提交时保留并明确反馈，不丢稿。
- 同一操作只形成一次逻辑历史；保存 single-flight，保存期间继续编辑仍为 dirty。运行态、相机、观察与 UI 临时状态不写作者历史。删除聊天不删除用户文件或恢复稿。
- 晚到/异步操作保持原目标、范围、版本与生命周期，失效返回可识别结果，不写当前碰巧选中的对象。Stop 先撤销后续写权；未知副作用查原操作，不能当未执行重放。

## 2. 表面布局与深度编辑

- Slide/Spatial 保持自由 frame、编组和顺序；Flow 保持阅读顺序、响应式正文与局部自排版。统一的是内容/身份/事务，表面选择、坐标及运行语义保留差异，不建立万能 Surface 服务。
- 深度编辑按下一次真实修改划界：原生字段、Runtime 内部作者绑定、局部 Source 和文件均可使用。已知对象/文字直接带当前可写引用和最小相关上下文；动态未知 DOM 不假称自动有稳定写回映射。
- 普通局改保留范围外内容、人工位置与其他实例；需要局部适配时只改合理邻域。实例 Source 深改复用现有 COW/依赖闭包，改共享定义必须遵守已授权影响范围。
- 新建或明确重做的自由范围可用 HTML/CSS 测量装配；共享动态逻辑可保合理整体。不要求全面原生化，也不把整页/主要内容封成缺少实际编辑边界的大 Web 黑盒。人和 AI 共用当前事实，不要求每项代码能力都有人工控件。
- 能实际承载、保存和使用的内容先保真接入；局部可修问题保留原件与可修输入并明确诊断，不整份拒绝或静默静态化，不强迫模型固定源格式或手工登记标记。
- 人工点击、选中、拖动、文字/公式/表格编辑、快捷键、全局层和 Source 入口等受支持行为继续保留；恢复已确认行为可直接修，新模式或默认交互变化按方法论确认。

## 3. 运行、导航与交付

- 编排从同一作者工程产生正式 Published/Player/导出，Player 不依赖 renderer Store，Preview/Export 不反写作者数据。编辑、试运行、播放及适用导出消费一致内容/资源与布局语义。
- 全局 Underlay → 当前内容 → 全局 Overlay 的平面关系保持；全局项不与本地项逐项交错。Flow 正文、浮层、视口与观察缩放各有明确坐标 owner，不额外为控制台挤占正文安全区。
- Slide 场景状态、Flow 章节/阅读位置、Spatial 镜头/路线沿现有导航 owner。导航、键盘和已选控制台复用正式推进；新作的页内/页间衔接由创作设计承担。沉浸式推进按内容需要，线性段落可用适当文案的下一步，不能强制统一模板。
- 局部程序的存活、更新、休眠与释放沿实际宿主生命周期；内容未变不因无关投影更新重挂。真实 Source/依赖改变仍按宿主合同更新或重建，不承诺任意程序热换后保留全部运行状态。
- 保存、预览、离线 HTML、静态格式各按其正式承诺验证；不静默把动态内容静态化或删除可编辑语义。受支持的表格/图表/媒体与导出能力不得通过清理入口取消。

## 4. 执行内核、工具与权限

- 模型执行循环与领域服务分开。通用会话可以换内核；对象范围、未保存人改、Source/COW、正式事务、结果版本、停止撤权和保存仍归果铃。一个会话只设一个权威模型历史，UI transcript 可以是展示副本。
- 目标明确时传最小相关事实；批量读写、已有 Source/文件修改、子成果封存和直接采用应充分复用。目录声明、工具加载、真实模型可见性及错误恢复必须由实际消费者贯通，不能以“接口存在”冒充可用。
- 子任务材料、可写副本与声明产物角色明确；公共事实与来源引用沿已有合同传递。父 Agent 负责目标、局部差异与整体验收，软件负责闭包、物化、版本与装配，不让父模型手抄子成果。
- 已应用、观察失败、保存成功与作品合格分别保持事实。可计算要求由软件返回结果，语义与视觉仍需判断；有界停止可报告失败/未验，不把 run completed 改写为作品成功。
- 不设累计调用数、内容体积或运行总时长的任意产品门槛；保留真实供应商限制、无响应检测、主动取消、授权根、CAS与必要格式/资源检查。研究预算不成为生产限制。
- 内外入口沿现有授权，观察范围不等于 OS 沙箱。原生 Agent 经版本化适配器保留其已授权能力与原生登录；不静默提权/缩权，不复制或中转订阅凭据，不把一个渠道的成功推及其他渠道。具体接入/默认行为按执行方案与授权决定。
- 外部文件变化不等于正式提交，由既有文件/保存 owner 处理重载与冲突。candidate 只摄取合法根内 realpath 闭合、身份与版本相符的成果；失败/拒绝/迟到不产生新写入，先前已提交结果保留。
- Runtime/Component 复用现有内容权限边界；Provider Secret 不进工程、组件包、Published或导出，不授予原始 Electron Main、任意 OS 命令或未开放宿主 API。信任来源/权限没有变化时不扩建安全审批平台。

## 5. 模块职责

| Owner | 负责 | 不负责 |
|---|---|---|
| Contracts/Domain | 格式、纯规则、共同能力定义 | UI/文件系统与执行循环 |
| DocumentSession/作者领域服务 | 当前稿、资源、正式命令、History与保存事实 | 模型历史、表面临时状态 |
| Surface/专业内容 owner | 相应布局、选择及专业编辑规则 | 第二工程/History、别域 writer |
| Runtime/Player/Export | 正式投影的运行、生命周期和输出 | 作者数据回写、模型编排 |
| 执行会话/适配器 | 模型循环、会话恢复、事件与工具转交 | 再造文档事务或复制领域状态 |
| Composition root/UI | 实例化、接线、展示与输入 | 跨域业务规则、完整 Store 公共接口 |

出现真实依赖环、错误 owner、重复 writer、完整 Store 跨域扩散或共享热点阻断已批准工作时，可在相应任务中迁移职责；改后接通直接消费者并退出旧决定。只减少行数或移动文件不能证明完成，不为架构整洁单独暂停产品主线。
