## 3. 验证与停止

1. 聚焦验证对应失败机制：路径含空格/中文、完整卡不要求再发现、资源只按当前不可变请求读取；时间戳排序/失败与旧记录兼容；按钮正常/失效/重名/禁用、预算/取消及 live session 零操作。
2. 相关 Player/Renderer/Electron 制品按变化准备一次；确定性真实宿主先证明新行为，再运行命名真实 CLI 样本。基线和修改后条件固定，原始失败保留。宿主改动不影响的已通过证据继续有效。
3. 103 原关键链每 CLI 三次独立完整运行（含新建/延续）与其他本版用例至少一次的要求保留。单次成功、fixture 或工具目录可用不代表完整矩阵通过。用户等待、截图分析开销和产品耗时分列。
4. 冷启动、进程复用、更细源码 patch、模型自动路由仅在本轮分段证据表明确有收益时再决定；不预建优化平台，不自动降低用户推理强度。
5. 工程结果、实际缺口、原始制品和复用证据写入本轮实施记录；有未满足的必选门如实保留。只有 Owner 对当前制品明确签署后才能发布 `v1.8.0` accepted 标签。

实测分支（9 月 10 日）：OpenCode Luna/default 实际为 none。路径缩减后的样本分别出现 UUID 转抄/短候选结构错误，以及原生命令 workdir 语法错误；后者没有执行到环境目录读取，不算环境传递失败。停止相同条件的重复，在原生已确认支持的 high 强度运行一个相同文字任务，观察输出可靠性和耗时；配置只限该工程测试会话，不改本机默认强度，不与 none 基线混算速度。

实际阻断追加（9 月 10 日）：互动复核在候选产生前遇到 V2 会话 `.tmp → .json` 原子替换 `EPERM`，随后失败记录又能保存到同一路径；Windows 保持读句柄可复现同类错误。保留单 Repository 队列与原子写入，在该 owner 内对短暂共享占用做有界异步等待，持续失败仍保留旧文件并抛出。只补临时占用恢复、持续失败与队列顺序检查，再复核受影响互动样本；不改工程保存或忽略持久化失败。
