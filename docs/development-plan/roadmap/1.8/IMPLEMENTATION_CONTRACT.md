## 1. 用户工作流与应用策略

### 2026-09-12 真实使用修复增量

背景目标由正式背景 Owner 在当前授权范围中捕获，发现、snapshot 与执行共用其有效域；明确“本页背景”先于默认选区，发送摘要和冻结范围一致。Course/命名状态不接受独立背景模式，未指定颜色、图片及继承字段保持。快捷图片接口失败后仍允许发现并组合现有素材导入和背景命令，所有路径进入同一 canonical transaction。

G1新增[选区动作窄合同](../../reviews/2026-09-12-r18-g1-selection-contract.md)：宿主根据明确指令和实际选区捕获 `selectionActions`，只允许同owner/plane的排序、单个保真副本或真实父容器中的单张after插图；candidate不能自报授权。消费者复用正式命令与唯一事务，晚步失败零写入。Flow宽度的V9/Published strict可选字段和各门实际验收见[本轮集成记录](../../reviews/2026-09-12-r18-user-experience-integration.md)。

候选拒绝后在同一 task/epoch、原冻结目标与期限内建立新观察，原子替换被检查的请求；旧请求退役不构成任务失效，真实 Stop、草稿、工程变化和超时继续拒绝。宿主拒绝与成功结果都保留待送状态，只有原生 startTurn 确认后标为已送达；显式继续接回原目标、最新提交及失败，询问状态只解释事实。旧记录不能还原的目标或材料如实阻断，不猜测恢复。

LocalAgent V2 的同一事件日志新增 strict `user-message`，含原 `itemId`、`text` 与 `purpose:initial|supplement|correct|answer`，沿既有 task/epoch/run 身份归属；输入队列继续管理实际消费，消息事件仅保存用户原话。generate 的可选 `userMessage` 保存原始输入，与包含恢复说明的执行目标分开。公开 text 的 phase 允许 `progress`/`final`，缺 phase 的旧文本作为普通消息保留。聊天由这份日志按 run/item 合并 append/replace，不创建另一套对话事实；原始事件仅留本地日志，公开过程与候选摘要可读展示，正式宿主结果决定完成状态。

### 2026-09-11 B0/B1 授权实施增量

本批分段计时增加首条可见原生正文、资源处理起止及任务终态等实际边界，不改变任务推进和预算。既有task.execution允许可选、版本1的每原生run输入量记录：原生adapter在实际发送边界测量prompt原始UTF-8字节、prompt JSON字节、outputSchema JSON字节、其余宿主JSON字节、宿主技术JSON总量、图片传输JSON差量及实际消息/params JSON总量；明确测量边界，分项必须闭合。只存计数，原图字节/按需读取/原生历史与token用量另列，不能把≤12KiB prompt冒称模型全部上下文。旧任务无该项表示未知；记录绑定run/observation且只首见，旧strict reader遇新增字段明确失败。

连续请求将待送正式回执投影为一次workspace及各result/request/candidate身份、状态、revision前后值、summary、准确owner/item操作、资源变化与后续动作；只移除重复持久化身份和可由owner/item确定的重复地址。完整回执仍存本地，禁止用此提示投影反写工程或代替正式回执。原生启动确认后才标已送达，失败仍pending，不靠额外总结回合送达。

Owner已授权按《常规课件任务三层执行与修改方案》完成1.8的B0/B1。单纯浏览页面或换选不重定向也不取消已冻结的任务：任务继续绑定原workspace/location/state/owner/item、内容revision、资源和task epoch。所有真实工程修改、Undo/Redo、Save As、关闭/切换工程、Stop和期限仍拒绝旧候选；不能通过关闭session检查放行。提交时以正式位置、Surface、状态、owner、选择及Flow正文范围比较教师是否已浏览或换选：有变化则保留当前浏览，无变化则采用事务的结果选择，使形状转图片后可以继续修改新图片；不使用session generation或revision猜测浏览。不得替教师提交或丢弃另一页草稿。初始、拒绝修正及提交后观察均须来自同一原目标的实际宿主，离屏结果明确标为候选/预览，无法取得有效观察时如实受阻。普通人工异步编辑的既有session/目标约束保持有效。

第二层首个窄语义族为候选内的`media.apply`：strict图片输入含`kind:image`、真实文件或既有asset的`source`、可选`fit`、`placement:content|background`及`preserveResolution`；目标继续使用本request内destination短引用或完整canonical destination。文件来源只接受本轮`$candidateFile`，既有素材只接受本轮asset短引用或真实assetId；Main将已校验文件投影为内部strict字节/文件名/媒体类型。Renderer从冻结的真实目标确定图片同实例更新、合法形状替换、支持的Flow媒体更新/插入或正式背景操作，展开现有工具并进入同一私有准备和单document/resource/History事务。命名状态中的形状转换仅在当前状态隐藏原形状、显示新图片，其他状态继承关系保留；不能映射的引用仍明确拒绝。模型无需拼装导入、创建和替换步骤；闲置导入、兄弟对象及越界写入继续拒绝，共享图片其他实例不变。Native的`edit-text`、`edit-image`、`edit-formula`窄输入与旧`edit`复用同一内容Owner，Flow文字/公式复用正文Owner，保持持久化Schema不变。完整候选和既有字符串媒体导入兼容。

素材交付帮助只在原生CLI已有权限下将其工具实际返回的文件复制到当前candidate root；不授予Main任意外部路径读取。图片准备在唯一资源准备边界进行完整解码、尺寸/编码与透明度检查并优化副本，不覆盖源文件。普通图片按fit和有效显示尺寸计算2倍显示预算，长边预算为512–1024，不放大或裁剪源内容；较大的PNG仅在最大质量WebP有实质节省时转换。明确保原图及动画/SVG保留源字节。已合法交付的素材可以在同一逻辑任务内跨拒绝/修正观察复用，新观察重新物化并获得新请求引用；释放跟随逻辑任务终态/期限，同时释放展开的图片内存，保留素材不恢复旧候选或别名。具体strict类型与首个consumer共同落地，不扩Course V9或Published V2。

2026-09-11媒体文件候选补充：在现有候选传输中，仅 `asset.media.import.input.base64` 可使用 strict `{"$candidateFile":"resources/相对文件名"}`。Main 在当前任务/request/observation/epoch 校验后，只读取该 candidate root 内 realpath 闭合的非空普通文件，合计最多 12 MiB，展开为正式工具原有 Base64 字符串；读取后重验最新任务状态和期限，再交同一 proposal、Facade 与唯一资源事务。缺失、非法路径、链接逃逸或超量文件返回带步骤定位的拒绝诊断；取消、stale、迟到零工程写入。同候选重复准备复用已摄取字节，原始会话保留文件引用。旧字符串输入保持兼容，工具正式 Schema、V9 与 Published 不变；不提供通用文件 RPC，不从候选根外自动复制素材。

2026-09-10路径交付补充：三CLI的每次原生进程启动可注入仅本次的`COURSEWARE_CANDIDATE_ROOT`，值为当前已创建的候选根；原生终端子进程继承该值，OpenCode ACP客户端终端同样接线。它仅是文件定位信息，不改变cwd、权限、原生工具或候选摄取边界；不修改全局环境/用户CLI配置。初始提示以此环境变量读取`request.json`并程序化带入requestId和输出文件位置，避免手抄UUID/hash。新观察的新进程覆盖旧值；未绑定候选的进程不得继承父进程中同名旧值。

三种工作意图固定为讨论、计划、编辑；模型推理强度和修改应用策略是另外两个维度，不混用。

| 意图 | 行为 | 合法结束 |
| --- | --- | --- |
| 讨论 | 可读取当前工程、图像和必要资源，可解释/澄清；不创建可应用工程候选 | 已回答、待补充、明确受阻 |
| 计划 | 读取和分析，输出可审阅的方案；不改工程 | 方案待审阅、待补充、明确受阻；用户执行方案后才转编辑 |
| 编辑 | 默认自动应用当前已授权范围内通过校验的修改；可选先预览后应用 | 已修改、经正式检查确认无需修改、待应用、已应用但验证/记录未完成、部分完成、明确失败、已取消 |

新建会话初始意图设为编辑，控件在输入框附近可见；每会话记住模式。教师在文字中明确“先别改/只讨论/先给方案”优先于控件，宿主与CLI应在计划/候选入口共同限制；不能靠模型输出自称未修改。按Owner最终决定，1.9的044交付自动/手动流程：自动必须上传且成功读取课程材料，优先模板/设计/Recipe/组件，无需逐份审批两稿；手动依次确认教学简报、策划、呈现简报、脚本。044同步实际guard、入口与Skill路由，外部已确认稿Builder保留其停点。现有纯回复不强制变候选，但明确编辑任务返回无法修改时，显示编辑未完成而非成功。

默认自动应用只是当前scope内的正式事务授权，不包括跨课件修改、任意远程操作或超范围重设计。预览模式提供前后视觉、对象/页面列表和共享影响；相关联步骤不可拆开只接受一半。模型认为需要扩展写范围时，用可读提问说明具体范围，不能静默升级选区为整课。

## 2. 任务、观察和候选身份

沿用现有LocalAgent V2任务记录及唯一Owner；一次CLI turn不等于整个用户任务。已有strict字段继续复用，本轮新增语义由r18-090版本化演进，并迁移所有直接consumer：

| 实体 | 必须携带 | 规则 |
| --- | --- | --- |
| Task | taskId、workspace、intent、applyPolicy、授权读写范围、原始目标、当前epoch、已提交receipt引用及既有预算/终态原因 | taskId由宿主生成；epoch在停止/重定向/失效时递增；一个当前写租约；budget不因续轮或子检查重置 |
| Observation | observationId、workspace、documentRevision、draftEpoch、viewEpoch、运行session/state版本、capturedAt、内容/资源索引 | 每份不可变；结构、图片与运行结果明确来自哪个状态；viewEpoch不能代替documentRevision |
| Proposal | taskId/epoch、observationId、requestId、candidateId、正式candidate、可选验证计划及成功后finish或observe/continue意图 | 短传输先按当前request展开完整candidate；canonical target和null保留，完成声明不代替宿主检查 |
| Host result | proposal身份、检查/提交状态、before/after revision、实际变更、结构化诊断及必要证据；committed/unchanged时携带对应真实回执 | CLI completed只说明回合结束；committed证明工程写入，unchanged证明无需修改；checked/rejected/stale/failed不伪造提交回执，重复结果幂等 |
| User input | inputId、taskId、类型（补充/纠正/回答/停止）、关联question或turn | 被接收与被CLI消费分开显示；重复输入不得重复执行 |

已有generation candidate V1和canonical commands可继续作为Proposal内部的正式payload。需要升级外层generation/localAgent记录时用新version和严格迁移，不能让旧reader静默忽略新语义。旧V1会话可以查看/摘要恢复，新任务必须重新捕获观察；旧候选不能自动重放。

会话、任务、观察不进入Course Project、Published、Component/Runtime包或导出。现有V1旧记录无需因新UI不能读而丢弃；解析损坏只隔离该条。

当前完整authoring/trial/preview观察、反馈和UI已有集成；不得继续把所有输入都描述为早期generation-snapshot。实际使用source=generation-snapshot的有限兼容分支仍保留draftEpoch/viewEpoch/runtime为null、只允许preview及既有活动草稿检查，不宣称捕获了未知事实，也不以该分支替代完整观察验收。

## 3. 状态与事件

任务状态由既有LocalAgent/Generation owner中的一条状态链派生，Chat仅展示：准备观察→CLI运行→候选检查/临时验证→等待预览或提交→反馈结果→继续运行或结束。等待用户回答、服务重试、过期恢复是明确状态；不是另一套聊天私有状态机。

- 一个任务可经过多轮观察与候选；宿主只按声明式结果驱动后续输入，规划仍交给同一CLI原生会话。
- CLI收到的是用户目标、观察和结果，不是宿主另一模型编造的计划。宿主不主动调用第二模型总结可读事件。
- 增量正文与终态正文按原生item identity去重，并依据item/phase/type分流。机器candidate增量不进入可读正文，只在完整终态验证后进入候选路径；普通讨论中的JSON仍可阅读。公开摘要/计划、工具结果、最终回复、用量分别投影，不获取不可用的原始推理。
- 提问必须能从UI回传；中途补充在原生支持的下一处理边界进入同一任务。不能继续以busy禁用发送来声称实时交互。
- 所有中途事件和终态均携带任务/epoch。乱序缓存有界；重复candidate/receipt不会重复写；不属于当前任务的事件只归档，不驱动当前工程。
- 截断/超限、服务错误、协议错误、候选格式错误、能力不支持、过期、准入失败、目标未达成分开报告。
- 本地停止立即让当前epoch失效并停止本任务拥有的原生进程/回合；已完成的先前事务保留，未提交内容清理。不得杀用户另开CLI或编辑器进程。

原生进程error/退出/主动close须结束并清空所有待处理请求，不能只终止事件队列而让open/配置/启动永久等待。各阶段等待有界；关闭幂等且不因进程已退出跳过Promise清理。恢复句柄必须是原生确认的externalSessionId，临时本地ID不能冒充；原生身份与唯一Harness持久化一致，缺失或冲突不静默新建另一会话。

格式修复沿用一次有明确诊断的修复；无进展按首个失败建立基线、其后连续两次无实质进展停止。依据错误类别、目标、资源/源码实质变化、诊断和实际成果；随机candidateId、注释或summary变化不算进展。普通有进展的多步创作不是格式重试。

### 3.1 结束、回执送达与失败

| 实际情况 | 唯一任务状态与动作 |
| --- | --- |
| auto检查通过、实际committed、必要证据满足、回执已保存且声明finish | main/renderer/AiTask一致进入已完成并持久化；UI展示回执支持的变化，不另开总结推理 |
| 正式检查确认目标已满足并返回unchanged，回执已保存且声明finish | 显示无需修改；不增revision或Undo，不将任意空候选当成功 |
| preview已检查但用户未应用 | 候选待应用、零提交；finish尚不生效 |
| preview用户应用且完成条件满足 | 保存committed或正式unchanged回执后结束 |
| 已提交但尚有具体后续阶段/必要观察 | 保存回执，按受影响范围观察后继续同一CLI任务 |
| prepare/apply失败，stale、取消或拒绝 | finish不生效；当前未提交阶段零写，保留既有已完成部分并给出明确结果 |
| 工程已提交但回执持久化失败 | 保留进程内已知receipt，只重试回执/状态保存；显示已应用但记录未完整，不再提交工程 |
| 旧adapter缺完成元数据 | 沿已有有预算的兼容路径，不推定任务完成 |

完整终态须由既有GenerationTaskController、main harness、AiTask guard/repository和投影共同消费，不能让feeding-back遗留成永久待续行。已持久化的回执和终态支持重开；提交后、回执未落盘即崩溃的状态只可按当前工程事实核实，未知明确显示，不自动重放相对修改或补造回执。

本地先保存真实回执，再确保后续原生请求获得该事实。Codex无推理追加接口须先验证当前adapter/版本的角色、身份、幂等与恢复；不支持时持久标记待送，下次真正请求前带入。无推理追加不是三CLI完成的共同前置；未送达不得标记已写原生历史，失败不触发重复提交或必需总结轮。

结构化失败沿AuthoringToolFailure→prepare→controller→LocalAgentHostResult→AiHostResult→下一原生输入完整保留：阶段/步骤、错误码、目标/asset、committed事实、revision、字段路径、可执行恢复信息、实际帧/动作/状态与已完成部分。新增字段在同一strict合同演进，不压成泛化“验证失败”。replacement-unmappable维持引用映射原意，不拿它表示意图越界。

### 4.1 活动草稿

### 4.2 三层同源信息

- 结构：scope/owner/位置/步骤/选择/可见性/锁定/样式、文本、资源ID、包与实例、共享影响。

## 5. 按需能力与资源：助手和Builder共用

唯一能力定义仍由正式Authoring Tool、Schema、支持矩阵和运行consumer产生。内容分三个层次，但不是固定三轮查询：

1. 精简入口：能力ID、简短用途、适用Surface/carrier/读写范围、发现入口和版本。
2. 能力卡：该操作完整输入Schema、允许目的地、所需依赖、最小有效示例、验证和限制。
3. 引用资料：相关资产、组件/Runtime协议、源码包、特定导出语义及诊断。按需读取，不能在每个简单任务里内联整个动态目录。

已明确选区和操作时直接附带同源小能力卡，只有需要新能力才发现；普通文字/样式/位置或公开参数修改不要求读取完整源码。096的共用数据/查询仅依赖090；095完整观察接线与三CLI实际消费在100/103汇合。

正式本地查询按关键词/任务类型/Surface/carrier/operation/mode及写域过滤，一次命中返回可用的完整卡、引用、示例与错误诊断；帮助入口独立正确处理。组件instance/shared和scene/Flow实例等模式域来自正式支持矩阵，不把工具顶层global误当所有模式的范围。不依赖另一个模型路由，不建手写第二目录。index.json和小入口由同一生成器产生，按内容版本失效缓存。

目标任务的最小调用信息应在一次发现后齐备，不强制目录→卡→Schema三次交互。必要卡直接完整附带，长尾资料按需读取；简单选区初始技术说明≤12KB，原图/材料/源码单列。必要技术内容超出该样本边界时报告分项及原因，不截断关键字段，也不宣称该简单选区验收已通过。语义稳定目录跨轮复用，不嵌本轮requestId扰动公共前缀。

CLI默认读取不可变观察、小能力卡及所需材料；未选材料不自动全量发送，原图用实际image/localImage等原生输入，路径文本不等于图像。CLI仍按原生授权查文件、使用终端/网络、用户工具与Skills；默认上下文和工程scope不限制它的全部文件系统权限。能力/素材可按需继续读取，不能用prompt、cwd或工具白名单强行削弱原生能力。

外部Builder：通过同一产品发现服务及API V2受管Facade查询；不得静态import内部源码。Facade复用已有observe/readReceipts/activateScope与工具描述发现；新建构建会话写入仍走原execute/finish，不另造Builder协议。当前V2没有打开已有工程的方法，已有教师工程的增量修改由Skill转正式编辑器入口和canonical target；不能用课例模块重建覆盖人工修改，也不以不存在的Facade方法作为104验收前提。课件Build Skill只维护启动、路由和验证流程，不复制完整字段表。仓库Skill及受管安装版通过现有installer同步；个人改动按installer冲突规则处理。

两份确认Markdown仍需整体了解教学目标与呈现约束；外部材料按所构建片段读取，不能把省token变成删内容或跳过教师确认。104保留现有编排门；1.9的044迁移内置自动/手动入口，手动及外部已确认稿路径保留分阶段确认，自动以材料前置和授权范围约束。045提供材料结构、摘要/搜索和页/片段/图片读取。

## 6. 编辑与资源事务

用正式窄语义操作和构造器降低模型猜字段成本；构造器只解析当前request的已授权目标/资源引用、生成候选身份、补齐正式默认值，不能按模型文字猜项目、对象或缺失scope。构造器是同一产品Facade/生成合同的消费层，不是第二Schema或generic JSON patch。

本轮strict短传输只压缩重复身份和默认值：局部target/asset别名由当前request绑定canonical target、revision、sessionGeneration及task epoch；宿主展开后仍进入既有完整candidate解析、精确destination校验和Facade。未知别名、跨范围、过期绑定拒绝，不从当前活动选区补猜。工具参数仍取正式Schema；短/完整传输须产生相同业务效果及Undo。afterCommit仅表达成功后finish或有理由的observe/continue，不授予新写域；不适用短投影时继续完整载体。

- Native文字/样式/位置修改和Flow正文修改走各自Owner。
- 选区替换允许创建实现同一目标所需的资产/新载体，但必须显式列出replacement目标及附带create scope；不等于授权修改其他页面。
- 替换由一个prepare阶段解析所有依赖和引用，再经单一document+resource transaction提交。步骤失败时老对象、老资源引用和历史保持完整；不能先删旧对象再尝试创建。
- 默认保留尺寸、位置、order、visibility、rotation和适用的交互引用；跨carrier不可表达字段必须产生明确迁移诊断，不静默丢交互。共享资源只改所选实例时创建新资源引用，不能把整课共用图片一起染色。
- 新建ID经正式factory或前序receipt引用产生；不能要模型猜UUID、package版本或稳定地址。
- 动态候选继续经过编译、协议、依赖/素材闭包、origin、生命周期、资源上限、静态后备和真实宿主；Native/Recipe/Existing Component仅承担自身已规定门。
- 每一完整替换是一个原子事务；同一长任务可含多个明确阶段事务。失败/Stop只保证当前未提交阶段零写，先前已提交阶段必须在结果里列出“部分完成”，不能称整个任务零写。

普通属性/公开props只传本次改变，宿主保留未提及字段并补正式默认值；一组相关变化不拆成逐属性历史。当前多步候选、$result及component.package的instance/shared patch、changedFiles/deleteFiles已存在，应先接齐提示、发现和consumer。源码增量带精确基线，由宿主补齐完整候选再进既有修订/闭包/事务；不对V9开放generic patch，也不把代码只留暂存。新增strict传输字段按独立合同提交。

共用Builder和Authoring Tools沿既有候选批量prepare/commit端口复用。完整页面或自洽互动单元可以逐阶段出现，沿手动确认稿或自动材料条件与scope执行；无需为此新增live工程接口、第二History，或在应用内启动外部Vite/第二浏览器。

## 7. 图片变换与动态验证

r18-098复用已有asset.image.transform和确定性像素实现；当前优先修坏PNG正例及诊断贯通。现有变换创建新asset，并在同一事务更新所选Native content或Flow media引用；它不是selection.replace。保留原资产、其他共享实例、节点身份与未要求的属性。原坏PNG字节保留负例，修正生成器后只重建受影响正例；不得把损坏输入与有效图像的耗时直接比较。有效1×1红图与含文字/透明区域图像分别验证，禁止绿色文字、shape或遮盖冒充改图。

颜色替换采用确定性像素运算，颜色容差、alpha保留和输出格式在该节点落到strict输入合同与fixture；不引入新Provider Secret或依赖未安装图像服务。用户没有给精确色值时使用产品默认绿色并报告；局部目标不清时才问具体范围。复杂语义生成式修图由当前CLI真实可用图像工具提供额外能力，未具备时明确说明，不冒充确定性改色已覆盖所有修图。

Runtime翻滚立方体用真实连续机制；候选临时宿主运行并给出时间点截图/错误/动作结果，不能仅生成静态立方体封面。针对效果的验证与静态安全准入分开：准入成功说明可执行，目标验证说明符合需求。

候选验证只使用当前任务确实需要的有限宿主动作和采样，复用已有位置/步骤、公开操作、捕获与状态接口；新增动作须对应真实用例，不建设通用断言DSL或验证解释器。检查只在候选副本/临时宿主运行，结果保存于同一任务；必要观察/修复时送回同一CLI，满足finish时按3.1终结并采用无推理追加或待送机制；Native和普通公开参数修改不强制生成独立验证计划。每次列明有限动作/采样与预计等待，执行受现有任务剩余预算和宿主timeout共同约束，累计等待不能借重开子检查而重置。超过预算返回未完成及已有证据；不操作教师live session，不增加任意脚本口。

099区分纯图层几何、公开参数、代码与共享接口变化，按真实影响走已有门。已有实例/共享patch和就地修订继续复用；仅用户目标确需载体转换时才selection.replace。普通包装层/位置变化或停用Runtime不一律要求完整动态准入。首次生成完整门及受影响门保留；代码、资源、配置和宿主依赖未变的证据可复用，但参数变化后的行为仍需对应检查。lifecycle smoke成功不证明任务语义满足，requires-review不得抹掉。失败worker/smoke保留实际已采集帧、动作、错误与状态，未采到的明确为空。

## 9. 三CLI和UI对等

r18-088先验证实际能力，不只看版本主号。所有adapter向UI提供同一概念能力，但不硬编码相同数值：模型列表、可用effort、图片/文件读取、当前mode、stream/steer/question/cancel、usage。配置状态必须以原生确认结果为准；模型变化时清除失效effort并采用该模型实际默认。

流式正文、公开摘要、计划、工具活动、提问、候选/提交/验证均用可读组件；机器候选及协议信封走数据/诊断通道，正常JSON或代码讨论保持可读。默认界面同时显示模型/effort、意图、读写范围和同步状态。任务期间可输入补充、纠正和回答；待用户动作不淹没在日志末尾。所有重要状态可通过键盘和读屏获取。

Codex outputSchema在同协议版本、同传输模式内保持稳定，requestId值保留于输入/信封并由宿主严格相等校验；candidate/auto分支可以不同，两处身份检查均须保留，不固定旧目标换缓存。用量按真实嵌套tokenUsage.last/total分别投影，保留input/output/cached/reasoning及原生提供的cacheWriteInputTokens，unknown=null。按原生事件身份/序列去重，turn只关联计量边界，不能整轮只留一条usage；同turn的多次有效累计更新继续接收。adapter、strict事件、投影、repository、diagnostic和UI一次贯通；累计值不重复相加，缓存输入不另算总输入。旧扁平假wire测试不足以证明修复。模型和Schema调整的缓存/耗时收益由固定有效配置的对照确认。

### 9.1 原生能力与应用边界

完整原生CLI加GUI为长期架构。相同账号/模型/配置/工作上下文与授权下，保留文件、终端、网络、用户工具与连接、Skills、子任务和循环。GUI回传真实原生授权决定；讨论/计划/编辑约束用户当前目标及工程提交，不作为工具白名单，不默默扩大用户授权。产品不另建MCP/通用工具RPC或自建模型循环，原生CLI已有连接仍可用。

090/091与三adapter保全当前已集成的原生cwd、环境、非秘密配置、文件/终端、工具和授权能力，不把历史只读/白名单/拒绝授权的旧probe断言为当前事实。新增变更不得恢复这些限制，也不得通过环境过滤意外移除代理/工具发现。GUI消费实际协议，保留允许、拒绝与取消，不造通用权限平台；相关行为改变才更新有限probe。

candidate root只限定宿主摄取realpath闭合候选，与CLI原生文件工具权限分开。编辑器修改仍必须经过canonical事务；原生工具修改外部磁盘工程不能冒称画布/History已提交，由既有打开/保存Owner处理必要重载与冲突。CLI拥有的终端/文件权限不传给生成的Runtime/Component。
