# 1.8–2.0 AI 创作共同实施合同

本合同用于[当前开发方案](../../AI_ASSISTANT_DELIVERY_PLAN.md)的088–104及后续1.9/2.0节点。首批已有本地strict类型、V2记录、原生transport及宿主接线；2026-09-08[审查](../../reviews/1.8-first-batch-review.md)确认恢复身份、失败收口、模型配置和Flow可达性仍须修复，按[首批执行包](FIRST_BATCH_EXECUTION.md)关闭反例。以Owner当前决定、正式Schema/架构合同及可复现事实为上位依据。Course Project保持V9、Published保持V2；本地AI协议可独立版本化，不把对话/观察写进课件。

## 1. 用户工作流与应用策略

三种工作意图固定为讨论、计划、编辑；模型推理强度和修改应用策略是另外两个维度，不混用。

| 意图 | 行为 | 合法结束 |
| --- | --- | --- |
| 讨论 | 可读取当前工程、图像和必要资源，可解释/澄清；不创建可应用工程候选 | 已回答、待补充、明确受阻 |
| 计划 | 读取和分析，输出可审阅的方案；不改工程 | 方案待审阅、待补充、明确受阻；用户执行方案后才转编辑 |
| 编辑 | 默认自动应用当前已授权范围内通过校验的修改；可选先预览后应用 | 已应用并验证、已应用但验证失败、待预览应用、部分完成、明确失败、已取消 |

新建会话初始意图设为编辑，控件在输入框附近可见；每会话记住模式。教师在文字中明确“先别改/只讨论/先给方案”优先于控件，宿主与CLI应在计划/候选入口共同限制；不能靠模型输出自称未修改。按Owner最终决定，1.9的044交付自动/手动流程：自动必须上传且成功读取课程材料，优先模板/设计/Recipe/组件，无需逐份审批两稿；手动依次确认教学简报、策划、呈现简报、脚本。044同步实际guard、入口与Skill路由，外部已确认稿Builder保留其停点。现有纯回复不强制变候选，但明确编辑任务返回无法修改时，显示编辑未完成而非成功。

默认自动应用只是当前scope内的正式事务授权，不包括跨课件修改、任意远程操作或超范围重设计。预览模式提供前后视觉、对象/页面列表和共享影响；相关联步骤不可拆开只接受一半。模型认为需要扩展写范围时，用可读提问说明具体范围，不能静默升级选区为整课。

### 1.1 创作流程与后续UI

创作流程（自动/手动）与工作意图、应用策略和EditorMode分别表达。成功读取指有效原件、整体结构和本次教学范围所需文字/图像已实际取得；未读片段保留缺口，只有影响本次教学目标才阻断，不另存“全材料已理解”状态。自动缺材料/坏材料不能生成，提示上传或切手动；手动依次确认教学简报、策划、呈现简报和脚本，不跨未确认阶段。切换流程保留工程和已提交成果，以新观察继续；普通局部修改不反复上传或重走教研。模板不适配时允许现有动态生成，内容和源码/资源可编辑性不能牺牲。

1.8完成当前工程编辑和必要教师交互；1.9实现材料/双流程及聊天主工作台。启动进入聊天首页，左侧项目/会话列表，中部对话；选已有工程显示其当前真实画布，新建在首个完整画布产物提交后显示。默认极简模式支持拖动、图文、参数和对象局部AI，专业模式保留完整手工能力及相同AI；主聊天操作页面、场景或整课。两模式复用工程、任务和History。2.0将材料处理、设计、构建、实际QA、修复、保存与导出全部在软件内闭环。

## 2. 任务、观察和候选身份

在现有LocalAgent会话中增加版本化任务记录；不再让一次CLI turn等于整个用户任务。新记录至少表达以下事实，具体命名在r18-090落到正式strict Schema，随后各consumer唯一复用：

| 实体 | 必须携带 | 规则 |
| --- | --- | --- |
| Task | taskId、workspace、intent、applyPolicy、授权读写范围、原始目标、当前epoch、已提交receipt引用 | taskId由宿主生成；epoch在停止/重定向/失效时递增；只有一个持有写租约的当前任务 |
| Observation | observationId、workspace、documentRevision、draftEpoch、viewEpoch、运行session/state版本、capturedAt、内容/资源索引 | 每份不可变；结构、图片与运行结果明确来自哪个状态；viewEpoch不能代替documentRevision |
| Proposal | taskId/epoch、observationId、requestId、candidateId、正式candidate、可选验证计划 | ID通过宿主提供的正式构造器形成；candidate仍完整携带canonical target，不丢null字段 |
| Host result | proposal身份、检查/提交状态、before/after revision、receipt、实际变更和诊断 | CLI completed只说明模型回合结束；host receipt才说明工程写入；重复结果幂等 |
| User input | inputId、taskId、类型（补充/纠正/回答/停止）、关联question或turn | 被接收与被CLI消费分开显示；重复输入不得重复执行 |

已有generation candidate V1和canonical commands可继续作为Proposal内部的正式payload。需要升级外层generation/localAgent记录时用新version和严格迁移，不能让旧reader静默忽略新语义。旧V1会话可以查看/摘要恢复，新任务必须重新捕获观察；旧候选不能自动重放。

会话、任务、观察不进入Course Project、Published、Component/Runtime包或导出。现有V1旧记录无需因新UI不能读而丢弃；解析损坏只隔离该条。

首批迁移保留当前手动预览应用能力：现有generation snapshot以source=generation-snapshot记录，draftEpoch/viewEpoch/runtime为null，不宣称实时草稿/视觉已捕获；只允许preview策略，沿用既有提交时活动草稿检查。095完整观察及101新UI到位后采用已定的默认auto。未知版本不填0，不能把迁移分支当T01/T07或完整观察验收通过。

## 3. 状态与事件

任务状态由既有LocalAgent/Generation owner中的一条状态链派生，Chat仅展示：准备观察→CLI运行→候选检查/临时验证→等待预览或提交→反馈结果→继续运行或结束。等待用户回答、服务重试、过期恢复是明确状态；不是另一套聊天私有状态机。

- 一个任务可经过多轮观察与候选；宿主只按声明式结果驱动后续输入，规划仍交给同一CLI原生会话。
- CLI收到的是用户目标、观察和结果，不是宿主另一模型编造的计划。宿主不主动调用第二模型总结可读事件。
- 增量正文与终态正文按原生item identity去重；公开摘要、计划、工具调用/结果与用量保留类型。无需获取或展示不可用的原始推理。
- 提问必须能从UI回传；中途补充在原生支持的下一处理边界进入同一任务。不能继续以busy禁用发送来声称实时交互。
- 所有中途事件和终态均携带任务/epoch。乱序缓存有界；重复candidate/receipt不会重复写；不属于当前任务的事件只归档，不驱动当前工程。
- 截断/超限、服务错误、协议错误、候选格式错误、能力不支持、过期、准入失败、目标未达成分开报告。
- 本地停止立即让当前epoch失效并停止本任务拥有的原生进程/回合；已完成的先前事务保留，未提交内容清理。不得杀用户另开CLI或编辑器进程。

原生进程error/退出/主动close须结束并清空所有待处理请求，不能只终止事件队列而让open/配置/启动永久等待。各阶段等待有界；关闭幂等且不因进程已退出跳过Promise清理。恢复句柄必须是原生确认的externalSessionId，临时本地ID不能冒充；原生身份与唯一Harness持久化一致，缺失或冲突不静默新建另一会话。

格式修复：沿用一次有明确诊断的候选修复；身份随机变化不算进展。普通多步创作不是格式重试。连续两个候选在实际变更/诊断/目标上无进展时停止并给出原因；有可观察进展的任务可在用户可见预算内继续。预算耗尽显示未完成和可恢复点，不能伪装成功或无限烧token。

## 4. 当前课件观察

只读观察来自正式内存文档、Surface作者投影和真实Player/作者宿主，不读上次保存文件替代内存，不增加第二renderer。

### 4.1 活动草稿

选区/当前页/整课观察同时包含活动文字草稿及draftEpoch，标明与正式documentRevision的关系。开始写候选前由既有草稿Owner通过现有提交准备完成草稿冻结/提交；不得绕过原Owner直接拷贝DOM到文档。如果教师继续打字，draftEpoch改变，旧候选不得覆盖。讨论允许观察草稿而不强迫保存工程或把讨论变成工程修改。

### 4.2 三层同源信息

- 结构：scope/owner/位置/步骤/选择/可见性/锁定/样式、文本、资源ID、包与实例、共享影响。
- 视觉：当前页面和相关对象截图、原始图片资产、viewport/缩放/裁切/渲染就绪状态。观察使用实际作者/试运行/预览模式标签，不能用另一个宿主截图冒充。
- 运行：仅现有公开状态/生命周期/错误/资源与测试动作结果；Runtime内部无法观察的私有变量不能猜。动画以多帧和行为证据判断。

先捕获结构版本，再等待对应渲染完成后关联图像；若期间版本变化则丢弃这组图像重取，或清楚报告待同步。文件字节可缓存复用，但画面变换和运行状态改变仍需新观察身份。

关注选区和任务目标分离。切页/换选择更新可见上下文，不隐式更改已绑定任务目标；显式“改这个”才能重新授权。如果现有canonical session token因导航失效，使用最新会话重新prepare同一稳定目标，不改旧candidate字段强行通过。

## 5. 按需能力与资源：助手和Builder共用

唯一能力定义仍由正式Authoring Tool、Schema、支持矩阵和运行consumer产生。生成三个层次：

1. 精简入口：能力ID、简短用途、适用Surface/carrier/读写范围、发现入口和版本。
2. 能力卡：该操作完整输入Schema、允许目的地、所需依赖、最小有效示例、验证和限制。
3. 引用资料：相关资产、组件/Runtime协议、源码包、特定导出语义及诊断。按需读取，不能在每个简单任务里内联整个动态目录。

已明确选区和操作时直接附带同源小能力卡，只有需要新能力才发现；普通文字/样式/位置或公开参数修改不要求读取完整源码。096的共用数据/查询仅依赖090；095完整观察接线与三CLI实际消费在100/103汇合。

正式本地查询按关键词/任务类型/Surface/载体过滤，返回稳定ID与可读文件位置；不做依赖另一个模型的路由，不建立手工维护的第二工具清单。`index.json`作为现有consumer兼容入口保留，新增精简发现入口由同一生成器产生。内容版本变化时显式失效缓存；不把“文件最新mtime”当能力语义兼容证明。

CLI默认读取不可变观察、小能力卡及所需材料；未选材料不自动全量发送，原图用实际image/localImage等原生输入，路径文本不等于图像。CLI仍按原生授权查文件、使用终端/网络、用户工具与Skills；默认上下文和工程scope不限制它的全部文件系统权限。能力/素材可按需继续读取，不能用prompt、cwd或工具白名单强行削弱原生能力。

外部Builder：通过同一产品发现服务及API V2受管Facade查询；不得静态import内部源码。Facade可以按需暴露工具描述与当前scope，新建构建会话写入仍走其原execute/finish。当前V2没有打开已有工程的方法，已有教师工程的增量修改由Skill转正式编辑器入口和canonical target；不能用课例模块重建覆盖人工修改，也不以不存在的Facade方法作为104验收前提。课件Build Skill只维护启动、路由和验证流程，不复制完整字段表。仓库Skill及受管安装版通过现有installer同步；个人改动按installer冲突规则处理。

两份确认Markdown仍需整体了解教学目标与呈现约束；外部材料按所构建片段读取，不能把省token变成删内容或跳过教师确认。104保留现有编排门；1.9的044迁移内置自动/手动入口，手动及外部已确认稿路径保留分阶段确认，自动以材料前置和授权范围约束。045提供材料结构、摘要/搜索和页/片段/图片读取。

## 6. 编辑与资源事务

用正式窄语义操作和构造器降低模型猜字段成本；构造器只解析当前request的已授权目标/资源引用、生成候选身份、补齐正式默认值，不能按模型文字猜项目、对象或缺失scope。构造器是同一产品Facade/生成合同的消费层，不是第二Schema或generic JSON patch。

- Native文字/样式/位置修改和Flow正文修改走各自Owner。
- 选区替换允许创建实现同一目标所需的资产/新载体，但必须显式列出replacement目标及附带create scope；不等于授权修改其他页面。
- 替换由一个prepare阶段解析所有依赖和引用，再经单一document+resource transaction提交。步骤失败时老对象、老资源引用和历史保持完整；不能先删旧对象再尝试创建。
- 默认保留尺寸、位置、order、visibility、rotation和适用的交互引用；跨carrier不可表达字段必须产生明确迁移诊断，不静默丢交互。共享资源只改所选实例时创建新资源引用，不能把整课共用图片一起染色。
- 新建ID经正式factory或前序receipt引用产生；不能要模型猜UUID、package版本或稳定地址。
- 动态候选继续经过编译、协议、依赖/素材闭包、origin、生命周期、资源上限、静态后备和真实宿主；Native/Recipe/Existing Component仅承担自身已规定门。
- 每一完整替换是一个原子事务；同一长任务可含多个明确阶段事务。失败/Stop只保证当前未提交阶段零写，先前已提交阶段必须在结果里列出“部分完成”，不能称整个任务零写。

普通属性/公开props只传本次改变，宿主保留未提及字段并补正式默认值；一组相关变化不拆成逐属性历史。源码增量必须带精确包/源码基线，显式声明新增/修改/删除文件，由宿主补齐完整候选后进入既有包修订/资源闭包/唯一事务；不得对V9开放generic patch或把代码只保存在暂存区。相关strict输入变化仍按独立合同提交。

共用Builder和Authoring Tools沿既有候选批量prepare/commit端口复用。完整页面或自洽互动单元可以逐阶段出现，沿手动确认稿或自动材料条件与scope执行；无需为此新增live工程接口、第二History，或在应用内启动外部Vite/第二浏览器。

## 7. 图片变换与动态验证

r18-098实现正式宿主图像变换能力：替换指定颜色/保留透明度、按范围或mask处理、裁切/尺寸等当前明确需求。输入引用现有资产和明确操作，输出新资产及可追踪变更；原图和非目标像素内容保留。一个1×1红图变绿与含文字图片局部改色必须分别验证，禁止纯色遮盖/替换成shape冒充图像修改。

颜色替换采用确定性像素运算，颜色容差、alpha保留和输出格式在该节点落到strict输入合同与fixture；不引入新Provider Secret或依赖未安装图像服务。用户没有给精确色值时使用产品默认绿色并报告；局部目标不清时才问具体范围。复杂语义生成式修图由当前CLI真实可用图像工具提供额外能力，未具备时明确说明，不冒充确定性改色已覆盖所有修图。

Runtime翻滚立方体用真实连续机制；候选临时宿主运行并给出时间点截图/错误/动作结果，不能仅生成静态立方体封面。针对效果的验证与静态安全准入分开：准入成功说明可执行，目标验证说明符合需求。

候选验证只使用当前任务确实需要的有限宿主动作和采样，复用已有位置/步骤、公开操作、捕获与状态接口；新增动作须对应真实用例，不建设通用断言DSL或验证解释器。检查只在候选副本/临时宿主运行，结果回同一CLI；Native和普通公开参数修改不强制生成独立验证计划。每次列明有限动作/采样与预计等待，执行受现有任务剩余预算和宿主timeout共同约束，累计等待不能借重开子检查而重置。超过预算返回未完成及已有证据；不操作教师live session，不增加任意脚本口。

099区分纯图层几何、参数、代码和共享接口变化，按实际影响选择验证。首次生成完整准入与所有受影响门保留；编译/准入证据仅在代码、资源、配置、宿主依赖匹配时复用，参数合法性和受影响行为仍验证。不能将不同参数的运行结果当作本次行为通过，也不能关闭准入来降低等待。

完整原生CLI加GUI为长期架构。相同账号/模型/配置/工作上下文与授权下，保留文件、终端、网络、用户工具与连接、Skills、子任务和循环。GUI回传真实原生授权决定；讨论/计划/编辑约束用户当前目标及工程提交，不作为工具白名单，不默默扩大用户授权。产品不另建MCP/通用工具RPC或自建模型循环，原生CLI已有连接仍可用。

candidate root只限定宿主摄取realpath闭合候选，与CLI原生文件工具权限分开。编辑器修改仍必须经过canonical事务；原生工具修改外部磁盘工程不能冒称画布/History已提交，由既有打开/保存Owner处理必要重载与冲突。CLI拥有的终端/文件权限不传给生成的Runtime/Component。
