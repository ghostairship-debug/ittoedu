# 1.1 Gemini 执行者指南

> 生效日期：2026-09-03；当前起点：`1bdcb3f`。本指南只约束 1.1 剩余实施卡。完整拆卡蓝图见 [GEMINI_EXECUTION_PLAN.md](GEMINI_EXECUTION_PLAN.md)。

## 1. 执行方式

1. 一次只执行任务板上的一张卡；不要提前做下一卡。
2. 先读卡中列出的目标函数、直接调用方和目标测试，不通读无关目录。
3. 只修改 `Write scope` 明列的文件。需要新增卡外文件、公共类型、兼容层、Facade 或 re-export 时停止并报告。
4. 缺陷卡先写卡中指定的一个失败场景，再修复；纯迁移卡不额外造红测试，复用最近层现有测试。
5. 每卡最多执行两类验证：一条目标测试命令，以及 TypeScript 产品代码发生变化时的 `npm run typecheck`。卡另有明确要求时总数仍不得超过三条。
6. 实施阶段禁止运行 `npm run test:product`、`npm run verify`、`check:preservation`、`check:legacy-zero`、候选 Hash、文件 Hash 或整仓字节比较。这些只在全部实施卡完成后由 Codex 最终复查一次。
7. 保持每个被编辑文件原有的换行符；仓库并非统一 CRLF。不要做换行符归一化。
8. 每卡形成一个可回滚提交；任务卡与实质改动放在同一提交，不再创建单独的“关闭卡”提交。

## 2. 什么算完成

- 缺陷卡：指定竞态或错误场景通过，旧场景仍通过。
- 迁移卡：实现与 writer 已进入指定 Owner，旧位置同一实现已删除；不能用代理函数、re-export 或双写过渡。
- 测试迁移卡：受支持行为仍有 V9/V2 测试；V8 只保留明确的拒绝场景。
- 删除卡：只删除上一卡给出的精确零 consumer 清单，不凭文件名判断。

文件行数、目录数量、Hash 相同、关键词存在或单纯“编译通过”都不能单独证明完成。

## 3. 最小验证规则

| 改动 | 每卡验证 |
|---|---|
| 单个缺陷 | 指定测试文件；产品 TypeScript 改动再跑 `npm run typecheck` |
| 单一 Owner 搬迁 | 该 Owner 最近层测试；`npm run typecheck` |
| 纯类型归位 | `npm run typecheck`；至多补一个直接消费者测试 |
| 纯测试迁移 | 只运行被修改的测试文件与它引用的 V2 替代测试 |
| 精确旧文件删除 | `npm run typecheck`；该删除组的一条最近层测试命令 |
| 最终集成 | 由 Codex 按 r11-055、060、061 各运行一次，不由 Gemini 提前运行 |

测试失败时只原样重跑一次。仍失败就停止，报告首个失败；不得增加 retry、timeout 或改弱断言。

## 4. 禁止形态

- 新建第二 Store、Session、History 或持久化文档。
- 把完整 `EditorState`、raw `get/set` 或完整 Store hook 传给 Feature。
- 新文件只包装旧函数，旧 writer 仍保留。
- 为通过结构测试而添加白名单、改关键词、改文件名或保留无效字符串。
- 删除入口、测试、Surface、导出格式、Runtime/Component 或用静态占位替代动态内容。
- 修改 V9 / Published V2 wire，恢复 V8 导入，或创建 V10。

## 5. 停止条件

出现以下任一情况，停止当前卡并只报告事实：

- 卡中的目标符号不存在，或直接 consumer 数量与卡不一致。
- 需要修改卡外文件才能编译或保持行为。
- 需要决定产品能力、Schema、导出语义或用户数据迁移。
- 指定测试在产品改动前已经通过，或失败原因不是卡描述的问题。
- 最近层测试出现与当前改动直接相关的新失败。

## 6. 交接格式

```text
卡号：
结果：完成 / 停止
修改文件：
目标测试：命令 + 通过/失败摘要
类型检查：通过 / 未运行（纯文档或纯测试）
停止原因或剩余问题：无 / 精确说明
提交：<sha>（仅完成时）
```

不要粘贴完整日志、Hash、全仓扫描 JSON 或测试输出全文。

## 7. 最终复查边界

Gemini 完成实施卡后停止。Codex 再执行：

1. r11-055：审查实际 diff、Owner 边界和两份结构测试；
2. r11-060：运行一次现有 Legacy zero scanner；
3. r11-061：运行一次 `typecheck`、一次 `test:product`、一次 `check:preservation`；
4. 有失败则回到最小责任卡，不在最终门现场改断言求绿。
