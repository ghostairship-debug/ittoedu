## 7. 验证成本、模型与候选准备

当前规划不执行下列命令。后续实施先查看 package.json 与目标 spec 的门控／配置：
- npm test 有 pretest build:player；npm run test:e2e 有多项 fixture/build 前置；npm start 会安装受管 Skills 并构建。不得为一次小改重复整套准备，不执行 npm run dev 作为验证捷径。
- 类型入口实际为 npm run typecheck；可直接选择受影响的 tsc project。局部测试用 npx --no-install vitest run <实际文件> -t <命名用例>；已有必要构建后用 npx --no-install playwright test <实际spec> --grep <命名用例>。尖括号是占位，不能照抄执行。
- verify:fast / verify:product 并不存在。generate/check 能力、合同、Player/renderer/electron 仅在变化涉及它们时准备；一次有效生成和校验后不紧接同义重验。
- 060 才汇合完整候选验证。npm run verify 会进入全 E2E，先审全部真实调用门控、模型、可复用范围与运行环境，不盲跑；不能为绿而排除必选路径。必要拆分执行时记录等价完整覆盖。
- 开始实现后的真实模型依根 AGENTS 约束：Codex/OpenCode 只用实际 Luna，默认 Fast；Claude 使用已确认 DeepSeek 路由，Fast 不支持则普通速度如实记录。不凭显示别名认定路由；不能换模型追绿。当前用户“只规划”覆盖既往测试许可，本回合不调用。
