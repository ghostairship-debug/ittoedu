# 1.9 教师可用性与前端专项实施方案

日期：2026-09-17。状态：**方案已编写，产品实现未开始；供其他 AI 接手。**

## 1. 目标、优先级与完成含义

Owner 决定：为完成 1.9 验收，先解决教师不会用、入口无反馈、材料不能方便编辑等问题，集中完成已确认的前端形态，不再逐处修补旧布局。当前阶段是前端专项，包含让新界面真实可用所必需的文件、会话与宿主接线；不是整套产品或 AI 底层重写。

本专项成功意味着：教师从真实工作空间开始，不必先创建课例；能够组织项目与会话、添加和使用材料、编辑真实文档、理解生成进展、进入原生编辑器并保存、重开和运行作品。界面达到已确认 V3.1 的视觉和布局要求。之后进入 1.9 剩余真实组合验收，**前端完成不等于 050、060 或整个 1.9 已完成**。

优先顺序：数据与核心操作正确 → 主要路径可发现、可完成 → 视觉与布局达到已确认设计 → 必要的错误恢复。一次专项交付完整形态，可以按可运行批次内部集成；不要求一口气替换所有代码。

## 2. 已确定的产品合同：不要重新问用户

| 事项 | 本次必须达到的行为 |
|---|---|

## 5. 实施结构与生命周期

### 5.1 唯一状态来源

- 应用布局状态只保存停靠方向、宽度、收展与工作位置；可本地持久化，不放进 V9，不持有正文或课程副本。
- 工作空间／项目／会话身份由 main 正式记录 Owner 提供，renderer 只投影；阶段状态来自既有流程 Owner。
- MD 当前稿、磁盘版本和恢复物继续由文档 session 管理；不能在标签或材料卡再存一份可编辑正文。
- h5lesson 使用唯一工程、资源事务与 History；工作台轻编辑和完整编辑器调用同一命令。
- 正在执行的任务始终绑定发送时目标／版本／epoch。浏览、折叠、改布局不重定向任务；切根目录等目标变更走现有取消／失效流程。

### 5.2 导航与文件合同的最小扩展（F01 先落地）

建议职责形态：`工作空间身份 + 可选项目目录身份 + conversationId` 表示会话归属；`真实文件引用 + 当前版本` 表示文档；工程 target 继续使用正式 projectId/revision/sessionGeneration。实际 TS 类型由 F01 沿现有 schema 定义，禁止其他包自行复制 DTO。

工作空间的规范化根路径、项目的根内真实路径、稳定身份及会话归属必须可重开；同名不同目录不混淆。新增项目可以关联已有 lesson 身份，不能给同一课例制造两套会话库。不得为了支持普通文件夹而把工作空间根目录改造成课例或强制写四阶段文件。新建项目只有明确教育创作时才激活教育流程；无项目教育任务的默认产出可位于根目录，但必须先展示实际产出位置，不能静默创建隐藏项目。

复用当前记录存储和 IPC；仅增加实际 UI consumer 需要的操作。共享 strict schema、main、preload、renderer 直接 consumer 在一个可运行批次接通。保存位置与 AI 工作权限是两件事，不可用项目目录替代工作空间权限根。

### 5.3 稳定挂载与工作位置切换

完整编辑器和工作台共享同一编辑器实例；优先用稳定 React 树及布局容器实现移动／收展，不按工作位置重新创建 Store、文档 session 或工程。若组件重挂载不可避免，先证明场景、状态、选择、缩放、草稿与 History 在正式 Owner 中连续，不能把“保存后重开”当连续切换。

关闭内容区是隐藏，不是关闭有草稿文件；关闭文件标签才触发 close/flush/recovery。恢复内容区回到最近实际文件。生成结果可提供“查看结果”，不得重置用户停靠方向或突然夺走当前编辑焦点。启动页没有打开文件时不显示空白课件。

### 5.4 状态与反馈要求

| 场景 | 用户应看到／能做什么 |
|---|---|
| 缺材料／缺输入／CLI 未就绪 | 主动作旁说明缺什么并给直接入口；不能只有禁用按钮 |
| 自动创作 | 模式选项写“自动推进”；明确主按钮“根据已选材料开始创作”；一次点击进入真实 start，不以 set-mode 成功充当任务开始 |
| 运行中 | 显示当前实际动作、已用时间、输出／文稿入口和停止；无估算基础不展示百分比或剩余时间 |
| 阶段完成 | 打开／定位实际当前稿；手动模式分别确认四阶段文件及版本，自动模式不新增逐稿审批 |
| 等待授权／输入 | 显示真实等待原因及操作；不能被归类成无限生成中 |
| 失败／停止／中断 | busy 正确结束，已完成文件保留，可编辑；重试针对失败步骤，不能默认重做所有阶段 |
| 已提交但后续失败 | 分别说明“已应用的内容”和“未完成的后续步骤”，不得称完全失败或全部成功 |
| 布局或会话切换 | 页面连续；任务不可串到新文件／新工作空间 |

不要通过延长超时、屏蔽错误或循环轮询来修复无限转圈；定位正式任务终态及 renderer 清理链。CLI/模型设置作为可发现的设置入口，不占据教师开始任务的主要空间；本轮不改模型默认策略。

### F01｜工作空间、项目与会话的真实接线

- 结果：工作空间可直接会话；指定／新建文件夹成为项目；项目分组对话可重开；跨根／跨项目不会串会话或 AI 目标。

- 动作：扩展归属而非复制旧系统；实现无项目会话、项目列表／会话加载、新会话、切换／重开；保留现有课例身份、首次保存与 Save As 语义；删除对话不得删除文件。
- 权限：核对 native adapters 的工作目录和授权配置，复用原生能力实现已确认范围；不把字符串前缀检查当完整外部权限约束。遇到某通道确无所需原生能力，报告具体缺口，不能宣称隔离已完成，也不扩大为新平台。
- 合同：同步修正文档中“所有对话必须归课例”的旧入口描述，保留工程目标与会话归属区分；不改变 V9。
- 最小检查：①无项目会话创建、重启续接；②两个同名项目各有独立会话，首次保存与切根目标不串；③新增路径／IPC 的越界和失败反馈及相关原生权限映射检查。权限实效若未能在实际通道证明，列为独立缺口，不用 UI 测试代替。
- 退出：接口与直接 consumer 可运行，不把 lesson schema 全量改名成通用产品框架。

### F02｜视觉基础与自由布局外壳

- 结果：真实应用采用 V3.1 暖纸面设计；侧栏／内容按需收展、尺寸及四向停靠可用，偏好重开保留。

### F03｜资源管理器、项目会话导航与内容标签
