# 内容模型、编辑合同与统一设计语言

本文是[统一架构方案](README.md)的设计语言。Owner 已授权实施，正式 Schema/API 增量见[架构合同 §1.2](../ARCHITECTURE_CONTRACT.md#12-统一内容布局与应用2026-10-03)，实际覆盖见[实施记录](EXECUTION_LOG.md)。本文的概念字段用于说明职责，不要求模型手写新协议，也不以目标设计冒称所有编辑能力均已完成。

## 1. 产品对象与术语

### 1.1 工作台对象

| 用户概念 | 工程含义 | 边界 |
|---|---|---|
| 空间 | 文件、会话及工作上下文的组织范围 | 不成为每份文件内容的第二 owner |
| 文件/作品 | 用户实际打开、修改、保存的对象 | 文件路径、文档身份、视图状态分离 |
| 会话 | 与 Agent 的交流与任务记录 | 不拥有文件内容；删除会话不删除作品 |
| 任务 | 一次有目标的执行，可包含创作与行动 | 冻结必要权限/目标，沿用已有 run 生命周期 |
| 视图 | 编辑、阅读、预览、运行或网页交接的显示位置 | 视图不是文档副本；切换视图不新建历史 |
| 结果 | 本次生成、应用或保存的实际产物 | “已生成”“已应用”“已保存”分别来自真实状态 |

课件、HTML、Markdown、Office、PDF 和图片都以文件/作品进入工作台；网页是任务关联的外部会话。共用打开、定位、状态和返回任务，不强行共享内部内容模型。

### 1.2 课件内容对象

| 用户术语 | 内部职责 | 常见操作 |
|---|---|---|
| 演示页面 | 有限页面及展示顺序，沿用 Slide 的分页/步进语义 | 新建、排序、改尺寸、播放 |
| 连续文档 | 自然阅读流与嵌入内容，沿用 Flow 语义 | 输入、插入、章节调整、打印 |
| 空间 | 世界坐标与相机，沿用 Spatial 语义 | 放置、连线、缩放、编排视点 |
| 容器 | 组合子内容并管理外部排列 | 横排、竖排、网格、自由摆放 |
| 元素 | 可独立选取的文字、媒体、形状或 Web 结构 | 修改内容、样式、排列 |
| 专业对象 | 保有数据或领域含义的图表、表格、公式等 | 改数据、改公式、专业属性 |
| 组件 | 可复用的定义与具体实例 | 插入、改参数、编辑此实例/共享定义 |
| 互动区域 | 由程序控制的内容边界 | 运行、改参数、可靠图文编辑、编辑源码 |
| 资产 | 已保存的模板、片段、组件或媒体 | 查看示例、插入、提取复用 |

内部的 Native、Runtime、Surface、Published 保留技术用途，常规界面不要求用户理解这些名称。组件不因采用 Web 实现而显示为低一档的对象；控件只呈现当前确实能持久保存的操作。

### 1.3 状态表达

- 生成中：展示过程或临时预览，不能暗示已写入文件。
- 已应用：正式文档/文件编辑状态已经改变；是否保存单独显示。
- 已保存：由文件服务确认实际保存；失败时保留可恢复内容并说明原因。
- 运行中：作品或网页正在执行，不等于任务仍在生成。
- 等待操作：显示具体站点、所需动作和继续入口；不要求用户理解内部暂停屏障。

底层回执与诊断继续记录真实 ID、revision、异常；普通聊天和状态条只展示用户能采取行动的信息。

## 2. 正式内容模型

### 2.1 一个组合文档，不同内容 owner

建议课件在现有正式工程内承载下列概念：

```text
课件工程（现有身份、资源、历史）
├─ 组织：页面 / 连续文档 / 空间
├─ 内容组合
│  ├─ 容器：子项关系与布局
│  ├─ 正文：沿用共享正文的段落、inlines、表格等语义
│  ├─ 专业对象：沿用 Native 数据，按需扩展呈现
│  ├─ Web 结构：元素结构、属性与样式规则
│  └─ 程序实例：源码/依赖或包引用、参数与合法持久数据
├─ 样式：作品样式、局部规则、组件作用域与实例覆盖
├─ 资源：现有素材及组件包引用
└─ 播放语义：现有导航、步骤、状态与事件
```

“组合”表示跨内容类型可布局、可选择、可调用对应编辑命令；不要求所有段落都变成 LayerItem，也不复制一份 Flow AST 到通用树。正文内部由正文模型拥有，组合容器只拥有它的放置关系。已有专业字段有唯一 owner，不再抄写到 Web 属性中维护第二份值。

| 内容种类 | 正式来源 | 派生物 | 持久编辑写入 |
|---|---|---|---|
| 正文/专业对象 | 正文 AST、图表数据、公式、媒体引用等 | DOM/SVG/Canvas、文字测量 | 对应专业内容命令 |
| 结构化 Web | 保存的元素/样式结构；无法理解但需保留的语法片段 | 运行 DOM、计算样式、几何 | 元素结构与真实样式声明 |
| 程序区域 | 源码/包、数据、参数及其明确绑定 | 程序创建的 DOM/Canvas、瞬时状态 | 可定位源码、数据/参数；不能只改临时 DOM |
| 组件实例 | 共享定义引用＋实例内容/参数 | 实例渲染树 | 明确修改实例或定义 |
| 原始导入材料 | 来源/恢复副本 | 仅供查看/重新显式导入 | 不自动覆盖已编辑的正式工程 |

结构化 Web 的内部实现可采用可序列化语法树/组件树；优先保留标准元素、属性、CSS 声明和未知语法，不先缩减为几种卡片模板。浏览器支持呈现而面板尚未支持编辑的 CSS 可以继续保存与运行，提供源码编辑。此处的“支持范围”约束编辑操作，不能被误用成整份导入白名单。

### 2.2 HTML/CSS 在三个阶段的地位

1. **创作时**：标准 HTML/CSS 是模型熟悉的表达方式，正文与专业组件可通过简短用例组合；不要求输出宿主身份或登记表。
2. **落地时**：软件解析并建立可编辑结构；专业对象使用已有内容模型；复杂行为保留到实际能维持行为的程序边界。
3. **编辑后**：后续 AI 从当前正式结构生成的上下文/源码投影继续修改；早期 HTML 不再是覆盖依据。

未指定规格的教师演示默认按 1280×720 设计；长文优先连续正文/Flow，明确要求的其他规格优先。默认作用于任务方法与软件交付，不要求模型填写 Surface 身份或内部转换参数。

对于结构化区域，“编辑源码”打开的是当前正式结构的序列化结果，提交后重新解析并在一次事务内更新同一区域；不是另存一个长期同步文件。对于程序区域，源码本来就是正式来源。源码无法解析时保留用户草稿与正式可用版本，不抹掉先前成功结果。

**重解析不等于重建全部身份。**软件保留未替换节点、容器和实例的内部身份，并维护样式/源码到正式对象的对应；普通改字、改 CSS、移动节点不能令 scene 覆写、互动目标、Spatial 关系或 AI 选区失效。局部源码修改优先在已绑定范围中更新，确定对应关系才沿用身份，不让模型填 ID，也不按相似文案猜配两个对象。确实删除/替换内容时，同一事务按既有删除语义处理其引用；无法可靠对应且会破坏实际连接时保留该区域的当前可用版本，指出需重绑的具体关系或缩小修改范围，不静默悬空、不拒绝其他独立可用区域。

### 2.3 样式所有权

布局、外观、内容样式可以共存，但同一属性不能由两个独立正式字段竞争：

- Web 的 `display/grid/gap/width` 等声明就是对应布局属性的正式来源；面板是其可理解投影，不再维护另一套等价 `layoutJson` 双写。
- 原生/正文容器的布局字段由软件序列化为 CSS/布局输入；生成的 CSS 不作为独立可写来源。
- 专业节点的数据/图表样式由节点拥有，外层容器的列宽/位置由父容器拥有；组件内部样式由组件定义或显式实例参数拥有。
- 用户改共享类时显示影响范围；默认“仅当前对象”建立有明确归属的局部声明，不能不断追加无法追溯的覆盖补丁。
- CSS 层叠、继承、媒体规则及变量保持真实顺序。属性面板无法无歧义表示的值显示其来源并允许编辑对应规则，不任意用计算像素覆盖原声明。

作品已有设计 token 可以作为共享颜色/字体/间距来源；用户/模型仍可自由设置。软件 UI 的主题 token 与作品主题分开，不引入一次全软件换肤工程。

### 2.4 内容、视图、运行与任务状态

| 状态 | owner 与生命周期 | 是否进入作品保存 |
|---|---|---|
| 内容、布局、组件参数与作者设定 | 正式文档及其历史 | 是 |
| 选择、观察缩放、编辑面板位置 | 文档视图/工作台 ViewState | 按已有视图偏好保存，不混入作品内容 |
| 当前答题值、模拟进度、运行 DOM | 播放实例及既有课程状态 | 仅按明确运行数据合同持久化，不能因测量回写工程 |
| Agent 进度、等待、取消、工具回执 | 当前任务/执行器 | 存任务记录，不成为课件节点 |
| 程序源码与专业事件规则 | 所属内容/组件定义 | 是，运行时状态与源码分开 |

标准导航、步骤和对象互动继续复用已有动作/Interaction 协议；程序内部逻辑留在程序区域，通过实际开放的接口联动。不能为统一外观在原互动上方加一套独立原生按钮，形成两个互不一致的状态机。编辑撤销针对作者修改，播放复位针对运行实例，两者不混用。

## 3. 导入、生成与续改流程

### 3.1 从无目标导入第三方 HTML

```text
用户选择 HTML 或要求“把它做成可编辑课件”
 → 软件准备目标和文件位置
 → 解析可直接承载的结构、资源与实际依赖
 → 建立可编辑结构；无法可靠拆分部分保留程序区域
 → 用现有事务应用、保存
 → 展示作品、已保存位置及具体可编辑范围
```

输入不要求 `section`、私有标记、固定模板或预登记文字。已有明确页面结构可以机械拆分；无法确定分页时优先保留一份可用内容，不猜测删除、截断或拆坏共享脚本。只有用户确实需要分页且存在多种有意义结果时，再由人/模型决定。

全局选择器、跨区域 JS、DOM 顺序依赖与共享状态可能要求保留整个文档为程序区域。区域大小应由实际依赖决定，不能为“原生占比”拆碎内容。是否能提升为结构化编辑是后续能力，不能成为首次成功导入的前提。

资源地址按实际来源基址解析。可打包资源进入既有资源服务；允许的远程依赖保留其真实运行要求。缺一个可修复素材时保留其他可用部分并定位问题，不宣称离线完整，也不整份拒绝。新增外部运行权限只按真实需要处理，沿用现有来源/权限边界。

### 3.2 创作新作品

软件先绑定结果类型与目标；专业 Skill 提供材料、必要方法与少量合适例子。模型产生完整内容与视觉/互动表达；软件接收并应用。普通 Web 结构无需被模型重新翻译为内部节点参数。

专业对象可由共享正文/数据表达，或使用软件提供的组件短示例。只有模型选择复用该对象时才读取对应内容参数；ID、资源地址映射、版本绑定由软件生成。外部 HTML 不必知道这些约定，也不因没有专业对象标识而不可导入。

首次实现选一种已有通道完成内容生成与应用，不并行发明多种生成协议。长输出流写入当前任务暂存内容，完整可解析结果才应用到正式对象；不将半个 JSON/HTML 段落误报为可保存结果。过程预览不拥有独立历史。

### 3.3 人工修改后再用 AI

- 选区身份由软件绑定，模型主要看到当前内容、上下文样式和有意义的可编辑范围。
- 当前内容已含人工修改；不回读最初提示词对应的旧 HTML 作为主来源。
- 保持未请求的相邻内容、布局和实例状态。局部输出通过同一区域的内容 owner 应用。
- 生成期间若正式目标已变化，最终事务不能覆盖后来的编辑。软件沿用最终版本检查并重新提供当前上下文；不能无依据自动重放可能带外部副作用的动作。
- 简单内容变更不要求模型携带 revision、完整工程 JSON 或内部 operationId。

### 3.4 动态内容的编辑边界

| 来源 | 可持久修改方式 | 不成立的做法 |
|---|---|---|
| 静态元素/内联样式 | 修改正式结构/声明 | 只改渲染 DOM 后当作保存成功 |
| 模板数组生成的卡片 | 定位对应数据项/模板源码 | 改一个结果节点后下一次刷新恢复 |
| 组件公开参数 | 修改实例参数 | 把渲染出来的文字复制成平行原生文本 |
| JS 写入的结果/答题反馈 | 修改控制它的源码/数据，或真实支持的持久覆盖合同 | 猜测某次结果文字是静态模板 |
| Canvas/WebGL | 组件参数、领域数据或源码 | 把截图中的图形当作已恢复原生对象 |

现有持久轻编辑机制可以在其实际合同范围继续使用；迁入新结构化区域时，由该区域的正式内容接管，避免同一文字同时被结构、源码和覆盖表分别写入。

## 4. 布局合同

### 4.1 两种布局责任

| 类别 | 正式保存 | 软件计算 | 适用 |
|---|---|---|---|
| 自由布局 | Native 等领域节点保存作者 frame/旋转；Web 保存 CSS 定位、尺寸和变换声明 | 变换、命中、吸附、Web 测量 frame | 图示、精确摆放、空间地图 |
| 自动布局 | 子项顺序、容器布局、间距、比例、尺寸约束与响应式规则 | 子项 frame、换行、内容高度 | 正文、卡片、栏布局、可适应尺寸的页面 |

坐标系统继续用于自由设计、渲染、拾取与组件内部数学空间。新增的是持久排版关系；自动区域测量结果只做可失效缓存，不作为第二种可独立编辑的正式 frame。自由 Web 元素也不额外保存可写 frame，例如 `left:10%; width:40%` 的正式来源仍是 CSS；拖拽按实际单位和作用域修改该声明，不静默改为另一份像素坐标。

固定教室演示页的普通自由摆放直接使用 px；内部正文与分栏继续使用浏览器自动布局。已有比例声明保留其单位；仅当前受影响的复杂表达不能换算时提示像素覆盖或保留规则编辑，不在普通拖拽中逐次确认，不扩成多设备断点求解器。

基本表达优先复用 CSS 的 block、flex、grid、尺寸约束与自由定位。首个切片实现竖排/横排或网格中的必要部分，但保留标准 Web 样式表达，不重写一个与浏览器竞争的完整约束求解器。

### 4.2 父子尺寸合同

父容器给出可用尺寸与排列规则；子内容提供自然尺寸、最小/最大尺寸、宽高比或按宽度求高度的能力。文字依宽度排版；媒体可保持比例；图表/互动接收实际显示尺寸但保有自己的数据坐标与状态。

不支持自动测高的程序区域保留明确高度/比例，由用户或作者设置。不能用反复截图、无限重测或强制所有程序具有同一种尺寸协议来掩盖缺口。字体/图片实际就绪、内容变化和目标规格变化触发相关区域测量；选中、缩放等观察动作不触发内容重写。

### 4.3 人工编辑如何写回

| 用户动作 | 自由布局 | 自动布局 |
|---|---|---|
| 拖动元素 | 改父坐标中的位置 | 改顺序/容器，显示实际插入位置 |
| 拖动栏间分隔 | 改相关自由尺寸（适用时） | 改列比例/宽度规则 |
| 拉宽文字框 | 改框宽，内部重排 | 改该项宽度/伸缩约束，不硬写所有相邻坐标 |
| 改间距 | 调整选定位置或适用间距命令 | 改容器 gap/padding |
| 改长文案 | 在原框内按已有策略排版 | 自动增长/换行，影响相邻排列 |
| 跨容器拖动 | 换父级并转换坐标 | 修改父子关系，采用目标容器规则 |
| 自由摆放 | 保持所属内容 owner 的自由定位表达 | 显式脱离自动排列，保留当前外观为起点 |
| 加入自动排列 | 放入目标容器并移交外部几何所有权 | 按目标规则重新排列 |

脱离自动布局是一项明确操作，可撤销；不在普通拖动时默默把整棵树绝对定位。多选包含不同布局时，提供对这些选中项真实有意义的操作；不将所有对象套进同一坐标批处理。

一次拖动可以有连续本地预览，结束时一条语义事务；排版变化本身不追加无数历史。用户撤销恢复设计关系与内容，而不是逐个恢复测量像素。

### 4.4 四个尺寸概念

| 概念 | 示例 | 改变时的行为 |
|---|---|---|
| 作品规格 | 页面 1280×720、A4、有限空间范围 | 显式修改设计规格；按作品策略重排/缩放 |
| 目标呈现尺寸 | 投影、手机 390 宽、打印可用宽度 | 响应式内容按规则重排 |
| 编辑窗口尺寸 | 打开侧栏、调整工作台分栏 | 默认调整可见范围/适配缩放，不改固定作品 |
| 观察变换 | 放大、平移、Spatial 相机 | 不改内容布局或组件数据 |

连续文档可以显式选择“随视图宽度排版”；固定页面默认等比适配。响应式预览控件改变目标宽度，缩放控件只改变观察。宿主不得因测量、重排或观察变化额外重建程序实例、清空参数或重置教学进度；程序自身的 resize 行为按源码与状态合同执行。发现第三方程序主动重置时定位并修复具体逻辑，不建设任意程序状态猜测/恢复系统。

**浏览器视口必须真正绑定目标规格。**普通 DOM 容器变窄并不会自动让其中的 `@media`、`vw/vh` 采用这个容器尺寸。建议页面/文档的排版根使用独立渲染文档与浏览器 layout viewport，首选扩展已有隔离文档承载；Native 的 DOM/SVG/Canvas 投影在该边界内合成，编辑控件在外层映射坐标。保留程序文档可有自身的嵌套 viewport，不逐元素创建浏览器实例。Flow 的内容高度与视口高度分别管理；Spatial 的卡片使用自身明确的布局规格。

首个切片就检查标准媒体查询和视口单位在两种目标尺寸下生效；打开侧栏与外层观察缩放不得误触这些规则。不能将任意第三方媒体查询自动改写为容器查询，也不能用改变 Electron 整页缩放代替作品观察变换。浏览器语义依据：[MDN Viewport concepts](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/CSSOM_view/Viewport_concepts)。

### 4.5 命中、层叠与混合渲染

选择框与指针映射必须使用真实布局结果，并依次处理工作台缩放、Surface 相机、容器和组件局部变换。内容看起来正确但点击位置错误，仍是不合格结果。

新增可布局区域优先使用上述作品渲染文档内的统一 DOM 合成边界，Native 内容可以嵌入 DOM/SVG/Canvas 子视图。Canvas 内部层级由程序拥有；跨 Canvas 与 DOM 的任意逐像素交错不能先行承诺。现有 global/surface Underlay/Overlay 保持明确 owner；不借统一布局改变教师控制器的归属和可见规则。

## 5. 三表面与画布规格

### 5.1 共同能力与保留语义

| 组织方式 | 共享的内容/编辑 | 保留的专属语义 |
|---|---|---|
| Slide | 自动容器、自由元素、专业对象与组件 | 页面/场景顺序、步骤、演示状态与导航 |
| Flow | 正文、媒体、自动容器与嵌入自由区域 | 阅读顺序、滚动、章节、正文环绕与打印分页 |
| Spatial | 自由放置的对象、自动卡片/页面与组件 | 世界坐标、相机、视点/路径和关系 |

“横向两栏＋图表”可在页面、连续文档或空间卡片中复用；其外部尺寸由所在组织提供。Flow 中的段落继续是正文，不逐段成为全局图层。相机移动不写回所有空间对象坐标。

跨组织复制/转换保留能够直接表达的内容；分页、阅读次序和镜头叙事需要明确策略，不提供虚假的无损切换按钮。

### 5.2 尺寸演进

本轮已实现 Slide scene 的可选 `canvas` 页面覆盖；surface.canvas 保持共享层参考尺寸，用户翻动的演示页对应 scene，不新建 Surface 来冒充单页尺寸。`effectiveSceneCanvas` 提供当前页有效规格；共享对象使用共同 contain 映射/逆映射，播放和导出按实际格式处理。课程默认规格的修改仍同步已有 surface 参考值，不新增第二个独立可写默认规格。

这是新产品/持久化语义，需同步修改 V9、Published 的尺寸一致约束及真实 consumer。先完成单页布局和持续编辑，再交付该扩展；不把目前已经有的自定义宽高重复列为新能力。

自由页面改规格时提供“保持大小/位置”与适用的“整体缩放”策略；自动容器按可用空间重排。混合页面的策略按容器执行，不把一个统一 scale 强加给正文与物理模拟。

**共享浮层必须有自己的参考规则。**本方案推荐：Slide 的 global/surface shared 自由层统一以作品默认页面规格为参考，显示到某个 scene 时按当前页规格等比适配并居中；共享项仍只存一份参考几何。选择框、拖拽、命中、Player 和导出使用同一个正/逆变换，拖拽写回共享参考坐标，不生成每页副本。教师控制器继续保持唯一身份与可见性，换页只调整显示映射，不复制或重置组件。Flow/Spatial 的既有浮层挂靠/相机规则不被此 Slide 策略重解释。若实际页面要求边缘锚定或可响应布局，由共享容器明确表达，再替换该容器的适配方式；不能在各 consumer 中各猜一次。

## 6. 编辑、播放与导出

编辑视图、试运行、整课播放消费相同正式内容和布局规则。它们的选择框、观察工具和目标规格可以不同，不能各有一套独立的页面排版解释。

| 输出 | 使用同一来源的方法 | 必须说清的结果 |
|---|---|---|
| HTML/课件包 | 发布结构、资源与运行代码；保留支持的响应式和互动 | 实际离线/联网要求、程序可运行性 |
| PNG/PDF | 按明确规格与状态排版/分页后输出 | 固定结果，不声称保留互动 |
| PPTX | 专业文字/图片/表格/图表映射为目标对象；程序按支持范围处理 | 哪些对象仍可编辑，哪些被静态呈现 |
| DOCX | 连续正文、表格等走文档语义映射 | 正确阅读/分页，不能把长页缩成一张小图 |
| Spatial 静态输出 | 明确选择相机视图、区域或组织好的页面 | 无限空间没有唯一“整页尺寸” |

复杂 CSS/滤镜/程序行为无法映射 Office 原生对象时，在具体对象层说明输出方式；不拒绝整份可用文档，也不默默把本应可编辑的文字都截图。是否接受某种降级由具体交付要求决定。

不同尺寸的页面导出到只支持单一页面规格的格式时，需要选定输出规格与适配策略；不能假设文件格式支持课件所有尺寸规则。导出不反向修改作者工程。

## 7. 资产定义、实例与复用

| 资产 | 正式保存内容 | 替换/编辑单位 |
|---|---|---|
| 页面模板 | 页面组织、布局、样式、示例内容和依赖 | 标题、图文、局部组件等真实槽位 |
| 布局片段 | 容器关系、结构样式与可替换内容 | 子内容与尺寸约束 |
| 专业图示 | 专业数据/几何及适用说明 | 数据、标注、显示参数 |
| 互动组件 | 定义、源码、公开参数与依赖 | 实例参数/数据及明确的源码修改 |
| 媒体 | 真实素材与必要元信息 | 资源引用、裁剪/适配 |

提取过程先由用户/模型选择边界和用途，软件整理依赖及实例化关系。没有必要把任意子树自动变为组件，更不自动上传或发布资产。

默认插入是一个可独立编辑的实例。修改实例与修改共享定义分开；更新共享定义时明确当前工程中会受影响的实例，跨作品更新不偷偷传播。组件参数、作者持久数据与一次播放的临时状态分离。

复用时提供少量预览、适用场景、可变内容和短例子；不向模型倾倒完整库。对陌生素材与缺少匹配的任务，允许自由创作。结构化片段与程序组件均可有价值，不能用原生比例当作品质量分数。

## 8. 统一交互语言

### 8.1 同一对象，同一动作

- 画面、结构树和属性面板共享选择身份；正文内部仍保留文字选区。
- 高频内容编辑就地呈现；布局属性归容器，专业属性归对象，源码入口归确实有源码的区域。
- 菜单、快捷条、AI 卡调用同一命令；“AI 修改”绑定当前正式对象，不新建平行按钮/图层代替原内容。
- “运行”进入交互模式，避免拖动编辑误触答题；退出后恢复编辑选择。运行状态按现有实例生命周期管理。
- 常用操作不可用时说明具体原因与可行入口，例如“此图由程序绘制，可修改参数或源码”；不把内部异常直接丢给用户。
- 直接编辑保留键盘操作、焦点与语义阅读顺序；视觉排序改变时同步考虑真实内容顺序，不能只有 CSS 画面换位。

### 8.2 不同视图共享外壳，保留内部职责

| 视图 | 应提供 | 不因嵌入而自动获得 |
|---|---|---|
| 任务网页 | 当前网址、交接原因、人工操作、返回任务 | 作品 writer、编辑器 preload、Provider 凭据 |
| HTML | 预览、真实可持久编辑、源码/结构定位 | 任意动态程序的完全原生编辑 |
| PDF | 页面导航、缩放、按实际实现的页操作/批注 | 任意正文重排与 Office 等价编辑 |
| 图片 | 缩放、裁剪、旋转、实际像素保存 | 无损历史永久嵌入所有格式 |
| Office | 原格式操作、结果查看、保存状态 | 从一次脚本接入自然获得完整桌面编辑器 |

任务网页的人工操作与自动化必须针对同一个页面实例。将外部 Edge 换成工作台内嵌页需要实际后端接线，不能仅画一个 WebView 当作完成。Provider OAuth 与任务网页登录分别按真实协议运行。

## 9. 关键不变量与待验证选择

**应固定的不变量**：唯一正式来源；软件维护机械元数据；自动布局坐标及 Web 测量坐标为派生值；作品视口与目标规格一致；所有直接 consumer 同批切换；不静态化可运行互动；不要求第三方输入专有标记；格式专业语义不互相吞并。

**用首个切片验证的实现选择**：Web 结构/样式解析库；结构化内容与专业节点的 DOM 合成方式；复杂脚本保留边界；可靠的源码定位范围；目标尺寸变化时程序实例的稳定性。优先复用成熟基础库和既有 owner，不在本方案预定 GrapesJS 或整套编辑器替换。

**应在扩大范围前明确的产品决定**：正式 Schema 变更范围与现存工程读取政策；按页规格覆盖；各格式的真实编辑/导出承诺。建议和受影响位置已列入实施方案，当前文档不自动授予这些实现权限。
