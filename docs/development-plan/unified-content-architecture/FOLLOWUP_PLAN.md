# 统一内容架构评审后的修改计划

日期：2026-10-03。状态：**F00–F06 功能修正及 F07 工程闭环、真实首稿对照已收口为工程候选；整体创作质量不弱于裸稿尚未获得充分证据，F08 保持后续增强范围。**

本计划接续 [重构实施方案](REFACTOR_PLAN.md)，依据 [Claude 评审](../reviews/2026-10-03-unified-content-plan-review.md)、对当前源码的独立核查及 Owner 在本会话中的质量标准纠偏。现有工程候选、已通过的证据和工作树改动保留；本文件不将评审意见自动视为 Owner 决定，不改变已签收的旧 2.0 状态。

## 1. 修改目标与成功标准

完成当前融合方案的关键缺口：普通原创内容能形成“可编辑静态结构＋专业内容＋独立局部互动”；人能持续修改布局，软件处理几何、资源、身份、准入及保存；自定义页面尺寸的直接消费者使用正确尺寸。

2026-10-03 调整：本轮核心结果是当前页面上的直接编辑和选中内容的 AI 精修。弹窗为深入编辑入口，不能替代主画布操作；已有布局互转和单位处理服务于此结果，不继续扩大复杂 CSS 求解范围。教师演示未指定规格时默认 1280×720，长文优先 Flow；明确的竖屏、长页和自定义规格继续有效，由软件选择载体并机械组装。

- **创作质量是相对标准**：同模型、同用户提示词、同素材与目标规格、相近生成预算下，新路径不弱于裸写 HTML。两路共同出现的模型缺陷不判为重构失败；新路径特有的问题需要观察、比较和定位，不能仅凭一个样本认定架构造成退化。
- **承载与编辑分别证明**：导入前后没有新增损失，不能单独代替相对创作质量比较；底层能运行嵌套 Runtime，也不能代替普通创作入口能够生成该结构。
- **分工继续有效**：模型负责内容、视觉、布局意图及互动程序。软件负责身份、资源闭包、包装、几何换算、准入、事务、历史与保存。Skill 给方法和短例子，不把宿主协议参数交回模型。
- **导入以可用为先**：独立局部互动是增强路径；普通 HTML、整页程序及共享脚本继续保真进入现有载体，不要求所有输入采用同一创作写法。
- **验证按变化选择**：每个包使用最低成本的直接检查；已有且未受影响的证据继续有效，不重复全矩阵，不增加模型评分平台或一般正确性 Hash 门。
- **验证不另设任务额度**：不在对照脚本添加输出 token、模型请求次数、工具调用次数或总执行时长上限；沿用实际产品设置与供应商能力。目录不可读或未列已授权别名只记录诊断，由真实请求记录实际支持情况。已有受限实验如实保留，不以截断结果判断创作质量或导入失败。

本轮优先补真实功能与既有架构的直接消费者。完整桌面 Office、任意第三方程序拆解、通用 CSS 求解器及新的资产平台不进入本计划。

多执行者实施时，唯一集成者持有共享合同、核心命令、Gateway 及集成写域；稳定叶子按精确非重叠路径分配。原任务卡沿用，实施时才更新当前写域与任务板，不为规划另建调度体系。

存档按可运行的改动边界组织：内容模型、布局、直接编辑与 Player 的相互依赖同批；浏览器、PDF/图片、Office 的独立改动可分别形成提交。每批实质修改与必要合同、生成物和证据一起存档，不创建流程空提交、不拆出不能保存运行的中间版本。现有工作树保留；本轮尚无 Git 提交或发布授权。

## 3. 修改包

### F00 路由配置与事实记录

**已知问题**：`scripts/quality/unified-content-comparison.ts` 仍指定 `deepseek-v4-flash`；四次实际响应是七月版。既有测试说明与 10 月 1 日记录已经明确 `deepseek-flash` 的 V4.1 路由依据，主因是执行未落实规则。

**修改**：

1. 将本脚本的后续请求 ID 固定为 `deepseek-flash`，纠正 `actualVersion` 的错误解释；记录请求 ID、实际响应型号、路由及真实计费类型，不将别名存在性当成版本正确性。
2. 在 Q03 报告追加事实勘误，保留原始请求、响应、耗时和作品；不把历史旧版调用改写为 V4.1。
3. 同步计划、实施记录及任务结果的质量判定：共同内容缺陷不等于软件工程失败，也不能直接证明相对质量失败。2.555 秒只表示修复稿的后续交付链，不包含 Agent 创作或前面的内容工具应用时间。
4. 通用模型选择规则不再加长；不改 `AGENTS.md`，不新建路由配置平台。

**修改域**：上述质量脚本、Q03 报告的勘误、`REFACTOR_PLAN.md` 质量条目、`EXECUTION_LOG.md` 及既有任务卡的相关结果；任务板由既有生成器维护。

**最小证据**：读取脚本配置和勘误，确认后续请求 ID 与历史实际响应分开记录。本包不为核对别名发起收费生成；实际响应型号由 F07 的有用途运行记录。

### F01 当前页有效尺寸与不必要的视觉阻断

**已知问题**：`slideVisualPreflight.ts` 的出界与密度判断，以及 `expandGenerationSemanticCandidate.ts` 的插图剩余空间计算，仍读课程默认画布。

**修改**：

1. 上述当前页计算统一使用已有 `effectiveSceneCanvas(surface, scene)`。共享层参考画布、课程默认及新场景模板仍按各自含义读取，不批量替换 `surface.canvas`。
2. 检查 `node-fully-outside-canvas` 的阻断必要性。纯视觉出界能被正常裁切、保存和输出时改为不阻断的 warning，准确报告不可见或裁切；真实解析失败、错误目标、缺少必要资源及不能运行仍由对应真实边界处理。
3. 不以扩大视觉预检阻止可用内容导入或交付。

**修改域**：`src/renderer/export/slideVisualPreflight.ts`、`src/renderer/authoring/generation/expandGenerationSemanticCandidate.ts`；诊断级别影响的 `exportPreflight` 直接消费者按需同步。

**最小证据**：一个针对性尺寸用例覆盖默认 1280×720、当前页 720×1280 中 y=900 的合法对象和说明后插图；较小页按真实边界处理。合法出界对象仍能输出并保留 warning。默认页的既有证据复用，不重跑无关格式。

### F02 嵌套引用清理、健康诊断与已接入路径的证据

**已知问题**：删除图层仅清顶层 Runtime 的 `nodeBindings`；健康检查漏认嵌套可执行消费者。前者是持久内容一致性缺陷，后者当前只影响信息诊断，不描述成已发生素材丢失或运行失败。

**修改**：

1. 正式删除事务通过已有动态叶子访问器清理顶层与嵌套 Runtime 对被删图层的绑定，保留其他绑定；不增加全局 Schema 拒绝门。
2. 健康检查复用现有遍历，按实际挂载和 enabled 状态识别嵌套 Runtime，保持 `asset-unused` 的原有信息语义。
3. 为已经接入但未独立证明的嵌套 document Component 新建路径补一个真实用例；若该用例发现缺陷，仅修对应生产者与直接消费者。静态组合资产不新增动态准入步骤。
4. composition 静态元素与程序区域的分类、正式编辑和 Player 行为采用一致的窄规则。明确拒绝当前载体确实不能运行的局部改动并保留草稿；能使用 Runtime 的内容进入对应载体，不做全局 HTML 拒绝。不把目前没有普通 UI/AI 触发证据的程序属性路径升级为安全事故。

**修改域**：`src/core/tools/courseReferenceCleanup.ts`、`src/shared/courseProjectHealth/controllerMedia.ts`、`src/shared/composition/dynamic.ts` 等已有访问器；嵌套 Component 构建/准入直接消费者及 composition 分类的现有边界。分类共享接口由唯一集成者与 F03 协调。

**最小证据**：分别选正式删除清理、嵌套消费者诊断的命名用例；不因此增加无关 Player 测试。嵌套 document Component 只补新建、实际使用、保存重开的一个集成用例。程序分类只覆盖当前已知的接受与渲染不一致，不扩成安全矩阵。

### F03 普通内容生成局部互动块

**已知问题**：底层能够运行嵌套 Runtime，但普通创作入口目前按整页二选一，缺少产生“静态壳＋独立互动文档”的路径。

**修改**：

1. 使用普通浏览器可运行的独立 HTML 嵌入作为内容边界，例如标准 iframe 引用本地独立 HTML。首个切片优先支持本地文件；单文件 `srcdoc` 是否同批支持，以已有资源闭包能否正确处理为准，不强制作者拆文件。
2. 软件先识别明确独立的互动文档，完成资源整理与 Runtime 包装，再解析外层静态结构。内部身份、后备图、素材绑定、编译和准入全部由软件维护，复用现有工厂与嵌套服务。
3. 外层共享脚本、跨块共享 DOM/状态或无法可靠隔离的页面继续整页 Runtime 保真运行；远程网页保留既有支持边界。不自动分析任意第三方引擎、不自动切岛、不静态化。
4. 嵌套互动区复用实际目标发现、文字/图片轻编辑及源码入口；外框尺寸由布局 owner 管理，内容和状态由程序 owner 管理。
5. 创作 Skill 只补一个可选短例子及选择原则：独立局部互动可用独立文档，全页共享行为保持完整。build Skill 调用软件用例，不要求模型注册块、编写宿主协议或后备资源。

**修改域**：`parseWebComposition.ts`、`prepareHtmlCourseCandidate.ts`、现有 HTML 资源闭包与 Runtime 源码工厂、嵌套准入消费者；`.agents/skills/orchestrate-courseware/` 和 build 的对应短例子。实际改变的打包资源同源生成。

**最小证据**：一页“静态两栏＋专业图表＋局部互动”经普通创作输入导入、保存重开和 Player；静态兄弟可改字、改栏、移动，互动在周围重排和自身尺寸变化后保留状态。独立内容在普通浏览器的原始表现与进入软件后的关键行为一致。已有嵌套 Runtime 生命周期证据继续有效；同一切片不拆成重复验收。

### F04 可靠的布局互转、单位与样式修改

**已知问题**：定位面板只写 `position`；自由手势写 px；样式面板只显示行内声明；自动布局缺常见尺寸调整。

**修改**：

1. 在现有 CSS 编辑命令上补“自由摆放”和“加入自动排列”，每次一次事务、可撤销，不增加第二套布局模型。
2. 转自由时按真实包含块换算当前显示几何，处理已有边框、滚动和盒模型。优先沿用定位祖先；需要改变父级定位时同时处理真实受影响的子项，不一概补 `position:relative`。
3. 转自动时按目标容器和 DOM 顺序排列，清理冲突偏移，写出实际生效的定位语义；不能只删除 `position`，让 class 中的 absolute 再次生效。不保证返回自动布局后外观不变，界面如实说明。
4. 固定演示页的普通自由摆放可直接写 px，不逐次确认，也不要求内部自动布局全部使用 px。自由手势保留可靠可换算的原 `%` 等声明；仅实际受影响的复杂 `calc()`、变量或规则不能直接反解时，保留原式编辑，或显式选择当前元素的像素覆盖，不静默固化。复杂多设备断点不成为本轮完成门。
5. 面板显示行内/共享规则/继承等实际来源和修改范围；“沿用规则”不能显示成没有值。默认局部修改说明覆盖关系，不对共享类无提示地批量改写。复用现有源码样式处理，不先建设完整 CSS 引擎。
6. 首批补常见 flex 项宽度和可可靠定位的 grid track 调整；未知布局保留属性或源码入口，不猜测修改整棵布局树。

**修改域**：`src/renderer/composition/CompositionContentEditor.tsx`、`compositionDrag.ts`、`WebCompositionAuthoringContent.tsx`、`src/core/tools/compositionContent.ts`、`src/shared/composition/inlineStyle.ts`，以及现有浏览器布局观察端口。

**最小证据**：一个真实浏览器切片覆盖布局互转、一次撤销、保存重开；一个针对性场景覆盖百分比拖动、变宽后规则仍生效及常见栏宽调整。只观察改变的布局与互动状态，不逐页截全课、不扩展任意 CSS 矩阵。

### F05 原位精修、跨容器手势与选中内容 AI

**已知问题**：内部手势目前只在弹窗，跨容器 `move` 已有但没有相应手势；composition 的 AI 内容通路只有文字/样式，没有图片替换。

**修改**：

1. 复用现有选择、命令和浮动入口，把支持范围内的内部选择、拖动和缩放接入主画布；Slide 优先打通，Flow/Spatial 复用同一能力接线。弹窗保留为深入编辑入口，不创建第二份内容或编辑历史；仅弹窗可用不算完成此项。
2. 在已有 `move` 上接跨容器拖放；落点采用目标容器布局规则，自由目标使用真实坐标换算。不支持的目标明确显示原因，不通过整页绝对定位伪装成功。
3. 对可靠绑定的图片目标接入既有图像资源准备、替换 planner 和 canonical transaction。模型只提供新内容/素材意图，软件维护资源及节点绑定；实际程序控制的图片继续使用对应 Runtime 编辑合同。
4. 选中内部文字或图片后使用现有元素 AI 入口；软件冻结精确内部目标并提供内容短句柄，不能把整图层授权冒充元素选区。正文、样式与图片均复用现有内容通路及最终 CAS，保留未选内容和互动实例；不扩成新的能力发现平台，不要求用户重新选择整页或重建作品。

**修改域**：三个 Surface 现有 composition 选择/挂载连接器、上述手势组件、`DocumentToolGateway.ts`、`CompositionContentEditPlanner.ts` 及现有内容目标与图像应用服务。

**最小证据**：一个真实主画布操作完成内部选择、拖动/缩放或重排、取消零提交和一次撤销；选中内部文字或图片经同一元素 AI 通路局部修改并保存重开，未选内容和既有互动保持。后台可调用或弹窗可编辑不代替用户入口证据；相关既有检查复用，未变化的三 Surface 不机械全跑。

### F06 组合 Native 输入的提交与判题

**已知问题**：组合中的 Native input 可填写，但当前提交被禁用，判题规则未接入。

**修改**：

1. 复用已有原生输入规则、提交/反馈及重置语义，使组合叶子参与对应 Player 行为；内部对象身份与目标映射由软件维护，不交给模型。
2. 只承接已有明确答题合同的输入类型。不另造评分 Schema，不为没有规则的普通表单伪造判题成功。
3. 输入临时状态与正式内容分开；普通尺寸变化和静态兄弟编辑不清空填写状态，作品重置按已有规则执行。

**修改域**：`src/player/composition/mountWebComposition.ts`、现有 Player 输入行为和 `src/core/tools/inputRuleFamily.ts` 等输入 owner 的直接适配端。

**最小证据**：一个已有规则的组合输入完成错误答案、正确答案、反馈和重置；调整容器尺寸后已填内容保留；保存重开仍有相同规则。未知规则仍明确未配置，不冒充通用判题器。
