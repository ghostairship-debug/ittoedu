## 1. 已确定的产品合同

**普通组先选整体、再选成员；组内默认自由布局；Flow负责持续阅读和绕排；AI可用复杂临时表达，软件负责应用、保全与必要兜底。**

| 范围 | 已确认的行为 | 不采用的做法 |
|---|---|---|
| 普通组选取 | 组外单击选最外层普通组；再次单击选可编辑成员，父组弱化显示；嵌套、框选与文字编辑按§3.1 | 为编辑先解组或调用AI；把修饰键作为选成员的唯一入口；把UI选择层级强加给AI目标 |
| 普通组内部 | 默认自由拖动、缩放、旋转和改内容；组合只提供整体组织与变换 | 把普通组分成用户必须学习的“响应式组/自由组”；拖动默认触发Flex/Grid重排 |
| 组合与解组 | 多选组合；解除一层后成员保持身份、内容和当前画面位置，可独立操作 | 为编辑必须先解组；用隐藏普通组伪装解组；批量递归拆散组件 |
| 自动排列 | 对齐、等距、横排等默认是一次性动作，完成后仍可自由拖动 | 点击“排列”即悄悄创建永久布局约束 |
| Flow | 正文持续响应式；图片和一般组件可拖动、改宽、随文移动，文字自动绕排 | 将整个文档冻结为坐标快照；把覆盖文字的浮层称为绕排 |
| 持续排版 | 保留在正文、分栏、表格、确有适配需求的组件中，以内容语义呈现 | 所有包装div长期变成布局组；要求普通组普遍维护约束 |
| HTML/Source/原生 | 都可作为创作与编辑载体，以实际拖拽、修改、保存能力判断 | 强制全面原生化；主要内容成为无内部编辑边界的大Web对象 |
| 复杂组件 | 整体可拖缩，稳定作者字段尽量直编；必要时进入同一对象局部Source | 强拆共享动画/模拟；把不能拆等同于只能让AI改 |
| 导航与推进 | 作者导航完整可用时不显示额外兜底入口；软件确认漏做、装饰按钮、失效、挂载失败或部分缺失后，只补所缺目录/控制台 | 依赖模型自报“导航完成”；仅凭controls:none/canvas取消兜底；完整导航旁始终显示宿主入口 |

“布局固定的组”指保留内部相对构图，**不等于锁定后代**。默认自由适用于新建普通组合、新静态自由构图及已有自由组；旧作品的持续布局关系不会在打开时被批量转换。Flow的自然增长也不会因一次普通拖动被隐式关闭。

Slides/Spatial采用类PPT语义：文字变长时沿用当前文本框尺寸策略（例如自动增高），允许与兄弟重叠，不自动推挤兄弟或新增持续布局；需要持续重排的内容使用Flow或明确的响应式组件。旧Flex/Grid等持续布局组同样先选组再选成员；其成员拖动、缩放和旋转沿用当前工作树已有行为，本轮不因拖动新增隐式转换。E1开工先记录该行为的实际结果与限制，不预写成“必然重排”或“必然自由移动”；显式解组仍按§4.2处理。

以上方向不再重复请求批准。新格式兼容、整作迁移、新账号/授权流程、默认模型/会话切换仍按原授权边界处理。

## 3. 统一操作与写入规则

### 3.1 先选整体，再选成员

组外单击组内任意可见对象，选中最外层普通组；此时拖动、缩放、旋转作用于整组。组已选中后，再完成一次该组内部的成员单击，选中该可编辑成员，进入该组的临时选择上下文，父组用弱化框提示；成员可独立拖缩、旋转、改格式。这个上下文只影响选择，不改变组合、布局、文档归属或History。

**嵌套推荐规则：第二次单击直达命中位置的最深可编辑对象，不逐层点普通子组。** 复杂组件本身或它正式暴露的作者字段是终点，不继续钻入任意DOM。[PowerPoint官方说明](https://support.microsoft.com/en-us/office/graphics-visuals/group-or-ungroup-shapes-pictures-or-other-objects)支持“选组后选成员”；[Figma官方说明](https://help.figma.com/hc/en-us/articles/360040449873-Select-layers-and-objects)采用双击/Enter逐层下钻，并另有深选。选择前者的整体→成员思路，可减少深组日常编辑点击；“第二次直达最深对象”是本方案的明确推荐，不声称PowerPoint所有版本的嵌套细节均如此。选中中间层子组可用Esc/“上选”逐级选择真实父组，或直接点面包屑/上下文菜单；选到子组时变换作用于该子组整体。

| 输入或场景 | 确定结果 |
|---|---|
| 已处于某组上下文，点击该范围内另一成员 | 直接切换该成员，保留上下文，不退回最外组；点中间组的面包屑可选该组整体，后续再次点成员可将上下文收窄至该组 |
| Ctrl（Windows）/Cmd（macOS）＋单击 | 直接深选最深可编辑对象/字段，并建立所属普通组上下文；这是熟练入口，常规两次单击同样可达 |
| Shift＋单击；Ctrl/Cmd＋Shift＋单击 | 分别为当前层级增减选、深选增减选；当前代码的Ctrl/Cmd增选与Alt深选须一并核对，Alt深选保留兼容，文本编辑器内的原生快捷键不改 |
| 已选中文字成员，再单击/双击其文字 | 进入专业文字编辑，单击放光标、双击按编辑器语义选词；组外的一次双击只完成选组→选成员，不额外跳进输入态 |
| Esc/上选；组外空白 | IME组合中的Esc先交输入法；其他状态先取消手势或退出文字编辑，再按次上选真实父组，最外组再次Esc清空。组内空白选当前上下文组整体，组外空白退出；点击另一组按组外首次选择处理 |
| 组外框选 | 完整包围一个组的有效可见边界时选整组；部分覆盖不选该组或偷选其成员。旋转对象按真实几何边界判断，空AABB角不计命中 |
| 组上下文内框选 | 仅在当前组范围内，完整包围成员才选中；完整包围子组可选子组整体并去除其后代重复项；部分覆盖不选。锁定/隐藏/裁剪规则照旧 |
| 悬停及按下修饰键 | 高亮这次单击实际将选到的组、成员或字段；悬停、点击、属性面板使用同一目标解析结果 |
| Runtime/复杂组件字段 | 外部普通组未进入时先选组；组上下文中才按组件已有可编辑边界命中成员或作者字段；没有独立写回合同的内部区域选组件整体，组件播放态控件与作者编辑态命中仍按原模式分派 |

单击的选择推进在未跨拖动阈值的松开后完成：组已选中时直接按住拖动仍操作整组，先完成第二次单击再拖动才操作成员；选择框/手柄始终操作它所标示的对象。成员文字上的按下先作为点击或拖动候选，跨阈值拖对象，未跨阈值才进文字编辑；已在文字编辑时由原编辑器处理选区与IME，不挪动对象。双击按手势开始状态归类，避免第二击被同时解释为入组、改字和拖动。异步命中使用按下时捕获的目标与会话，不因控件出现后画面变化重新猜目标。

锁定、遮挡、裁剪和组件可编辑边界继续有效；只选实际可见内容，不越过前景误选被盖住的对象。祖先与后代同时进入多选时保留祖先、去除其后代，避免重复变换。AI、MCP、ACP可直接以成员ID或作者字段target/slot调用领域能力，无需模拟鼠标选择层级；仍执行原锁定、范围、版本和写权检查。

**组边界采用画面保全口径，不在本轮把持久frame改成派生格式。** 成员移动只影响所选内容的画面位置；若既有外框更新确需重定原点，可在同一事务内由软件列出必要的组frame与子frame坐标补偿，使未操作兄弟的世界坐标、四角及绘制效果保持不变。补偿字段由正式writer验证并计入变更回执，限于等价坐标重表达；若会改变共同裁剪、百分比布局或效果，则按§3.2保全边界处理，不能扩大为内容、资源、样式或行为修改。除此之外的范围外字段仍为零差异。仅为选择框展示的边界可临时计算，不因此重写作者几何。Flow外部占位按真正外框更新；整体变换保持相对构图，锁定仍是独立操作。

父组旋转、非等比缩放或镜像时，按完整父到屏幕矩阵的逆变换换算拖动；缩放柄沿对象投影后的局部轴工作，对侧锚点保持，预览和提交都从手势初始几何计算。解组按`新局部矩阵 = 新父世界矩阵⁻¹ × 旧父世界矩阵 × 旧局部矩阵`换父，保留可能产生的斜切，不能退成轴对齐外框或丢弃斜切的旋转/缩放分解。现有`ComponentFrame.transform`与`reparentFrame`已支持六参数仿射矩阵，无需新格式；矩阵不可逆时拒绝该变换并保留原稿。本次只在内存复核换父四角和拖动数学，完整手柄、合成效果、Undo与冷开由E1验证。

### 3.2 组合、解组和一次性排列

复用现有几何与结构操作，并让UI、内置AI、MCP/ACP最终调用同一正式能力。现有算法位于renderer时，只把需要共享的纯规则移到合适领域位置，旧消费者改为复用；不复制第二份算法或新建万能布局服务。

普通组合与解组均保留旧成员ID、内容、资源、Source及绑定，形成一次逻辑History。解组只解除所选层，非目标子组或复杂组件不被递归拆开。普通背景优先作为可编辑子对象保留。

对共同裁剪、mask/filter/opacity、特殊合成、外部引用和交错层级进行实际判定：可无损处理则直接处理；无法保全时明确受限的具体效果或引用，保留原稿。不能仅因builtin叫group就删除责任，也不能据此把所有普通组都判为不可拆。常见普通组合无需额外确认步骤。

对齐、分布、排成行列默认只提交本次几何结果；用户随后可直接拖走任一成员。确有持续关系的分栏/表格等沿原专业内容入口处理，不把“一次排列”和“持续布局”混为一个默认动作。

### 3.3 每项修改仍只有一个正式责任方

人工与AI共用当前稿、目标/字段、版本、范围、资源、DocumentSession、History和保存。手势中间态只是预览；放下形成一次正式操作；取消不留半个改动。已应用而观察失败不重放写入；越域或存在真实字段/依赖冲突时保留原稿，layout-only版本推进按§5.2校验和合并。

普通改字优先直接字段；用户明确修改代码文字或复杂文字效果时，允许进入同一对象局部Source/COW，不被“文字只能text.format”拦住。Source深改不扩成整页重写，也不覆盖其他实例。

## 4. Flow与复杂组件：明确承诺和实施边界

### 4.1 Flow的主交互

| 操作 | 预览与正式结果 |
|---|---|
| 拖到正文插入位置 | 显示真实插入线，按阅读顺序行内或独占一行放置 |
| 拖到段落旁侧 | 显示对象框及真实文字避让；放下保存位置、随文关系和绕排 |
| 拖动缩放柄 | 直接改变宽度/大小并实时重排；不能只有固定左右百分比 |
| 在前面增删文字 | 对象按作者指定关系随相关段落移动，文字继续绕排 |
| 窗口或纸面变窄 | 正文真实重新换行；空间不足按规则转整行，不仅缩放整个文档 |
| 明确选择前景/背景覆盖 | 按覆盖用途处理，不伪称文字会自动避让 |

位置锚定与文字环绕是两个独立事实，由软件从手势落实；常规拖动不要求用户先学习它们。图片和普通互动组件采用同一交互，不另做只对图片有效的方案。自由组可以作为Flow中的一个整体参与绕排，但其内部自由构图不会天然获得任意宽高比自适应；需要内部重排时采用有明确语义的响应式组件。

首批完整交付左右绕排、上下避让、一般组件改宽、段落跟随和窄屏行为。中央放置预览实际效果；中央双侧绕排另用一个样本验证文本选区、中文输入、多对象和窄屏。现行[CSS Shapes Level 1](https://www.w3.org/TR/css-shapes-1/)以float为基础，不能把现有左右float/shape-outside直接视为任意中央双侧绕排；本项目浏览器中的实现仍须样本证实。**E2给该可行性试验最多4小时累计工程投入，或首轮完整样本跑完即裁决，以先到者为准。** 全部通过才纳入该能力；否则明确标为未支持，中央放置按已验证的上下避让预览，记录具体障碍后继续常规E2，不靠追加样本延长本轮，也不把长期目标改成只能左右吸附。

动态Runtime/iframe绕排须有明确尺寸责任：宿主分配可用宽度，组件报告所需高度；纯测量结果不反写成新的作者宽度。复用已有尺寸通知合并相同结果，按帧处理，跨域iframe沿正式尺寸协议，不任意读取内部DOM。以文字增长、组件展开/收起、连续改宽和窄屏为样本，在外部输入停止后尺寸应收敛，不发生宽高往返振荡、无限测量或重复History。仅用requestAnimationFrame推迟回调不等于消除反馈；[Resize Observer规范](https://www.w3.org/TR/resize-observer-1/)中的循环错误也不应被捕获后忽略来当作通过。判定数值与观察窗见§8.2。

### 4.2 Flow中解除组合

先处理自由组，再处理失去持续布局owner的旧布局组。后者必须测量当前实际画面，为失去布局来源的成员落实合法几何，且处理原块占位、随文锚点和周围文字。

最小验证优先复用已有纸面定位、段落锚点和正文占位。解除后成员可独立选中与移动；仍保留的子组继续按§3.1先组选取，复杂组件保持完整。取消的那层不再作为隐藏普通组共同变换。仅把自动排版改为自由内部布局但保留组合时，操作叫“自由摆放”；本轮不因拖动旧布局成员自动触发它。

如果保当前画面确需布局范围或占位信息，它属于Flow排版，不得继续成为选择/组合屏障。现有字段不足时先提出最小持久表达及兼容成本，只暂停该范围启用，继续其他工作；不得批量迁移旧文件。不能保全的例子明确列为未交付，而不把普通组永久不可拆当作完成。

### 4.3 Source/Runtime可拖拽深度

整体拖缩、稳定文字/图片字段直编和有geometry合同的局部拖缩分别验收；不以整体能动替代内部能改。拖动不改变Source时，按既有生命周期避免无关重挂；真实Source改变按合同重建，不承诺任意程序热换都保全部临时状态。

对不支持几何写回的内部内容，准确显示边界，优先补高频字段的作者映射；无法稳定映射的动态绘制保持组件整体与局部Source入口。编译/保Source的选择由实际修改能力决定，不为拖动强拆共同动画、模拟或图表计算逻辑。

## 5. 单向布局与保身份重排的实现合同

### 5.1 两种场景，共用底座而不混用应用语义

**新静态自由构图：** AI可用HTML/CSS/Flex/Grid表达；软件沿已有测量和装配，将纯构图关系落实为自由对象或普通组。无需保留的包装不长期约束用户。确有持续行为的Flow/组件/Runtime边界保留，不能为减少组数破坏保真。

**已有对象大重排：** 从当前正式内容构造临时布局，只重新求位置/尺寸/顺序和授权关系；不执行重新生成内部ID的redo。软件提供引用，模型不手抄当前正文、不猜ID，也不必反推历史CSS。

### 5.2 正式步骤

1. 取当前允许范围的对象引用、内容/资源、锁定/排除项、未保存合法人改和revision；未完成的IME草稿不得被覆盖或当旧正文测量。
2. 模型生成临时构图，引用已有内容；软件用真实字体、图片、盒模型及资源条件测量。Runtime只按声明边界处理，不为测量任意重放有副作用的程序。
3. 形成仅含授权布局字段的候选：frame、parent/order及必要布局参数。文字、富文本、数据、资源、裁剪、Source、作者记录和行为引用默认不变；样式/字号变化必须在任务范围内单列。
4. 校验身份、范围、锁、会话、重复/遗漏引用和循环；缺少引用不等于删除授权。将候选的布局写集与实际测量读集保留为字段前置条件，比较基线、当前稿和候选：revision推进本身不拒绝，不相交的人改保留。同一布局字段、父子归属/顺序或依赖的祖先变换发生变化时，重新获取受影响范围，不覆盖人工布局。**正文、字号、图片尺寸等即使不与写集相交，也可能影响测量**：使用最新内容重测该布局后再校验；无关数据变化可直接合并。不把“只检查同对象frame”当作充分条件。
5. 复用`captureComponentOperation(..., readPaths)`、`checkComponentExpectations`及`DocumentSession`现有串行校验/事务提交；依赖核对通过后将候选重基到当前revision，一次应用并返回布局与必要补偿的字段差量。应用、观察、保存分别判断；再次出现冲突则明确返回重读范围，保留最新人改，不盲重放。当前底座已有按字段前置条件重基，尚需为layout-only补完整测量依赖与消费者测试；不另建通用合并器。

先完成一个真实区域，不建立通用CSS双向映射、不设计第二套LayoutGraph或正文副本。普通500/600字重、padding、自定义字体和响应式图片不能靠禁止使用来规避；有限原生补强或Source可视编辑，采用能更短完成真实修改的一条。

首次样本必须先有人改文字、裁剪或数据，再由AI重排；至少包含文字、图片、专业数据对象及一个有界Runtime。保ID只是必要条件，还需核绑定、生命周期和保存。失败保留当前稿，退回可用的原生布局/有界Source操作，不退成截图或无内部编辑边界的整页Web。

## 6. 内容导航优先，软件保证基本可达

复用 `ComponentNavigationOwner` 与正式推进/presenter；目录、顶部/侧边/进度导航和全局控制台是不同呈现，不拥有第二份章节、位置或播放状态。

宿主在编辑预览、播放和离线交付中检测导航缺失，并按需挂载兜底；作者导航完整可用时不显示额外入口。检测与显隐不写作者稿，也不生成成堆目录对象。用户可插入、配置正式导航组件并融入内容；先打通一种组件的必要呈现变体，后续变体复用同一合同，不建多套导航。

| 作品实际状态 | 软件行为 |
|---|---|
| 绑定与目标有效，所需作用域内的内容导航完整且实际可用 | 只使用作者导航，不额外显示兜底按钮、目录或可唤起入口 |
| 确认漏做、仅有装饰按钮，或关闭默认控件后确实缺少导航 | 只提供缺少的目录与推进；controls:none/canvas本身既不证明缺少，也不豁免检查 |
| 只完成部分功能或部分作用域 | 补缺少部分，避免整套重复和遮挡 |
| 自定义控件挂载失败、目标失效 | 自动恢复相应宿主控制，不等待模型修复 |
| 当前动作按作品规则合法禁用 | 保持条件约束，不越过剧情/步骤，也不误判为控件丢失 |

覆盖判断消费正式目标、动作绑定、作用域、挂载与可操作状态，不依赖模型强弱、自报标记、节点名称或按钮文字。先按作品正式章节/步骤与自然阅读方式确定所需通路；单屏静态内容等无需导航的情形不凭空补按钮。检测分为“待就绪、完整、确认缺失”：缺少可观察元数据本身不等于缺导航；对任意Source未暴露的内部状态保持未知，只为已确认缺少的作品级通路提供兜底，不猜内部步骤。

挂载优先以当前作用域的就绪/失败事件判定；无明确就绪事件时，建议从宿主启动该作用域导航挂载起给2秒宽限期，届满且必要导航仍不可用才判缺失；明确失败可立即判定。事件和计时器绑定当前挂载代次，切页/卸载时取消，旧回执不覆盖新状态。正常加载期间不先亮兜底再撤掉；晚到的有效导航经完整性确认后撤下对应兜底，合法禁用动作不触发替换。2秒是本轮待测挂载宽限参数，不是等待全部图片/字体或AI生成的时限。

兜底显隐保持正文滚动锚点、可用宽高与排版：优先使用既有shell/inset已安排的宿主槽位，只切换控件，不临时增减安全区。N覆盖运行中失败与全屏/离线宿主；没有可用槽位时，先验证稳定承载方案，不用遮挡正文或给所有完整作品强加常驻空白带来替代验收。无法同时满足这些条件的宿主单列为未通过，不据此改变默认画布边界。当前`playbackNavigationChrome.ts`会随visible改写content.bottom（52px/0），是无跳动验收的具体修订点。

**用户已批准：允许作者显式选择“有意无宿主导航UI”。** 用于展台、游戏等明确用途，交付检查显示该选择，必要时说明作品自身退出/恢复方式；模型漏做或controls:none不自动等于此声明。实施沿现有正式播放配置及保存链补最小表达，未显式选择的作品继续按缺失事实兜底；新增持久字段先核旧文件、导出和读取兼容。

推进须分清章节跳转与作品内部authored-command，兜底调用对应已有接口。全局控制台是呈现/控制入口，不能无意赋予强制跳转权限。Flow目录高亮改用同一reading事实；同一viewer内同源，多个viewer各有自己的会话位置。

共用现有shell/inset，禁止重复扣安全区和覆盖正文。目录开合、阅读位置及兜底出现不写History；作者修改导航样式/配置才写正式事务。运行时兜底不等于静态打印格式自动支持互动。

## 7. AI方法、Skill、发现和参考：与能力同时交付

### 7.1 模型只走当前任务需要的路径

| 任务 | 优先路径 |
|---|---|
| 已知对象的小改 | 当前精确target/slot及相关最小上下文，直接领域操作；不足时快速扩展关联上下文或同对象Source |
| 普通布局调整/组合解组 | 与人工相同的结构/几何命令，必要时批次；不为挪一个成员重编整页 |
| 新静态自由构图 | 高层HTML/CSS测量或原生批次；采用后普通组自由，不逐对象问坐标 |
| 已有内容大重排 | 当前对象引用→临时布局→保身份差量应用 |
| 连续阅读/响应式 | Flow正文、可绕排组件和必要持续语义；不默认冻结整篇 |
| 连续动画/模拟 | 有界Runtime及作者字段，稳定正文与可独立内容保持可接手 |

先生成有意义的区域/批次，观察代表画面与真实操作，再定点返修。软件负责身份、依赖、测量、应用和保存；模型负责内容、艺术判断和选择。复杂度不通过逐对象往返、手写装配或冗长提示词转移给模型。

### 7.2 每项能力的完成条件

能力实现、UI及领域调用、同源schema/索引、必要Skill/示例、真实消费者五者同一增量交付。`generate:ai-capabilities` 与 `check:ai-capabilities` 复用现有生成链；不手工维护第二份目录，不把生成检查当成模型已正确使用。

发现根据真实目标/字段适用性披露，不仅按“大类可写”猜工具；已知目标不重读全目录，未知或关联不足可以扩展。内置AI核最终ModelRequest和实际应用；ACP核工具披露/加载、实际调用及正式结果，原生通道未暴露的token/schema记不可观测。OAuth阻塞时标记内置真实消费者未验，不用ACP或模拟结果替代。

**交互：** 单击选组、再次单击选成员，无需AI、无需解组；整组与成员拖动/缩放/旋转均正确。普通组默认自由，一次排列后仍可拖走；悬停预告与实际选择一致。复杂组件按真实边界验到修改、保存，不止选中。

**保全：** 布局任务旧身份不重建。除授权写集及§3.1由软件明确列出的必要几何补偿外，范围外字段差异为0；未操作兄弟的世界四角、画面位置、绘制与行为保持，补偿不得改变内容、富文本、资源、裁剪、Source或作者字段。显式授权的新增/删除/样式变化单列。Undo/Redo、保存、独立冷开及受影响离线输出成立。

**持续行为：** Flow及明确持续布局区域在文字增长、换图、窗口变宽变窄后按各自合同重排；覆盖模式按作者显式设置处理。Slides/Spatial自由组允许文字增长后重叠，沿原文本框尺寸策略、不推挤兄弟。锁/裁剪/变换不串目标；Runtime几何与Source改动分别验生命周期。动态组件尺寸样本在字体/资源就绪及最后一次外部尺寸输入结束后，1秒内进入稳定状态并持续观察2秒，变化≤0.5 CSS px、无双值往返振荡、循环错误或自动追加History；这是该静态收敛样本的判据，不限制组件真实动画。不能收敛的尺寸策略不启用自动高度协商，保留明确外框。导航完整时无额外兜底，确认缺失才补，显隐不使正文跳动或绕过合法推进条件。

**异常：** 版本推进按§5.2区分可合并人改、需重测依赖与真实冲突；重复/漏引用、越域、取消、迟到和应用成功但观察失败都有确定结果。未知写入先核回执与正式稿，不自动重放。

**性能与质量：** 手势反馈、选择、排版、保存/导出在同构建、同作品、同设备留基线与候选记录；明显卡顿要定位，不因组数减少就宣称加速。完整生产沿原冻结协议的T1有效预览、T2首次合格已保存离线交付、T3同等人工修改状态后的共同局改；人工操作耗时另列，返工和等待不删账。十分钟仍是挑战目标，不新增随意倍率门槛。

三路线保持：A主Agent真实果铃MCP；B同主Agent独立写HTML、不经果铃作者流程；C果铃内置AI。ACP是接入/可靠性验证，不冒充C。记录实际模型、档位、渠道和人工恢复，未测项记未测。

**简短术语表**

| 术语 | 本文含义 |
|---|---|
