# 创作方法与质量判断

本参考提供内容、视觉与创作组织方法，不重复工具参数或工程合同；具体操作沿 `orchestrate-courseware` 与共享能力指南按需读取。成熟策划直接承接，简单任务不必增加策划文件、额外交接或多 Agent 流水线。

## 整作主线与场景

先读用户材料、已有策划及当前作品，明确本次交付范围，以及观众要看见、理解、操作和获得的反馈。大型新作先形成整作主线与可直接创作的场景稿：关键正文、初始画面、必要动作、反馈和前后承接基本明确，再批量形成已确定的场景与布局；不只列标题和“设计一个互动”。像素细节和微动画在实际画面中调整。只有未知机制可能改变整体设计时，先做一个代表性片段，其余已确定内容仍可批量推进，不让整作等待一个程序反复精修。

每个场景依要表达的关系构图，统一字号、色彩和阅读层次，避免批量套同一种卡片。写清目标、受众、内容主线、场景承接、视觉体系、载体理由和交付范围；大型新作可保存为 `<作品名>/01-创作策划.md`，已有策划直接沿用。参考[场景策划](creation-plan.md)理解完成度，不加固定页数、对象数或必填模板。教育任务按需读[教学质量](teaching-design-quality.md)，其他内容不套教学策略。

## 载体选择与接手边界

独立场景有各自正文、配图或局部实验，且主要共享结果/完成事实时，用正式场景组织内容，将持续机制保留为局部程序。需要连续时钟、相机或高频共同模拟的完整世界，可以保持一个程序根。已有应用先保留用户认可的组织；自然长文保留自然滚动。按内容和接手需求决定，不设置容器数量或原生化比例门槛。

普通标题、说明、配图与局部布局需要直接接手时，保留相应独立对象；交互接线优先使用现有 `enhance`，短例见[导航与控制](teacher-controller.md#局部增强的最短路径)。同一科学模型只维护一个可读源码模块，由相关实验引用；跨幕传实际结果，不在每页复制计算与状态。`project.list` 会提供当前 `.modules/` 路径，局改一个作者模块即可；不要为了找模块重写整份 data.json。

`program.set` 成功回执中的 `rootCount`、`containerCount`、`replacedFactoryEmptyRoot` 描述本次实际形态后果。它们用于确认既有内容是否保留，不能代替画面和接手体验验证。需要刷新或关闭后续玩时，按[本设备学习进度](learning-progress.md)显式接入并验证；普通运行状态不会自动成为存档。

## 内容、动效与推进

按内容需要安排交互：适合比较、探索或操作的部分，用动作改变真实状态并给出相符反馈；适合线性讲述的部分可自然滚动、翻页或使用贴合语境的“下一步”，不强制增加状态和操作。不设每页互动配额或普遍答对门槛。导航按内容选择标签、目录、翻页、地图或混合形式，融入作品的构图与主题；主动作完成后应有自然的继续路径。

先确定正文、构图、素材和结果阅读区域，再为必要互动安排输入和反馈。状态适合明确设计的线性、分支和选择，Runtime 适合连续变量、模拟和程序过程，Spatial 适合真实空间关系；不为原生化拆散高频共享状态，也不默认把独立正文、图像和参数吞入一个大程序。涉及观众操作的比较、回看和复盘使用实际选择及记录；预置例证明确其条件，不代替当前结果。联动消费同一实际状态，背景和装饰不抢前景输入。具体参考[互动设计](interaction-design.md)、[推进与使用路径](main-progression.md)、[导航与控制](teacher-controller.md)。

新作按实际用途设计进入、选择和回看，不默认完整全局控制台或外加底部翻页条；保留人工添加、用户要求及已有作品的合法控制台。复杂动画可沿当前源码或参数修改，普通过渡可用宿主已有快照，不把手动时间轴、全局暂停或任意运行状态热换恢复当作通用前置。教育组织话术留策划，观众画面保留必要解释与操作提示，不自动新增备注或讲稿。

## 素材和参考复用

需要参考现有作品或实现时，内置工作台先用 `skills.read {skill:"orchestrate-courseware",path:"references/creative-reference.md"}` 取得随附参考库的实际入口，再用 `file.read` 读取所需条目。仓库环境也可直接读取 `creative-reference/README.md`。参考不是必读步骤或固定模板；按本次内容与设计需要选择，不预读全库。

用户未提供素材时，主动补足内容与视觉目标所需的材料，明确用途、语义、风格和人物一致性；声音明确台词、角色和使用时机。真实事件、实物和原作重视用户原材料、互联网图库或机构原图与上下文；一致性故事可直接生图并传真实参考；普通配图按匹配度、质量和效率搜索或生成；准确关系、数据和联动可用原生或代码。来源无全局排名或搜索次数门，生成图不冒充真实证据，粗糙手画 SVG 不默认代替合适图片。

听力、发音等活动需要实际音频：正式新作与离线交付使用可随作品运行的音频文件。普通朗读用已支持的本机语音文件，剧情、多角色或明确语气按需要选已配置且支持所需表现能力的语音服务；教材原音沿用户材料，不以生成朗读替代，原创或改编声音不冒充原文原音。用户明确要求实时朗读时按其范围处理，配置缺口如实说明。方法见[视觉及素材](visual-design.md)。

参考用于理解关系、实现和构图，也可以直接复用适合当前作品的高质量局部；不必为使用参考而采用整作模板。只有题材和交互确实相符时才套用，允许拒用或换风格。[表达范例](web-composition-examples.md)是局部机制参考，不是所有作品必套模板。优先复用已经适合的资源和实现，避免重复生成、重复装配。

## 推进与协作

持续完成已授权目标，展示策划或进度不等于结束或等待。用户明确要求先确认时，只在有选择价值的产物节点提问；不要求前置选择自动或逐步模式，不增加固定阶段确认门。

只有任务可独立完成且能减少等待或返工时才并行。大型作品可按实际依赖使用几个协作任务；主任务保留整作主线、共同约定和最终集成，独立场景、关键图像或局部机制可同时准备，不固定内容、视觉、素材、代码四次串行交接。方向明确后可提前启动关键素材，实际图像再反馈构图和热点位置，其他已就绪内容继续前进。不为填满并发额度拆出没有独立成果的任务；简单流程足够时保留简单流程。

## 质量与交付

默认目标是完整覆盖本次范围、正文、必要媒体与主要互动可用、可继续编辑的首版，不用占位或粗糙代码插画交付核心内容。严重运行错误、数据或结果错误、主路径受阻应修正；可选润色和穷尽分支检查按用户实际要求进行。用户明确要求终稿、特定验收或导出时完成相应要求，不能以“首版”为由降低承诺。

复用已有有效证据，针对足以使当前作品不可用的未证实属性，观察代表性关键画面、操作必要主动作并核对后果与衔接。发现严重错误只复查受影响范围；没有具体问题时停止自检，不默认逐页截图或重复全矩阵。保存、重开、导出成功和内容视觉合格分别判断；必须兑现本任务承诺的局部编辑能力。首版达到目标即可交付，不因仍有可优化之处扩大任务；保留首个真实结果和修复过程，修后产物不冒充原始首稿。
