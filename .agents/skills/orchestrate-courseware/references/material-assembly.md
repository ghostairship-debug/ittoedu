# 从材料到正式对象

本指南说明已有入口，不规定作品类型、页数、每页对象数量或构图。先决定观众要看什么关系、进行什么操作，再选择能继续编辑的载体；教育任务再按需要安排活动。分素材不是把每个词拆成对象：专业连续正文、带刻度的完整图示、具有共同状态的局部实验各有合理整体范围；页面标题、说明和独立配图则无需包在同一整页脚本中。已确定且独立的素材及布局可以批量生成、同批装配；分素材要求约束最后的对象结构，不规定一次只能生成/插入一项，不为此再建从任意整页程序逆向拆素材的平台。

## 普通内容直接装配

完整新作先在同一工程形成整作布局框架，再沿当前框架接力素材和互动。已确定的页面、原生内容和布局以跨页批次提交；框架含真实标题、关键正文、关系与所需素材/操作空间。批量是减少机械往返，不是让所有页面套同一种卡片。未知机制按需局部试验，已确定结构不等待它反复精修。

装配到已有区域前读取该对象/容器的当前内容与frame，按实际可用尺寸准备素材及程序内部视口；继续沿同一对象改内容，保留未要求改的外框和邻居。软件提供正式几何和身份，不凭旧策划猜尺寸或为改内容另建同位置对象。新建/明确重做范围可重新设计区域，普通接力修改不重新排整页。采用新片段时，`project.apply` 的可选 `region:{width,height,transform:[1,0,0,1,x,y]}` 将局部尺寸交给测量、位置交给正式frame，单项、`operations` 及新页首稿均可使用。百分比、`vw/vh` 和响应式布局以这个局部视口运行，不要求固定像素根；省略区域仍可表达整页或有意重叠。已有对象的 `content/redo` 保留当前frame，明确移动或缩放用 `object.update`。素材插入和编译成功尚不证明内部视口、文字裁切或操作结果已正确，按受影响属性观察实际画面与后态。

独立子任务可以用 `delegate.agent` 的 `target:{project?,path,region?}` 指向已观察页面或对象，宿主冻结当前frame、内部视口及相关外围事实；纯素材任务可省略。模型给清楚表达目标、操作后果、反馈及必要共同约定，软件负责冻结来源与目标，不让父子重复转抄整课或各算一套位置。子任务返回的实际 `source` 可直接交 `project.apply.from`，宿主收齐同组相对依赖并沿本次区域装配；父模型检查集成后的画面和主动作，不需复制长源码或逐文件保存登记。

`file.create` 或 `file.open` 返回整文档目标。新course-v10自带一个空Slide，框架计入并复用或改名它；其余页面在整课授权下用 `project.apply {path:"pages",intent:"surface.add",pages:[{kind:"slide",title:页面名称},…]}` 批量建立。单页或数组中的每页可同时携带 `content` 或授权源文件 `from` 首稿，软件建页并装配内容，一次提交/撤销；已有空白页保留。回执`targets[].path`提供实际页面结构路径，可直接用 `object.insert {path:页面路径,…}` 插入专业对象。已有页面句柄也可继续作为 `target`；需要取得句柄时，一次`listChildren {target:整文档句柄,limit:100}`返回各页`target`，更长目录按回执分页。用`batch`跨同一课件的已授权页面装配，软件分配身份并一次提交/撤销。按本任务ACK续用已有页路径和对象目标，不逐对象重新遍历；冲突或明确刷新诊断才取新事实。

新建或明确重做的自由范围，也可向已观察的页面结构路径用`project.apply intent:"insert"`／`"redo"`整段提交普通HTML/CSS/SVG构图，软件测量并装配可保真的独立内容，共同依赖保合理整体。已观察且同一工程内的多个页面、内容或源码，用 `project.apply {operations:[{path:"实际页面或内容路径",intent:"insert",content:"实际内容"},…]}` 同批提交；每项沿用原 content/from/edits 输入，软件准备内容并在同一次正式事务装配，逐项返回诊断和当前路径。此批只引用已有正式路径；新页面的已确定首稿可随 `surface.add` 提交，真正依赖新对象回执的部分才接下一批。首段入工程后沿实际对象和源文续改，不维护外部HTML同步。两条入口按表达需要选择，不为方法强迫输入格式。独立讲解和局部程序已经确定时，从第一批就按各自合理范围表达，可用同批operations向同页插入多个片段，无需先提交整页脚本再拆分。软件会把可确定的固定单根程序的实测页面位置交给正式frame，保留原内部坐标和脚本；不要再为同一片段手工归零一次、补frame一次。普通续改继续保留已读人工frame，未知耦合脚本仍保整体。

页面级普通 HTML 的底色、单图，以及可等价承载的渐变、多图和透明叠层由软件写入正式页面背景，移除无意义的整页包裹；背景绘制没有组件身份或子正文。简单编组、色块及可等价图元复用原生组件；依赖文本裁切、特殊盒几何或真实跨层交错的表达保源并明确诊断，不据对象总数宣称全部原生可编辑。插入已有页面保留其人工背景，明确重做页面才重新接收页面背景。若保源结果可用，沿现源文或专业内容继续改，不为消除一个保源诊断删除整页并手工重建文字坐标；实际装配缺陷应保原输入定位软件问题。

单独插入一个专业对象时可用 `object.insert` 的已观察页面 `path`，或继续使用页面/容器句柄 `target`；目标不变且无冲突时不逐对象重走目录。下例省略位置尺寸，由现入口准备；已有明确几何时才提供可选 `x/y/width/height`：

```json
{"path":"已观察的页面结构路径","kind":"text","text":"观察与解释"}
```

独立内容链接/按钮的目的页已知时，插入可直接带 `click:{action:"location-go",value:"已观察的目的页句柄"}`；同批跨页插入全部已确定入口，软件同时生成正式导航规则，无需先写导航程序、复制再移动，或等待新对象句柄另绑一批。现有对象继续用 `interaction.update`。

软件准备专业数据、容器和身份。正文可独立插入；公式用 `kind:"formula"`，简单图形用 `kind:"shape"` 与实际 `shapeType`。Flow 正文插入可选 `destination:"document"`，纸张浮层选 `"paper"`。需要专业表格、图表或填空时同样使用已有类型，再依实际对象能力填写内容。不要把 `object.author` 当插入入口，或把 `object.place` 当图片入口。

文字、公式、图形、表格或图表的初始外观已经确定时，可在 `object.insert` 一并提供 `appearance`，语义与后续 `object.update.properties.appearance` 相同，一次插入完成内容、位置和外观。省略时使用人工插入默认；字段依当前类型的专业能力，不把任意CSS或填空配置当作外观。后续局部修改仍用已有对象入口。

要调文字外观，可直接使用插入回执 `affected` 中返回的新对象句柄，再用 `object.update`，无需猜对象路径；也可使用 `project.list/read` 返回的对象路径。例如 `properties.appearance={fontSize:40,color:"#15384d"}`；局部位置尺寸用 `properties.frame`，多对象对齐或分布用 `object.layout`。复用已观察对象的外观可用 `appearanceFrom`，不反复转抄所有样式。已确定且独立的内容可同批调用准备；需要前一回执的新目标时顺序推进。

## 专业表格与图表数据

材料需要可编辑的分类或数值表征时，可用专业表格或图表，不必仅为固定数字另写程序；载体仍按本课的表达与互动需要选择。`object.insert {target:当前页面句柄,kind:"chart",chartType:"bar"}` 返回新对象后，对其 `affected` 句柄使用 `object.update.properties.data`，可直接提供下列已有数据格式，不抄内部点编号或运行代码：

```json
{"title":"分类数量（个）","categories":[{"label":"甲类"},{"label":"乙类"}],"series":[{"name":"数量（个）","values":[20,35]}]}
```

类别、系列及数值依实际材料填写；每个系列的数值数与类别数相同，使用有限数字。软件维护正式身份，未提供的图表类型、外观和位置保留。单位可写在标题或系列名，当前没有独立轴标题或单位字段。数据来源和模拟、测量的性质要说清楚。

新表可在 `object.insert` 一次提供 `kind:"table",table:{rows:[["项目","数量"],["甲类","20"]],headerRowCount:1}`；省略 `table` 时沿用默认表格。`rows` 是完整可见表格的文字矩阵，各行列数相同，`headerRowCount` 可选，软件生成行列与单元格身份。明确替换已有整表内容时，向 `object.update.properties.data` 或当前 `.data.json` 提交同样的 `{rows:[[...]],headerRowCount?}`，软件按当前可见行列顺序保留对应身份、尺寸、外观、未变富文和仍有效的合并；已有合成列头由软件对应到矩阵首行。新内容落入原合并覆盖格时，软件只解除受影响的合并，使内容可见。

局部改格仍沿现专业入口，例如 `object.author {target:当前表格句柄,change:{kind:"table",edit:{kind:"cell-text",cellId:实际读回的单元格身份,text:"新内容"}}}`；富文本格按实际 `content` 修改。已有显式身份的专业数据格式继续有效，普通整表矩阵不要求模型搬运内部编号。

表格与图表的源数据持续可编辑，仍要在实际页面看尺寸、边界及标签。当前图表的 `appearance.fontSize` 只改变标题字号，不能以此判断轴、分类和数据标签已经达到课堂可读尺度；发现具体限制时，按材料需要调整表达，不能把写入成功当作视觉通过。

## 图示、图片与局部程序

先按表达任务选择来源与载体，具体判断见[视觉与素材](visual-design.md)。真实事件/实物图片需要合适来源；连续故事可直接生图并用真实参考维持角色/场景；精确图示或联动内容可直接用原生/代码。没有统一搜索→生图→SVG的必经链，也不把“示意图”一律判为手写SVG。

已有图片、图库/生成结果与适合直接复用的静态 SVG 可沿媒体入口：`media.insert {target:当前页面句柄,source:实际授权文件路径或当前返回的资源}`。软件读取字节、绑定资源和登记身份；未指定 frame 时按媒体尺寸放置，指定时用当前工具 `frame:{width,height,transform:[1,0,0,1,x,y]}`，后续移动沿正式对象入口。`asset.import` 用于组件归档，不能拿它插入普通图片。媒体不表示内部每条SVG路径都成为原生可拖拽图形。

新绘制且需修改、参数变化或互动的图示，优先保留合适的局部代码表达，可内联 SVG/Canvas/HTML；无需先存外部SVG图片再反复回源文件应用。`project.apply {path:当前页面结构路径,intent:"insert",content:素材源文}` 可装配局部 HTML/SVG；内部保 viewBox/关系，页面位置交正式frame，不把整页 absolute/left/top 编进素材根。共同状态的程序保其合理整体，外围标题/说明/独立配图分开。现局部SVG可能保为含源文的 Web 组，不冒称内部全部原生可编辑，亦不为每条路径增加人工控件。见[局部表达](web-composition-examples.md)。

只有明确采用外部SVG资产时，才沿该文件修改源文，再以 `media.apply {target:当前图片句柄,source:修改后的实际文件路径}` 原位应用；保对象身份、人工位置和未指定效果。媒体入口读取磁盘字节，外部源文若是 `saved:false`，需先保存该源文档再应用；已回 `saved:true` 不重复保存。改变外部文件不会自动刷新工程内资源，不能靠猜资源编号更新。SVG可修改而非只能重生，但这条外部源文流程不是新绘图默认步骤；已进入工程的素材是当前作品事实，续改先读现目标，避免用旧外部版本覆盖人工修改。

复杂实验保留一个局部程序，内部有自己的图形、控制项和反馈；实验外标题、知识说明和其他素材继续独立。跨页记录或导航只使用已观察的宿主能力，不以界面文案假装联动。成功装配回执的 `files` 给当前路径和 `frame/viewport`，软件生成的短 Source 入口及本次明确写入的主 Source 还返回 `content`；可直接沿这些当前事实接续，不为确认刚写的同一源码再读一遍。未返回内容的路径仍按需读取，`staleSnapshot` 表示提交后另有修改，需要读取当前稿；不为改文案重读默认运行器和其依赖包。

接入局部业务或宿主端口时，可向当前实例主 Source 路径用 `project.apply intent:"enhance"` 提交普通模块，导出 default 函数或具名 `enhance(context)`。软件等待原实现挂载、组合增强并维护其更新/销毁生命周期；模型只写本次业务。`context` 提供当前 `root/instance/scope`、局部委托监听 `listen(type,selector,listener)`、首值与后续值共用的 `observe(key,render)`，以及显式状态别名 `bindings`。回执 `enhancementPath` 是实际业务模块，后续沿该路径用普通 `content` 或局部 `edits` 续改；完整 Source 的 `content` 编辑继续有效。

对象的 `object.update.properties.stateBindings` 将业务别名映射到已声明的标量 `courseState.key`；只合并提供项，单项 `null` 删除该别名，整体 `null` 清空。增强使用 `bindings.get/set/observe(alias)`，其中 `observe` 立即给首值并自动管理后续订阅。同课普通复制保持共享，已有托管输入键复制映射时同步重绑；软件不扫描改写任意 JS 字符串。结构化 JSON 运行状态继续由局部业务显式使用 `scope.state`。

`scope.state/events.subscribe` 和 `teacherController.subscribe` 已随挂载自动清理，无需重复包 `scope.cleanup`；原始 state/tc 订阅不回放当前值，首次显示另读 `get/read`，或对状态使用增强的 `observe`。`listen` 自动清理局部 DOM 监听，自行建立的其他监听、定时器或 Observer 等资源按需交给 `scope.cleanup`。普通暂停、跨页保留当前挂载；销毁、取消或重置时清理，不把每次离页当成程序重建。

装配后看最重要片段的真实画面与操作，发现放大、裁切、滚动条、默认字号不合适或图文条件不一致就修该素材及必要的正式frame。根据实际可用范围调整构图、信息量和控件，保留可读字号与明确反馈；仅隐藏滚动条或缩小全部文字不能证明内容放得下。沿回执给出的当前正文、Source及诊断续改；高层入口确实不能完成时使用已有源码或文件入口，保留原输入与正式目标，不用整页截图掩盖局部问题，也不把一次插入成功当作视觉与互动已经通过。
