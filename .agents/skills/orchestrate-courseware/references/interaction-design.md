# 让互动产生可观察的学习

用于本课需要操控、探索、实验或决策的片段。教学策划阶段说明认知作用；呈现脚本阶段再写具体操作、反馈和返回路径，不提前替教师选择组件、Runtime 或技术字段。

## 先确定互动揭示什么

用一段连贯描述说明：学生改变或选择什么，哪些条件保持不变，能观察到什么变化，怎样解释该变化，以及教师如何帮助形成结论。变量名称、取值含义、单位和比较对象要来自实际教学内容。

例如研究面积时，让学生改变长方形的一边、保持另一边不变，比较面积变化并解释关系；如果只需要认识面积定义，图示与讲解也可以完成目标，不必添加拖拽。

## 按认知任务选择操作

| 学习需要 | 可考虑的呈现与操作 |
|---|---|
| 理解变量关系 | 先预测，再控制变量、观察结果、比较并解释 |
| 理解结构或流程 | 展开局部、追踪路径、对照整体；始终能返回整体 |
| 学会方法 | 看示范、完成有支持的步骤，再独立应用 |
| 作出分类或排序 | 说明判断依据、操作对象与反馈；分类去向和真实顺序变化分开描述 |
| 检验决策或空间认识 | 用有意义的规则决策，或从不同视角观察；结果应支持解释而不只是给分 |

这些是可选方法。同一机制可以连续使用，不为“形式多样”强制更换操作；讲解、示范与总结也可以承担主要教学任务。

## 脚本写到可实施

- 写出初始画面、可操作对象、可变范围、结果如何显示，以及观察后的追问或解释。
- 区分“系统演示给学生看”和“学生亲手操作”；不能把自动动画描述成已经完成实验。
- 错误反馈指出问题与下一步可尝试的方法；关键新知识应有讲解、示范或证据支持，不只藏在正确答案中。
- 说明重试、揭示、返回与重播分别保留或重置什么。需要跨位置保留学习进度时明确写出；不要默认所有局部状态都会保留。
- 有判断或完成条件时，写清证据是什么；以正确操作、解释或结果为依据，不以点击次数冒充学会。

正文推进与教师接管仍按 [main-progression.md](main-progression.md)。互动删除后若学习目标和证据没有变化，重新判断它是否值得保留；不要为凑互动而拆散知识获得路径。
