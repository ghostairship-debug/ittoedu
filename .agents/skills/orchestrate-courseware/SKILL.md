# 编排互动课件

形成或修订教学策划、呈现简报和呈现脚本时，同时遵守 [main-progression.md](references/main-progression.md)；教师控制器只作课堂兜底，不能代替正文主推进。

目标是得到两份足够支撑制作、仍保留教师自由度的当前 Markdown；聊天记录不是交付真相。

## 原则

1. 直接读取教师提供的文件和材料，不要求教师复述已经写明的内容。
2. 材料越完整，提问越少；只有主题时可以多轮确认，不设置轮次上限。
3. 与教师交互优先用少量结构化选项（弹出按钮：继续 / 修改文件后再来 / 补一个缺口），不要连珠开放问答。只有选项盖不住的原文、数据或题干才请教师填写。
4. 不预设课型、教学法、场景数量、页面结构、互动比例或视觉风格。每一课的呈现形态写在脚本里，不写进本 Skill。
5. 默认先写中等详细的教学策划并确认，再写教学呈现脚本。材料再完整也不许两份一起交。只有教师已经提供足够清楚的对应文件时才跳过该步骤，并明示「采用已有文件」后用一次选项确认。
6. 不建立 Hash、签名、审批状态机、候选等级、固定字段清单或额外合同文件。
7. 本 Skill 不选择 Native、Runtime、Component，不写 `projectMode`、节点类型、API、Schema、工厂或命令，不写代码、Project 或导出物。呈现脚本必须选定阅读/操作表面（演示页 / 流式讲义 / 无限画布，可写 `slide` / `flow` / `spatial-2d`），并写细布局与操作；这是呈现设计，不是工程实现。

## 1. 诊断输入

读取主题、材料路径、既有两份 Markdown 和用户本轮补充。区分：

- 已由材料确定的事实；
- 可以合理起草、但需要教师复核的判断；
- 会改变教学目标、内容正确性、课堂实施或评价方式的缺口。

只为第三类弹出选项。涉及版本、来源或学科事实且不能从材料确定时，先核查权威来源；不要把检索结果伪装成教师选择。

若教师已给出可直接使用的策划或脚本，记录将跳过哪一步，不要重写已经闭合的文件。

## 2. 形成教学策划

未确认前不要写 `02-presentation-script.md`。

创建或修订 `01-teaching-plan.md`，深度为**中等**：另一位教师脱离聊天也能批准教学意图，但还不是分镜。覆盖：教谁、为何教、教什么（大纲级）、怎样知道学会、主要困难、课堂条件、材料依据和仍存在的假设。不要写逐页布局、表面选择、点击步骤、Hash 或 `case.json`。

按输入缺口起草后，用一次选项请教师确认或直接改文件。每次继续前重读当前文件，以文件为准。未确认前不进入脚本，更不进入工程构建。

## 3. 形成教学呈现脚本

策划确认后再创建或修订 `02-presentation-script.md`。用相对稳定的标题组织，使 Builder 无需猜测即可还原教师可感知的体验。每个片段（页/场/世界区域）建议包含：

- **表面**：演示页（分场、教师控节奏）、流式讲义（阅读与块）、无限画布（空间布置与漫游）。同一课可按片段混用，不要给整课贴 `projectMode`。
- **布局**：相对分区（主视觉/左/右/上/下），谁在哪；不要假装像素级设计稿，除非教师已给精确稿。
- **入场**：看见什么；尽量写清逐字文案、公式、数据、答案、解释或素材引用。
- **操作**：教师逐步做什么、学生可做什么；无限画布写明自由逛与镜头巡游如何配合。
- **状态**：交互前、中、对、错、揭示、返回、重试、重播等确有需要的路径。
- **动态类型**：整页少字的动画/特效/连续机制，还是角落里的局部互动（拖拽、配对等）。
- **不能静默改动的教学与视觉取舍**、教师控制、评价边界、静态导出差异和无障碍。

点明体验，不要写图层 kind、组件包名、Runtime API 或命令名。完成后停止第二次，用选项展示最重要的体验取舍并请教师确认。

## 4. 交给干净 Builder

两份都确认后使用 `$build-courseware-project`。优先启动不继承本轮长聊天的干净 Build Coordinator；只传：

- 两份当前 Markdown 的路径（`01-teaching-plan.md`、`02-presentation-script.md`）；
- 原始材料路径；
- 编辑器根目录，以及能力索引 `<editor-root>/artifacts/ai-capabilities/index.json`；
- 用户仍然有效的额外约束。

不要传递旧草案、被否决方案、冗长讨论摘要或本 Skill 的内部推断。不要要求 Builder 去运行已删除的 `agent-kit` CLI。若不能启动干净上下文，也要重新从两份文件开始构建，而不是依赖聊天记忆。

Builder 发现真正的教学内容缺口或需要改变教师已确认的体验时，返回本 Skill 修订相应文件；纯技术分解留在 Builder。
