# 在现有作品上修改

从当前绑定的文件、页面、选区及用户修改要求出发。已有目标明确时直接使用，不重新遍历全工程或重建作品。只有目标或修改含义存在真实歧义时才补充观察或澄清。

先确定此次需要改变的内容与可见结果。模型负责替换文案、数据、样式、布局关系或局部行为；宿主维护目标身份、关联资源、事务和应用结果。依据当前环境提供的编辑入口交付修改，不自造接口，不手工登记对象、修订号或资源编号。

- 文字修改保留事实、格式和用户要求保留的语气；长度变化时关注所在区域的容量。
- 图表修改关注数值、分类、系列和解释一致性；不把可改数据的图表替换成截图。
- 自动布局区域修改顺序、间距、比例或尺寸约束；自由定位区域才直接调整位置。先沿用现有设计，避免为移动一个对象重写整页。
- 替换素材保留用户需要的主体、比例和相关标注；新的裁剪需要看实际结果。
- 互动修订保留未涉及的状态、导航和重置行为；共享程序的修改范围以真实依赖为准。

HTML/CSS 修订保留原有 DOM 结构及相关选择器；专业正文或图表使用现有结构。普通选区有明确替换通道时，生成所需内容即可，不把整份工程 Schema 混入输出。需要视觉判断时观察目标及邻近受影响区域，修复具体问题后停止。

已有工程不会因为生成了新 HTML 就自动同步。使用实际编辑能力把修订应用到当前作品；不要调用新建课件入口覆盖人工修改。如果当前环境只能生成建议或候选，就如实交付该状态。已应用、已保存、已导出分别依据真实结果，不承诺尚未提供的自动保存或格式转换。

新建教学作品使用 `orchestrate-courseware`；已有 HTML 新建为课件使用 `build-courseware-project`；Word、Excel、PowerPoint 原格式内容修改使用 `office-content`。任务涉及特定文档格式时，只加载当前可用的对应专业 Skill，不把它的全部接口说明常驻到通用上下文。
