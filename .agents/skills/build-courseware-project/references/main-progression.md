# 教学推进与操作边界

先服从用户的使用情境。默认教师演示允许讲解后用正式翻页、键盘、目录或控制器继续；这些都是正常课堂推进，不要求每页设计闯关、失败反馈和放行状态。

用户明确要求自主学习、测验或按完成条件推进时，才实现必要的正文触发、反馈、重试及可到达的终点。关键知识先通过图示、讲解、示范或实验获得，再用问题检验；不要为了互动数量强行游戏化。

页内互动与跨页导航分开：页内操作限定本页，跨页默认复用正式导航。用户有明确导航设计时，可以深度改造教师控制台或关闭默认控制台后自写独立导航，按实现和编辑哪种更方便选择。不能引用不存在的另页 DOM，不能删除已经要求的互动。技术说明放讲稿或备注，不展示“正文主推进”等内部流程文字。

检查范围服从交付目标：初稿复用宿主机械检查与保存重开；用户要求完整互动检查时，验证其真实主路径与必要恢复；局部修订只检查受影响范围。控制器是否隐藏不再作为普通演示初稿的完成门。

自主学习确需状态时，按正式能力使用 `course-state.exists` / `course-state.compare` 和同步 `course-state.set`。已声明状态有默认值，不要把 `exists` 误当“已完成”；条件使用实际比较。目标 Surface 没有通用作者命令时使用受支持的 Component／Runtime，或说明具体缺口，不直接改 document 绕过正式命令。
