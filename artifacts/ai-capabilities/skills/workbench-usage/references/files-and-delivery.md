# 文件与保存

工作区源文与策划用文件能力，正式工程虚拟路径用工程能力；两者保存状态分别说明。已有文件按当前内容局部修订，新文档直接使用本任务可用的文件创建/写入入口，默认位置以软件回执为准，用户指定目录优先。

工程修改进入正式文档与恢复稿，默认不写盘。用户要求保存或交付已保存文件时使用当前保存入口，依据真实回执的路径和状态交付。内容提交、作业 ready、文件已保存和导出已写盘是不同事实；传输成功不能代替它们。

新建GLX只写入创建时的初始内容，后续工程修改仍需保存。`file.save` 的 `target` 使用本任务 `file.create/open` 返回的整文档句柄，不用页面虚拟路径代替；核保存回执中 `savedRevision`、`currentRevision` 与 `dirty`，尚有新改动时不能称当前版本已保存。需要冷开时先完成正式保存，再正常关闭并打开实际GLX；导出的HTML不是原生工程保存回执，也不需为核工程内容先进入HTML磁盘冲突处理。外部文件确有修改时，继续沿现有比较/协调入口处理。

用户选所需输出与位置，软件负责成果来源、文件身份和保存。目标冲突时保留用户后改，按真实冲突结果选择新名称或处理；不盲目重放结果未知的写操作。图片和计算临时成果按需用成果保存入口，报告只引用真实可打开路径。

交付给出实际文件或当前工程、已完成的内容与具体未完成项。真实预览和互动证据独立于提交/保存回执，不能仅凭源文宣称画面已检查。

HTML／ZIP 从当前正式工程编译实际运行内容与依赖，首次进入、离开返回、状态、输入、复位及所用资源按相关行为核对。GLX 是继续编辑的工程；HTML／ZIP 的运行结果与 GLX 保存回执分开。普通翻页结束不是全目标完成，生成候选、正式应用、磁盘保存和导出各取对应回执。
