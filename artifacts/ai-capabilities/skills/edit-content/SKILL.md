# 在现有作品上修改

从当前绑定的文件、页面、选区及用户修改要求出发。已有目标明确时直接使用，不重新遍历全工程或重建作品。只有目标或修改含义存在真实歧义时才补充观察或澄清。

已有 GLX 的普通改字、换图、局部布局或反馈直接读取当前目标与必要邻近事实，使用正式事务续改，不重做整作策划。主线、章节或重要互动关系实质改变时才同步已有策划的对应段落；策划不承担另一份保存义务或运行状态。

先确定此次需要改变的内容与可见结果。模型负责替换文案、数据、样式、布局关系或局部行为；宿主维护目标身份、关联资源、事务和应用结果。依据当前环境提供的编辑入口交付修改，不自造接口，不手工登记对象、修订号或资源编号。

- 文字修改保留事实、格式和用户要求保留的语气；长度变化时关注所在区域的容量。
- 图表修改关注数值、分类、系列和解释一致性；不把可改数据的图表替换成截图。
- 自动布局区域修改顺序、间距、比例或尺寸约束；自由定位区域才直接调整位置。先沿用现有设计，避免为移动一个对象重写整页。
- 替换素材保留用户需要的主体、比例和标注，新的裁剪看实际结果。来源按本次目标选择：真实事件/实物优先核适用原始材料与互联网图片，连续故事可直接参考既有角色/场景生成或编辑，普通配图按适用性选搜索/生成，精确关系用原生或代码。无全局来源顺序或固定搜索次数，生成图不冒充事实图片；不因局部换图加载完整新课流程。
- 互动修订保留未涉及的状态、导航和重置行为；共享程序的修改范围以真实依赖为准。
- 修改结论、条件或任务含义时，核对与它直接关联的标题、提示、反馈及导航文案，避免正文已改而入口仍承诺旧任务；只调整真实依赖，保留其他内容安排。

复杂动画/局部程序沿当前正式源码和参数修改，保留用户既有代码改动，不要求人工控件覆盖全部能力或在运行暂停点无损接续。已有导航保留未要求修改部分，不因新作规则自动删除已有全局控制台。

HTML/CSS 修订保留原有 DOM 结构及相关选择器；专业正文或图表使用现有结构。普通选区有明确替换通道时，生成所需内容即可，不把整份工程 Schema 混入输出。需要视觉判断时观察目标及邻近受影响区域，修复具体问题后停止。

当前精确选区可直接复用任务提供的内容和可写目标，生成所需替换即可。需要工程页、对象或源码操作说明时读取共享指南的[选择与局部编辑](../workbench-usage/references/selection-and-editing.md)或[工程内文件](../workbench-usage/references/project-files.md)；内置读取用 `skills.read {skill:"workbench-usage",path:"references/所需文件.md"}`，安装版用目录返回的完整名称。不为短编辑加载教学创作方法。不要修改外部源 HTML 后重导覆盖现有课件。

修改和保存按共享指南的[文件与保存](../workbench-usage/references/files-and-delivery.md)及实际回执说明。若环境只能生成建议或候选，如实交付该状态。

新建互动演示使用 `orchestrate-courseware`；已有 HTML 新建为课件使用 `build-courseware-project`；Word、Excel、PowerPoint 原格式内容修改使用 `office-content`。所选节点、背景和行为可以按需深改，仍保正式数据、未选内容和人工布局。需要特定格式的内容策略时，按需读取当前可用的专业方法；已有工具入口明确时直接修改。Skill 不解锁工具，也不把完整软件接口常驻到通用上下文。
