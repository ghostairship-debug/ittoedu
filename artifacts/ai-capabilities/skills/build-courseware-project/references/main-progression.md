# 正文主推进构建与 QA 合同

本合同把已确认脚本中的正文主路径落实为可运行课件。教师控制器是课堂兜底，不是课程导航骨架。

## 构建前路径检查

1. 从脚本标明的起点列出预期主路径、所有分支位置和教学终点。
2. 对每个已创作的非终点位置（包括分支位置），确认脚本同时给出正文内触发面、明确目的地、前置条件和失败/未完成后的继续方式。
3. 只把正文按钮或链接、选择/互动完成、明确条件下的自动推进及其它可发现正文动作计入路径；控制器、缩略导航、键盘快捷键或开发调试跳转不计入。
4. 至少存在一条有限的起点到终点正文路径，并且每个非终点分支都能经正文动作到达某个教学终点；守卫、错误、重试或揭示不能把它变成死路。

脚本缺少上述事实时，停止构建并返回 `$orchestrate-courseware` 的相应阶段；不要自行添加下一步按钮、猜测自动推进时机或把控制器当替代路径。若脚本事实完整但 Capability Index 没有可表达载体，只有必须改变教师已确认的可感知体验时才返回编排阶段；否则报告精确产品缺口，不伪造实现。

## 实现边界

- 依据当前 Capability Index，在 Native 声明式互动、课程状态/导航守卫、Component 或 Runtime 中选择最窄且真实可执行的正文触发；不写播放器不会执行的规则。当前 Published V2 的 `node.click` 窄切片支持 `course-state.exists` / `course-state.compare` 条件和同步 `course-state.set` 动作；仍没有判题结果自动分支或自动写状态桥。已声明状态在播放启动时都有默认值，因此完成门通常用 boolean/number `compare`，不要把 `exists` 误当“已完成”。
- 外部案例 Builder 当前只暴露 Slide-local 声明式互动作者命令；Flow/Spatial 的 Native/global `node.click` 没有通用作者命令时，改用 Component/Runtime 或报告精确 Facade 产品缺口，不直接改 document 绕过正式命令。
- 控制器固定为独立的全局 Overlay 兜底。正文使用完整表面，不为控制器预留安全区，也不复制控制器到位置内容中。
- 若正文推进依赖状态或守卫，完成动作必须真实写入或满足条件；拦截提示、重试/返回和重新开始后的默认状态都必须可达。

## 真实 Player 与 HTML 验证顺序

先验证正文主路径，再验证控制器：

1. 在起点隐藏或收起教师控制器，只通过正文动作从起点走到教学终点；记录每次触发、目的地和可见结果。
2. 覆盖脚本存在的守卫拦截、错误反馈、重试、揭示和自动推进；证明被拦或失败后仍能回到正文路径。
3. 执行重新开始，确认位置与课程状态回到正式初始值，并再次能够由正文推进。
4. 主路径通过后，单独验证控制器的恢复、手动跳转、重播和守卫越过。控制器成功不能补偿正文路径失败。

以上顺序同时适用于 CoursePlayer 和默认离线 HTML。任一非终点只能靠控制器继续时，交付仍失败，不得称为 `engineering candidate`。
