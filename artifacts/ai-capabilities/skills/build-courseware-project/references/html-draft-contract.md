# HTML 输入与分页

接受普通 HTML、CSS、SVG 和必要的 JavaScript，不要求私有模板、登记表或编辑编号。保留原有标签、样式和布局关系；软件解析、包装并管理资源。已有第三方页面不需要先被模型重写。

创作彼此独立的课件页时，可用 body 下的 `section`，或唯一 main 的直接 `section` 表达页序。每页具有实际内容，公共 CSS 可以放在 head；页内逻辑应能在该页独立运行。普通 section 是方便软件识别分页的标准结构，并非所有输入的强制合同。

完整页面、共享 DOM 状态或跨页程序不能可靠分离时，保留整体 HTML。没有 section、含共享脚本都不能单独作为拒绝输入的理由。拆页后是否保留共享行为以宿主实际结果为准，不能把逻辑删除后称为成功。

布局可使用 Grid、Flex、自然排版、媒体查询和必要的绝对定位。按目标作品设置页面尺寸或宽度约束；内容过长时调整设计，不能靠裁切掩盖缺失。缩放画布与内容重新排版是不同操作。

资源使用当前工作区可读取的文件或可用 data URI；资源读取范围、闭包和绑定由宿主维护。所引用的图片和字体需要真实存在。代码不得含供应商凭据；联网资源按当前已授权能力处理。

整页程序继续通过现有 Runtime 承载，文字和图片的轻编辑能力不意味着可以直接编辑任意程序内部对象。可独立组装的静态内容保留 Web 组合结构。具体限制应对应当前内容，不能用静态化或截图替代已要求的互动。

局部独立互动可用标准 `<iframe src="experiment.html" title="实验" style="width:100%;height:180px;border:0"></iframe>`，或标准 `srcdoc`。本地嵌入 HTML 及其图片、样式、脚本由软件读取闭包并包装成局部 Runtime，外层静态兄弟保留结构化编辑。模型无需生成 Runtime 协议、内部编号、素材登记或后备图。共同脚本和外层程序仍整体运行；第三方内容无需改写成这一可选组织方式。
