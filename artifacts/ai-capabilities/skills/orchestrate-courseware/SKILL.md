# 创作教学作品

先读用户材料、已有策划和当前作品。完整新课按下列阶段推进；续作从当前实际阶段继续。默认面向教师演示，演示页按 1280×720；阅读与长文选 Flow，镜头叙事选 Spatial，允许混用。用户明确要求的用途和规格优先。

模型负责内容、图示、布局关系、视觉和互动设计；软件负责排版、身份、素材绑定、装配和播放。页面用普通 HTML/CSS/SVG 表达，不手算派生坐标，不填写工程编号。先读[工程内文件](references/project-files.md)，之后只读当前需要的参考。

每个新概念都要有足以支持教学的解释、图示、示范或实验。关键知识不能只出现在答案反馈或素材说明中；不以“想象图甲”代替图甲。比较时保持其他条件一致，说明单位、条件和判断依据。让操作带来真实可见的证据变化，反馈回应实际选择，并支持必要的重试或重置。教学难点不明确时再参考[教学质量](references/teaching-design-quality.md)；需要实验、探索或决策时参考[互动设计](references/interaction-design.md)。

1. **策划**：在工作区保存 `<课名>/01-教学策划.md`，写明目标、主线、难点、表面选择及理由、逐页要讲清的内容与证据、图示/互动需求、视觉和导航方向。通过 `ask_user` 等教师确认。
2. **框架**：在同一课件工程内写主题、逐页文字和版式、简单图示；复杂素材先写有具体说明的待填引用。让教师在编辑器里看到框架，通过 `ask_user` 确认。教师可能手改，继续前读取当前工程。
3. **资产与装配**：按框架逐项补图示、图片与互动，软件自动填入引用位置。素材优先级为用户材料 → 资产库 → 示意图用 SVG、照片查图库 → 已配置图像模型。没有可用来源时保留待填项并说明原因，不能以占位宣告完整交付。取图方法见[素材](references/assets.md)。
4. **检查与精修**：在真实预览中检查关键页和核心互动，只修具体问题。用工程文件或当前选区原位修改，保留其他内容和人工调整；不重新生成整课。
5. **交付**：说明当前工程、页面与表面、素材来源、组件新建/复用和未完成项。用户要求保存时调用 `project.save`；未保存要明确说明。优质组件仅在用户要求时存入资产库。

用户明确要求“根据材料自动创作”或已授权自动推进时，两处不等待、不提问，策划与框架仍照常产出；否则策划、框架默认各确认一次。局部修改使用 `edit-content`，纯第三方 HTML 导入使用 `build-courseware-project`。

从框架起，工程是唯一作品。不要另写整课 HTML 后再导入，不用 `build.*` 串接工程步骤。页面不另写翻页、键盘或窗口缩放逻辑；需要导航时沿用教师控制台并调整外观，控制台源码确需修改时先读工程内现有源码。页内逐条出现用 `fragment`；复杂实验、模拟和游戏放在独立组件，不把所有简单互动都程序化。教学推进见[边界](references/main-progression.md)；专业图表或正文按需使用[短组件表达](references/web-composition-examples.md)。
