# 编排互动课件

根据教学主题、教材、教案、题目、课程标准或既有课件，在课例目录形成 `01-teaching-plan.md`、`02-course-frame.html` 与一页 `02-presentation-script.md`（讲解与操作说明）。接着交给 `$build-courseware-project` 做后置表示规划与组装。课件内容遵守 [main-progression.md](references/main-progression.md)：先让学生通过观察、讲解、证据与操作获得知识，再用练习检验；教师控制器只作课堂兜底。本课需要探索变量、结构或实验时，按需读 [interaction-design.md](references/interaction-design.md)。

## 模式与确认

- 默认模式：教学策划写完后展示当前文件，教师确认①；框架 HTML 与说明写完、在工作台预览后展示当前文件，教师确认②。两次确认分别针对教师看过的当前制品；修改后重新展示受影响制品。确认前停在相应阶段，不预先代签。信息不足时优先用弹窗提供少量高影响选项，材料已经回答的事实不再问。
- 用户明确要求“根据材料自动创作”：跳过全部确认，也不提问；仍写上述中间文件，缺口采用合理假设，直接衔接 Builder 直到保存好的成品，并在交付时列出假设。不要把普通“直接做完”推定为这个模式。
- 用户明确要求按材料要求实现：逐项保留原文、数据、题干、页序、互动与视觉约束，不简化、不删减、不换成静态图。若确实做不到，默认模式在发现时先用弹窗询问；自动模式继续可完成部分，交付时逐条说明未做到的要求和原因。不得将材料静默降级。

两种模式均不创建额外审批状态文件或 Hash。对已有课件的局部修订，保留未要求改变的内容与身份；若用户只要策划或 HTML，按实际请求停在该产物。

## 1. 教学策划

直接读取教师给出的文件、路径、附件和本轮约束。区分材料事实、合理假设与会改变目标的缺口。既有 PPT 先辨明保留原稿、局部修订或重做教学的真实意图；只在用途不清且影响结果时询问。涉及学科事实或版本时先核查可靠来源，不把检索结果伪装成教师选择。

起草时阅读 [teaching-design-quality.md](references/teaching-design-quality.md)。`01-teaching-plan.md` 用教师可修改的正文写明学习对象与条件、目标、知识获得主线、关键困难与处理、评价证据、材料依据及假设。它应足以让另一位教师理解怎样推进，不写成题目清单，也不预先选 Native、Runtime、Component 或工程 API。已有可用策划可以采用并注明来源，无需重写。

默认模式在这里展示文件和关键教学取舍，等待确认①。自动模式接着写框架。

## 2. 框架 HTML 与讲解说明

在确认②之前，不读取编辑器能力简介、Capability Index、能力卡、Native Schema，也不展开课件编辑工具族。此时只根据教学目标与材料设计教师和学生可感知的体验。

写一个整课 `02-course-frame.html`。`<body>` 下每个顶层 `<section>` 对应一页，保持稳定顺序与清晰标题；每节根据内容选固定画布、流式长页或镜头编排，在 HTML 中写出布局、逐字文案、基本视觉层次和大致功能。互动的触发、反馈、重试与前往目标写在页面里；不要只画静态截图。图片、音频、视频用没有 `src` 的 `<img>`、`<audio>`、`<video>` 占位，并在邻近文字或属性中写清素材需求。此阶段不生成素材，不引用远程脚本或 CDN。

另写一页 `02-presentation-script.md`，只补 HTML 难以表达的教师讲解、学生操作、控制与评价；不要复制整套页面，也不要提前做表示规划。框架 HTML 在工作台预览；默认模式展示预览和说明，等待确认②。自动模式直接进入 Builder。

## 3. 交给 Builder

把课例目录、当前教学策划、框架 HTML、说明、原始材料、模式、确认事实和仍有效约束交给 `$build-courseware-project`。Builder 到表示规划阶段才读短能力简介。不要要求教师提供或切换到编辑器仓库，也不运行已删除的 `agent-kit` CLI。默认模式两次确认完成后继续；自动模式无需确认继续。只传当前文件与有效约束，不传旧草案或被否决方案。

Builder 发现必须改变教学内容或确认过的体验时，默认模式返回相应制品让教师选择；自动模式按不降级规则记录无法实现的要求。技术载体选择留给 Builder。
