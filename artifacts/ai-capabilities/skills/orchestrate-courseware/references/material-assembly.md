# 从材料到正式对象

本指南说明已有入口，不规定作品类型、页数、每页对象数量或构图。先决定观众要看什么关系、进行什么操作，再选择能继续编辑的载体；教育任务再按需要安排活动。分素材不是把每个词拆成对象：专业连续正文、带刻度的完整图示、具有共同状态的局部实验各有合理整体范围；页面标题、说明和独立配图则无需包在同一整页脚本中。已确定且独立的素材及布局可以批量生成、同批装配；分素材要求约束最后的对象结构，不规定一次只能生成/插入一项，不为此再建从任意整页程序逆向拆素材的平台。

## 普通内容直接装配

关键场景和整体扩展沿同一工程装配，内容主线先于载体结构。用户已确定的页面描述可用已提供的批量入口一次提交，身份与完整目标回执由软件维护；模型不逐页抄句柄或登记编号。依赖前一结果的内容才顺序推进，不为了方法阶段再加机械等待。

`file.create` 或 `file.open` 返回整文档目标；`listChildren {target:本次返回的整文档句柄}` 得到页面句柄。新增页沿 `project.apply` 的 `surface.add`，随后取当前页面，不猜编号或沿用过期句柄。工具定义与真实返回为准。

普通内容使用 `object.insert`，例如下列参数传给该工具；文案、位置和尺寸依当前构图选择，数值只是调用形状示例：

```json
{"target":"本次取得的页面句柄","kind":"text","text":"观察与解释","x":48,"y":40,"width":760,"height":72}
```

软件准备专业数据、容器和身份。正文可独立插入；公式用 `kind:"formula"`，简单图形用 `kind:"shape"` 与实际 `shapeType`。Flow 正文插入可选 `destination:"document"`，纸张浮层选 `"paper"`。需要专业表格、图表或填空时同样使用已有类型，再依实际对象能力填写内容。不要把 `object.author` 当插入入口，或把 `object.place` 当图片入口。

文字、公式、图形、表格或图表的初始外观已经确定时，可在 `object.insert` 一并提供 `appearance`，语义与后续 `object.update.properties.appearance` 相同，一次插入完成内容、位置和外观。省略时使用人工插入默认；字段依当前类型的专业能力，不把任意CSS或填空配置当作外观。后续局部修改仍用已有对象入口。

要调文字外观，可直接使用插入回执 `affected` 中返回的新对象句柄，再用 `object.update`，无需猜对象路径；也可使用 `project.list/read` 返回的对象路径。例如 `properties.appearance={fontSize:40,color:"#15384d"}`；局部位置尺寸用 `properties.frame`，多对象对齐或分布用 `object.layout`。复用已观察对象的外观可用 `appearanceFrom`，不反复转抄所有样式。已确定且独立的内容可同批调用准备；需要前一回执的新目标时顺序推进。

## 专业表格与图表数据

材料需要可编辑的分类或数值表征时，可用专业表格或图表，不必仅为固定数字另写程序；载体仍按本课的表达与互动需要选择。`object.insert {target:当前页面句柄,kind:"chart",chartType:"bar"}` 返回新对象后，对其 `affected` 句柄使用 `object.update.properties.data`，可直接提供下列已有数据格式，不抄内部点编号或运行代码：

```json
{"title":"分类数量（个）","categories":[{"label":"甲类"},{"label":"乙类"}],"series":[{"name":"数量（个）","values":[20,35]}]}
```

类别、系列及数值依实际材料填写；每个系列的数值数与类别数相同，使用有限数字。软件维护正式身份，未提供的图表类型、外观和位置保留。单位可写在标题或系列名，当前没有独立轴标题或单位字段。数据来源和模拟、测量的性质要说清楚。

`kind:"table"` 新插入的是默认表格。读取当前专业 `data`，保留其 `columns/rows/cells` 和身份，只改需要的单元格文本；首行是表头时设置 `headerRowCount`。已有富文本格按实际 `content` 修改，不再同时加 `text`。单格短改也可用 `object.author {target:当前表格句柄,change:{kind:"table",edit:{kind:"cell-text",cellId:实际读回的单元格身份,text:"新内容"}}}`。整表写入沿 `object.update.properties.data` 或已观察的 `.data.json`，不能自造 `rows:[[...]]` 格式。

表格与图表的源数据持续可编辑，仍要在实际页面看尺寸、边界及标签。当前图表的 `appearance.fontSize` 只改变标题字号，不能以此判断轴、分类和数据标签已经达到课堂可读尺度；发现具体限制时，按材料需要调整表达，不能把写入成功当作视觉通过。

## 图示、图片与局部程序

先按表达任务选择来源与载体，具体判断见[视觉与素材](visual-design.md)。真实事件/实物图片需要合适来源；连续故事可直接生图并用真实参考维持角色/场景；精确图示或联动内容可直接用原生/代码。没有统一搜索→生图→SVG的必经链，也不把“示意图”一律判为手写SVG。

已有图片、图库/生成结果与适合直接复用的静态 SVG 可沿媒体入口：`media.insert {target:当前页面句柄,source:实际授权文件路径或当前返回的资源}`。软件读取字节、绑定资源和登记身份；未指定 frame 时按媒体尺寸放置，指定时用当前工具 `frame:{width,height,transform:[1,0,0,1,x,y]}`，后续移动沿正式对象入口。`asset.import` 用于组件归档，不能拿它插入普通图片。媒体不表示内部每条SVG路径都成为原生可拖拽图形。

新绘制且需修改、参数变化或互动的图示，优先保留合适的局部代码表达，可内联 SVG/Canvas/HTML；无需先存外部SVG图片再反复回源文件应用。`project.apply {path:当前页面结构路径,intent:"insert",content:素材源文}` 可装配局部 HTML/SVG；内部保 viewBox/关系，页面位置交正式frame，不把整页 absolute/left/top 编进素材根。共同状态的程序保其合理整体，外围标题/说明/独立配图分开。现局部SVG可能保为含源文的 Web 组，不冒称内部全部原生可编辑，亦不为每条路径增加人工控件。见[局部表达](web-composition-examples.md)。

只有明确采用外部SVG资产时，才沿该文件修改源文，再以 `media.apply {target:当前图片句柄,source:修改后的实际文件路径}` 原位应用；保对象身份、人工位置和未指定效果。媒体入口读取磁盘字节，外部源文若是 `saved:false`，需先保存该源文档再应用；已回 `saved:true` 不重复保存。改变外部文件不会自动刷新工程内资源，不能靠猜资源编号更新。SVG可修改而非只能重生，但这条外部源文流程不是新绘图默认步骤；已进入工程的素材是当前作品事实，续改先读现目标，避免用旧外部版本覆盖人工修改。

复杂实验保留一个局部程序，内部有自己的图形、控制项和反馈；实验外标题、知识说明和其他素材继续独立。跨页记录或导航只使用已观察的宿主能力，不以界面文案假装联动。编辑 HTML 程序内容先读实际 `.content.html` 或模块数据，不为改文案重读默认运行器和其依赖包。

装配后看最重要片段的真实画面与操作，发现放大、裁切、滚动条、默认字号不合适或图文条件不一致就修该素材及其正式 frame。不要用整页截图或再生成整页 HTML 来掩盖局部问题；也不把一次插入成功当作视觉与互动已经通过。
