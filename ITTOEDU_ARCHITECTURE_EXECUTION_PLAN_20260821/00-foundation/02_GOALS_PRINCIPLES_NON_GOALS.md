# 目标、原则与非目标

---

## 1. 一级目标

### G1：能力不降级

重构前可达的长期能力，重构后仍可达，并可在后续继续增强。

### G2：唯一可写工程真相

所有模式和 Surface 最终修改同一个 `CourseProjectDocument`，不再维护可写的 V8-shaped project 或多个互相同步的文档副本。

### G3：Feature 纵向解耦

修改组件、互动、媒体、诊断或某个 Surface 时，AI 可以从一个 Feature 公共入口进入，而不是同时遍历几个上帝文件。

### G4：模式共用能力内核

简单、专业、代码模式只决定：

- 入口是否可见；
- 默认展示层级；
- 表单复杂度；
- 代码视图。

它们不得拥有不同的业务逻辑和写入链。

### G5：开发认知按需加载

AI 先通过静态知识图谱生成 Context Pack，再读取少量相关源码。

### G6：验证高效

对正确性负责，但不把每个任务变成完整发布验证。

---

## 2. 架构原则

### P1：先收口再拆文件

先明确数据真相和职责，再移动代码。禁止把大文件机械切成多个互相深度引用的小文件。

### P2：单向数据流

```text
Document
→ Selector / Projection
→ UI / Player / Export
```

投影不得反向成为写入源。

### P3：纯命令优先

能够写成纯函数的领域修改应保持纯函数：

```ts
result = command(document, input)
```

Store 只负责：

- 调用；
- 事务；
- history；
- UI 状态；
- 错误展示。

### P4：草稿与文档分离

文本输入、代码编辑、拖拽中间态可以局部存在，但只有提交时才更新 canonical document。

### P5：公共入口稳定

跨模块只通过 Feature `index.ts` 或明确公共文件引用，避免深层互相导入。

### P6：复用现有协议

不因内部重构创建 V10；不建立第二套 Component、Runtime、Interaction 协议。

### P7：高级能力渐进披露

高级能力可以隐藏在专业或代码模式，但不因为默认界面简洁而删除。

### P8：索引可重建

开发知识图谱必须可由源码重新生成，不能成为新的手工事实源。

### P9：方案完整，执行克制

方案要覆盖长期方向与风险；每个实际任务只完成其最小闭环。

---

## 3. 明确非目标

本轮不做：

- 整体重写；
- 替换 React、Zustand、Immer、Electron 或 Phaser；
- 引入 Redux、MobX、XState、Event Sourcing；
- 建立依赖注入容器；
- 建立微前端或插件平台；
- 建立图数据库服务器；
- 立刻加入 Embedding 和向量搜索；
- 立刻统一三种 Surface 的内部模型；
- 修改所有 UI；
- 删除专业、代码、组件或 Runtime 能力；
- 为覆盖率数字补无意义测试；
- 每个任务都跑完整桌面 E2E。

---

## 4. 删除与保留的判断方式

### 必须保留

满足任意一项：

- 当前核心用户路径；
- 明确长期路线能力；
- persisted 数据兼容需要；
- Player/Export/AI Builder 仍在消费；
- 已有真实工程依赖；
- 是高级能力但简单模式未显示。

### 可暂时收进实验区

- 路线有价值；
- 当前实现不完整；
- 默认 UI 不应暴露；
- 仍需保留代码或样例验证。

### 可以删除

必须同时满足：

1. 无运行时消费者；
2. 无 persisted 兼容义务；
3. 无明确路线价值；
4. 有唯一替代实现或确认不再需要；
5. 测试、文档、索引可同步删除；
6. 删除后核心流程和相关 Feature 验证通过。
