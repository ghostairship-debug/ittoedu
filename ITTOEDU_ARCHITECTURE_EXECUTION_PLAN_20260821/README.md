# IttoEdu 统一架构、能力整合与项目知识系统执行方案

> 方案基线：ghostairship-debug/ittoedu `main` @ `690411d4a101b4020134712108262bddf08e0d2e`  
> 方案日期：2026-08-21  
> 适用方式：单人维护、AI/Vibe Coding 为主、允许按任务调用多个编码 Agent  
> 核心目标：**不降低产品能力上限，同时显著降低实现耦合、认知成本和回归概率。**

---

## 1. 本文档包解决什么问题

IttoEdu 当前同时具备 Slide、Flow、Spatial、Runtime、Component、互动规则、素材、预览、导出、简单/专业界面与代码编辑能力。这些能力本身大多具有长期价值，问题不在“功能太多”，而在于：

1. 多种能力集中在少数超大文件中；
2. V9 文档、旧形状投影和多个作者会话同时存在；
3. 简单、专业和代码入口没有完全共用一套能力 API；
4. 工程检查、教学分析和导出校验混在一个产品入口中；
5. 项目认知索引依赖手工维护并已出现路径漂移；
6. 后续 AI 经常需要重新扫描大量源码和历史文档。

本方案采取的路线是：

```text
保留并增强产品能力
        ↓
统一唯一可写数据真相
        ↓
按 Feature 建立清晰模块边界
        ↓
让简单/专业/代码模式复用同一能力内核
        ↓
建设静态生成的轻量项目知识图谱
        ↓
用 Context Pack 替代 AI 每次全仓库阅读
```

---

## 2. 关键决策

### 2.1 保留的长期能力

以下能力不得因为当前使用频率低而删除：

- 简单模式；
- 专业模式；
- 代码模式；
- 内置/本地/未来远程组件库；
- Component API 4；
- Runtime API 2/3；
- 完整互动与动画规则；
- Slide、Flow、Spatial 与 Mixed 课程；
- 教师控制器与全局层；
- 结构检查、教学流程分析和视觉密度分析；
- HTML、网页包、PPTX、PDF、DOCX 导出。

### 2.2 需要删除的是重复实现

优先删除或收口：

- 可写的旧 Project/V8 形状；
- 多套互相同步的文档状态；
- 多套 history；
- 缓存后又反向写回的投影；
- 已完全失效的适配器、任务卡、历史入口和索引条目；
- 没有消费者且没有路线价值的实验实现；
- 简单/专业/代码模式中重复实现的业务逻辑。

### 2.3 项目知识图谱采用轻量静态方案

建设开发侧 `repo-index/`，但不引入：

- Neo4j；
- 向量数据库服务；
- 独立后端；
- 常驻索引进程；
- 产品运行时依赖。

第一版只使用现有 TypeScript 工具链生成 JSON/JSONL 图数据，并提供按任务输出小型 Markdown Context Pack 的 CLI。

## 4. 推荐启动方式

### 第一步：锁定方案基线

```bash
git rev-parse HEAD
git status --short
```

若 HEAD 已不同于本方案基线，不需要重写整套方案，但应先更新：

- `00-foundation/01_BASELINE_AND_CURRENT_FACTS.md`；
- `repo-index/generated/manifest.json`；
- 相关 Feature 元数据。

### 第二步：先建设知识系统 V1

优先执行：

```text
IDX-01 → IDX-02 → IDX-03 → IDX-04
```

这样后续重构任务即可使用 Context Pack，减少重复读取。

### 第三步：按阶段推进，不直接重写

```text
P0 基线与索引
P1 Feature 边界与公共入口
P2 低风险解耦
P3 唯一文档与历史
P4 模式、组件与诊断整合
P5 Surface 模块迁移
P6 Legacy 清理与最终收口
```

## 5. 正确性与效率原则

### 正确性优先

-  persisted Schema 初期不改；
- 每次只迁移一个职责；
- 新旧路径短期并存时必须单向；
- 投影只能读取，不能反向写回；
- 删除前必须确认消费者与路线价值；
- 方案中的索引永远低于源码与 Schema 的权威级别。

### 执行不过度验证

- 基线时做一次完整验证；
- 每个任务只跑最相关测试；
- 每个阶段结束做一次阶段验证；
- 最终收口只做一次全量验证；
- 不因小改动反复运行完整 E2E 和桌面构建。

详细规则见 `40-development/02_VALIDATION_STRATEGY.md`。

## 6. 最终形态

完成后，AI 开发任务的默认流程应是：

```text
任务描述
→ repo:context 生成 4k–12k Token Context Pack
→ 阅读相关 Feature 公共入口和少量源码
→ 通过统一命令修改唯一 V9 文档
→ 跑目标测试
→ 更新自动索引
→ 交接
```

而不再是：

```text
全量读取 README / 计划 / 历史任务 / 大 Store / 大 App
→ 猜测真实入口
→ 在多个状态源之间补接线
→ 修复一个问题并引入另一个回归
```
