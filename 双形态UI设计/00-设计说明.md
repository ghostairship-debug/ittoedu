# 果铃统一工作台与原生编辑器设计说明

> 版本：V3.1 · 2026-09-17  
> 范围：前端产品形态、信息架构、布局与视觉原型  
> 原型入口：`v3/index.html`（默认工作台）与 `v3/index.html?view=editor`（原生编辑器）  
> 边界：本说明及配套页面是设计原型，不代表产品已经实现，也不代表长期能力已经进入当前排期。

---

## 1. 设计结论

果铃是一个以真实文件、任务和持续修改为中心的 AI 原生工作台。V3 不再把“人工编辑”和“Agent 工作”拆成两套产品，也不再用固定三栏规定唯一工作方式，而是建立两个连续的工作位置：

1. **工作台**：组织工作空间、可选项目、文件、会话和任务；支持阅读、创作以及有足够深度的高频轻编辑。
2. **原生编辑器**：承载果铃原生互动内容的完整专业编辑能力。进入编辑器只是同一内容的布局与工具集合切换，不重新打开工程，不丢失选区、视图、对话、候选或撤销历史。

两者共用同一套文件身份、保存状态、选择上下文和 AI 任务状态。界面可以自由收展和停靠，但布局变化不改变能力，也不产生“简洁模式 / 专业模式”这样的第二层模式。

这套形态服务于长期产品方向，同时保持当前建设边界：Office 高级编辑在 WPS、Microsoft Office 等专业宿主中接续；自研完整 Office 编辑器只是长期可能方向；外部 HTML 的编辑器级支持同样属于长期能力，前中期不作为原型承诺。

## 2. 产品层级与用户概念

### 2.1 工作空间、项目与课例

```text
工作空间（真实根目录，也是 AI 的默认权限范围）
├── 全部文件与文件夹
├── 未归项目的工作空间会话
└── 项目文件夹（可选、由用户指定）
    ├── 项目文件与默认产出位置
    ├── 该项目的会话与任务
    └── 项目类型：课例、提案、研究等
```

- **工作空间**是用户明确选择的根目录，也是安全与权限范围。用户可直接在整个工作空间工作，不必先建项目。顶部工作空间切换器只切换这些独立根目录，不列出根目录内部的项目。
- 在产品合同中，AI 对当前工作空间默认具有完整工作权限；工作空间以外默认只读，写入、执行或其他更高权限需要另行授权。V3 只表达这项界面与权限合同，不声称设计原型已经实现授权隔离，也不改变当前宿主的实际权限。
- **项目**是工作空间内由用户指定或新建的真实文件夹，用于组织有明确目标、材料和连续会话的工作，完全可选。项目为会话提供优先上下文和默认产出目录，但不把 AI 困在项目文件夹内；仍可引用工作空间里的其他内容。
- **课例**是教育场景下的一种项目类型，不是全产品固定的二级目录。
- 普通目录可以任意嵌套，但只有用户明确指定的文件夹才成为项目，不能把工作空间中的所有目录自动项目化。
- **会话**可以挂在某个项目文件夹下，也可以是不归属项目的工作空间会话。会话记录交流连续性，任务记录一次具体执行，两者不混为一谈。

首页只给出三个主入口：`描述任务`、`打开文件或文件夹`、`继续最近工作`。新建项目是在当前工作空间中新建并命名一个真实文件夹，或把现有文件夹指定为项目；它是管理选择，不是使用 AI 或打开内容的前置条件。

### 2.2 文件、任务与内容视图

- 文件是实际资料或作品，始终显示真实名称、位置、保存状态和与当前任务的关系。
- 任务展示目标、采用的资料、进展、产物和需要用户处理的事项，不退化为一段聊天记录。
- 内容视图按需打开：文档、图片、课件画布、预览、变更对比或任务结果都可成为主区域；没有内容需要查看时，不保留空画布占位。

## 3. 两个工作位置

### 3.1 统一工作台

工作台围绕“完成事情”组织，而不是围绕某一种编辑器组织。它包含四类可组合区域：

| 区域 | 职责 |
|---|---|
| 资源管理器 | 左栏上方，始终对应整个工作空间；支持定位、引用、拖入和基础文件操作 |
| 项目与会话 | 左栏下方，按 Codex 式项目文件夹分组展示各自会话，并保留未归项目的工作空间会话 |
| 主内容区 | 任务概览、文档、材料、课件画布、预览、对比或产物，按需打开和关闭 |
| 助手区 | 对话、当前引用范围、执行状态、结果与待办；可以停靠或收起 |

工作台的轻编辑不是只保留最轻的动作。凡是高频、结果可预判、能够可靠保存并撤销的操作，都应直接提供。例如：

- 文字修改、基础字形与段落样式；
- 图片替换、裁切和常用适配；
- 对象移动、缩放、对齐、层级和复制；
- 页面或场景的新增、删除、复制与排序；
- 常用内容结构调整和即时预览；
- 基于真实选区的 AI 修改。

是否开放某项操作取决于当前文件的可靠读写能力，而不是人为规定“简单操作手动、其余只能找 AI”。无法持久化的对象保持只读，并明确给出对应宿主或转换入口。

### 3.2 原生编辑器

原生互动内容需要完整编辑时，通过`在编辑器中打开`进入原生编辑器。这个动作具有以下含义：

- 内容、当前页或场景、选中对象、缩放位置保持不变；
- 撤销与重做历史、未发送的对话草稿和任务上下文连续；
- 只是展开结构、属性、交互、状态、组件与运行时等专业工具；
- 编辑器内不再区分简洁模式和专业模式，面板收起只是布局偏好；
- AI 助手仍然可用，并以相同选区和文件版本工作。

原生编辑器与工作台不是两个工程，也不是导入导出的关系。返回工作台后立即看到同一内容的最新状态。

### 3.3 外部专业宿主

Office 文档的专业排版、公式、动画、复杂表格和宏等能力由对应宿主承担。工作台的“在专业宿主中打开”允许用户选择 Microsoft Office、WPS 或系统中的其他兼容编辑器；Markdown 也可以选择外部专业编辑器。外部保存后，果铃检测文件变化并重新载入。

前中期不假装主应用拥有完整 Office 编辑能力，也不在本轮开发这些宿主接续能力。长期可以逐步建设自有 Office 编辑器；达到正式兼容要求后，果铃原生 Office 编辑器成为默认宿主，外部宿主继续作为可选项。外部 HTML 的完整编辑器支持同样属于相当长期方向，V3 原型只表达未来可接入的位置，不展示为当前可用功能。

### 3.4 试运行边界

“试运行”只用于具备播放语义的 PPT、PPTX 和 `.h5lesson`。文档、Markdown、图片及普通资料使用预览、阅读或编辑，不显示试运行入口。原型出现试运行按钮只是在对应内容上的交互演示，不证明真实播放器或格式兼容已经接入。

## 4. 自由布局系统

### 4.1 基本规则

V3 不规定“左边一定是资源、中间一定是聊天、右边一定是画布”。默认布局只是第一次打开时的起点，用户可以：

- 分别展开或收起左侧栏、右侧栏；
- 独立展开上方资源管理器和下方项目／会话区域；
- 拖动侧栏分隔线调整宽度；
- 将内容区与助手区左右排列或上下排列；
- 关闭主内容区，只保留任务与对话；
- 在需要查看作品时重新打开内容区；
- 将画布或文档置于主区域，并临时进入专注显示；
- 保存当前布局偏好，并一键恢复默认布局。

面板移动、收起或切换方向只影响显示，不改变当前文件、任务、选区、编辑能力和保存状态。生成结果不得擅自重置用户布局。

### 4.2 默认工作台布局

```text
┌──────────────────────────────────────────────────────────────┐
│ 全局栏：工作空间切换 / 打开内容 / 保存与交付 / 布局           │
├──────────────┬──────────────────────────────┬────────────────┤
│ 左侧栏       │ 助手／会话区                  │ 主内容区（按需）│
│ 工作空间资源 │ 当前会话与执行                │ 文件/画布/对比  │
│ 项目＋其会话 │ 可与内容上下或左右排列         │ 可关闭、可调宽  │
└──────────────┴──────────────────────────────┴────────────────┘
```

当前 V3 原型演示的初始默认是左侧工作空间资源与项目会话、中间助手、右侧内容。它只是起点，不是推荐用户长期固定使用的唯一布局。内容和助手可以左右互换或上下排列；若尚未打开内容，内容区可以关闭，开始对话也不会强行弹出空白画布。

### 4.3 默认编辑器布局

```text
┌──────────────────────────────────────────────────────────────┐
│ 编辑器栏：返回工作台 / 内容名 / 保存 / 撤销重做 / 预览与交付 │
├──────────────┬──────────────────────────────┬────────────────┤
│ 场景树       │ 原生画布                      │ 属性与专业工具 │
│ 展开各场景状态│ 当前场景、状态与选区连续        │ 可收起调宽     │
├──────────────┴──────────────────────────────┴────────────────┤
│ 当前场景状态条：切换 / 新增 / 重命名 / 排序；可选助手 Dock    │
└──────────────────────────────────────────────────────────────┘
```

编辑器保留稳定的结构导航和专业工具入口，但所有面板都可收起。不存在因面板多少而不同的编辑模式。场景树展开显示每个场景的状态；底部状态条操作当前场景的状态。切换状态必须让画布显示该状态的真实画面变化，并提供新增、重命名与排序入口，不能用固定的单个“状态属性”示意代替状态导航。

### 4.4 `.h5lesson` 的场景与状态

- 工作台打开 `.h5lesson` 时，内容区提供场景条，并在其下显示当前场景的状态条。
- 原生编辑器左侧以场景树展开状态，底部状态条聚焦当前场景，支持状态切换、新增、重命名和排序。
- 工作台与编辑器切换时，保持当前场景、当前状态、选区与画面位置；在任一位置切换场景或状态，另一位置再次打开时延续相同上下文。
- 状态是课件呈现过程的真实层级，不是属性面板里的一个静态字段。场景与状态导航必须始终成对表达。

## 5. 关键交互原则

### 5.1 选中即上下文

用户在内容中选中文字、页面、对象或区域后，助手输入区显示自然语言范围标签，例如`当前页 · 标题`、`第 4—6 页`、`材料：产品手册`。标签可移除或补充，发送时绑定当前版本；执行中的任务不会因用户随后切页而改写错误目标。

### 5.2 手动与 AI 连续协作

界面不使用不同颜色把“人做的”和“AI 做的”划成两个系统。颜色表达交互状态，例如选中、主要动作、提醒和错误；操作来源由文案、图标和变更记录说明。

- 手动编辑即时生效，并可撤销。
- AI 修改显示目标、实际进展和结果；涉及已有内容时提供变更摘要或必要的前后对比。
- 从零创建、读取分析、明确的小改和大范围重构采用与风险相称的反馈，不强迫所有任务经历同一审批仪式。
- 后台候选和宿主事务仍然保留，但界面优先使用`查看改动`、`应用`、`已应用`、`撤销`等用户语言。

### 5.3 真实进度与异常恢复

运行中展示当前动作、已完成范围、耗时和停止入口。只有可靠估算时才显示剩余时间，不用无限转圈或虚构倒计时。失败状态说明失败发生在哪一步，并提供重试、继续编辑或查看已完成结果的明确出口。

### 5.4 保存与跨宿主连续性

顶栏始终可辨认当前内容是否已保存、保存到哪里、是否检测到外部修改。进入编辑器不触发另存；进入外部宿主前确认文件已落盘，返回后以最新文件为准处理冲突。

## 6. 视觉方向：暖纸面与深墨绿

V3 放弃 V2 的大面积冷黑、蓝绿双强调色和开发工具感，采用**暖白纸面、深墨绿结构色、少量杏橙点睛**。整体应像一张秩序良好的创作桌：安静、可信、有质感，同时让内容比工具更突出。

### 6.1 色彩系统

| Token | 建议值 | 用途 |
|---|---:|---|
| `--canvas` | `#F4F1EA` | 应用背景，带轻微暖度 |
| `--surface` | `#FFFEFA` | 文档、面板与主要卡片 |
| `--surface-muted` | `#ECE9E1` | 次级区域、控件底 |
| `--ink` | `#17221D` | 主文字与深色结构 |
| `--ink-muted` | `#66706A` | 次文字 |
| `--line` | `#D9D6CE` | 低对比分隔线 |
| `--green` | `#245B46` | 主要动作、选中与品牌识别 |
| `--green-deep` | `#173E31` | 顶栏、强调块与深色浮层 |
| `--green-soft` | `#DDE9E2` | 选中背景、进度与提示 |
| `--apricot` | `#D88755` | 少量提醒、成果到达和品牌点睛 |
| `--apricot-soft` | `#F3E1D3` | 温和提示背景 |
| `--danger` | `#B34E46` | 错误与破坏性操作 |

杏橙只用于小面积焦点，不与绿色争夺主动作。AI 消息、手动按钮和选框不再各自占用固定语义色。深色主题可以保留为后续主题，但不是 V3 的默认视觉，也不能简单反转颜色。

### 6.2 字体与信息密度

- 中文正文默认 15px，紧凑面板正文不低于 14px；长文阅读可使用 16px。
- 标题采用 18 / 22 / 28px 三级，字重 600 左右，避免到处加粗。
- 辅助文字最低 12px，只用于时间、路径和次级说明。
- 行高正文 1.55—1.7；中文内容不使用大写字距模拟层级。
- 字体优先使用系统可用的清晰中文无衬线；文档预览可按内容采用适度衬线标题，不能影响编辑一致性。

### 6.3 形状、层级和材质

- 圆角使用 8px（控件）、12px（卡片）、16px（大浮层）三档。
- 主要层级依靠留白、对齐、字号和低对比分隔，不依靠大量色块和粗边框。
- 面板以暖白平面为主，浮层使用克制的柔和阴影；禁止满屏毛玻璃和装饰性渐变。
- 主要按钮使用深墨绿实色，次按钮使用暖白描边；杏橙只点亮提醒或阶段成果。
- 图标与文字搭配用于关键入口，低频熟悉动作才允许仅显示图标。
- 主内容可采用更宽松的呼吸区，工具区保持精确紧凑，形成“内容舒展、工具克制”的节奏。

### 6.4 动效

动效只解释空间和状态：侧栏收展、停靠位置变化、内容区打开、任务结果到达和选区反馈。持续时间以 140—220ms 为主；尊重减少动态效果设置；不使用循环呼吸、装饰性漂浮或长时间思考动画。

## 7. 核心页面与状态

V3 原型至少清楚表达以下状态：

1. **工作空间起始**：可直接描述任务、打开文件或继续最近工作；项目是可选入口。
2. **无内容区的任务工作**：资源与会话可见，主内容区关闭，不出现空画布。
3. **内容按需打开**：材料、文档或课件进入主区域，可关闭后继续任务。
4. **自由布局**：左右侧栏独立收展、宽度可调，内容与助手支持左右或上下停靠。
5. **工作空间与项目会话**：资源管理器覆盖整个工作空间；下方项目文件夹各自带会话，同时允许未归项目会话。
6. **场景与状态双层导航**：工作台和编辑器都能切换场景及其状态，并看到状态对应画面变化。
7. **原生编辑器连续切换**：从工作台进入编辑器后保持同一场景、状态、选区和历史，再返回工作台。
8. **外部宿主接续**：Office 与 Markdown 显示可选择的专业宿主入口和保存返回意图。
9. **执行反馈**：运行、完成、失败、停止和可恢复状态均有清楚出口。

教育创作的教学简报、教学策划、呈现简报和呈现脚本，是课例项目采用的一种阶段流程。它不常驻于所有工作空间，也不把已有内容的一次局部修改重新拉回完整创作流程。

## 9. 设计验收边界

本轮验收关注设计形态是否自洽：用户能否从工作空间直接开始；是否理解项目为可选组织；内容是否按需出现；轻编辑与原生编辑器、外部宿主的边界是否清楚；布局自由度是否不改变能力；视觉是否达到清晰、精致、可长时间使用的要求。

原型中的按钮、文件、任务进度、主题和布局变化只用于展示交互意图。它们不证明真实保存、候选提交、Office 接续、HTML 编辑、未来自研 Office 或其他长期能力已经完成。产品实现仍须依据正式合同、源码能力与单独验收推进。

## 10. 当前前端实施范围：Office 先走外部宿主（2026-09-17）

**开发交接入口：**[1.9 教师可用性与前端专项实施方案](../docs/development-plan/R19_FRONTEND_SPECIAL_IMPLEMENTATION_PLAN.md)。该方案将本设计拆成 F00–F08 任务包，明确源码入口、真实接线、并行写域与验收；目前仅方案完成，产品实现未开始。实施时以本设计的已确认形态为目标，静态原型不作为能力已完成的证据。

Owner 已认可 V3.1，当前阶段开始落地前端。Office 的纳入条件是低成本、可靠的保真预览；经源码与方案核对，当前没有可直接接入的 Office 原文件保真渲染内核。已有材料提取、PPTX 课件导入及适用导出不能代替原文件预览。

本阶段的产品取舍：

- DOC/DOCX、XLS/XLSX、PPT/PPTX 在资源管理器中作为真实文件展示，通过系统关联的专业宿主打开；没有关联程序或打开失败时明确反馈。
- 不新增 Office 内嵌预览、轻编辑、播放、PDF 转换服务或内核依赖；不把文本抽取、全页图片或转换后的课件标为原 Office 的保真预览。
- 既有 Office 材料提取、PPTX 课件导入和既有导出保留，不借此次收敛删除已支持能力。
- 本阶段内置试运行针对 h5lesson；PPT 的播放交给外部宿主。前文的 PPT 内嵌试运行及宿主选择清单为后续形态，本阶段不做静态假入口。
- Markdown 编辑与外部编辑器打开、原生互动轻编辑与完整编辑器、场景/状态两级导航、工作空间/项目/会话组织及自由布局属于当前前端目标。
- 未来原生 Office 编辑器开发完成后成为默认宿主；此路线不作为本阶段依赖。

核查依据：当前 package.json、lessonMaterialDesktopService/lessonMaterials 与工作台打开文件路径。Microsoft Office Online Server 的在线查看需要服务获取并渲染文件；LibreOffice 的 PDF 转换需要安装并调用转换程序。引入这些路径还需单独处理部署、字体、转换失败与真实样本的保真验证，超出本阶段低成本预览的条件。
