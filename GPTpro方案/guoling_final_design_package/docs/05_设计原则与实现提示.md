# 05 设计原则与实现提示

> 2026-09-22：以[收敛方案 v2.0](../../../果铃2.0收敛方案.md)为当前合同；API/套餐为主、OAuth 可选、统一自建执行器和外部 MCP。图稿是视觉参考，不代表旧导航/预览审批为必经流程。
## 一、产品设计原则

### 1. 默认路径必须简单
普通用户应该能够快速完成：
- 打开文件
- 选择内容
- 提出修改
- 直接看到结果

### 2. AI 负责思考，产品负责通道
产品不替模型做审美与语义判断。  
产品负责的是：
- 把上下文给全
- 把工具给直接
- 把结果呈现清楚
- 把撤销与恢复做好

### 3. 会话独立于文件
会话是长期线程，不因切换文件而重置。  
文件只是当前引用对象之一。

### 4. 活文档优先
普通编辑优先作用于当前内容本身，而不是外部候选副本。

### 5. 过程透明但不臃肿
用户需要能看到过程，但不应该被技术术语淹没。

## 二、界面实现提示

### 1. 版式结构
推荐默认三栏：
- 左：资源与导航
- 中：内容
- 右：AI

### 2. 统一组件
建议统一以下组件样式：
- 标签页
- 文件树项
- 上下文芯片
- AI 过程卡片
- 结果卡片
- 附件预览卡片
- 快捷操作按钮

### 3. 正文编辑
“排版”建议改名为：
- 正文（可编辑）
- 源文（源码 / 原始格式）
- 预览（只读时才使用）

### 4. 过程展示
建议分层展示：
- 摘要层：当前在做什么
- 详情层：步骤 / 工具 / 结果
- 成果层：文件、图片、页面修改

### 5. 附件
支持：
- 点击上传
- 粘贴图片
- 拖拽文件
- 文件引用
- 发送前预览
- 删除单个附件
