# M15｜统一编辑目标、元素 AI 卡与 Runtime 图文轻编辑

**阶段：中期产品体验 · 2.0 必须完成**  
**实施依赖：** M21、M19

## 完成定义

基线已于 2026-09-25 提交（`25b12b4b`）。本任务按 2026-09-25 Owner 决定扩为**统一编辑目标**：原生对象、文档中的图片/表格/图表/组件、选中文字，以及 Runtime/Component 里的文字和图片，共用 M21 的选中快捷条和同一套提交抽象；快捷条上的“AI 修改”打开**元素级临时 AI 卡**。Runtime 部分恢复“运行到哪里即可返回哪里编辑”：当前状态中的文字和图片可选、可改、可撤销、可保存重开。目标不是把 Runtime 变成完整网页开发器。

## 元素 AI 卡

- 点快捷条 AI 按钮后出现该元素自己的卡：对话记录、撤销/重做、输入框。卡片不进常规会话列表，与右侧 AI 助手无关；执行仍用同一执行器、权限档位、提问选项卡、修改前询问的批准和文档事务。
- 同一元素的多个要求排队，不同元素可同时进行，不设并发上限。第一版卡内 AI 只修改该元素，需要牵动其他元素时提示改用右侧助手。
- 单独撤销就是打开该元素的卡点撤销：只回退 AI 在那一步改过的属性（用既有对象属性命令写回，作为一次普通修改），之后手动拖动的位置等不受影响；同一属性后来被改过时先提示再覆盖。全局 Ctrl+Z 照旧。
- 选区失效改为按目标判定（对象仍在即可；文字选区看那段文字是否仍在），不再按整份文档 revision 拒绝其他元素的请求。
- 记录只在文件打开期间存在：保存不清空，关闭文件或退出应用即清空，不落盘找回、不做崩溃恢复。元素删除后记录隐藏，撤销删除时恢复。
- 选中文字（Markdown 与讲义正文，两者同一编辑器）的卡在打开期间可连续追问并撤销/重做，关闭即结束；文档里的图片、表格、图表、组件有稳定 ID，按对象处理。
- 顶栏保留一个固定位置的“进行中/需回答”小指示，其他页的元素需要回答时可以跳转过去。

## Runtime 图文：软件登记，AI 不登记

- AI 按正常方式写页面和代码，**不再承担任何登记**：删除 Runtime API 2/3 与 Component API 4 能力说明中“所有可见文字必须来自 content.values”和“显式注册编辑目标/加 data-courseware-edit-key”的义务，同步能力索引与合同注释。已使用文案表的旧 Runtime/组件继续按编号编辑，作为兼容。
- 运行时由宿主自动识别可见图文：DOM 文字与图片、Phaser Text 与静态 Image。修改按“原文 + 所在区域 → 新文字”记录，图片/音频按受管资源替换；规则存于工程，重绘、切换状态、撤销/重做与保存重开后保持；原文不存在时在元素卡标明，不误改。
- 另由软件只读扫描页面源码，列出像显示文字的字符串作为“页面文字”清单，覆盖只在其他状态出现的文字；在清单中修改同样生成上述规则，不改写 AI 的源码。
- 能热更新的 Runtime 修改后保持当前运行状态；不能热更新的明确提示后重新加载。改字后需自动重新截取静态后备图。
- Three/WebGL、直接画在 canvas 上的内容与程序实时计算的文字（得分、计时等）不提供直接手改，只提供 AI 修改。

## 停止条件

文字/图片闭环与元素 AI 卡成立即停止扩展；不做 Three.js 适配，Phaser 只做 Text 与静态 Image（不做 Sprite/BitmapText）；不在 2.0 增加任意 CSS 属性、任意动画帧、任意 JS state、通用场景编辑或复杂视觉设计器；不把编号写进 AI 源码，也不做源码反编译。

### M15-T01｜运行到哪里即可返回哪里轻编辑

**环境／前置：** 含动态状态的 Runtime，编辑/试运行共用同一工程

**操作：** 试运行推进到非初始状态，返回编辑后修改当前可见文字和图片，再继续运行

**验收：** 返回编辑时保留可识别的当前业务状态；支持热更新的 Runtime 修改后无需重建、继续运行不破坏原交互；不支持热更新的明确提示后重新加载，不静默丢失状态

**验证层：** electron；范围：`2.0`；当前状态：`not_run`。

### M15-T02｜软件自动识别图文，AI 不登记

**环境／前置：** 未写 authoring.register、data-courseware-edit-key 或文案表的 DOM 页面，Phaser 常用 Text 与静态 Image，以及外来 HTML（听力案例：React 打包，HTML 内无静态文字）

**操作：** 由宿主进入轻编辑，点击可见图文，并打开页面文字清单

**验收：** DOM 可见文字与图片、Phaser Text 与静态 Image 自动成为目标；只读扫描源码列出页面文字（含仅在其他状态出现的文字）；Three/WebGL 与直接画在 canvas 上的内容保持黑盒，只提供 AI 修改；生成与导入都不需要 AI 或作者登记，AI 能力说明不再要求登记

**验证层：** integration；范围：`2.0`；当前状态：`not_run`。

### M15-T03｜文字图片修改可持久化

**环境／前置：** 自动发现目标可选择，Runtime 会发生一次 rerender

**操作：** 修改一处文字与一张图片，触发 rerender，撤销/重做，保存关闭重开

**验收：** 文字按原文与所在区域匹配、图片/音频按受管资源替换，rerender、切换状态、撤销/重做与保存重开后保持；原文消失时在元素卡标明而不误改；只持久化轻量规则或既有文案表字段，不改写 Runtime 源码

**验证层：** integration；范围：`2.0`；当前状态：`not_run`。

### M15-T04｜Scene Runtime 与 Component 共用轻编辑机制

**环境／前置：** 一个场景 Runtime 和一个 Component 均包含可见图文

**操作：** 分别进入编辑、修改、保存重开

**验收：** 复用同一轻编辑目标/提交抽象，允许 adapter 差异但不维护两套用户编辑器；锁定/只读目标不写入

**验证层：** electron；范围：`2.0`；当前状态：`not_run`。

### M15-T05｜元素级 AI 卡

**环境／前置：** Slide/Spatial 原生对象、文档中的图片或表格、Runtime 图文各至少一个；右侧助手收起

**操作：** 对多个元素分别点快捷条 AI 按钮提交要求，对同一元素连续追问；期间切换选择、删除并撤销删除一个元素，保存后关闭并重开文件

**验收：** 每个元素有自己的 AI 卡（对话记录、撤销/重做、输入框），不进会话列表、与右侧助手无关；同一元素排队、不同元素并行且不设上限；卡内 AI 只改该元素；提问与批准在卡内完成，顶栏“进行中/需回答”指示可跳转；撤销删除后记录恢复，保存不清空，文件关闭后清空

**验证层：** electron；范围：`2.0`；当前状态：`not_run`。

### M15-T06｜单元素撤销与按目标失效

**环境／前置：** 同一课件中 A、B、C 三个元素

**操作：** A 的修改进行中给 B 发送；完成后手动拖动 B，再在 B 的卡里撤销；对 C 修改后手动改同一属性，再撤销 C

**验收：** A 进行中时 B 的请求不因整份文档版本变化被拒；B 只回退 AI 改过的属性，位置等后续手动修改与 A、C 不变；同一属性后来被改过时先提示再覆盖；每一步都可被全局撤销

**验证层：** integration；范围：`2.0`；当前状态：`not_run`。

### M15-T07｜选中文字 AI 卡

**环境／前置：** Markdown 文档与讲义正文各选中一段文字

**操作：** 点快捷条 AI 修改，连续追问两次并撤销/重做，关闭卡片后再次选中同一段文字

**验收：** 卡片内可连续追问并撤销/重做；关闭即结束、修改保留且可用全局撤销；再次选中开启新卡；讲义与 Markdown 行为一致

**验证层：** electron；范围：`2.0`；当前状态：`not_run`。
