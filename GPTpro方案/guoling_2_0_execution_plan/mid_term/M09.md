# M09｜可展开的完整 AI 过程与任务控制

**阶段：中期产品体验 · 2.0 必须完成**  
**实施依赖：** S05、S07、S12、S13、S14、M07

## 时间线体验

默认简洁，但展开能查看上游实际提供的思考/摘要、工具名称与具体对象、参数、实时输出、结果、差异、错误、计划及可获得的子任务。不能只保留“正在处理”几句泛化文案。

每个工具一张稳定卡片：运行/完成/失败在同卡更新，输出可分块加载；同状态的新内容持续追加或覆盖对应字段。执行计划是实际结构化计划/模型公开文字，不生成假的计划补空白。

原生思考内容按提供的类型准确命名，缺失不伪造。子任务默认折叠但可以进入其实际过程；只有完成摘要就显示摘要，不制造token级动画。内置执行器提供其完整可见事件。外部 MCP 只显示果铃实际收到的工具、资源、修改与回执，不获取外部 CLI 全聊天/思考，不承诺停止其模型循环。

## 内容结果

文档修改卡显示实际文档/对象与应用状态，可点击定位。工具“已运行”不等于文档“已应用”，文档“已应用”不等于原文件“已保存”；据S03事实更新。不要求用户打开外部candidate路径才看变化。

只读工具失败与已有正式修改并存时，结束文案要分别说明已应用内容和未完成工作；不把只读失败概括为“所有修改失败”，也不因已有修改把 `invalid-target` 等错误改报全部成功。请求预算耗尽显示暂停原因和手动继续入口，自动队列停止后只有用户操作才恢复剩余任务。此处补充 S05-T09/M09-T03 的使用语义，不把既有通过状态扩大为真实模型完整旅程已验。

原始工具输入/输出作为可读数据安全呈现，不能直接插HTML或执行链接。敏感路径/密钥默认脱敏，用户主动导出诊断时再确认范围。

## 控制与滚动

新内容只在用户位于底部时自动跟随；向上浏览后保留位置，提供回到底部。展开/折叠状态跨更新保持，不自动反复弹开；流式更新不抢输入焦点。授权和提问在出现位置可答，等待状态有明确原因。

2026-09-24 Owner 决定：内置 AI 的提问能力保留，并以弹出的选项卡呈现，用户点选即可回答，必要时可补充文字，不能只靠一段文字提问。内置执行器没有子任务，M09-T04 的子任务要求删除；上文“子任务”只指上游实际提供的子过程。

M09-T02 保留 r20 的文本分片与工具/用量事件交错反例：运行状态依据当前任务完整生命周期，不能只看最后一条事件而让 `aria-busy` 提前结束或永远挂起；稳定内容不被整段反复播报。DOM/事件检查与真实读屏观察分列，旧 030 未执行/环境阻塞不成为 2.0 已验收证据，也不恢复旧整套 CLI 对照门。

停止立即在UI生效，并经S03等待终止屏障；失败保留已完成结果、未发送输入和附件。会话关闭/面板收起不误取消任务；程序退出按明确恢复策略停止，不下次启动偷偷继续付费。

## 验收范围

所有稳定连接真实运行一次包含文本、工具、失败/授权的任务，再对照该连接事件样本回放。上游缺项只减少该项声明，不能豁免已有却被软件丢弃的内容。
