# M05｜Markdown 正文编辑、选区与源文一致性

**阶段：中期产品体验 · 2.0 必须完成**  
**实施依赖：** S06、M02、M04

## 交付体验

默认模式名“正文”，另一个叫“源文”；“预览”仅指只读结果。正文是真编辑器，可输入、拖选、键盘扩展范围、复制粘贴和AI局部修改。模式名称、aria-label、帮助与测试定位同步。

## 正常内容必须覆盖

普通段落、各级标题、粗斜体、链接文字、嵌套列表基本文本、跨行引用、表格单元格、中文/emoji与重复短语都能定位。跨普通段落选区可用；公式、代码块、资源对象按已有真实能力显示，不把它们压成丢失内容的普通文字。

“正文选区已存在但ranges为空”不能直接作为让用户切源文的最终方案；在普通内容上修复映射与ID更新。复杂未知结构可以保留为只读对象并指明范围，但不能据此降低正文基础支持。

M05-T02 沿用 r20 的标题后空行、可见首尾空格、列表缩进续行、裸 URL 和中间未映射槽位反例；不通过删除可见空格或跳过无法定位的中段来“修复”范围。旧真实 Luna 选区用例未运行的状态保留为历史，2.0 真实共编仍由当前 API 路由验证。

## 接线

SharedDocumentEditor从统一session取得sourceMap/revision，不生成第二份不同ID的fallback文档；目标bind不要求disk存在。编辑器flush只完成IME和人工待提交队列，不触发首次保存弹窗。

切模式前提交待确认人工修改；切回正文以同一source解析投影，保留可以可靠映射的selection。源文故意写出不完整Markdown时保留源文草稿和错误，不把它变成正式正文或悄悄删字。

正文轻改采用最小范围source更新，格式化操作只改变对应结构。未触及内容的链接、换行与转义不因一次局部编辑而重排全文。复制正文给其他程序是可读内容，不夹带内部标识；内部复制需要资源时携带受管引用。

## 故障恢复

映射错误在当前位置显示具体提示并保留输入；记录工程缺陷，不让模型反复重写以“修复位置”。外部文件更新走统一冲突机制，不抹掉当前正文草稿。正常内容持续触发映射拒绝属于2.0阻断。
