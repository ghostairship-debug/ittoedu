## M19-T02｜命中、选择、拖动、快捷条与 Runtime 目标都按当前画布

`tests/e2e/g20M19CanvasRuntime.spec.ts` 1/1（2.1 分钟），原始记录 `output/g20/m19/canvas-runtime/run-NNxnm4/`。夹具分横屏 1280×720 和竖屏 720×1280 两份，每份各有一个 Native 文字块和一个 DOM Runtime。Runtime 自己画文字，不登记任何编辑目标。两种画布上都通过了以下检查：

- **Runtime 文字位置。** 文字按课件画布排版并随页面缩放。横屏页面宽 960，缩放 0.75，文字在 (342, 494.8)；竖屏缩放 1.333，文字在 (400.3, 615.2)，与画布坐标换算值一致。
- **可编辑目标。** 宿主识别出的目标框与文字的实际范围逐像素重合。在该处双击会先按画布坐标命中，再打开原位编辑框，编辑框与目标左上角重合。改字当场生效，文档 revision 增加，目标名随新文字更新。
- **选择框。** 点击 Native 文字后，选择框的角点手柄（#5b9cff）恰好出现在按当前画布算出的角上。
- **快捷条。** 快捷条出现在选区上方，左缘与选区左缘对齐。
- **拖动与缩放。** 拖动 (130, 50) 个画布单位后，写入的 frame 正好是 (210, 150)。拉右侧手柄 100 单位后，宽度从 360 变为 460，x 不变。
- **窗口变化。** 把窗口缩到 1300×900，页面按同一规则重新适配（宽度 960 → 660），手柄和 Runtime 目标都跟着新位置走。

这次运行发现并修复了一个缺陷：工作台外壳的通用按钮样式（奶白底、边框、圆角）漏进了嵌入的 Slide/Flow/Spatial 工作区。结果是 Runtime 与组件文字上本应透明的可编辑框变成实心奶白框，把文字完全盖住；编辑器里没有这个问题。修复把这条通用样式限制在 `.workspace` 以外，并用 `:where()` 保持原有优先级。用例现在还会检查目标框的计算背景为透明，以及文字区域有可见笔画。
