## 3. 本次续接额外发现并修复

### 3.1 已确认保存意图导致无关日志重读

绑定索引已建立后，原逻辑仍会因为保留的 save-intent 与当前 binding 相同而恢复整份日志。新增回归首先复现此问题。现由 `documentJournal.ts` 内统一的 `pendingSave()` 区分已确认保存与真正待恢复的 Save As；列表和恢复共用条件，避免两处规则漂移。实测另一文档的重命名与回收不再打开无关正文日志。

### 3.2 并行只读调用丢失回执时，错误保留为 pending

旧并行路径绕过执行器的调用状态和异常回执边界：工具已经调用，RunStore 却仍显示未调用。当前以固定的本轮只读集合调度，发起前登记 executing，异常先查询既有回执，再保留 unknown；按顺序回收后，尚未调用的写操作仍保持 pending，不会误重放。已有七项恢复/未知副作用测试与三十五项执行器测试均通过。

### 3.3 检查证据跨宿主重启复用

成功检查复用增加宿主实例身份。相同源码、相同观察意图只在同一有效宿主实例内复用；重建宿主后重新检查，不把旧宿主证据当成当前准入结果。

### 3.4 失败与重试反馈

构建检查超时保留可继续的 failed 候选，而非永久 exhausted；回归验证在同一 job 修改并重新通过。文本版本变化与打开状态变化分别报错。普通模型 Provider 不再声称自己决定“未自动重试”，实际重试决策归执行器。

## 5. 必须保留的边界

- 外部供应商真正的限流、订阅额度与授权不能由果铃取消；当前修改消除的是宿主不必要的使用限制，并让独立工作尽量继续。
- 显式配置的预算继续生效。历史候选未记录预算来源时，不把它当成宿主默认并静默解除；旧 exhausted 候选与真实用户恢复日志没有自动改写。
- 单图 64 MiB、MCP 单次 JSON 64 MiB、若干数据链 256 MiB 等仍是当前工程支持边界，不是累计使用次数。已经完成的工作不会因为下一次操作超过边界被自动删除。少数实现仍需全量实例化单个文件或单条记录，未声称所有大对象已实现零拷贝或任意体积处理。
- 上下文目前采用图片数量/字节工作集与整轮压缩。按页面、版本、任务相关性的精细排名，以及超出单次模型输入范围时的自动拆解，不在本次机械回归证明范围内；必要新图不能静默裁掉。
- 新建合规页内脚本可机械拆页；任意已有 HTML 的跨页共享状态、第三方脚本或特殊布局，仍需按实际依赖处理，不能删除脚本后谎称保真。
- 尚未重新运行收费的完整课件生成或模型/推理档位对照，因此不能承诺从 66 分钟降低到某个固定时间，也不能将工具替身测试称为真实模型生成质量验收。
- 原 2.30 GB 日志仍原样保留。修复代码通过 fixture 证明读取、归并和绑定隔离；没有在线压缩原件。首次遇到未索引历史日志可能仍需一次受控读取；可证明损坏的历史不能被静默忽略。

## 6. 使用与后续定位

本轮修改留在工作树，未提交 Git。运行构建已更新；用户先保存正在编辑的内容，再完全退出并从当前仓库重新启动，才会加载新的主进程与内置 Skill。无需删除旧课件、聊天记录或恢复目录。

后续真实体验只需关注：初稿是否实际含关键图示/示范、是否尽早保存交付、选页精修是否保留其他页、长任务是否继续而不是重建。确有剩余问题时用新 runId 和真实回执定位，不恢复全课后台检查义务，也不再增加固定模型轮数限制。
