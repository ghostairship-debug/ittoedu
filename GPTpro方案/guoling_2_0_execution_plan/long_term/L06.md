## 1. 目标、范围与实施约束

### 1.1 补全后的产品目标

用户在果铃中提出一个任务，系统能够连续完成：

```text
取得资料 → 理解与核实 → 计算／生成 → 形成工作成果
                                    ↓
                           观察 → 修改 → 保存／导出
```

典型任务不是单纯回答问题，而是：

- 从本地资料与公开信息中整理讲稿，生成演示，并依据实际画面修正布局。
- 读取 CSV，执行确定性计算，生成图表及报告，再插入已有文档。
- 在已经生成的 HTML / Runtime 中修改文字、替换图片，而不是重写整份工程。
- 生成配音、视频等素材，与讲稿和演示组合，最后交付能够继续编辑的成果。

教育仍是首发场景；工作空间、文件、会话、工具和执行器保持通用。教学流程作为可选 Skill，不把所有任务变成课件制作。

### 1.1A 通用 Agent 核心完成定义

核心必须同时具备：零文档任务；通用文件读写与多文件修改；PDF/DOCX/PPTX 资料读取与定位；网络检索和来源引用；至少一种真正可用的通用脚本与必要进程执行；独立图像生成/编辑与 HTML 运行观察修正；按需 Skill；外部工具发现与授权读写；上下文压缩、暂停继续、异步等待取消和真实完成判定。

上述能力由原生 Engine 自主组合，不要求用户先创建 V9 文档、手动搬运中间结果或切换外部 Agent。缺少通用写入、只能运行固定 helper、长历史无法继续、独立 HTML 无法观察，均不能标为“核心完成”。核心门现为当前2.0最终闭合前置，另含媒体最小框架与单runner薄委派，见§15、§20。

完整音视频编辑/音乐生产、Office原格式无损编辑、完整IDE、操作系统级Computer Use和多执行器递归协作仍非本期目标；首个语音或视频及一个薄委派按§20纳入本期。浏览器中的基本网页读取、点击、输入和文件传递可由一个受管浏览器工具通道提供；不得把所有动态网页一概列为不支持来替代通用网页能力。登录由用户正常完成，不承诺绕过验证码、访问控制或覆盖所有网站。

### 1.2 这次不改变的决定

1. **自建执行器是默认执行主体。** 它应覆盖内容调研、文案、布局、素材、计算与受控构建；不退回“自建只做轻编辑、CLI 永久负责重任务”。
2. **文档写入仍通过原有正式入口。** 人工、内置 AI 与外部工具对同类对象的修改，共用文档事务、历史和保存语义。
3. **文件格式各自保留模型。** Markdown、TXT、HTML、H5 演示以及未来 Office 文件不统一成一个万能 JSON；普通源文件不因可写就必须新增 DocumentDriver。
4. **对话、图片理解、图片生成和图片编辑的槽位继续保留。** 本方案不重新设计已经存在的模型角色体系。
5. **普通修改走最短路径。** 改字、换图、调整位置，不强制先生成计划、重建 HTML、跑完整构建或等待多轮审查。
6. **复杂代码保留准入。** Runtime / Component 的代码改动、HTML 导入继续使用真实编译／检查／准入与正式提交；不是因为追求即时性就直接执行残缺源码。

上述方向来自当前收敛方案与长期路线，见 [R01]、[R11]。

### 1.3 本方案与当前 2.0 的关系

本版已由Owner前移为2.0最终闭合必需范围。原 `M17-T05 → M23/M24 → M18 → REL-T11 → M14-T05` 是旧范围及其证据顺序，不删除、不伪造首轮成功，也不再作为“不能追加收口”的禁令。

当前完成顺序：**B18既有基线 → B19/M25基本可用修复 → B20/M26长任务可靠性 → B21/M27文件与编辑基础 → B22/M28执行和观察 → B23/M29网络/外部/首个媒体/有限委派 → B24/M30体验整合、综合验证和Owner终局签收。** 稳定窄接口后的独立叶子可并行，后端调查可前置，见§15。

原H01–H09正文保留完整技术边界。§20把核查结论变成可实施单元，§21给全部D/G问题的去向；误报和否决方案保留理由，不转成删除功能任务。新增状态只看权威JSON，不重复维护HC状态表。

本轮仅方案写入。下一轮实施无需重新说服Owner是否在2.0中做这些能力；新增采购、重大依赖或具体外部写授权只就实际选择报批，不重新讨论已定路线。

### 1.4 不在本轮预建的系统

不预建插件市场、工作流 DSL、全局知识图谱、独立向量数据库平台、完整 Office 编辑器、通用 Computer Use、完整 IDE、递归多智能体网络、云端团队权限平台或商业 Credits 账本。

这些不是被永久排除，而是不能作为补齐一个搜索工具、一个脚本环境或一家媒体供应商的前提。已成熟且没有明显害处的现有功能保留，不为“架构瘦身”再次删除。

### 2.3 本轮增量事实

2026-09-28 对 `5d331b88` 的源码与只读探针确认：

1. `selectRunToolNames` 对 HTML 不提供 `image.*` 或 `view.observe`；无文档时 Gateway 返回 `skills.read`，Engine 另加工作空间文件工具和 `ask_user`，并非完全不能发起零文档任务。
2. `ExecutionDesktopService` 把历史对话和附件纳入初始输入；`prepareContext` 压缩时保留全部 `initialMessageCount`，初始历史本身过大时仍无法继续。
3. 一次读取失败后成功重读，`hasUnresolvedToolFailure` 仍可能保留旧失败，最终状态为部分完成。恢复后的完成语义需要修正，不能简单“有任一成功就清除全部错误”。
4. `ViewObservationService` 有可选 live 端口，但当前主进程只接 `captureIsolated`。隔离初始渲染不能证明用户已点击后的实际状态。

以上为待补增量，不回写成当前能力已通过。没有重跑全套测试或付费模型；后续仅对变化的直接 consumer 验证。

## 3. 总体接入方案

### 3.1 保留主干，只增加能力分支

```text
用户／元素 AI 卡／任务会话
            │
     ExecutionEngine
     ├─ 原有模型循环、流、停止、恢复、事件
     ├─ 原有 tools.load + ask_user
     └─ 按当前任务组装工具
            │
            ├─ 领域工具 → DocumentToolGateway → DocumentSession
            │                                   └─ History／视图／保存
            ├─ 文件与资料工具 → 既有文件服务／附件提取
            ├─ 观察工具 → 实际宿主观察 → 结构＋图像输入
            ├─ 搜索工具 → 搜索／网页获取服务
            ├─ 计算与媒体工具 → 作业服务 → 真实成果
            ├─ Skill → 方法、模板、现有工具、机械辅助程序
            └─ 后续外部工具／有限委派
```

所有分支仍由同一个执行器组织。非文档任务不必伪造一个 DocumentSession；当成果确实需要进入文档时，再通过正式资源与文档操作提交。

### 3.2 工具接入的最小改造

现状不是完全通用的工具注册平台：文档工具来自 `ToolCatalog`，文件工具另有 `AgentFileTools`，`tools.load` 与 `ask_user` 由 Engine 提供；部分执行结果处理仍在 Engine 中按工具名分支。[R02][R04][R05]

建议分两步处理：

**第一步：按现有模式接入第一组真实工具。** 保留领域目录和文件工具；为新增宿主能力提供定义、调用与结果适配。不要先迁移所有工具或建设一个全新的注册平台。

**第二步：当多个新分支重复了相同代码，再抽取一个薄的运行期分派层。** 它只解决“工具在哪里定义、如何调用、停止时通知谁、结果怎样进入模型”，不接管文档事务，不另存任务真相。

实现必须遵守：

- 每个工具只有一份权威输入 Schema；内部函数工具与可开放的 MCP 投影从同源定义生成。
- 工具定义可以带最少的类别信息，用于区分观察、文档修改、文件写入、外部作业。不要扩展成复杂权限策略语言。
- 宿主能力按需加载；新增搜索或计算能力不意味着每轮把所有 Schema 塞给模型。
- 没有实现或没有连接的工具不虚报可用；“需要配置”与“不支持”应能区分。
- 新工具的 operationId、权限、冻结目标由宿主注入，模型不能自报。

### 3.3 三种对象不要混淆

| 对象 | 谁负责 | 例子 |
|---|---|---|
| 正式内容 | 原有文档或文件服务 | 当前演示页、Markdown 源文、已保存文件 |
| 工作结果／资源 | 相应服务及现有存储 | 网页正文、截图、计算输出、生成视频 |
| 执行过程 | 原有运行与事件存储 | 正在等待、工具结果、已提交回执、失败原因 |

只读材料可以有来源定位，生成结果可以有资源引用，作业可以有状态。但不为此新增一个必须由用户管理的“成果项目”层级；也不另建与附件、图片资源、运行记录重复的全局资产数据库。

### 3.4 模型应拿到什么

模型工具输入保持任务语义：目标短句柄、来源引用、要修改的内容、计算脚本、输出要求。

宿主保留运行身份、文档版本、精确授权、凭据、真实物理路径映射、计费连接、幂等键及正式提交逻辑。

模型输出应尽量是内容判断和创作意图，而不是大量维护性字段。哈希、资源 ID、包摘要、正式操作序号等确定性内容由软件产生。

### 3.5 新工具命名说明

下文工具名、TypeScript 和 JSON 为**拟议接口语义**，不是现有 API 的复制，也不是要求全部一次性实现。开工时应优先复用当前命名、类型与资源引用；只在无法清楚表达时增加最小新类型。不要依据示例生成一套与原有合同平行的实现。

## 4. H01：已有能力接线与最终交付

**归属：核心 HC-A/HC-B。** 已交付部分复用，仅实施下列增量。

### 4.1 H01-A：把画面观察变成模型可主动调用的工具

**现状。** M24 已交付 V9 的主动观察与模型图像输入；当前使用隔离 Published 渲染，可观察非当前页。`authoringObservation.ts` 的作者/运行状态观察可作为增量复用点，但主进程 live capture 尚未接通。[R05][R06]

**复用入口：** `view.observe`；扩展目标解析，不另建同义截图工具。

下列 JSON 仅表示目标语义；已有工具的调用参数以当前正式 Schema 为准，不照抄示意重建 API。

```json
{
  "target": "已授权的页面或对象短句柄",
  "detail": "standard"
}
```

沿用并补齐实际可取得的信息：

- 实际观察目标、文档版本与视图来源。
- 有界对象结构、文字、布局信息及已有诊断。
- 当前画面资源引用，必要时包含对象裁切图。
- 观察覆盖范围与未覆盖原因，例如目标当前没有实际挂载。

**实现路径。** 先通过只读宿主端口复用真实观察控制器。观察目标必须来自冻结授权，不把“当前焦点”当作任务目标。返回的图像字节由主进程解析为当前 Provider 能力支持的图像输入，不能只把路径或 Base64 当普通文字传给模型。

如果当前模型不支持视觉，按已有图片理解角色的显式配置处理；返回结果中区分“模型看到了画面”与“只获得结构／另一视觉模型的分析”。没有合适连接时明确缺口，不静默换收费来源。

**本次增量。** 保留 V9 隔离渲染，补独立 HTML 的版本绑定观察与受管交互会话。返回 `isolated` 或 `live` 的真实来源；用户要求当前交互状态时必须读到该会话状态，无法取得则明确失败，不用初始截图代替。后台观察不强行切换用户视口。

HTML 至少支持打开本地成果、截图、读取有界控制台/页面错误、点击与输入、再次观察；刷新到新源码版本时明确会话重建与交互状态变化。选择器/元素句柄由宿主观察产生并绑定会话，不把 UI 编辑目标 ID 写进用户源码。公网浏览器任务复用同一窄端口或 H08 接入的成熟浏览器服务，避免再造第二套浏览器 Harness。

不把“看一次”规定为所有改字任务的必经步骤。用于排版、动态内容、用户要求视觉核对或已有诊断指出问题的任务。

**验收。** 修改前后分别观察，同一版本和目标关联正确；返回图像确实进入模型请求；用户切页或编辑造成快照失效时没有串读；观察不写文档、不改变选区、不将视图变化记入 Undo。

### 4.2 H01-B：复用 Runtime / Component 图文轻编辑

**现状。** 已有自动识别与轻编辑事务。Component 文案采用实例级 override，不是任意源码字面量的反向替换；部分能力仍未进入低成本领域工具。[R02][R07]

**拟议入口：** `content.targets` 与 `content.update`；若现有统一编辑目标能够直接承载，优先扩展已有工具，不硬加一套同义工具。

```json
{
  "target": "一个 Runtime 或 Component 的短句柄",
  "kind": "text"
}
```

返回宿主实际识别的目标、当前内容及位置摘要。后续更新只提交新文字或已获授权的媒体资源，不让模型填写 CSS 选择器、注入编辑编号或维护源码文案表。

需要保持：

- 同文同区域有歧义时重新观察／选择，不能默认替换所有同名文字。
- 整页替换同一原文只有在用户要求和工具语义明确时才使用。
- Source／实例变化后，旧目标不得落到另一个对象。
- 文字、资源引用和必要静态后备图按既有 precommit 路径一致提交。
- 一次轻修改对应现有事务与撤销，不另做一份 UI 私有历史。

**实现落点。** 复用 `runtimeLightEditCommands`、Component 的纯 planner、Flow 对应轻编辑与已建立的 fallback precommit。需要去除 renderer 依赖时，只抽取真正纯的数据 planner；DOM 命中和渲染测量继续留在视图端口。

**完成点。** 内置 AI 能完成一个 Runtime 文字修改和一个 Component 图片替换，保存重开与导出后正确；没有为了改字执行整份代码重写。Three.js 等未覆盖对象仍明确不支持，不扩大当前识别承诺。

### 4.3 H01-C：为已有机械 HTML 导入增加 AI 入口

**现状。** M24 已将 `HtmlImportService` 的资源、scratch、动态准入、按页正式导入及网络授权接入 AI。[R08] 本小节保留复用合同，不新增重复 importer 或重跑无变化的验收。

**已交付入口：** `html.import`，复用高层机械包装。

```json
{
  "source": "已有 HTML 文件或本任务成果引用",
  "target": "已授权的 H5 页面／Flow 插入位置"
}
```

软件内部解析源位置与资源根、准备候选、调用现有准入、提交并返回新对象句柄。模型不重新生成 V9 工程 JSON、不计算摘要、不发送图片 Base64。

**必须注意的两个现有接口边界：**

1. 高层调用与内部 `build.*` 不能复用同一个幂等身份去代表不同调用。宿主生成稳定的子调用身份，最终只返回实际文档提交回执，不能把内部阶段报成多次独立成功修改。
2. 导入取消复用 M24 的实际子流程边界；如扩展“只取消该导入”，取消范围不得误停同任务其他工作。不要把旧服务的整 run 取消直接当成通用 `job.cancel`。

网络和资源闭包继续沿用 M17 当前规则；本方案不重新解释远程 HTML、React 资源或脚本准入范围。

**完成点。** “把这个 HTML 插入当前讲义”可由内置 AI 完成，视觉保真和轻编辑复用现有验收；目标基线变化时明确冲突，未准入内容不进入文档。

### 4.4 H01-D：把保存和导出补成真实交付入口

**现状。** M24 已接 `DocumentHostService` 保存和真实导出服务。[R09] 已有某格式的 renderer 导出代码不代表该格式已开放给 AI；实际格式以目标工具 Schema 与服务返回为准，不将扩大全部导出格式列为本轮前置。

**已交付入口：** `file.save`、`document.export`。

`file.save` 优先保存当前已绑定路径；未命名文档按照当前工作空间与已授权命名规则确定位置。另存为、覆盖和文档身份变化复用现有语义，不让模型设置 `overwriteConfirmed`。

`document.export` 的格式可用性从真实导出能力取得。源文档类型、Surface 组合或对象导致不支持时，返回具体原因；Flow DOCX 只能标注为相应导出能力，不能宣称已有 DOCX 原格式编辑。

```json
{
  "target": "正式文档短句柄",
  "format": "当前目标实际支持的格式",
  "destination": "已授权输出位置或宿主默认位置"
}
```

回执至少区分：生成完成、已写入文件、文件路径、保存的版本、导出警告。导出过程需要真实 renderer 捕获的，建立窄的请求与回应端口；不能让 Renderer 成为新的文档 writer。

**重点场景。** 用户要求“生成并保存”，而模型只完成内存编辑时，任务不可呈现“已保存”。用户只要求编辑时，仍按现有保存策略处理，不擅自把每次操作变成磁盘保存。

### 4.5 H01-E：补齐有真实需求的文件操作

`WorkspaceFiles` 已有多种人工文件操作。优先复用其移动、重命名、复制、新建目录、回收站等能力，而不是直接让模型调用 `fs`。

第一批只为真实办公闭环接入必要操作。例如批量成果需要新建目录，文件整理需要移动和重命名。永久删除不作为默认工具；打开文档的路径变化必须经过当前文件协调服务。

这些扩展可与 H02 一同交付，不要求为了完成 H01-A 先把所有文件管理工具全部补齐。

### 4.6 H01 的停止条件

达到本节列出的实际观察、低成本轻改、独立图像和已有交付增量即停止。通用源码修改通过 H02，不额外提供一套 CSS 专用改写器；不增加自动视觉评分、固定审查循环或全格式导出框架。

### 4.7 H01-F：图像生成/编辑脱离 V9 目标

复用 `image.generate/edit/status`、现有图片连接和资源校验。无文档、TXT、Markdown、HTML 任务也可以按冻结的文件/素材权限调用；不能靠临时创建空 V9 来绕过当前 `hasV9Write` 限制。

生成服务返回任务所属的持久资源引用、可查看图片、实际连接/模型/用量与未知状态；输入图片来自授权文件或资源。随后可通过 H02 的成果交付保存为文件，或通过既有文档资源事务插入。生成完成、已保存、已插入是三个事实，Provider 不自行写正式文档。任务成果复用现有资源/运行存储，不复制一套全局素材库。

完成证据：零 V9 的 HTML 任务可以生成并编辑一张图、保存到资源目录、引用它、实际预览并重开。真实模型与图片通道沿用已有授权和配置；未接通或无视觉连接时明确缺口，不以工具可见代替完成。

## 5. H02：通用文件读写、检索与资料重读

**归属：核心 HC-A。** 同时补读和写；不能交付成一个只能研究、不能修改普通工作文件的 Agent。

### 5.1 当前缺口

`AgentFileService.file.search` 只按文件名匹配；`file.list/search` 有结果上限，缺少完整的持续读取语义。附件服务能够提取 PDF、DOCX、PPTX，但模型缺少主动定位和反复读取具体材料范围的完整工具路径。[R04][R10]

### 5.2 第一版工具组

| 工具 | 作用 | 与现有能力的关系 |
|---|---|---|
| `file.list/search` | 文件枚举与文件名搜索 | 保留语义，补分页／截断说明 |
| `file.read` | 读取普通文本文件的范围 | 新入口；打开文档优先读取内存正式快照 |
| `file.grep` | 搜索正文，返回位置及上下文 | 新增，不把 `file.search` 悄悄改成另一种功能 |
| `file.write/patch` | 创建、完整写入或局部修改普通文本文件 | 新语义入口；最终命名复用现有类型，遵守 §5.9 |
| `material.read` | 读取 PDF／DOCX／PPTX 或附件的指定表示／范围 | 复用附件快照和提取服务 |
| `material.find` | 在已知材料中定位精确词句 | 复用提取结果，不重新解析整份文件 |

第一版支持范围由实际解析器决定。TXT、Markdown、CSV、JSON、HTML、CSS 等可按文本读取；H5 演示通过文档／归档解析取得内容，不能对压缩字节直接 grep。Office 与 PDF 通过现有提取链路读取，未具备的格式明确标注。

### 5.3 来源与范围表示

建议返回以下最小信息；优先附加到现有结果和附件结构中，不另立一个大来源模型：

```typescript
// 拟议返回字段；不是新的文档格式。
interface MaterialExcerpt {
  sourceRef: string;
  title: string;
  representation: 'text' | 'page-image';
  version?: string;
  location?: {
    page?: number;
    slide?: number;
    paragraph?: number;
    lineStart?: number;
    lineEnd?: number;
  };
  text?: string;
  imageRef?: string;
  truncated: boolean;
  nextCursor?: string;
  warnings?: string[];
}
```

这些定位按来源实际能力填写：PDF 可以有页码，PPTX 可以有幻灯片编号；DOCX XML 的段落位置不等于排版后的页码，不能编造页码。返回的 `version` 应来自快照或文件版本，不由模型填写。

### 5.4 正文搜索路径

```text
用户确定的工作空间／目录
          ↓
枚举本次可访问的候选文件
          ↓
普通文本直接搜索；已解析材料搜索提取结果
          ↓
必要时按预算增量提取尚未解析的支持格式
          ↓
返回命中、上下文、来源位置、覆盖范围和继续入口
```

默认做字面量检索；正则等高级选项按明确需要增加。不要默认扫描依赖目录、构建产物或二进制大文件。排除规则应可说明，不能把跳过内容当成没有命中。

当资料过多或解析达到预算时，结果应回答：搜索了哪些范围、哪些未搜索、哪些失败、能否继续。存在未搜索文件时不能声称“已检查所有资料”。

**缓存策略。** 先复用附件快照及进程内／现有存储中的提取结果，以文件版本失效；不恢复已经删除的 `repo-index`，不预建常驻全仓索引器。只有实际重复提取成为瓶颈时，再增加局部缓存。

### 5.5 已打开文件与磁盘的优先级

对果铃已经打开且有未保存内容的文档，默认读取 `DocumentSession` 当前正式快照；结果说明这是未保存版本。明确要求“比较磁盘版本”时才额外读取磁盘。

普通文件读取与搜索也必须遵守任务已冻结的工作空间范围。文件路径只是资源位置，不能因为工具返回了一个路径就自动授予写入权。

### 5.6 图像和扫描材料

默认优先使用已有文本提取。表格、图表、公式、扫描页等文字不完整的材料，按相关页请求真实页图；视觉角色接线复用 H01 的模型输入适配。

不默认对整个工作空间做 OCR。需要 OCR 时，作为按页、按任务的后续能力接入，保留识别不确定性和来源；不能把识别错误当原文。首版没有 OCR 并不妨碍支持已可提取文字的 PDF。

### 5.7 代表性任务

> “在这个资料文件夹中找出关于数列递推的内容，整理成一份讲义，并标注来自哪份资料的哪一部分。”

完成点是搜索正文、重读相关范围、生成有出处的内容。不接受仅按文件名猜测、只读取前几个文件、或把不完整搜索宣称为全量完成。

### 5.8 验收

- 长文件分页重读没有遗漏、重复或中文截断；游标与原查询／快照绑定。
- 文件在读取期间变化时，有明确的新版本或冲突语义，不拼接两版内容。
- PDF／PPTX 页范围正确；DOCX 不伪造页码。
- 未保存文档修改可被读到；只读检索不触发保存。
- 结果截断、排除和解析失败均可见。
- 同一附件反复读取复用已有表示，不每次重新全量提取。

### 5.9 通用写入与多文件修改

覆盖 UTF-8 文本和常见源文件：TXT、Markdown、HTML、CSS、JS/TS、Python、CSV、JSON、配置文件；按实际文本编码识别，不用扩展名白名单把普通源文件全部拒绝。二进制内容通过已生成的资源/输出文件交付，不把普通文本 patch 施加于 `.h5lesson` 或 Office 归档。

最低输入语义：目标路径/短引用、新内容或明确匹配范围、读取时取得的版本。新建要求目标不存在；覆盖/patch 要求当前基线匹配。多处匹配或基线变化返回冲突和可重读范围，不猜测覆盖。保留原文件编码/换行或明确报告不支持；不默认自动格式化整份文件。模型不能自报已审批、已保存或新的宿主版本。

唯一写入归属：

- 已打开且由 DocumentSession 管理的正式文档：路由到现有 Driver/事务，产生真实撤销和 revision；用户要求落盘时再保存，禁止绕过未保存内容直接覆盖磁盘。
- 其他普通文件：复用 WorkspaceFiles/文件协调与路径权限，完成版本检查和原子单文件替换；之后打开时读取同一磁盘事实。无需为每个后缀新增 Driver，也不承诺为未打开文件提供文档 Undo。
- 已打开 V9 与其受管素材只能经正式事务；脚本和普通写文件入口均不得旁路修改工程包。

一次任务可以编辑多个文件，每个结果返回操作身份、路径、前后版本、已提交/已保存状态及失败原因。跨文件不承诺原子回滚；中途失败保留成功文件，重读后只继续未完成项。未知写入先查回执，不重发。写权限沿用四档，父目录创建/移动/重命名复用 H01-E。

完成证据：在空工作空间创建 JSON、Python、HTML/CSS 多文件成果，局部修改一个字段/函数并重开；再用一条聚焦检查覆盖已打开未保存文档的路由与旧版本拒写。这里只证明文件能力，计算和浏览器的真实运行分别在 HC-B 集成。

<a id="s06"></a>
## 6. H03：网络检索、正文获取与引用

**归属：核心 HC-C。** 本地检索不等待搜索供应商；网络内容读取和网页交互分别按真实能力披露。

### 6.1 工具边界

建议第一版只增加两个主要入口：

- `web.search`：查找结果，返回标题、URL、摘要和来源元信息。
- `web.open`：取得网页正文或可供现有材料解析器处理的文件，并支持继续读取。

页面内精确定位可以复用 `material.find` 或结果重读能力；不要为了命名完整而先建设很多同义工具。

搜索服务可以独立于模型，也可以使用供应商已公开的服务端搜索。OpenAI 官方已有服务端 Web Search；独立工具路线的理由是跨模型复用和产品控制，而不是“模型 API 不可能提供搜索”。[E01]

**本方案默认推荐：** 先接一个独立、已有明确 API 合同的搜索 Provider，并复用统一抓取／材料表示。供应商原生搜索保留后续适配空间，不同时实现多套后端。

### 6.2 搜索与阅读流程

```text
形成检索词 → 获取结果 → 选择相关来源 → 取得正文
                                            ↓
                             按需重读、比较并引用
```

不强制“每次搜索固定十条、固定打开三条”。如果搜索 Provider 已返回足够的正文和明确来源，可以直接复用；如果只有摘要，就不能据此宣称读过全文。

第一版输入可以保持简洁：

```json
{
  "query": "用户任务需要核实的问题",
  "limit": 5
}
```

时间、语言和站点限制属于实际支持的可选参数。`limit: 5` 仅为示例，不是产品永久限制。

### 6.3 来源保留

每个已获取结果至少保留：标题、原始 URL、抓取时间、实际返回内容、正文是否完整，以及来源明确提供的发布时间。发布时间未知时留空，抓取日期不得代替发布日期。

搜索摘要、原网页正文、模型摘要分开记录。模型可以总结来源，但不能把自己的推断写回成来源原文。

源内容存储尽量复用运行结果／附件机制。聊天中使用可点击引用；写入文档时由相应生成或编辑工具建立普通的引用文字、脚注或参考条目。引用链接必须来自实际读取结果，而不是让模型凭记忆补 URL。

### 6.4 网页与文件处理

- 普通 HTML：提取主要正文，保留标题层级、表格和必要链接。
- PDF 等文件：受控下载后交现有材料服务；不把 PDF 的二进制字节作为文本。
- 需要登录、付费或动态脚本才能取得的内容：明确当前获取边界，不绕过访问控制。
- 页面为空或正文提取失败：返回原因，允许模型换来源；不把登录页或错误页当正文。

普通资料优先使用成本更低的只读抓取；需要动态页面或实际操作时进入 §6.8 的受管浏览器通道。搜索/抓取完成不能代表交互路径已完成。

### 6.5 网络边界与费用

HTTP 请求由宿主执行，不在 Renderer 暴露凭据。公网抓取应校验 URL 协议、解析后的地址及重定向目标，避免未经授权访问本机、局域网或链路本地地址；需要内部资料源时走明确配置的连接器，而不是放宽所有抓取。

设置有界超时、正文大小和下载限制。网页内容是待分析数据，不能成为新的系统指令或扩权依据。

Provider 凭据、实际收费方式和限流由已有 Connection / Billing 思路管理。本文不采用 Gemini 原稿中的免费额度、价格或“无限免费”断言；上线时以选定服务的实际合同核对。不把不稳定的公共抓取入口作为必须依赖的商用主通道。

### 6.6 与普通用户配置的关系

内部自用阶段可以允许高级配置。普通用户版本应提供一个“联网检索”连接预设或由平台托管的服务；不要要求用户分别填写搜索、正文提取、PDF 下载等多个 Key。

没有可用连接时，提示可配置的检索能力缺口；仍允许用户提供本地材料继续工作，不阻断原有编辑。

### 6.7 验收

复用 §16 T2 的搜索、真实正文、引用交付与一次可恢复读取失败。分页、重定向或取消只在其实现变化且现有证据不足时选直接检查，不把这些分支各自扩成一次真实模型任务。

### 6.8 最小网页交互能力

通过一个成熟受管浏览器适配或 H08 的浏览器 MCP 服务提供导航、页面/元素观察、点击、输入、截图以及授权上传/下载。复用 H01-A 的观察会话语义；本地成果预览不依赖外部服务，公网浏览器接入不引入第二套任务循环。

浏览器会话由宿主绑定任务/授权/页面身份；切换用户前台标签不改变任务目标。元素句柄随页面变化失效，动作后观察真实结果；截图进入模型图像输入，下载转为授权成果引用。登录/cookie 留在该服务的受管会话，不写入模型、Skill 或文档。外部页面内容不能扩权。

本地预览默认不允许任意网络副作用；联网、上传、表单提交及外部修改按既有任务授权执行，不能以“点击”隐藏写入。只读档禁止有副作用的动作；无法判定时不冒充只读。停止后不得继续提交表单或自动保存迟到下载。

HC-C 选定一条通道即可，不同时实现多浏览器、多站点专用脚本或桌面鼠标键盘平台。用 §16 T4 的可控网页验证导航/输入/提交/下载；用户正常登录的商业站点差异不扩成矩阵。

## 7. H04：受控计算与独立成果

**归属：核心 HC-B。** 通用执行必须真实可用，不能后置到 H09 或以固定助手替代。

### 7.1 与现有 `build.*` 的分工

当前 `build.*` 面向 V9 的 Component / Runtime 候选、准入和导入；`build.compile` 并不是可执行任意 Python / JS 的终端。[R03]

新增计算能力面向：

- CSV、结构化数据和确定性统计。
- 批量文本、图片等文件处理。
- 图表及独立文件生成。
- 独立 HTML / CSS / JS 成果的产生和后续可选导入。

计算作业可以不关联任何已打开文档。输出进入工作空间或作为媒体／文档输入时，再通过对应服务正式交付。

### 7.2 第一版优先支持的工作形态

**默认优先支持 Python 数据处理；JS 执行在存在明确用例时追加。** 这是产品选择建议，不是当前已经具备的运行环境。不要为了语言列表完整同时实现两套环境。

第一批至少打通一个稳定的通用计算环境和必要受管进程调用；解释器、输入文件、标准输出/错误、退出码、超时、取消与输出文件均可由模型使用。已有 TypeScript/JavaScript 构建继续复用；浏览器负责 HTML/JS 成果运行，不因此强制再建一套 Node 沙箱。固定机械助手仅在出现真实重复时添加。

### 7.3 拟议接口

`compute.run` 提交一次有明确输入与输出的计算。

```json
{
  "language": "python",
  "inputs": [
    { "source": "本任务已授权的CSV资源引用", "name": "grades.csv" }
  ],
  "code": "读取 input/grades.csv，计算并把结果写入 output/ ...",
  "outputs": ["summary.json", "summary.csv", "distribution.png"]
}
```

`name` 只是安全的任务内别名，由宿主校验，不是访问任意磁盘路径的授权。代码可直接传入或引用当前任务已准备的源文件；两种方式使用相同执行边界，不必须先新建果铃文档。

返回作业句柄、执行状态、日志摘要和产物引用。运行较久时立即返回句柄，由宿主等待或查询；不要让模型反复空转轮询。

可提供 `job.status`、`job.logs`、`job.cancel` 作为薄路由，分别转给持有作业的服务。既有 `image.status`、`build.logs` 不需要为了统一名字先全部迁移。

需要调用解释器或其他工具时使用受管程序与参数数组，工作目录在本任务环境内，继承同一文件/网络/进程边界。它可以执行模型生成的不同程序，不限制成几个内置统计命令；不要求建设可交互 PTY、终端 UI 或完整 IDE。任务依赖安装如需网络，只在已授权源与任务隔离环境进行，实际版本可复现，不修改全局环境。

### 7.4 输入、输出和文件保护

建议采用如下作业目录结构：

```text
受管作业目录/
├─ input/       本轮冻结的输入副本
├─ work/        中间文件
├─ output/      待登记成果
└─ logs/        有界运行日志
```

已打开文档的输入来自正式内存快照，不悄悄读取旧磁盘版本。脚本对输入的修改不算用户文件修改；正式用户文件不得被该流程旁路覆盖。

输出路径通过宿主登记，不因脚本声称成功就自动信任。检查预期文件存在、非异常空文件、格式可识别、路径闭合及必要的基本结构。数据正确性由确定性断言或任务要求核验，不能由文件存在代替。

生成成果先作为可查看的独立文件／资源返回；用户已要求保存时，执行到授权目录的正式交付。没有要求覆盖原文件时默认产生新成果，不改源文件。

### 7.5 计算正确性

模型负责理解任务、编写计算或选择方法，计算由程序执行。

- 缺失值、单位、百分比与筛选条件应显式记录。
- 金额、精度、日期和时区等按用户任务明确约定，不随意猜补。
- 关键汇总可以检查行数、合计、分类总和等不变量。
- 写入工作簿公式与得到重算结果是不同能力；没有实际重算就不能把缓存值当已验证计算值。
- 利用脚本生成 DOCX / XLSX 等新文件，不等于支持这些格式的原文件无损编辑。

第一版只对选定的实际工作类型提供验证，不建设一个“自动证明所有脚本正确”的通用验证器。

### 7.6 运行环境与隔离：不能用 `cwd` 冒充沙箱

本方案要求区分：受管目录、进程生命周期限制、真正的文件／网络访问限制。设置工作目录、超时或清理环境变量，本身不能证明任意 Python 代码无法读写其他文件。

**实施顺序建议：**

1. HC-B0 先核对产品可交付的已有运行环境/成熟后端，选一条路径做一次不调用 LLM 的聚焦探针。开发者电脑有 Python 不等于产品已经可以使用。
2. 正常“工作空间权限”下开放任意生成脚本，必须有真实可执行的文件和网络边界。不要在产品界面显示受限，底层却运行全权限进程。
3. HC-B0 必须在默认“完全访问（工作空间）”档证明可执行模型生成脚本且权限真实受限，才能进入 HC-B 完成门。仅固定助手或仅全权限本机执行可单独交付并如实标注，但 HC-B 与通用 Agent 核心门保持未完成，不能更名绕过。
4. 需要系统级或远程执行后端时只选一种，复用成熟实现，不为本次补全自研通用 OS 沙箱平台。Windows AppContainer 等机制可以作为工程评估材料，但不因本文提及就自动指定为必做方案。[E05]

这是能力可用性的真实边界，不是新增一套复杂权限产品。环境一次配置后沿用任务授权，不在每条安全计算命令前重复弹窗。

HC-B0 交付一份短决策记录：唯一后端、产品获取/启动方法、支持平台、解释器与依赖来源、文件/网络限制、子进程取消、成本和未覆盖项。一次探针同时运行普通脚本、尝试读写授权外测试文件、检查子进程取消；相关属性不足才补检查。不能仅靠提示词、cwd、字符串过滤或清理环境变量宣布隔离成立。需要新增重大依赖/远程服务/收费才升级 Owner；普通实现选型由执行者完成。不满足时记录具体阻断并继续独立叶子，不反复试同一失效方案。

### 7.7 依赖和生命周期

首版使用可复现、版本明确的依赖集合。依赖缺失返回可处理错误；不允许模型在普通办公任务中无边界地安装包、修改全局环境或更换解释器。

作业服务负责超时、日志上限、退出结果与取消；若产生子进程，清理范围必须与实际后端能力一致。不能把“已发出终止请求”写成“所有子进程必定停止”。

长期 Provider 凭据不传入脚本。需要联网或调用媒体服务时优先使用正式工具，而不是让脚本读取应用凭据。

### 7.8 独立网页的运行与修正

先允许生成并保存独立 HTML／资源包；需要进入 H5 演示时调用 H01 的机械导入。不能要求用户先新建 H5 文档才能得到一个网页文件。

M23 已有独立 HTML 预览和轻编辑。HC-B 必须复用它补齐 H01-A 的截图、运行错误与有限交互反馈，允许模型修正普通 HTML/CSS/JS 文件并重开验证。无需完整前端 IDE，也不以“预览已有”代替模型真正看见结果。生成工程所需的本地构建命令使用上述受管进程入口，不能把改一个脚本归到 H09 外部代理。

### 7.9 完成点与降级

目标任务：读取真实 CSV，执行计算，生成图表和汇总文件，写一份有依据的报告，保存到指定目录。测试输入保持不变，计算结果符合确定性断言，输出能够重新打开。

固定助手降级不得通过 HC-B。验收中的脚本由任务实际生成，可以修改方法再运行；不是把固定答案封装为 `compute.run`。无需穷举脚本类型，用 §16 T1 与 HC-B0 的权限探针证明通用执行和边界。

## 8. H05：薄 Skill 与机械辅助命令

**归属：核心 HC-A 的加载增量；机械助手随真实需求。** 复用 M24，避免再次建设 Skill 平台。

### 8.1 当前基础与原则

M24 已有 `BundledSkillService`、`skills.read` 和工具描述中的元信息，正文及直接引用支持有界读取。[R12] 剩余增量是用户明确启用目录的同路读取；辅助程序执行分别走既有函数服务或 H04。

Skill 应由“方法说明＋按需参考资料＋必要模板／机械命令”组成，不等于一段很长的提示词。Claude Code 官方的 Skill 文档也支持附带参考文件和脚本；这里借鉴能力结构，不绑定其执行器。[E02]

### 8.2 第一版发现与读取

沿用现有 `skills.read` 与 `tools.load`/工具描述发现方式，不再新增同义 `skills.list`。用户目录接入同一元信息/读取入口，做到：

- 默认只披露简短名称、用途与适用条件，不加载全文。
- 真正使用某项方法时再读取正文和直接引用的资料。
- 支持读取 Skill 内的特定参考文件，不默认递归加载整个目录。
- Skill 版本和来源可查；加载行为写入已有运行事件即可。
- 普通局部改字不被强制导入完整课件策划流程。

首版只加载产品随附及用户明确启用的技能目录，不无边界地扫描整台电脑或在线市场。

用户目录只增加明确启用路径、来源、版本与禁用能力；同名 Skill 不静默覆盖随附版本，直接引用必须闭合在允许根内。沿用文件/配置服务，不建设市场、自动安装器或新的权限中心。

### 8.3 可按任务选用的内容

下表是方法示例，不是四个必做开发任务或核心门。复用已有 Skill，缺少方法且有真实任务时再补一份；通用 Agent 不以这些 Skill 为操作前置。

| Skill | 主要方法 | 对应机械能力 |
|---|---|---|
| 资料整理 | 明确问题、定位证据、区分原文与推断 | `file.grep`、`material.read/find`、引用整理 |
| 报告／讲稿 | 结构、信息密度、论证与表达 | 模板填充、既有正文编辑、保存导出 |
| 演示与互动内容 | 理想呈现、表示选择、视觉核对 | 现有领域工具、`view.observe`、HTML 导入 |
| 数据分析 | 数据口径、计算方法、结果解释 | 受控计算或固定统计助手 |

课件 Skill 既有确认环节如何随 M18 调整，仍按 Owner 对该任务的决定处理。本方案不借“接入 Skill”重新规定所有创作任务必须逐阶段确认。

### 8.4 机械辅助命令的优先事项

优先解决模型不应该负责的维护工作：

1. 根据实际字节计算组件内容摘要并同步包元数据。
2. 登记素材、产生宿主 ID、处理引用与必要重复利用。
3. 将已生成 HTML 或已准备组件包接入现有导入／构建链。
4. 根据已有模板创建结构，再由模型只填内容。
5. 准备输出目录、组装已支持格式和收集实际成果。

例如当前受控构建会给出正确的 `contentSha256`，让模型修正工程元数据后重试。该验证应保留，但“生成正确摘要并写入候选”的工作可以机械化，避免每次浪费一轮模型调用。[R03]

**不允许以机械化为名跳过验证。** 命令负责产生正确候选，既有 Schema、资源闭包与动态准入仍负责接收候选。

### 8.5 辅助程序如何执行

产品随附的确定性助手优先直接调用经过验证的函数服务；需要进程时通过 H04 的受管执行路径。不要把所有机械操作都绕回 LLM，也不要为调用一个函数先启动外部 Agent。

第一版只允许明确登记的辅助入口。Skill 中描述的命令不是任意执行授权，下载的 Skill 不能自动获得本机 Shell、网络或凭据。

Skill 可以说明哪些工具有用，但不能自行扩大任务权限或自动启用新的收费 Provider。方法加载与权限授权是两件事。

### 8.6 不建设工作流引擎

暂不增加 Skill DAG、步骤数据库、固定审查 Agent 或独立审批图。已有 Engine 负责推进，Skill 提供方法，机械工具提供确定性实现。

只有确实有一段稳定且重复执行的业务流程时，才把它包装成一个可测试的高层工具；内部仍调用现有服务，不复制 writer 或任务循环。

### 8.7 验收

在 §16 T2 中按需读取一个明确启用的用户 Skill 及直接引用，验证来源与禁用生效；随附加载复用 M24 证据。只有本批实际新增机械助手才做一条确定性检查，确认无需模型手填摘要/ID 且原准入仍有效，不把“至少新增一个 helper”作为核心门。

## 9. H06：工作记忆与上下文治理

**归属：核心 HC-A。** 与 H02 同批完成，不等待媒体供应商；只补最小工作记录和可靠续接。

### 9.1 当前问题

当前压缩保留原始输入和操作事实，普通读取结果往往压成“旧观察，需要重读”。这对避免副作用重放有价值，但不充分保留创作取舍、资料结论和剩余工作。[R05]

必须同时处理 `ExecutionDesktopService` 送入的旧会话和附件，以及 `ExecutionEngine` 的同 run 工具历史。只压缩 `initialMessageCount` 之后的消息不算完成；不能每次遇到长会话都要求用户手工删历史或重新开任务。

另外，默认 `maxContextBytes = 1024 * 1024` 是**序列化字节预算**，不是 1M token 窗口；不能直接用厂商宣称的上下文长度推导当前实际有效容量。

### 9.2 新增一份轻量工作记录

优先在现有 run 记录或其明确的附属记录中增加以下内容，不再建立平行数据库：

```typescript
// 拟议工作记忆；不承担授权、文档或作业真相。
interface WorkingNote {
  goal: string;
  userConstraints: string[];
  decisions: Array<{
    text: string;
    reason?: string;
    sourceRefs?: string[];
  }>;
  remaining: string[];
  openQuestions: string[];
}
```

可以通过一个 `task.note` 工具更新，也可以由已有计划入口维护。第一版不要求所有任务拥有计划，不把写 note 作为编辑前置。

**三类内容要分开：** 用户确认要求、模型工作取舍、已核实操作事实。模型写入“已完成”不能覆盖真实作业状态；note 中出现路径或目标也不代表授予访问权限。

### 9.3 当前请求上下文：先修剪，再做语义压缩

完整日志/回执与给模型的工作上下文分离。Pruning确定性移除不再必要的重复内容；语义摘要整合长历史的决策/来源，不每轮额外调用LLM总结。

时序：完整模型及工具回合收拢→登记资源/回执→软预算修剪工作投影→必要时结合工作记录压缩旧叙述→序列化/计数/发送。未返回调用及协议必需字段不能拆开；Provider原生签名/推理块按协议整轮保留或替换。

1. 优先引用化历史view.observe截图。图片在user-role image_url中，不能只清理tool-role文本。保留当前任务必要的新画面及明确要求的对比前图；被新版本替代/无关旧图转来源、版本、结论、可重读资源引用。
2. 再引用化已正式落盘或已成为工作结果的大代码参数、重复正文、列表/inspect返回。未保存稿重读仍走DocumentSession，不改读旧磁盘。
3. 累计facts按目标/成果/未知操作整理，旧成功记录留回执索引，不反复平铺完整lineage；必要查询身份不能截断。
4. 旧会话和大附件也处理，不再把initialMessageCount之前视为永不可压缩；当前用户原话、有效限制、来源、权限保留，摘要不改写用户要求。
5. 不每轮小删破坏缓存前缀；达到软阈值批量释放，保持稳定system与必要固定上下文。

首版工程参数：硬字节上限沿用配置，软触发70%，目标回落约45%；先删明确被替代内容，不为凑比例丢必要材料。已知模型容量时另留输出预算，以用量/估算触发，字节不是token。阈值集中设置而非散落每Provider。

### 9.4 持久引用、统计和实证

复用EventStore blob、图片/附件/构建存储，缺少部分补窄结果引用，不另建全局库。引用含来源、版本、表示和重读入口；旧短句柄不是新权限，仍被引用资源不可清理。必要旧图重读后真正进入视觉输入，不把路径/Base64当普通文本。

既有REL只读统计：6段331请求/416工具，末段请求体105,327→8,252,458 bytes，硬限8,388,608；6段无compacted。末段messages的image data URL为7,420,826/8,180,498 bytes（90.7%），tool-role约2.1%。这是字节不是token/费用比例。末段前/后10次首事件等待中位3.139/12.074s只支持相关，不证明单一网络或算力根因。

验证用旧脱敏记录离线比较原/修剪请求：逐类UTF-8字节、图片数量尺寸、可用token/缓存输入，引用可重读、协议配对不丢。真实执行用同进程单调时钟拆序列化/落盘/发起/首事件/结束，不直接减跨进程时钟，不把prepared→dispatched当全部本地成本。不承诺未经控制变量证明的倍数提速。

### 9.5 预算和成本

字节上限保留为传输和内存保护，模型上下文预算另依据已配置模型能力、可用 token 估算和实际用量记录处理。估算不是供应商账单，未知值保持未知。

不要建立一套复杂的全模型 tokenizer 服务作为前置。先解决明显过大的全文、重复工具 Schema、重复附件和不可重读结果，再决定是否引入更精细的估算。

### 9.6 恢复与无进展

继续复用原有回执核对与未知副作用保护。保留工作笔记不意味着恢复时可以跳过重新观察已经改变的文档。

无进展检测应关注重复输入、相同实质结果和无有效修改，不把新短句柄、时间戳或重复日志当进展。不要用一个很小的固定工具次数上限截断所有复杂创作；预算应能解释，并沿用用户配置与实际任务边界。

### 9.7 验收

选一个多资料、多步骤的真实任务，触发一次上下文压缩与一次显式继续。检查目标、用户决定、尚未完成的步骤、来源引用与未知操作均被正确保留；已完成的生成或文件创建没有重复执行。

不以“压缩后还能聊天”代替任务恢复验收。

## 10. H07：视频、语音、音乐与长作业

**归属：当前2.0必做HC-XM语音/视频/音乐最小扩展框架；真实生成闭环独立延期。** 通用等待、取消、恢复和完成判定已前移到 HC-B/§13.6；本节只接实际媒体能力，不再独占通用作业机制。

### 10.1 先核实既有授权，不预建全供应商平台

先核实GPT OAuth/TeamoRouter实际目录、协议、授权及可用通道；订阅/文字或图片接通不能推断音视频可用。有既有授权可用通道则接一个薄适配并做必要验证；否则仅完成speech/video/music的最小扩展点和未配置反馈。不得为本期媒体采购、索要新凭据或阻塞图片/通用作业/其他任务。下列§10.2–10.7是框架接线约束与以后真实通道合同，不要求同时实现三种生成或新建平台。

### 10.2 媒体工具的职责

拟议工具：`speech.generate`、`video.generate`、后续 `music.generate`。

输入只包括任务内容、已授权参考素材与产品支持的少量参数；供应商、凭据、计费来源和实际模型由已冻结的连接配置决定。

输出包括：

- 宿主作业句柄与可核对的 Provider 请求身份。
- 提交／等待／完成／失败／取消等实际阶段。
- 原始用量或收费信息，供应商未提供则未知。
- 完成媒体的资源引用、格式和必要元数据。

生成结果必须下载或按产品既有资源策略保全，不把即将过期的临时 URL 当作长期素材保存。

### 10.3 一个任务不应被一次长生成堵住

当前同一 run 内的工具调用按顺序执行；不同元素卡／运行的并发不等于单个任务可以在等待媒体时继续推进。[R05]

媒体作业复用 HC-B 已完成的等待机制：

```text
提交视频作业 → 返回真实作业句柄
       │
       ├─ 继续生成讲稿、排版、处理其他素材
       │
       └─ 宿主查询／接收作业结果
                         ↓
              登记资源 → 正式插入 → 保存交付
```

短文档修改仍按现有序列与 batch 处理。没有必要把所有工具一律并行；优先让独立只读任务和异步媒体工作不互相阻塞。

对同一目标的修改继续串行或进行现有冲突检查。遵守供应商真实并发和速率限制，但不另加一个与现有 Owner 决定冲突的“所有元素卡统一最多 N 个”的产品限制。

### 10.4 等待状态与任务完成

不要因为模型暂时没有更多工具调用，就把尚有必需视频作业的任务标为完成。

实现可以在现有运行状态中记录等待原因和待处理作业，不必立即重建整套状态机。但必须核对所有把非 `queued/running/stopping` 视为终态的代码；增加新状态时同步修改消费者，不能只改 UI 标签。

最低行为：

- 有其他可做的工作时继续。
- 只剩必要作业时进入可见等待，不反复让模型轮询。
- 作业完成后按原授权继续处理成果。
- 作业失败时真实报告部分完成，已有成果保留。
- 模型文本、媒体生成、文档应用和磁盘保存分别记录。

### 10.5 停止与恢复

停止先撤销本任务继续写入的权限，再请求取消可取消的远程作业。供应商不支持取消时，如实显示；不保证退款，也不在迟到结果到达后自动插入文档。

已提交但完成情况未知的生成请求，优先通过请求身份查询。没有可靠查询能力时保留未知，不换一个 ID 自动再生成一份付费结果。

应用重启后可以恢复已知作业状态；重新发起收费生成或继续模型推理须符合既有恢复与授权策略。不因增加媒体就悄悄引入无限后台执行承诺。

### 10.6 结果进入文档

当前 `media.insert/apply` 对已有素材有一定支持，但外部新媒体入库仍需复用或补齐宿主资源接线。[R02]

需要完成：实际媒体校验 → 受管资源登记 → 相应目标允许的插入／替换 → 事务与撤销 → 保存重开。声音、视频和图片各自遵守载体支持边界，不因统一 Provider 就混成一个无类型资源。

视频裁剪、配音时间轴、字幕、背景音乐混合等是后续实际编辑能力，不应在首个视频生成工具中全部承诺。可先支持已有媒体播放器与现有属性操作。

### 10.7 成本记录和未来 Credits

按每个作业记录实际连接、模型、输入参数、Provider 用量、已知成本及未知状态。先提供可计算的事实，为未来统一 Credits 服务；不立即建设充值、退款、分账、账号容量池和商业价格引擎。

一个用户钱包可以覆盖多种服务，但不能因此推定供应商的 Token Plan 已包含视频，或推定不同账号权益可以商用汇总。接入层保留实际账源，商业托管另行确认。

### 10.8 验收

当前M29-T05只验证真实框架边界：能力发现/未配置、参数、授权、作业路由和停止；复用B1与资源已有证据。无模型时没有生成请求/伪资源/成功回执。原M29-T03真实生成→保全→插入/保存→重开播放保留为media-followup，未实测维持not_run；本地fixture不能证明供应商接通。

## 11. H08：外部工具接入

**归属：核心 HC-C。** 一个薄 Client 解决外部工具扩展，不把所有长尾工具都做进产品核心。

### 11.1 两个方向保持独立

```text
已有方向：外部 Agent → 果铃 MCP Server → 果铃正式文档工具
新增方向：果铃原生 Agent → MCP Client／连接器 → 外部工具
```

新增方向不替换当前 MCP Server，也不是通过 MCP 调用外部 Agent 的私有模型循环。它只是让果铃拥有更多可用工具。

### 11.2 第一版范围

先接一个真实外部服务，必须覆盖读取和一次明确授权、可核对的小规模写入（使用测试资源，不发送消息或动真实业务资料）。只有只读服务时可完成读取子集，但 H08 读写完成门仍未通过。若选成熟浏览器 MCP 服务，可同时承担 H03 网页交互，避免重复接入；不能用内置同进程假服务代替真实 Client 往返证据。

需要支持：

- 服务配置一次、任务中按需使用。
- 工具名称带服务命名空间，避免覆盖内部 `read`、`file.*` 等名称。
- 只向当前任务披露可访问的工具；按需加载定义。
- 参数、超时、取消和错误信息可归因。
- 远程返回的文件引用不被猜成当前电脑的路径。
- 外部结果保留来源与权限边界，不成为指令或授权。

### 11.3 写入与凭据

凭据由宿主管理，不进入文档、Skill 或普通工具结果。外部应用修改和本地文档修改是不同副作用，沿用用户已有授权；涉及发消息、上传或修改外部资源时，应显示真实行为，不把它们统一包装成“只读查询”。

外部工具不能直接写入果铃 DocumentSession。需要修改果铃内容时，必须返回材料／成果，再由果铃领域工具提交。

MCP 接口和自定义工具可以是成熟执行器的扩展方式，但协议不会自动替产品完成授权和文档协作。[E03]

### 11.4 不做的事情

首版不建应用商店、不自动发现整台电脑所有服务、不实现企业 SSO／多租户权限平台、不默认暴露任意第三方工具、不承诺所有 MCP Server 即插即用。

### 11.5 验收

复用 §16 T4：实际发现、读取、授权小写入、回读和撤权拒绝；外部写入结果未知时先查询，不盲重试。命名/错误映射按必要直接检查覆盖，不为每种 MCP Server 再跑同一矩阵。没有外部写入授权时如实保留未验收，不由计划推定已授权。

## 12. H09：外部 Agent 委派与深度编码

**归属：当前2.0必做HC-XD单执行器薄委派闭环。** 高阶递归/完整IDE不在范围，首次接入不再等待额外需求出现。

### 12.1 适用场景

大型仓库开发、复杂依赖环境、现有外部 Agent 已明显成熟的专业编码流程。不要因为一个内容任务很长，就默认委派整个任务。

普通内容调研、报告、演示、数据分析、脚本/小型多文件项目编辑和媒体组合仍由果铃原生 Engine 组织；基础文件或执行能力不足不能成为启动 H09 的理由。

### 12.2 最小委派合同

父任务明确交付子任务目标、可访问材料、允许修改范围和期望成果。子任务返回：实际状态、事件摘要、成果引用、已发生的可核实变更及验证信息。

外部 Agent 退出码或“我完成了”只能作为线索，不能代替成果存在和必要验证。

**委派与交接不同：** 委派时父任务等待结果后继续；交接则结算旧任务，由新执行者重新取得授权。不能把停止父任务伪装成受管子任务。

### 12.3 技术接入

优先选择官方结构化事件接口、SDK 或无头命令模式，不解析完整 ANSI 终端画面，不复制外部私有会话和思考。Codex 的 App Server 官方材料说明了以结构化事件连接客户端的方式；外部执行器不是原则上无法做界面联动。[E04]

先支持一个确实有用的执行器。适配差异仅限启动、事件、停止和成果收集，不恢复三家 CLI 各自拥有果铃业务 writer 的架构。

采用外部完整 Agent SDK 仍然是外部循环；采用模型 SDK 或可注入自定义工具的基础组件则可以继续属于自建执行器。不要在产品说明中混淆二者。[E03]

### 12.4 边界

子任务的授权不能超过用户已授予的范围。果铃文档通过 MCP 正式工具修改；外部 Shell 的文件变化继续由现有文件服务作为外部变化协调。

撤销 MCP 授权不等于外部进程已停止。父任务取消时分别处理写入权撤销、进程终止请求与实际退出结果，不承诺超出后端能力的原子回滚。

Git、LSP、多 worktree、递归子 Agent、共享黑板等按真实仓库开发需求追加，不作为 H01–H08 的前置。

### 12.5 开始该模块的触发条件

原生工具已能完成常用办公任务，但重复出现一种清楚的环境或长程编码瓶颈；且一个外部执行器在同任务上有可复现优势。本版Owner已将首个薄委派前移；本条只用于决定是否追加更复杂的执行器或递归能力，不阻挡§20.22。

## 13. 权限、结果与恢复的共同规则

这一节只补新增能力需要的共同语义，不重做现有权限和恢复架构。

### 13.1 四档权限继续复用

| 现有档位 | 新能力接入时的解释 |
|---|---|
| 完全访问 | 在现有授权和真实后端能力下访问文件；不等于自动启用任意 Provider、付费服务或外部账户 |
| 工作空间完全访问 | 保持当前工作空间范围；元素卡等更窄目标继续有效，不能通过打开同文件扩大范围 |
| 修改前询问 | 对真正修改用户内容／外部资源的行为沿用审批；读取、提取缓存、日志等不是用户文档修改 |
| 只读 | 允许已授权读取与分析；受控临时计算只有在不会修改用户文件的边界真实成立时开放；不允许保存覆盖或外部写入 |

权限最大范围、任务精确目标和服务连接是不同层次。网页、Skill 或外部工具的返回内容不能提升任何一层授权。

### 13.2 统一的是结果语义，不是所有服务状态机

新增能力沿用真实服务状态，至少让上层能够区分：

| 语义 | 示例 | 不能替代的事实 |
|---|---|---|
| 已观察 | 读到一段正文或实际截图 | 不代表已修改 |
| 已准备 | HTML 候选、图像／视频结果已可用 | 不代表已进入文档 |
| 已提交 | 正式文档操作有回执 | 不代表文件已保存 |
| 已保存 | 指定版本已写入实际文件 | 不代表之后没有新修改 |
| 已验证 | 做过具体检查并有结果 | 不代表所有视觉／语义问题都已证明正确 |
| 未知 | 请求或副作用结果无法确认 | 不得标为失败后自动重做，也不得标成功 |

不要为了统一呈现把 `ToolResult`、文档回执和各种服务状态全部改成一个丢失语义的 JSON。可以增加薄投影，由原有结果与事件提供事实。

### 13.3 新工具必须接入的五个位置

新增一个工具不止是“模型看得到定义”。实施时核对：

1. **发现与授权：** Schema、工具族和当前 run 的可用范围。
2. **真实执行：** 参数验证、目标解析、服务调用与取消信号。
3. **模型输入：** 有界结果、来源、图像等内容真的进入请求。
4. **事实与恢复：** 回执、作业引用、未知状态和可重读结果。
5. **完成与界面：** `executionOutcome`、过程卡和最终交付状态能正确解释结果。

这是同一个能力的接通检查，不是五轮独立审批或五套验收文件。

### 13.4 模型重试与未知业务副作用分开

本版采用多轮评估的最终裁决：**普通模型生成可在预算内有限重新请求，承认可能重复消耗推理额度；图片/视频/外部写入等未知业务副作用不继承该策略。** 不把跨供应商统一回执查询作为普通推理恢复的先决条件，不声称未收响应头等于未发送。

- 由ExecutionEngine.drive在升级任务终态前管理一次逻辑模型轮的尝试；Provider报告单次事实，避免内外两层重试相乘。默认总尝试3次（初次+2次），约1s/2s退避加有界抖动；尊重有效Retry-After，超出自动等待预算显示等待/继续，不提前抢发。所有尝试计入既有请求/费用预算。
- 可恢复连接失败、临时5xx、确定为速率限制的429可以重试；认证/不支持/余额耗尽不原样重试。有服务端工具或外部副作用的Provider不因“对话接口”名称自动视为纯生成。
- 每次尝试有独立宿主requestId/attempt身份，关联同一逻辑轮，保留原unknown和真实用量。相同客户端ID、jitter和退避不是服务端幂等保证。
- 流中断撤销本次未提交预览、清理半截参数，保留中断过程显示；从最近完整回合重做，不拼接两次输出，不重放此前已提交工具。Stop在等待前后/重新发起前检查；耗尽后再走终态和gateway.stop，不删除最后撤权屏障。
- 两Provider复用计时语义，区分传输活性、有效进展、总时限。初版空闲120s、有效进展等待300s、总请求600s作为可配置工程起点，非实测最优值；有效SSE keepalive可续连接活性，正文/推理/参数进展续进展时限，普通垃圾字节不无限续期，总时限不被ping延长。OAuth不再固定120s总时限杀持续正常输出。
- 已提交工具、远程写入或收费媒体结果未知：按原operation/job/request查询；无查询能力保留未知并提示，不自动换ID重做。用户明确批准新的独立操作才再生成，不改写原操作为未执行。
- 图片短429按连接+角色冷却，不直接结束文本/排版独立工作；必要素材等待/未完成，非必要素材由用户取舍。黑名单收窄到具体未决操作/目标/服务，一次read成功不能全清。

这是一次默认恢复政策的计划裁决，不是本次收费请求授权；不每次瞬断再弹成本确认，不静默切供应商/模型/账源。

### 13.5 跨格式与跨文件

每份文档各自提交，每个保存操作返回自己的结果。跨文件任务可以部分完成，不承诺全工作区原子回滚。

例如三个文件导出成功、一个失败，应保留并展示三个真实成果和一个失败原因。不能删除已成功成果掩盖部分完成，也不能只说“任务完成”。

### 13.6 作业等待、目标完成与历史诊断

复用各服务作业状态和Run/EventStore，不建全局JobStore。作业事实包含来源、宿主身份、状态、结果/日志引用、是否仍为必要成果和最后核实操作。提交即返回job，执行无依赖步骤，仅剩必需作业时宿主等待；结果只在原授权有效时唤醒。停止/撤权先禁止新提交再请求取消，迟到仅保全不自动写入。

**终态按当前用户要求与必要成果，不按历史错误数或最后一条saved。** 分清探索诊断、尚未满足的明确要求、未知业务副作用；前者不永久阻塞，后两者不能由无关成功清除。

- 参数探索、失效观察、已改用其他来源/工具/实现的尝试，保留诊断，按同一目标/成果消解，不要求旧句柄/参数/工具名一一配对。
- 必需资料不可得、必需修改/保存/导出未发生、作业仍运行或未消费，列实际缺口；保存一个文件不清另一个文件的失败。
- 用户约束与模型自增设计分开。模型自加守卫、额外空稿和未采纳增强不自动成为用户验收债务；可撤回自增设计并说明，不取消用户要求。
- 复用WorkingNote有效约束/剩余工作和回执；只补窄成果/缺口关联，不新建目标DSL、评分Agent或每轮审批。软件不能证明全部语义质量时说明已验证范围。
- completed/partial/waiting/stopped/failed/interrupted同步到主任务、队列、元素卡、最终回复；取消partial→completed误映射。真实partial列具体缺项；交付完整但有非阻塞警告可为completed+warnings。
- 新waiting同步终态判断、订阅、重启、队列、停止和时间线；模型stop不等于必需作业完成。
- 用户checkpoint/fork不复制旧写权限、不重放旧任务；历史REL partial不回写。摘要区分未返回调用、诊断、未决副作用和未完成要求，不把state!=returned叫全部unresolved。

独立纯只读工具可有限并行，默认4是资源起点，保留顺序归档和有界结果；写入、审批、依赖引用不并行猜测，不给所有元素卡加统一并发产品上限。计算、媒体和薄委派共用薄等待机制，无模型空轮询。

## 14. 用户配置、额度与过程展示

### 14.1 保留槽位，简化入口

普通用户不需要理解对话、视觉、图像生成、图像编辑、搜索和媒体 API 的每一个配置项。

在已有连接与角色配置之上增加一个轻量**连接预设**：配置一次供应商连接，自动填入该预设已验证支持的角色；高级设置仍可分别调整。预设是现有配置的便捷填充，不是新的 Provider 协议，也不覆盖用户已明确的高级设置。

连接预设作为M30/U3的窄体验收口；不独立建设配置平台，不推定共享额度。

同一连接不必有所有能力；不支持的视频／编辑能力应显示未接入，而不是假定同厂商型号都可调用。

### 14.2 一套配置与共享额度分开

- **一套配置：** 产品替用户填好可用连接和角色。
- **共享额度：** 供应商或果铃商业服务实际提供统一结算。

前者可以先做，后者不应假装已成立。API Key、Token Plan、订阅、预付和未来果铃 Credits 继续与认证方式解耦。

本期先记录真实使用事实，统一 Credits、托管采购与容量分配另案。不要为了未来号池先设计复杂的账号调度或推定个人套餐可被转售。

### 14.3 默认路由

默认使用用户已配置并授权的能力组合。新增工具可以选择对应角色，但不能因为“任务复杂”就在未告知的情况下改变供应商、档位或费用来源。

后续自动路由只在用户预先选择的策略内运行；质量、速度、费用是可解释的配置，不是模型临时决定的隐藏行为。

### 14.4 AI 在场感只反映真实事件

可以复用执行事件，为正在读取、修改或生成的对象显示短暂高亮、标签和真实状态。用户选框与 AI 状态应区分；不抢焦点，不默认跟随每次切页，不把源数据尚未准备好的内容伪装成已经提交。

不强制逐页串行生成来制造过程感。后台并行和前台逐步展示可以分开。完整工具参数到达前，仍只有安全的正文草稿投影可以逐步显示；残缺代码不可实时执行。供应商支持工具参数分片并不意味着分片已经有效或可以正式执行。[E06]

发光动效、复杂插值和自动镜头跟随不作为本期能力验收前置；先做好真实进度、停止、结果和撤销。

### 17.2 允许新增的最小模块

可以在现有 `workbench` 范围下按实际功能新增 `research`、`compute` 或媒体服务模块，但不要一次建立大量空接口和空目录。

### 17.3 上线方式

以实际能力和连接是否可用控制暴露。某工具未实现、不支持当前目标或没有可用环境时，不出现在可执行目录中，或返回清楚的配置缺口；不能展示可点击入口后无限失败。

先在内部真实任务中启用新能力，再进入默认用户路径。高级配置可以先存在，普通用户默认入口应保持简单。

每个批次独立交付：网络检索故障不影响本地编辑，计算环境不可用不影响资料整理，媒体 Provider 额度耗尽不影响已经完成的讲稿与文档。

### 17.4 回退与保留

新增能力出现问题时先关闭该能力的暴露或回到前一个稳定适配，不退回旧文档 writer，不删除已有用户成果。

正在执行的作业按实际状态收拢：停止继续写入，保留结果与未知状态；已经提交或保存的内容由原有 Undo／文件服务处理，不做跨系统“假原子回滚”。

代码回退与用户文件回退分开。不要使用 Git reset、删除工作树或覆盖用户文件作为产品恢复方案。
