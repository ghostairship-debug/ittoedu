# 自有执行器路线｜2.0 基线与后续演进

## 已进入 2.0 的能力

果铃统一自建执行器覆盖产品内编辑、内容/素材生成、受控构建与导入；上下文组织、工具循环、状态、取消/恢复和成本记录属于本次交付，不再作为长期兜底。API/Token Plan 为主、OAuth 可选；外部 AI 经 MCP 使用领域能力。

## 可复用底座

模型 SDK、轻量 Agent 核心和经过验证的媒体/进程组件可复用，果铃持有任务与文档真相。Pi 等候选在引入时核对实际版本、许可证和边界。完整外部 Agent 的 SDK 仍由外部控制循环，不能标成自建；不为三家 CLI 深度嵌入建设必需依赖。

## 后续增长

在真实任务证据基础上扩展更长任务、跨格式编排、领域技能、知识组织与有必要的独立子任务。优化指标是首次成功率、正确成果总时间、成本、人工修正与恢复；Agent 数和层数不是能力指标。

对任意仓库开发、远程协作和多用户托管计费另行评估。CLI 可长期作为外部 MCP 客户端；果铃后续也允许用薄 runner 主动委派外部 Agent，不以物理退役为产品目标。runner 的具体实现未排期，MCP 工具服务本身不提供进程启动、停止或外部完整上下文接管保证。

## 2026-09-23 后续方案补充：局部调整，保留主架构

Owner 已确认：正在开发的部分暂时不动，本次只补齐后续方案。保留自建执行器、同源工具、独立格式模型和每文档事务；不暂停开发、不追溯重做已开发模块，不增加当前任务、依赖、验收门或发布前置。以下是后续功能接入时的约束与范围，不是已经实现的能力。

### 通用执行与领域能力

Engine 组织目标、上下文、工具往返、任务状态、预算与恢复。Gateway 将能力分派给文档、文件、构建、媒体或后续作业服务。DocumentSession 仅负责文档内容、事务与历史，任务可以引用零份或多份文档；不能要求脚本、独立成果和外部作业先伪造一个文档目标。

工具/job 类别可以随实际能力扩展；授权由宿主绑定对应文档、文件范围、scratch 或作业，不由模型自报，也不因增加类别而授予任意 OS 权限。各格式保留自己的模型、操作与冲突依赖，不把所有内容塞进“元素”，不把现有示例接口扩成通用插件或权限平台。

运行事实与模型上下文分离：操作回执、待处理 job、成果引用和验证证据可查询；上下文只装当前必要观察与可重读引用。压缩、断线和恢复不得重放结果未知的副作用，任务结束按实际成果和必要验证结算。具体行为沿用 S05/S07/S13，不再建设另一套事实存储或固定审查循环。

### 编码能力分层接入

| 场景 | 接入时新增 | 涉及的核心边界 | 当前安排 |
|---|---|---|---|
| Python/JS 数据处理、小脚本 | 受控运行环境、输入输出、成果读取和必要验证 | 作业/进程生命周期、权限、取消、资源与日志上限；复用现有循环 | 后续未排期，不现在建设终端/包管理平台 |
| 独立 HTML/CSS/JS 互动内容 | 源码/资源包、隔离预览、运行错误和交互观察、修复验证 | 成果保存/交付与运行证据；不强制走课件导入 | 后续未排期，既有 Component/Runtime 构建照常交付 |
| 多文件小项目修改、测试和构建 | 工作区读取/检索、文件版本、变更集、测试/构建、必要依赖环境 | 文件变更应用与冲突、进程管理、权限；与已打开文档协调 | 功能接入时定义，不以 shell + patch 宣称成熟 coding harness |
| 长程仓库任务 | 薄 runner、外部任务结果收集与核验 | 父子任务、授权收拢、取消与外部成果状态 | 优先复用成熟外部 Agent，未排期，不复制完整 coding 产品 |

成果按领域交付：Component/Runtime 进入正式文档前仍走 staging、准入与事务；独立脚本/网页保留文件及源码；已有项目使用可核实的文件变更集。作业运行成功、成果验证通过、文档提交及磁盘保存分别记录，不承诺跨文件全局原子回滚。

### 薄 runner 与 MCP 的分工

- runner 只负责有限的启动参数、任务关联、可见事件、进程取消和结果收集。允许 CLI 启动/事件适配差异，不让各 CLI 拥有果铃文档、画布或权限业务逻辑，不解析私有完整思考/会话来补齐产品状态。
- MCP 是外部 Agent 使用果铃能力的入口；原生文档操作走同一 Catalog/Gateway/DocumentSession。外部 Agent 自己的 shell 磁盘修改是外部文件变化，由 FileService 处理重载与保存冲突，不能冒充文档提交回执。
- **交接**：结算旧 run，携带目标、已提交事实、剩余任务和必要附件，接手方取得新授权并重新观察。**委派**：父任务等待一个子任务，接收真实结果后继续；不能通过停止父任务来启动其受管子任务，也不复制外部私有上下文假装无损接续。
- 委派授权与子任务关联，范围不超过用户已授予的范围；避免父子任务无协调写同一对象，仍由正式事务检查冲突。父任务取消先撤销关联写授权，再请求终止受管进程；分别记录授权已失效、进程是否停止、已产生的成果/外部文件变化。未知终止状态如实保留，迟到结果不能自动写入。
- runner 退出码和外部自述只作为结果线索，不能代替成果存在、目标正确和所需测试/验证证据。果铃只汇总实际可核实的信息；不为支持委派重建三家完整聊天、模型菜单或收费状态。

### 实施顺序与重新评估条件

1. **现在只补方案**：明确上述能力归属、分类型成果提交、完成事实和交接/委派区别；当前会话继续既定开发。本次不触碰产品代码、不创建任务或改验收登记。
2. **保留接口余地**：新增工具、job 或格式时允许扩展能力与宿主资源授权；不固定一套永久枚举或统一 patch，不提前实现空泛抽象。SDK、协议传输、解析/计算、编译和进程基础组件可复用，果铃保有产品任务与文档真相。
3. **接入功能再做**：完整 Office、独立网页调试、脚本环境、项目变更集和 runner 根据真实需求排期、实现和验证。原有 S05 循环/恢复、S12 MCP、S13 受控构建和 S14 图片等当前承诺不因本补充延期。

在相关功能接入或既有集成评审时检查边界，不因文档补充重跑已有效通过的测试。新增格式若必须重写模型循环、每种工具都要求专用任务状态、非文档任务被迫套文档事务，或外部 Agent 必须复制业务 writer，才有具体理由重新评估架构。先记录受影响位置、真实用例与局部调整范围；本次不据假设启动核心重构。

## 三层继续独立

ExecutionEngine 负责循环，ModelProvider 负责请求，Connection/Auth 与 Billing 分开配置。API Key 可以使用套餐额度；OAuth 可用范围按供应商事实验证。停止旧 run 后按当前事实接续，不复制私有会话假装无损恢复。
