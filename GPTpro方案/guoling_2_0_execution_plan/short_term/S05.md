# S05｜统一自建执行器与 API、套餐、OAuth 连接

**阶段：短期基础设施 · 2.0 必须完成**
**实施依赖：** S04

## 交付物

果铃拥有统一 ExecutionEngine 的任务循环，直接消费 ModelProvider；覆盖产品任务所需的规划、工具往返、停止、恢复、上下文与用量。构建工具由 S13 提供、图像由 S14 提供、外部 MCP 由 S12 提供，均不要求嵌入 CLI。不得把外部 Agent 的 SDK 包装标成自建模型循环。

## 连接与计费

API 是主要使用方式：供应商、base URL、模型、API Key 引用和能力配置可修改。认证方式与计费方式独立：API Key 可用于按量、预付、Token Plan 或其他允许的套餐；OAuth 是可选补充。套餐 endpoint、模型目录、额度窗口和并发限制按真实供应商处理；未知额度显示未知，不把 token 估算冒充实际扣费。

兼容 API 与必要原生协议并存。Provider 保留 tool-call ID、原生续接项、reasoning 签名等确需往返的字段，不用一套简化 message schema 静默丢失能力。用户可按对话/规划、视觉理解、图像生成/编辑选择不同连接；S10 持久化其角色配置。

GPT OAuth 首轮上线，使用 Owner 当前账号通过正式登录流程接入，前期图片生成使用该连接；独立图片 API 待定。S05 验证认证/刷新/退出及工具调用，S14/P5 在 B05 图像实测与首轮上线前验证实际生图/编辑。登录完成不等于全部模型或图片可用。OpenClaw 的 OAuth 图像路径可作参考，但须记录果铃实际 endpoint、执行者和计费来源，排除隐式调用整个 Codex runtime。资料记载不代替真实接通。

当前工程证据见 `evidence/B07_2026_09_23_INTEGRATION.md`：正式 OAuth 已保存于隔离工程配置，`gpt-6-luna` 的真实工具调用在修复响应协议兼容后通过；一次完整工作台聊天任务实际调用 `image.generate` 并把图片成果交给用户预览与插入。图片生成/编辑另走独立 Images 端点，分别已有真实成功。前六次工具探针均为本地适配失败后的未知结果，不折算为成功；API 核心独立性、OAuth 刷新/退出、其他账号或供应商能力仍按验收用例单独判断。

开发期默认连接为 TeamoRouter（`teamorouter`，`https://api.teamorouter.com/v1`）DeepSeek，第二路由为官方 DeepSeek API；模型 ID 在探针时按供应商实时目录钉定，首选 V4.1 Flash。开发运行时读取 `TEAMOROUTER_API_KEY` / `DEEPSEEK_API_KEY`，不把内部测试配置写为产品默认。TeamoRouter 的按量/套餐/免费档以实际账户为准；两把 API Key 不等于 Token Plan 已开通，S05-T07 缺真实套餐连接时记录条件缺口，不用两条普通 API 代替。

## 循环合同

1. 每个 run 固定用户要求、目标、配置版本与授权；模型收到同源工具及必要上下文。
2. 工具请求交 Gateway，收到真实 read/operation/job 结果后由模型继续或结束。没有固定外层审查轮，也不以 candidate 文件作为普通成功终态。
3. 模型请求、工具调用和正式 operation ID 分别管理。回执丢失先查询已提交操作；不能通过重开模型轮伪装工具重试。
4. 请求失败区分未发送、可证实失败与提交状态未知。遵循 Retry-After/限流和明确重试预算；上游没有请求查询能力时记录 unknown，不自动重复可能收费的生成请求。
5. 上下文按预算压缩；保留原始用户目标、文档引用、已提交事实、待处理工具和剩余工作。压缩摘要不能替代权限或真实文档状态。
6. 先设置本地 run/授权失效屏障，再请求 Provider 与受控子任务取消；晚到结果不能写文档。恢复先重新观察，继续未完成任务，不复演历史工具。
7. 连接复用按账户、供应商、endpoint、权限、协议/schema 与配置版本隔离；切账号不复用旧凭据。
8. 工具与模型的超时、重试、预算、用量和错误有结构化记录。用户配置范围之外不自动更换模型、供应商或计费来源。

请求预算耗尽时给稳定错误码，暂停自动队列；界面允许用户显式继续同一任务的未完成工作。继续前沿用冻结的目标和已提交事实，不重放已应用工具，也不把一次预算耗尽当成自动换模型或自动付费续跑。S05-T09 已通过的压缩、未知请求恢复证据保持原范围；本轮预算续跑另有本地夹具及实窗证据，未新增真实收费请求结论。

## 质量与实现边界

可复用成熟 SDK 或轻量 Agent 核心，果铃保有任务状态与 Gateway。完整 harness 不等于只写一个 while 循环；发布以低成本 API/Token Plan 实际生产能力与高能力模型对照共同验收，不以 GPT 单通道成功代表所有路径。

执行器不把所有失败归内核：网络/认证/限流属 Provider，循环/压缩/重复模型请求属 Engine，权限/工具回执属 Gateway，提交/历史/恢复属 DocumentSession。长任务、构建、图像的集成完成在 S11/S13/S14 验收。

## 后续扩展与完成语义补充（2026-09-23）

保持现有开发安排；以下明确既有职责的使用方式，不新增当前任务、验收门或重构要求。Engine 面向目标、授权、工具观察和作业生命周期，不依据 Markdown/V9/XLSX 或特定元素模型选择专用业务循环。任务可以没有已打开文档，新增资源通过工具创建和授权；未来工具/job 类别按具体功能增加，不要求现在建通用平台。

S07 的运行事实、待处理调用/job、已提交操作和成果引用独立于可压缩的消息；上下文预算覆盖初始输入、工具说明和后续观察，大输出分页或外置，保留重新读取入口。压缩不删除权威操作记录、不制造权限，也不能把旧观察当成最新状态。恢复先查询未知结果和重新观察，再继续剩余工作；有副作用且结果未知的调用不能因模型重试而重放。

模型结束、进程退出、成果生成、文档提交/文件保存及验证通过是不同事实。任务按实际目标和必要子任务结果结算：所需成果缺失、关键 job 失败或结果未知时不能仅因模型正常结束标记全部完成；保留已提交部分，显示失败、停止、部分完成或待核实事实。验证工具提供可检查的证据，模型可据此继续修复；不为所有任务强加一个固定验证模型轮。复用 S05/S07/S13 的既有用例，补充说明本身不使已通过证据失效。

薄 runner 是后续可选外部 job 能力，不能作为 ModelProvider 包装完整外部循环。委派/交接及新增编码能力的范围见 [L03](../long_term/L03.md)，本次不要求实现。
