# S07｜统一过程事件、运行状态与分段存储

**阶段：短期基础设施 · 2.0 必须完成**
**实施依赖：** S02、S05

## 交付物

内置执行器的完整可见过程与外部 MCP 实际调用事件共用时间线信封。任务状态不依赖面板挂载；text、上游公开摘要、tool、edit、image/job、build、usage、document.commit 与 run.end 分流。

## 事件与存储

信封含 conversationId、taskId、runId、itemId、可选 parentItemId、sequence、time 与来源。相同 running 状态的新增输出仍须合并；最终快照按对应 item 覆盖，不能重复追加。供应商未提供的思考不还原、不编造。原生保留字段放受限 Provider payload，不泄漏凭据。

主进程持有运行与订阅，renderer 按 cursor 补拉；分段持久化、摘要快照和大输出外置。页面关闭后重新订阅不重跑任务。回放只读，tool.start/edit.complete 记录不能触发真实工具。

外部 MCP 的来源标成外部调用，仅记录果铃实际收到的读写、构建/导入与回执。外部客户端的完整聊天、思考、任务结束与模型用量没有信息就显示未知，不为补齐 UI 去解析三家 CLI 协议。

## 状态与控制

运行、等待输入/授权、排队、停止、失败、完成、部分完成、外部接手分别表达。任务取消保留已提交部分；内置子任务收拢真实状态。外部撤权只表示果铃停止接受该授权的操作，不宣称外部模型/进程已停止。

图像与构建长任务持久化 job 引用、状态与结果资源；未确认结果不能自动重发收费生成或重复导入。大日志不进入每轮模型上下文。
