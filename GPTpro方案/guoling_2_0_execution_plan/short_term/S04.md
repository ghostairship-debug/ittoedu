# S04｜同源领域工具、短句柄与直接操作

**阶段：短期基础设施 · 2.0 必须完成**  
**实施依赖：** S02、S03

## 交付物

将现有 AuthoringToolFacade 演进成同源的 ToolCatalog + ToolGateway，人工菜单和AI调用复用领域 schema/planner。模型只处理目标短句柄与内容，不填写项目/owner/版本等工程元数据。

## 接口与调用

模型侧：`text.replace({target:'t1', content:'…'})`、`object.update({target:'t2', properties:{…}})`、`document.insert({parent:'t3', content:…})`。命名可映射现有 `native.content`、`layer.edit`、`flow.content`、`owner.background` 等，不要求新增一套同义工具。

宿主文档写入侧：`invoke(context, call)` → 解析句柄 → 验证可用能力/授权/读集 → 对句柄绑定的 DocumentSession 执行 planner → S03 提交 → 返回 `applied/unchanged/conflict/failed` 和必要影响集。应用结果不是模型自己的描述。

Gateway 是能力入口，DocumentSession 只是文档写入的目标服务。读取、文件操作、构建和媒体任务按各自服务返回观察、操作或 job 结果；后续脚本/外部作业不要求伪造文档目标。不同入口复用同类能力的授权、业务规则与回执，不能为每个 CLI 复制业务逻辑。本次补充明确后续扩展边界，不要求重做当前 S04 或新增通用插件框架。

文档句柄至少绑定documentId、epoch、对象/文本锚点、读时内容足迹、授权上限。它不是任意内部路径，也不是永久能力令牌。其他能力的资源/job 引用由相应服务校验寿命与范围，不能借类型扩展获得任意文件或进程权限。别名短不代表可以省掉宿主检查。

## 实施步骤

1. 从现有 registry 自动生成模型 schema 与手动操作元数据；保留样式、组件、Runtime、资源与导航命令的正式业务定义。消除三家CLI分别维护工具说明的分支。
2. 建立 target resolver：短句柄映射真实文档、owner与位置；不读取活动tab或当前selection。创建操作从父容器句柄取得位置，返回新对象句柄；模型无需提前发明对象ID。
3. 给纯读提供 `read/inspect/listChildren` 的小范围返回及分页。初始上下文给当前内容/选择的必要信息，完整资源与工具细节按需读取。截断明确并给cursor，不偷偷丢掉目标。
4. 定义批量单文档操作。先验证所有目标与相互依赖，在内存局部计划后一次提交；任何一步失败整批不提交。跨文档分次提交并返回各自结果。
5. 普通公开属性、文本和结构操作接入main内核；需要图像或代码运行证据的工具先异步准备资源，再在同一调用中提交，不把它升级为整个Agent的固定外层流程。
6. 增加结果压缩：默认返回状态、更新句柄/版本、影响对象和精确错误；有需要再读取全文/截图。重复大JSON、base64、完整工具说明不进入每次结果。

## 并发与安全

句柄过期先按同文档可验证的操作映射更新；目标已变化或依赖不完整返回冲突。不能把documentRevision强行换成最新来让旧操作通过。只要是另一页的无关操作，不应因浏览位置变化失败。

显式局部编辑工具限定其目标区域。普通会话提供的选区只是上下文，是否使用其他对象由模型与实际权限决定。授权检查不解释“风格一致”等语言。

## 日常路径退出条件

普通工具执行不经过候选文件、不调用外层generation driver、不等待turn-ended才提交。registry保留全工程导入/代码工具，但它们是按需调用的明确能力。一个新的公开属性能力完成后，不应修改三个runtime adapter。
