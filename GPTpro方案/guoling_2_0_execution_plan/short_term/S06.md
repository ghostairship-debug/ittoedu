# S06｜正文编辑流、源文保真与位置映射

**阶段：短期基础设施 · 2.0 必须完成**  
**实施依赖：** S03、S04

## 交付物

一个与执行后端无关的 EditSession；目标句柄、增量事件、正文临时投影、完整操作提交和一次撤销。MD与Flow正文共用接口，不共用不兼容的权威格式。

## 编辑生命周期

`begin(editId,targetHandle,epoch)` 固定选区和基准；`delta(seq,text)`追加；`snapshot(seq,text)`替换当前生成片段；`complete(seq,content)`校验后提交；`abort`丢弃当前草稿。sequence按editId递增，同片重复去重，断流需补快照，不猜缺失文本。final snapshot不能追加到已流出的内容后面。

每份文档先限制一个活动的正文生成组。别处人工编辑允许继续，重叠区域临时只读；多任务同目标排队。取消与target失效即时撤回生成草稿，忽略晚到delta/complete。已完成操作按History保留。

## Markdown 的准确定位

1. 权威source不变形；sourceMap/AST/正文节点来自同一revision。普通段落、标题、强调、链接文本、列表、引用、表格单元格必须覆盖。
2. 节点ID由文档会话维护。局部修改后通过操作范围/解析增量保持未触及节点身份；不在每次渲染中随机重建全部ID，不靠相同文本猜重复段落身份。
3. 正文选择→block/slot/offset→明确源文范围。模型只拿句柄，不计算UTF-16索引。源文切片、escape、列表/引用前缀与资源链接保全由文档模块完成。
4. 普通文本修改以最小源文编辑保留未触及字节；需要结构变更时调用明确的块操作。不能对任意选区完整序列化整篇文档，顺带改掉用户未选区域。
5. ProseMirror映射只解决其自身位置；必须同时维护它到source的映射。对不支持结构保留原件/可读对象并清楚标记；不能把正常列表和引用一概要求切源文。

沿用 r20 暴露的真实反例补强既有 S06/M05 样本：标题后的空行、块首尾可见空格、列表缩进续行、裸 URL 与中间未映射槽位。正常内容必须准确映射，无法证明连续范围时不得跳过中间内容后部分提交。Flow 源文 Ctrl+Z 后即使视图实例/代次变化，选区回报和后续编辑也须恢复；不保留因重挂载永久等待的守卫。旧修复是参考证据，不能替代新内核接线后的目标验证。

## Provider 分片转换

原始参数分片先进入解析缓冲；调用身份、目标和权限固定后，可解码已确认的 content 字符串并输出类型化 delta/snapshot。流式文字投影不是执行不完整 JSON，也不要求额外模型轮。参数顺序导致目标尚未到齐时暂存，不猜目标；重复 key、转义截断、缺片、失败结束、目标变化则撤回或明确失败。完整参数与 finalText 一致并通过校验后才能正式 commit。普通聊天和思考不得被截取当正文。

## 投影与人工输入

生成中内容不是正式source。renderer由权威内容+EditSession片段生成投影，维护canonical与presentation位置映射。临时新增文字不可被当作已保存正文，隐藏旧文字不可留可落入的光标。可采用受控widget/NodeView或带preview标记的局部事务；选定一种并在同一插件处理光标、复制与映射，不能只用CSS盖住旧字。

别处人工输入从presentation坐标映射为正式编辑操作；与目标相交则拒绝该编辑或先取消生成，用户动作不可消失。点击生成区清楚显示正在生成；不锁整个文档。

当前 `editorSession.update()` 的内容变化会重建EditorState。普通增量必须改为同实例transaction，重建只限加载/确需结构重建，且恢复可验证的视图位置。生成流按UI帧合并，避免每token全量React渲染/全source解析。

## 完成、保存与撤销

完成先验证epoch/目标/结构及所需资源，再通过S03一次提交并去掉投影；已显示文本与正式文本相同不闪回或重复追加。停止恢复当前组原文；Ctrl+Z在活动生成组内先取消该组。后续正常撤销遵循正式操作序列。

生成中保存仅保存已提交revision，界面明确生成部分未完成；不是把半段JSON/半个表格落盘。断电后默认恢复正式内容、用户输入与附件，不自动启动模型；可选保留未完成片段供用户阅读，但不能自动应用。

## 后端不能成为借口

真实内容增量由明确编辑通道提供。若原生后端只能返回最终工具参数，仍可做到操作级即时，但不能假称正文逐步生成。统一自建执行器是默认路径；2.0 须在主 API 使用方式中接通真实正文流，OAuth 不是前置。不能用读半写入文件、截取普通聊天或播放完整稿动画替代。

行内修订展示复用同一EditSession，只改变呈现/接受策略；2.0默认直接替换。持久审阅和多人合并留长期。
