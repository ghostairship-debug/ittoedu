# S01｜开发基线、能力保全与重构边界

**阶段：短期基础设施 · 2.0 必须完成**
**实施依赖：** 无

## 交付物

固定实现起点、工作树差异、依赖与环境版本；建立可复现构建记录、基线样本和旧代码到新内核的职责地图。代码迁移地图与旧用户数据迁移不同，前者保留，后者取消。

## 实施步骤

1. 读取当前正式入口与现有证据，固定实际源码起点；只补缺失且影响重构判断的基线检查，不因新会话重复全部测试。
2. 复用受支持 V9、Markdown、图片/附件、三表面、交互、Runtime/Component、播放器和导出样本副本；不在唯一原件上试验。
3. 按 REFACTOR_MAP 标出唯一 writer、History、资源与视图端口的替换边界。保留能力不等于保留旧执行链。
4. 使用隔离分支与可复现基线构建推进；不建立 legacy-session/document-session 双内核切换，不做旧聊天/缓存迁移。
5. 新功能的实现、集成与实际验收分别记录；历史绿色结果不自动成为 2.0 完成证据。
6. B01 开工前确认旧路线卡已处置、无与本批冲突的协调任务，不要求清空合法的其他任务。Owner 于 2026-09-23 已授权吸收有效经验后退役 r20 卡，本轮删除 `docs/development-plan/tasks/r20/r20-contextual-authoring.md` 并运行 `npm run generate:task-board`；吸收映射和历史未完成项见[退役记录](../evidence/R20_RETIREMENT.md)。协议的同锁互斥适用于 active 任务，不把原 blocked 卡误述为已触发并发锁冲突。旧用例不自动实例化为 2.0 任务，也不豁免 2.0 仍适用的文件、导出和能力保全要求。

## 完成条件

可复现基线、样本与代码职责齐备；恢复、保存保护和受支持文件读取仍是产品要求。无用户不是删除恢复机制的理由。当前方案修订不执行本任务的产品测试。
