# S13｜受控代码构建、修复与正式导入

**阶段：短期基础设施 · 2.0 必须完成**
**实施依赖：** S03、S04、S05、S07、S09

## 交付物

同一果铃执行器使用 build 工具在独立 scratch 生成 Component/Runtime 或准备外部工程，读取构建错误并修复，经资源/协议/运行检查后调用正式导入。无需调用完整外部编码 Agent。

## 构建合同

宿主发放 build job、scratch 和工具权限；源文件、已打开工程和凭据目录不提供直接写权限。scratch 允许必要创建和修改，网络/安装依赖仅按批准范围。实际 OS/进程隔离或等效受控运行机制必须验证，cwd/提示词不能替代；不自行扩大成通用终端平台。

工具返回 job 与阶段化输出，长日志分页/外置。编译失败向同一任务返回精确错误，模型据证据修复；超过明确预算或同因无进展时停止并保留可阅读成果，不无限循环。

静态检查包括协议、依赖、素材闭包、入口和资源限制；动态检查在隔离宿主验证生命周期、可见结果和所需交互，不能污染用户当前播放。复用现有编译、准入、播放器与导出能力，不能把 mount 成功等同交互正确。

通过检查后以冻结目标与读集合提交，资源+内容共用一个 History。导入时目标已变则冲突，不用最新 revision 替换旧前提。失败或取消不能把半成品写入正式文件。只删除普通编辑的候选往返；build/import staging 保留。

一次混合任务可以先直接修改，再调用 build 工具，模型和连接依用户配置保持一致；无需用户选运行模式。未提交构建失败时，如实显示前面已完成部分。

## 后续编码成果边界（2026-09-23）

本任务当前受控构建、修复、验证与正式导入继续按既有范围开发。上述导入合同适用于进入果铃文档的 Component/Runtime 等成果，不表示所有未来代码任务都必须导入课件。

- 文档扩展：继续 staging、准入、冻结目标检查及 DocumentSession 事务/History。
- 独立 HTML、脚本与数据处理成果：后续保留源码/文件包与成果引用，使用适用的预览、运行和验证能力，再经受控文件服务交付；不强制转成 V9 元素或 Runtime。
- 已有多文件代码项目：后续定义文件版本、变更集、冲突与应用结果；协调打开文档的未保存内容，不让构建子进程旁路覆盖源文件，也不把文档 undo 宣称为整个项目原子回滚。

共用的是作业执行、取消、日志、预算和模型反馈循环；不同成果自行定义提交与验收。编译成功不等于交互正确，进程退出也不等于成果已应用。后两类当前仅保留设计边界，运行环境、项目修改和薄 runner 待具体功能接入，见 [L02](../long_term/L02.md)、[L03](../long_term/L03.md)；不新增本任务验收或发布前置。
