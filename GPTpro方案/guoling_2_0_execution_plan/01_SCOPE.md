# 交付范围与固定决策

## 阶段边界

| 阶段 | 必须交付 | 完成的含义 |
|---|---|---|
| 短期 S：2.0 基础设施 | 文档会话、直接工具、事务/资源/恢复、正文内容流、完整事件、附件输入编译、文件服务、独立会话、统一自建执行器、外部 MCP、受控构建和图像生产 | 自动化合同与至少一条真实端到端路径成立；不是只建接口或换目录 |
| 中期 M：2.0 产品体验 | 完整文件操作、轻量内容区、四表面共编、即时正文、统一聊天附件、过程透明、可靠保存、外部发布 | 用户不用切源文、读外部候选或进入开发终端来完成核心工作；所有声明支持路径通过实测 |
| 长期 L：2.x–3.0 | 多格式深度支持、自有 harness 的持续优化、多步骤全画布实时、协作/版本、插件连接器、布局预设及长尾性能 | 形成候选方向、价值、依赖与取舍；不把这些方向伪装成本次已实现能力 |

短中期是同一 2.0 交付，不把基础设施叫 2.0、把核心体验叫 2.1。内部演示也不是外部发布的替代。

## 固定的产品决策

1. 会话属于工作空间，与文件正交；文件夹承担组织，不要求用户建立项目/课例对象。空间可以是用户目录，也可以是首次启动的受管本地空间。
2. 每份打开的 MD 与 h5lesson 有独立 DocumentSession。多个课件标签不得共用一个可写单例；重构为真正的每文档会话是 2.0 必做。
3. h5lesson 是可关闭文件；Flow、Slides、Spatial 是它的内部表面。编辑文档不取决于它是否已保存或是否为当前可见页。
4. 正文/源文是 Markdown 的两种视图，默认正文。用户在正文中选择和编辑；不能把切源文当正常的局部 AI 入口。
5. MD 与 Flow 正文在模型生成期间原位显示真实新文字，完成后自动提交，一次撤销；行内划线修订可增强，但不是默认路径的前提。
6. Slides/Spatial 中每个完整工具操作完成即更新画布；所有表面逐 token、逐手势动画式演进属于长期，不影响 2.0 的直接工具即时反馈。
7. 模型与实际连接在输入区可见；API/Token Plan 为主，OAuth 可选。对话、视觉与图片可分配不同模型，费用来源透明；外部 MCP 设置单独呈现，不以隐藏模型或强制 Auto 简化交互。
8. 附件支持选择、拖入、截图粘贴、工作区文件引用、Windows 普通文件复制粘贴。仅附件可发；真实输入能力与卡片显示分别验收。
9. 布局先完成一套默认：左侧资源管理器在上、会话列表在下，默认常驻；中间文档内容与课件底部固定场景/状态导航；右侧 AI 常驻。用户可主动收展、调尺寸并记忆状态；将来支持预设与拖拽换位，不先造布局平台。专业编辑器保留主体布局，右侧工具和 AI 改为侧边按钮按需展开。
10. 显式“修改选中内容”限定其编辑范围；普通聊天里的选区/图片是已知上下文，不由软件按自然语言猜测它们的语义角色。
11. 工作台可插入文字、图片、视频、音频，并通过选中后的快捷工具条/属性浮层手改。保留原处快捷工具条内 AI 输入和提交，不强制跳转右侧助手；两个入口共用任务和文档内核。完整交互约束见[工作台与编辑器细则](mid_term/WORKBENCH_EDITOR_LAYOUT.md)。

## 2.0 支持范围

| 对象 | 2.0 最低完整能力 |
|---|---|
| Markdown | 创建、正文/源文编辑、普通格式/列表/引用/表格文本选区、即时文字修改、保存与重开 |
| h5lesson | 三表面与混合课件导航/深度编辑能力保全；工作台四类基础元素插入、属性及原处 AI 修改；多文档隔离、领域操作直达、试运行与已支持导出 |
| 图片/文本/PDF 附件 | 输入、预览/提取、按真实模型能力供给；PDF 页与提取完整性可见 |
| DOCX/PPTX/XLSX 等其他文件 | 资源管理和外部打开；已存在且宣称的提取/导出能力保全，不等于完整原格式画布编辑 |
| 内置执行器与连接 | 自建统一循环覆盖直接编辑、构建修复和图像；API/可用 Token Plan 主链与低成本组合实测；OAuth 按具体支持矩阵验证 |
| 外部 MCP | 同一工具服务接多客户端，真实读改与回执、授权撤销和交接；不要求三家 CLI 深度嵌入 |
| 图片生产 | 文生图、参考图编辑、资源导入、撤销、保存重开与离线导出；具体模型能力分别标注 |

不得把高能力 GPT 单路成功当成 API 主方式或低成本生产已完成。不能用“至少一条稳定连接”掩盖其余已宣称支持的核心缺陷：每个显示为可用的连接均有功能矩阵和对应测试。接口确实没有上游能力时明确标注，不伪造；产品核心任务仍须有可见、经用户配置允许的完成路径。

## 明确的发布底线

实际数据丢失、串文件写入、停止后新写入或伪报保存按数据与核心可用性阻断发布；核心路径只能绕到外部候选、源文、系统资源管理器或开发终端为 P1。已证实越权单列安全/数据影响；假设性纵深、流程或文档问题不冒充可用性 P0/P1。2.0 发布前，范围内已知 P0/P1 必须清零。没有发现缺陷不等于证明绝无缺陷，仍需独立实际使用验收。

十分钟案例只用于调查通道成本和观察模型表现，不建设背景语义专项。工程保证输入真实、调用正确、传输低开销，不保证模型审美或自然语言理解总是正确。
