# 目标架构：活文档、统一自建执行器与外部 MCP

## 1. 四个边界

```text
API / Token Plan / 可选 OAuth → 果铃统一执行器 ─┐
人工编辑 ─────────────────────────────────────┼─ Tool Gateway
外部 AI / CLI → 统一 MCP bridge ──────────────┘       ├─ 文档工具 → DocumentSession → 资源 / History / 保存 / 恢复
                                                     ├─ 文件 / 构建 / 媒体服务 → 操作或 job 回执
                                                     └─ 后续可选薄 runner → 外部 Agent → 同一 MCP
```

领域逻辑不读取 React Store、不依赖当前画布页，不导入 Codex/Claude/OpenCode。执行后端不直接改文档内核；界面不解析 CLI 协议。模块边界通过允许依赖检查维护，不引入微服务或为本地函数再造通用消息总线。

2026-09-23 补充：本图明确后续能力归属，不增加当前实施范围或要求重做在开发部分。DocumentSession 是文档 writer，不是全部任务的容器；任务可引用零份或多份文档，Gateway 按能力分派服务。文档内核不承担进程、任意项目文件变更集或所有成果的统一提交。

## 2. 进程与权威状态

**2.0 的目标实现选择：权威 DocumentRegistry/DocumentSession 由主进程的文档服务持有；纯 TypeScript 内核不依赖 Electron。** 大文件解析和资源转换放受控 worker；不先建设独立文档服务器。这样切标签、卸载画布或渲染器重建都不改变任务与文档身份。

renderer 中 ProseMirror、画布 backend 和 Zustand 都是视图、缓存或未确认编辑投影，不拥有第二套可独立保存的正式内容/History。人工输入允许本地即时显示；其修改按顺序提交文档服务，ACK 后对齐正式 revision。AI 修改前按文档排队完成已发出的人工修改，不能读取旧快照。

当前大量领域函数在 `src/renderer/course` 与 `authoring`，迁移时先分离纯 planner，再移动至 `src/core` 或等价的纯模块。含 DOM/Phaser/播放器依赖的观察与渲染保留 renderer，经窄请求端口提供。不是把整个 editorStore 搬进 main。

## 3. 权威内容与格式

MD 的正式内容是保真的源文与资源引用；解析树和正文状态是同版本的投影。h5lesson 的正式内容沿用 V9 与资源侧车。共用生命周期与能力接口，不统一为万能文档 JSON。

每文档独立 documentId、revision、资源、History、草稿、写队列与任务租约。文件路径是可变 binding；当前页/选区/缩放属于 ViewState；内置 run 属于 Conversation；外部 connection/grant 与交接事实单独记录，不依赖原生 thread。会话、视图和文件三个身份不能互相替代。

## 4. 两条操作形态

**直接编辑：** 模型调用已注册工具 → 句柄解析及局部检查 → 同一文档事务 → 通知视图 → 返回工具结果；都在同一任务的工具调用往返内完成。既有领域命令、资源与逆操作继续复用。

**构建与导入：** 用于导入果铃文档的外部工程、新代码包、需隔离运行的内容在受控区准备 → 类型/资源/运行边界检查 → 仍经同一正式文档 commit。它是独立工具能力，不是所有任务的外层仪式。后续独立 HTML、脚本成果和已有代码项目变更使用各自交付/提交语义，不强制转为 V9 或导入课件，见 S13、L02、L03。

普通文本/属性的直接编辑不调用 `createGenerationCandidateCoordinator`，不经过 `candidate.json`，不设置“必须交候选才能完成”的终态。批量操作可以在一个工具调用内形成单文档事务；跨文档任务按文档分别提交、如实显示部分完成，不许伪称全工作区原子事务。

## 5. 工具接口分层

模型侧用短句柄与内容参数；宿主注入 documentId、基准、owner、操作 ID、写入授权。短句柄只减小通信，不放松身份与授权。句柄与任务/文档寿命绑定，失效返回具体错误，不偷换成当前活动对象。

工具定义与 UI 手动命令共用领域 schema 和 planner；迁移期允许少量语法适配，不复制业务校验。文档能力按 Driver 支持情况与权限生成；文件、媒体、构建及后续作业能力按相应资源范围和权限提供，不要求伪造文档句柄，不由每句自然语言的任务分类器决定。

## 6. 正文流与正式事务

`edit.begin → edit.delta/snapshot → edit.complete/abort` 是类型化内容流，不是聊天正文。临时草稿只持有目标范围和替换片段，生成中原位展示；正式完成后一个撤销组。文本流不逐 token 写盘/深复制工程，不把 incomplete JSON 作为可执行操作。

执行器接收原始工具分片，绑定身份/目标后可增量解码 content 字符串形成安全草稿；参数完整前不得提交正式操作。异常转义、重复 key、截断或目标失效明确失败。内部文本流不必绕 MCP；外部完整工具调用只承诺操作级更新。

## 7. 最小通用保护

每个真实写入都保留身份、范围、结构、资源和幂等检查；检查为工具内部执行，不增加模型轮次。普通操作检查局部足迹；完整结构校验保留于导入、整文档替换及开发回归。未知 planner 先维持保守校验，只有对应局部不变量和测试齐备后才解除全量校验。

恢复日志与 UI 事件不同：权威操作依靠小型日志记录恢复，完整过程分段存储。工具结果若已确定成功，传输失败只查询/补发结果，不重复内容动作。

## 8. 基础设施完成标准

两份课件和一份未保存 MD 可以独立编辑；在非当前页执行操作不切焦点；正文真实流式；普通编辑无候选交付；一个新领域能力不要求改三家适配器；关闭面板不终止任务；崩溃后恢复与撤销不依赖聊天文本。

现有工具门面、事务、资源历史及正文实现的复用/迁移位置见 [REFACTOR_MAP](delivery/REFACTOR_MAP.md)。这是一项目标架构规定，不是对当前代码已完成程度的描述。


## 9. 连接、构建与开放边界

ExecutionEngine、ModelProvider、Connection/Auth、Billing 分层。API 与套餐为主，OAuth 可选，文本/视觉/图像角色独立；schema 兼容不等于能力或费用相同。默认循环归果铃，ModelProvider 只负责模型请求，不用完整外部 Agent 冒充 Provider。后续可经薄 runner 委派外部作业，由外部 Agent 管自己的循环；果铃管理父任务、授权和可核实结果，不复制其业务内核。

live/build 是同一任务可用的工具权限与结果准入方式。构建子进程仅在受控 scratch 执行，源工程与正式内容不可旁路写入；导入文档时必要检查后仍经同一文档 commit。具体权限必须实际实现，不以 cwd 或提示词替代。任务事实与模型上下文分离，完成依据见 S05；未来作业和工具类别可以扩展，不由当前示例枚举永久限定。

MCP Server 是同源 Gateway 的外部包装，不是第二文档服务。配置兼容与工具互通由 S12 验证，不托管外部完整聊天/模型循环。MCP 撤权阻断果铃写入，不阻断外部 CLI 自己的 shell；外部磁盘变化走保存冲突处理。
