# 2.0开发顺序与完成边界

**V3.3｜2026-09-25｜只修订本方案包，不修改任务登记或验收状态。** 按Owner本轮决定，Runtime当前状态轻编辑、常见图文自动发现、HTML机械式保真导入、Flow网页承载/原生文本框、后置呈现策略及机械Skill闭环纳入2.0阶段完成范围；不再笼统推迟到2.x。

## 1. 先收口当前基线，再完成2.0能力增量

Owner报告现有Codex验收剩3项。先完成正在进行的旧范围验收并固定可回退基线，再改Runtime/Flow相关链路；不一边验收旧实现一边改它的运行内核。若旧范围最后一项本身是总范围核对，保留它对旧范围的结论，新增能力完成后再做最终范围核对，不形成循环依赖，也不据旧范围通过宣称本轮新增能力完成。

本包描述开发建议与完成标准，不直接新增、重排、关闭S/M任务，不写task_registry、正式acceptance_cases、TASK_BOARD或任何现有任务卡。后续实施由实际开发会话按授权接续。保留现有DocumentSession、单writer/History、Gateway、执行器、资源、构建、MCP入站与CLI薄runner方向；不重构已经稳定的底座。

## 2. 建议实施顺序

以下是方案中的工作顺序，不是新的任务编号或固定多Agent流水线。运行入口、目标身份、保存必须由同一集成人协调；明确非重叠的界面文案和Skill草案可并行。

| 顺序 | 本轮交付 | 到此即可结束 |
|---|---|---|
| 现有验收收口 | 完成旧范围剩余工作，保留构建/差异与可回退点 | 不重复全仓审查；未通过项如实留存，不为新方案篡改旧证据 |
| 当前状态编辑与自动图文目标 | 在已有Runtime宿主/选择/提交链上，先贯通DOM与Phaser常见文字、图片，覆盖场景和组件；Three做已知可访问表示 | 运行到后续状态→进入编辑仍在这里→修改文字/换图→恢复运行；保存重开后修改仍在，跨句/重复对象不串改。详见14 |
| HTML整体机械导入与共享轻编辑 | 本地HTML及其受支持依赖由程序封装，默认全Runtime；DOM编辑复用上一层，静态HTML可直接保存源文，动态HTML明确持久化方式 | 用已有HTML真实导入、改字换图、保存重开和HTML导出；无LLM重设计或强制拆原生。首次对照定位问题，不建评分系统 |
| Flow整页承载与自由图层 | 将现有Flow Surface Runtime补为真实编辑/运行的页面正文承载，处理内容高度、滚动与坐标；Flow“插入文字”改为原生文本框 | 长网页能滚到末尾、编辑不跳回初态；插入文本框/图片/箭头随paper滚动，正文仍可正常输入与回车，保存重开成立 |
| 三表面接线与呈现策略/Skill | 补本轮所需Slide/Flow/Spatial Runtime运行与编辑缺口；在框架HTML完成后，单独决定载体，再接现有素材/装配工具 | 空间画布中相机移动不破坏命中；一个新建教学作品从文稿/HTML到工程与局部修改闭合；教学/HTML设计阶段未提前加载编辑器能力 |
| 2.0最终收口 | 合并上述结果，仅复验受影响行为和新增承诺 | 关键内容/行为不缩水，编辑能持久化，支持与限制清楚；不以安装包或Office全接入作为完成前置 |

HTML包装器可在Runtime编辑接口稳定后并行实现；Flow的整页占位/高度设计应在导入样例时一起确认，不把长网页留到最后才发现放不下。三表面只补这些能力用到的挂载、状态、坐标与保存，不顺带重造完整局部Interaction系统。

## 3. 2.0承诺的具体边界

**必须交付：** 支持对象的文字替换与图片替换；运行到哪编辑到哪的会话内操作；DOM和Phaser常见图文自动发现，不要求AI逐个expose；Three已有可访问的Sprite图片/DOM文字等已知模式；场景与组件复用编辑机制；HTML整体保真导入；Flow网页正文承载和原生文本框；后置呈现策略及机械装配。未支持对象保留显示，不伪装可编辑。

**不扩大为：** 任意JS现场序列化、所有Canvas像素逆向、烘焙文字识别、任意React状态到源码反编译、通用DOM自由拖排、任意HTML全原生转换、Three任意材质/几何深编、三表面全部特性完全等同。已有原生拖拽、参数或富文本能力保留，不以本轮轻编辑边界为由删除。

Slides任意尺寸值得后续参数化，但当前1280×720假设涉及命中/导出/编辑边界，本轮通过Flow承载长网页，不把全局画布尺寸重构加为前置。原生拆分是后续可选优化，不是HTML导入或2.0完成的必要条件。

## 4. 足够的代表性验证，不建立全组合矩阵

| 代表路径 | 只验证关键差异 |
|---|---|
| 听力HTML | 原HTML与机械导入结果的少量关键画面/操作；切到后续句改原文/译文和图片，保存重开/导出；尤其确认同一气泡复用于不同句时不串改 |
| 无expose的引擎样例 | 一个小型Phaser场景及组件，文字/图片自动出现为可编辑目标；容器变换与对象重建后匹配正确；Three只对实际支持的表示补最小例子 |
| 长网页与Flow | 至少超过一屏的真实流式HTML，改字后高度变化；末尾可达，原生文本框随paper滚动，切编辑/运行不漂移。含sticky/视口依赖时核对选定承载方案 |
| 新建教学作品 | 教学与呈现稿→框架HTML→后置载体决策→必要素材/模块→机械装配→局部改动；不是仅特配已有听力页 |

多种行为可由同一份样例覆盖，不展开成引擎×表面×状态的全乘积。保存、撤销、锁定、资源与取消已有测试直接引用；只有改到该边界才补相应回归。失败定位后修相关路径，不要求全部历史测试在每个小批次重跑。

原听力文件来自本轮会话，V7工程只是失败参考，不用它代表当前V9。原文件不在本包；后续从已授权位置取得，不制作相似文件冒充。F-CURRENT三方诊断只在确需归因时补一次，默认直接比较原HTML与导入结果，不强制每次再花模型额度生成第三份。原HTML自身缺陷另记，不把复制缺陷算保真。

## 5. 日常执行的轻量边界

机械导入/资源搬运/装配不调用LLM；新教学内容、新素材和必要新代码才由模型负责。已有成品直接导入可跳过教学、框架生成及模型载体决策；已有代码已检查且未改变时复用结果。

权限、来源/目标版本、取消、资源引用、正式提交与保存反馈沿用当前入口。正常改字不触发全工程扫描、全资源hash、重编译、截图或视觉Agent。截图/人工对照只在首次接入、相关渲染变化或怀疑退化时使用。关键交互丢失和误保存必须修，像素细差不构成无限重试理由。

本包benchmarks中的35条历史定义保留原样，不增加ID、不写测试结果、不当本轮正式任务台账。新增能力的完成判据以本页和14为准，由后续实现按实际差异选择已有测试或补最小检查，而非再建一套验证平台。

## 6. 其他路线和停止条件

Office多方案研究与普通文件打开保留，不借本轮扩张Office内核、插件市场、完整浏览器或发行工程。若出现Journal增长或高频事件延迟，复用12中的OJ/OE做局部优化；不先建设完美架构。

未取得稳定内容身份，就不能用“发现了对象”冒充“修改可持久化”；先缩小该类对象支持范围或补确定的绑定，不引入语义猜测/多Agent复审。现有成熟原生节点不删，不设置Runtime占比KPI；根据完整作品质量、修改收益及维护成本选择表示。

最终报告区分文档检查、产品实现、实际测试和Owner接受。本轮只更新方案，不提前声称上述能力已完成。
