# Office 验证计划与性能基线

## 1. 先定义“打开”

T0是用户点击工作区文件。分别记录：界面响应、真实内容首次可读、视口稳定、可输入编辑、首次保存确认、文件重开成功。空工具栏、加载动画或只显示文件名不算内容已经打开。

ONLYOFFICE的onAppReady与onDocumentReady恰好说明应用就绪和文档就绪不是同一时刻；其他Provider需自行找到等价信号并人工确认。[S13]

## 2. 六种状态分别测

| 状态 | 测量意图 |
|---|---|
| 首次安装/尚无运行时 | 包下载与安装单列，不能隐藏 |
| 冷应用、打开本地新文件 | 首次引擎加载、文件读取、解析和排版 |
| 热引擎、打开另一新文件 | 不被同文件缓存美化的常用路径 |
| 同文件重开/已缓存 | 缓存收益，来源版本一致性 |
| 已打开Tab切回 | 是否无谓销毁并重建实例 |
| 云端文件已存在 vs 本地首次上传 | 对网络/上传的端到端影响 |

清楚记录缓存、预热、内存驻留和网络条件。不能把文档上传提前到未授权后台；也不能把预热消耗从产品成本中删除。

## 3. 初始性能目标〔产品假设，非实测结论〕

普通文件以“约1–2秒可读”为优化目标，可暂设常用样本p50≤2秒、p95≤5秒的讨论门槛；切回已经打开的Tab目标≤300毫秒。首次重运行时冷加载、大型或复杂文件单列，不用同一数字掩盖极端值。

这些数值须在目标设备上确认后才变成发布门槛。速度不达标先定位瓶颈，不立即加第二套查看器。样本不足以支持百分位时只报告每次原始值与中位数/最大值，避免伪精确。

编辑模式另测可输入时间、打字/拖动响应、保存时间；“查看很快但点编辑再等一分钟”也应暴露。打开与手动输入不得调用LLM。

## 4. 第一轮样本

先用9个授权、脱敏文件：每种DOCX/PPTX/XLSX各取简单、常用、复杂一个。每个冷状态至少做数次独立启动，热状态重复若干次，保留原始记录。此轮用于定位问题，不宣称统计覆盖整个用户群。

有候选表现可用后，再扩到每种格式约10个文件或真实用户材料。文件大小不是唯一复杂度：形状/表格/字体/公式/媒体数量同样记录。测机器固定，记录CPU、内存、系统、显示缩放、字体、应用与引擎版本；云端记录地域、延迟与吞吐。

| 格式 | 样本应包含 |
|---|---|
| DOCX | 中文教案、标题列表、复杂表格、公式、图片环绕、长讲义、页眉页脚 |
| PPTX | 教学公式、母版、组合图形、图表、裁剪透明图、备注/媒体边界、大页数 |
| XLSX | 课表、成绩表、合并/冻结、格式化日期百分比、公式、图表、多sheet、大范围 |

宏和外部链接不执行；加密文件要求明确授权与正常密码输入；不能因忽略宏而声称保留其行为。浏览器不支持的嵌入媒体和对象需要说明。

## 5. 显示质量验收：容许差异，不容许误导

| 类别 | 例子 | 处理 |
|---|---|---|
| 可接受偏差 | 字体替代、少量行距、装饰效果、分页不同但内容完整 | 记录，不阻断基本查看 |
| 任务相关偏差 | 图注错位、表格遮挡、公式排版难读、关键形状关系改变 | 真实任务判断，需修复或明显提示 |
| 内容错误 | 数值错误、漏页、丢图表、公式变成错误关系、静默截断 | 不以“高保真预览”通过 |

指定参考应用版本；同一文件在不同Office产品中可能不同。截图比较只辅助定位，数学关系、公式缓存和表格数据用结构断言/人工抽查。不能用全页视觉相似度掩盖关键区域丢失。

## 6. 编辑与AI接力测试

按能力分开记，不要求只读方案通过编辑测试，也不能把失败算成零性能。

1. 查看：打开、翻页/切sheet、搜索、缩放。
2. 选区：获得文字范围、页/shape或sheet/range；验证目标可否在当前版本再次定位。
3. 手改：文字、形状位置或单元格输入，撤销后正确恢复。
4. AI接口：通过受支持命令改明确对象，不靠截图猜测；没有接口则标缺失。
5. 接力：人→AI→人多轮；检查陈旧选区、跳焦点和未保存版本覆盖。
6. 保存：保存结果真正落到工作区；重开和外部应用打开后正确。

开放编辑器时不要同时用另一个文件工具直接改磁盘上的同一Office文件。优先经当前编辑会话命令修改；无此能力就采用保存—修改副本—重新加载的明确接力，不伪装成实时同状态共编。

## 7. 性能优化清单〔逐项验证，不先全做〕

模块按需加载；重用已授权运行时；先显示可见页/工作表；媒体按需解码；长任务移出主UI；取消过时任务；文件版本缓存；Tab预算与LRU；字体提前就绪；不在首屏做全文件缩略图与OCR。

延迟渲染不等于延迟解析。ZIP中央目录、共享字符串、样式等可能仍需读取；第三方未提供流式/局部解析时，不在方案里假定已经具备。缓存要含内容版本与影响显示的引擎/字体版本。

预热只能减少使用时等待，仍会占内存和启动资源。先测，再决定一套或多套常驻引擎。并行Office和生成任务要测试是否拖慢前台编辑。

## 8. 成本与商务询证

统一口径：每100次普通打开、每个活跃用户、每个成功保存任务的费用与资源消耗。云端考虑文档取用、凭证刷新、会话、存储与流量；本地考虑包体、内存、更新和技术维护。

报价询证包括：只读和编辑是否分别计费、外部自动化是否加价、并发定义、离线/本地部署、白标、再分发、源代码义务、技术支持和数据处理地域。价格未知填null，不估成免费。

原始模板见 `benchmarks/office-run.template.json`。最终结果同时报告失败率、打开时间、保存正确性与未测项，不用单个综合分掩盖硬缺陷。

## 9. V3.1轻量执行

首次可先围绕一个真实需求格式、少量授权文件筛查硬问题，再对进入候选使用本章完整矩阵。完整矩阵是扩样方案，不是任何试接都要全部通过的前置。复用已有日志、测试脚本与模板，不开发Office评测后台。套件内部Undo归真实编辑会话，宿主验证唯一writer、保存与AI接力，不强制复制细粒度History。
