# Skill机械命令与执行合同

**V3.3｜2026-09-25｜2.0阶段方案，尚未实现或安装。** 保留三份薄Skill和三个拟新增工具名称，不增加执行器、质量服务或任务台账。状态/持久化细节统一见14，不在每份Skill复制协议。

## 1. 既有宿主与机械职责

复用DocumentSession、文件协调、ToolCatalog/Gateway、ExecutionEngine、资源、图像与受控构建/导入。读取源文件、确定依赖、资源登记、ID/引用、HTML包装、构造工程与提交由程序完成；教学、呈现、新素材和必要新代码由模型完成。

Agent Skills的方法、资源与可选scripts可配合确定性工具，但文件存在不等于宿主已加载或工具已接通。[S37][S38][S39] 生产模型只读当前方法与必要参考；已知机械步骤宿主直接调用函数，不为每个函数建Service或独立CLI。

## 2. 三份Skill与后置策略

course-design负责教学和理想呈现稿；layout-shell负责框架HTML。**这两步不读取编辑器能力、Schema、Builder或shell-contract。** 框架HTML完成后才进入专门的呈现策略，作为slot-build的第一个明确子步骤，读取精简能力摘要并选择载体；随后只加载所选实现需要的API。

策略输出少量区域、Surface、Native/Runtime/Component选择及素材需求，不要求新配置文件、评分或另一个Agent复审。工具权限仍由原宿主管理，阶段输入过滤不成为新的权限系统。已有完整HTML默认全Runtime机械导入，跳过无必要的设计/策略调用。

旧提示中的“Runtime少放文字”“稳定图文必须原生”和设计阶段前置能力说明，在后续实际接入时同步修正；本轮不改根AGENTS或安装版Skill。自生成Runtime的可读数据和已有稳定键保留，但不再要求AI逐个登记文字图片，自动发现由宿主完成。

## 3. 已有能力和待补缺口

| 能力 | 处理 |
|---|---|
| 正式文档/文件、授权、取消和History | 复用已有入口，不另建writer、版本或回滚系统 |
| 原生、资源、批量与图像工具 | 读取真实目录，不凭本文假设命令已经注册 |
| build.create/check/import | 延续真实授权和目标基线，check不等于import，import不等于保存 |
| Runtime/Component目标 | 先复用现有字段/props/登记与选择；补自动发现和当前状态保留，不复制另一编辑器 |
| 完整HTML承载 | 复用隔离内容宿主，补确定性document包装、依赖和保存；不能把HTML直接当Runtime source |
| Flow页面Runtime/原生文本框 | 复用surfaceLayerItems、paperSpace和Document正文，补真实编辑挂载、滚动占位及按钮语义 |
| 三个拟新增工具 | shell.inspect、slot.prepare、shell.assemble；仍未注册，内部函数可先用，不强制三次工具往返 |

## 4. 一个装配入口，整体Runtime优先

2.0默认已有HTML整体保留：CSS、数据、脚本、文档结构和资源关系不由LLM重写。独立图文有收益时可沿已有工厂构造Native；任意HTML机械拆Native不作为本轮前置。原静态子集仅是后续转换器参考，不限制框架设计或Runtime表现力。

素材是Runtime或Native使用的资源，不是必须单独生成一种宿主。用户已删除槽、不需新素材或已有完整模块时直接跳过准备。页面可以整体运行，也可与独立原生文本框/批注共存，不碎片化拆开共享状态的气泡、图片和播放器。

## 5. 三个拟新增工具的最小责任

### shell.inspect：读取当前来源

沿用输入`{source, pages?}`，source是已授权文件/模块引用。正式输入采用当前会话已确认版本；磁盘尚未保存时可用受管当前快照，不静默读旧盘稿。宿主冻结本次所需内容/依赖，不要求先把所有文件保存成功才能编辑未保存文档。

已有HTML路径只需识别文档/资源、主要viewport/滚动需求和明显不支持项；不扫描全部DOM生成原生映射，不要求用户补data-gl标签。测量只在需要布局时等相关字体/图片，不扫全字体库；字体ready和视口坐标的原有边界继续适用。[S40][S41]

返回沿用`{snapshot, status, pages, slots, issues}`，无槽可为空。自动图文目标属于运行中的编辑能力，不把首次导入静态扫描当作全部动态对象清单。可保真承载但不能原生化不是失败；实际资源/安全/宿主缺口如实说明。

### slot.prepare：准备尚缺的局部输入

沿用`{snapshot, slots?}`。当前HTML的brief、尺寸及已确认策略优先，MD仅补未表达背景。明确可复用资源由程序复用；需要语义判断时由当前生产模型处理，不另建相似素材匹配平台。

按槽返回ready、needs-generation、needs-context或unsupported及真实资源/任务引用。无槽或成品直接跳过；只有新素材才调用真实已授权Provider，不用占位图/静态后备冒充交互完成。

### shell.assemble：确定性封装候选

沿用`{snapshot, job, fills?}`。读取已确认区域策略或整体Runtime默认值，调用既有构建能力；完整HTML保留浏览器语义，资源按支持格式归档，必要JS打包复用受控构建。不让LLM逐页重写project.json、复制坐标和封装代码。

返回沿用`{job, status, mappedObjects, editableTextObjects, filledSlots, issues}`；原生对象数量只作诊断，不代表质量或总可编辑性。必要能力说明放已有结果字段，不加全局评分系统。新动态代码按既有准入检查，未改变的结果复用；静态来源无需重复编译。

工具只准备候选，不另增shell.import。首次实现包装器可能需要开发编程；投入使用后的受支持HTML导入必须机械执行，不能以“首次适配”名义每份网页都让模型重写。超出支持范围明确失败或保留原文件，不静默简化。

## 6. 正式导入与保存

新工程通过真实目标、已有build任务、暂存候选与现有必要准入进入build.import/Session，再沿现有保存。未保存新文档、来源版本与目标锁定按当前正式合同处理，不用临时副本冒充已打开文档，不让离线Builder直接覆盖正式文件。

独立HTML轻编辑使用对应窄文件Driver/会话；工程导入后工程拥有当前HTML/Runtime内容。原HTML、MD不自动回写。来源授权/目标版本/取消只在现有提交协调区间核对，不在三个工具各复制全量hash和全工程测试。

## 7. 编辑连接：自动发现＋同一正式写入

按照14复用现有RuntimeAuthoring/Component目标、资源和提交。DOM与Phaser常见图文自动发现，Three仅做当前可访问的已知类型；场景和组件通过薄宿主适配共用编辑。稳定目标绑定优先，没有时允许工程内窄覆盖，禁止第二History或独立覆盖文件。

句子复用同一DOM/引擎对象时，要关联真实内容身份，不仅匹配对象路径或当前位置。需要重建/重排后无法明确对应时保留修改并说明失效，不语义猜配。操作提交和重开/导出读取同一内容，不能只改屏幕。

Flow插入文本框通过已有Native工厂建立paper-space对象，正文paragraph/heading操作仍保留。只调整对应UI/工具意图路由，不全局替换正文命令或恢复旧格式兼容分支。

## 8. 运行成本与检查

文字完整输入/IME结束、图片替换或几何手势结束后提交；对象测量、滚动、相机和自动内容高度在视图缓存中处理，不连续写历史和磁盘。不逐帧全量枚举、不全局注入拦截器、不用MutationObserver与框架无限争写。

同一成果不在inspect、prepare、assemble和每份Skill重复检查。权限、取消、版本冲突、资源与保存是必要边界，沿用现有机制；外部编辑仍由原文件观察/冲突处理，不承诺OS全局锁定。

按02和14完成少量真实路径：保真HTML、后续状态图文修改、无expose引擎内容、Flow长网页/原生文本框、新建课程的后置策略与机械装配。测试仅覆盖本次差异，保存/撤销/安全原证据可复用。

本包35条基准JSON保持原样；不据新方案新增任务登记或伪填通过。产品代码和运行验证由后续实现会话完成，文档存在、工具名称或Schema字段本身都不是接通证据。
