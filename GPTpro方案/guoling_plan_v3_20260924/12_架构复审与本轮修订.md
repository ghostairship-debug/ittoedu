# V3.3 架构复审、Runtime与Flow方案修订

**本版日期：2026-09-25｜只修订指定方案包。V3.1/V3.2证据保留，新增第10节记录本会话Runtime/Flow定向阅读与Owner决定；不是全仓重审。**

## 1. 总体判断

保留V3.1“不先全仓重构”的判断。此次案例要求修正内容生产与验收的假设：有限原生映射不是所有内容的默认终点；不以工程可导入替代创作质量，也不以整页能嵌入替代实际可编辑。旧样本不能证明当前底座上限，具体限制先用一个当前版本案例定位。

本版保留教育切入、通用 Agent、单向创作、HTML 轻编辑、原生/混合作品及开放 Office 候选。教育方法是可选能力，不将所有办公任务强制套入教学策划和多阶段流程。

当前收敛是：**沿用已建立的内核；简单内容可靠映射，完整区域保留实现；让程序接管搬运封装，只补实际编辑缺口。** 不新增保真服务、评分平台、逐保存截图、通用CSS转换器或更多Agent角色。

## 3. 需要修正的过度设计风险

| 风险 | 处理 | 不做什么 |
|---|---|---|
| 把现行验收与所有长期格式绑定 | 原范围先收口，Owner要求的Runtime/HTML/Flow增量仍在2.0完成，Office另排 | 不修改任务/验收状态，不追溯把新能力记为已通过 |
| 先限制所有设计，再追求原生映射 | 真实听力案例一次诊断；简单对象有限映射，完整区域保留实现 | 不先做完整HTML编辑器或任意网页转换器，不主动删内容来适应子集 |
| 每个 Skill 自己写保存、hash、重试、装配代码 | 共享少量宿主确定性函数，必要时暴露薄工具 | 不建设 Skill 自己的执行器、队列和权限系统 |
| “复用 DocumentSession”被理解为所有格式变成 V9 | HTML 保留源文；Office Provider 保留真实内部模型与编辑会话 | 不统一所有 AST，也不镜像第三方每次键入到第二撤销栈 |
| 人工 HTML、模型、外部文件工具各自写盘 | 接入已有文档/文件协调；补同一来源的保存与提交版本检查 | 不靠前端独立 writeFile 或先 check 后无锁 write |
| 工程优化扩成新主线 | Journal/事件列独立窄任务，热点按需处理 | 不为了减行数拆大文件、删组件、清空测试/索引 |
| 候选池变成多个常驻 Office 和评测后台 | 保留研究文档，本轮只做一个有具体问题的实验 | 不安装全候选，不先开发公共插件 SDK/市场 |

## 5. V3.3的2.0路径

**原验收收口 → 当前状态Runtime轻编辑/常见图文自动发现 → HTML机械整体导入 → Flow整页承载和原生文本框 → 所需三表面接线、后置呈现策略与Skill → 2.0最终收口。** 顺序与范围见02，技术边界见14。

V3.2不将新增链路纳入2.0的版本安排，被Owner本轮要求取代；不是回头修改旧任务状态。静态原生映射保留为可选后续能力，不成为导入前置。教学与框架HTML先设计，编辑器能力在后置策略才加载。

保留执行器、文档内核、成熟原生能力和构建/准入。受支持HTML机械封装不允许每份都让LLM重写；自动发现与内容身份/保存分开，不因容易扫描DOM而承诺任意动态内容可持久修改。

安全、来源/目标版本、取消和保存事实仍由现有宿主保障，减少的是重复工作，不是删除这些底线。轻微像素差别为提醒，明确内容/关键行为丢失不能冒充成功。

## 7. 未来扩展不被堵住

新格式复用真实共性：身份、文件绑定、授权、任务、成果回执与保存协调。自有 HTML 可以沿用 DocumentSession 正式内容和 History；第三方 Office 的细粒度撤销可由其编辑引擎拥有，果铃协调唯一活动 writer、保存边界和 AI 操作结果。不承诺所有编辑器共享一个跨格式逐键 Undo。

独立文件成果、通用代码任务、薄 runner、公共插件体系在真实需求进入时再扩展；当前 V9 build 合同不应为它们重写，但也不能被宣传为已经支持。首发课程内容是用例，不是给通用 Agent 加永久教育限制。

## 9. 本次听力案例依据与推论边界

来源是用户本轮上传的 `Starter-Unit-1-Hello-standalone.html`、`Starter-Unit-1-Hello-listening(1).h5lesson`，及上一轮生成的 `guoling_case_evidence.md`。本节转述该对照记录，未在本轮重跑。原始两个文件仍在会话附件，本方案包不附教材图片/音频，不将它们默认为可公开分发资源。

| 上一轮记录支持的观察 | 此次规划后果 |
|---|---|
| 三张图片和音频与HTML对应素材字节一致 | 优先查构图与迁移，不把问题归因于素材质量 |
| V7工程已有DOM Runtime，但句子数据删了中文、人物/气泡定位关系 | DOM存在不等于实际生产保真；封装要保留完整数据与行为，不扩大低层Schema来补被主动删掉的内容 |
| 原HTML的图片放大裁切、角色气泡、原文/译文显隐、进度条等在工程内未被完整保留 | 关键教学表达与操作必须一起对照，不仅核验文件合法、节点数量或一张初始截图 |
| 内容播放区与全局教师控制器声明区域重叠 | 当前宿主还需看实际层级/点击；先调整该作品配置，不删除成熟功能或建设通用冲突系统 |
| Runtime只有整体segments内容字段，未显式登记逐句目标 | 先核对当前已有编辑入口，补少量稳定字段定位；不宣称现有模块完全不能编辑，也不新建任意DOM编辑器 |

上一轮只在浏览器与最小Runtime宿主测试，未启动真实V7 Player，也未检查当前版本。原HTML自然连续播放的跨对话同步本身也有缺口。故不能推出“最新Schema导致全部退化”“原HTML完全正确”“调提示词就够”或“必须重构底座”。

本版据此改变的是开发默认策略与一次代表性验收：保真承载、持久编辑、真实新建生成分开验证，按失败层补最小实现；架构主线、成熟功能和近期通用方向保留。
