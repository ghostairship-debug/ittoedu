## 2.0规划的调整

先收口正在进行的原范围验收并固定稳定基线，再完成：Runtime运行到哪编辑到哪、常见文字/图片自动发现、HTML整体机械保真导入、Flow页面Runtime/原生文本框，以及后置呈现策略与机械Skill闭环；这些不再笼统推迟到2.x。**这是本方案的阶段调整，不是把未完成任务改成已完成，也不是重新登记Codex任务。**

保留现有架构和成熟功能。Runtime轻编辑以DOM/Phaser常见对象及Three已知表示为范围；不承诺任意Canvas像素、任意JS现场或所有网页都可自动深编。对象发现与稳定内容身份分开处理，避免运行中的同一气泡被错当成同一句内容。

HTML默认整体保留，不先拆Native；原生化是后续有明确收益才做的优化。Flow保留Word式正文，同时支持页面Runtime和paper-space自由原生图层；“插入文字”改为“插入文本框”，正文输入与段落操作仍留在Document体系。

## 创作主线

**教学策划 → 理想呈现脚本 → 高质量框架HTML → 后置呈现策略 → 必要素材/模块生产 → 机械装配 → 果铃工程 → 轻编辑与保存。**

框架HTML完成前不读取编辑器能力、Schema或静态转换白名单。后置策略才选择Slide/Flow/Spatial及Native/Runtime/Component，并明确素材来源；复用三份薄Skill，不增加Agent群。已有完整HTML可直接机械导入，跳过无需执行的模型环节。

当前HTML人改内容用于后续实现，MD只补未表达的教学背景；工程生成后工程是当前作品，不建立MD、HTML与工程双向同步。独立HTML编辑和工程导入共用编辑能力，保存目的地分别清楚。

## 已确定的边界

| 项目 | 处理原则 |
|---|---|
| 2.0主线 | 原验收收口后完成Runtime/HTML/Flow/呈现策略增量，再最终收口 |
| 表现力 | 保住完整布局、数据与交互；不以Native/Runtime占比衡量质量 |
| Runtime编辑 | 软件自动发现常见图文；绑定优先、正式内容覆盖兜底，仍只有一个writer/History |
| Flow | 连续Document正文＋页面Runtime＋paper-space原生图文，不推翻现有正文模型 |
| 原生文本框 | 插入按钮/AI工具语义区分自由文本框和正文段落，不删除正文能力 |
| 机械执行 | 资源、封装、装配与提交由共享工具完成；不让LLM反复重写已有作品 |
| 验证 | 少量代表路径、按变化选测；不逐保存截图、重复全量检查或新增质量网关 |
| 后续 | HTML机械拆Native、任意Slides尺寸、Office全接入、发行工程不作本轮前置 |
